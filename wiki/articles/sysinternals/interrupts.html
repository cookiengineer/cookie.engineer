Interrupts

Hardware and software interrupt architecture on x86-64 Linux, from the IDT through the API C, softirqs, and N API , to the Windows IRQL comparison.

Overview

An interrupt suspends the current instruction stream so the CPU can service an event. This article follows the complete path from a device asserting an interrupt line, through the APIC and the Interrupt Descriptor Table, into a Linux handler and its bottom-half mechanisms. After reading it you can decode /proc/interrupts , follow a handler through the kernel source, and contrast the Linux model with the Windows IRQL model.

The Interrupt Taxonomy

CPU s receive notification of events through three distinct mechanisms, all routed through the same hardware table - the Interrupt Descriptor Table (IDT):

Type Source Examples
Hardware Interrupt External device via APIC/LAPIC NIC packet, disk I/O, timer keyboard, mouse, NMI
Exception (Fault/Trap) CPU itself instruction error Page fault (#PF), div0 (#DE) breakpoint (#BP), GPF (#GP)
Software Interrupt Program requested viaint N int $0x80 (legacy syscall) int3 (debugger breakpoint)

Exceptions are further subdivided into three categories based on the saved instruction pointer:

Category RIP points to... Example Behavior
Fault Faulting instruction Page fault (#PF) Instruction can be retried after fix
Trap Next instruction Breakpoint (#BP) Debugger single-step
Abort Unpredictable location Machine check (#MC) Process/CPU likely unrecoverable

x86-64 Interrupt Vector Table (0-255)

The x86-64 architecture reserves the first 32 vectors (0-31) for exceptions and non-maskable interrupts. Vectors 32-255 are available for external hardware interrupts and software-defined uses.

Interrupt Descriptor Table (IDT)

The IDT is an array of 256 gate descriptors, each 16 bytes on x86-64. The CPU uses the vector number as an index into this table to find the handler address. The IDT base address is stored in the idtr register and loaded via the lidt instruction. 

Interrupt Gate Descriptor (16 bytes, x86-64):

 127                              96  95               64  63              32  31              0
┌──────────────────────────────────+────────────────────+──────────────────+──────────────────┐
│   Reserved (must be 0)           │  Offset 63:32       │  IST ────┐ DPL  │  Offset 31:16     │
│                                  │                     │  │  Type │  │  │                  │
└──────────────────────────────────+────────────────────+──+───+────+──+──+──────────────────┘
  63                              32  31               16  15               0
┌──────────────────────────────────+────────────────────+──────────────────┐
│  Segment Selector                │  Offset 15:0       │   ── Offset ──    │
└──────────────────────────────────+────────────────────+──────────────────┘

  Type:  0xE = 64-bit Interrupt Gate (disables IF)
         0xF = 64-bit Trap Gate (preserves IF)
  DPL:   Descriptor Privilege Level (0 = kernel only, 3 = user allowed)
  IST:   Interrupt Stack Table index (0-7) — uses dedicated stack

Key fields: - Offset : Full 64-bit address of the handler function - Segment Selector : Must be __KERNEL_CS (kernel code segment) - DPL : 0 for kernel-only vectors (most); 3 for int3 , int $0x80 - IST : If non-zero, the CPU switches to a dedicated interrupt stack (used for NMI, #DF, #MC to avoid stack overflows on corrupted stacks)

APIC Architecture

Modern x86-64 systems route interrupts through the Advanced Programmable Interrupt Controller ( API C), replacing the legacy 8259 PIC:

MSI/MSI-X (Message Signaled Interrupts)

Modern PCI e devices bypass the I/O API C entirely, writing interrupt messages directly to the L API C via the system bus. This eliminates the shared- IR Q problem and reduces latency: 

PCIe device → MSI write to LAPIC address → LAPIC receives vector → CPU interrupted
             (no I/O APIC involved)
						
# List MSI/MSI-X usage
sudo cat /proc/interrupts | grep -i 'msi\|msi-x\|nvme\|eth\|enp'

# Inspect MSI capabilities of a device
sudo lspci -vvv -s 00:1f.6 | grep -A10 MSI

Interrupt Handling Flow

The complete path from hardware signal to device driver ISR:

   Hardware Device
        │
        ▼
  ┌─────────────┐
  │ I/O APIC    │  (or MSI write)
  └──────+──────┘
         │
         ▼
  ┌─────────────┐
  │ Local APIC  │  Raises INT pin on CPU (or priority arbitration)
  └──────+──────┘
         │
         ▼  CPU accepts interrupt (between instructions, after EFLAGS.IF check)
  ┌─────────────────────────────────────────────────────────────────┐
  │ 1. CPU reads vector number from LAPIC                           │
  │ 2. Indexes IDT[idt_vector] → gate descriptor                    │
  │ 3. Switches stack to IST stack (if IST != 0)                    │
  │ 4. Pushes SS, RSP, RFLAGS, CS, RIP onto stack                   │
  │ 5. Clears EFLAGS.IF (mask further maskable interrupts)          │
  │ 6. Loads CS:RIP from gate descriptor → handler entry            │
  └─────────────────────────────────────────────────────────────────┘
         │
         ▼
  common_interrupt()          // arch/x86/kernel/irq.c
         │
         ├─ SAVE_REGS         // Save all GPRs
         │
         ▼
  do_IRQ()                    // kernel/irq/handle.c
         │
         ├─ irq_enter()        // Enter interrupt context
         │
         ├─ generic_handle_irq(irq)
         │    │
         │    └─ handle_fasteoi_irq()  ← for modern devices
         │         │
         │         ├─ handle_irq_event()
         │         │    │
         │         │    └─ __handle_irq_event_percpu()
         │         │         │
         │         │         └─ Calls every registered ISR (handler->handler())
         │         │             (multiple drivers can share an IRQ line)
         │         │
         │         └─ cond_unmask_eoi_irq()  // Send EOI to LAPIC
         │
         ├─ irq_exit()
         │    │
         │    ├─ invoke_softirq()   // Process pending softirqs
         │    │
         │    └─ rcu_irq_exit()     // Notify RCU
         │
         └─ return from interrupt (iretq)

Top Half vs Bottom Half

The interrupt handler running directly in the IDT path is the top half . It runs with interrupts disabled (or at least the current IR Q line masked) and must execute as fast as possible. Any work that can be deferred belongs in a bottom half mechanism. 

     Top Half (Hard IRQ Context)
     ═══════════════════════════
     - Interrupts disabled on this CPU
     - NO sleeping, NO mutex, NO GFP_KERNEL
     - Acknowledge device (clear interrupt)
     - Copy data from device registers
     - Schedule bottom half
     - Return quickly

     Bottom Half (Soft IRQ / Tasklet / Workqueue Context)
     ══════════════════════════════════════════════════
     - Interrupts enabled
     - Can sleep (workqueues only)
     - Protocol processing (TCP/IP)
     - Block I/O completion
     - Timer expiry processing

Linux Bottom-Half Mechanisms

Linux provides four bottom-half deferral mechanisms, each with different execution context and constraints:

Softirq Tasklet Workqueue Threaded IRQ
Sleep OK? No No Yes Yes
Concurrency Same softirq can run on multiple CPUs Serialized (same tasklet not on 2 CPU) Per-CPU pool Per-thread
Priority Fixed: HI, TIMER, NET, TASKLET, ... TASKLET_SOFTIRQ only worker_priority RT priority adjustable
Preemptible? No (runs in irq context) No Yes Yes (thread)
Use case High-perf networking Simpler than raw softirq Complex, blocking I/O Simple device drivers

Softirqs

Softirqs are the fastest bottom-half mechanism. They are statically allocated at compile time and run in interrupt context: 

// include/linux/interrupt.h
enum {
    HI_SOFTIRQ       = 0,  // High-priority tasklets
    TIMER_SOFTIRQ    = 1,  // Timer wheel processing
    NET_TX_SOFTIRQ   = 2,  // Network transmit completions
    NET_RX_SOFTIRQ   = 3,  // Network receive processing (NAPI)
    BLOCK_SOFTIRQ    = 4,  // Block layer completions
    IRQ_POLL_SOFTIRQ = 5,  // Block layer polled completions
    TASKLET_SOFTIRQ  = 6,  // Regular tasklets
    SCHED_SOFTIRQ    = 7,  // Scheduler (load balancing)
    HRTIMER_SOFTIRQ  = 8,  // High-resolution timers
    RCU_SOFTIRQ      = 9,  // RCU processing (PREEMPT_RCU)
    NR_SOFTIRQS
};

// Registration (compile-time only):
// kernel/softirq.c
static struct softirq_action softirq_vec[NR_SOFTIRQS];

// Raising a softirq:
void raise_softirq(unsigned int nr)
{
    unsigned long flags;
    local_irq_save(flags);
    raise_softirq_irqoff(nr);
    local_irq_restore(flags);
}

// Processing loop:
asmlinkage __visible void __softirq_entry __do_softirq(void)
{
    // ... runs through softirq_vec, calls registered handlers
    // Limited to MAX_SOFTIRQ_TIME (2 ms) or MAX_SOFTIRQ_RESTART (10 restarts)
    // If softirqs keep arriving, ksoftirqd/N thread takes over
}

Tasklets

Tasklets are built on top of TASKLET_SOFTIRQ and HI_SOFTIRQ . They provide a simpler API than raw softirqs and guarantee that the same tasklet never runs concurrently on two CPU s: 

// Declare and schedule a tasklet
DECLARE_TASKLET(my_tasklet, my_tasklet_func);

void my_tasklet_func(unsigned long data)
{
    // Deferred work — still cannot sleep
    printk(KERN_INFO "Tasklet running on CPU %d\n", smp_processor_id());
}

// Schedule (typically from hard IRQ handler):
tasklet_schedule(&my_tasklet);

Workqueues

Workqueues run in process context (kernel threads), so they can sleep:

// Schedule work on the system workqueue
static struct work_struct my_work;

static void my_work_func(struct work_struct *work)
{
    // Can sleep, use mutex, allocate with GFP_KERNEL
    mutex_lock(&some_mutex);
    // ... blocking I/O ...
    mutex_unlock(&some_mutex);
}

// Init: INIT_WORK(&my_work, my_work_func);
// Schedule: schedule_work(&my_work);  // default workqueue
// Or: queue_work(system_wq, &my_work);
						
# List kernel worker threads
ps aux | grep '\[kworker\|\[ksoftirqd'

# Workqueue statistics
ls /sys/devices/virtual/workqueue/
cat /sys/devices/virtual/workqueue/*/max_active

Threaded IRQs

The simplest approach: when request_threaded_irq() returns, the top-half only acknowledges the device; all processing runs in a dedicated kernel thread: 

// Modern device driver pattern
static irqreturn_t my_hard_isr(int irq, void *dev_id)
{
    // Top half: acknowledge device, mask interrupt
    return IRQ_WAKE_THREAD;  // Wake up the thread
}

static irqreturn_t my_threaded_isr(int irq, void *dev_id)
{
    // Bottom half: runs in process context, can sleep
    mutex_lock(&dev_lock);
    // ... process data ...
    mutex_unlock(&dev_lock);
    return IRQ_HANDLED;
}

// Registration
request_threaded_irq(irq, my_hard_isr, my_threaded_isr,
                     IRQF_ONESHOT, "mydrv", dev);
						
# Find threaded IRQ handlers
ps aux | grep 'irq/'
# [irq/120-nvme0q0]
# [irq/121-enp0s31f6]

NAPI Interrupt Coalescing

Under heavy network load, the interrupt rate can exceed the CPU 's ability to handle each packet individually. N API solves this by switching between interrupt-driven and polling modes: 

Low load (interrupt mode):
  NIC packet → IRQ → softirq NET_RX → process single packet → return

High load (polling mode):
  NIC packet → IRQ → softirq NET_RX → disable NIC interrupts
                                     → poll loop: reap N packets from ring buffer
                                     → re-enable NIC interrupts when budget exhausted
                                     → return
  (More packets arrive while polling — handled without additional IRQs)
						
// Simplified NAPI poll function:
static int my_napi_poll(struct napi_struct *napi, int budget)
{
    int work_done = 0;

    while (work_done < budget) {
        struct sk_buff *skb = my_dequeue_packet(dev);
        if (!skb)
            break;
        napi_gro_receive(napi, skb);  // GRO: Generic Receive Offload
        work_done++;
    }

    if (work_done < budget) {
        napi_complete_done(napi, work_done);
        enable_irq(dev->irq);  // Re-enable interrupts
    }

    return work_done;
}
						
# Check network driver's NAPI and interrupt coalescing settings
ethtool -c eth0   # Interrupt coalescing
ethtool -g eth0   # Ring buffer sizes
ethtool -S eth0   # Driver statistics (packet counts, coalesce events)

# Total NAPI budget per softirq cycle (default: 300 packets)
cat /proc/sys/net/core/netdev_budget

# Per-device poll weight (default: 64 packets)
cat /proc/sys/net/core/dev_weight

Interrupt Affinity

Modern SMP systems can steer interrupts to specific CPU cores, isolating interrupt handling from application CPU time: 

# View current IRQ affinity (bitmask: each bit = one CPU)
cat /proc/irq/120/smp_affinity
# 00000000,00000000,00000000,00000000,00000000,0000000f → CPUs 0-3

# Set IRQ 120 to CPU 4 only
echo 10 | sudo tee /proc/irq/120/smp_affinity
# 0x10 = bit 4 set

# Use the list-based interface (easier)
cat /proc/irq/120/smp_affinity_list
# 0-3
echo 4 | sudo tee /proc/irq/120/smp_affinity_list

# Spread all NVMe IRQs across CPUs 0-7
for irq in $(grep nvme /proc/interrupts | awk -F: '{print $1}'); do
    echo "Setting IRQ $irq to CPU $(($irq % 8))"
    echo $(($irq % 8)) | sudo tee /proc/irq/$irq/smp_affinity_list
done

# irqbalance: automatic interrupt distribution daemon
sudo systemctl status irqbalance

Timer Interrupts

The timer interrupt is the heartbeat of the kernel, driving scheduling, timekeeping, and RCU. Linux can use multiple timer sources:

PIT (8254) ~1 ms Moderate Legacy, 1.193 MHz clock
HPET ~100 ns High High Precision Event Tim.
ACPI PM Timer ~279 ns High Power Management Timer
LAPIC Timer Per-CPU High One-shot or periodic
TSC-Deadline ~1 ns Very High Posts deadline to LAPIC
RTC ~1 s Low Periodic, wakes from S3

Windows Comparison: IRQL and DPC/APC

Windows uses a fundamentally different model - Interrupt Request Levels ( IR QLs) - where each processor runs at a specific IR QL, and only interrupts at higher IR QLs can preempt: 

x86-64 IRQL Levels (Windows):

  IRQL       Purpose
  ═══════    ════════════════════════════════════════════════
  HIGHEST    Machine checks, bus errors (unrecoverable)
  POWER      Power failure notification
  IPI        Inter-processor interrupts
  CLOCK      Clock interrupts
  PROFILE    Profiling timer
  DEVICE     Device interrupts (DIRQLs, mapped from IRQ vectors)
  DISPATCH   DPCs and scheduler (thread dispatching runs here)
  APC        Asynchronous Procedure Calls
  PASSIVE    Normal thread execution (user & kernel mode)
  
  INTERRUPT_LEVEL = DIRQL through HIGHEST

Windows bottom-half equivalents:

Linux Windows
Softirq DPC (Deferred Procedure Call) - runs at DISPATCH_LEVEL
Workqueue Work item queued to system worker thread
Threaded IRQ ISR at DIRQL, DPC at DISPATCH_LEVEL
Signal delivery APC (Asynchronous Procedure Call) - runs at APC_LEVEL

Challenge

Write a Go tool that samples /proc/interrupts twice, one second apart, and prints the per- CPU rate for every interrupt source. The first line of /proc/interrupts names the CPU s; each following line holds one counter per CPU , then the controller type and device name. Run the tool while generating disk or network load and identify which source and which CPU carry the most interrupts. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
	"time"
)

type sample struct {
	cpus  []string
	order []string
	lines map[string][]uint64
}

func readCounters(path string) (*sample, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer file.Close()

	result := &sample{lines: map[string][]uint64{}}
	scanner := bufio.NewScanner(file)
	first := true

	for scanner.Scan() {

		fields := strings.Fields(scanner.Text())
		if len(fields) == 0 {
			continue
		}

		if first {
			result.cpus = fields
			first = false
			continue
		}

		key := strings.TrimSuffix(fields[0], ":")
		counts := make([]uint64, 0, len(result.cpus))

		for _, field := range fields[1:] {
			value, err := strconv.ParseUint(field, 10, 64)
			if err != nil {
				break
			}
			counts = append(counts, value)
		}

		if len(counts) == len(result.cpus) {
			if _, ok := result.lines[key]; !ok {
				result.order = append(result.order, key)
			}
			result.lines[key] = counts
		}

	}

	return result, scanner.Err()
}

func main() {
	before, err := readCounters("/proc/interrupts")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	time.Sleep(time.Second)

	after, err := readCounters("/proc/interrupts")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	total := make([]uint64, len(after.cpus))

	fmt.Printf("%-14s", "SOURCE")
	for _, cpu := range after.cpus {
		fmt.Printf("%10s", cpu)
	}
	fmt.Println()

	for _, key := range after.order {
		a, ok := before.lines[key]
		if !ok {
			continue
		}
		b := after.lines[key]
		fmt.Printf("%-14s", key)
		for i := range b {
			delta := b[i] - a[i]
			total[i] += delta
			fmt.Printf("%10d", delta)
		}
		fmt.Println()
	}

	fmt.Printf("%-14s", "TOTAL")
	for _, value := range total {
		fmt.Printf("%10d", value)
	}
	fmt.Println(" interrupts/s")
}
