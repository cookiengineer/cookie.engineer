Page Cache

The Linux page cache, from address_space and the xarray to writeback, dirty page management, read-ahead, and direct I/O.

Overview

The page cache is the bridge between the VFS and the memory manager. It caches file-backed pages so repeated reads return from RAM, absorbs writes for asynchronous writeback, and backs mmap() . After reading this article you can inspect cache residency, tune dirty page limits, explain read-ahead, and decide when O_DIRECT is worth the trouble.

Required Reading

  • Virtual Memory - page tables, TLB, page faults, mmap() internals
  • Memory Manager - physical memory management, page frame reclamation, LRU
  • VFS - superblock, inode, dentry, struct file, address_space

Page Cache I/O Bridge

The page cache is the central bridge between the VFS and the memory manager. It caches file-backed pages in memory so that repeated reads return from RAM instead of going to disk, and writes can be buffered, coalesced, and deferred. Without the page cache, every read() would be a synchronous disk operation, a 10,000x slowdown.

The page cache serves three simultaneous roles:

  1. Read cache : file data read from disk stays in memory for subsequent reads
  2. Write buffer : writes are absorbed by the cache and flushed asynchronously (writeback)
  3. mmap() backing : memory-mapped file pages are the same physical pages as the cache

address_space Per Inode

Every struct inode that supports file-backed data has an embedded struct address_space in i_mapping . The address_space ties together the file's logical offset space with physical memory pages:

// include/linux/fs.h — struct address_space (abbreviated)
struct address_space {
    struct inode        *host;          // owning inode
    struct xarray        i_pages;       // radix tree of cached pages (folio → struct folio *)
    gfp_t                gfp_mask;      // allocation flags for new pages
    atomic_t             i_mmap_writable; // VM_SHARED mappings count
    struct rb_root_cached i_mmap;        // tree of VMA mappings
    struct rw_semaphore  i_mmap_rwsem;   // lock for mapping tree
    unsigned long        nrpages;        // total number of cached pages
    unsigned long        nrexceptional;  // shadow / swap entries
    pgoff_t              writeback_index; // writeback starting offset
    const struct address_space_operations *a_ops;
    unsigned long        flags;          // error bits, writeback state
    spinlock_t           private_lock;
    struct list_head      private_list;
    void                 *private_data;
    errseq_t              wb_err;        // writeback error tracking
};

// struct folio — the new page cache unit (since 5.16)
// A folio is a collection of contiguous physical pages (to support large folios)
struct folio {
    struct page page;                    // embedded page descriptor
    // ... accessor macros hide internal layout
};

// Key folio state flags:
// PG_locked   — folio is locked for I/O
// PG_dirty    — folio has been modified and needs writeback
// PG_uptodate — folio content is valid (either from disk or written recently)
// PG_writeback— folio is currently being written to disk
// PG_reclaim  — folio is a candidate for page reclaim
						
# Observe the address_space indirectly through page cache stats

# Total pages in the page cache
cat /proc/meminfo | grep -E "^Cached:|^Buffers:|^SwapCached:"
# Cached:      8388608 kB  ← file-backed pages in page cache
# Buffers:       524288 kB  ← block device buffer cache (legacy, small)
# SwapCached:         0 kB  ← pages in both swap and page cache

# Per-file page cache residency
# The fincore tool shows cache residency per file (from util-linux)
fincore /usr/bin/bash /usr/lib/libc.so.6
# RES  PAGES  SIZE  FILE
# 720K  180   892K  /usr/bin/bash       ← 180 pages cached
# 1.2M  328   2.0M  /usr/lib/libc.so.6  ← 328 pages cached

# If fincore not available, use mincore():
python3 -c "
import mmap, os
fd = os.open('/etc/passwd', os.O_RDONLY)
st = os.fstat(fd)
m = mmap.mmap(fd, st.st_size, mmap.MAP_SHARED, mmap.PROT_READ)
pagesize = os.sysconf('SC_PAGE_SIZE')
num_pages = (st.st_size + pagesize - 1) // pagesize
vec = mmap.mincore(m, num_pages * pagesize)
cached = sum(1 for v in vec if v & 1)
print(f'Total pages: {num_pages}, cached: {cached}')
m.close()
os.close(fd)
"

Page Cache Radix Tree / XArray

The page cache uses an xarray (formerly radix tree) to map file offsets (in page-sized units) to struct folio pointers. This enables O(log n) lookups and efficient range scans:

XArray Structure (per-address_space i_pages):
══════════════════════════════════════════════════════════════

Logical layout for a file with pages at indices 0, 1, 2, 100, 1000:

                    xa_head
                       │
                       ▼
              ┌─────────────────┐
              │  Slot[0..63]    │  ← top-level node (order 6 = 64 slots)
              │                 │
              │  [0] → node_1 ──+──► middle-level node
              │  [1] → NULL    │       │
              │  [2] → NULL    │       ▼
              │  ...           │  ┌──────────┐
              │  [63] → NULL   │  │ Slots...  │
              └─────────────────┘  │ [0]→folio│ ← page index 0
                                   │ [1]→folio│ ← page index 1
                                   │ [2]→folio│ ← page index 2
                                   │ ...      │
                                   │ [36]→NULL│
                                   │ ...      │
                                   │ [63]→node_2 │ ← points deeper
                                   └──────+───┘
                                          ▼
                                     ┌──────────┐
                                     │ Slots...  │
                                     │ [0]→folio│ ← page index 100
                                     │ ...       │
                                     │ [40]→node_3│
                                     └──────+─────┘
                                            ▼
                                       ┌──────────┐
                                       │ [0]→folio│ ← page index 1000
                                       └──────────┘

Lookup: xa_load(&mapping->i_pages, index)
  - Walk the tree levels following slot pointers
  - Each level is a 64-entry array (or internal node)
  - Sparse files are efficient — no memory wasted on gaps
  - Multi-order entries (large folios) occupy multiple slots

Write-Through vs Write-Back

Linux uses write-back caching by default. Writes are buffered in the page cache and flushed to disk asynchronously. This is far faster than write-through (where every write() blocks until disk I/O completes) but risks data loss on power failure:

Write-Through:                          Write-Back (Linux default):
══════════════                          ═══════════════════════════

write(fd, buf, 4096)                   write(fd, buf, 4096)
  │                                      │
  ▼                                      ▼
┌──────────────┐                       ┌──────────────────────┐
│ 1. Copy to   │                       │ 1. Copy to page cache│
│    page cache│                       │    Mark page dirty   │
│ 2. Submit I/O│                       │ 2. Return immediately│
│    to disk   │                       └──────────────────────┘
│ 3. Wait for  │                              │
│    completion│                         ... later ...
│ 4. Return    │                              │
└──────────────┘                              ▼
                                       ┌──────────────────────┐
                                       │ Writeback thread     │
                                       │ flushes dirty pages  │
                                       │ to disk              │
                                       └──────────────────────┘

Write-through: safe, slow            Write-back: fast, risky (data in RAM)
						
# Compare write-through (sync) vs write-back (async) behavior

# Write-back (default) — fast
dd if=/dev/zero of=/tmp/wb_test bs=1M count=100 2>&1
# Output: 104857600 bytes (105 MB) copied, 0.03 s, 3.5 GB/s

# Write-through (sync every write) — slow
dd if=/dev/zero of=/tmp/wt_test bs=1M count=100 conv=fsync 2>&1
# Output: 104857600 bytes (105 MB) copied, 1.2 s, 87 MB/s

# Write-through with O_SYNC — even slower (syncs every write() call)
dd if=/dev/zero of=/tmp/wt_sync_test bs=4K count=2560 conv=fsync oflag=sync 2>&1

# Check what's still dirty (not yet written to disk)
cat /proc/meminfo | grep Dirty
grep -E "^nr_dirty|^nr_writeback|^nr_dirty_threshold" /proc/vmstat

Dirty Pages and Writeback

Dirty pages are the kernel's responsibility. They must be written to disk before they can be reclaimed or before the system shuts down:

Dirty Page Lifecycle:
══════════════════════════════════════════════════════════════

1. write(fd, buf, 4096)
   └── generic_perform_write()
         └── copy_page_from_iter_atomic()  ← copy data to page cache page
               └── folio_mark_dirty()      ← set PG_dirty flag

2. Page is now dirty — it sits in the page cache until writeback

3. Writeback triggers:
   ├── Periodic flush (every 5 seconds by default: dirty_writeback_centisecs)
   ├── Dirty ratio exceeded (dirty_ratio = 20% of memory by default)
   ├── Explicit sync() / fsync() / fdatasync()
   ├── Memory pressure (reclaim wants to free dirty pages)
   └── Filesystem journal commit (ordered mode)

4. Writeback execution:
   └── wb_workfn() → wb_do_writeback()
         └── writeback_sb_inodes()
               └── __writeback_single_inode()
                     └── do_writepages()
                           └── mapping->a_ops->writepages()
                                 └── (e.g., ext4_writepages)
                                       └── submit_bio() → disk

5. After I/O completion:
   └── end_page_writeback() → clear PG_writeback
         └── folio_clear_dirty() → clear PG_dirty
               └── Page is clean — can be reclaimed or stay cached
						
# Monitor writeback activity in real-time

# ── Terminal 1: Generate writes ──

# ── Terminal 2: Watch dirty pages ──
watch -n 0.5 "grep -E '^Dirty:|^Writeback:' /proc/meminfo"

# ── Terminal 3: Per-backing-device writeback stats ──

Writeback Throttling

When a process writes faster than the disk can absorb, the kernel throttles the writer. The function balance_dirty_pages() is called at the end of each write and blocks the writing process if the system's dirty page limit is exceeded:

balance_dirty_pages() Logic:
══════════════════════════════════════════════════════════════

Thresholds (configurable via /proc/sys/vm/):

  dirty_background_ratio (10%)  ← start background writeback
  dirty_ratio (20%)             ← synchronous throttling of writers
  dirty_background_bytes        ← absolute byte alternative
  dirty_bytes                   ← absolute byte alternative

Memory = 16 GiB, dirty_ratio = 20%
  → Throttle when 3.2 GiB of dirty pages accumulate

Algorithm (simplified):
  while (nr_dirty > dirty_limit):
      │
      ├── Calculate task's dirty rate
      ├── Calculate device's writeback throughput
      ├── Pause = (nr_dirty - target) / writeback_rate
      ├── io_schedule_timeout(pause)
      └── Recheck nr_dirty

  If a process writes 500 MB/s and the disk writes 200 MB/s:
    Process is paused for ~60% of the time to keep dirty pages within bounds.
						
# Inspect and tune writeback parameters

# Current thresholds
echo "=== Dirty page limits ==="
sysctl vm.dirty_background_ratio
sysctl vm.dirty_ratio
sysctl vm.dirty_expire_centisecs
sysctl vm.dirty_writeback_centisecs

# Current dirty state
echo "=== Current dirty state ==="
cat /proc/meminfo | grep -E "^Dirty:|^Writeback:|^Cached:"
grep -E "^nr_dirty |^nr_writeback |^nr_dirty_threshold |^nr_dirty_background_threshold" /proc/vmstat

# Absolute byte limits (override ratios if set)
sysctl vm.dirty_background_bytes
sysctl vm.dirty_bytes

# Temporarily reduce dirty limit to observe throttling
echo "=== Reducing dirty limit to 5% and testing ==="
sudo sysctl -w vm.dirty_ratio=5
sudo sysctl -w vm.dirty_background_ratio=2

# Generate writes — should see throttling
dd if=/dev/zero of=/tmp/throttle_test bs=1M count=1000 conv=fsync status=progress 2>&1

# Restore defaults
sudo sysctl -w vm.dirty_ratio=20
sudo sysctl -w vm.dirty_background_ratio=10

mmap() and Page Cache Interaction

Memory-mapped files share pages directly with the page cache. When you mmap() a file and write to the mapped memory, you're modifying the same physical page that a concurrent read() would see:

mmap() and Page Cache — Same Pages:
══════════════════════════════════════════════════════════════

Process A: mmap(file, PROT_READ|PROT_WRITE, MAP_SHARED)
Process B: read(fd, buf, 4096)

          ┌─────────────────────────────────┐
          │       Page Cache                 │
          │                                 │
          │  struct folio (physical page)    │
          │  ┌─────────────────────────┐    │
          │  │  file data: "hello\n"   │    │
          │  │  PG_uptodate = 1       │    │
          │  │  PG_dirty = 0          │    │
          │  └─────────────────────────┘    │
          └──────────+──────────────────────┘
                     │
          ┌──────────+──────────┐
          ▼                     ▼
   Process A's VMA       Process B's read()
   (virtual address       (kernel copies from
    0x7f... pointing      same page cache page
    to same page)         to user buffer)

Process A writes: *(char *)0x7f... = 'H'
  → PTE becomes writable (minor page fault)
  → Same page cache page is modified
  → folio_mark_dirty() → PG_dirty set
  → Process B's next read() sees "Hello\n"
						
# Demonstrate mmap/page cache sharing

python3 << 'PYEOF'
import mmap, os, tempfile, threading, time

# Create a file and write initial content
with tempfile.NamedTemporaryFile(delete=False) as f:
    f.write(b'A' * 4096)
    tmpfile = f.name

def writer():
    """mmap the file and modify it."""
    fd = os.open(tmpfile, os.O_RDWR)
    m = mmap.mmap(fd, 4096, mmap.MAP_SHARED, mmap.PROT_WRITE)
    print(f"[Writer] Read via mmap: {m[0:10]}")
    m[0:5] = b'HELLO'
    print(f"[Writer] Wrote HELLO at offset 0")
    m.flush()
    time.sleep(1)
    m.close()
    os.close(fd)

def reader():
    """read() the file after writer modifies it."""
    time.sleep(0.5)
    fd = os.open(tmpfile, os.O_RDONLY)
    data = os.read(fd, 10)
    print(f"[Reader] Read via read(): {data}")
    os.close(fd)

threading.Thread(target=reader).start()
writer()
os.unlink(tmpfile)
PYEOF

Read-Ahead Prediction

The page cache implements read-ahead to hide I/O latency for sequential readers. When the kernel detects sequential access, it proactively reads pages ahead of the current position:

Read-Ahead State Machine:
══════════════════════════════════════════════════════════════

ondemand_readahead(ractl, ...):
    │
    ├── Initial read (sequential detection window):
    │     ra->start = 0
    │     ra->size = 0 (no readahead yet)
    │     → read only the requested page
    │     → if next read is sequential: activate readahead
    │
    ├── Sequential read detected:
    │     ra->start = current_offset
    │     ra->size = initial_size (typically 4 pages = 16KB)
    │     ra->async_size = ra->size / 2 (pages to read ahead)
    │
    │     Read pattern:
    │                    ┌── requested ──┐ ┌── readahead ──┐
    │                    │               │ │               │
    │     Page index:   [N] [N+1] [N+2] [N+3] [N+4] [N+5] [N+6]
    │                    ↑               ↑
    │                    sync read       async readahead
    │
    ├── Sustained sequential:
    │     ra->size = min(ra->size * 2, max_readahead)
    │     → window grows exponentially (4→8→16→32→64 pages)
    │     → caps at /sys/block/*/queue/read_ahead_kb (usually 128KB)
    │
    └── Random access detected:
          ra->size = 0 (disable readahead until next sequential pattern)
						
# Inspect and tune read-ahead

# Current read-ahead value (in 512-byte sectors)

# Typically 128 KB (256 sectors)

# Change read-ahead

# Observe read-ahead in action

    printf("ondemand_readahead: offset=%lu\n", arg1);
}
' &

Page Cache Coherency and Invalidation

The page cache must stay coherent with on-disk data. Several mechanisms ensure this:

// Cache invalidation scenarios:

invalidate_mapping_pages(mapping, start, end):
    // Remove clean pages from the cache (dirty pages stay)
    // Used when: truncating a file, unmounting, memory pressure

truncate_inode_pages(mapping, start):
    // Remove all pages beyond start offset
    // Used when: ftruncate() shrinks a file
    // Dirty pages are written back first

// Coherency with external modifications:
// If another process/machine (NFS client) modifies the file,
// the local cache must be invalidated:
//  - NFS: uses file handle + attribute cache timeout
//  - Local: no issue (same page cache for all local access)
//  - O_DIRECT: bypasses cache entirely → always reads from disk
						
# Demonstrate cache coherency

# 1. Read to fill cache, modify externally, observe stale read
echo "original" > /tmp/coherence_test
cat /tmp/coherence_test > /dev/null        # Populate cache
# Modify via shell redirection (bypasses the same page cache)
echo "modified" > /tmp/coherence_test
cat /tmp/coherence_test                    # Sees "modified" — local coherency works!

# 2. Drop caches to force re-read from disk
fincore /tmp/coherence_test 2>/dev/null
echo 3 | sudo tee /proc/sys/vm/drop_caches > /dev/null
fincore /tmp/coherence_test 2>/dev/null    # Now 0 pages cached

# 3. O_DIRECT — always reads current on-disk data
# The page cache is bypassed entirely
dd if=/tmp/coherence_test of=/dev/null bs=4K iflag=direct 2>&1
rm /tmp/coherence_test

Page Cache and Memory Pressure

Under memory pressure, the page allocator invokes page reclaim. Clean file-backed pages are the preferred reclaim targets: they can be freed instantly (just drop the page, data is on disk). Dirty pages must be written back before reclaim. Anonymous pages (process heap/stack) must be swapped out, which is slower and more expensive:

Reclaim Priority Order (simplified):
══════════════════════════════════════════════════════════════

1. Clean file-backed pages     ← cheapest: just free the page
2. Dirty file-backed pages     ← must writeback first, then free
3. Anonymous pages (swap)      ← most expensive: swap out to disk

This is why Linux uses "swappiness" — it's a tuning knob:
  vm.swappiness = 60 (default)
    Low value  → prefer reclaiming file-backed pages over swapping
    High value → more willing to swap out anonymous pages
    Value 0    → only swap under extreme memory pressure
						
# Observe page cache under memory pressure

# 1. Current cache and swap state
cat /proc/meminfo | grep -E "^Cached:|^SwapTotal:|^SwapFree:|^SwapCached:"
sysctl vm.swappiness

# 2. Fill page cache with a large file read
# (Pick a file that's 2x RAM for visible effect on small VMs)
LARGE=$(find / -type f -size +100M 2>/dev/null | head -1)
echo "Reading $LARGE (this will fill page cache)..."
cat "$LARGE" > /dev/null 2>/dev/null
echo "Cache after read:"
cat /proc/meminfo | grep "^Cached:"

# 3. Drop caches and observe reclaim
echo "=== Dropping page cache ==="
echo 1 | sudo tee /proc/sys/vm/drop_caches > /dev/null  # drop page cache
cat /proc/meminfo | grep "^Cached:"
echo "=== Dropping all (page cache + dentries + inodes) ==="
echo 3 | sudo tee /proc/sys/vm/drop_caches > /dev/null
cat /proc/meminfo | grep "^Cached:"

# 4. Page reclaim stats
grep -E "^pgsteal_|^pgscan_|^kswapd_|^compact_" /proc/vmstat | head -20
# pgsteal_kswapd: pages reclaimed by kswapd
# pgscan_kswapd:  pages scanned by kswapd
# High scan-to-steal ratio = memory pressure

# 5. Per-zone memory states
cat /proc/zoneinfo | grep -A5 "Node 0, zone" | head -30

# 6. Watch reclaim in action (needs bpftrace)
sudo bpftrace -e '
kprobe:shrink_page_list {
    printf("reclaim: nr_to_scan=%lu\n", arg1);
}
kretprobe:shrink_page_list /retval >= 0/ {
    printf("  → freed %lu pages\n", retval);
}'

Direct I/O: Bypassing the Page Cache

Applications that manage their own caching (databases, virtual machines) can use O_DIRECT to bypass the page cache entirely. Direct I/O transfers data directly between the user buffer and the block device:

Direct I/O Path vs Buffered I/O:
══════════════════════════════════════════════════════════════

Buffered (default):
  read(fd, buf, 4096)
      │
      ▼
  generic_file_read_iter()
      │
      ├── Hit: copy_page_to_iter() ← page cache
      └── Miss: readahead → submit_bio() → page cache → copy to user

Direct (O_DIRECT):
  read(fd, buf, 4096)
      │
      ▼
  generic_file_direct_read()
      │
      ├── Flush any dirty cached pages for this range
      ├── Allocate DIO structure
      ├── submit_bio() directly to block layer
      │     ← No page cache involved!
      ├── Wait for completion
      └── Return data directly to user buffer

Requirements for O_DIRECT:
  - Buffer, length, and file offset aligned to the device logical block size
    (512 bytes on older disks, 4096 bytes on most modern SSDs and NVMe)
  - No memory pressure on cache (good for DBs)
  - No read-ahead, no write buffering, no cache coherency issues
						
# Direct I/O demonstration

# Attempt O_DIRECT with a 1K transfer (fails on 4K logical-block devices)
dd if=/dev/zero of=/tmp/direct_test bs=1K count=10 oflag=direct 2>&1
# Output: dd: error writing '/tmp/direct_test': Invalid argument
# Reason: 1K is a multiple of 512 but not of the 4K logical block size

# Correct: 4K aligned, valid for 512-byte and 4K logical-block devices
dd if=/dev/zero of=/tmp/direct_test bs=4K count=100 oflag=direct 2>&1

# Check cache residency — O_DIRECT write should NOT populate cache
echo "=== Before O_DIRECT ==="
fincore /tmp/direct_test 2>/dev/null || echo "(file not in cache yet)"
cat /proc/meminfo | grep "^Cached:"

dd if=/dev/zero of=/tmp/direct_test bs=1M count=100 oflag=direct conv=notrunc 2>/dev/null

echo "=== After O_DIRECT ==="
fincore /tmp/direct_test 2>/dev/null || echo "(still not cached)"

# For comparison, buffered write fills cache:
dd if=/dev/zero of=/tmp/cached_test bs=1M count=100 2>/dev/null
fincore /tmp/cached_test 2>/dev/null
# Shows pages in cache!
cat /proc/meminfo | grep "^Cached:"

# Clean up
rm -f /tmp/direct_test /tmp/cached_test

import mmap, os

import mmap, os
tmpf = '/tmp/pgcache_mmap'
with open(tmpf, 'wb') as f:
    f.write(b'X' * 4096)
fd = os.open(tmpf, os.O_RDWR)
