System Call Dispatch

Deep dive into Linux syscall dispatch - entry_SYS CA LL_64, syscall/sysret instruction pair, SYS CA LL_DEFINEn macros, seccomp-BPF, Syscall User Dispatch, vDSO, ptrace mechanics, K PT I overhead, and the syscall table.

Overview

Every system call crosses from user mode to kernel mode and back, and that crossing is where security controls, tracing, and performance all meet. This article follows the path from the syscall instruction through the entry stub, the dispatch table, and the return trampoline, and shows where seccomp, ptrace, the vDSO, and K PT I intervene. After reading it you can read the entry code and reason about the cost and the attack surface of a syscall.

  • System Calls - user-space view of the syscall table, strace, vDSO, raw invocation
  • Kernel Architecture - kernel layout, entry points, ring transitions, kernel stack

The Ring 0 Crossing

Every instruction that transitions from ring 3 (user) to ring 0 (kernel) is essentially an interrupt

  • NMI, exception, hardware IR Q, or software interrupt. syscall is
the fastest because it performs the absolute minimum state save required to enter the kernel, leaving the rest to software. 

The syscall instruction (x86-64) performs atomically:
┌─────────────────────────────────────────────────────────────┐
│ 1. Store RIP → RCX   (user return address)                  │
│ 2. Store RFLAGS → R11 (user flags)                          │
│ 3. Load new RIP ← MSR_LSTAR  (kernel syscall entry point)   │
│ 4. Load new CS  ← MSR_STAR[47:32] (kernel code segment)     │
│ 5. Load new SS  ← MSR_STAR[47:32] + 8 (kernel stack segment)│
│ 6. Mask RFLAGS with MSR_FMASK (clear IF, AC, NT, TF, etc.)  │
│ 7. Set CPL to 0 (ring 0)                                    │
└─────────────────────────────────────────────────────────────┘

Total cost: ~100-150 CPU cycles on modern Intel (Ice Lake+)
vs int 0x80: ~700-1000 cycles (full interrupt dispatch)

Key MSRs for syscall

MSR Name MSR Addr Purpose
LSTAR 0xC0000082 Long System Target Address Register -> kernel RIP after syscall
STAR 0xC0000081 SYSCALL Target Address Register -> bits 47:32 = kernel CS; bits 63:48 = user CS (for sysret)
FMASK 0xC0000084 RFLAGS mask applied on syscall entry -> clears IF (interrupts off inside kernel)
EFER 0xC0000080 Bit 0 = SCE (SysCall Enable); Must be set for syscall/sysret to work 
# Read MSR values (requires msr-tools)
sudo modprobe msr
sudo rdmsr -a 0xC0000082  # LSTAR: all CPUs' syscall entry points
sudo rdmsr -a 0xC0000081  # STAR: SS/CS segment selectors
sudo rdmsr -a 0xC0000084  # FMASK: RFLAGS mask

# Verify SCE (SysCall Enable) bit
sudo rdmsr 0xC0000080 | awk '{print and(strtonum($1), 1) ? "SCE=1 (enabled)" : "SCE=0"}'

# Dump all syscall-related MSRs
for msr in 0xC0000080 0xC0000081 0xC0000082 0xC0000084; do
    printf "MSR 0x%x: " $msr
    sudo rdmsr $msr 2>/dev/null || echo "unreadable"
done

The Entry Point: entry_SYSCALL_64

The entry point in 'arch/x86/entry/entry_64.S' is a masterpiece of assembly engineering - it must save the user context, switch to the kernel stack, enable kernel mitigations, call the right handler, then cleanly return. 

entry_SYSCALL_64 execution flow:

syscall            ← User executes 'syscall'
  │
  ▼
entry_SYSCALL_64   ← RIP loaded from MSR_LSTAR
  │
  │  1. swapgs_unsafe_stack    ← switch GS base to kernel GS
  │                              (kernel per-CPU pointer → GS_BASE)
  │
  │  2. push %rax (pt_regs→orig_ax)
  │
  │  3. PUSH_AND_CLEAR_REGS    ← save all regs to kernel stack
  │     push %rdi, %rsi, %rdx, %rcx, %rax, %r8, %r9, %r10, %r11
  │     push %rbx, %rbp, %r12, %r13, %r14, %r15
  │
  │  4. IBRS / retpoline microcode (if Spectre v2 mitigation)
  │
  │  5. Save user stack pointer: mov %rsp, PER_CPU_VAR(cpu_tss_rw + TSS_sp2)
  │     Stack switch: mov PER_CPU_VAR(pcpu_hot + X86_top_of_stack), %rsp
  │
  │  6. push 5*8(%rax)  ← push 5th stack frame slot
  │
  │  7. STACKLEAK_ERASE  ← erase unused kernel stack (if enabled)
  │
  │  8. do_syscall_64(regs, nr)
  │     │
  │     ├──► conti_emu: handle 32-bit compat syscalls on 64-bit kernel
  │     │
  │     ├──► Check nr >= NR_syscalls → return -ENOSYS
  │     │
  │     └──► regs->ax = sys_call_table[nr](regs)
  │          │
  │          └──► [handle: ptrace_check, seccomp, audit]
  │               └──► [handle: mitiations, KPTI trampoline]
  │                    └──► sysretq

GPR Save/Restore Layout

// arch/x86/include/asm/ptrace.h
struct pt_regs {
    unsigned long r15;
    unsigned long r14;
    unsigned long r13;
    unsigned long r12;
    unsigned long bp;         // RBP
    unsigned long bx;         // RBX
    // --- arguments (syscall args) ---
    unsigned long r11;
    unsigned long r10;
    unsigned long r9;
    unsigned long r8;
    unsigned long ax;         // RAX (retval on return)
    unsigned long cx;         // RCX (saved RIP)
    unsigned long dx;         // RDX (arg3)
    unsigned long si;         // RSI (arg2)
    unsigned long di;         // RDI (arg1)
    unsigned long orig_ax;   // Original syscall number
    unsigned long ip;         // RIP (saved)
    unsigned long cs;         // CS
    unsigned long flags;      // RFLAGS
    unsigned long sp;         // RSP (user stack ptr)
    unsigned long ss;         // SS
    // --- end: top of stack ---
};

The sys_call_table

The syscall table is the kernel's dispatch array - one array of function pointers, indexed by syscall number. It is architecture-specific and lives in read-only memory after boot. 

// arch/x86/entry/syscall_64.c (simplified)
#define __SYSCALL(nr, sym) [nr] = sym,
asmlinkage const sys_call_ptr_t sys_call_table[] = {
#include <asm/syscalls_64.h>   // Generated from syscall_64.tbl
};
// Example: [0] = __x64_sys_read, [1] = __x64_sys_write, ...

// Type of each entry:
typedef void (*sys_call_ptr_t)(void);

// The actual cast happens in do_syscall_64():
// sys_call_table[nr](regs)
// Each handler receives (struct pt_regs *) and returns via regs->ax

The SYSCALL_DEFINEn Macros

Every syscall in the kernel source is defined with the SYSCALL_DEFINEn() macro family. These macros handle type annotations, __user pointer sanitization metadata, and architecture-specific boilerplate. 

// include/linux/syscalls.h

// The macro magic:
// SYSCALL_DEFINE3(read, unsigned int, fd, char __user *, buf, size_t, count)
// expands to:
//   1. struct for types: struct __TYPE_read { unsigned int fd; char *buf; size_t count; };
//   2. asmlinkage long __x64_sys_read(const struct pt_regs *regs) { ... unpack regs ... }
//   3. static inline long __do_sys_read(unsigned int fd, char __user *buf, size_t count)
//   4. asmlinkage long __ia32_sys_read(const struct pt_regs *regs)  (if CONFIG_IA32_EMULATION)

// Example expansion of SYSCALL_DEFINE3(write, ...):
asmlinkage long __x64_sys_write(const struct pt_regs *regs)
{
    return __se_sys_write(
        (unsigned int)regs->di,      // fd
        (const char __user *)regs->si, // buf
        (size_t)regs->dx              // count
    );
}

static long __se_sys_write(unsigned int fd, const char __user *buf, size_t count)
{
    long ret = __do_sys_write(fd, buf, count);
    // Instrumentation points (trace_sys_enter/trace_sys_exit) inserted here
    return ret;
}

// The actual implementation:
static long __do_sys_write(unsigned int fd, const char __user *buf, size_t count)
{
    // The driver code goes here
    return ksys_write(fd, buf, count);
}

Maximally
rcx is clobbered by syscall instruction; r10 replaces it.

Why r10, not rcx?
syscall saves RIP -> RCX. The original 4th arg must therefore NOT be in RCX.
The x86-64 ABI uses R10 for the 4th syscall argument.

User Pointer Sanitization

At the kernel entry, user-supplied pointers are just numbers. Before dereferencing them, the kernel must validate: 

// arch/x86/include/asm/uaccess.h

// access_ok() — fast range check: is the entire [ptr, ptr+size)
// region within the user address space?
#define access_ok(addr, size) \
    (__chk_range_not_ok((unsigned long)(addr), (size), user_addr_max()) == 0)

static inline bool __chk_range_not_ok(unsigned long addr, unsigned long size,
                                       unsigned long limit)
{
    // O(1): just checks addr + size doesn't overflow and fits in user range
    // On x86-64: limit = TASK_SIZE_MAX = 0x00007fffffffffff (47-bit VA)
    unsigned long sum = addr + size;
    return sum < addr || sum > limit;  // Overflow check + upper bound
}

// After access_ok, copy_from_user still might fault (race with munmap).
// The safe approach: use exception table entries.
// If the copy faults, the exception table points to a fixup that
// copies -EFAULT to the return value and jumps forward.
						
User Pointer Sanitization Flow:
════════════════════════════════

    User passes: ptr = 0x7fffffffe000, len = 0x1000

    access_ok(ptr, len):
        addr + len = 0x7ffffffff000
        user_addr_max() = 0x00007fffffffffff
        0x7ffffffff000 < 0x00007fffffffffff  →  OK

    copy_from_user(kbuf, ptr, len):
        ┌── stac (SMAP: allow kernel to access user memory)
        │   rep movsb  ← copy bytes
        │   └── if page fault → exception table lookup → fixup
        └── clac (SMAP: disallow again)

    Exception table (__ex_table section):
        Faulting addr → Fixup addr
        0xfffff...    → 0xfffff...     (jump here, set rax = len - copied)

    The put_user/get_user macros use uaccess_error patterns:
        get_user(val, ptr) → if fails, return -EFAULT

# Examine exception table size

sudo cat /proc/kallsyms | grep '__stop___ex_table'

seccomp-BPF

seccomp (secure computing) allows a process to restrict its own syscall access. At each syscall entry, before the handler runs, the kernel evaluates a cBPF program that can kill the process, return an error, or allow the syscall through. 

seccomp evaluation point (in do_syscall_64):

    entry_SYSCALL_64
    │
    ▼
    do_syscall_64(regs, nr)
    │
    ├── if (secure_computing())  ← __secure_computing() evaluates BPF
    │   │
    │   ├── Iterate all seccomp filters on this task
    │   │   │
    │   │   ├── SECCOMP_RET_KILL_PROCESS → immediate SIGSYS
    │   │   ├── SECCOMP_RET_KILL_THREAD  → immediate SIGSYS
    │   │   ├── SECCOMP_RET_ERRNO        → regs->ax = -errno, return
    │   │   ├── SECCOMP_RET_TRAP         → SIGSYS with si_code=TRAP
    │   │   ├── SECCOMP_RET_LOG          → log + allow
    │   │   ├── SECCOMP_RET_ALLOW        → continue to syscall handler
    │   │   └── SECCOMP_RET_USER_NOTIF   → send to userspace listener
    │   │
    │   └── If KILL: send SIGSYS, never return to user
    │
    └── sys_call_table[nr](regs)
						
# Show seccomp state for a process
cat /proc/self/status | grep -i seccomp
# 0 = disabled, 1 = strict, 2 = BPF

# Trace seccomp events
sudo cat /proc/kallsyms | grep seccomp_filter

# strace with seccomp filter injection
strace -e inject=openat:error=ENOENT cat /etc/hostname

# Check process seccomp filter with bpftrace
sudo bpftrace -e 'kprobe:__seccomp_filter { printf("PID %d filters syscall %d\n", pid, arg1); }' -c 'sleep 1'

# Chrome/Firefox use seccomp extensively
cat /proc/$(pgrep -f firefox | head -1)/status | grep Seccomp

Syscall User Dispatch (SUD)

SUD reverses the typical model: instead of the kernel deciding dispatch, user space can intercept specified syscalls and handle them in a user-space handler. This enables Wine/Proton to emulate Windows syscalls and user-space threading libraries to implement custom behavior. 

Normal Path:                 SUD Path:
────────────                 ─────────
Application                  Application
    │ syscall                    │ syscall
    ▼                            ▼
Kernel handler              Kernel sees SUD selector matches
    │                            │
    │                            ├── SIGSYS → user-space signal handler
    │                            │   │
    │                            │   ▼
    │                            │ User-space handler (Wine, etc.)
    │                            │   │
    │                            │   ├── Translate Windows APIs or
    │                            │   │   implement custom threading
    │                            │   │
    │                            │   └── Return or re-syscall with
    │                            │       different arguments
    │                            │
    │                            └── (If not handled): kernel handler
    ▼                            ▼
Return to user               Return to user
						
// prctl-based configuration (kernel 5.11+)
prctl(PR_SET_SYSCALL_USER_DISPATCH,
      PR_SYSCALL_DISPATCH_FILTER_ALLOW,   // Mode
      offset_of_segment,                   // On: SIGSYS sent
      length_of_segment,                   // Off: normal dispatch
      &selector);                          // 8-byte selector variable

ptrace

strace works by using ptrace . For every syscall, ptrace generates two stops: one before the call ( PT RACE_SYS CA LL) and one after. 

strace's PTRACE workflow:

    1. strace forks child
    2. strace: ptrace(PTRACE_SEIZE, child_pid, 0, PTRACE_O_TRACESYSGOOD)
    3. strace: ptrace(PTRACE_SYSCALL, child_pid, 0, 0)
    4. strace: waitpid(child_pid) ← blocks until child hits syscall

    Child in kernel: do_syscall_64()
        │
        ├──► ptrace_report_syscall(entry)  ← STOP before call
        │    │ child SIGSTOP'd
        │    ▼
        │  strace wakes from waitpid(2)
        │  strace: ptrace(PTRACE_GETREGS) → get syscall number + args
        │  strace: prints "openat(AT_FDCWD, \"/etc/hostname\", ..."
        │  strace: ptrace(PTRACE_SYSCALL) → resume
        │
        └──► sys_call_table[nr](regs)  ← actual syscall executes

        ptrace_report_syscall(exit)  ← STOP after call
            │ child SIGSTOP'd
            ▼
          strace wakes
          strace: ptrace(PTRACE_GETREGS) → get return value
          strace: prints " = 3" (fd number)
          strace: ptrace(PTRACE_SYSCALL) → resume
						
// kernel/ptrace.c — the check in do_syscall_64():
static inline void syscall_trace_enter(struct pt_regs *regs)
{
    if (test_thread_flag(TIF_SYSCALL_TRACE))
        ptrace_report_syscall(regs, PTRACE_EVENTMSG_SYSCALL_ENTRY);

    if (test_thread_flag(TIF_SYSCALL_TRACEPOINT))
        trace_sys_enter(regs, regs->orig_ax);

    audit_syscall_entry(regs);
}

vDSO: Syscall Avoidance

Some syscalls are so frequent that the ring transition cost dominates. The vDSO is a shared library injected into every process by the kernel, providing in-process implementations of clock_gettime() , gettimeofday() , time() , and getcpu() - all without syscall . 

vDSO Memory Layout:
═══════════════════

    /proc/PID/maps:
    7ffff7fca000-7ffff7fcc000 r--p ... [vvar]          ← kernel-updated data page
    7ffff7fcc000-7ffff7fce000 r-xp ... [vdso]          ← executable vDSO code
    7ffff7fce000-7ffff7fd0000 r--p ... [vdso]          ← read-only data

    vvar page contains (updated by kernel timer tick):
        struct vdso_data {
            u32 seq;              // Sequence counter (seqlock)
            s32 clock_mode;
            u64 cycle_last;       // Last cycle counter reading
            u64 mask;
            u32 mult;             // Multiplier (cycles → nanoseconds)
            u32 shift;            // Shift (division by 2^shift)
            struct vdso_timestamp basetime[VDSO_BASES];
            // ... per-CPU data, timezone info
        };

    clock_gettime(CLOCK_MONOTONIC) in vDSO:
        1. Read TSC (rdtsc): ~20 cycles
        2. Read seq lock: if odd, retry (~99.9% no retry needed)
        3. Compute: nanoseconds = (tsc - cycle_last) * mult >> shift
        4. Add basetime
        5. Check seq lock after: if changed, retry
        Total: ~30-40 cycles vs ~200 cycles for a syscall
						
# Inspect vDSO
cat /proc/self/maps | grep -E 'vdso|vvar'

# Extract vDSO (it's a real ELF)
objdump -d /proc/self/exe 2>/dev/null; \
    # Actually, the vDSO is mapped, not in the binary
    # Copy it from process memory:
    # First, find the vdso address
VD=$(cat /proc/self/maps | grep '\[vdso\]' | head -1 | cut -d'-' -f1)
echo "vDSO at: 0x$VD"

# Disassemble vDSO functions
gdb -batch -ex "disassemble __vdso_clock_gettime" /proc/self/mem 2>/dev/null; \
    # Or:
objdump -d /usr/lib/modules/$(uname -r)/vdso/vdso64.so 2>/dev/null | \
    head -30

# Count clock_gettime calls (they should NOT appear via strace)
strace -e clock_gettime date 2>&1
# If nothing → vDSO is working

# Force syscall path (bypass vDSO)
LD_BIND_NOW=1 strace -e clock_gettime date 2>&1

perf_event_open and PMU Integration

The perf_event_open() syscall (number 298 on x86-64) is a meta-syscall - it configures hardware performance counters (PMU) to count events and deliver samples to user space via mmap'd ring buffers. It can also attach to tracepoints, kprobes, and software events. 

perf_event_open configuration:

    fd = syscall(SYS_perf_event_open, &attr, pid, cpu, group_fd, flags);

    struct perf_event_attr {
        __u32 type;           // PERF_TYPE_HARDWARE, SOFTWARE, TRACEPOINT, ...
        __u32 config;         // Event selector (depends on type)
        __u64 sample_period;  // or sample_freq
        // ... 80+ fields: precise_ip, exclude_kernel, exclude_user, ...
    };

    PMU Counter Event Encoding (x86 / PERF_TYPE_HARDWARE):
        config = (event_select << 0) | (umask << 8) | (any_thread << 21)
               | (edge << 18) | (inv << 23) | (cmask << 24);
						
# List available PMU events
perf list | head -30
sudo perf list tracepoint | head -20

# hardware event types
cat /sys/devices/cpu/events/instructions
cat /sys/devices/cpu/events/cache-misses

# Read PMU counters manually
perf stat -e instructions,cycles,cache-misses,branch-misses ls /

# perf_event_open in action — trace with strace
strace -e perf_event_open perf stat -e cycles true 2>&1

# Check PMU version and capabilities
cat /sys/devices/cpu/caps/pmu_name

# CPU-specific: Intel PEBS (Precise Event Based Sampling) events
cat /sys/devices/cpu/events/ 2>/dev/null

Syscall Table Hooking

Before KASLR was default, before kernel lockdown, and before sys_call_table became read-only, rootkits simply overwrote table entries: 

// HISTORICAL (pre-4.x, pre-KASLR) — DO NOT RUN
// This approach no longer works on modern kernels due to:
// 1. sys_call_table is in read-only memory (.rodata section)
// 2. KASLR randomizes its address
// 3. Kernel lockdown prevents /dev/mem writes
// 4. LKRG (Linux Kernel Runtime Guard) detects modifications

// Old hooking code (for educational reference):
unsigned long *sct = (unsigned long *)kallsyms_lookup_name("sys_call_table");
unsigned long orig_open = sct[__NR_openat];
sct[__NR_openat] = (unsigned long)hooked_openat;
// ^ This panics or silently does nothing on modern kernels

Modern Alternatives

1. ftrace-based hooking (kprobe with RETURN override):
   register_kprobe() + override_handler — used by livepatch, but detectable

2. Kprobes with instruction patching:
   register_kprobe() replaces first byte with INT3 (0xCC)

3. eBPF programs attached at tracepoint or kprobe level:
   bpf_trace_printk() or bpf_perf_event_output()

4. Static key patching via text_poke_bp():
   Legitimate kernel mechanism used by livepatch; hardware breakpoint-based

5. Page table manipulation:
   Remap .rodata as writable, modify, remap as read-only
   Constantly checked by kernel lockdown and LKRG

KPTI (Kernel Page Table Isolation)

Meltdown ( CVE -2017-5754) exploited that user code could speculatively read kernel memory because the kernel was mapped in every user page table entry. K PT I (formerly KAISER) removes kernel mappings from user page tables entirely. 

Without KPTI:
════════════

    User page table:              Kernel page table:
    0x0 – 0x7fffffffffff   user   0x0 – 0x7fffffffffff   user
    0xffff800000000000+    kernel 0xffff800000000000+    kernel
    ^─ mapped in both              ^─ full kernel mapping

    Problem: CPU speculatively accesses kernel-only page
    even in ring 3, revealing data through cache timing


With KPTI:
═════════

    User page table:              Kernel page table:
    0x0 – 0x7fffffffffff   user   0x0 – 0x7fffffffffff   user
    (kernel absent except          0xffff800000000000+    kernel
     minimal trampoline for
     syscall entry/exit)           ^─ kernel only visible in kernel PGD

    At syscall entry: CR3 switch to kernel page table
    At syscall exit:  CR3 switch back to user page table

    Cost: ~200-500 extra cycles per syscall (CR3 write + TLB flush)
    Mitigated by PCID (Process Context Identifier) — tags TLB entries
    so full flush is avoided
						
KPTI Trampoline Stacks:
════════════════════════

    User space          Trampoline           Kernel space
    ─────────          ───────────           ────────────
    user RSP
        │
        ▼
    push regs onto      TRAMPOLINE STACK:
    user stack          [small stack for
                         syscall entry]
        │                    │
        │   syscall          │
        │────────►───────────┤
        │                    │
        │              push kernel GS base
        │              SWITCH_CR3 to kernel PGD ← expensive!
        │                    │
        │              jump to kernel entry_64.S
        │                    │
        │              use KERNEL STACK
        │                    │
        │              ... do work ...
        │                    │
        │              return to trampoline
        │                    │
        │              SWITCH_CR3 to user PGD ← expensive!
        │              pop kernel GS
        │              sysretq
        │◄─────────
        │
    return to user
						
# Check if KPTI is active
cat /proc/cpuinfo | grep -o 'pti' | head -1
dmesg | grep -i 'page table isol'
dmesg | grep -i 'KPTI'

# PTI bit in /proc/cpuinfo
grep -c 'cpu_insecure' /proc/cpuinfo

# Measure syscall cost overhead due to KPTI
perf stat -e page-faults,dTLB-load-misses,iTLB-load-misses \
    taskset -c 0 perf bench syscall basic

# Disable KPTI at boot (bootloader config): pti=off
cat /proc/cmdline | grep -o 'pti=[^ ]*' || echo "pti not in cmdline"

The Return Path: sysretq

After the syscall handler finishes, do_syscall_64() sets regs->ax to the return value. The kernel then returns through several layers: 

    do_syscall_64() returns
        │
        ▼
    syscall_exit_to_user_mode()
        │
        ├── syscall_exit_work()  ← processes signals, resched, TIF bits
        │
        ├── exit_to_user_mode_prepare()  ← schedule if NEED_RESCHED
        │
        └── exit_to_user_mode_loop()
            │
            ▼
        arch_exit_to_user_mode_prepare()
            │
            ├── SWITCH_CR3 to user PGD (if KPTI)
            ├── IBRS / STIBP restore
            └── swapgs (restore user GS)
                │
                ▼
            USERGS_SYSRET64   ← macro expands to swapgs + sysretq
                │
                ▼
            sysretq: CPU loads RIP from RCX, RFLAGS from R11
                     Switch to ring 3
                     Continue user execution at saved RIP

Error Handling and Signals

Syscalls return -errno values, not raw negative numbers. The kernel's return path interprets negative values and user space's libc formats them: 

// include/linux/err.h — kernel error conventions
#define MAX_ERRNO   4095

// If regs->ax is between -4095 and -1, it's an error code.
// Otherwise, it's a success value.
static inline long IS_ERR_VALUE(unsigned long x)
{
    return (unsigned long)(void *)(x) >= (unsigned long)-MAX_ERRNO;
}

// In user-space libc (musl example):
// syscall returns -errno; libc stores errno = -ret, returns -1
// ret < 0 && ret > -4096 → errno = -ret, return -1

Signals from syscall context

// kernel/signal.c
// If a fatal signal is pending when returning to user mode:
// exit_to_user_mode_loop() calls do_signal() which:
void do_signal(struct pt_regs *regs)
{
    struct ksignal ksig;
    if (get_signal(&ksig)) {
        // SIGKILL or SIGSEGV: never returns — kills process
        do_group_exit(ksig.sig);
    }
    // Handler: set up signal frame on user stack, modify regs->ip
    handle_signal(&ksig, regs);
    // On resume: user code jumps to signal handler instead of
    // returning to the instruction after syscall
}
