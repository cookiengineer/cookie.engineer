GoGANet

Overview

GitHub Repository | GitLab Mirror

GoGANet trains and embeds network-traffic classifiers entirely in Go. It reads labelled capture recordings, renders every socket session into a multi-frame pixel image, and learns to separate malicious from normal network traffic with a conditional WGAN-GP that carries an auxiliary classifier head.

Most intrusion detection is either a static signature list or an overblown cloud service that filters network traffic after the fact.

GoGANet on the other hand is a self-contained library and command set, that you can drop into a honeypot, a gateway or a small edge box and score sessions on the device that actually sees the packets.

The interesting part is not that adversarial training can classify network traffic, it is that the whole thing, from capture reader to embedded weights, fits into one pure-Go module with no dependencies.

Features

  • Wasserstein critic with gradient penalty (lambda = 10, n_critic = 5) and LayerNorm instead of BatchNorm in the critic.
  • Auxiliary classifier head on the critic (AC-GAN style) that exposes a scalar realness score and class logits at once, plus a classification loss on the generator so generated traffic stays class-discriminative.
  • An exact gradient penalty, differentiated through a second-order reverse-mode autodiff tape, which is possible because the convolution operators are composed from linear primitives.
  • Two architectures: a dense MLP for small feature vectors and a strided/transposed convolutional model for image windows.
  • A multi-frame image representation of up to 32 frames of 1480 bytes, with a frame-presence channel that separates padding from real zero bytes and makes early-detection windows trainable.
  • Protocol adapters for DNS, HTTP/1, HTTP/2, HTTP/3 (QUIC, opaque), SNMP, ICMP, TLS (opaque) and a generic raw fallback that matches any flow.
  • Session grouping with label joining from CTU-13 *.binetflow files and IoT-23 Zeek conn.log.labeled logs.
  • Embedded classifier weights (versioned GGNT binaries) that need no external files at runtime.
  • Binary metrics (AUC, balanced accuracy, specificity, F1) and a holdout mode that measures cross-scenario generalisation.
  • AVX-512 SIMD kernels with a scalar fallback, so the same code builds and runs anywhere Go does with the optimum performance on CPUs.

Architecture

GoGANet is a data path followed by a model. A capture is streamed through a reader, decoded into frames, grouped into bidirectional sessions, filtered by a protocol adapter that selects the bytes to render, and finally rasterised into an image that the critic consumes.

pcap -> frames -> sessions -> adapter -> byte rows -> image -> WC-GAN -> malicious / non-malicious

The convolutional path consumes the planar layout (channels, frames*bytes), while the dense path consumes the row-major layout. The image planar method converts between them. Models train in pure Go and serialise to a versioned GGNT binary, which is what the classifiers package embeds.

Building

Go 1.27 or newer is required. Go's AVX-512 support is experimental and must be opted into:

make build;         # GOEXPERIMENT=simd go build ./...
make test;          # GOEXPERIMENT=simd go test ./...
make test-scalar;   # plain go test ./... (scalar fallback)

Testing

make test;          # unit and end-to-end tests with SIMD enabled
make test-scalar;   # proves the scalar fallback builds and passes
make bench;         # correctness, throughput and convergence benchmarks
make vet;

The suite covers the vector kernels against the scalar path within floating-point tolerance, gradient correctness, convolution gradients, serialization round-trips and convergence on synthetic fixtures.

Usage: Datasets

Download and extract both datasets with the helper script. It skips downloads whose files already exist and extraction whose directories are already populated, so it is safe to re-run:

./download-datasets.sh;              # CTU-13 and IoT-23
./download-datasets.sh --only ctu;   # just CTU-13
./download-datasets.sh --force;      # re-download
./download-datasets.sh --verify;     # gzip/bzip2 integrity check before extracting

A single CTU-13 scenario can also be extracted with the extractor:

go run ./examples/extract-ctu13 -scenario 4;

Usage: Training

Inspect the protocol and label balance of a scenario, then train and benchmark:

go run ./examples/analyze-ctu13 -dir datasets/ctu-13/4;

# Whole CTU-13 dataset, one protocol, saved to classifiers/weights/http1.ggnt
go run ./examples/train-ctu13 -dir datasets/ctu-13 -protocol http1 -arch conv -epochs 10;

# Benchmark a saved or embedded model on a cross-scenario holdout
go run ./examples/benchmark-ctu13 -dir datasets/ctu-13 -protocol http1 -holdout 1,8;

IoT-23 stores one directory per capture with PCAPs and a Zeek conn.log.labeled file. train-iot23 discovers captures recursively and joins labels from the Zeek log, so the same flags apply:

go run ./examples/train-iot23 -dir datasets/iot-23 -protocol http1 -arch conv -epochs 10;
go run ./examples/train-iot23 -dir datasets/iot-23 -protocol http1 -holdout Capture-1;

Usage: Classifying

The repository ships a single model, classifiers/weights/bundled.ggnt, trained on every campaign from both datasets with the raw adapter, so each campaign's flows are represented. It uses the 8x64x2 window:

# Reproduce the bundled model (all campaigns, bounded per capture).
go run ./examples/train-bundled -epochs 3;

# Classify each session in a capture.
go run ./examples/classify-session -pcap capture.pcap -protocol raw;

# Inspect the rendered image geometry for a capture.
go run ./examples/inspect-image -pcap capture.pcap -protocol dns;

Usage: Embedding

Trained weights are embedded at compile time, so a classifier can be used without any external files. classifiers.New returns an embedded model, classifiers.Available lists the embedded protocols, and classifiers.Wrap wraps a model held in memory:

clf, err := classifiers.New("bundled")
if err != nil {
    log.Fatal(err)
}

img := pipeline.Render(session, adapter.ByName("raw"), clf.Shape())

result, err := clf.Classify(img)
if err != nil {
    log.Fatal(err)
}

log.Printf("%s p(malicious)=%.3f score=%+.3f", result.Protocol, result.Probability, result.Score)

Rebuild after adding or updating a weight file, because embedding is resolved at compile time.

Benchmark Results

Both datasets were trained with the convolutional model on 8x64x2 window images, LeakyReLU 0.2, no BatchNorm and the exact WGAN-GP penalty.

Dataset Adapter Split AUC(clf) Bal. acc Specificity
CTU-13 http1 random 0.998 0.999 1.000
CTU-13 http1 holdout {1,8} 0.537 0.746 0.500
CTU-13 raw random 0.989 0.833 0.667
CTU-13 raw holdout {1,8} 0.767 0.580 0.162
IoT-23 raw random 0.978 0.962 0.947
IoT-23 raw holdout Capture-1-1 0.978 0.978 0.957

CTU-13 ships botnet-filtered captures with roughly 99% malicious sessions, so a classifier learns to answer "malicious" for almost everything and specificity collapses. IoT-23 contains large benign volumes (device background traffic and honeypot captures, around 20-30% benign in the sampled set), which is enough to train a genuinely balanced classifier that still generalises to a completely held-out capture. The key difference between the two is the data, not the model.

The bundled model reaches accuracy 0.917, balanced accuracy 0.867, specificity 0.780 and AUC 0.928 on its held-out session split. That split is random, so the same captures appear in train and test; treat it as indicative, not as a cross-campaign score.
