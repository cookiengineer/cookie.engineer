Heap

Dynamic memory allocation - malloc() internals, ptmalloc2 arenas and bins, tcache, chunk structure, sbrk vs mmap, and heap profiling tools.

Overview

The heap is the region of a process that holds dynamically allocated memory, memory that lives until the program frees it. Unlike the stack, allocation and deallocation are driven by the program, so the allocator keeps its own bookkeeping structures to track free and used space. This article walks through the glibc allocator: how it asks the kernel for memory, how it organizes chunks and bins, what happens on every allocation and free, and which tools expose the resulting layout.

What the Heap Is

The heap is the region of a process's address space where dynamically allocated memory lives

  • memory whose lifetime is not tied to function scope. Unlike the stack, which auto-frees
on return, heap memory persists until explicitly freed by free() . The heap sits between the BSS segment and the mmap region, growing upward (toward higher addresses) as brk() is called.

Virtual Address Space:
┌──────────────────────┐ 0x0000000000000000
│  Text (.text)        │
├──────────────────────┤
│  Data (.data, .bss)  │ ← Static/global variables
├──────────────────────┤ ← program break (brk)
│  HEAP                │ ← malloc() region, grows upward
│    ...               │
│    ...               │
│    ┌──────────────┐  │
│    │ Allocated chk│  │
│    ├──────────────┤  │
│    │ Free chunk   │  │
│    ├──────────────┤  │
│    │ Allocated chk│  │
│    ├──────────────┤  │
│    ▼               │  │
├──────────────────────┤
│  mmap gap            │ ← Space between heap and libs
├──────────────────────┤
│  Shared libraries    │ ← libc, ld-linux, .so files
├──────────────────────┤
│  Stack               │ ← Function calls, grows downward
└──────────────────────┘

How malloc() Gets Kernel Memory

malloc() is a user-space library, not a syscall. It requests memory from the kernel through two mechanisms:

// Small allocations: move the program break upward
// brk(NULL) returns the current program break
// brk(addr) sets the break to addr
void* ptr = sbrk(0);    // Current break
sbrk(4096);             // Extend heap by 4096 bytes
// Equivalent: brk(ptr + 4096);

// Large allocations: create a separate mapping
void* big = mmap(NULL, 1024*1024, PROT_READ|PROT_WRITE,
                 MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
						
# Observe which mechanism a program uses
strace -e brk,mmap ls 2>&1 | head -20
# Small allocations: brk(NULL) → brk(some_addr) — heap extends
# Large / many: mmap(NULL, ..., MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)
Allocation Size glibc Behavior
<= 128 KiB (default) Use arena (sbrk/brk) - from the main heap
> 128 KiB Use mmap() - separate anonymous mapping
Freed mmap chunks munmap() returns memory to OS immediately
Freed brk chunks Kept in arena; top chunk may shrink with MADV_DONTNEED

glibc ptmalloc2 Architecture

glibc uses ptmalloc2 (derived from Doug Lea's dlmalloc, rewritten by Wolfram Gloger). It organizes memory into arenas to reduce lock contention in multi-threaded programs:

Process:
┌──────────────────────────────────────────────┐
│                                              │
│  Main Arena (uses sbrk/brk)                  │
│  ┌──────────────────────────────────────┐    │
│  │ Fastbins: [16] [24] [32] [48] [64]  │    │
│  │           [80] [96] [112] [128]      │    │
│  │ Each: singly-linked LIFO list        │    │
│  ├──────────────────────────────────────┤    │
│  │ Smallbins: [32] [48] ... [1008]      │    │
│  │ 62 bins, each: doubly-linked, FIFO  │    │
│  ├──────────────────────────────────────┤    │
│  │ Largebins: [1024+] → [∞]            │    │
│  │ 63 bins, sorted by size, best-fit   │    │
│  ├──────────────────────────────────────┤    │
│  │ Unsorted bin: recently freed chunks  │    │
│  │ cache-like, 1 bin, doubly-linked    │    │
│  ├──────────────────────────────────────┤    │
│  │ Top chunk: unallocated space at end  │    │
│  │ Allocations come from here first     │    │
│  ├──────────────────────────────────────┤    │
│  │ Tcache (per-thread) ← glibc 2.26+   │    │
│  │ [64 bins, each 64 entries max]       │    │
│  └──────────────────────────────────────┘    │
│                                              │
│  Thread Arena 1 (uses mmap)                  │
│  ┌──────────────────────────────────────┐    │
│  │ (same bin structure as main arena)   │    │
│  │  ± tcache per thread                 │    │
│  └──────────────────────────────────────┘    │
│                                              │
│  Thread Arena N                              │
│  ┌──────────────────────────────────────┐    │
│  │ ...                                   │    │
│  └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘

Number of arenas formula

num_arenas = 8 * num_cpus   # 64-bit
num_arenas = 2 * num_cpus   # 32-bit

For an 8-core 64-bit system: up to 64 arenas. M_ARENA_MAX can cap the total. Each arena has its own mutex. Threads are assigned to arenas round-robin.

glibc Bins Reference Table

Bin Type Count Range Structure Strategy
Fastbins 10 32, 48, 64, 80, 96, 112, 128 Singly-linked LIFO O(1), never coalesced
Tcache 64 32-1040 Singly-linked LIFO Per-thread, no locking, counts 0-7 per size
Smallbins 62 32-1008 (16B steps) Doubly-linked FIFO Exact fit only; coalesced with neighbors
Largebins 63 1008+ Doubly-linked, sorted by size Best-fit; coalesced
Unsorted bin 1 Any Doubly-linked circular Temporary staging; iterated on next malloc

Chunk Structure

Every allocated or free block of heap memory is preceded by metadata called a chunk header. The user receives a pointer past this header.

Allocated chunk:
┌────────────────────────┐
│ prev_size     │ size   │ ← 8 + 8 = 16 bytes overhead (x86-64)
│ (8 bytes)     │ (8 B)  │
├────────────────────────┤
│                        │
│  User data             │ ← Pointer returned by malloc()
│  (requested size)      │
│                        │
├────────────────────────┤
│  (next chunk begins)   │

Free chunk (doubly-linked in a bin):
┌────────────────────────┐
│ prev_size     │ size   │ ← 8 + 8 = 16 bytes overhead
├────────────────────────┤
│ fd            │ bk     │ ← Forward/backward pointers in free list
│ (8 bytes)     │ (8 B)  │
├────────────────────────┤
│                        │
│  Unused space          │
│                        │
├────────────────────────┤

size field bits: The chunk size is stored as a multiple of 16 (on x86-64), with the low 3 bits used as flags:

size field (64-bit):
┌────────────────────────────────────────────────────────────┐
│  Chunk size (multiple of 16)                   │ N │ M │ P │
└────────────────────────────────────────────────────────────┘
                                                          │
                                        PREV_INUSE ──────┘ (bit 0)
                                        IS_MMAPPED ─────── (bit 1)
                                        NON_MAIN_ARENA ─── (bit 2)
  • PREV_INUSE (P) : The previous chunk is in use. Used for coalescing decisions.
  • IS_MMAPPED (M) : This chunk was allocated via mmap.
  • NON_MAIN_ARENA (N) : This chunk belongs to a non-main arena.
// Inspect chunk metadata
#include <stdio.h>
#include <stdlib.h>
#include <malloc.h>

int main() {
    void *p1 = malloc(24);
    void *p2 = malloc(24);
    void *p3 = malloc(1024);

    printf("malloc(24) → usable size: %zu\n", malloc_usable_size(p1));
    printf("  Header at %p, data at %p\n",
           (char*)p1 - 16, p1);  // Header is 16 bytes before data on x86-64
    printf("  Chunk size: %zu\n", *(size_t*)((char*)p1 - 8) & ~0x7);

    printf("  Next chunk size: %zu\n",
           *(size_t*)((char*)p1 - 8 + malloc_usable_size(p1) + 16) & ~0x7);

    free(p1);
    free(p2);
    free(p3);
    return 0;
}

malloc_usable_size() vs Requested Size

malloc(n) may allocate more than n bytes. malloc_usable_size(ptr) returns the actual usable space. The overhead is: - Minimum chunk size : 32 bytes on x86-64 (16 header + 16 min data)

  • Alignment : 16-byte aligned on x86-64
  • Padding : Rounded up to next 16-byte boundary

What Happens During free()

Calling free(ptr) does NOT necessarily return memory to the OS. The sequence depends on the chunk:

free(ptr):
    │
    ▼
┌──────────────────────────────────────────────────────┐
│  Is ptr NULL?                                        │
│  Yes → return immediately (free(NULL) is safe)       │
│  No  → continue                                      │
├──────────────────────────────────────────────────────┤
│  Is chunk mmap'd? (IS_MMAPPED flag)                  │
│  Yes → munmap() immediately, return to OS            │
│  No  → continue                                      │
├──────────────────────────────────────────────────────┤
│  Is chunk in tcache bin size range?                   │
│  Is tcache bin not full? (< 7 entries by default)    │
│  Yes → push to tcache bin; return                    │
│  No  → continue                                      │
├──────────────────────────────────────────────────────┤
│  Is chunk in fastbin size range?                      │
│  Yes → push to fastbin (LIFO, no coalescing)         │
│  No  → continue                                      │
├──────────────────────────────────────────────────────┤
│  Not fastbin-eligible:                               │
│  - Check if adjacent chunks are free                 │
│  - Coalesce (merge) backward if prev is free         │
│  - Coalesce (merge) forward if next is free          │
│  - Place merged chunk in unsorted bin                │
│  - If merged chunk touches top chunk → absorb        │
└──────────────────────────────────────────────────────┘

Coalescing merges adjacent free chunks into a larger one, reducing fragmentation. The PREV_INUSE bit on the next chunk tells whether the current chunk can be merged backward. The forward merge checks if the chunk after the next chunk has its PREV_INUSE bit clear.

tcache (Thread Cache) - glibc 2.26+

The tcache is a per-thread cache that sits in front of all other bins. It's lock-free (thread-local) and provides fast reuse for small allocations:

// Simplified tcache representation
typedef struct tcache_entry {
    struct tcache_entry *next;  // Singly-linked
    // Optional: key field for double-free detection
} tcache_entry;

typedef struct tcache_perthread_struct {
    uint16_t counts[TCACHE_MAX_BINS];  // 64 entries
    tcache_entry *entries[TCACHE_MAX_BINS];  // 64 bin heads
} tcache_perthread_struct;
Property Value
Number of bins 64
Size range 32 to 1040 bytes (16B increments)
Max entries per bin 7 (tcache_count)
Locking None (per-thread, no contention)
Coalescing Never - tcache chunks are not merged

The tcache dramatically improves performance for workloads with many small, short-lived allocations. However, it bypasses many consistency checks that other bins perform, making it a common target for heap exploitation.

sbrk() for Small, mmap() for Large

The threshold for using mmap() instead of sbrk() is determined by M_MMAP_THRESHOLD :

#include <malloc.h>
#include <stdio.h>

int main() {
    /* Default threshold is 128 * 1024 = 131072 bytes. Lower it to 4 KiB so
       that medium allocations use mmap instead of brk. mallopt() returns 1
       on success and 0 on error. */
    if (mallopt(M_MMAP_THRESHOLD, 4096) == 0) {
        fprintf(stderr, "mallopt failed\n");
        return 1;
    }

    printf("mmap threshold set to 4096 bytes\n");

    /* Also adjustable via environment: MALLOC_MMAP_THRESHOLD_=4096 ./program */
    return 0;
}
						
# Trace to see when sbrk vs mmap is used
MALLOC_MMAP_THRESHOLD_=4096 strace -e brk,mmap,mprotect ./chunk-demo 2>&1 | grep -E 'brk|mmap'

Heap vs Other Memory Regions

Region Lifespan Size Allocation
Text Program life Fixed Compile-time
Data (init) Program life Fixed Compile-time
BSS (0-init) Program life Fixed Compile-time
Heap Manual Dynamic malloc/free
Stack Automatic Dynamic Function scope
mmap (anon) Manual Dynamic mmap/munmap
mmap (file) Manual File size mmap/munmap 
#include <stdio.h>
#include <stdlib.h>

int data_init = 42;        // .data (initialized)
int bss_zero;              // .bss (zeroed)
const int rodata = 100;    // .rodata (read-only)

int main() {
    static int data_static = 7;   // .data
    int stack_var = 1;            // Stack
    char* heap_var = malloc(64);  // Heap

    printf("Text (main):     %p\n", main);
    printf(".data:           %p\n", &data_init);
    printf(".bss:            %p\n", &bss_zero);
    printf(".rodata:         %p\n", &rodata);
    printf("Stack:           %p\n", &stack_var);
    printf("Heap:            %p\n", heap_var);

    free(heap_var);
    return 0;
}

Heap Profiling Tools

# massif — Valgrind's heap profiler
valgrind --tool=massif --massif-out-file=/tmp/massif.out ./your-program
ms_print /tmp/massif.out | less
# Shows heap usage over time: peak, allocation rate, where allocations happen

# mtrace — glibc's built-in allocation tracer
cat > /tmp/mtrace-test.c << 'EOF'
#include <mcheck.h>
#include <stdlib.h>
int main() {
    mtrace();  // Start tracing
    void* p = malloc(100);
    // free(p);  // Uncomment to fix the leak
    muntrace();  // Stop tracing
    return 0;
}
EOF
gcc -o /tmp/mtrace-test /tmp/mtrace-test.c

MALLOC_TRACE=/tmp/mtrace.log /tmp/mtrace-test
mtrace /tmp/mtrace-test /tmp/mtrace.log
# Shows unfreed allocations with backtrace

# ltrace — library call tracer
ltrace -e malloc+free+realloc+calloc ls 2>&1 | head -20

# strace — system call level
strace -e brk,mmap,munmap,mprotect ls 2>&1

# /proc/self/maps — current heap boundaries
cat /proc/self/maps | grep heap

Dumping and Inspecting Heap Contents

# Read heap memory of a running process (requires root or ptrace scope)
sudo cat /proc/$(pidof program)/maps | grep heap
# 55555555a000-55555557b000 rw-p 00000000 00:00 0  [heap]

# Dump heap:
sudo dd if=/proc/$(pidof program)/mem bs=1 skip=$((0x55555555a000)) \
        count=$((0x55555557b000 - 0x55555555a000)) | hexdump -C | head -50

# Or with gdb:
gdb -p $(pidof program)
(gdb) info proc mappings
(gdb) find /w 0x55555555a000, 0x55555557b000, 0x41414141  # Search for 'AAAA'

Verification Checklist

# 1. Check heap boundaries
cat /proc/self/maps | grep heap

# 2. Count how many malloc/free happen during a command
ltrace -e malloc+free ls 2>&1 | grep -c malloc

# 3. Test malloc overhead
python3 -c "
import os
# Using the posix malloc wrapper
data = [b'x' * 64 for _ in range(10000)]
# Read /proc/self/status for VmData
pid = os.getpid()
with open(f'/proc/{pid}/status') as f:
    for line in f:
        if 'VmData' in line:
            print(line.strip())
"

# 4. Inspect malloc trim behavior
man mallopt  # Read M_TRIM_THRESHOLD

# 5. Profile heap with massif on a simple program
echo 'int main(){for(int i=0;i<1000;i++) malloc(1024); return 0;}' > /tmp/heap-test.c
gcc -o /tmp/heap-test /tmp/heap-test.c
valgrind --tool=massif /tmp/heap-test 2>&1 | grep -A5 'total heap'

# 6. System-wide memory usage
free -h
cat /proc/meminfo | grep -E 'MemTotal|MemFree|MemAvailable|Cached'

Challenge

Write a Go program that decodes a glibc heap chunk chain from a hex dump. The input is one 64-bit little-endian value per line, starting at the first chunk header. For each chunk, print the prev_size , the size with the low three flag bits masked off, and the active flags ( PREV_INUSE , IS_MMAPPED , NON_MAIN_ARENA ). Advance to the next chunk by the raw size value in bytes, so the walk follows the real chunk chain and stops at the top chunk.

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func flags(size uint64) string {
	var names []string
	if size&0x1 != 0 {
		names = append(names, "PREV_INUSE")
	}
	if size&0x2 != 0 {
		names = append(names, "IS_MMAPPED")
	}
	if size&0x4 != 0 {
		names = append(names, "NON_MAIN_ARENA")
	}
	return strings.Join(names, "|")
}

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	var words []uint64
	for scanner.Scan() {
		w := strings.TrimSpace(scanner.Text())
		if w == "" || strings.HasPrefix(w, "#") {
			continue
		}
		v, err := strconv.ParseUint(w, 16, 64)
		if err != nil {
			fmt.Fprintln(os.Stderr, err)
			os.Exit(1)
		}
		words = append(words, v)
	}

	// TODO: walk the dump two words at a time. For each chunk print
	// prev_size, size&^0x7, and flags(size). Advance the index by
	// (size&^0x7)/8 words. Stop when the size is zero.
	_ = words
	_ = flags
}

Feed it the x/20gx dump from the GDB listing above with the 0x...: addresses stripped, and check that the first chunk reports size 0x50 with PREV_INUSE set.
