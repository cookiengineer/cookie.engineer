Cookie's Antibote

Overview

GitHub Repository | GitLab Mirror

The Antibote project is my attempt to uncover botnets on GitHub and GitLab with shared operators.

A lot of GitHub accounts are bots that are parts of the same shared botnet. Turns out, different botnet operators have different PGP keys that they use to push commits to those accounts.

This tool scrapes a user's social connections on GitHub and maps the keys back to the fake accounts, so that you can trace which botnet operator (co-)controls whhich other fake accounts.

Multiple accounts use the same PGP key, and this tool tries to scrape related accounts of a botnet user's followers, repositories, and contributors (pull requests) to uncover the botnet on a larger scale.

Usually lots of botnets work in a way that they create other fake accounts and follow each other once they go online, so that these accounts get pushed into the "not being a bot" classification by GitHub's very flawed bot detector mechanism that just checks for account age and followers.

Usage

The Antibote tool automatically scrapes all followers, repositories, issues, comments from GitHub and GitLab and tries to correlate connected accounts. 

cd /path/to/antibote;

# setup personal access token first
echo "My-Personal-Access-Token" > constants/Token.env;

# trace the botnet behind fake user account
go run cmds/antibote/main.go xiexinch;

# GPG key for this botnet operator is mapped in keymap
cat ~/Antibote/github/xiexinch.json;
cat ~/Antibote/keymap.json;

The only limitation for this approach has been so far that the GitHub Web UI (Codespaces) is also signing its commits with the same GPG key. This means that all commits done with the GitHub Web UI can't be correlated back to their respective botnet operators.
