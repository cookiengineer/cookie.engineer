Binary Emulation

Running binaries in emulated environments with QEMU user-mode, Unicorn Engine, and Qiling for cross-architecture analysis.

Overview

Malware often targets a different architecture than the analyst's workstation. Emulation runs those binaries, or individual functions, under software control so that you can observe and instrument them without compatible hardware. This article covers QEMU user-mode, Unicorn Engine, and Qiling, and shows how to extract and decode a function from a foreign-architecture binary.

Required Reading

  • Symbolic Execution - symbolic execution concepts, angr framework, constraint solving
  • Reading Assembly - instruction set basics and calling conventions

Why Emulation

Malware targets specific architectures. You receive an ARM IoT sample but work on x86. You need to extract an encryption algorithm from a binary without running its network callbacks. You want to trace every instruction a suspicious function executes. Emulation provides:

  1. Cross-architecture execution - run ARM, MIPS , or PowerPC on x86
  2. Isolation - no kernel compromise from user-mode emulation
  3. Introspection - hook any instruction, memory access, or register change
  4. Function extraction - emulate a single function in isolation

QEMU User-Mode Emulation

QEMU user-mode ( qemu-x86_64 , qemu-aarch64 , qemu-arm ) emulates a single binary - translating its instructions via TCG (Tiny Code Generator) and intercepting syscalls, forwarding them to the host kernel. No kernel emulation, no device emulation, just the process.

Installation

$ sudo pacman -S qemu-user qemu-user-binfmt qemu-user-static

# Verify
$ qemu-x86_64 --version
qemu-x86_64 version 9.2.0

# List all available user-mode emulators
$ ls /usr/bin/qemu-*
qemu-aarch64      qemu-arm          qemu-loongarch64
qemu-mips         qemu-mips64       qemu-ppc
qemu-ppc64        qemu-riscv32      qemu-riscv64
qemu-x86_64       qemu-i386

Basic Usage

# Run an x86-64 binary on any host architecture
$ qemu-x86_64 ./x86_64_malware.elf
# Run an ARM binary on x86 host
$ qemu-arm ./arm_malware.elf
# Run with library path pointing to ARM rootfs
$ qemu-arm -L /path/to/arm/sysroot ./arm_binary.elf

The -L flag is critical for cross-architecture: it tells QEMU where to find the target architecture's dynamic linker and shared libraries. Without it, QEMU would try to load the host's x86-64 ld-linux.so , which will fail.

Cross-Architecture Library Setup

# Extract libraries from an ARM firmware or rootfs
$ mkdir -p /opt/sysroots/arm
$ cp -r /path/to/firmware_extracted/lib /opt/sysroots/arm/
$ cp -r /path/to/firmware_extracted/usr/lib /opt/sysroots/arm/usr/

# Run ARM binary with those libraries
$ qemu-arm -L /opt/sysroots/arm ./arm_target.elf

Static Binaries

Statically linked binaries ( file binary reports statically linked ) have all libraries compiled in. They run without -L : 

$ qemu-aarch64 ./statically_linked_aarch64.elf

This is common for embedded malware - the entire binary is self-contained.

How TCG Translation Works

TCG is the core of QEMU's user-mode emulation. It operates in two phases:

GUEST INSTRUCTION                TCG IR (Intermediate Representation)
─────────────────                ─────────────────────────────────────
add rax, rbx          →           mov_i32 tmp1, rbx
                                  add_i32 tmp1, tmp1, rax
                                  mov_i32 rax, tmp1

str w0, [sp, #8]      →           add_i64 addr, sp, 8
                                  qemu_st_i32 w0, addr, le

TCG's intermediate representation is architecture-neutral. Each guest architecture's frontend translates to it, and each host architecture's backend translates it to native instructions. This is how QEMU supports 20+ guest architectures on any host.

GDB Debugging of Emulated Binaries

QEMU user-mode includes a GDB stub. Attach GDB to an emulated process:

# Start QEMU with GDB stub on port 1234
$ qemu-x86_64 -g 1234 ./malware.elf

# In another terminal, connect GDB
$ gdb -q
(gdb) target remote :1234
(gdb) file ./malware.elf        # Load symbols
(gdb) break *0x403a00
(gdb) continue

Limitations of QEMU User-Mode

  1. Syscall numbers differ between architectures. ARM and x86-64 have different syscall numbers for the same operation. QEMU translates these, but edge cases exist.
  1. /proc and /sys come from the host. When emulated malware reads /proc/cpuinfo , it sees the host's CPU , not the emulated architecture's. This causes anti- VM detection issues.
  1. Thread-local storage (TLS) and signals behave differently across architectures. Heavily multi-threaded malware may crash in emulation.
  1. Not all syscalls are implemented. Rare or architecture-specific syscalls may not have QEMU translations.

Unicorn Engine

Unicorn is a lightweight CPU emulation library - it emulates raw CPU instructions without any OS. You are responsible for memory mapping, syscall handling, and environment setup. The tradeoff: more work, but complete control.

Installation

$ pip install unicorn
$ python -c "import unicorn; print(unicorn.__version__)"
2.1.1

Core API

from unicorn import *
from unicorn.x86_const import *

# 1. Create emulator instance
mu = Uc(UC_ARCH_X86, UC_MODE_64)

# 2. Map memory (address, size, permissions)
BASE = 0x400000
SIZE = 2 * 1024 * 1024  # 2 MB
mu.mem_map(BASE, SIZE, UC_PROT_ALL)

# 3. Write code to memory
code = b'\x48\x31\xc0\x48\xff\xc0'  # xor rax,rax; inc rax
mu.mem_write(BASE, code)

# 4. Set up stack
STACK = 0x7ffffffde000
mu.mem_map(STACK, 0x2000, UC_PROT_READ | UC_PROT_WRITE)
mu.reg_write(UC_X86_REG_RSP, STACK + 0x1000)

# 5. Set initial RIP
mu.reg_write(UC_X86_REG_RIP, BASE)

# 6. Emulate
mu.emu_start(BASE, BASE + len(code))

# 7. Read results
rax = mu.reg_read(UC_X86_REG_RAX)
print(f"RAX = {rax}")  # RAX = 1

Emulating a XOR Decode Routine

This is the most common Unicorn use case: extract a decode function from malware and emulate it in isolation.

The Target Decode Function

// Typical malware string decoder
// decode_string(char *buf, size_t len, unsigned char key)
void decode_string(char *buf, size_t len, unsigned char key) {
    for (size_t i = 0; i < len; i++) {
        buf[i] ^= key;
    }
}

Disassembly at 0x4011a0

; decode_string(buf=rdi, len=rsi, key=rdx)
PUSH   RBP
MOV    RBP, RSP
MOV    qword [RBP-0x18], RDI    ; buf ptr
MOV    qword [RBP-0x20], RSI    ; len
MOV    byte  [RBP-0x21], DL     ; key
MOV    qword [RBP-0x8], 0x0     ; i = 0
JMP    loop_check
loop_body:
MOV    RAX, [RBP-0x8]           ; i
MOV    RCX, [RBP-0x18]          ; buf
MOVZX  EAX, byte [RCX+RAX*1]    ; buf[i]
XOR    AL,  byte [RBP-0x21]     ; buf[i] ^= key
MOV    RDX, [RBP-0x18]
MOV    byte [RDX+RAX*1], AL     ; buf[i] = result
ADD    qword [RBP-0x8], 0x1     ; i++
loop_check:
MOV    RAX, [RBP-0x8]           ; i
CMP    RAX, [RBP-0x20]          ; i < len?
JB     loop_body
POP    RBP
RET

Unicorn Emulator for the Decode Function

#!/usr/bin/env python3
"""unicorn_decode.py — Emulate XOR string decoder with Unicorn"""

from unicorn import *
from unicorn.x86_const import *

def emulate_xor_decode(code: bytes, encoded_data: bytes, key: int) -> bytes:
    """
    Emulate the decode_string function in isolation.
    
    Args:
        code: Raw bytes of the decode function (extracted from ELF)
        encoded_data: The XOR-encoded buffer
        key: Single-byte XOR key
    Returns:
        Decoded plaintext bytes
    """
    # Memory layout
    CODE_ADDR  = 0x400000
    STACK_ADDR = 0x7fff0000
    DATA_ADDR  = 0x600000  # For encoded data buffer

    CODE_SIZE  = 2 * 1024 * 1024
    STACK_SIZE = 0x10000
    DATA_SIZE  = len(encoded_data) + 0x1000

    # Initialize emulator
    mu = Uc(UC_ARCH_X86, UC_MODE_64)

    # Map memory regions
    mu.mem_map(CODE_ADDR,  CODE_SIZE,  UC_PROT_ALL)
    mu.mem_map(DATA_ADDR,  DATA_SIZE,  UC_PROT_READ | UC_PROT_WRITE)
    mu.mem_map(STACK_ADDR, STACK_SIZE, UC_PROT_READ | UC_PROT_WRITE)

    # Write code
    mu.mem_write(CODE_ADDR, code)

    # Write encoded data to the data buffer
    mu.mem_write(DATA_ADDR, encoded_data)

    # Set up stack
    mu.reg_write(UC_X86_REG_RSP, STACK_ADDR + STACK_SIZE - 0x100)
    mu.reg_write(UC_X86_REG_RBP, STACK_ADDR + STACK_SIZE - 0x100)

    # Set function arguments (System V AMD64 ABI)
    # decode_string(buf=rdi, len=rsi, key=rdx)
    mu.reg_write(UC_X86_REG_RDI, DATA_ADDR)
    mu.reg_write(UC_X86_REG_RSI, len(encoded_data))
    mu.reg_write(UC_X86_REG_RDX, key)

    # Set RIP to function entry and start emulation
    mu.reg_write(UC_X86_REG_RIP, CODE_ADDR)

    # Emulate — we need to know where the function ends (RET instruction)
    # The function is small, so we emulate until we run out of code
    try:
        mu.emu_start(CODE_ADDR, CODE_ADDR + len(code))
    except UcError as e:
        print(f"[-] Emulation error: {e}")
        # Read what we have so far
        pass

    # Read the decoded buffer
    decoded = mu.mem_read(DATA_ADDR, len(encoded_data))
    return bytes(decoded)

# Extract the decode function bytes from ELF using pyelftools
def extract_function_from_elf(elf_path: str, func_addr: int, func_size: int) -> bytes:
    """Extract raw bytes of a function from an ELF file."""
    from elftools.elf.elffile import ELFFile

    with open(elf_path, 'rb') as f:
        elf = ELFFile(f)

        # Find the segment containing func_addr
        for segment in elf.iter_segments():
            seg_start = segment['p_vaddr']
            seg_end   = seg_start + segment['p_memsz']
            if seg_start <= func_addr < seg_end:
                offset = func_addr - seg_start + segment['p_offset']
                f.seek(offset)
                return f.read(func_size)

    raise ValueError(f"Address 0x{func_addr:x} not found in any segment")

if __name__ == '__main__':
    import sys

    # Example: emulate a decode function at 0x4011a0 (size 0x50)
    # from malware.elf
    elf_path = sys.argv[1]

    # These values would come from Ghidra/r2 analysis
    DECODE_FUNC_ADDR = 0x4011a0
    DECODE_FUNC_SIZE = 0x50
    ENCODED_DATA = bytes([0x9e, 0x91, 0x9a, 0x9b, 0x96, 0x91])  # "C2_HOST" ^ 0xfe
    XOR_KEY = 0xfe

    code = extract_function_from_elf(elf_path, DECODE_FUNC_ADDR, DECODE_FUNC_SIZE)
    print(f"[+] Extracted {len(code)} bytes of decode function")

    decoded = emulate_xor_decode(code, ENCODED_DATA, XOR_KEY)
    print(f"[+] Decoded: {decoded}")

Unicorn Hooks

Hooks are the reason Unicorn excels for analysis - intercept any instruction, memory access, or register change:

Instruction Tracing Hook

def hook_code(uc, address, size, user_data):
    """Called before EVERY instruction."""
    code = uc.mem_read(address, min(size, 15))
    print(f"  0x{address:x}: {code.hex()}")

mu.hook_add(UC_HOOK_CODE, hook_code)

Memory Access Hooks

def hook_mem_read(uc, access, address, size, value, user_data):
    print(f"  MEM READ  0x{address:x} [{size} bytes]")

def hook_mem_write(uc, access, address, size, value, user_data):
    print(f"  MEM WRITE 0x{address:x} [{size} bytes] = 0x{value:x}")

def hook_mem_invalid(uc, access, address, size, value, user_data):
    """Called when accessing unmapped memory - map it on-the-fly."""
    print(f"  [!] Invalid access at 0x{address:x}")
    # Map the page containing this address
    page = address & ~0xFFF
    uc.mem_map(page, 0x1000, UC_PROT_ALL)
    return True  # Continue emulation

mu.hook_add(UC_HOOK_MEM_READ, hook_mem_read)
mu.hook_add(UC_HOOK_MEM_WRITE, hook_mem_write)
mu.hook_add(UC_HOOK_MEM_READ_UNMAPPED | UC_HOOK_MEM_WRITE_UNMAPPED, hook_mem_invalid)

Syscall Interception Hook

This is necessary because Unicorn doesn't implement any OS. You must handle every syscall:

def hook_syscall(uc, user_data):
    """Handle Linux x86-64 syscalls."""
    rax = uc.reg_read(UC_X86_REG_RAX)  # Syscall number

    if rax == 1:  # sys_write
        rdi = uc.reg_read(UC_X86_REG_RDI)  # fd
        rsi = uc.reg_read(UC_X86_REG_RSI)  # buf
        rdx = uc.reg_read(UC_X86_REG_RDX)  # count
        data = uc.mem_read(rsi, rdx)
        print(f"  [SYSCALL] write({rdi}, {data}, {rdx})")
        uc.reg_write(UC_X86_REG_RAX, rdx)  # Return bytes written

    elif rax == 0:  # sys_read
        rdi = uc.reg_read(UC_X86_REG_RDI)
        rsi = uc.reg_read(UC_X86_REG_RSI)
        rdx = uc.reg_read(UC_X86_REG_RDX)
        # For analysis, return EOF or mocked data
        uc.reg_write(UC_X86_REG_RAX, 0)  # 0 = EOF

    elif rax == 60:  # sys_exit
        rdi = uc.reg_read(UC_X86_REG_RDI)
        print(f"  [SYSCALL] exit({rdi})")
        uc.emu_stop()

    else:
        print(f"  [SYSCALL] Unknown syscall: {rax}")
        uc.reg_write(UC_X86_REG_RAX, -1)  # Return error

# Hook SYSCALL instruction (0x0F 0x05 on x86-64)
mu.hook_add(UC_HOOK_INTR, hook_syscall)

Complete Shellcode Emulation

Emulating shellcode is a common Unicorn use case - write raw bytes to memory, set up registers, emulate, and observe effects: 

#!/usr/bin/env python3
"""emulate_shellcode.py — Analyze shellcode with Unicorn"""

from unicorn import *
from unicorn.x86_const import *

def emulate_shellcode(shellcode: bytes, arch='x64') -> dict:
    """
    Emulate shellcode and capture all syscalls and memory writes.
    
    Returns a dict with trace information.
    """
    trace = {
        'instructions': 0,
        'syscalls': [],
        'memory_writes': [],
        'final_registers': {},
    }

    # Set up architecture
    if arch == 'x64':
        mu = Uc(UC_ARCH_X86, UC_MODE_64)
        SC_ADDR  = 0x1000000
        STACK    = 0x7fff0000
        REG_RIP  = UC_X86_REG_RIP
        REG_RSP  = UC_X86_REG_RSP
        REG_RAX  = UC_X86_REG_RAX
        REG_RDI  = UC_X86_REG_RDI
        REG_RSI  = UC_X86_REG_RSI
        REG_RDX  = UC_X86_REG_RDX
        SYSCALL_INSN = b'\x0f\x05'
        REG_NAMES = [
            UC_X86_REG_RAX, UC_X86_REG_RBX, UC_X86_REG_RCX,
            UC_X86_REG_RDX, UC_X86_REG_RSI, UC_X86_REG_RDI,
            UC_X86_REG_R8,  UC_X86_REG_R9,  UC_X86_REG_R10,
            UC_X86_REG_RSP, UC_X86_REG_RBP, UC_X86_REG_RIP,
        ]
    else:
        raise ValueError(f"Unsupported arch: {arch}")

    # Map memory
    mu.mem_map(SC_ADDR, 2 * 1024 * 1024, UC_PROT_ALL)
    mu.mem_map(STACK, 0x10000, UC_PROT_READ | UC_PROT_WRITE)

    # Write shellcode
    mu.mem_write(SC_ADDR, shellcode)

    # Set up stack
    mu.reg_write(REG_RSP, STACK + 0xF000)
    mu.reg_write(REG_RIP, SC_ADDR)

    # Hook: count instructions
    def count_insn(uc, addr, size, user_data):
        trace['instructions'] += 1
    mu.hook_add(UC_HOOK_CODE, count_insn)

    # Hook: capture syscalls
    def capture_syscall(uc, user_data):
        rax = uc.reg_read(REG_RAX)
        rdi = uc.reg_read(REG_RDI)
        rsi = uc.reg_read(REG_RSI)
        rdx = uc.reg_read(REG_RDX)

        syscall_info = {
            'number': rax,
            'rdi': rdi,
            'rsi': rsi,
            'rdx': rdx,
            'rip': uc.reg_read(REG_RIP),
        }

        if rax == 1:  # write
            try:
                data = uc.mem_read(rsi, min(rdx, 256))
                syscall_info['data'] = data
            except:
                syscall_info['data'] = b'<unreadable>'

        elif rax == 59:  # execve
            try:
                cmd = uc.mem_read(rdi, 64)
                syscall_info['execve_path'] = cmd.split(b'\x00')[0]
            except:
                syscall_info['execve_path'] = b'<unreadable>'

        elif rax == 2:  # open
            try:
                path = uc.mem_read(rdi, 64)
                syscall_info['open_path'] = path.split(b'\x00')[0]
            except:
                pass

        trace['syscalls'].append(syscall_info)

    mu.hook_add(UC_HOOK_INTR, capture_syscall)

    # Hook: capture memory writes to target regions
    def capture_mem_write(uc, access, address, size, value, user_data):
        trace['memory_writes'].append({
            'address': address,
            'size': size,
            'value': value,
            'rip': uc.reg_read(REG_RIP),
        })
    # mu.hook_add(UC_HOOK_MEM_WRITE, capture_mem_write)

    # Emulate (stop when we hit end or error)
    try:
        mu.emu_start(SC_ADDR, SC_ADDR + len(shellcode), timeout=5000000)
    except UcError as e:
        trace['error'] = str(e)

    # Capture final register state
    for reg in REG_NAMES:
        try:
            trace['final_registers'][reg] = mu.reg_read(reg)
        except:
            pass

    return trace


if __name__ == '__main__':
    # Test: simple execve("/bin/sh") shellcode
    shellcode = (
        b'\x48\x31\xd2'              # xor rdx, rdx
        b'\x48\xbb\x2f\x2f\x62\x69\x6e\x2f\x73\x68'  # mov rbx, "/bin//sh"
        b'\x48\xc1\xeb\x08'           # shr rbx, 8
        b'\x53'                       # push rbx
        b'\x48\x89\xe7'               # mov rdi, rsp
        b'\x48\x31\xc0'               # xor rax, rax
        b'\x50'                       # push rax
        b'\x57'                       # push rdi
        b'\x48\x89\xe6'               # mov rsi, rsp
        b'\xb0\x3b'                   # mov al, 59
        b'\x0f\x05'                   # syscall
    )

    trace = emulate_shellcode(shellcode)
    print(f"Instructions: {trace['instructions']}")
    for sc in trace['syscalls']:
        print(f"  Syscall: {sc}")

Qiling Framework - Unicorn with an OS

Qiling wraps Unicorn and adds full OS support - filesystem, network, registry, shared libraries. It's the "batteries included" approach: 

$ pip install qiling
						
#!/usr/bin/env python3
"""qiling_emulate.py — Run a binary with full OS emulation"""

from qiling import Qiling
from qiling.const import QL_VERBOSE

def emulate_full_binary(binary_path: str, rootfs_path: str):
    """
    Emulate a full binary with Qiling - filesystem, syscalls, libraries.
    
    Args:
        binary_path: Path to the target binary
        rootfs_path: Path to root filesystem (can be / for same arch)
    """
    ql = Qiling(
        [binary_path],
        rootfs_path,
        verbose=QL_VERBOSE.DEBUG
    )

    # Hook: print every API call
    @ql.os.function_hook
    def my_hook(ql, address, params):
        print(f"  API: {hex(address)} params={params}")

    # Hook: intercept specific function
    def intercept_connect(ql, sockfd, addr, addrlen):
        print(f"  [!] Intercepted connect() — blocking outbound connection")
        return -1  # Return error

    ql.os.set_api('connect', intercept_connect)

    # Run
    ql.run()

if __name__ == '__main__':
    emulate_full_binary('./malware.elf', '/')

QEMU vs Unicorn vs Qiling

Criterion QEMU User Unicorn Qiling
Runs full binary Yes No (must extract functions) Yes
OS support Host kernel via syscall translation None (manual) Full simulated OS
Cross-architecture Yes Yes Yes
Speed Near-native Emulated (slower) Slowest
API hooking Limited (GDB) Full (Python) Full (Python)
Filesystem support Host FS None Simulated or host
Network support Host network None Simulated
Binary format support ELF (all archs) Raw bytes only PE, ELF, MachO
Best for Running malware to observe behavior Extracting algorithms from functions Full sandboxed analysis

Verifying Emulation Accuracy

Emulation introduces subtle bugs. Verify with:

def verify_emulation_accuracy():
    """Compare emulated result against native execution."""

    # Native: run XOR decode on host
    data     = b'\x9e\x91\x9a\x9b\x96\x91'
    key      = 0xfe
    expected = bytes([b ^ key for b in data])
    print(f"Native result: {expected}")

    # Emulated: same decode via Unicorn
    # (extract function bytes, emulate...)
    emulated = emulate_xor_decode(
        extract_function_from_elf('malware.elf', 0x4011a0, 0x50),
        data, key
    )
    print(f"Emulated result: {emulated}")

    assert expected == emulated, "Emulation mismatch!"
    print("[+] Emulation verified — results match native execution")

Then use /opt/scripts/extract-function.py to pull the decode function out of /opt/samples/xor_decode , load those bytes into Unicorn, emulate the function, and recover the plaintext. Compare the emulated output with the native ./xor_decode output.
