HTTP

Hypertext Transfer Protocol/1.1 from first principles - request/response structure, headers deep dive, status codes, methods and idempotency, cookies, CORS, URL encoding, persistent connections, chunked transfer, and writing a minimal HTTP server in Python.

Overview

The HTTP is the application protocol of the web. A client opens a transport connection, sends a request message, and reads back a response message. The format looks simple, but its details decide how servers, proxies, and browsers interoperate, and where they disagree. This article walks through the message format, methods, status codes, headers, cookies, caching, and cross-origin rules, then shows how to drive the protocol by hand and how message-boundary confusion turns into request smuggling.

  • TCP - three-way handshake, sequence numbers, connection lifecycle

What HTTP Is

HTTP is the application-layer protocol for distributed, hypermedia information systems. The HTTP /1.1 core was defined in RFC 7230-7235, which RFC 9110-9112 now obsoletes. HTTP /2 is defined in RFC 9113 (replacing RFC 7540), and HTTP /3 in RFC 9114. Together they are the foundation of the World Wide Web.

HTTP is a request/response protocol built on top of TCP . A client opens a TCP connection to a server, sends a request message, and receives a response. HTTP itself is stateless - each request is independent, carrying all the information the server needs to process it. State (sessions, authentication) is layered on top via cookies, tokens, and other mechanisms.

HTTP/1.1 Request Structure

METHOD /path?query=value HTTP/1.1\r\n
Header-Name: Header-Value\r\n
Header-Name2: Header-Value2\r\n
\r\n
[Optional Body]

The first line is the Request-Line: <METHOD> <Request-URI> <HTTP-Version> . Each header is Name: Value , separated by \r\n . The headers section ends with an empty line ( \r\n\r\n ). The optional body follows.

Raw Request on the Wire

GET /index.html HTTP/1.1\r\n
Host: www.example.com\r\n
User-Agent: Mozilla/5.0\r\n
Accept: text/html,application/xhtml+xml\r\n
Accept-Encoding: gzip, deflate\r\n
Connection: keep-alive\r\n
\r\n

Every byte shown - including the \r\n line endings - is part of the protocol. A single missing \r\n breaks the parser.

HTTP Request Methods

Method Purpose Has Body Idempotent Safe Cacheable
GET Retrieve a resource No Yes Yes Yes
HEAD Retrieve headers only (no body) No Yes Yes Yes
POST Create/submit data Yes No No Conditional
PUT Replace or create a resource Yes Yes No No
DELETE Remove a resource May Yes No No
PATCH Partial update to a resource Yes No No No
OPTIONS Discover supported methods No Yes Yes No
TRACE Echo back the request (diagnostics) No Yes Yes No
CONNECT Establish a tunnel (e.g., for HTTPS proxy) No No No No

Idempotency: An idempotent request produces the same server state whether executed once or multiple times. GET, HEAD, PUT, DELETE, O PT IONS, TRACE are idempotent. POST is not - submitting a form twice creates two records.

Safety: A safe method does not modify server state. GET and HEAD are safe (by specification). All safe methods are idempotent, but not all idempotent methods are safe (DELETE modifies state but is idempotent).

# HEAD — check if resource exists, get Content-Length without downloading
curl -I https://example.com/large-file.zip

# OPTIONS — discover allowed methods
curl -X OPTIONS https://api.example.com/users -v

# TRACE — debug proxy chains (rarely enabled)
curl -X TRACE https://example.com/

# CONNECT — HTTP tunnel through proxy
curl -x http://proxy:8080 --proxytunnel https://example.com/

HTTP Response Structure

HTTP/1.1 200 OK\r\n
Date: Fri, 26 Jun 2026 12:00:00 GMT\r\n
Content-Type: text/html; charset=utf-8\r\n
Content-Length: 42\r\n
Connection: keep-alive\r\n
\r\n
<html><body>Hello World</body></html>

Status-Line: <HTTP-Version> <Status-Code> <Reason-Phrase> . The reason phrase is human-readable but optional - HTTP /2 removes it entirely.

HTTP Status Codes

Range Category Key Examples
1xx Informational 100 Continue, 101 Switching Protocols, 103 Early Hints
2xx Success 200 OK, 201 Created, 204 No Content, 206 Partial Content
3xx Redirection 301 Moved Permanently, 302 Found, 304 Not Modified, 307 Temporary Redirect, 308 Permanent Redirect
4xx Client Error 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 405 Method Not Allowed, 429 Too Many Requests
5xx Server Error 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout

Key status codes in detail

Code When It Happens
200 OK Request succeeded. Body contains the resource.
201 Created POST or PUT created a new resource. Location header points to it.
204 No Content Request succeeded but there is no body (common after DELETE).
301 Moved Permanently Resource has a new permanent URL. Search engines update their index.
302 Found Temporary redirect. Browsers follow but search engines keep original URL.
304 Not Modified Conditional GET - resource unchanged since If-Modified-Since or If-None-Match.
307/308 Like 302/301 but preserve the original HTTP method (POST stays POST).
400 Bad Request Malformed syntax - the server cannot understand the request.
401 Unauthorized Authentication required. WWW-Authenticate header specifies scheme.
403 Forbidden Server understands the request but refuses it. Authentication won't help.
404 Not Found The resource does not exist.
405 Method Not Allowed The method is not supported for this resource (e.g., POST on a static file).
429 Too Many Requests Rate limiting. Retry-After header indicates when to retry.
500 Internal Server Error Generic server failure - something went wrong in application code.
502 Bad Gateway Proxy/gateway received an invalid response from upstream.
503 Service Unavailable Server is overloaded or down for maintenance. Retry-After common.

Host Header and Virtual Hosting

The Host header is mandatory in HTTP /1.1. It enables virtual hosting - multiple domains served from the same IP address:

GET / HTTP/1.1
Host: www.example.com       → Server returns example.com's content

GET / HTTP/1.1
Host: www.other-site.com    → Same IP, same port, different content

Without the Host header, the server cannot distinguish which site is being requested. HTTP /1.0 did not require it, but HTTP /1.1 makes it mandatory.

# Test virtual hosting — different Host headers, same IP
curl -H "Host: www.example.com" http://93.184.216.34/
curl -H "Host: www.other.com" http://93.184.216.34/

Content-Length vs Transfer-Encoding

The server must indicate the size of the response body. Two mechanisms exist:

Content-Length: The server sends a Content-Length: N header before the body, and then exactly N bytes of body. Simple, predictable, requires knowing the total size before sending.

Transfer-Encoding: chunked: The server sends the body in chunks, each prefixed with its size in hexadecimal. The final chunk has size 0. Used when the total size is unknown at the start (streaming, server-side processing).

HTTP/1.1 200 OK\r\n
Transfer-Encoding: chunked\r\n
\r\n
1a\r\n                          ← chunk size: 26 bytes
<html><body>Hello World\r\n     ← 26 bytes of data
0d\r\n                          ← chunk size: 13 bytes
</body></html>\r\n              ← 13 bytes of data
0\r\n                           ← final chunk (size 0)
\r\n                            ← trailer section (empty)

Both mechanisms cannot be used simultaneously. HTTP /1.1 requires one or the other for any response with a body.

# Observe chunked transfer encoding
curl -v --raw https://example.com/stream 2>&1 | grep -i transfer

# Manually decode chunked body
python3 << 'EOF'
import socket

def recv_chunked(sock: socket.socket) -> bytes:
    """Read a chunked Transfer-Encoding response body."""
    body = b''
    while True:
        # Read chunk size line
        line = b''
        while not line.endswith(b'\r\n'):
            line += sock.recv(1)
        chunk_size = int(line.strip(), 16)

        if chunk_size == 0:
            # Read trailing \r\n after final chunk
            sock.recv(2)
            break

        # Read chunk data + trailing \r\n
        chunk = b''
        while len(chunk) < chunk_size:
            chunk += sock.recv(chunk_size - len(chunk))
        body += chunk
        sock.recv(2)  # Trailing \r\n
    return body
EOF

Persistent Connections

HTTP /1.0 opened a new TCP connection for every request/response pair. HTTP /1.1 defaults to persistent connections - the TCP connection stays open after a response, allowing multiple requests without re-establishing the TCP handshake.

HTTP/1.0 (non-persistent):
  TCP Connect → Request → Response → TCP Close
  TCP Connect → Request → Response → TCP Close
  TCP Connect → Request → Response → TCP Close
  (3 TCP handshakes, 3 TLS handshakes, 3 slow starts)

HTTP/1.1 (persistent):
  TCP Connect → Request → Response → Request → Response → Request → Response → TCP Close
  (1 TCP handshake, 1 TLS handshake, 1 slow start)

The Connection: keep-alive header signals that the connection should persist. Connection: close signals that it should close after the current response.

# Observe keep-alive — multiple requests on one connection
echo -e "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: keep-alive\r\n\r\n" \
       "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n" \
    | nc example.com 80

# curl reuses connections by default for multiple URLs
curl -v http://example.com/ http://example.com/about 2>&1 | grep "Re-using"

Caching and Validation

HTTP caching reduces latency and bandwidth. Two validation mechanisms:

Last-Modified Validation

Response: Last-Modified: Mon, 23 Jun 2026 10:00:00 GMT
Next request: If-Modified-Since: Mon, 23 Jun 2026 10:00:00 GMT
  → 304 Not Modified (resource unchanged, use cached copy)
  → 200 OK + new body (resource changed)

ETag Validation

Response: ETag: "abc123"
Next request: If-None-Match: "abc123"
  → 304 Not Modified (same ETag, use cache)
  → 200 OK + new ETag (content changed)

ETags are more precise than timestamps - they detect changes that don't modify timestamps, and sub-second changes.

# Conditional GET with ETag
curl -v -H "If-None-Match: \"abc123\"" https://example.com/page

# Conditional GET with Last-Modified
curl -v -H "If-Modified-Since: Mon, 23 Jun 2026 10:00:00 GMT" https://example.com/page

Cache-Control directives

Directive Meaning
public Any cache may store the response
private Only the browser may cache it (not shared caches)
no-cache Must revalidate before using cached copy
no-store Do not cache at all (sensitive data)
max-age=3600 Cache is fresh for 3600 seconds
s-maxage=3600 Override max-age for shared caches only
must-revalidate After expiry, must revalidate before serving stale
immutable Resource never changes - don't revalidate during max-age

Cookies and State

HTTP is stateless. Cookies add state. The server sets a cookie via the Set-Cookie response header; the browser sends it back via the Cookie request header:

Server → Client:
  Set-Cookie: session_id=abc123; Secure; HttpOnly; SameSite=Lax; Path=/

Client → Server (subsequent requests to the same domain):
  Cookie: session_id=abc123

Cookie attributes

Attribute Purpose
Secure Only send cookie over HTTPS (never HTTP)
HttpOnly Block JavaScript access (document.cookie cannot read it)
Domain Scope the cookie to a domain and its subdomains
Path Scope the cookie to a URL path prefix
SameSite Control cross-site requests: Strict, Lax, None
Max-Age Lifetime in seconds (alternative to Expires)
Expires Absolute expiration date (GMT)

SameSite values

Value Behavior
Strict Cookie never sent on cross-site requests (strongest CSRF protection)
Lax Sent with top-level navigations (clicking a link), not with iframes/images/forms
None Sent on all cross-site requests (must also have Secure) 
# View cookies set by a site
curl -v https://example.com/ 2>&1 | grep -i "set-cookie"

# Send cookies with a request
curl -b "session_id=abc123" https://example.com/dashboard

# Store cookies to file (cookie jar) for session persistence
curl -c cookies.txt -b cookies.txt https://example.com/login -d "user=admin&pass=secret"
curl -b cookies.txt https://example.com/dashboard

CORS - Cross-Origin Resource Sharing

Browsers enforce the Same-Origin Policy: a page from site-a.com cannot read data from api.site-b.com unless the API explicitly allows it. CORS is the mechanism for API s to opt in to cross-origin access:

Browser: sends request to api.site-b.com with Origin: site-a.com
Server:  responds with Access-Control-Allow-Origin: site-a.com
Browser: allows the JavaScript to read the response

CORS headers (response)

Header Purpose
Access-Control-Allow-Origin Which origins can access: * or https://site-a.com
Access-Control-Allow-Methods Allowed methods: GET, POST, PUT
Access-Control-Allow-Headers Allowed request headers: Content-Type, Authorization
Access-Control-Allow-Credentials Whether cookies/HTTP auth are sent: true
Access-Control-Max-Age How long to cache preflight results (seconds)
Access-Control-Expose-Headers Which response headers JavaScript can read beyond the defaults

Preflight requests: For non-simple requests (anything using PUT , DELETE , PATCH , or custom headers), the browser sends an OPTIONS request first to check if the cross-origin request is allowed:

OPTIONS /api/users HTTP/1.1
Host: api.site-b.com
Origin: https://site-a.com
Access-Control-Request-Method: DELETE
Access-Control-Request-Headers: Authorization

URL Structure and Encoding

scheme://user:password@host:port/path/to/resource?key=value&other=thing#fragment
^^^^^^   ^^^^^^^^^^^^  ^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^^^^^ ^^^^^^^^
scheme   userinfo      host:port   path                 query string            fragment

URL encoding (percent-encoding) replaces non-ASCII and reserved characters with %XX (hexadecimal byte value):

Character    Encoded    Reason
space        %20        Not allowed in URLs
#            %23        Reserved (fragment delimiter)
%            %25        Reserved (encoding prefix)
&            %26        Reserved (query separator)
+            %2B        Treated as space in query strings
/            %2F        Reserved (path separator)
?            %3F        Reserved (query delimiter)
=            %3D        Reserved (key-value separator)
ü            %C3%BC     Non-ASCII (UTF-8 encoded)
						
# URL encode/decode with Python
python3 -c "from urllib.parse import quote, unquote; \
    print(quote('hello world & friends?')); \
    print(unquote('hello%20world%20%26%20friends%3F'))"

# curl with URL-encoded data
curl "https://api.example.com/search?q=$(python3 -c 'from urllib.parse import quote; print(quote("hello world"))')"

HTTP/2 - Key Differences from HTTP/1.1

HTTP /2 (RFC 9113, previously RFC 7540) is a binary protocol that addresses HTTP /1.1 limitations while preserving semantics:

Feature HTTP/1.1 HTTP/2
Format Text-based (ASCII) Binary frames
Multiplexing No (head-of-line blocking) Yes (multiple streams per connection)
Header compression None HPACK (static/dynamic table)
Server push No Yes (PUSH_PROMISE)
Connection Multiple TCP connections (6-8 per origin) Single TCP connection
Priorities None Stream prioritization

HTTP /2 does not change the semantics - methods, status codes, headers, and URI s are the same. Only the framing and transport change.

HTTP/3 - QUIC-Based Transport

HTTP /3 (RFC 9114) replaces TCP with QUIC ( UDP -based transport):

Feature HTTP/2 HTTP/3
Transport TCP QUIC (over UDP)
Handshake TCP + TLS (2-3 RTT) QUIC + TLS 1.3 (0-1 RTT)
Head-of-line blocking TCP level (one lost packet blocks all streams) Per-stream (loss on one stream doesn't affect others)
Connection migration No (IP change = reconnect) Yes (connection ID survives IP changes)
0-RTT resumption With TLS 1.3 Built into QUIC

Writing a Minimal HTTP Server in Python

#!/usr/bin/env python3
"""
Minimal HTTP/1.1 server demonstrating the protocol from first principles.
Handles GET, HEAD, and POST. Shows every byte on the wire.
"""
import socket
import threading
import os
import sys
import json
from urllib.parse import urlparse, parse_qs

HTTP_PORT = 8080

STATUS_CODES = {
    200: "OK",
    201: "Created",
    204: "No Content",
    301: "Moved Permanently",
    400: "Bad Request",
    404: "Not Found",
    405: "Method Not Allowed",
    500: "Internal Server Error",
}

def parse_http_request(raw: bytes) -> dict:
    """Parse raw HTTP request bytes into structured components."""
    try:
        text = raw.decode("utf-8", errors="replace")
    except UnicodeDecodeError:
        text = raw.decode("latin-1", errors="replace")

    lines = text.split("\r\n")

    # Parse request line
    if not lines:
        return {"error": "empty request"}

    request_line = lines[0].split(" ")
    if len(request_line) < 3:
        return {"error": "malformed request line"}

    method, path, version = request_line[0], request_line[1], request_line[2]

    # Parse headers
    headers = {}
    i = 1
    while i < len(lines) and lines[i]:
        if ":" in lines[i]:
            key, value = lines[i].split(":", 1)
            headers[key.strip().lower()] = value.strip()
        i += 1

    # Parse body
    body = ""
    if i + 1 < len(lines):
        body = "\r\n".join(lines[i+1:])

    # Parse query string
    parsed_url = urlparse(path)
    query = parse_qs(parsed_url.query)

    return {
        "method": method,
        "path": parsed_url.path,
        "query": query,
        "version": version,
        "headers": headers,
        "body": body,
    }

def build_response(status: int, headers: dict = None,
                   body: str = "", content_type: str = "text/html; charset=utf-8") -> bytes:
    """Build a complete HTTP response, handling Content-Length automatically."""
    if headers is None:
        headers = {}

    response_headers = {
        "Content-Type": content_type,
        "Content-Length": str(len(body.encode("utf-8"))),
        "Connection": "close",
        "Server": "MinimalHTTP/1.0",
    }
    response_headers.update(headers)

    status_text = STATUS_CODES.get(status, "Unknown")
    header_block = "\r\n".join(
        f"{k}: {v}" for k, v in response_headers.items()
    )

    raw = f"HTTP/1.1 {status} {status_text}\r\n{header_block}\r\n\r\n{body}"
    return raw.encode("utf-8")

def route_request(request: dict) -> tuple[int, str, str]:
    """Route a request to the appropriate handler. Returns (status, content_type, body)."""
    method = request["method"]
    path = request["path"]

    # ── Routes ──
    if path == "/":
        return 200, "text/html; charset=utf-8", f"""<!DOCTYPE html>
<html>
<head><title>Minimal HTTP Server</title></head>
<body>
<h1>HTTP/1.1 Minimal Server</h1>
<p>Request path: {path}</p>
<p>Method: {method}</p>
<p>Your IP: {request.get('client_ip', 'unknown')}</p>
<p>Your headers:</p>
<pre>{json.dumps(request['headers'], indent=2)}</pre>
<form method="POST" action="/echo">
  <input type="text" name="message" placeholder="Type a message">
  <button type="submit">Echo via POST</button>
</form>
</body>
</html>"""

    elif path == "/echo" and method == "POST":
        # Parse URL-encoded form data or JSON
        content_type = request["headers"].get("content-type", "")
        if "application/json" in content_type:
            try:
                data = json.loads(request["body"])
                response = json.dumps({"received": data}, indent=2)
            except json.JSONDecodeError:
                response = f"Invalid JSON: {request['body']}"
        elif "application/x-www-form-urlencoded" in content_type:
            parsed = parse_qs(request["body"])
            response = json.dumps({"received": {k: v[0] for k, v in parsed.items()}}, indent=2)
        else:
            response = f"Received: {request['body']}"

        return 200, "application/json", response

    elif path == "/headers":
        # Echo all request headers as JSON
        return 200, "application/json", json.dumps(request["headers"], indent=2)

    elif path == "/status":
        # Demonstrate all status code categories
        code = int(request["query"].get("code", [200])[0])
        return code, "text/plain", f"Status: {code} {STATUS_CODES.get(code, 'Unknown')}"

    elif path == "/chunked":
        # Demonstrate chunked transfer encoding
        return 200, "text/plain", "This demonstrates how chunked transfer works.\n" * 10

    elif path == "/redirect":
        return 301, "text/html; charset=utf-8", "<html><body>Redirecting to /...</body></html>"

    else:
        return 404, "text/plain", f"Not Found: {path}"

def handle_client(conn: socket.socket, addr: tuple):
    """Handle a single client connection."""
    try:
        conn.settimeout(30)
        raw = conn.recv(65535)

        if not raw:
            conn.close()
            return

        # Print what was received (raw bytes)
        print(f"\n{'='*60}")
        print(f"Connection from {addr[0]}:{addr[1]}")
        print(f"{'='*60}")
        print(raw.decode("utf-8", errors="replace").rstrip())

        request = parse_http_request(raw)
        request["client_ip"] = addr[0]

        if "error" in request:
            response = build_response(400, body=request["error"])
        else:
            status, content_type, body = route_request(request)

            extra_headers = {}
            if request["path"] == "/redirect":
                extra_headers["Location"] = "/"

            response = build_response(status, headers=extra_headers,
                                      body=body, content_type=content_type)

        conn.sendall(response)
        print(f"\n--- Response ({len(response)} bytes) ---")
        print(response.decode("utf-8", errors="replace").rstrip())

    except socket.timeout:
        pass
    except (ConnectionResetError, BrokenPipeError):
        pass
    except Exception as e:
        print(f"Error handling {addr}: {e}")
        try:
            conn.sendall(build_response(500, body=str(e)))
        except Exception:
            pass
    finally:
        conn.close()

def run_server(host: str = "0.0.0.0", port: int = HTTP_PORT):
    """Start the HTTP server."""
    server_sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_sock.bind((host, port))
    server_sock.listen(128)

    print(f"[*] HTTP/1.1 server listening on {host}:{port}")
    print(f"    Try: curl -v http://localhost:{port}/")
    print(f"    Or:  http://localhost:{port}/ in your browser")
    print(f"    Ctrl+C to stop")
    print()

    try:
        while True:
            conn, addr = server_sock.accept()
            t = threading.Thread(target=handle_client, args=(conn, addr))
            t.daemon = True
            t.start()
    except KeyboardInterrupt:
        print("\n[*] Shutting down.")
        server_sock.close()
        sys.exit(0)

if __name__ == "__main__":
    run_server()

HTTP Request Smuggling

HTTP request smuggling exploits differences in how front-end proxies and back-end servers parse HTTP message boundaries. Two common vectors:

CL.TE Smuggling

POST / HTTP/1.1
Host: example.com
Content-Length: 13
Transfer-Encoding: chunked

0

SMUGGLED DATA

The front-end uses Content-Length (13 bytes: 0\r\n\r\nSMUGGLED ), so it sees one request. The back-end uses Transfer-Encoding (chunked with size 0 = end), so it sees SMUGGLED DATA as the start of the next request. This desynchronizes the connection.

TE.CL Smuggling

POST / HTTP/1.1
Host: example.com
Content-Length: 4
Transfer-Encoding: chunked

5c
SMUGGLED DATA...
0

The front-end uses Transfer-Encoding (processes chunked body), while the back-end uses Content-Length (reads only 4 bytes: 5c\r\n ). The remaining SMUGGLED DATA... is treated as a new request by the back-end.

Summary

HTTP is a text-based request/response protocol over TCP . HTTP /1.1 standardizes persistent connections, chunked transfer encoding, virtual hosting via the Host header, and caching with ETag/Last-Modified. HTTP /2 moves to a binary framing layer while preserving semantics. HTTP /3 replaces TCP with QUIC. The protocol is deceptively simple

  • the text format makes it human-readable, but edge cases in parsing, connection management,

and caching create subtle security and reliability challenges.
