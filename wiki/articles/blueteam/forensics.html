Forensics

Systematic collection, preservation, and analysis of digital evidence from disk and filesystem.

Overview

Digital forensics is a methodology for collecting and analyzing evidence so that findings hold up in court or in an incident report. This article covers disk imaging and write blockers, The Sleuth Kit, timeline reconstruction, file carving, deleted-file recovery, and anti-forensics detection. After reading, you can acquire an image, build a timeline, and recover artifacts that an attacker tried to destroy.

Required Reading

  • Filesystems - inode structure, superblock, journaling, block allocation
  • Unix Permissions - owner/group/other, setuid, setgid, sticky bit

Concept

Digital forensics is the systematic collection and analysis of digital evidence for investigative purposes. It is not about running tools - it is about a methodology that ensures findings are complete, accurate, and defensible in any forum (incident response, legal proceedings, compliance audits).

The three principles:

  1. Minimize changes to the evidence. Every tool you run makes modifications. Know what they are.
  2. Document everything . Keep timestamped notes of every action. Screenshot output. Hash everything.
  3. Maintain chain of custody . The evidence must be provably unaltered from collection to presentation.

Disk Imaging

Disk imaging creates a bit-for-bit copy of a storage device. This is the foundational forensic step - all analysis is performed on the image, never the original. 

# dd — available on every Linux system, slow but reliable
sudo dd if=/dev/sda of=/mnt/evidence/sda.dd bs=4M conv=noerror,sync status=progress
# conv=noerror: continue on read errors
# conv=sync: pad incomplete blocks with nulls on error

# dc3dd — enhanced dd with hashing and progress
sudo dc3dd if=/dev/sda of=/mnt/evidence/sda.dd hash=sha256 log=/mnt/evidence/sda.log

# Hash verification after imaging
sha256sum /mnt/evidence/sda.dd > /mnt/evidence/sda.dd.sha256
# Compare against original device
sudo sha256sum /dev/sda | cut -d' ' -f1
# These must match — if they don't, the image is incomplete

Forensic image formats

Format Extension Features
Raw (dd) .dd,.img,.raw Bit-for-bit copy, no metadata, no compression
EWF (Expert Witness) .E01,.Ex01 Compression, hash verification, metadata, case management
AFF (Advanced Forensic Format) .aff Compression, metadata, extensible, open source
SMART .smrt ASR Data format, used by Magnet Forensics 
# Create E01 image with guymager (GUI) or ewfacquire (CLI)
ewfacquire /dev/sda -t /mnt/evidence/sda -b 2048 -S 2GiB -c best -f encase7 -l sda_evidence.log

# Convert between formats
# dd → E01
ewfacquirestream /mnt/evidence/sda.dd -t /mnt/evidence/sda -b 2048 -S 2GiB -c best

# E01 → dd
ewfexport /mnt/evidence/sda.E01 -t /mnt/evidence/sda.dd

Write blockers

Hardware write blockers physically prevent write commands from reaching the evidence drive. Software write blockers use kernel mechanisms. 

# Software write blocker (Linux) — mount evidence read-only
sudo mount -o ro,noexec,nodev,noatime /dev/sdb1 /mnt/evidence

# Verify write protection
touch /mnt/evidence/test_write
# Expected: "Read-only file system" error

# Alternative: use losetup with read-only
sudo losetup -r /dev/loop0 /mnt/evidence/sda.dd
sudo mount -o ro /dev/loop0p1 /mnt/analysis

The Sleuth Kit (TSK)

The Sleuth Kit is the open-source standard for filesystem forensic analysis. It operates on disk images, not live filesystems. 

# Install on ArchLinux
sudo pacman -S sleuthkit autopsy

Core TSK commands

# mmls — display partition layout
mmls /mnt/evidence/sda.dd
# Output:
# Slot  Start      End        Length     Description
# 000   0000002048  0001026047  0001024000  Primary (NTFS/exFAT)
# 001   0001026048  0020971519  0019945472  Linux (Ext4)

# Use offset to target a specific partition
OFFSET=$((1026048 * 512))  # Start sector * sector size

# fsstat — filesystem details (superblock info)
fsstat -o $OFFSET /mnt/evidence/sda.dd
# Shows: volume name, block size, total blocks, free blocks,
# last mount time, last write time, features (has_journal, extents)

# fls — list files and directories (including deleted!)
fls -r -o $OFFSET /mnt/evidence/sda.dd
# -r: recursive
# Output: r/r 12345: filename.txt
# r/r = regular file, d/d = directory
# 12345 = inode number
# * prefix = deleted file, recoverable

# fls with timestamps
fls -m / -r -o $OFFSET /mnt/evidence/sda.dd > bodyfile
# -m / : prepend "/" to paths (for timeline tools)

# istat — inode details
istat -o $OFFSET /mnt/evidence/sda.dd 12345
# Shows: permissions, owner, timestamps (MACB), data blocks,
# whether the file is deleted (allocated: no)

# icat — extract file by inode (works on deleted files if inode intact)
icat -o $OFFSET /mnt/evidence/sda.dd 12345 > recovered_file.txt

# ifind — find inode by filename or find metadata address
ifind -o $OFFSET -n /etc/passwd /mnt/evidence/sda.dd

# ils — list all inodes (including unallocated/free inodes)
ils -o $OFFSET /mnt/evidence/sda.dd

# blkcat — extract raw data blocks
blkcat -o $OFFSET /mnt/evidence/sda.dd 20480  # extract block 20480

# blkls — list data blocks, show unallocated space
blkls -o $OFFSET /mnt/evidence/sda.dd > unallocated.raw
# Unallocated space may contain file fragments, slack space data

# sigfind — search for magic bytes (file signatures)
sigfind -o $OFFSET -t \x89PNG /mnt/evidence/sda.dd
# Find all PNG file headers

# tsk_recover — recover deleted files
tsk_recover -o $OFFSET /mnt/evidence/sda.dd /mnt/recovered/

Understanding MACB timestamps

Timestamp Meaning Changed When
Modified File content changed write(),truncate()
Accessed File read read(),mmap()(often disabled vianoatime)
Changed Inode metadata changed Permissions, owner, hard links, content changes
Birth File creation File first created in this filesystem 
# Extract all timestamps from an inode
istat -o $OFFSET /mnt/evidence/sda.dd 12345
# Look for:
#   Accessed:    2026-06-25 22:15:00
#   File Modified:  2026-06-25 20:00:00
#   Inode Modified:  2026-06-25 22:15:00
#   Created:  2026-03-15 08:00:00

Timeline Analysis

A forensic timeline reconstructs the sequence of events from filesystem and system log timestamps.

# Step 1: Generate bodyfile from filesystem
fls -m / -r -o $OFFSET /mnt/evidence/sda.dd > fs_timeline.body

# Step 2: Convert to mactime timeline (human-readable)
mactime -b fs_timeline.body -z UTC > fs_timeline.csv

# Step 3: Filter for a specific date range
mactime -b fs_timeline.body -z UTC 2026-06-25..2026-06-26 > incidents.csv

# Step 4: Combine with system logs
# Extract timestamps from auth.log
grep "2026-06-2[56]" /mnt/evidence/sda1/var/log/auth.log > auth_timeline.txt

# Extract timestamps from bash history (.bash_history doesn't have timestamps,
# but .bash_history modification time gives a rough order)

Super Timeline with Plaso/log2timeline

# Create a super timeline from multiple evidence sources
log2timeline.py --status_view window timeline.plaso /mnt/evidence/sda.dd

# Add system logs to the timeline
log2timeline.py timeline.plaso /mnt/evidence/sda1/var/log/

# Filter timeline by time range
psort.py -o L2tcsv -w "2026-06-25 00:00:00,2026-06-26 23:59:59" \
  timeline.plaso > filtered_timeline.csv

# Filter by specific event types
psort.py -o dynamic "date > '2026-06-25'" timeline.plaso

File Carving

File carving recovers files based on content signatures (magic bytes), not filesystem metadata. This works when filesystem structures are damaged or the attacker attempted to delete evidence. 

# foremost — file carving by header/footer signatures
sudo foremost -t all -i /mnt/evidence/sda.dd -o /mnt/carved/
# -t all: search for all known file types (jpg, png, pdf, docx, zip, etc.)
# Custom file types can be defined in /etc/foremost.conf

# scalpel — faster, more configurable file carving
sudo scalpel -c /etc/scalpel.conf -o /mnt/carved/ /mnt/evidence/sda.dd

# Recover specific file types from unallocated space
blkls -o $OFFSET /mnt/evidence/sda.dd > unallocated.raw
foremost -t jpg,png,pdf,zip,exe -i unallocated.raw -o /mnt/carved/

# photorec — companion to testdisk, excellent for photo/video recovery
sudo photorec /mnt/evidence/sda.dd
# Interactive mode — select partition, filesystem type, output directory
# Recovers: jpg, gif, png, bmp, pdf, doc, xls, zip, tar, exe, elf, and 200+ others

Deleted File Recovery

A file is "deleted" when its directory entry is removed and its inode is marked free. The data blocks persist until overwritten. 

# Find deleted files (fls shows * prefix)
fls -r -d -o $OFFSET /mnt/evidence/sda.dd
# -d: show deleted entries only

# Recover a deleted file by inode
icat -o $OFFSET /mnt/evidence/sda.dd 12345 > recovered.txt

# Check if the file is actually recoverable
istat -o $OFFSET /mnt/evidence/sda.dd 12345
# Look at "Direct Blocks" section — if blocks are allocated to another file,
# the data has been partially or fully overwritten

# tsk_recover — automated deleted file recovery
tsk_recover -o $OFFSET /mnt/evidence/sda.dd /mnt/recovered/
# Recovered files are named by inode number with original extension

Log Analysis for Forensics

System logs provide context that filesystem analysis cannot.

# Authentication timeline
grep "Accepted\|Failed\|session opened\|session closed" \
  /mnt/evidence/sda1/var/log/auth.log > auth_events.txt

# Extract all logins by a specific user
grep "Accepted.*for alice" /mnt/evidence/sda1/var/log/auth.log

# Sudo command history
grep "COMMAND=" /mnt/evidence/sda1/var/log/auth.log > sudo_commands.txt

# Package installation history (ArchLinux pacman log)
cat /mnt/evidence/sda1/var/log/pacman.log | grep installed

# Systemd journal (if persistent journal is enabled)
# Extract journal from image
journalctl --file /mnt/evidence/sda1/var/log/journal/*/system.journal \
  --since "2026-06-25" --until "2026-06-26"

# Apache access log — correlate with webshell activity
grep "POST" /mnt/evidence/sda1/var/log/httpd/access.log | \
  awk '{print $1, $4, $7, $9}' | sort | uniq -c | sort -rn

Anti-Forensics Detection

Attackers may attempt to destroy or alter evidence.

Timestomping detection

# Detect timestomping: compare inode change time (ctime) with file content modification time (mtime)
# If mtime is older than ctime on ext4, the file was likely timestomped
fls -m / -r -o $OFFSET /mnt/evidence/sda.dd | while read line; do
    inode=$(echo "$line" | awk '{print $2}' | tr -d ':')
    ctime=$(istat -o $OFFSET /mnt/evidence/sda.dd $inode | grep "Inode Modified" | awk '{print $4, $5}')
    mtime=$(istat -o $OFFSET /mnt/evidence/sda.dd $inode | grep "File Modified" | awk '{print $4, $5}')
    # If ctime is noticeably LATER than mtime (and file hasn't had permissions changed),
    # it's suspicious
done

Detecting file wiping

# Wiped files leave inode structures but zeroed data blocks
# Find files where direct blocks are all zero but metadata exists
# This is time-consuming on large images — use sampling

Detecting log tampering

# Check for gaps in log files
# auth.log entries should be sequential — gaps indicate deletion
grep "2026-06-2[56]" /mnt/evidence/sda1/var/log/auth.log | awk '{print $1, $2, $3}'

# Check journalctl for rotated/deleted journals
ls -la /mnt/evidence/sda1/var/log/journal/*/

Forensic Analysis Workflow

Consistent workflow for every investigation:

# 1. Verify image integrity
sha256sum -c /mnt/evidence/sda.dd.sha256

# 2. Identify partitions and filesystems
mmls /mnt/evidence/sda.dd
fsstat -o $OFFSET /mnt/evidence/sda.dd

# 3. Generate filesystem timeline
fls -m / -r -o $OFFSET /mnt/evidence/sda.dd > timeline.body
mactime -b timeline.body -z UTC > timeline.csv

# 4. List all files, flag suspicious locations
fls -r -o $OFFSET /mnt/evidence/sda.dd > all_files.txt
grep -E '(/tmp/|/var/tmp/|/dev/shm/|/home/.*/\.ssh/)' all_files.txt

# 5. Extract known artifacts
icat -o $OFFSET /mnt/evidence/sda.dd $(ifind -o $OFFSET -n /etc/passwd /mnt/evidence/sda.dd)
icat -o $OFFSET /mnt/evidence/sda.dd $(ifind -o $OFFSET -n /etc/shadow /mnt/evidence/sda.dd)
# SSH authorized_keys for all users
for home_dir in /home/* /root; do
    user=$(basename "$home_dir")
    inode_num=$(ifind -o $OFFSET -n "$home_dir/.ssh/authorized_keys" /mnt/evidence/sda.dd 2>/dev/null)
    if [ -n "$inode_num" ]; then
        echo "=== SSH keys for $user ==="
        icat -o $OFFSET /mnt/evidence/sda.dd $inode_num
    fi
done

# 6. Recover deleted files
tsk_recover -o $OFFSET /mnt/evidence/sda.dd /mnt/recovered/

# 7. Carve files from unallocated space
blkls -o $OFFSET /mnt/evidence/sda.dd > /mnt/unallocated.raw
foremost -i /mnt/unallocated.raw -o /mnt/carved/

# 8. Search for specific strings (IOCs, IPs, domains, email addresses)
strings -t d /mnt/evidence/sda.dd | grep -E \
  '(185\.130\.[0-9]+\.[0-9]+|evil-.*\.com|@evil\.com)' \
  > ioc_hits.txt

# 9. Generate report
echo "=== Forensic Analysis Report ==="
echo "Image: sda.dd"
echo "SHA256: $(cat /mnt/evidence/sda.dd.sha256)"
echo "Filesystem: $(fsstat -o $OFFSET /mnt/evidence/sda.dd | grep 'File System Type')"
echo ""
echo "=== Deleted Files ==="
fls -r -d -o $OFFSET /mnt/evidence/sda.dd
echo ""
echo "=== IOCs Found ==="
cat ioc_hits.txt
