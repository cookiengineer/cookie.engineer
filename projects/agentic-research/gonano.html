GoNano

Overview

GitHub Repository | GitLab Mirror

GoNano is a pure-Go LLM training and inference harness. It started as a reimplementation of nanochat and grew into a reimplementation of the DeepSeek V4.1-Flash long-context design, built on the experimental Go 1.27 simd standard-library package.

One programming language, one binary, and the AVX-512 kernel run the full harness. Train, evaluate and infer directly on the CPU without any GPU being required.

What sets GoNano apart is Mixture-of-Experts Sharding. Instead of one monolithic model, it trains and serves a bank of independent domain experts behind a small meta-router. Only the routed experts are loaded into memory. Each of the experts contributes its next-token logits, and the result is blended into a single distribution. A desktop can keep a large on-disk library of experts and needs only to load the selected experts for that specific question.

The project is for engineers who want to audit, extend, and deploy an LLM stack in a single language, and for researchers who want a readable implementation of the DeepSeek V4.1-Flash attention, its KV cache optimizations, and a MoE implementation that runs on commodity hardware.

Features

  • Mixture-of-Experts Sharding: a bank of independently trained experts, a meta-router with an n-gram fast path and a transformer classifier, on-demand loading under a byte-budgeted LRU , and blended logits across the routed experts.
  • DSpark semi-autoregressive speculative decoding: a distilled trunk, a learned draft-mask embedding, a low-rank Markov head, and a confidence scheduler that trims drafts by prefix-survival probability while staying bit-for-bit greedy.
  • Reasoning-effort control and explicit thinking: an effort level in [1,100] with an exponential token penalty during reinforcement learning, and <|think_start|> / <|think_end|> traces available as reasoning_content with an optional token budget.
  • Optimizers: AdamW , Muon with Polar-Express orthogonalization, Sinkhorn-balanced updates for embeddings and the prediction head, and the MuonAdamW router.
  • Data and training: byte-level BPE , Parquet and Markdown sources, BOS-aligned packing, sample-level attention masking, scaling-law hyperparameters, SFT , GRPO and REINFORCE policy gradients, full-vocabulary on-policy distillation, and model merging for RL re-initialization.
  • Serving: an OpenAI-compatible HTTP server with chat completions, streaming, tool calls, reasoning content, prefix reuse, and single-model or bank mode.
  • Persistence and evaluation: .gn checkpoints, GGUF export, a persistent multi-entry KV cache with LRU and TTL eviction, a sandboxed Python executor for HumanEval, and bits-per-byte, CORE, and ChatCORE evaluation.
  • A kernels.Backend contract with an AVX-512 / AVX2 SIMD implementation, a portable scalar reference for parity tests, and goroutine-per-op parallelism; everything stays float32 by design.

The transformer is selected by one of three presets. Each preset turns on a different set of architecture features; the flash preset is the default.

Flash: DeepSeek V4.1 Long Context

The recommended and default preset. It enables the complete DeepSeek V4.1-Flash long-context stack plus SwiGLU DeepSeek MoE , and it measures the best combined result.

At sequence length 16384 it is roughly 3.3x faster at prefill and 1.6-2.1x faster at decode than an uncompressed model. The trade-off is complexity and a small short-context decode cost. The sliding window and encoder-decoder replay give up a 10-15% decode margin at short context in exchange for local fidelity and the large prefill win.

Concept What it does
Causal encoder-decoder Decoder's global KV projected from the encoder's final hidden state.
HCA dense compression Merges each block of ratio key/value rows into one compressed entry.
CSA sparse attention Each query attends to the top-k compressed blocks selected by indexer.
Cross-layer reuse (FRU) Layers share compressed KV and indexer work.
Hierarchical indexer Coarse-to-fine block selection keeps deeper indexing in context length.
Local sliding window Bounded local attention merged into the same softmax as global branch.
DeepSeekMoE One shared expert plus routed fine-grained experts per block.
GQA and partial RoPE Fewer KV heads and DeepSeek-style rotary on the trailing dimensions.
Head-wise Muon and Sinkhorn Query and key updates split per head with Sinkhorn momentum.

Latent: Absorbed Low-Rank Attention

An alternate architecture that replaces the compression stack with absorbed MLA (the two are mutually exclusive) and keeps SwiGLU DeepSeek MoE and grouped-query attention. Its advantage is a genuinely smaller KV cache: instead of storing full keys and values per token, the cache holds one shared content latent row plus a decoupled rotary key, cutting cache bytes and attention compute. The disadvantage is that none of the long-context machinery is available, so long sequences do not get the flash prefill and decode speedups, and head-wise Muon stays off because it is incompatible with MLA .

Concept What it does
Low-rank query and KV latent Factors through shared low-rank latent instead of full-rank projections.
Absorbed MLA cache One latent row per token plus a rotary key, so attention reads the latent.
DeepSeekMoE Same shared-plus-routed feed-forward as the flash preset.
GQA and partial RoPE Fewer effective key/value heads and DeepSeek-style rotary.
Sinkhorn only Embedding and head stay Sinkhorn-balanced; head-wise Muon is disabled.

Dense: Classic Decoder

The historical nanochat decoder and the simplest baseline: full multi-head attention and a dense squared- ReLU MLP , with no compression, sliding window, encoder-decoder split, or mixture of experts. It is the smallest and easiest preset to reason about, which makes it a useful correctness reference and a sanity check for the optimized presets. It is also the slowest and the most memory-hungry at long context, and it carries none of the long-context optimizations, so it is not the preset to reach for beyond small models or debugging.

Concept What it does
Full multi-head attention Every head keeps its own keys and values.
Dense squared-ReLU MLP Original nanochat feed-forward, with no routed or shared experts.
No KV compression No compression, sparsity, sliding window, or encoder-decoder split.
Partial RoPE and QK-norm The shared transformer core, at full attention cost.

Architecture

GoNano is a single Go module of importable packages in three layers. The numeric core ( kernels , kernels/simd , kernels/scalar , tensors ) computes through a kernels.Backend contract and knows nothing about transformers. The model ( model ) is the DeepSeek-style transformer and its training forward/backward. The orchestration ( trainer , inference , data , tokenizer , evaluator , and - for sharding - router and bank ) drives it. No package imports one above it.

MoE Sharding is a bank-level, not a layer-level, design. The prompt is inferred through the meta-router, which keeps the domain scores for each expert. The model bank is responsible for loading and evicting the selected experts at runtime.

This ultimately saves a lot of RAM in practice, because it allows to train a non-dense model on available consumer hardware with 96GB RAM as the trainer target.

Each expert is a full, independently trained checkpoint with its own dataset and no shared weights. The meta-router maps a prompt to a domain distribution with a cheap hashed n-gram classifier that escalates to a small transformer encoder when its confidence is low. The bank loads only the routed experts and evicts the rest under a byte and model-count budget. At each decode step every selected expert runs a forward pass and their next-token logits are combined as a weighted sum, so exactly one token is sampled from the blended distribution.

This is deliberately not the same as DeepSeekMoE . DeepSeekMoE , which GoNano also implements, routes within a single layer's feed-forward block to fine-grained experts that all live in one model. MoE Sharding routes between whole models at the bank level, and the two compose: a bank expert can itself be a DeepSeekMoE model.

Building

GoNano depends on the experimental Go 1.27 simd package, so every build, test, and run needs the goexperiment.simd build tag:

export GOEXPERIMENT=simd;

go build ./...;

Vector width is auto-selected from the CPU (128, 256, or 512-bit), with AVX-512 forced via GODEBUG=simd=512 . Numeric precision is float32 everywhere and parallelism is goroutine-per-op through the internal/parallel package. Low-bit weights and KV caches were evaluated and rejected: the Go simd package has no vectorized int8-to-float32 widening, and decode is compute-bound rather than bandwidth-bound, so the backend stays float32 -only.

Testing

The suite covers scalar-vs- SIMD parity for the entire numeric backend (including flash attention), numerical gradient checks of the backprop, and an end-to-end domain-bank test that trains from datasets/ and serves over HTTP :

export GOEXPERIMENT=simd;

go test ./...;
go test -short ./...;   # skips the slow end-to-end test

go vet ./...;
gofmt -l model inference cmd internal kernels tensors;

Usage

Train a tiny model on synthetic data, then chat with it:

export GOEXPERIMENT=simd;

go run ./cmd/base_train --depth 2 --max-seq-len 64 --num-iterations 20;

go run ./cmd/chat_cli \
  --model ~/.cache/gonano/base_checkpoints/d2/model_000020.gn \
  --prompt "the capital of France is" \
  --max-tokens 24;

Serve it over an OpenAI-compatible API :

go run ./cmd/server \
  --model ~/.cache/gonano/base_checkpoints/d2/model_000020.gn \
  --addr ":8080";

curl http://localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"gonano","messages":[{"role":"user","content":"what is 2+2?"}]}';

Usage: Domain Bank

Train one expert per domain, train the meta-router, register the bank, then serve with per-turn routing and 2-way blending. The datasets/ directory is a runnable example corpus:

export GOEXPERIMENT=simd;

go run ./cmd/base_train \
  --domain "physics" \
  --depth 4 \
  --num-iterations 200 \
  --data-dir "datasets/physics" \
  --data-format "markdown";

go run ./cmd/base_train \
  --domain "math" \
  --depth 4 \
  --num-iterations 200 \
  --data-dir "datasets/math" \
  --data-format "markdown";

go run ./cmd/router_train \
  --domain physics="datasets/physics" \
  --domain math="datasets/math" \
  --data-format "markdown" \
  --out ~/.cache/gonano/router/router.gn;

go run ./cmd/bank_init \
  --domain physics=~/.cache/gonano/domains/physics/base_checkpoints/d4/model_000200.gn \
  --domain math=~/.cache/gonano/domains/math/base_checkpoints/d4/model_000200.gn \
  --router ~/.cache/gonano/router/router.gn \
  --out ~/.cache/gonano/bank/bank.json;

go run ./cmd/server \
  --bank ~/.cache/gonano/bank/bank.json \
  --max-domains 2 \
  --addr ":8080";

The router's choice is returned in the X-Gonano-Domains response header, and requesting a domain by name in the model field pins it. Every expert in a bank must share one tokenizer and vocabulary, which the bank validates at load time so their logits can be combined.

Usage: Long Context

The recommended long-context configuration is simply the default flash preset: compression ratio 4, top-k 8, indexer pool 8, FRU reuse, a sliding window of 128, and causal encoder-decoder prefill. A depth-20 pretraining run on Markdown data looks like this:

export GOEXPERIMENT=simd;

go run ./cmd/base_train \
  --depth 20 \
  --data-dir ~/webdata-md \
  --data-format "markdown" \
  --num-iterations 10000;

export SEQS="4096,16384";
export BATCH_SIZES="1,16,64";
export DECODE_TOKENS="16";
bash ./benchmark_longctx.sh;

Speedups at sequence length 16384 versus an uncompressed model, measured on a 16-core AVX-512 machine:

Configuration Prefill Decode x1 Decode x64
Compression plus sparsity 1.05-1.23x 1.31x 1.48x
Plus sliding window and CED (flash, default) ~3.3x 1.6x 2.1x

The bounded encoder-decoder replay cuts prefill work independently of context length, while decode still runs every layer per token. Treat the numbers as relative comparisons and reproduce them with ./benchmark.sh and ./benchmark_longctx.sh .
