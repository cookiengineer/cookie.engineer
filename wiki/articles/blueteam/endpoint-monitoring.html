Endpoint Monitoring

Monitoring host activity and process execution with auditd, bpftrace, Falco, and osquery.

Overview

Endpoint monitoring instruments the syscalls and process events that a compromised host leaves behind. This article covers the Linux audit subsystem, bpftrace, Falco, and osquery, compares their event sources and overhead, and shows how to turn each into a detection. After reading, you can write auditd rules, trace syscalls live, and query host state on a schedule.

Required Reading

  • /wiki/articles/fundamentals/processes.html - process lifecycle, fork/exec semantics, signals
  • /wiki/articles/fundamentals/system-calls.html - syscall interface, user/kernel transition
  • /wiki/articles/fundamentals/virtual-memory.html - address spaces, mmap, shared memory

Why Endpoint Monitoring

Network monitoring catches traffic crossing boundaries. Endpoint monitoring catches the activity that generates that traffic - process creation, file access, privilege changes, and memory manipulation. An attacker who compromises a host leaves traces in syscalls. Endpoint monitoring instruments those syscalls.

auditd Deep Dive

The audit subsystem hooks kernel syscall entry/exit points. It is the most battle-tested Linux endpoint monitoring tool. Rules are additive - the kernel evaluates all rules per syscall and fires events when criteria match.

Rule Syntax

-a action,list -F field=value -S syscall -k key
-w path -p permissions -k key

Actions: always (always log), never (never log). Lists: task (process creation), entry (syscall entry), exit (syscall exit - most useful), user (userspace messages).

Advanced Rule Set

# /etc/audit/rules.d/99-endpoint-monitoring.rules
-D
-b 8192
-f 1

# === Process Creation ===
# Capture full command line of every new process
-a always,exit -F arch=b64 -S execve -F key=proc_creation
-a always,exit -F arch=b32 -S execve -F key=proc_creation

# Capture child process creation (fork/clone)
-a always,exit -F arch=b64 -S fork -S vfork -S clone -F key=proc_fork

# === File Integrity Monitoring ===
# System configuration files
-w /etc/passwd -p wa -k etc_passwd
-w /etc/shadow -p wa -k etc_shadow
-w /etc/group -p wa -k etc_group
-w /etc/sudoers -p wa -k etc_sudoers
-w /etc/crontab -p wa -k cron_config
-w /etc/cron.d -p wa -k cron_config
-w /etc/ssh/sshd_config -p wa -k sshd_config

# Web shells — PHP file creation in web root
-w /var/www/html -p wa -k webroot_write

# Setuid/setgid binary creation
-a always,exit -F arch=b64 -S chmod -F a1=04777 -F key=setuid_creation
-a always,exit -F arch=b64 -S chmod -F a1=02777 -F key=setgid_creation

# === Privilege Operations ===
-a always,exit -F arch=b64 -S setuid -S setreuid -S setresuid -k priv_escalation
-a always,exit -F arch=b64 -S setgid -S setregid -S setresgid -k priv_escalation
-a always,exit -F arch=b64 -S capset -S prctl -k capability_change

# === Network Activity ===
-a always,exit -F arch=b64 -S socket -S bind -S connect -S accept -k socket_activity

# === Suspicious Paths ===
# Execution from temporary directories
-a always,exit -F arch=b64 -S execve -F dir=/tmp -k tmp_exec
-a always,exit -F arch=b64 -S execve -F dir=/dev/shm -k shm_exec
-a always,exit -F arch=b64 -S execve -F dir=/var/tmp -k vartmp_exec

# === Persistence Mechanisms ===
-w /etc/systemd/system -p wa -k systemd_unit
-w /etc/init.d -p wa -k init_script
-w /root/.ssh/authorized_keys -p wa -k ssh_persistence
-w /home -p wa -k home_ssh_keys -F dir=.ssh

# === Kernel Module Loading ===
-w /sbin/insmod -p x -k kernel_module
-w /sbin/rmmod -p x -k kernel_module
-w /sbin/modprobe -p x -k kernel_module
-a always,exit -F arch=b64 -S init_module -S finit_module -S delete_module -k kernel_module

-e 2

Querying with ausearch and aureport

# All process creations with command arguments
ausearch -k proc_creation --raw | ausearch --format interpret

# Failed execve attempts (nonexistent binaries, permission denied)
ausearch -m SYSCALL -sc execve --success no

# Summary report: executable invocations per user
aureport -x --summary

# Summary report: authentication events
aureport -au

# Summary report: file access
aureport -f --summary

# Summary report: anomalies (failed syscalls with unusual patterns)
aureport -a --summary

# Filter by time window
ausearch -ts 06/26/2026 00:00:00 -te 06/26/2026 23:59:59 -k proc_creation

# Filter by user
ausearch -ua 1000 -k proc_creation

# Filter by executable name
ausearch -x /usr/bin/python3 -k proc_creation

# Interpret raw audit events as readable strings
ausearch -k proc_creation --format interpret | head -50

# Real-time tail of audit events
ausearch -k proc_creation -i --format interpret -w

bpftrace

bpftrace compiles BPF programs from a high-level awk-like language and attaches them to kernel tracepoints. It provides live visibility without kernel modules.

Installation

pacman -S bpftrace bcc-tools

Live Tracing Recipes

# Trace all execve calls with command and arguments
bpftrace -e '
tracepoint:syscalls:sys_enter_execve {
    printf("PID %-6d UID %-6d %s\n", pid, uid, str(args->filename));
}'

# Trace processes creating network connections
bpftrace -e '
tracepoint:syscalls:sys_enter_connect {
    $fd = args->fd;
    printf("PID %-6d EXE %-20s UID %-6d connect(fd=%d)\n",
        pid, comm, uid, $fd);
}'

# Trace file open operations (excluding noise)
bpftrace -e '
tracepoint:syscalls:sys_enter_openat {
    if (args->flags & O_CREAT) {
        printf("PID %-6d EXE %-20s creates %s\n",
            pid, comm, str(args->filename));
    }
}'

# Trace process tree (follow fork/exec)
bpftrace -e '
tracepoint:sched:sched_process_fork {
    printf("PARENT PID %-6d -> CHILD PID %-6d %s\n",
        pid, args->child_pid, comm);
}'

# Trace privilege escalation (setuid calls)
bpftrace -e '
tracepoint:syscalls:sys_enter_setuid {
    printf("PID %-6d EXE %-20s UID %d -> %d\n",
        pid, comm, uid, args->uid);
}'

# Capture count of execve by binary (top 10)
bpftrace -e '
tracepoint:syscalls:sys_enter_execve {
    @execs[str(args->filename)] = count();
}
interval:s:10 {
    print(@execs, 10);
    clear(@execs);
}'

# Trace DNS queries made by processes
bpftrace -e '
tracepoint:syscalls:sys_enter_sendto {
    $saddr = (struct sockaddr_in *)args->addr;
    if ($saddr->sin_port == 13568) {  // port 53 in network byte order
        printf("PID %-6d EXE %s sending to port 53\n", pid, comm);
    }
}'

Falco

Falco is a graduated project of the Cloud Native Computing Foundation. It uses a kernel module or eBPF probe to capture syscalls, evaluates them against a rule engine (similar to a WAF for syscalls), and emits alerts. Rules are written in a YAML -like DSL.

Installation (Arch)

pacman -S falco falco-rules
# Or via AUR: yay -S falco-bin

Key Configuration

# /etc/falco/falco.yaml
json_output: true
json_include_output_property: true
log_stderr: true
log_level: info
priority: debug
buffered_outputs: false
outputs:
  rate: 1
  max_burst: 10

Default Rule Examples

# Detect shell spawned in a container
- rule: Terminal shell in container
  desc: A shell was used as the entrypoint/exec point into a container
  condition: >
    spawned_process and container and
    proc.name in (shell_binaries)
  output: "Shell spawned in container (user=%user.name container=%container.info shell=%proc.name cmdline=%proc.cmdline)"
  priority: NOTICE
  tags: [container, shell]

# Detect write below binary dir
- rule: Write below binary dir
  desc: File written below /bin, /sbin, /usr/bin, /usr/sbin
  condition: >
    evt.dir = < and evt.type in (open, openat, creat) and
    fd.name startswith /bin or fd.name startswith /sbin or
    fd.name startswith /usr/bin or fd.name startswith /usr/sbin
  output: "File below binary dir written (user=%user.name file=%fd.name)"
  priority: CRITICAL
  tags: [filesystem, mitre_persistence]

Custom Rule: Detect Reverse Shell

# /etc/falco/rules.d/custom-reverse-shell.yaml
- rule: Reverse shell connection
  desc: Process with shell name establishes outbound connection
  condition: >
    spawned_process and
    proc.name in (nc, ncat, netcat, bash, sh, zsh, busybox) and
    evt.type = connect and fd.sport != 0
  output: >
    Reverse shell detected: pid=%proc.pid cmd=%proc.cmdline
    connection=%fd.name
  priority: CRITICAL
  tags: [network, reverse_shell, mitre_execution]

Rule Writing Syntax

Fields:
  evt.type — syscall event type (open, openat, connect, execve, etc.)
  evt.dir  — direction: > (enter) or < (exit)
  proc.name — executable name (bash, python, curl)
  proc.cmdline — full command line
  proc.pid, proc.ppid — PID and parent PID
  fd.name — file descriptor name (path, socket address)
  user.name — user running the process
  container.id — container ID if applicable

Operators:
  and, or, not
  in, contains, startswith, endswith
  =, !=, <, >, <=, >=
  exists (field exists)

Macros (reusable):
- macro: shell_procs
  condition: proc.name in (bash, sh, zsh, dash)

osquery Introduction

osquery exposes the operating system as a relational database. You query running processes, open sockets, kernel modules, and file metadata with SQL . The full osquery article covers this in depth (see /wiki/articles/blueteam/osquery.html ). Here we focus on its role in endpoint monitoring. 

# Installation
pacman -S osquery

# Interactive mode
osqueryi

# Query: all processes with listening ports
osquery> SELECT pid, name, uid, cmdline FROM processes
  WHERE pid IN (SELECT pid FROM listening_ports);

# Query: processes with outbound connections to non-standard ports
osquery> SELECT p.pid, p.name, p.cmdline, s.remote_address, s.remote_port
  FROM processes p
  JOIN process_open_sockets s ON p.pid = s.pid
  WHERE s.remote_port NOT IN (80, 443, 53);

# Query: recently modified executables
osquery> SELECT path, mtime, size FROM file
  WHERE (path LIKE '/usr/bin/%' OR path LIKE '/usr/sbin/%')
  AND mtime > (strftime('%s', 'now') - 86400);

Comparing Approaches

Tool Event Source Latency Overhead Scope
auditd Kernel syscalls Low Medium (5-10% at heavy rulesets) All syscalls, rule-filtered
bpftrace eBPF tracepoints Near-zero Low (< 1% per probe) Specific events, not persistent
Falco Kernel module / eBPF Low Low-medium Syscall-level, rule engine
osquery Userspace polling + events Medium Low State queries, scheduled packs

Decision matrix:

  • auditd - mandatory baseline, required for compliance, persistent rules
  • bpftrace - ad-hoc investigations, live debugging, one-off tracing tasks
  • Falco - runtime alerting, behavioral detection, container security
  • osquery - scheduled state queries, compliance checks, forensics

None of these tools replace each other. A mature SOC runs auditd persistently, deploys Falco for behavioral alerting, uses osquery for scheduled state monitoring, and keeps bpftrace in the toolbox for live investigations.

eBPF-based Monitoring

eBPF is the substrate beneath bpftrace, Falco (modern driver), Cilium, and many monitoring tools. It provides a sandboxed virtual machine in the kernel that runs verified programs at hook points.

Key hook types for security monitoring:

  • tracepoint - static kernel instrumentation (syscall entry/exit, scheduler events, network stack)
  • kprobe/kretprobe - dynamic kernel function entry/return hooks
  • uprobe/uretprobe - dynamic userspace function hooks
  • raw_tracepoint - lower-overhead tracepoints
  • fentry/fexit - lowest-overhead kernel function hooks (BPF trampoline)

    bpf_get_current_comm(&comm, sizeof(comm));

    return 0;

Detection: Process Injection

# auditd rule: detect ptrace-based injection
-a always,exit -F arch=b64 -S ptrace -k process_injection

# bpftrace: detect ptrace attachment
bpftrace -e '
tracepoint:syscalls:sys_enter_ptrace {
    printf("PTRACE PID %d -> TARGET %d REQUEST %d\n",
        pid, args->pid, args->request);
}'

# Falco rule: alert on PTRACE usage by anything other than a debugger
- rule: PTRACE usage
  desc: A process other than gdb invokes ptrace
  condition: evt.type = ptrace and proc.name != "gdb"
  output: "PTRACE used (caller=%proc.name pid=%proc.pid)"
  priority: WARNING

Challenge

Write a Go tool that scans /proc , resolves each process's exe symlink, and prints an alert for every process executed from /tmp , /var/tmp , or /dev/shm . These are the same paths the auditd rules above watch, but the tool needs no kernel audit subsystem. Build it, run a harmless binary from /tmp , and confirm that the tool reports it while ss reports nothing unusual. 

package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strconv"
	"strings"
)

var suspicious = []string{"/tmp/", "/var/tmp/", "/dev/shm/"}

func main() {
	entries, err := os.ReadDir("/proc")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	for _, entry := range entries {
		if !entry.IsDir() {
			continue
		}

		pid, err := strconv.Atoi(entry.Name())
		if err != nil {
			continue
		}

		exe, err := os.Readlink(filepath.Join("/proc", entry.Name(), "exe"))
		if err != nil {
			continue
		}

		for _, prefix := range suspicious {
			if !strings.HasPrefix(exe, prefix) {
				continue
			}

			raw, _ := os.ReadFile(filepath.Join("/proc", entry.Name(), "cmdline"))
			args := strings.Split(strings.TrimRight(string(raw), "\x00"), "\x00")

			fmt.Printf("ALERT pid=%d exe=%s cmd=%s\n", pid, exe, strings.Join(args, " "))
		}
	}
}
						
go build -o tmp-exec tmp-exec.go
./tmp-exec

# Trigger the alert from a second terminal
install -m 0755 /bin/sleep /tmp/harmless
/tmp/harmless 300 &
./tmp-exec
# ALERT pid=... exe=/tmp/harmless cmd=/tmp/harmless 300
