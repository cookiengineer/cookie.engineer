GoNano

Overview

GitHub Repository | GitLab Mirror

GoNano is a pure-Go reimplementation of nanochat : an end-to-end LLM training and inference harness built on the experimental Go 1.27 simd standard-library package.

Most LLM infrastructure is a thin Go wrapper around Python and C, which makes it awkward to audit and hard to deploy. GoNano flips that around: one language, one binary, and AVX-512 kernels that stretch long-context, batched inference across the CPU - no GPU required.

The project is tuned for long context (100k tokens and beyond) rather than single-stream latency, so a plain x86 box can run the same train, evaluate, and serve loop that usually needs a full Python stack.

Features

  • End-to-end training and inference, from tokenizer to chat, in a single Go program.
  • SIMD kernels for matmul, softmax, RMSNorm, and reductions, with a portable scalar fallback used for parity testing.
  • The nanochat GPT transformer with RoPE , QK-norm, GQA , value embeddings, and sliding windows.
  • Measured long-context optimizations: goroutine-parallel kernels, split-K flash decoding, a vectorized SIMD exp , and a rank-1 score-tile GEMM .
  • HCA dense KV compression with a learned per-channel softmax compressor.
  • CSA with a hierarchical lightning indexer that bounds the scored entries per query.
  • A local sliding-window attention branch merged into the compressed branch through one exact softmax.
  • Causal encoder-decoder prefill: the decoder global compressed KV is projected from the encoder hidden state, and prefill is encoder-only plus a bounded decoder replay.
  • Cross-layer KV and indexer reuse ( F / R / U patterns) that drops compressor and indexer parameters from reuse layers.
  • Partial RoPE and grouped-query or multi-query attention for cheaper KV caches.
  • Byte-level BPE tokenizer training and inference.
  • AdamW , Muon, and MuonAdamW optimizers.
  • An OpenAI -compatible HTTP server with chat completions, streaming, and tool calls.
  • GGUF export for running models elsewhere.
  • A sandboxed Python executor for HumanEval benchmarks.

Architecture

The numeric core lives behind a small kernels.Backend contract. kernels/simd is the production implementation ( AVX-512 / AVX2 , goroutine-parallel), while kernels/scalar is a portable pure-Go reference that the parity tests compare against; backends can be swapped at runtime with tensors.UseKernelBackend .

On top of that sit tensors (dense float32 / int32 types), model (the nanochat transformer plus the compressed, sparse, sliding-window, and encoder-decoder attention paths), optimizer , tokenizer , data (Parquet, Snappy, Hugging Face downloads, Markdown, dataloaders), trainer , inference ( KV -cache engine, sampler, benchmark), server , evaluator , executor , and the internal/parallel worker pool.

Building

The simd package is experimental and gated behind the goexperiment.simd build tag, so every build, test, and run must set it. 

export GOEXPERIMENT=simd;

go build ./...;

Vector width is auto-selected from the CPU (128, 256, or 512-bit), with AVX-512 enabled via GODEBUG=simd=512 . Numeric precision is float32 everywhere, and parallelism is goroutine-per-op through the internal/parallel package. Low-bit weights and KV were evaluated and rejected: the Go simd package has no vectorized int8-to-float32 widening, and decode is compute-bound rather than bandwidth-bound, so the backend stays float32 -only.

Testing

Every feature has a unit test: scalar-vs- SIMD parity tests for the entire numeric backend (including flash attention), numerical gradient checks of the backprop (including grouped-query, compressed, sparse, sliding-window, and encoder-decoder paths), and an end-to-end train, save, load, generate test. 

export GOEXPERIMENT=simd;

go test -race ./...;
go vet ./...;
gofmt -l model inference cmd internal kernels tensors;

Usage

Train a tiny model on synthetic data, then chat with it:

export GOEXPERIMENT=simd;

# Train a tiny model (synthetic data, no dataset required)
go run ./cmd/base_train --depth 4 --max-seq-len 64 --num-iterations 50;

# Chat with it
go run ./cmd/chat_cli --model ~/.cache/gonano/base_checkpoints/d4/model_000050.gn --prompt "the capital of France is";

Serve it over an OpenAI -compatible API : 

go run ./cmd/server --model ~/.cache/gonano/base_checkpoints/d4/model_000050.gn --addr :8080;

curl http://localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"gonano","messages":[{"role":"user","content":"what is 2+2?"}]}';

Pretrain on real data from Parquet shards or a folder of Markdown documents with ./trainer.sh , or export your checkpoint to GGUF with go run ./cmd/export .

Usage: Long Context

The recommended long-context configuration enables the full compression, sparsity, sliding-window, and causal encoder-decoder stack: 

export GOEXPERIMENT=simd;

go run ./cmd/base_train --depth 20 --data-dir ~/webdata-md --data-format markdown \
  --compression-ratio 4 --sparse-topk 8 --swa-window 128 --ced --num-iterations 10000;

At a sequence length of 16384 that stack measures roughly 3.3x prefill and 1.6-2.1x decode versus an uncompressed model on a 16-core AVX-512 machine. Run ./benchmark.sh to reproduce the numbers from a fresh temporary directory: it builds the binaries, trains a tiny model on synthetic data, and sweeps the decode batch sizes.
