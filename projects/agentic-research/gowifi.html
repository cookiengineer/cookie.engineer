GoWIFI

Overview

GitHub Repository | GitLab Mirror

GoWIFI is an evil-twin access point framework that runs as a single self-contained pure-Go binary on a Raspberry Pi 4 with a couple of Atheros adapters. It stands up a fake copy of a target network, serves a captive portal to harvest credentials, then replays those credentials to join the real network and bridge the victim onto the internet.

It exists for one purpose: to show organizations, concretely, how their Wi-Fi security fails - in an authorized test, on a network you are allowed to hit. Everything from reconnaissance to deauthentication to credential replay happens from one binary.

Features

  • Reconnaissance of the target network via nmcli .
  • An evil-twin access point on the target ESSID and channel.
  • A pure-Go DHCP server, DNS hijacker, and templateable captive portal.
  • A transparent HTTP proxy and SMTP / IMAP relays that capture plaintext credentials.
  • Optional 802.11 deauthentication frames to force clients off the real AP .
  • Credential replay on a second adapter to join the real network, with NAT bridging.
  • Resumable, goroutine-parallel WPA2 -PSK cracking with checkpoint files.

Building

make build;                 # native binary
make build-arm64;           # cross-compiled static binary for the Pi
make build-portal-generic;  # bundle only the generic portal

Portal themes are separate packages and are go:embed ed at build time. Build tags control which are bundled (exclude with -tags no_fortinet,no_cisco ).

Usage

GoWIFI has four modes, which exchange data through a single campaign folder. 

gowifi scan      # capture handshakes + campaign data (monitor mode)
gowifi prepare   # crack captured handshakes (wordlist and/or brute force)
gowifi deploy    # run the full attack for a campaign folder
gowifi check     # verify dependencies and hardware

A typical campaign splits the work between the physical twin and a bigger cracking machine:

# 1. On the physical evil twin: capture handshakes
sudo gowifi scan -ssid "CORP_WIFI" -bssid "aa:bb:cc:dd:ee:ff" -monitor wlan2 -campaign ./gowifi-campaign;

# 2. On the big CPU machine: crack
gowifi prepare -campaign ./gowifi-campaign -wordlist words.txt;
gowifi prepare -campaign ./gowifi-campaign -charset abcdef0123456789 -minlen 8 -maxlen 10 -workers 16;

# 3. Back on the physical twin: deploy
sudo gowifi deploy;

The campaign folder is self-contained and timestamped, holding the target's SSID and BSSID , observed clients, captured handshakes, and any credentials intercepted from victims.

Testing

make test;              # unit + loopback end-to-end tests
make test-race;         # with the race detector
make test-integration;  # hardware tests (run on the Pi only)
make vet;

Wi-Fi operations are hard to test on a dev host, so every OS boundary sits behind a runner.Executor interface. Parsing, DHCP / DNS wire formats, and 802.11/netlink encoders are pure functions tested against golden fixtures, and the full attack flow is covered by a dry-run end-to-end test against fakes.
