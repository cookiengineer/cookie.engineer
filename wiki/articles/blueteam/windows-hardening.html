Windows Hardening

Practical Windows security configuration covering GPO s, Defender, ASR rules, credential protection, and logging.

Overview

Windows hardening shifts the default posture from a general-purpose desktop OS to a purpose-restricted workstation or server. Unlike Linux where the admin typically starts from a minimal install and adds services, Windows ships with a broad set of features enabled. The hardening process is therefore subtractive - identify what is not needed and disable it, then lock down what remains.

Required Reading

  • PE (Portable Executable) - Windows executable format, import/export tables
  • Authorization - authorization models, RBAC , ABAC, MAC

Group Policy Objects

GPO s are the primary configuration delivery mechanism for Windows domains. They apply registry keys, security policies, software restrictions, and scripts to groups of machines.

Core GPO hierarchy for hardening: 

Default Domain Policy
  +-- Account Policies (password, lockout, Kerberos)
  +-- Local Policies (audit, user rights, security options)

Workstation Hardening GPO
  +-- Windows Defender Antivirus
  +-- Attack Surface Reduction
  +-- Windows Firewall
  +-- Administrative Templates (PowerShell logging, legacy protocols)

Server Hardening GPO
  +-- (Inherits Workstation + adds role-specific policies)

Key GPO Settings

# Account Policies
Password Policy:
  Minimum password length: 14 characters
  Enforce password history: 24 passwords
  Maximum password age: 60 days
  Minimum password age: 1 day
  Password must meet complexity: Enabled

Account Lockout Policy:
  Account lockout threshold: 5 invalid logon attempts
  Account lockout duration: 30 minutes
  Reset lockout counter after: 30 minutes

# Security Options
Interactive logon: Do not display last user name: Enabled
Network security: LAN Manager authentication level: Send NTLMv2 response only, refuse LM and NTLM
Network security: LDAP client signing requirements: Require signing
Microsoft network server: Digitally sign communications (always): Enabled
Microsoft network client: Digitally sign communications (always): Enabled
Accounts: Administrator account status: Disabled
Accounts: Guest account status: Disabled

Windows Defender Configuration

Windows Defender Antivirus is the built-in antimalware, and Microsoft Defender for Endpoint extends it to EDR . Configure via GPO (preferred) or PowerShell.

Real-Time Protection

# Enable cloud-delivered protection (MAPS)
Set-MpPreference -MAPSReporting Advanced

# Enable automatic sample submission
Set-MpPreference -SubmitSamplesConsent SendAllSamples

# Enable PUA protection (Potentially Unwanted Applications)
Set-MpPreference -PUAProtection Enabled

# Enable network protection (blocks outbound to malicious URLs)
Set-MpPreference -EnableNetworkProtection Enabled

# Scan removable drives automatically
Set-MpPreference -DisableRemovableDriveScanning $false

# Enable behavior monitoring
Set-MpPreference -DisableBehaviorMonitoring $false

# Check current configuration
Get-MpPreference | Format-List

Scheduled Scans

# Configure daily quick scan at 2 AM
Set-MpPreference -ScanScheduleQuickScanTime 02:00

# Configure weekly full scan on Sunday
Set-MpPreference -ScanScheduleDay Sunday
Set-MpPreference -ScanScheduleTime 03:00

# Enable scan after signature update
Set-MpPreference -CheckForSignaturesBeforeRunningScan $true

Attack Surface Reduction Rules

ASR rules prevent common attack techniques at the process level. Each rule is identified by a GUI D and can be set to Off , AuditMode , Block , or Warn .

Rule ID Description
BE9BA2D9-53EA-4CDC-84E5-9B1EEEE46550 Block executable content from email client and webmail
D4F940AB-401B-4EFC-AADC-AD5F3C50688A Block all Office applications from creating child processes
5BEB7EFE-FD9A-4556-801D-275E5FFC04CC Block execution of potentially obfuscated scripts
75668C1F-73B5-4CF0-BB93-3ECF5CB7CC84 Block Office applications from injecting code
3B576869-A4EC-4529-8536-B80A7769E899 Block Office applications from creating executable content
D3E037E1-3EB8-44C8-A917-57927947596D Block JS or VBScript from launching downloaded content
92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B Block Win32 API calls from Office macros
9E6C4E1F-7D60-472F-BA1A-A39EF669E4B2 Block credential stealing from LSASS
D1E49AAC-8F56-4280-B9BA-993A6D77406C Block process creations from PSExec and WMI commands
B2B3F03D-6A65-4F7B-A9C7-1C7EF74A9BA4 Block untrusted and unsigned processes that run from USB
E6DB77E5-3DF2-4CF1-B95A-636979351E5B Block persistence through WMI event subscription
56A863A9-875E-4185-98A7-B882C64B5CE5 Block abuse of exploited vulnerable signed drivers

Deploy the rules in Enabled (block) mode with one command: 

$rules = @(
    'BE9BA2D9-53EA-4CDC-84E5-9B1EEEE46550',
    'D4F940AB-401B-4EFC-AADC-AD5F3C50688A',
    '5BEB7EFE-FD9A-4556-801D-275E5FFC04CC',
    '75668C1F-73B5-4CF0-BB93-3ECF5CB7CC84',
    '3B576869-A4EC-4529-8536-B80A7769E899',
    'D3E037E1-3EB8-44C8-A917-57927947596D',
    '92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B',
    '9E6C4E1F-7D60-472F-BA1A-A39EF669E4B2',
    'D1E49AAC-8F56-4280-B9BA-993A6D77406C',
    'B2B3F03D-6A65-4F7B-A9C7-1C7EF74A9BA4'
)
$actions = @('Enabled') * $rules.Count
Add-MpPreference -AttackSurfaceReductionRules_Ids $rules -AttackSurfaceReductionRules_Actions $actions

Always deploy ASR rules in audit mode first for at least 7 days:

# Audit mode - logs events without blocking
$actions = @('AuditMode') * $rules.Count
Add-MpPreference -AttackSurfaceReductionRules_Ids $rules -AttackSurfaceReductionRules_Actions $actions
# Check audit events in Event Viewer:
# Applications and Services Logs > Microsoft > Windows > Windows Defender >
#   Operational (Event ID 1121 = block, 1122 = audit)

LSASS Protection

LSASS stores credentials in memory. It is the primary target for credential dumping tools like Mimikatz. 

# Enable LSA protection (requires reboot)
# GPO: Computer Configuration > Admin Templates > System > Local Security Authority >
#   Configure LSA to run as a protected process: Enabled with "Enabled with UEFI Lock"

# Check via registry
Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name RunAsPPL

# Set via registry
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" \
  -Name RunAsPPL -Value 1 -PropertyType DWord -Force

Credential Guard

Credential Guard uses virtualization-based security (VBS) to isolate credential storage in a separate virtualized memory space.

Prerequisites

UEFI with Secure Boot, VT-x or AMD-V, and TPM 2.0. 

# Verify hardware support
Get-ComputerInfo -Property DeviceGuard*

# Enable via GPO:
# Computer Configuration > Admin Templates > System > Device Guard >
#   Turn On Virtualization Based Security: Enabled
#   Platform Security Level: Secure Boot and DMA Protection
#   Credential Guard Configuration: Enabled with UEFI Lock

# Verify after reboot
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard

WDAC Application Control

WDAC (formerly Device Guard) enforces that only trusted, signed code can execute. The policy is enforced by the kernel and cannot be bypassed by user-mode tricks. 

<!-- WDAC baseline policy: Allow Microsoft + signed applications -->
<?xml version="1.0" encoding="utf-8"?>
<SiPolicy xmlns="urn:schemas-microsoft-com:sipolicy"
          PolicyType="Base Policy">
  <VersionEx>10.0.0.0</VersionEx>
  <PolicyID>{A244370E-44C9-4C06-B551-F6016E563076}</PolicyID>
  <BasePolicyID>{A244370E-44C9-4C06-B551-F6016E563076}</BasePolicyID>
  <Rules>
    <Rule>
      <Option>Enabled:UMCI</Option> <!-- User Mode Code Integrity -->
    </Rule>
    <Rule>
      <Option>Enabled:Update Policy No Reboot</Option>
    </Rule>
    <Rule>
      <Option>Required:WHQL</Option> <!-- Windows Hardware Quality Labs -->
    </Rule>
  </Rules>
</SiPolicy>
						
# Convert XML to binary policy
ConvertFrom-CIPolicy -XmlFilePath baseline.xml -BinaryFilePath baseline.bin

# Deploy (requires reboot to activate)
Copy-Item baseline.bin "C:\Windows\System32\CodeIntegrity\SiPolicy.p7b"

# Verify enforcement
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard

# Audit mode first:
# Add <Option>Enabled:Audit Mode</Option> to policy XML before deploying
# Monitor Event ID 3076 in:
# Applications and Services Logs > Microsoft > Windows > CodeIntegrity > Operational

BitLocker

Full-disk encryption is baseline. Without it, physical access to the machine grants access to all data. 

# Check BitLocker status on all volumes
Get-BitLockerVolume | Format-List MountPoint,ProtectionStatus,EncryptionMethod

# Enable BitLocker with TPM protector
Enable-BitLocker -MountPoint "C:" -TpmProtector -RecoveryPasswordProtector

# For non-TPM machines, use a password protector
Enable-BitLocker -MountPoint "C:" -PasswordProtector

# Backup the recovery key to AD (domain-joined)
$volume = Get-BitLockerVolume -MountPoint "C:"
Backup-BitLockerKeyProtector -MountPoint "C:" `
  -KeyProtectorId $volume.KeyProtector[1].KeyProtectorId

Windows Firewall

Default-deny inbound and default-allow outbound is the Windows default, but outbound filtering should be enabled for high-security workstations. 

# Enable firewall on all profiles
Set-NetFirewallProfile -All -Enabled True

# Default inbound: block, Default outbound: block (Server hardening)
Set-NetFirewallProfile -All -DefaultInboundAction Block
Set-NetFirewallProfile -All -DefaultOutboundAction Block

# Allow outbound DNS, HTTP, HTTPS
New-NetFirewallRule -DisplayName "DNS Out" -Direction Outbound `
  -Protocol UDP -RemotePort 53 -Action Allow
New-NetFirewallRule -DisplayName "HTTP Out" -Direction Outbound `
  -Protocol TCP -RemotePort 80 -Action Allow
New-NetFirewallRule -DisplayName "HTTPS Out" -Direction Outbound `
  -Protocol TCP -RemotePort 443 -Action Allow

# Log dropped packets (troubleshooting)
Set-NetFirewallProfile -All -LogAllowed False -LogBlocked True `
  -LogFileName "%SystemRoot%\System32\LogFiles\Firewall\pfirewall.log"

PowerShell Logging

PowerShell is the primary attack tool on Windows. Comprehensive logging is mandatory for detection.

# Enable ScriptBlock Logging (logs full script content, even obfuscated)
# GPO: Computer Config > Admin Templates > Windows PowerShell >
#   Turn on PowerShell Script Block Logging: Enabled
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" `
  -Name EnableScriptBlockLogging -Value 1 -PropertyType DWord -Force

# Enable Module Logging (logs cmdlet usage)
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging" `
  -Name EnableModuleLogging -Value 1 -PropertyType DWord -Force
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging\ModuleNames" `
  -Name "*" -Value "*" -PropertyType String -Force

# Enable Transcription (records entire session)
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription" `
  -Name EnableTranscripting -Value 1 -PropertyType DWord -Force
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription" `
  -Name OutputDirectory -Value "C:\Logs\PSTranscripts" -PropertyType String -Force

# Event IDs for detection:
# 4104 - ScriptBlock logging
# 4103 - Module logging (pipeline execution)
# 4105 - Transcription started
# 4106 - Transcription stopped

Disabling Legacy Protocols

Legacy protocols are responsible for a disproportionate number of lateral movement attacks.

# Disable SMBv1 (WannaCry/EternalBlue vector)
Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol
Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force

# Disable LLMNR (Link-Local Multicast Name Resolution - used for poisoning)
New-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient" `
  -Name EnableMulticast -Value 0 -PropertyType DWord -Force

# Disable NetBIOS over TCP/IP (NBT-NS - also a poisoning vector)
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\NetBT\Parameters\Interfaces\Tcpip*" `
  -Name NetbiosOptions -Value 2

# Disable WPAD (Web Proxy Auto-Discovery - poisoning vector)
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\Wpad" `
  -Name WpadOverride -Value 1 -PropertyType DWord -Force

# Disable mDNS (multicast DNS poisoning)
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters" `
  -Name EnableMDNS -Value 0 -PropertyType DWord -Force

Security Compliance Toolkit

The Microsoft Security Compliance Toolkit (SCT) provides baseline policies that can be imported into GPO or applied locally with LGPO.exe : 

# Download from: https://www.microsoft.com/en-us/download/details.aspx?id=55319
# Extract and apply baselines:

# Apply a local GPO backup
.\LGPO.exe /g "C:\SecurityBaselines\Windows-10-v22H2\GPOs"

# Apply specific policy components
.\LGPO.exe /s "C:\MyCustom\DefenderSettings.inf"

AppLocker

AppLocker restricts executable execution by publisher, path, or hash (less granular but simpler than WDAC ).

AppLocker rules for a hardened workstation:

# Default Rules (required - allow Windows system binaries):
Allow Everyone: %WINDIR%\*  (Path: All Windows files)
Allow Everyone: %PROGRAMFILES%\*  (Path: All Program Files)

# Publisher Rules (recommended over path/hash):
Allow Everyone: Publisher=O=MICROSOFT CORPORATION, L=REDMOND, S=WASHINGTON, C=US
Allow Everyone: Publisher=O=VMWARE, INC., L=PALO ALTO, S=CA, C=US

# For enterprise apps - Publisher rules with version range:
Allow "Finance": Publisher=O=ORACLE AMERICA, INC., S=*, C=*,
  Product=JAVA(TM) PLATFORM SE *, AND FileVersion >= 8.0 AND FileVersion < 22.0

# Enforce DLL rules (important but high-touch - deploy in audit first)
AppLocker DLL Rule Collection: Enabled, Audit Only initially

# Audit log location:
# Event Viewer > Applications and Services > Microsoft > Windows > AppLocker
						
# Test the effective policy against an application (audit mode)
Get-AppLockerPolicy -Effective | Test-AppLockerPolicy -Path C:\Apps\ -User Everyone

# Export for deployment
Get-AppLockerPolicy -Effective -Xml > C:\Policies\AppLocker.xml

# Import on target
Set-AppLockerPolicy -XmlPolicy C:\Policies\AppLocker.xml

# The AppLocker service must be running
Set-Service AppIDSvc -StartupType Automatic
Start-Service AppIDSvc

Practical Hardening Order

Deploy hardening in this order, testing between each stage:

Phase 0 - Baseline: Install Windows, apply all updates
Phase 1 - Credential Hardening: LSASS protection, Credential Guard, BitLocker
Phase 2 - Network Hardening: Disable legacy protocols, configure firewall
Phase 3 - Execution Hardening: WDAC (audit first), or AppLocker
Phase 4 - PowerShell Hardening: ScriptBlock + Module logging, Transcription
Phase 5 - Defender + ASR: Real-time protection, ASR rules (audit first)
Phase 6 - Remove Software: Uninstall unnecessary components, disable services

# Export current security settings
secedit /export /cfg C:\audit\current-policy.inf

Get-MpPreference | Select-Object -ExpandProperty AttackSurfaceReductionRules_Actions

Challenge

Write a Go tool that audits an exported Windows security policy against a baseline. On a Windows host run secedit /export /cfg current-policy.inf , copy the INF to your Linux machine, then parse the [System Access] values and report PASS , FAIL , or MISSING for each control. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

type check struct {
	key string
	min int
	max int
}

var baseline = []check{
	{"MinimumPasswordLength", 14, 0},
	{"PasswordHistorySize", 24, 0},
	{"MinimumPasswordAge", 1, 0},
	{"MaximumPasswordAge", 1, 60},
	{"LockoutBadCount", 1, 5},
	{"LockoutDuration", 30, 0},
	{"ResetLockoutCount", 30, 0},
	{"ClearTextPassword", 0, 0},
	{"EnableGuestAccount", 0, 0},
}

func main() {
	path := "current-policy.inf"
	if len(os.Args) > 1 {
		path = os.Args[1]
	}

	values, err := parseINF(path)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	failed := 0

	for _, c := range baseline {
		raw, ok := values[c.key]
		if !ok {
			fmt.Printf("MISSING  %s\n", c.key)
			failed++
			continue
		}

		value, err := strconv.Atoi(strings.Trim(raw, "\""))
		if err != nil {
			fmt.Printf("INVALID  %s = %s\n", c.key, raw)
			failed++
			continue
		}

		if (c.max > 0 && value > c.max) || value < c.min {
			fmt.Printf("FAIL     %-24s %d\n", c.key, value)
			failed++
		} else {
			fmt.Printf("PASS     %-24s %d\n", c.key, value)
		}
	}

	fmt.Printf("\n%d of %d controls failed\n", failed, len(baseline))
	if failed > 0 {
		os.Exit(1)
	}
}

func parseINF(path string) (map[string]string, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer file.Close()

	values := make(map[string]string)
	scanner := bufio.NewScanner(file)

	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		if line == "" || strings.HasPrefix(line, ";") {
			continue
		}
		parts := strings.SplitN(line, "=", 2)
		if len(parts) != 2 {
			continue
		}
		key := strings.TrimSpace(parts[0])
		value := strings.TrimSpace(parts[1])
		values[key] = value
	}

	return values, scanner.Err()
}
