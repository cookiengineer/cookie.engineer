Synchronization

Kernel concurrency control from spinlocks to RCU - the locking hierarchy, lockdep, atomic operations, memory barriers, and real-time kernel synchronization on x86-64 Linux.

Overview

Kernel code runs concurrently with itself: preemption, interrupts, and other cores can all touch the same data structure at the same moment. This article follows the primitives the kernel uses to keep that safe, from spinlocks and mutexes through RCU and seqlocks, then shows how lockdep finds deadlocks before they happen and how PREEM PT _RT reshapes the locking model.

Why Kernel Synchronization Exists

User-space programs can get away with sloppy locking because the kernel provides scheduling boundaries. In kernel space, there is no such safety net. A kernel thread can be preempted at any instruction (with CONFIG_PREEMPT ), interrupts can fire between any two machine instructions, and other CPU cores execute code simultaneously on the same data structures. The three forces that create concurrency in the kernel are:

Source Description
Preemption A higher-priority task wakes up while your kernel code is mid-execution -> schedule()
Interrupts A hardware IRQ fires -> top-half handler runs on the same CPU, potentially touching shared data structures your code is modifying
SMP Another CPU core is executing the same kernel code path simultaneously, operating on global per-subsystem data structures

The kernel's locking hierarchy is designed to address all three sources proportionally:

Critical section protected only against →  Mechanism needed
════════════════════════════════════════   ══════════════════
Other CPUs (SMP)                           spin_lock()
Other CPUs + bottom halves                 spin_lock_bh()
Other CPUs + interrupts                    spin_lock_irqsave()
Multiple writers + readers                 read/write locks
Writer exclusion (no CPU spinning)         mutex / semaphore
Read-mostly scalability                    RCU
Lockless producer/consumer                 seqlock

Spinlocks

A spinlock is the simplest and most fundamental kernel synchronization primitive. It busy-waits (spins) until the lock is acquired, consuming CPU cycles but avoiding the overhead of context switching. Spinlocks are suitable only for short critical sections - microseconds, not milliseconds.

Classic Ticket Spinlock

The traditional Linux spinlock used a ticket-based fairness scheme:

ticket spinlock structure (arch/x86/include/asm/spinlock_types.h):

struct arch_spinlock {
    union {
        __ticketpair_t head_tail;
        struct __raw_tickets {
            __ticket_t head;   // ticket currently being served
            __ticket_t tail;   // next ticket to hand out
        } tickets;
    };
};
						
// Conceptual ticket spinlock implementation
static __always_inline void arch_spin_lock(arch_spinlock_t *lock)
{
    register struct __raw_tickets inc = { .tail = TICKET_INC };
    inc = xadd(&lock->tickets, inc);   // Atomic fetch-and-add tail

    // Spin until our ticket is being served
    while (lock->tickets.head != inc.tail)
        cpu_relax();  // PAUSE instruction — reduces power, avoids speculation
}

static __always_inline void arch_spin_unlock(arch_spinlock_t *lock)
{
    __add(&lock->tickets.head, TICKET_INC);  // Increment head, next waiter can go
}

The ticket mechanism guarantees FIFO ordering: waiters are served in the order they arrived.

Queued Spinlocks (qspinlock)

Starting from Linux 4.2, x86-64 uses queued spinlocks. Each CPU waiting for the lock forms a queue using per- CPU qnode structures. When the lock holder releases, only the next CPU in the queue is awoken

  • eliminating the cache-line bouncing of ticket spinlocks where all waiters poll the same
cache line. 

qspinlock structure:

  ┌────────────────────────────────┐
  │ 32-bit atomic value            │
  ├───────+───────+────────────────┤
  │ locked│pending│ tail (CPU idx) │
  │  1 bit│ 1 bit │    14 bits     │   (remaining bits: unused/debug)
  └───────+───────+────────────────┘

  Locked: 1 = held by someone
  Pending: 1 = one waiter in pending slot (optimistic, no queue needed)
  Tail: points to last CPU in the MCS-based wait queue
						
// arch/x86/include/asm/qspinlock.h
// The queued spinlock for x86 is derived from the generic MCS-based qspinlock

// Fast path (no contention):
void queued_spin_lock_slowpath(struct qspinlock *lock, u32 val)
{
    // Complex queue building with MCS nodes
    // See kernel/locking/qspinlock.c for the complete implementation
}

// The unlock simply clears the locked byte:
static __always_inline void queued_spin_unlock(struct qspinlock *lock)
{
    smp_store_release(&lock->locked, 0);
}

Spinlock API

// Basic usage — protects against other CPUs only
DEFINE_SPINLOCK(my_lock);

spin_lock(&my_lock);
    /* Critical section — runs on this CPU, other CPUs spin */
spin_unlock(&my_lock);

// Protect against interrupts on this CPU too:
unsigned long flags;
spin_lock_irqsave(&my_lock, flags);
    /* Interrupts disabled on this CPU; preemption disabled; SMP-safe */
spin_unlock_irqrestore(&my_lock, flags);

// Protect against bottom halves on all CPUs:
spin_lock_bh(&my_lock);
    /* Softirqs disabled on this CPU; SMP-safe */
spin_unlock_bh(&my_lock);

// Non-blocking trylock:
if (spin_trylock(&my_lock)) {
    /* Got the lock */
    spin_unlock(&my_lock);
}

Mutexes

A mutex is a sleeping lock. If the lock is unavailable, the task goes to sleep ( TASK_UNINTERRUPTIBLE ) rather than spinning. This makes mutexes suitable for longer critical sections where context switch overhead is amortized. 

// include/linux/mutex.h
struct mutex {
    atomic_long_t       owner;       // Pointer to owning task_struct
    raw_spinlock_t      wait_lock;   // Protects the wait list
    struct list_head    wait_list;   // Tasks waiting for this mutex
    ...
};

Linux mutex's optimistic spinning: before sleeping, a task spins briefly hoping the lock holder (which might be running on another CPU ) releases the lock soon. This is the MCS-based optimistic spinning from the MCS lock algorithm: 

// kernel/locking/mutex.c (simplified flow)
void __sched mutex_lock(struct mutex *lock)
{
    might_sleep();

    // Fast path: uncontended
    if (__mutex_trylock_fast(lock))
        return;

    // Slow path: contended
    __mutex_lock_slowpath(lock);
    // Inside slow path:
    // 1. Optimistic spin (MCS-style) if owner is running on another CPU
    // 2. If spin fails, sleep on wait_list
    // 3. When awoken, try to acquire
    // 4. On success, set owner and return
}

void __sched mutex_unlock(struct mutex *lock)
{
    __mutex_unlock_slowpath(lock);
}
						
// Usage:
DEFINE_MUTEX(my_mutex);

mutex_lock(&my_mutex);
    /* Can sleep here — but don't call schedule() explicitly */
    /* OK to use GFP_KERNEL allocations */
mutex_unlock(&my_mutex);

// Trylock variant:
if (mutex_trylock(&my_mutex)) {
    /* Got it without sleeping */
    mutex_unlock(&my_mutex);
}

Spinlock vs Mutex decision rule

Factor Use Spinlock Use Mutex
Critical section duration < 10 us (busy-wait OK) > 10 us (sleep is cheaper)
Can you sleep? No (interrupt context) Yes (process context)
Data structure shared with ISR? Yes (must spin) No (ISR can't sleep)
Contention rare? Yes (spinning is cheap) Either
Memory pressure OK? Yes (no alloc) Yes (struct mutex is prealloc)

Semaphores

A semaphore generalizes a mutex to allow a configurable number of concurrent holders. A binary semaphore (count = 1) is equivalent to a mutex. A counting semaphore (count > 1) is used when multiple identical resources are available. 

// include/linux/semaphore.h
struct semaphore {
    raw_spinlock_t      lock;
    unsigned int        count;
    struct list_head    wait_list;
};

// API:
void down(struct semaphore *sem);          // Decrement, sleep if zero
int down_interruptible(struct semaphore *sem);  // Returns -EINTR on signal
int down_trylock(struct semaphore *sem);   // Return 0 on success, 1 if would block
void up(struct semaphore *sem);            // Increment, wake one waiter

// Initialization:
DEFINE_SEMAPHORE(my_sem);                  // count = 1
static DECLARE_SEMAPHORE_GENERIC(my_sem_5, 5);  // count = 5
						
// Classic producer/consumer with counting semaphore:
// Buffer has N slots → semaphore initialized to N
// Consumer does down() before reading; producer does up() after writing

static DECLARE_SEMAPHORE_GENERIC(empty, 8);  // 8 empty slots
static DECLARE_SEMAPHORE_GENERIC(full, 0);   // 0 filled slots
static DEFINE_SPINLOCK(buf_lock);
static char buffer[8];
static int head, tail;

// Producer:
down(&empty);
spin_lock(&buf_lock);
    buffer[head] = produce_item();
    head = (head + 1) % 8;
spin_unlock(&buf_lock);
up(&full);

// Consumer:
down(&full);
spin_lock(&buf_lock);
    item = buffer[tail];
    tail = (tail + 1) % 8;
spin_unlock(&buf_lock);
up(&empty);

Read-Write Locks

Read-write locks distinguish between readers (shared access) and writers (exclusive access). Multiple readers can hold the lock simultaneously, but a writer must wait for all readers to leave. 

// Spinlock-based rwlock:
DEFINE_RWLOCK(my_rwlock);

// Reader:
read_lock(&my_rwlock);
    /* Multiple readers OK concurrently */
read_unlock(&my_rwlock);

// Writer:
write_lock(&my_rwlock);
    /* Exclusive access — no readers or other writers */
write_unlock(&my_rwlock);

// IRQ-safe variants:
read_lock_irqsave(&my_rwlock, flags);
write_lock_irqsave(&my_rwlock, flags);

The x86-64 rwlock uses a single 32-bit counter where bit 31 indicates a writer, and bits 0-30 count readers. A writer waiting sets bit 31 which blocks new readers (reader preference is configurable). 

// arch/x86/include/asm/rwlock.h — conceptual:
static __always_inline void arch_read_lock(arch_rwlock_t *rw)
{
    // Atomically: if (rw->lock >> 1) == 0 (no writer waiting or active)
    //               rw->lock += 1 (increment reader count)
    //             else
    //               spin until writer releases
    asm volatile(LOCK_PREFIX " ; incl (%0)\n\t"
                 "jns 1f\n\t"
                 "call __read_lock_failed\n\t"
                 "1:\n"
                 :: "r" (rw) : "memory");
}

RCU - Read-Copy-Update

RCU is Linux's most innovative synchronization mechanism. The key insight: for read-mostly data structures, writers can create a new version, atomically swap the pointer, and wait until all pre-existing readers have left their critical sections before freeing the old version. 

RCU Update Pattern:

Before:
  ┌──────┐
  │ Node │  ←── reader_ptr → points here
  │  A   │
  └──────┘

Writer wants to change "A" to "B":

  1. Copy Node A → Node B'
     ┌──────┐     ┌──────┐
     │ Node │     │ Node │
     │  A   │     │  B'  │  ← modified copy
     └──────┘     └──────┘
          ▲
     reader_ptr

  2. rcu_assign_pointer(): atomically swing pointer
     ┌──────┐     ┌──────┐
     │ Node │     │ Node │
     │  A   │     │  B'  │  ← new readers see B'
     └──────┘     └──────┘
                    ▲
               reader_ptr

  3. synchronize_rcu(): wait for all pre-existing RCU readers to finish
     (pre-existing readers might still hold a reference to A)

  4. kfree(Node A) — safe now: no reader references A anymore
						
// RCU API:
// Reader — extremely cheap (barrier-free on x86):
rcu_read_lock();
    struct my_node *node = rcu_dereference(global_ptr);
    /* Use node — must NOT sleep, must NOT block */
    /* Must NOT store pointer to node for later use outside critical section */
    do_something(node);
rcu_read_unlock();

// Writer:
struct my_node *old, *new;

new = kmalloc(sizeof(*new), GFP_KERNEL);
*new = *old;          // Copy
new->field = updated_value;  // Modify copy
old = rcu_replace_pointer(global_ptr, new, lockdep_is_held(&my_lock));

synchronize_rcu();    // Wait for grace period — can sleep!
/* Or use call_rcu() for asynchronous callback: */
// call_rcu(&old->rcu_head, my_free_callback);

kfree(old);           // Safe: all readers have released references

RCU Grace Period

A grace period is the interval during which every CPU has passed through a quiescent state (context switch, return to user space, or idle). synchronize_rcu() blocks until all CPU s have reported a quiescent state. 

CPU 0:  ████[reader]███████████[qs]██████████████████
CPU 1:  ██████████[reader]██████████████[qs]██████████
CPU 2:  █████████████████████[qs]██████████████████████
CPU 3:  ███████████████[reader]████[qs]████████████████
                        │                           │
                        ▼                           ▼
              synchronize_rcu() called        Grace period ends
                                              (all CPUs passed QS)
                                              kfree() is now safe

Atomic Operations

Atomic operations are the building blocks of lock-free algorithms. They guarantee that a read-modify-write operation completes without any other CPU observing an intermediate state. 

// include/linux/atomic/atomic-instrumented.h

typedef struct {
    int counter;
} atomic_t;

typedef struct {
    s64 counter;
} atomic64_t;

// Core operations — all return void (set/destroy) or old/new value:
int atomic_read(const atomic_t *v);
void atomic_set(atomic_t *v, int i);
void atomic_inc(atomic_t *v);
void atomic_dec(atomic_t *v);
int atomic_inc_return(atomic_t *v);        // Return new value
int atomic_dec_and_test(atomic_t *v);      // Return true if result == 0
int atomic_cmpxchg(atomic_t *v, int old, int new);  // CAS — returns old value
int atomic_xchg(atomic_t *v, int new);     // Exchange, return old
int atomic_fetch_add(atomic_t *v, int i);  // Add, return old

compare-and-swap (cmpxchg) in depth

cmpxchg is the universal atomic primitive - all other atomic operations can be built from it: 

// arch/x86/include/asm/cmpxchg.h
// Hardware instruction: LOCK CMPXCHG
//
// Pseudocode: if (*ptr == old) { *ptr = new; return old; } else { return *ptr; }
//
// The LOCK prefix makes it atomic across all CPUs.

static __always_inline unsigned long
__cmpxchg(volatile void *ptr, unsigned long old, unsigned long new, int size)
{
    unsigned long prev;
    switch (size) {
    case 1:
        asm volatile(LOCK_PREFIX "cmpxchgb %b2,%1"
                     : "=a"(prev), "+m"(*(u8 *)ptr)
                     : "q"(new), "0"(old)
                     : "memory");
        return prev;
    case 4:
        asm volatile(LOCK_PREFIX "cmpxchgl %2,%1"
                     : "=a"(prev), "+m"(*(u32 *)ptr)
                     : "r"(new), "0"(old)
                     : "memory");
        return prev;
    case 8:
        asm volatile(LOCK_PREFIX "cmpxchgq %2,%1"
                     : "=a"(prev), "+m"(*(u64 *)ptr)
                     : "r"(new), "0"(old)
                     : "memory");
        return prev;
    }
    return old;
}

Memory ordering barriers

x86-64 memory ordering model (strong — TSO):
  Loads are not reordered with loads
  Stores are not reordered with stores
  Stores are not reordered with prior loads
  Loads MAY be reordered with prior stores (only allowed reordering)

Linux barrier macros:
  barrier()          — Compiler barrier only (no asm volatile reordering)
  smp_mb()           — Full memory barrier (mfence / lock;addl)
  smp_rmb()          - Read barrier (compiler barrier on x86; loads stay ordered)
  smp_wmb()          - Write barrier (compiler barrier on x86; stores stay ordered)
  smp_store_release()— Store-release: all prior stores visible before this one
  smp_load_acquire() — Load-acquire: all subsequent loads see this one's effect

Linux atomic operations imply memory ordering:
  atomic_read() / atomic_set()  — No ordering (RELAXED)
  atomic_inc() / atomic_dec()   — Full barrier before and after
  atomic_cmpxchg()              — Full barrier
  atomic_fetch_add()            — Full barrier

Seqlocks

A seqlock (sequential lock) provides lock-free reads while writers use a spinlock:

// include/linux/seqlock.h
typedef struct {
    seqcount_spinlock_t seqcount;
    spinlock_t          lock;
} seqlock_t;

// Writer:
write_seqlock(&my_seqlock);
    /* Modify data under spinlock protection */
    /* seqcount auto-incremented on unlock */
write_sequnlock(&my_seqlock);

// Reader (lock-free, optimistic):
unsigned seq;
do {
    seq = read_seqbegin(&my_seqlock);
    /* Read data — no locking! */
    value = shared_data;
} while (read_seqretry(&my_seqlock, seq));
/* If seq changed, a writer ran during our read → retry */

The seqcount is the backbone of the kernel's timekeeping subsystem ( ktime_get() ). The timekeeper sequence counter lets thousands of concurrent readers sample the clock while only the timer interrupt writes it, without taking a lock. The jiffies_64 counter itself is a plain variable that readers load with READ_ONCE() .

Completion Variables and Wait Queues

A completion is a one-shot synchronization primitive: one task waits for a specific event, and another task signals when it occurs. 

// include/linux/completion.h
struct completion {
    unsigned int done;          // 0 = not done; 1 = done
    swait_queue_head_t wait;    // Wait queue for sleepers
};

DECLARE_COMPLETION(my_done);

// Waiter:
wait_for_completion(&my_done);  // Sleep until complete
// Or with timeout:
if (wait_for_completion_timeout(&my_done, msecs_to_jiffies(5000)) == 0)
    printk("Timeout!\n");

// Signaler:
complete(&my_done);             // Wake exactly one waiter
// complete_all(&my_done);      // Wake all waiters

Wait queues are more general - they wake on arbitrary conditions: 

// Simplest usage: wait for a flag to become true
static DECLARE_WAIT_QUEUE_HEAD(my_wq);
static int condition = 0;

// Waiter:
wait_event(my_wq, condition != 0);
// Or interruptible:
if (wait_event_interruptible(my_wq, condition))
    return -ERESTARTSYS;

// Signaler:
condition = 1;
wake_up(&my_wq);                // Wake all waiters (default for exclusive=0)
// wake_up_interruptible(&my_wq);

Lockdep - Lock Dependency Validator

Lockdep is the kernel's runtime deadlock detector. It tracks lock acquisition order across the entire kernel and reports any potential deadlock cycles - before they actually deadlock. 

How Lockdep works:

  1. Every lock class (struct spinlock, struct mutex, etc. at a given code location)
     is assigned a unique class ID.
  2. Lockdep maintains a directed graph: if lock A is held while acquiring lock B,
     an edge A → B is added.
  3. Before each lock acquisition, Lockdep checks that adding the new edge does not
     create a cycle. If it would, Lockdep warns immediately.
  4. Lockdep also tracks interrupt state: holding a non-irq-safe lock while
     interrupts are disabled is flagged as a potential deadlock.

  Example detection:

    CPU 0:  lock(A) → lock(B)         Creates edge A → B
    CPU 1:  lock(B) → lock(A)         Detects cycle: A → B → A = DEADLOCK!
                                          │
                                          ▼
    =============================================
    WARNING: possible circular locking dependency detected
    ...stack trace on both CPUs...
    =============================================
						
# Check if lockdep is enabled

# Enable lockdep diagnostics

# wait-total  = total nanoseconds spent waiting for this lock

Preempt-RT and Priority Inversion

The CONFIG_PREEMPT_RT patch converts most kernel spinlocks into mutexes, making nearly all kernel code preemptible at any point. This reduces scheduling latency but requires careful migration of locking primitives:

Standard Kernel PREEMPT_RT Kernel
spinlock = raw spin spinlock = rt_mutex (sleeps!)
local_irq_disable() local_irq_disable() (same)
spin_lock_irqsave() spin_lock_irqsave() = rt_mutex
raw_spinlock_t (true spinlock) raw_spinlock_t = true spinlock (for truly atomic sections)

Priority Inversion Problem

Without priority inheritance (standard kernel):
  Low-priority task holds mutex M
  High-priority task wakes, tries lock(M) → sleeps waiting
  Medium-priority task runs, preempts low → high waits indefinitely
  (Medium is not using M but has higher priority than low)

With priority inheritance (PREEMPT_RT, also in pthread_mutex PI):
  Low holds mutex M → inherits high's priority while holding M
  Low runs at high priority → finishes quickly → releases M → high gets M
  Priority inversion bounded

zcat /proc/config.gz 2>/dev/null | grep PREEMPT_RT
# CONFIG_PREEMPT_RT=y

# Check kernel preemption model

Common Kernel Race Conditions

Double-fetch (TOCTOU in kernel)

// Vulnerable: user pointer read twice, value can change between reads
SYSCALL_DEFINE2(bad_copy, int __user *, user_ptr, size_t, size)
{
    int len;

    if (copy_from_user(&len, user_ptr, sizeof(len)))
        return -EFAULT;
    // ... ATTACKER CHANGES *user_ptr HERE ...
    if (len > MAX_BUF)
        return -EINVAL;
    // len is validated, but user memory may now contain a different value

    copy_from_user(kbuf, user_buf, len);  // Uses unchecked len!
    // Attacker races: first read len=small, second read len=huge → kernel overflow
}

// Correct: fetch once, validate and use the local copy
SYSCALL_DEFINE2(good_copy, int __user *, user_ptr, size_t, size)
{
    int len;

    if (copy_from_user(&len, user_ptr, sizeof(len)))
        return -EFAULT;
    // Validate locally
    if (len > MAX_BUF)
        return -EINVAL;
    // Use local variable — cannot be changed by attacker
    copy_from_user(kbuf, user_buf, len);
}

Per-CPU race with preemption

// Wrong: preemption between get_cpu_ptr() and use
void bad_percpu(void)
{
    int *ptr = per_cpu_ptr(&shared_var, smp_processor_id());
    // <<< PREEMPTION HERE → we're on a different CPU → ptr is wrong! >>>
    *ptr = 42;
}

// Correct: disable preemption
void good_percpu(void)
{
    int *ptr = get_cpu_ptr(&shared_var);  // Disables preemption
    *ptr = 42;
    put_cpu_ptr(&shared_var);             // Re-enables preemption
}
