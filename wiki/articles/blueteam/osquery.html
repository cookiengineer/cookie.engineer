Osquery

Endpoint querying for investigations using osquery virtual tables, scheduled packs, and forensic use cases.

Overview

Osquery exposes operating system state as relational tables, so the same SQL query runs on Linux, macOS, and Windows. This article covers the architecture, the tables that matter during incident response, scheduled differential queries, and a challenge that hunts planted forensic artifacts on a live host.

Required Reading

  • Processes - process lifecycle, signals, parent relationships
  • Filesystems - inodes, file metadata, extended attributes

Why Osquery

Osquery turns your operating system into a relational database. Instead of writing platform-specific scripts to query process lists, open sockets, kernel modules, or installed packages, you write SQL . This uniformity across Linux, macOS, and Windows is osquery's superpower. A query written on your Arch workstation runs identically on a Windows domain controller.

Architecture

osqueryi — interactive SQL shell, ad-hoc queries, one-shot
osqueryd — daemon mode, scheduled queries, log results, distributed plugins
osquery  ─+─ osquery-extension (thrift-based plugin)
          ├─ RocksDB (internal state database)
          └─ Virtual Tables (filesystem, process table, etc.)

osquery uses virtual tables - tables that look like SQL but are backed by function calls to the OS API . A SELECT * FROM processes triggers /proc enumeration on Linux, sysctl on macOS, and CreateToolhelp32Snapshot on Windows.

Installation (Arch)

pacman -S osquery
# Or AUR for newer versions
yay -S osquery-bin

Interactive Mode (osqueryi)

osqueryi

# Show all tables
osquery> .tables

# Describe a table's schema
osquery> .schema processes
osquery> .schema listening_ports

# Enable/disable display modes
osquery> .mode line       # one field per line (best for reading)
osquery> .mode csv        # CSV output
osquery> .mode column     # columnar table (default)
osquery> .mode pretty     # formatted bordered table
osquery> .mode json       # JSON output

# Exit
osquery> .exit

Essential Schema Tables

Process Tables

-- All running processes
SELECT pid, name, uid, gid, parent, cmdline, start_time
FROM processes
WHERE name != ''
ORDER BY start_time DESC
LIMIT 20;

-- Processes that are listening on network ports
SELECT DISTINCT p.pid, p.name, p.cmdline, p.uid, p.parent
FROM processes p
JOIN listening_ports l ON p.pid = l.pid
WHERE l.port > 0;

-- Process ancestry — find what spawned a suspicious process
WITH RECURSIVE ancestors(pid, name, parent, depth) AS (
    SELECT pid, name, parent, 0
    FROM processes
    WHERE pid = 12345  -- target PID
    UNION ALL
    SELECT p.pid, p.name, p.parent, a.depth + 1
    FROM processes p
    JOIN ancestors a ON p.pid = a.parent
    WHERE a.depth < 10
)
SELECT * FROM ancestors ORDER BY depth;

-- Processes running from temp directories (malware staging)
SELECT pid, name, cmdline, uid
FROM processes
WHERE cmdline LIKE '%/tmp/%' OR cmdline LIKE '%/dev/shm/%'
   OR cmdline LIKE '%/var/tmp/%';

Network Tables

-- All listening ports with process info
SELECT l.port, l.protocol, l.address, p.pid, p.name
FROM listening_ports l
JOIN processes p ON l.pid = p.pid
WHERE l.port > 0
ORDER BY l.port;

-- Outbound connections (not listening)
SELECT s.pid, s.remote_address, s.remote_port, s.local_port, s.state, p.name
FROM process_open_sockets s
JOIN processes p ON s.pid = p.pid
WHERE s.remote_port > 0 AND s.state != 'LISTEN';

-- Check for services listening on all interfaces (0.0.0.0 / ::)
SELECT l.port, l.protocol, l.address, p.name
FROM listening_ports l
JOIN processes p ON l.pid = p.pid
WHERE l.address IN ('0.0.0.0', '::') AND l.port > 0;

-- Open sockets to external IPs (exclude RFC 1918 and loopback)
SELECT p.name, p.cmdline, s.remote_address, s.remote_port
FROM process_open_sockets s
JOIN processes p ON s.pid = p.pid
WHERE s.remote_address NOT LIKE '127.%'
  AND s.remote_address NOT LIKE '10.%'
  AND s.remote_address NOT LIKE '192.168.%'
  AND s.remote_address NOT LIKE '172.1_.%'
  AND s.remote_address NOT LIKE '172.2_.%'
  AND s.remote_address NOT LIKE '172.3[0-1].%';

File Tables

-- Setuid/setgid binaries (privilege escalation paths)
SELECT path, uid, gid, mode, mtime
FROM file
WHERE (path LIKE '/usr/bin/%' OR path LIKE '/usr/sbin/%'
    OR path LIKE '/bin/%' OR path LIKE '/sbin/%')
  AND (mode LIKE '4%' OR mode LIKE '2%')
ORDER BY path;

-- Recently modified files in system bin dirs (potential tampering)
SELECT path, mtime, size, uid
FROM file
WHERE path LIKE '/usr/bin/%'
  AND mtime > strftime('%s', 'now') - 604800  -- last 7 days
ORDER BY mtime DESC
LIMIT 30;

-- SSH authorized_keys files (persistence check)
SELECT path, mtime, size
FROM file
WHERE path LIKE '%/.ssh/authorized_keys';

-- Writable crontabs (persistence)
SELECT path, mtime
FROM file
WHERE path LIKE '/var/spool/cron/%' OR path LIKE '/etc/cron.d/%';

User and Authentication Tables

-- Users with UID 0 (root-equivalent)
SELECT uid, username, description, directory, shell
FROM users
WHERE uid = 0;

-- Users with shells (can log in)
SELECT uid, username, shell
FROM users
WHERE shell NOT LIKE '%/nologin%' AND shell NOT LIKE '%/false'
  AND uid >= 1000;

-- Recently logged in users
SELECT time, type, username, host, message
FROM last
ORDER BY time DESC
LIMIT 20;

Persistence Detection Tables

-- Crontab entries
SELECT command, path, hour, minute, day_of_week, day_of_month, month
FROM crontab;

-- Systemd units (Linux)
SELECT id, fragment_path, active_state, sub_state
FROM systemd_units
WHERE fragment_path != '';

-- Shell history — check for suspicious commands
SELECT uid, command, history_file, line
FROM shell_history
WHERE command LIKE '%curl%|%bash%' OR command LIKE '%wget%|%bash%'
   OR command LIKE '%nc -e%' OR command LIKE '%/dev/tcp/%';

-- Loaded kernel modules (rootkit detection)
SELECT name, size, used_by, address
FROM kernel_modules
ORDER BY name;

Scheduled Queries and Packs

osqueryd runs queries on a schedule and logs differential results. It writes to a local log file and can forward results to remote collectors. 

// /etc/osquery/osquery.conf
{
  "options": {
    "config_plugin": "filesystem",
    "logger_plugin": "filesystem",
    "logger_path": "/var/log/osquery",
    "schedule_splay_percent": 10,
    "events_expiry": 3600,
    "disable_audit": false,
    "audit_allow_config": true,
    "audit_allow_sockets": true,
    "enable_syslog": true,
    "syslog_pipe_path": "/var/osquery/syslog_pipe"
  },

  "schedule": {
    "processes_listening": {
      "query": "SELECT p.pid, p.name, p.cmdline, l.port, l.protocol FROM processes p JOIN listening_ports l ON p.pid = l.pid WHERE l.port > 0;",
      "interval": 300
    },
    "new_setuid_binaries": {
      "query": "SELECT path, uid, mode FROM file WHERE (path LIKE '/usr/bin/%' OR path LIKE '/usr/sbin/%') AND mode LIKE '4%' AND mtime > strftime('%s', 'now') - 86400;",
      "interval": 3600,
      "removed": false
    },
    "unauthorized_users": {
      "query": "SELECT uid, username, shell FROM users WHERE uid = 0 AND username != 'root';",
      "interval": 7200
    },
    "kernel_modules": {
      "query": "SELECT name, size, used_by FROM kernel_modules;",
      "interval": 3600
    },
    "suspicious_processes": {
      "query": "SELECT pid, name, cmdline FROM processes WHERE cmdline LIKE '%/tmp/%' OR cmdline LIKE '%nc -e%' OR cmdline LIKE '%/dev/tcp%';",
      "interval": 60
    }
  },

  "packs": {
    "incident-response": "/usr/share/osquery/packs/incident-response.conf",
    "osquery-monitoring": "/usr/share/osquery/packs/osquery-monitoring.conf",
    "vuln-management": "/usr/share/osquery/packs/vuln-management.conf"
  }
}

Custom Pack Example

// /usr/share/osquery/packs/linux-persistence.json
{
  "platform": "linux",
  "queries": {
    "systemd_services": {
      "query": "SELECT id, fragment_path, active_state FROM systemd_units WHERE fragment_path != '';",
      "interval": 3600,
      "description": "Enumerate all systemd units"
    },
    "authorized_keys": {
      "query": "SELECT path, mtime FROM file WHERE path LIKE '%/.ssh/authorized_keys';",
      "interval": 1800,
      "description": "Check SSH authorized_keys for changes"
    },
    "crontab_entries": {
      "query": "SELECT command, path, hour, minute FROM crontab;",
      "interval": 3600,
      "description": "Enumerate all crontab entries"
    },
    "shell_history_suspicious": {
      "query": "SELECT uid, command FROM shell_history WHERE command LIKE '%base64%|%sh%' OR command LIKE '%bash -i%' OR command LIKE '%/dev/tcp%';",
      "interval": 300,
      "description": "Detect suspicious shell history entries"
    },
    "kernel_module_load": {
      "query": "SELECT name, size, used_by FROM kernel_modules WHERE name NOT IN ('ext4', 'nf_conntrack', 'nfnetlink', 'nf_tables', 'iptable_filter');",
      "interval": 7200,
      "description": "List non-standard kernel modules"
    }
  }
}

Differential Queries

Differential queries track state changes between runs. They detect addition, removal, or modification of rows. 

-- Track new processes since last query
-- When configured with "removed": true, osquery reports:
-- "added": rows that appeared since last query
-- "removed": rows that disappeared since last query
SELECT pid, name, cmdline FROM processes WHERE parent = 1;

-- Track new listening ports (potential backdoors)
SELECT port, protocol, pid FROM listening_ports WHERE port NOT IN (22, 80, 443);

-- Track changes to /etc/passwd
SELECT * FROM file WHERE path = '/etc/passwd';

YARA Integration

osquery supports YARA scanning via the yara table. It can scan files, process memory, or both. 

-- Configure YARA signature file
-- In osquery.conf:
-- "yara": { "signature_urls": ["file:///etc/osquery/yara/signatures.yara"] }

-- Scan a specific directory with a YARA signature group
SELECT path, matches, count
FROM yara
WHERE path LIKE '/var/www/%'
  AND sig_group = 'webshell_signatures';

-- Scan running process memory (Linux only, requires /proc/sys/kernel/yama/ptrace_scope = 0)
SELECT pid, name, matches
FROM yara
WHERE count > 0
  AND sig_group = 'malware_signatures';

-- Scan process memory of non-system processes
SELECT y.pid, p.name, y.matches, y.count
FROM yara y
JOIN processes p ON y.pid = p.pid
WHERE y.sig_group = 'credential_dump_signatures'
  AND y.count > 0;

Fleet Central Management

Fleet (successor to Kolide) manages osquery deployments at scale - pushing configs, collecting results, and providing a web UI. 

# Fleet server setup (simplified)
git clone https://github.com/fleetdm/fleet.git
cd fleet
./tools/backEnd/build/fleet prepare db --dev
./tools/backEnd/build/fleet serve --dev

# Enroll host
fleetctl package --type deb --fleet-url https://fleet.example.com:8443 --enroll-secret=secret

# Query all hosts for open SSH sessions
fleetctl query --hosts all "SELECT * FROM logged_in_users WHERE tty != '';"

# Schedule a query across the fleet
fleetctl apply -f scheduled-query.yaml

Forensic Use Cases

Finding Persistence Mechanisms

-- Combine multiple persistence indicators
SELECT 'crontab' AS source, command AS detail FROM crontab
UNION ALL
SELECT 'systemd_user_unit', target_path FROM systemd_units WHERE fragment_path LIKE '/home/%'
UNION ALL
SELECT 'ssh_key', path FROM file WHERE path LIKE '%/.ssh/authorized_keys'
UNION ALL
SELECT 'bashrc', key || '=' || value FROM file
WHERE (path LIKE '/home/%/.bashrc' OR path = '/root/.bashrc');

Unusual Process Investigation

-- Find processes without a known parent (potential daemonization or PID reuse)
SELECT p.pid, p.name, p.parent, p.cmdline
FROM processes p
LEFT JOIN processes pp ON p.parent = pp.pid
WHERE pp.pid IS NULL AND p.parent != 0;

-- Find processes with deleted executables (malware that unlinks itself)
SELECT pid, name, path, cmdline
FROM processes
WHERE on_disk = 0;

Challenge

The container ships osqueryd, a set of planted persistence artifacts, and ten investigation exercises. Build it, run it, and answer each exercise with a query instead of with shell commands.

osquery.Containerfile

podman build -f blueteam/osquery.Containerfile -t osquery-ctf .
podman run -it --rm osquery-ctf

Inside the container, start from the planted shell history:

osqueryi "SELECT uid, command, history_file FROM shell_history WHERE command LIKE '%/dev/tcp%';"
