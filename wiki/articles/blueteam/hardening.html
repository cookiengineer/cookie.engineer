Hardening

Systematic reduction of attack surface through configuration baselines, service control, and filesystem restrictions.

Overview

Hardening removes the components an attacker can use and tightens the configuration of what remains. This article covers the baseline frameworks, the attack-surface reduction workflow, service, kernel, SSH , and PAM hardening, and the audit loop that keeps a hardened host hardened. After reading, you can write a sysctl baseline, lock down a systemd unit, and detect configuration drift.

Required Reading

  • Processes - process lifecycle, signals, namespaces
  • Unix Permissions - user/group/other, setuid, setgid, sticky
  • Capabilities - Linux capabilities, ambient sets, bounding sets

Concept

Hardening is the process of eliminating unnecessary components and tightening configurations to reduce the number of paths an attacker can take to compromise a system. It is not a one-time checklist - it is a continuous methodology that must be re-evaluated whenever the system's role or software inventory changes.

The core principle: if a component does not have a documented operational need, it should not exist on the system.

Every running service, every installed package, every open port, every kernel module, every SUID binary, every world-writable directory is a potential entry point. You cannot defend what you do not know exists.

Security Baselines

Security baselines provide a standardized starting point. They define minimum acceptable configurations for operating systems and applications.

Baseline Publisher Scope Format
CIS Benchmarks Center for Internet Security OS, DB, Web, Cloud PDF / SCAP
STIG DISA (US DoD) OS, Network, Apps XCCDF / SCAP
PCI DSS PCI Security Standards Council Payment systems Requirements doc
BSI Grundschutz BSI (Germany) Comprehensive IT PDF / XML

CIS Benchmarks are the most accessible starting point. They are community-reviewed, freely available, and come with tools like oscap for automated assessment. 

# Install SCAP tools on ArchLinux
sudo pacman -S openscap scap-security-guide

# Scan a system against CIS Level 1 profile
sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_cis \
  --results /tmp/cis-results.xml \
  --report /tmp/cis-report.html \
  /usr/share/xml/scap/ssg/content/ssg-archlinux-ds.xml

Attack Surface Reduction - Methodology

Attack surface is the sum of all points where an unauthenticated or low-privilege user can interact with the system. Reduction follows this priority order:

Step 1 - Remove packages

# List all installed packages by size
pacman -Qi | awk '/^Name/{name=$3} /^Installed Size/{print $4, name}' | sort -h

# List all enabled services
systemctl list-unit-files --state=enabled

# Mask everything that isn't strictly required
sudo systemctl mask bluetooth.service
sudo systemctl mask avahi-daemon.service
sudo systemctl mask cups.service
sudo systemctl mask auditd.service   # unless auditing is required

Step 2 - Close network listeners

# Show all listening TCP/UDP sockets with owning process
sudo ss -tulnp

# Expected baseline for a hardened server:
# - tcp 22 (sshd) — if SSH access is required
# - tcp 443 (nginx/apache) — if a web server
# - Anything else requires justification

Step 3 - Harden kernel parameters

# /etc/sysctl.d/99-hardening.conf

# IP stack hardening
net.ipv4.tcp_syncookies = 1
net.ipv4.ip_forward = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.conf.default.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.rp_filter = 1
net.ipv4.icmp_echo_ignore_broadcasts = 1
net.ipv4.icmp_ignore_bogus_error_responses = 1

# ASLR and memory protection
kernel.randomize_va_space = 2
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
kernel.yama.ptrace_scope = 2

# Restrict kernel module loading
kernel.modules_disabled = 1   # irreversible until reboot — ensure all modules loaded first

Apply with sudo sysctl -p /etc/sysctl.d/99-hardening.conf .

Service Hardening

Every service should run with the least privilege possible. This goes beyond just the unix user:

# Create dedicated system users — no shell, no home, no login
sudo useradd -r -s /usr/sbin/nologin -M myservice

# systemd service with hardening directives
						
# /etc/systemd/system/myservice.service
[Unit]
Description=My Service

[Service]
Type=simple
User=myservice
Group=myservice

# Filesystem protection
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/myservice

# Network isolation (remove if networking needed)
PrivateNetwork=yes

# Capabilities
CapabilityBoundingSet=
AmbientCapabilities=
NoNewPrivileges=yes

# System call filtering
SystemCallFilter=@system-service
SystemCallArchitectures=native

# Device access
PrivateDevices=true
DeviceAllow=

# Kernel tunables
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectKernelLogs=yes
ProtectClock=yes

# Memory and process isolation
MemoryDenyWriteExecute=yes
RestrictRealtime=yes
RestrictNamespaces=yes
LockPersonality=yes
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6

[Install]
WantedBy=multi-user.target

Verify with:

sudo systemd-analyze security myservice

The output gives an exposure score (lower is better). Each missing directive lowers the score.

Filesystem Hardening

# /etc/fstab hardening options for critical mounts

# /tmp — noexec prevents execution of attacker-uploaded binaries
tmpfs /tmp tmpfs defaults,noexec,nosuid,nodev 0 0

# /dev/shm — commonly used for shared memory attacks
tmpfs /dev/shm tmpfs defaults,noexec,nosuid,nodev 0 0

# /home — nosuid if users do not need suid binaries there
/dev/sda3 /home ext4 defaults,nosuid,nodev 0 2

# /var — noexec on directories with writable content
# Use bind mounts for specific paths:
# /var/tmp  /var/tmp  none  bind,noexec,nosuid,nodev  0 0

Find all world-writable directories and files:

sudo find / -xdev -type f -perm -0002 2>/dev/null
sudo find / -xdev -type d -perm -0002 2>/dev/null

Find all SUID/SGID binaries:

# Baseline SUID binaries, then audit weekly for changes
sudo find / -xdev -type f \( -perm -4000 -o -perm -2000 \) -ls 2>/dev/null > /var/log/suid-baseline.txt

SSH Hardening

# /etc/ssh/sshd_config (or /etc/ssh/sshd_config.d/99-hardening.conf)

# Protocol and algorithms
Protocol 2
HostKeyAlgorithms ssh-ed25519-cert-v01@openssh.com,ssh-ed25519
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org
Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com
MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com

# Authentication
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
ChallengeResponseAuthentication no
PermitEmptyPasswords no
MaxAuthTries 3
AuthenticationMethods publickey

# User control
AllowUsers alice bob
AllowGroups ssh-users

# Session hardening
ClientAliveInterval 300
ClientAliveCountMax 2
X11Forwarding no
PermitTunnel no
AllowAgentForwarding no
AllowTcpForwarding no

# Privilege separation
UsePAM yes

Validate configuration:

sudo sshd -t
sudo systemctl reload sshd

PAM Hardening

PAM controls authentication, account, session, and password policies. It is not the same as privileged access management, despite the similar name. 

# /etc/security/faillock.conf — lock account after failed attempts
deny = 5
unlock_time = 300
						
# /etc/security/pwquality.conf — password quality requirements
minlen = 12
dcredit = -1    # at least one digit
ucredit = -1    # at least one uppercase
lcredit = -1    # at least one lowercase
ocredit = -1    # at least one special char
minclass = 3    # at least 3 character classes
						
# /etc/pam.d/system-auth — add faillock and pwquality
auth     required  pam_faillock.so preauth
auth     [success=1 default=ignore] pam_unix.so
auth     [default=die] pam_faillock.so authfail
auth     sufficient pam_faillock.so authsucc
password required  pam_pwquality.so

Ongoing Maintenance

Hardening is not a one-time event. Maintain state:

# Weekly audit script — run from cron
#!/bin/bash
# Check for new listening ports
ss -tulnp > /var/log/hardening/ports-$(date +%Y%m%d).log

# Check for new SUID binaries
find / -xdev -type f \( -perm -4000 -o -perm -2000 \) -ls 2>/dev/null \
  | diff /var/log/suid-baseline.txt -

# Check systemd service exposure
systemd-analyze security --no-pager | grep -E 'EXPOSED|UNSAFE'

# Check for package changes
pacman -Qq | diff /var/log/hardening/packages-baseline.txt - 2>/dev/null

Defense in Depth

Hardening operates at multiple layers. Failure at one layer should be contained by others:

  [ Network ] → firewall, no open ports
  [ Service ] → systemd isolation, restricted capabilities
  [ OS      ] → sysctl, filesystem restrictions, PAM
  [ Kernel  ] → seccomp, LSMs (AppArmor/SELinux)
  [ App     ] → least privilege user, read-only paths

Each layer assumes the layer above it can be breached. Design accordingly.

Detection

Audit critical changes:

# audit.rules — monitor hardening-relevant events
-w /etc/sysctl.d/ -p wa -k sysctl_change
-w /etc/ssh/sshd_config -p wa -k sshd_change
-w /etc/fstab -p wa -k fstab_change
-w /etc/pam.d/ -p wa -k pam_change
-w /etc/systemd/system/ -p wa -k systemd_unit_change
-w /etc/security/ -p wa -k security_config_change
-a always,exit -F arch=b64 -S mount -S umount2 -k mount_event
-a always,exit -F arch=b64 -S init_module -S finit_module -k module_load

Challenge

Write a Go tool that parses /etc/sysctl.conf and every /etc/sysctl.d/*.conf file, then compares the effective values against the baseline used in this article. Print MISSING for keys that are absent and WEAK for keys whose value differs, and exit non-zero when any check fails. Run it on a hardened host, then weaken one setting with sudo sysctl -w and confirm that the tool reports the drift. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"path/filepath"
	"sort"
	"strings"
)

var baseline = map[string]string{
	"net.ipv4.tcp_syncookies":            "1",
	"net.ipv4.ip_forward":                "0",
	"net.ipv4.conf.all.accept_redirects": "0",
	"net.ipv4.conf.all.rp_filter":        "1",
	"kernel.randomize_va_space":          "2",
	"kernel.kptr_restrict":               "2",
	"kernel.dmesg_restrict":              "1",
	"kernel.yama.ptrace_scope":           "2",
}

func parse(path string, cfg map[string]string) {
	file, err := os.Open(path)
	if err != nil {
		return
	}
	defer file.Close()

	scanner := bufio.NewScanner(file)
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		if line == "" || strings.HasPrefix(line, "#") {
			continue
		}
		parts := strings.SplitN(line, "=", 2)
		if len(parts) != 2 {
			continue
		}
		cfg[strings.TrimSpace(parts[0])] = strings.TrimSpace(parts[1])
	}
}

func main() {
	cfg := make(map[string]string)

	parse("/etc/sysctl.conf", cfg)

	matches, _ := filepath.Glob("/etc/sysctl.d/*.conf")
	sort.Strings(matches)
	for _, path := range matches {
		parse(path, cfg)
	}

	failures := 0
	for key, want := range baseline {
		got, ok := cfg[key]
		if !ok {
			fmt.Printf("MISSING %-38s expected %s\n", key, want)
			failures++
		} else if got != want {
			fmt.Printf("WEAK    %-38s got %s want %s\n", key, got, want)
			failures++
		}
	}

	if failures > 0 {
		fmt.Printf("%d checks failed\n", failures)
		os.Exit(1)
	}
	fmt.Println("all checks passed")
}
						
go build -o sysctl-audit sysctl-audit.go
./sysctl-audit

# Weaken a setting and confirm the tool detects the drift
sudo sysctl -w kernel.kptr_restrict=0
./sysctl-audit
# WEAK kernel.kptr_restrict got 0 want 2
