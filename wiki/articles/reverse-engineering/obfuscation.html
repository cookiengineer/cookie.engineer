Obfuscation & Deobfuscation

Techniques malware uses to hide code and how to defeat them, from UPX packing to control flow flattening and virtual machines.

Overview

Obfuscation raises the cost of static analysis. Packers compress code, crypters encrypt data, protectors add anti-debug and anti-dump checks, and virtualizers translate native instructions into a private bytecode. Each layer wraps the one below, so a sample may be a custom packer around an RC4 payload around a virtualized routine. This article walks the layers from outside in: detection, automated and manual unpacking, crypto identification, string deobfuscation, control flow recovery, and virtual machine analysis.

The Obfuscation Arms Race

Malware authors and reverse engineers operate in an escalating conflict. Each generation of obfuscation spawns a generation of deobfuscation tools, which in turn drives more sophisticated obfuscation. The taxonomy follows a clear progression:

Level Technique Goal Defeat Difficulty
1 Packer (UPX, MPRESS) Compress binary, evade signature Trivial (automated)
2 Crypter (XOR, RC4) Encrypt sections, hide strings Low
3 Protector (Themida, ASPack) Anti-debug, anti-dump, import destruction Medium
4 Virtualizer (VMProtect, Code Virtualizer) Translate x86 to custom bytecode Hard
5 Full metamorphism Rewrite entire binary per-sample Extreme

Each layer wraps the one below. A VM Protect-protected binary might contain an RC4-crypted payload, packed with a custom packer. The reverse engineer must unwind these layers from outermost to innermost - onion-peeling the binary.

UPX: The Universal Packer

UPX is the most common packer in Linux malware. It is not malicious - it is a legitimate compression tool - but it is widely abused because it is free, open-source, and trivially scripted.

How UPX Works

The packer reads the original ELF, compresses the loadable sections ( .text , .data ), and rewrites the binary with three components: 

[UPX Stub (decompressor)] -> [Compressed Data Block] -> [ELF Footer]

The stub is a small (a few KB) position-independent piece of code that:

  1. Locates the compressed data, positioned after itself in memory.
  2. Allocates memory for the decompressed sections.
  3. Decompresses using the UCL/NRV algorithm.
  4. Resolves dynamic imports (GOT/PLT reconstruction).
  5. Transfers control to the Original Entry Point (OEP).

Identifying UPX

$ strings suspicious_elf | grep -i upx
UPX!
$Info: This file is packed with the UPX executable packer
UPX1
UPX2

The section names UPX0 , UPX1 , UPX2 are characteristic. UPX0 is empty in the file (zeros) but holds the uncompressed original .text in memory. UPX1 contains both the stub code and compressed data. 

$ readelf -S suspicious_elf
[ 1] UPX0             PROGBITS         0000000000401000  00001000
     000000000001f000  0000000000000000         0         0
[ 2] UPX1             PROGBITS         000000000041f000  00001000
     000000000000c000  0000000000000000         0         0

Notice UPX0 has a filesize of 0 but memory size of 0x1f000 - the section exists only in memory after decompression.

Automated Unpacking

The simplest approach:

$ upx -d packed_binary -o unpacked_binary

This works because UPX stores the necessary decompression metadata in the binary. The -d flag invokes UPX's own decompressor on the file.

Manual Unpacking with GDB

When upx -d fails (modified UPX header, corrupted metadata), manual unpacking is required. The core technique is finding the OEP - the point where the stub finishes decompressing and jumps to the original code. 

#!/usr/bin/env python3
"""find_oep.py — Locate Original Entry Point in UPX-packed binary"""

import struct
import sys

def find_tail_jump(filepath):
    """
    UPX stubs end with a tail jump to OEP. The pattern:
    - Long unconditional jump: jmp 0x... (0xE9 + 4-byte relative)
    - POPA + RET: 0x61 0xC3 (restore registers, return to OEP)
    - PUSH + RET: push addr; ret  (0x68 + 4-byte addr + 0xC3)
    
    We search the stub section (UPX1) for these patterns.
    """
    with open(filepath, 'rb') as f:
        data = f.read()

    # Find UPX1 section offset from ELF program headers
    # PHDR offset at e_phoff (usually 0x40 for 64-bit ELF)
    elf64 = data[4] == 2  # ELFCLASS64

    if elf64:
        phoff = struct.unpack_from('<Q', data, 0x20)[0]
        phnum = struct.unpack_from('<H', data, 0x38)[0]
        phentsize = struct.unpack_from('<H', data, 0x36)[0]

        for i in range(phnum):
            off = phoff + i * phentsize
            p_type = struct.unpack_from('<I', data, off)[0]
            if p_type == 1:  # PT_LOAD
                p_offset = struct.unpack_from('<Q', data, off + 8)[0]
                p_vaddr  = struct.unpack_from('<Q', data, off + 16)[0]
                p_filesz = struct.unpack_from('<Q', data, off + 32)[0]
                p_memsz  = struct.unpack_from('<Q', data, off + 40)[0]

                # UPX1: filesz matches compressed data, memsz larger
                if p_filesz > 0 and p_memsz > p_filesz * 2:
                    stub_start = p_offset
                    stub_end   = p_offset + p_filesz
                    stub_data  = data[stub_start:stub_end]
                    print(f"[+] Found UPX1 segment: file offset 0x{stub_start:x} "
                          f"size 0x{p_filesz:x}")

                    # Search for tail jump patterns
                    # Pattern 1: jmp rel32 (0xE9 XX XX XX XX)
                    for j in range(len(stub_data) - 5):
                        if stub_data[j] == 0xE9:  # JMP rel32
                            rel = struct.unpack('<i', stub_data[j+1:j+5])[0]
                            target = p_vaddr + j + 5 + rel
                            # OEP is usually in high address range
                            if target > p_vaddr + p_memsz:
                                print(f"  [*] Possible OEP via JMP rel32 at "
                                      f"0x{p_vaddr+j:x} → 0x{target:x}")

                    # Pattern 2: popa (0x61) followed by jmp/ret within 8 bytes
                    for j in range(len(stub_data) - 10):
                        if stub_data[j] == 0x61:  # POPA
                            tail = stub_data[j+1:j+9]
                            # Check for JMP near
                            for k in range(min(8, len(tail) - 4)):
                                if tail[k] == 0xE9:
                                    print(f"  [*] POPA at 0x{p_vaddr+j:x}, "
                                          f"JMP at +{k+1}")

    else:
        print("[-] Only 64-bit ELF supported in this script")

if __name__ == '__main__':
    find_tail_jump(sys.argv[1])

Import Reconstruction

After unpacking, the dumped binary has broken imports. UPX resolves imports dynamically at runtime

  • the GOT entries are populated with resolved addresses. The dumped file contains the runtime

GOT values (absolute addresses from the host process), not the original import stubs.

For Linux ELF imports, there are two approaches:

Approach 1: Fix the GOT in the dump

Write a script that walks the dynamic symbol table, identifies GOT entries, and converts absolute addresses back to relocation entries: 

#!/usr/bin/env python3
"""fix_imports.py — Reconstruct ELF imports from a memory dump"""

import struct
import sys
from elftools.elf.elffile import ELFFile

def reconstruct_imports(dump_path, original_path):
    """
    The memory dump contains resolved GOT addresses.
    We match these against the original binary's symbol table
    to determine which symbol each GOT slot corresponds to.
    """
    with open(original_path, 'rb') as f:
        orig = ELFFile(f)

    with open(dump_path, 'rb') as f:
        dump = bytearray(f.read())

    # Find .got.plt section in original
    for section in orig.iter_sections():
        if section.name == '.got.plt':
            got_off = section['sh_offset']
            got_size = section['sh_size']
            got_addr = section['sh_addr']
            print(f"[+] .got.plt at offset 0x{got_off:x} size {got_size}")

            # GOT[0] = _DYNAMIC, GOT[1] = link_map, GOT[2] = _dl_runtime_resolve
            # GOT[3+] = resolved function addresses

            for i in range(3, got_size // 8):
                entry_off = got_off + i * 8
                if entry_off + 8 > len(dump):
                    break

                addr = struct.unpack_from('<Q', dump, entry_off)[0]
                print(f"  GOT[{i}] @ 0x{got_addr + i*8:x} → "
                      f"rva 0x{addr - 0x400000:x}")

In practice, for comprehensive import reconstruction, use LIEF:

#!/usr/bin/env python3
"""reconstruct_elf.py — Use LIEF to rebuild import table"""

import lief

def rebuild_imports(unpacked_path, output_path):
    binary = lief.parse(unpacked_path)

    # LIEF can reconstruct imports from the dynamic section
    # if the .dynsym and .dynstr sections survived unpacking
    if binary.has_dynamic_symbols:
        for sym in binary.dynamic_symbols:
            if sym.imported:
                print(f"  Import: {sym.name} @ {hex(sym.value)}")

    binary.write(output_path)
    print(f"[+] Reconstructed binary written to {output_path}")

Encrypted Code: XOR Cipher

The simplest encryption malware uses is XOR - fast, reversible, and trivially implemented:

/* xor_decrypt.c — Typical malware string decoder */
void decode_string(unsigned char *data, size_t len, unsigned char key) {
    for (size_t i = 0; i < len; i++) {
        data[i] ^= key;
    }
}

In disassembly, an XOR decode loop is unmistakable:

; Ghidra decompiler output, cleaned up
void decode_buffer(byte *buf, ulong len, byte key)
{
    ulong i;
    for (i = 0; i < len; i = i + 1) {
        buf[i] = buf[i] ^ key;
    }
    return;
}

Breaking Single-Byte XOR

Without knowing the key, frequency analysis recovers it:

#!/usr/bin/env python3
"""xor_crack.py — Recover XOR key via frequency analysis"""

FREQ_ENGLISH = {
    ' ': 13.0, 'e': 12.7, 't': 9.1, 'a': 8.2, 'o': 7.5,
    'i': 7.0, 'n': 6.7, 's': 6.3, 'h': 6.1, 'r': 6.0,
    'd': 4.3, 'l': 4.0, 'c': 2.8, 'u': 2.8, 'm': 2.4,
}

def score_text(text: bytes) -> float:
    """Score how 'English-like' a byte sequence is."""
    if not text:
        return 0.0
    score = 0.0
    for b in text:
        ch = chr(b).lower()
        if ch in FREQ_ENGLISH:
            score += FREQ_ENGLISH[ch]
        elif b < 0x20 and b not in (0x0a, 0x0d, 0x09):
            score -= 2.0  # Penalty for control chars
        elif b > 0x7e:
            score -= 2.0
    return score / len(text)

def crack_single_byte_xor(data: bytes) -> tuple:
    best_score = -999.0
    best_key   = 0
    best_plain = b''

    for key in range(256):
        plain = bytes([b ^ key for b in data])
        sc = score_text(plain)
        if sc > best_score:
            best_score = sc
            best_key   = key
            best_plain = plain

    return best_key, best_plain

# Known-plaintext attack: if you know part of plaintext
def crack_with_known_plaintext(ciphertext: bytes, known_plain: bytes, offset: int = 0):
    """XOR ciphertext with known plaintext bytes to reveal key."""
    key_bytes = []
    for i, kp in enumerate(known_plain):
        key_bytes.append(ciphertext[offset + i] ^ kp)

    # Check if all key bytes are the same (single-byte key)
    if len(set(key_bytes)) == 1:
        return key_bytes[0]
    else:
        print("[*] Multi-byte key detected")
        return bytes(key_bytes)

Multi-Byte XOR Keys

If single-byte XOR fails to produce readable text, the key may be multi-byte (repeating XOR):

def crack_repeating_xor(data: bytes, min_len: int = 1, max_len: int = 40):
    """Attempt to crack repeating-key XOR via Hamming distance analysis."""
    
    def hamming(a: bytes, b: bytes) -> int:
        dist = 0
        for x, y in zip(a, b):
            dist += bin(x ^ y).count('1')
        return dist

    def normalized_distance(data: bytes, keylen: int) -> float:
        blocks = [data[i:i+keylen] for i in range(0, len(data), keylen)][:4]
        if len(blocks) < 2:
            return float('inf')
        dist = 0
        pairs = 0
        for i in range(len(blocks)):
            for j in range(i+1, len(blocks)):
                dist += hamming(blocks[i], blocks[j])
                pairs += 1
        return (dist / pairs) / keylen

    # Find most likely key lengths
    scores = []
    for kl in range(min_len, max_len + 1):
        if kl * 4 <= len(data):
            scores.append((kl, normalized_distance(data, kl)))

    scores.sort(key=lambda x: x[1])

    for keylen, _ in scores[:3]:
        # For each key length, crack each byte
        key = []
        for pos in range(keylen):
            block = data[pos::keylen]
            k, _ = crack_single_byte_xor(block)
            key.append(k)

        plain = bytes([data[i] ^ key[i % keylen] for i in range(len(data))])
        print(f"  keylen={keylen} key={bytes(key).hex()} plain_preview={plain[:60]}")

RC4 Encryption

RC4 is a stream cipher frequently found in malware due to its simplicity (no block operations needed). The algorithm initializes a 256-byte state with the key, then generates a keystream XORed with the plaintext: 

/* rc4.c — Standard RC4 implementation */
typedef struct {
    unsigned char S[256];
    unsigned char i, j;
} rc4_state;

void rc4_init(rc4_state *state, const unsigned char *key, size_t keylen) {
    state->i = 0;
    state->j = 0;
    for (int k = 0; k < 256; k++)
        state->S[k] = k;

    int j = 0;
    for (int k = 0; k < 256; k++) {
        j = (j + state->S[k] + key[k % keylen]) % 256;
        unsigned char tmp = state->S[k];
        state->S[k] = state->S[j];
        state->S[j] = tmp;
    }
}

void rc4_crypt(rc4_state *state, unsigned char *data, size_t len) {
    for (size_t n = 0; n < len; n++) {
        state->i = (state->i + 1) % 256;
        state->j = (state->j + state->S[state->i]) % 256;
        unsigned char tmp = state->S[state->i];
        state->S[state->i] = state->S[state->j];
        state->S[state->j] = tmp;
        data[n] ^= state->S[(state->S[state->i] + state->S[state->j]) % 256];
    }
}

Identifying RC4 in Disassembly

RC4 has a distinctive pattern: two 256-byte loops. The first (KSA - Key Scheduling Algorithm) initializes S[0..255] = 0..255 then permutes. The second (PRGA - Pseudo-Random Generation Algorithm) generates keystream. Look for:

  • Array of 256 bytes ( S[256] ) accessed with modulo-256 arithmetic
  • Two index variables ( i , j ) that wrap around
  • XOR of data with S[(S[i] + S[j]) % 256]

The KSA loop is especially recognizable because it fills an array with sequential values 0-255, then permutes it. In Ghidra, this appears as a loop initializing local_108[0..0xff] with ascending values.

Recovering RC4 Key

If you observe the KSA executing (via debugger or emulation), you can recover the key by capturing the key material passed to the KSA. Or, if you have known plaintext, XOR it with ciphertext to get the keystream - then backtrack through the RC4 state (if you captured the initial state). 

#!/usr/bin/env python3
"""rc4_identify.py — Scan binary for RC4 constant patterns"""

def find_rc4_ksa_pattern(filepath: str):
    """
    Scan for the 256-byte initialization loop pattern.
    RC4 KSA: for(i=0;i<256;i++) S[i]=i;
    Compiles to: mov byte [base+i], i  (with increment)
    """
    with open(filepath, 'rb') as f:
        data = f.read()

    # Look for byte sequences that might be RC4 init
    # Common pattern: XOR EDX,EDX; MOV [RCX+RDX],DL; INC RDX; CMP RDX,0x100
    # In x86-64: 31 d2 88 14 11 48 ff c2 48 81 fa 00 01 00 00
    
    patterns = [
        # mov [rcx+rdx], dl ; inc rdx ; cmp rdx, 0x100 ; jl loop
        bytes([0x88, 0x14, 0x11, 0x48, 0xFF, 0xC2, 0x48, 0x81, 0xFA, 0x00, 0x01]),
        # xor edx,edx ; mov [mem+edx], dl ; inc edx ; cmp edx, 0x100
        bytes([0x31, 0xD2, 0x88, 0x14]),
        # ARM variant: strb rX, [rY, rZ]; add rZ, #1; cmp rZ, #256
    ]

    for pattern in patterns:
        pos = data.find(pattern)
        if pos != -1:
            print(f"[+] Potential RC4 KSA pattern at offset 0x{pos:x}")
            return pos
    return -1

AES Encryption

AES is common in ransomware and sophisticated malware. Unlike RC4, it operates on fixed 16-byte blocks with a key schedule expansion. Detection relies on the constant tables embedded in the binary:

AES S-box (first 16 bytes)

0x63, 0x7c, 0x77, 0x7b, 0xf2, 0x6b, 0x6f, 0xc5,
0x30, 0x01, 0x67, 0x2b, 0xfe, 0xd7, 0xab, 0x76

AES Inverse S-box (first 16 bytes)

0x52, 0x09, 0x6a, 0xd5, 0x30, 0x36, 0xa5, 0x38,
0xbf, 0x40, 0xa3, 0x9e, 0x81, 0xf3, 0xd7, 0xfb

Rcon (Round Constants)

0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80, 0x1b, 0x36

def scan_crypto_constants(data: bytes, base_offset: int = 0):
    """Scan data for embedded cryptographic constants."""
    results = []

    # Search AES S-box (256 bytes)
    pos = data.find(AES_SBOX)
    if pos >= 0:
        results.append(('AES S-box', pos + base_offset))
        print(f"[+] AES S-box found at offset 0x{pos + base_offset:x}")

    # Search CRC32 table head (multiples of 4 bytes)
    pos = data.find(CRC32_TABLE_HEAD)
    if pos >= 0:
        results.append(('CRC32 table', pos + base_offset))
        print(f"[+] CRC32 table at offset 0x{pos + base_offset:x}")

    # Search MD5 IV
    for md5_const in [MD5_CONSTANTS]:
        pos = data.find(md5_const)
        if pos >= 0:
            results.append(('MD5 IV', pos + base_offset))
            print(f"[+] MD5 initialization vector at 0x{pos + base_offset:x}")

    # Search SHA1 IV
    for sha1_const in [SHA1_CONSTANTS]:
        pos = data.find(sha1_const)
        if pos >= 0:
            results.append(('SHA1 IV', pos + base_offset))
            print(f"[+] SHA1 initialization vector at 0x{pos + base_offset:x}")

    return results

if __name__ == '__main__':
    import sys
    with open(sys.argv[1], 'rb') as f:
        scan_crypto_constants(f.read())

String Obfuscation

Malware hides strings to evade static analysis. The techniques and their countermeasures:

Stack Strings (x86-64)

Instead of storing the string as a data constant, the malware constructs it byte-by-byte on the stack: 

; CONSTRUCTING THE STRING "/bin/sh" ON THE STACK
mov    rax, 0x0068732f6e69622f   ; "/bin/sh\0" in little-endian
push   rax
mov    rdi, rsp                   ; rdi now points to "/bin/sh"
; ... execve syscall ...

This is visible when Ghidra shows local_18 = 0x68732f6e69622f and the decompiler outputs a comment. To find stack strings programmatically: 

#!/usr/bin/env python3
"""scan_stack_strings.py — Find stack-constructed strings in disassembly"""

import re

def find_stack_strings(ghidra_export_file: str):
    """
    Parse a Ghidra export (or use r2/Ghidra scripting) to find
    MOV-immediate instructions that push string bytes.
    
    Pattern: MOV RAX, 0xXXXX (where high bytes are printable ASCII)
    followed by PUSH RAX within a few instructions.
    """
    stack_strings = []

    with open(ghidra_export_file) as f:
        lines = f.readlines()

    for i, line in enumerate(lines):
        # Match: mov reg, imm64 where imm64 looks like a string fragment
        m = re.search(r'mov\s+(r\w+),\s*(0x[0-9a-fA-F]+)', line)
        if m:
            imm = int(m.group(2), 16)
            # Check if the immediate decodes to printable ASCII
            try:
                s = imm.to_bytes(8, 'little').decode('ascii', errors='ignore')
                printable = ''.join(c for c in s if 0x20 <= ord(c) <= 0x7e)
                if len(printable) >= 4:
                    # Look for a push within next 5 lines
                    for j in range(i, min(i+5, len(lines))):
                        if m.group(1) in lines[j] and 'push' in lines[j]:
                            stack_strings.append((i, printable))
                            break
            except:
                pass

    return stack_strings

XOR-Encoded Strings

The malware stores encrypted strings in .rodata and decodes them at runtime: 

/* Typical XOR string decode wrapper */
static char encoded_config[] = {
    0x9e, 0x91, 0x9a, 0x9b, 0x96, 0x91, 0xff,  // "C2_HOST" ^ 0xfe
    0x9e, 0x8c, 0x91, 0x8e, 0x87, 0xff,         // "C2_GET" ^ 0xfe
};

void init_strings(void) {
    for (int i = 0; i < sizeof(encoded_config); i++) {
        encoded_config[i] ^= 0xfe;
    }
}

To deobfuscate, identify the decode function and emulate it (see binary-emulation.html ), or use floss (FireEye's FLARE Obfuscated String Solver): 

$ floss -n 8 malware.elf
FLOSS decoded 23 strings
Decoding function at 0x4023a0 (XOR, key=0xfe):
  "C2_HOST"
  "C2_GET"
  "/proc/self/exe"
  ...

If floss misses built-in strings, write a custom Unicorn-based decoder (emulation approach in binary-emulation article).

Base64 + XOR Combination

A common pattern layers base64 encoding over XOR:

char encoded[] = "dGhpcyBpcyBhIHNlY3JldA==";  // base64(xor(plaintext, key))

The decode sequence: base64_decode -> xor_decrypt -> use. To deobfuscate, reverse the order:

import base64

def decode_b64_xor(encoded: str, key: int) -> str:
    decoded = base64.b64decode(encoded)
    plain = bytes([b ^ key for b in decoded])
    return plain.decode('ascii', errors='replace')

Opaque Predicates

An opaque predicate is a conditional expression whose value is known at obfuscation time but appears complex to the analyst:

Type Expression Always
Zero algebra x - x 0
Zero multiply x * 0 0
Identity OR x \| 0 x
Identity AND x & -1 x
Square hash (x * x) % 4 == 0(x even) 1
Fermat ltl a^(p-1) % p == 1(p prime) 1

In disassembly:

; OPAQUE PREDICATE: branching on 0xF1 + 0x0F
mov    eax, 0xF1
add    eax, 0x0F       ; eax = 0x100 = 256
cmp    eax, 0x100
je     target          ; ALWAYS taken — the add result is deterministic

The branch is always taken. Its purpose: bifurcate the control flow graph, creating a "dead branch" that the disassembler may follow but execution never reaches. This confuses both static analysis and decompilation.

  1. Pattern recognition - most opaque predicates follow known formulas. A Ghidra script can fold them:

  1. Symbolic execution - angr trivially solves opaque predicates. Feed the binary through angr's CFGFast and check which branches are unreachable:

# Find dead branches (edges where the condition is unsatisfiable)

  1. Dynamic tracing - run the binary and record which branches are actually taken. Dead branches are never executed and can be pruned from the CFG.

Control Flow Flattening

Control flow flattening (CFF) is a transformation that replaces the natural control flow of a function with a switch-based dispatcher: 

NATURAL CFG:                    FLATTENED CFG:

  A                              dispatcher:
  |\                               state = next_state
  | B                              switch(state):
  | |                                case 0: goto A'
  | C                                case 1: goto B'
  |/                                 case 2: goto C'
  D                                ...
                                    A':
  A → B → C → D                      ...code...
                                     state = F(B); goto dispatcher
                                   B':
                                     ...code...
                                     state = F(B); goto dispatcher
                                   C':
                                     ...code...
                                     state = F(C); goto dispatcher

Each basic block is split out and assigned a numeric state. After executing, the block computes the next state and jumps back to the dispatcher. The original control flow is encoded in the state variable assignments.

Identifying CFF

In Ghidra, a flattened function shows: - A large switch statement (indirect jump table) at the function entry - Every block ending with state_var = <constant>; goto dispatcher - No fall-through between logical blocks

The telltale sign in assembly is a function that is essentially one giant loop with an indirect jump: 

; FLATTENED FUNCTION (Ghidra decompiler view)
undefined8 flattened_func(void)
{
    int state;
    undefined8 result;
    
    state = 0;
    do {
        switch(state) {
        case 0:
            /* Block A */
            local_variable = 42;
            state = 1;
            break;
        case 1:
            /* Block B */
            if (local_variable > 10) {
                state = 3;
            } else {
                state = 2;
            }
            break;
        case 2:
            /* Block C (else branch) */
            local_variable = local_variable * 2;
            state = 1;
            break;
        case 3:
            /* Block D (exit) */
            return local_variable;
        }
    } while( true );
}

Deobfuscating CFF

O-LLVM is the most common tool producing CFF. Tigress and Hikari also implement it. Each produces predictable patterns.

Use deflat.py (open-source deobfuscation tool) to recover the original CFG: 

$ git clone https://github.com/purseclab/deflat
$ cd deflat
$ python3 deflat.py -f obfuscated.elf --addr 0x4023a0
[+] Recovered 12 basic blocks in function 0x4023a0
[+] Graph built, writing patched binary to obfuscated.elf_recovered

Manual approach: reconstruct the state transition table:

#!/usr/bin/env python3
"""cff_recover.py — Manually recover CFF control flow"""

def recover_cff_states(trace_log: str):
    """
    From a runtime trace, build the state transition table.
    trace_log format: each line is <address> <state_after>

    Then use NetworkX to build the CFG and perform path analysis.
    """
    import networkx as nx

    G = nx.DiGraph()
    states = {}
    current = None

    with open(trace_log) as f:
        for line in f:
            addr, next_state = line.strip().split()
            addr = int(addr, 16)
            next_state = int(next_state)

            if current is not None:
                G.add_edge(current, addr)
            current = addr
            states[addr] = next_state

    print(f"[+] Recovered graph: {G.number_of_nodes()} nodes, "
          f"{G.number_of_edges()} edges")

    # Find the original CFG structure
    # Shortest path from entry to exit
    entry = list(G.nodes())[0]
    for node in G.nodes():
        if G.out_degree(node) == 0:
            print(f"  Exit block: 0x{node:x}")
            path = nx.shortest_path(G, entry, node)
            print(f"  Path: {' → '.join(hex(n) for n in path)}")

Virtual Machine Obfuscation

VM Protect and Themida represent the apex of obfuscation difficulty. They translate native x86 instructions into custom bytecode executed by an embedded interpreter.

How It Works

  1. The protector selects critical functions
  2. Each x86 instruction is translated to equivalent VM bytecode (e.g., add rax, rbx -> VM_ADD_R64_R64 0 1 )
  3. The original code is replaced with a VM_ENTER stub
  4. At runtime, the VM interpreter fetches, decodes, and executes bytecodes
  5. The VM handler table is a set of small functions - one per opcode

Identifying VMProtect

The VM interpreter has a recognizable structure: 

; TYPICAL VM HANDLER DISPATCH LOOP
vm_loop:
    movzx  eax, byte [esi]      ; fetch opcode
    inc    esi                   ; advance VM IP
    jmp    [handler_table + eax*8] ; dispatch to handler

handler_ADD_R64:
    mov    rax, [vregs + rbx*8]
    mov    rcx, [vregs + rdx*8]
    add    rax, rcx
    mov    [vregs + rbx*8], rax
    jmp    vm_loop

The handler table is an array of function pointers - typically 50-200 entries, each a small code block. This is visible in Ghidra as a large jump table.

Analysis Approaches

  1. VM handler identification : Find the dispatch loop, dump the handler table, categorize handlers by operation (arithmetic, memory, control flow).
  1. Bytecode extraction : Locate the VM bytecode (usually in .vmp0 or .themida section), parse the custom instruction format:
#!/usr/bin/env python3
"""vm_bytecode_dump.py — Dump VMProtect bytecode section"""

def parse_vmp_bytecode(data: bytes):
    """
    VMProtect bytecode format (simplified):
    - Opcode: 1 byte (handler table index)
    - Operands: variable length depending on opcode
    
    This script dumps a disassembly of the bytecode stream.
    """
    pos = 0
    handlers = {
        0x00: 'VM_ENTER',
        0x01: 'VM_PUSH_IMM32',
        0x02: 'VM_PUSH_IMM64',
        0x03: 'VM_POP_R64',
        0x04: 'VM_PUSH_R64',
        0x10: 'VM_ADD_R64',
        0x11: 'VM_SUB_R64',
        0x12: 'VM_MUL_R64',
        0x20: 'VM_JMP',
        0x21: 'VM_JZ',
        0x22: 'VM_JNZ',
        0x30: 'VM_CALL_NATIVE',
        0xFF: 'VM_EXIT',
    }

    while pos < len(data):
        opcode = data[pos]
        handler_name = handlers.get(opcode, f'UNK_{opcode:02X}')
        pos += 1

        if opcode == 0x01:  # VM_PUSH_IMM32
            imm = int.from_bytes(data[pos:pos+4], 'little')
            print(f"  {handler_name} 0x{imm:x}")
            pos += 4
        elif opcode == 0x02:  # VM_PUSH_IMM64
            imm = int.from_bytes(data[pos:pos+8], 'little')
            print(f"  {handler_name} 0x{imm:x}")
            pos += 8
        elif opcode in (0x03, 0x04, 0x10, 0x11, 0x12):
            reg = data[pos]
            print(f"  {handler_name} r{reg}")
            pos += 1
        elif opcode in (0x20, 0x21, 0x22):
            target = int.from_bytes(data[pos:pos+2], 'little')
            print(f"  {handler_name} {target}")
            pos += 2
        elif opcode == 0x30:
            native_addr = int.from_bytes(data[pos:pos+8], 'little')
            print(f"  {handler_name} 0x{native_addr:x}")
            pos += 8
        elif opcode == 0xFF:
            print(f"  {handler_name}")
            break
        else:
            pos += 1
  1. Dynamic analysis : Hook the VM dispatch loop, log opcodes and operands, reconstruct the execution trace.
  1. Lifting : If you fully document the VM instruction set, write a "lifter" that translates VM bytecode back to native x86 or to an IL (Intermediate Language) for analysis.

Deobfuscation Workflow

A systematic approach to deobfuscating an unknown binary:

1. IDENTIFY
   strings → entropy → section analysis → detect packer/protector

2. UNPACK (if packed)
   upx -d → manual OEP find → memory dump → import fix

3. DECRYPT (if encrypted)
   find crypto constants → locate decode function → emulate → extract plaintext

4. STRING DECODE
   floss → unicorn emulation of decode routines → custom scripts

5. CFG RECOVERY
   identify CFF patterns → deflat → manual state reconstruction

6. VM DECOMPILE (if virtualized)
   handler identification → bytecode extraction → lifter construction

Obfuscation Scanner Script

A comprehensive scanner that runs all detection checks:

#!/usr/bin/env python3
"""obfuscation_scanner.py — Full-spectrum obfuscation detection"""

import sys
import struct
import math
from collections import Counter

def entropy(data: bytes) -> float:
    """Shannon entropy of byte sequence."""
    if not data:
        return 0.0
    counter = Counter(data)
    length = len(data)
    return -sum((count/length) * math.log2(count/length) 
                for count in counter.values())

def detect_packer(filepath: str) -> dict:
    results = {
        'file': filepath,
        'packed': False,
        'packer': None,
        'entropy': 0.0,
        'crypto_detected': [],
        'suspicious_imports': [],
        'section_anomalies': [],
    }

    with open(filepath, 'rb') as f:
        data = f.read()

    # 1. Section name analysis
    if b'UPX' in data[:0x1000]:
        results['packed'] = True
        results['packer'] = 'UPX'

    # 2. Entropy analysis (>7.0 = encrypted/compressed)
    # Sample .text section
    text_entropy = entropy(data[:min(len(data), 0x10000)])
    results['entropy'] = text_entropy
    if text_entropy > 7.0:
        results['packed'] = True
        results['section_anomalies'].append(f'High entropy: {text_entropy:.2f}')

    # 3. Import table analysis
    # Packed binaries typically have very few imports
    if b'GetProcAddress' in data and b'LoadLibrary' in data:
        results['suspicious_imports'].append('Dynamic loading detected')

    # 4. Crypto constant scan
    from find_crypto import scan_crypto_constants
    crypto_hits = scan_crypto_constants(data, 0)
    results['crypto_detected'] = [c[0] for c in crypto_hits]

    # 5. Stack string detection — scan for push+mov string patterns
    # (simplified — full implementation would parse disassembly)
    stack_string_patterns = find_stack_string_heuristic(data)
    if stack_string_patterns:
        results['section_anomalies'].append(
            f'{len(stack_string_patterns)} stack-constructed strings')

    return results

def find_stack_string_heuristic(data: bytes) -> list:
    """
    Heuristic for stack strings: look for MOV RAX, <ascii> patterns.
    Search for 48 B8 (MOV RAX, imm64) where imm64 contains printable bytes.
    """
    results = []
    pos = 0
    while True:
        pos = data.find(b'\x48\xB8', pos)
        if pos == -1:
            break
        if pos + 10 <= len(data):
            imm = struct.unpack_from('<Q', data, pos + 2)[0]
            try:
                s = imm.to_bytes(8, 'little')
                # Check if mainly printable
                printable = sum(0x20 <= b <= 0x7e for b in s)
                if printable >= 5:
                    results.append({'offset': pos, 'string': s})
            except:
                pass
        pos += 1
    return results

if __name__ == '__main__':
    for path in sys.argv[1:]:
        result = detect_packer(path)
        print(f"\n{'='*60}")
        print(f"File: {result['file']}")
        print(f"Packed: {result['packed']} ({result['packer'] or 'unknown'})")
        print(f"Entropy: {result['entropy']:.2f}")
        print(f"Crypto: {result['crypto_detected']}")
        print(f"Suspicious imports: {result['suspicious_imports']}")
        print(f"Anomalies: {result['section_anomalies']}")

Challenge

Write a Go tool that reads an ELF file, prints each section with its Shannon entropy, and flags a section as packed when its entropy exceeds 7.0 . Then scan the whole file for the first bytes of the AES S-box and report whether a crypto implementation is statically linked. 

package main

import (
	"debug/elf"
	"fmt"
	"math"
	"os"
)

func entropy(b []byte) float64 {
	if len(b) == 0 {
		return 0
	}
	var counts [256]int
	for _, c := range b {
		counts[c]++
	}
	l := float64(len(b))
	e := 0.0
	for _, c := range counts {
		if c == 0 {
			continue
		}
		p := float64(c) / l
		e -= p * math.Log2(p)
	}
	return e
}

var aesSbox = []byte{0x63, 0x7c, 0x77, 0x7b, 0xf2, 0x6b, 0x6f, 0xc5}

func indexOf(haystack, needle []byte) int {
	for i := 0; i+len(needle) <= len(haystack); i++ {
		match := true
		for j := range needle {
			if haystack[i+j] != needle[j] {
				match = false
				break
			}
		}
		if match {
			return i
		}
	}
	return -1
}

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintln(os.Stderr, "usage: entropy <elf>")
		os.Exit(1)
	}

	f, err := elf.Open(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	defer f.Close()

	for _, s := range f.Sections {
		data, err := s.Data()
		if err != nil || len(data) == 0 {
			continue
		}
		e := entropy(data)
		flag := ""
		if e > 7.0 {
			flag = "  <-- high entropy"
		}
		fmt.Printf("%-16s %8d bytes entropy=%.3f%s\n", s.Name, len(data), e, flag)
	}

	raw, err := os.ReadFile(os.Args[1])
	if err == nil {
		if idx := indexOf(raw, aesSbox); idx >= 0 {
			fmt.Printf("AES S-box candidate at offset 0x%x\n", idx)
		} else {
			fmt.Println("no AES S-box found")
		}
	}
}
