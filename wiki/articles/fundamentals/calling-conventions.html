Calling Conventions

The ABI contract between caller and callee - System V AMD64, x86-32 comparisons, ARM64 AAPCS , varargs, and writing assembly callable from C.

Overview

A calling convention is the contract that lets code compiled by different compilers call each other. It decides where arguments go, which registers survive a call, how the stack is aligned, and where the return value lands. This article documents the System V AMD64 ABI used on Linux, compares it with the 32-bit and Windows x64 conventions, and shows how C functions translate to assembly. By the end you can read a disassembly and know exactly which register holds which argument, and you can write assembly that a C caller can invoke.

What a Calling Convention Defines

A calling convention is a contract between caller and callee that answers:

  1. Where are arguments placed? (registers or stack)
  2. In what order are arguments pushed? (left-to-right or right-to-left)
  3. Who cleans up the stack? (caller or callee)
  4. Where is the return value? (which register)
  5. Which registers must the callee preserve? (callee-saved vs caller-saved)
  6. How is the stack aligned? (boundary requirement)

Without conventions, a function compiled by GCC couldn't call a function compiled by Clang. The ABI (Application Binary Interface) standardizes these contracts per platform.

System V AMD64 ABI

This is the convention used on all x86-64 Linux systems (including ArchLinux), and by macOS and the BSDs. Microsoft Windows uses a different convention for x86-64.

System V AMD64 ABI Summary
Parameter slots rdi, rsi, rdx, rcx, r8, r9 (integer/pointer)
Float params xmm0 - xmm7
Return (int) rax (rdx:rax for 128-bit)
Return (float) xmm0 (xmm1:xmm0 for complex)
Stack align 16 bytes before call instruction
Red zone 128 bytes below rsp
Caller-saved rax, rcx, rdx, rsi, rdi, r8-r11
Callee-saved rbx, rbp, r12-r15, rsp
Varargs al = # of vector register args
Static chain r10 (for nested functions)
Frame pointer rbp (optional; may be omitted)

long func(long a, long b, long c, long d,
          long e, long f, long g, long h,

g

Arguments 7+ are pushed right-to-left on the stack. The first stack argument is closest to the return address (lowest offset from rsp ).

Integer and Float Arguments

When a function takes both integer and float arguments, the integer regs and xmm regs are consumed independently: 

// void g(int a, double b, int c, double d);
Arg Location Notes
a (int) rdi Uses first integer reg
b (dbl) xmm0 Uses first float reg
c (int) rsi Uses second integer reg
d (dbl) xmm1 Uses second float reg

If float regs run out but integer regs are available, the float argument goes on the stack - the integer register is NOT used. The classification of each argument is independent.

Return Values

Return Type Where
Integer <= 64 bits rax
Integer 65-128 bits rax (low) + rdx (high)
Float / Double xmm0
Float complex xmm0 (real) + xmm1 (imaginary)
struct <= 16 bytes rax + rdx (field-by-field, based on integer/float classification)
struct > 16 bytes Caller allocates space, passes pointer in rdi (hidden first argument)
__int128 rax + rdx 
#include <stdio.h>
#include <stdint.h>

// Returns 128-bit value in rax:rdx
__int128 make128(uint64_t hi, uint64_t lo) {
    return ((__int128)hi << 64) | lo;
}

int main() {
    __int128 val = make128(0xDEADBEEF, 0xCAFEBABE);
    printf("High: %016lx  Low: %016lx\n",
           (uint64_t)(val >> 64), (uint64_t)val);
    return 0;
}

Caller-Saved vs Callee-Saved

Item Rule
Caller-Saved (Volatile) rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11
Callee-Saved (Nonvolatile) rbx, rbp, r12, r13, r14, r15, rsp
Direction flag Must be cleared (DF=0) before call and on return from any function
x87 FPU stack Must be empty on call (except for returning float80 values)
mxcsr Callee-saved portion: bits

Caller-saved (volatile) means: if the caller needs a register's value after a function call, it must save it before the call. The callee is free to clobber these.

Callee-saved (nonvolatile) means: the callee must preserve these registers. If the callee uses them, it must save them in the prologue and restore them in the epilogue. 

; Caller perspective - needs rax value after call
mov [rsp-8], rax       ; Save rax (in red zone - valid on Linux)
call some_function
mov rax, [rsp-8]       ; Restore rax

; Callee perspective - uses rbx
my_function:
    push rbx              ; Save callee-saved register
    sub rsp, 16           ; Allocate locals
    ; ... use rbx freely ...
    add rsp, 16           ; Deallocate locals
    pop rbx               ; Restore rbx
    ret

Stack Frame Alignment

The ABI mandates 16-byte stack alignment at the point of the call instruction (equivalently: rsp % 16 == 0 before call ). 

At function entry:
  rsp % 16 == 8          (because `call` pushed 8-byte return address)
  -> Prologue must adjust rsp by 8n + 8 to realign before any calls.
  -> sub rsp, 24 makes rsp % 16 == 0 (24 = 8*3, +8 from ret addr = 32 total)
						
; Function that calls printf - needs 16-byte alignment
; At entry: rsp % 16 == 8
; push rbp makes it 0; sub rsp, 16 keeps it 0.

extern printf

section .data
    fmt db "x = %d, y = %d", 10, 0

section .text
global my_func
my_func:
    push rbp
    mov rbp, rsp
    sub rsp, 16           ; Allocate locals, keep rsp 16-byte aligned
    mov rdi, 1
    mov rsi, 2
    call printf           ; Aligned: rsp % 16 == 0 before call

    add rsp, 16
    pop rbp
    ret

When in doubt, the prologue push rbp; mov rbp, rsp; sub rsp, N aligns if N % 16 == 0 , because push rbp already turns rsp % 16 == 8 (at entry) into rsp % 16 == 0 .

The Red Zone

The 128 bytes immediately below rsp are the red zone . A leaf function (one that doesn't call other functions) can use this memory without adjusting rsp : 

; Leaf function - no calls to other functions
; Can use [rsp-8] through [rsp-128] freely
leaf_func:
    mov [rsp-8], rdi      ; Store argument temporarily in red zone
    mov rax, [rsp-8]      ; Read it back
    add rax, 1
    ret                   ; No stack adjustment needed - leaf function

This optimization is only valid on System V AMD64 (Linux, macOS, BSD). Windows x64 has no red zone

  • the space below rsp can be overwritten by interrupts or exception handling at any time.

x86-32 Conventions

Before x86-64, there were multiple competing conventions on 32-bit x86. All pass arguments on the stack (no register args), differ in who cleans up:

Convention Parameter order Stack cleanup by Used by
cdecl Right-to-left Caller Linux, GCC
stdcall Right-to-left Callee Win32 API
fastcall ecx,edx, stack Callee Various
thiscall ecx + stack Callee (MS) C++ on Win
pascal Left-to-right Callee Borland
register eax,edx,ecx Caller (Borland) Deprecated

cdecl is the default on Linux x86-32: 

; cdecl: caller pushes right-to-left, cleans after call
push argv
push argc
call main
add esp, 8              ; Caller cleans 8 bytes from stack

; stdcall: callee cleans with 'ret N'
; In callee: ret 8      ; Pop return address AND clean 8 bytes of args

Microsoft x64 ABI

Windows x64 uses a different convention than Linux x86-64. Key differences:

Feature System V AMD64 Microsoft x64
First 4 int args rdi, rsi, rdx, rcx rcx, rdx, r8, r9
Float args xmm0-xmm7 xmm0-xmm3
Shadow space None 32 bytes (home for first 4 args)
Red zone 128 bytes None
Caller-saved rax,rcx,rdx,rsi,rdi,r8-r11 rax,rcx,rdx,r8-r11,xmm0-xmm5
Callee-saved rbx,rbp,r12-r15 rbx,rbp,rdi,rsi,r12-r15, xmm6-xmm15
Stack alignment 16 bytes 16 bytes
Varargs al = count of xmm args Shadow space + stack, same as regular args
Non-leaf func sub rsp, N sub rsp, 32+N (always has shadow space)

Shadow space (home space): On Windows x64, the caller must allocate 32 bytes of stack space before calling, even if the first 4 arguments are passed in registers. The callee may use this space to spill register args for debugging. On Linux, this doesn't exist - the callee manages its own locals.

ARM64 AAPCS

On AArch64 (64-bit ARM), the procedure call standard:

Item Value
Parameter 1-8 x0 - x7
Float 1-8 v0 - v7 (SIMD regs)
Return value x0 (x1 for 128-bit)
Stack align 16 bytes
Caller-saved x0-x18, v0-v7, v16-v31
Callee-saved x19-x29 (x29 = fp), v8-v15
Frame pointer x29
Link register x30 (lr)
Stack pointer x31 (sp)
Zero register xzr
Red zone None
Indirect calls x16 (IP0), x17 (IP1) for PLT stubs 
// ARM64 function call
mov x0, #1          // First argument
mov x1, #2          // Second argument
bl my_function      // Branch with link - sets lr (x30) to return addr
// ...
my_function:
    stp x29, x30, [sp, #-16]!  // Save frame and link register
    mov x29, sp                // Set frame pointer
    // ... function body ...
    ldp x29, x30, [sp], #16    // Restore
    ret                        // Return via lr

C Functions to Assembly

// Source
int multiply_add(int x, int y, int z) {
    int result = x * y;
    result = result + z;
    return result;
}
						
# Compile to assembly and inspect
gcc -O2 -S -o /tmp/multiply_add.s -xc - <<<'int multiply_add(int x,int y,int z){return x*y+z;}'
cat /tmp/multiply_add.s
						
multiply_add:
    imul   esi, edi      ; esi = x * y  (imul can do reg *= reg)
    lea    eax, [rsi + rdx]  ; eax = x*y + z
    ret

With optimizations, the function body collapses into 3 instructions. The compiler eliminated the result variable and put everything in registers. No stack frame, no spills.

Without optimization

multiply_add:
    push   rbp
    mov    rbp, rsp
    mov    DWORD PTR [rbp-4], edi    ; x -> stack
    mov    DWORD PTR [rbp-8], esi    ; y -> stack
    mov    DWORD PTR [rbp-12], edx   ; z -> stack
    mov    eax, DWORD PTR [rbp-4]    ; load x
    imul   eax, DWORD PTR [rbp-8]    ; x * y
    mov    DWORD PTR [rbp-16], eax   ; store result
    mov    eax, DWORD PTR [rbp-16]   ; reload result
    add    eax, DWORD PTR [rbp-12]   ; + z
    pop    rbp
    ret

Varargs

Variadic functions (those taking ... ) use a different protocol. The key insight: the caller sets al (the low byte of rax ) to the number of vector (xmm) registers used for floating-point arguments. 

// printf("Hello %s, value %d, pi is %f\n", name, val, 3.14);
// Arguments:
//   rdi = format string  (int arg)
//   rsi = "name"         (int arg)
//   rdx = val            (int arg)
//   xmm0 = 3.14          (float arg)
//   al = 1               (one vector register used)

The callee uses al to determine whether it needs to save xmm0-xmm7 to the register save area. If al = 0, no vector regs were used; if al > 0, the callee saves that many to the stack. 

; Calling printf with mixed args via assembly
section .data
    fmt db "Name: %s, Age: %d, Score: %f", 10, 0
    name db "Alice", 0
    score dq 95.5

section .text
extern printf
global _start
_start:
    ; Set up args
    mov rdi, fmt        ; Format string
    mov rsi, name       ; %s
    mov rdx, 30         ; %d
    movsd xmm0, [score] ; %f
    mov al, 1           ; We used 1 vector register
    call printf

    ; Exit
    mov rdi, 0
    mov rax, 60         ; SYS_exit
    syscall
						
nasm -f elf64 -o /tmp/varargs.o varargs.asm
gcc -no-pie -o /tmp/varargs /tmp/varargs.o
/tmp/varargs
# Output: Name: Alice, Age: 30, Score: 95.500000

setjmp and longjmp

setjmp saves the calling environment (registers, stack pointer, instruction pointer). longjmp restores that environment, effectively jumping back to the setjmp call. This bypasses normal function return. 

#include <stdio.h>
#include <setjmp.h>

jmp_buf env;

void second() {
    printf("[second] About to longjmp\n");
    longjmp(env, 42);  // Jump back to setjmp; returns 42
}

void first() {
    second();
    printf("[first] Never reached\n");
}

int main() {
    int val = setjmp(env);
    if (val == 0) {
        printf("[main] setjmp returned 0; calling first()\n");
        first();
    } else {
        printf("[main] setjmp restored; longjmp returned %d\n", val);
        // val = 42
    }
    return 0;
}
						
gcc -o setjmp-demo setjmp-demo.c && ./setjmp-demo

setjmp / longjmp save and restore:

  • General-purpose registers (including rsp, rbp, rip)
  • Signal mask (if using sigsetjmp / siglongjmp )

They do NOT restore:

  • Heap allocations (leaked if not freed before longjmp)
  • File descriptor state
  • Floating-point register state (implementation-defined)

Calling Assembly from C

; file: add_two.s
; Function: long add_two(long a, long b)
; Takes a in rdi, b in rsi, returns a + b in rax

section .text
global add_two:function (add_two.end - add_two)

add_two:
    ; Prologue (minimal - callee-saved registers unchanged)
    ; No need to push anything if we don't touch callee-saved regs

    lea rax, [rdi + rsi]   ; rax = a + b
    ret                     ; Return in rax

add_two.end:
						
// file: main.c
#include <stdio.h>

extern long add_two(long a, long b);

int main() {
    printf("add_two(40, 2) = %ld\n", add_two(40, 2));
    return 0;
}
						
nasm -f elf64 add_two.s -o add_two.o
gcc -o asm-call main.c add_two.o
./asm-call
# Output: add_two(40, 2) = 42

objdump and the ABI

# Create a binary with a mix of argument types
cat > /tmp/abi-test.c << 'EOF'
#include <stdio.h>
long func(long a, long b, double c, long d, double e, long f) {
    return a + b + (long)c + d + (long)e + f;
}
int main() {
    printf("%ld\n", func(1,2,3.0,4,5.0,6));
    return 0;
}
EOF

gcc -O0 -o /tmp/abi-test /tmp/abi-test.c

# Disassemble to see argument handling
objdump -d -M intel /tmp/abi-test | grep -A30 '<func>:'

# You'll see:
# func:
#   push rbp              ; prologue
#   mov rbp, rsp
#   mov [rbp-8], rdi      ; a (1st int) from rdi -> stack
#   mov [rbp-16], rsi     ; b (2nd int) from rsi -> stack
#   movsd [rbp-24], xmm0  ; c (1st float) from xmm0 -> stack
#   mov [rbp-32], rdx     ; d (3rd int) from rdx -> stack
#   movsd [rbp-40], xmm1  ; e (2nd float) from xmm1 -> stack
#   mov [rbp-48], rcx     ; f (4th int) from rcx -> stack
#   ...

# Compare with optimized version
gcc -O2 -o /tmp/abi-test-opt /tmp/abi-test.c
objdump -d -M intel /tmp/abi-test-opt | grep -A10 '<func>:'
# No stack spills; registers stay in regs; likely folds to constant

Verification Checklist

# 1. Check ABI documentation on your system
ls /usr/include/x86_64-linux-gnu/ 2>/dev/null || true
dpkg -L gcc 2>/dev/null | grep abi || pacman -Ql gcc 2>/dev/null | grep abi

# 2. Disassemble and annotate a simple function
gcc -O0 -g -o /tmp/demo -xc - <<<'long f(long x){return x*2;}'
objdump -d -M intel /tmp/demo | grep -A10 '<f>:'

# 3. See the effect of different optimization levels
gcc -S -O0 -o /tmp/f-O0.s -xc - <<<'int f(int x){return x*2;}'
gcc -S -O2 -o /tmp/f-O2.s -xc - <<<'int f(int x){return x*2;}'
diff -u /tmp/f-O0.s /tmp/f-O2.s

# 4. Inspect callee-saved register usage
objdump -d /usr/bin/bash | grep -E 'push.*(rbx|rbp|r12|r13|r14|r15)' | head -10

# 5. Verify function symbols have proper type info
readelf -s /usr/lib/libc.so.6 | grep ' FUNC ' | head -10

# 6. Test varargs alignment
cat > /tmp/va-test.c << 'EOF'
#include <stdio.h>
#include <stdarg.h>
void vatest(const char* fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    printf("First: %d\n", va_arg(ap, int));
    printf("Second: %f\n", va_arg(ap, double));
    printf("Third: %ld\n", va_arg(ap, long));
    va_end(ap);
}
int main() { vatest("test", 1, 2.5, 3L); return 0; }
EOF
gcc -o /tmp/va-test /tmp/va-test.c && /tmp/va-test

# 7. Check stack alignment enforcement (ABI test)
cat > /tmp/align-test.c << 'EOF'
#include <stdio.h>
void check_alignment() {
    unsigned long rsp_val;
    asm volatile("mov %%rsp, %0" : "=r"(rsp_val));
    printf("Stack pointer: 0x%lx (mod 16 = %lu)\n", rsp_val, rsp_val % 16);
}
int main() { check_alignment(); return 0; }
EOF
gcc -o /tmp/align-test /tmp/align-test.c && /tmp/align-test
# At function entry, rsp % 16 should be 8 (8-byte return address pushed)

Challenge

Write a Go tool that maps a function signature to its System V AMD64 argument locations. This is the reasoning you do in reverse when you read disassembly, and it makes the "first six integer args live in registers" rule concrete: 

package main

import (
	"fmt"
	"reflect"
)

var intRegs = []string{"rdi", "rsi", "rdx", "rcx", "r8", "r9"}

func mapArgs(params []reflect.Kind) []string {
	locations := make([]string, len(params))
	intIdx, floatIdx, stack := 0, 0, 0

	for i, kind := range params {
		switch kind {
		case reflect.Float32, reflect.Float64:
			if floatIdx < 8 {
				locations[i] = fmt.Sprintf("xmm%d", floatIdx)
				floatIdx++
			} else {
				locations[i] = fmt.Sprintf("[rsp+%d]", 8+stack*8)
				stack++
			}
		default:
			if intIdx < len(intRegs) {
				locations[i] = intRegs[intIdx]
				intIdx++
			} else {
				locations[i] = fmt.Sprintf("[rsp+%d]", 8+stack*8)
				stack++
			}
		}
	}

	return locations
}

func main() {
	// long f(long, double, long, double, long, long, long)
	params := []reflect.Kind{
		reflect.Int, reflect.Float64, reflect.Int, reflect.Float64,
		reflect.Int, reflect.Int, reflect.Int,
	}
	for i, loc := range mapArgs(params) {
		fmt.Printf("arg %d -> %s\n", i, loc)
	}
}

Expected output: arg 0 -> rdi , arg 1 -> xmm0 , arg 2 -> rsi , arg 3 -> xmm1 , arg 4 -> rdx , arg 5 -> rcx , arg 6 -> r8 . Extend the tool so that arguments past the register limit are placed at increasing [rsp+N] offsets, then verify the mapping against objdump output for a real function.
