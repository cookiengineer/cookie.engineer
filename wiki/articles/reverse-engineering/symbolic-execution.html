Symbolic Execution

Automatically explore program paths with angr to solve license keys, find vulnerabilities, deobfuscate code, and trigger hidden behavior.

Overview

Traditional testing runs a program with one input. Symbolic execution runs it with unknown inputs and asks a solver which values drive execution down each branch. This article introduces the technique through angr, solves a license check and locates a parser crash, and explains where the approach breaks down.

Required Reading

  • Control Flow - CFG construction, dominator trees, loop detection
  • Reading x86-64 Assembly - register conventions, calling conventions, condition codes

What Symbolic Execution Is

Traditional execution runs a program with concrete values: x = 42 . Symbolic execution runs it with symbolic values: x = lambda (lambda, "could be anything"). When execution encounters a branch on a symbolic value, the executor forks into two states - one for each branch - accumulating constraints along each path. 

CONCRETE EXECUTION                    SYMBOLIC EXECUTION

x = 42                                x = λ (symbolic)
if x > 10:                            if x > 10:
    // Always enters here                 ┌─ Path A: assume λ > 10
    print("big")                          │  constraint: x > 10
                                          │
                                          └─ Path B: assume λ ≤ 10
                                             constraint: x ≤ 10

At any point on a path, the SMT solver can answer: "What value of x reaches this instruction?" From Path A, the solver returns x = 11 (the smallest satisfying integer). From Path B, x = 10 . This is the core power of symbolic execution: it automatically finds inputs that drive execution to any reachable program point.

SMT Solvers

SMT (Satisfiability Modulo Theories) solvers decide whether a formula is satisfiable given background theories (bit-vectors, arrays, arithmetic). Z3 (Microsoft Research) is the dominant solver used by angr. 

from z3 import *

# Example: Find x such that x * 2 + 3 == 11 AND x > 0
x = BitVec('x', 32)
s = Solver()
s.add(x * 2 + 3 == 11)
s.add(x > 0)

if s.check() == sat:
    print(f"x = {s.model()[x]}")  # x = 4

Z3 operates on bit-vectors (fixed-width integers with modular arithmetic) and supports constraints like x < y , x & y == 0 , x << 2 == y . The solver can handle thousands of constraints on hundreds of variables - which is what symbolic execution generates.

Core angr Workflow

Every angr analysis follows this pattern:

import angr

# 1. Load the binary
proj = angr.Project('./target.elf', auto_load_libs=False)

# 2. Create a state (snapshot of registers, memory, constraints)
state = proj.factory.entry_state()

# 3. Create a simulation manager (manages forking/exploration)
simgr = proj.factory.simulation_manager(state)

# 4. Explore paths
simgr.explore(find=0x4013c0, avoid=0x4014a0)

# 5. Examine results
if simgr.found:
    found_state = simgr.found[0]
    print(f"Found path! Input: {found_state.posix.dumps(0)}")

Loading the Binary

proj = angr.Project('./binary', auto_load_libs=False)

auto_load_libs=False prevents angr from loading shared libraries (glibc, etc.), which speeds things up. For binaries that depend on specific library behavior, you'd load them - but for most RE tasks, library calls are handled by angr's SimProcedures (simulated replacements for common functions).

The State Object

A state represents a snapshot of the program at a specific point: - Registers (RAX, RBX, RIP , etc.) - Memory (all mapped regions) - Constraints (SMT solver state - conditions accumulated along this path) - P OSI X environment (stdin, stdout, filesystem, argv, envp) 

state = proj.factory.entry_state()
print(state.regs.rip)           # Address of entry point
print(state.regs.rsp)           # Stack pointer
print(state.mem[state.regs.rsp].uint64_t)  # Value at top of stack

The Simulation Manager

simgr manages the set of active states. When a state encounters a conditional branch, the simulation manager forks it. Key simgr attributes:

Stash Contains
simgr.active States still being explored
simgr.found States that reached the find address
simgr.avoided States that reached an avoid address
simgr.deadended States that terminated (no valid successor)
simgr.errored States that caused an unhandled error 
simgr = proj.factory.simulation_manager(state)

# Step one instruction
simgr.step()
print(len(simgr.active))  # Number of active states

# Run until find or avoid is reached
simgr.explore(find=0x401234, avoid=0x401567)

Solving a License Key Checker

The canonical angr use case: a program checks a license key against a hardcoded value. angr finds the key without you ever knowing it.

The Target Program

/* license_check.c */
#include <stdio.h>
#include <string.h>

int check_license(const char *key) {
    if (strlen(key) != 16) return 0;

    unsigned int sum = 0;
    for (int i = 0; i < 16; i++) {
        sum = (sum << 1) ^ (key[i] * 0x41) ^ (sum >> 31);
    }
    return sum == 0xDEADBEEF;
}

int main(int argc, char **argv) {
    if (argc != 2) {
        printf("Usage: %s <key>\n", argv[0]);
        return 1;
    }
    if (check_license(argv[1])) {
        printf("License valid!\n");
        return 0;
    } else {
        printf("Invalid license.\n");
        return 1;
    }
}

Compile:

$ gcc -O0 -o license_check license.c

The angr Solver

#!/usr/bin/env python3
"""crack_license.py - Use angr to find a valid license key"""

import angr
import claripy

def find_license_key():
    proj = angr.Project('./license_check', auto_load_libs=False)
    cfg = proj.analyses.CFGFast()

    # Locate the "License valid!" and "Invalid license." addresses
    # These are the puts() calls in main
    # (find them with: objdump -d license_check | grep -A2 puts)
    find_addr    = 0x401234   # Address after "License valid!" puts
    avoid_addr   = 0x401256   # Address after "Invalid license." puts

    # Create entry state with symbolic argv
    # We need a 16-byte symbolic buffer (angr appends the null terminator)
    symbolic_key = claripy.BVS('license_key', 16 * 8)  # 128 bits symbolic

    state = proj.factory.entry_state(
        args=['./license_check', symbolic_key],
        add_options={angr.options.ZERO_FILL_UNCONSTRAINED_REGISTERS}
    )

    # Constrain: the key must be printable ASCII
    for i in range(16):
        byte = symbolic_key.get_byte(i)
        state.solver.add(byte >= 0x20)  # Space
        state.solver.add(byte <= 0x7e)  # Tilde

    # Explore
    simgr = proj.factory.simulation_manager(state)
    simgr.explore(find=find_addr, avoid=avoid_addr)

    if simgr.found:
        found_state = simgr.found[0]
        key = found_state.solver.eval(symbolic_key, cast_to=bytes)
        print(f"[+] License key found: {key.decode()}")
        return key
    else:
        print("[-] No valid license key found")
        return None

if __name__ == '__main__':
    find_license_key()

Run it:

(angr_env) $ python3 crack_license.py
[+] License key found: ............

Understanding Constraints

The solver accumulates constraints as the program executes. To inspect the solver state:

found_state = simgr.found[0]

# Print all accumulated constraints
print(found_state.solver.constraints)

# Get a concrete evaluation
key = found_state.solver.eval(symbolic_key, cast_to=bytes)

# Get all possible solutions (if bounded)
solutions = found_state.solver.eval_upto(symbolic_key, 10, cast_to=bytes)

# Test if a condition is possible given the constraints
if found_state.solver.satisfiable(extra_constraints=[symbolic_key == b'AAAA']):
    print("This key could be valid")

Finding Vulnerabilities

Rather than finding a specific address, explore toward a crash state:

#!/usr/bin/env python3
"""find_crash.py - Symbolically find inputs that crash a parser"""

import angr
import claripy

def find_crashing_input(binary_path, max_size=256):
    proj = angr.Project(binary_path, auto_load_libs=False)

    # Symbolic stdin of max_size bytes
    symbolic_input = claripy.BVS('input', max_size * 8)
    state = proj.factory.entry_state(
        stdin=angr.SimFile('/dev/stdin', content=symbolic_input),
        add_options={angr.options.ZERO_FILL_UNCONSTRAINED_REGISTERS}
    )

    simgr = proj.factory.simulation_manager(state)

    # Explore: look for states that crash (SIGSEGV, SIGILL, SIGABRT)
    # angr detects these as 'errored' states
    while simgr.active:
        simgr.step()

        if simgr.errored:
            for err_state in simgr.errored:
                error = err_state.error
                addr  = err_state.state.addr if hasattr(err_state.state, 'addr') else err_state.addr
                print(f"[!] Crash at 0x{addr:x}: {error}")

                # Get the input that caused the crash
                crash_input = err_state.state.solver.eval(
                    symbolic_input, cast_to=bytes
                )
                # Trim to actual length (strip trailing zeros)
                crash_input = crash_input.rstrip(b'\x00')
                print(f"    Input ({len(crash_input)} bytes): {crash_input[:64]}")
                return crash_input

        if len(simgr.active) == 0:
            break

Malware Analysis Use Cases

Decoding Obfuscated Strings

Malware often has a function like decode_string(char *buf, int len, char key) . Instead of running malware, emulate just that function symbolically: 

#!/usr/bin/env python3
"""decode_symbolic.py - Symbolically execute a string decode function"""

import angr
import claripy

def decode_string_symbolically(binary_path, func_addr, encoded_data, key=None):
    """
    Call a decode function symbolically.
    
    Args:
        binary_path: Path to malware ELF
        func_addr: Address of decode function (e.g., 0x4023a0)
        encoded_data: The encoded blob (bytes)
        key: If known, concretize; if None, make symbolic
    """
    proj = angr.Project(binary_path, auto_load_libs=False)

    # Create a blank state (no OS, no libs - just registers and stack)
    state = proj.factory.blank_state(addr=func_addr)

    # Set up the calling convention (x86-64 System V: RDI, RSI, RDX)
    # decode_string(char *buf, int len, char key)
    data_addr = 0x1000000  # Arbitrary mapped address
    state.memory.store(data_addr, encoded_data)

    state.regs.rdi = data_addr
    state.regs.rsi = len(encoded_data)

    if key is not None:
        state.regs.rdx = key
    else:
        symbolic_key = claripy.BVS('key', 8)
        state.regs.rdx = symbolic_key

    # Run until the function returns
    simgr = proj.factory.simulation_manager(state)
    simgr.run()

    if simgr.deadended:
        result_state = simgr.deadended[0]
        # Read the decoded buffer from memory
        decoded = result_state.memory.load(data_addr, len(encoded_data))
        concrete_decoded = result_state.solver.eval(decoded, cast_to=bytes)

        # If key was symbolic, get the concrete key too
        if key is None:
            concrete_key = result_state.solver.eval(symbolic_key)
            print(f"[+] Recovered key: 0x{concrete_key:02x}")
        print(f"[+] Decoded: {concrete_decoded}")
        return concrete_decoded

    return None

2. Triggering Time-Bombs

Malware that checks if (current_time > deadline) { deploy_payload(); } can be analyzed by making the time value symbolic: 

# Force malware past a time check without waiting
# Replace the concrete time with a symbolic one
symbolic_time = claripy.BVS('time', 64)
state.memory.store(time_addr, symbolic_time)
state.solver.add(symbolic_time > deadline_value)  # Force branch

3. Recovering Protocol Structure

For unknown binary protocols, make the entire input symbolic and explore states. Each state's constraints describe the protocol structure: 

# Protocol reversing via symbolic execution
symbolic_packet = claripy.BVS('packet', MAX_PACKET * 8)
state = proj.factory.entry_state(
    stdin=angr.SimFile('/dev/stdin', content=symbolic_packet)
)

simgr = proj.factory.simulation_manager(state)
simgr.explore(find=VALID_PACKET_HANDLER, avoid=ERROR_HANDLER)

if simgr.found:
    constraints = simgr.found[0].solver.constraints
    # Each constraint reveals a protocol requirement
    # e.g., buf[0] == 0xAA, buf[2] + buf[3] == checksum(buf[4:])
    for c in constraints:
        print(f"  Constraint: {c}")

Path Explosion and Mitigations

The fundamental problem of symbolic execution: a program with n conditional branches can produce 2^n paths. Even a simple loop of 32 iterations creates 4 billion states. angr uses heuristics to manage this:

Veritesting

Instead of forking at every branch, veritesting merges states when they reconverge:

simulation = proj.factory.simulation_manager(
    state,
    veritesting=True  # Enable veritesting
)

Veritesting works by identifying "micro-loops" and analyzing them statically before dynamically exploring, significantly reducing path explosion in simple patterns.

2. Exploration Strategies

The simulation manager uses strategies to prioritize states:

# Depth-first: follow one path to its end before the next
simgr.use_technique(angr.exploration_techniques.DFS())

# Length-limited: give up on states that exceed N instructions
simgr.use_technique(angr.exploration_techniques.LengthLimiter(10000))

# Loop seer: detect and limit loop iterations
simgr.use_technique(angr.exploration_techniques.LoopSeer(bound=5))

3. Manual Steering

Guide the exploration toward relevant code by avoiding irrelevant paths:

# Avoid library initialization code
simgr.explore(
    find=0x403000,
    avoid=[0x401000, 0x401100, 0x401200]  # Skip CRT init
)

Limitations of Symbolic Execution

Environment Dependencies

angr cannot execute real syscalls. When the binary calls open() , read() , socket() , angr must model these with SimProcedures. If the malware's behavior depends on a specific syscall response that isn't modeled, angr may dead-end.

Workaround: hybrid execution - run concretely through syscalls, symbolically through computation.

# Hybrid: concrete for I/O, symbolic for logic
state = proj.factory.entry_state(
    add_options={angr.options.SYMBOLIC_WRITE_ADDRESSES}
)
# When visiting a syscall, switch to concrete mode briefly

Anti-Symbolic Execution

Obfuscators specifically target symbolic executors:

  • Opaque predicates that create infinite symbolic branches (but are always concrete)
  • Hash functions used as opaque predicates - SMT solvers can't invert SHA256
  • Input-dependent loops (loop count = hash(input) % N) - explode path count

Defense: use concretization - when a hash result is needed, plug in a concrete value and continue symbolically. 

# Concretize after hash operations
state.solver.add(symbolic_input.get_byte(0) == 0x41)  # Force first byte

Memory Model

angr's memory model is symbolic at the byte level. Reading a symbolic address (e.g., a jump table indexed by symbolic input) causes the memory to fork into many states - one per possible address. This is expensive.

Practical Symbolic Execution Scripts

Finding All Magic Numbers

#!/usr/bin/env python3
"""find_magic.py - Use angr to enumerate all magic constants in a binary"""

import angr

def find_all_magic_numbers(binary_path: str) -> dict:
    """
    For each comparison against a constant, determine if the constant
    could be derived from symbolic input. Useful for finding "magic bytes."
    """
    proj = angr.Project(binary_path, auto_load_libs=False)

    magic_constants = {}
    cfg = proj.analyses.CFGFast()

    for node_addr, node in cfg.get_all_nodes().items():
        if node.is_simprocedure:
            continue

        try:
            block = proj.factory.block(node_addr)
            for insn in block.capstone.insns:
                # Look for CMP with immediate
                if insn.mnemonic == 'cmp' and insn.operands:
                    for op in insn.operands:
                        if op.type == 2:  # Immediate
                            imm = op.value.imm
                            if 0x10000000 <= imm <= 0xFFFFFFFF:
                                magic_constants[insn.address] = hex(imm)
        except:
            continue

    return magic_constants

Forcing Conditional Branches

#!/usr/bin/env python3
"""force_branch.py - Force execution down a specific branch"""

import angr
import claripy

def force_path_to_address(proj, start_addr, target_addr, avoid_nop=0):
    """
    Force angr to find the path from start_addr to target_addr.
    Useful for "I want to reach this code, what input gets me there?"
    """
    state = proj.factory.blank_state(addr=start_addr)

    # Make RDI (first argument) symbolic if function takes an argument
    symbolic_arg = claripy.BVS('arg', 64)
    state.regs.rdi = symbolic_arg

    # Add: the argument should be non-zero (if looking for interesting paths)
    state.solver.add(symbolic_arg != 0)

    simgr = proj.factory.simulation_manager(state)
    simgr.explore(find=target_addr)

    if simgr.found:
        solution = simgr.found[0].solver.eval(symbolic_arg)
        print(f"[+] To reach 0x{target_addr:x}, argument must be: "
              f"0x{solution:x}")
        return solution
    else:
        print(f"[-] 0x{target_addr:x} is unreachable from 0x{start_addr:x}")
        return None

Deobfuscating Opaque Predicates

#!/usr/bin/env python3
"""deobf_opaque.py - Find and resolve opaque predicates with angr"""

import angr

def resolve_opaque_predicates(binary_path: str, func_addr: int):
    """
    For each conditional branch in the target function, use angr
    to determine if it's always taken, never taken, or truly conditional.
    """
    proj = angr.Project(binary_path, auto_load_libs=False)

    # Create a state at the function entry
    state = proj.factory.blank_state(addr=func_addr)

    # Get the function's CFG
    cfg = proj.analyses.CFGFast(
        regions=[(func_addr, func_addr + 0x10000)],
        function_starts=[func_addr]
    )

    opaque_results = {}

    for node_addr, node in cfg.get_all_nodes().items():
        # Check if this node has multiple successors (conditional branch)
        successors = list(cfg.get_successors(node))
        if len(successors) == 2:
            # Try to find a path from func entry to each successor
            for succ in successors:
                simgr = proj.factory.simulation_manager(state.copy())
                simgr.explore(find=succ.addr)

                if not simgr.found:
                    opaque_results[node_addr] = {
                        'type': 'never-taken branch',
                        'dead_target': hex(succ.addr)
                    }
                elif not any(s for s in simgr.active):
                    opaque_results[node_addr] = {
                        'type': 'always-taken branch',
                        'always_target': hex(succ.addr)
                    }

    return opaque_results

Symbolic Execution for Cryptanalysis

When the target uses a cryptographic algorithm, symbolic execution can't directly invert it (Z3 doesn't do SHA256 inversion). However, it helps in other ways:

Finding Weak Key Material

If the key derivation involves predictable operations (bit shifts, XORs, additions), angr can solve for the key: 

# Key derivation: derived = (input * 0x41 + 0x7F) ^ 0xAA
# Given derived = 0xDEADBEEF, what is input?
import claripy

derived = claripy.BVS('derived', 32)
input_sym = claripy.BVS('input', 32)
solver = claripy.Solver()

solver.add(derived == 0xDEADBEEF)
solver.add(derived == ((input_sym * 0x41 + 0x7F) ^ 0xAA))

if solver.satisfiable():
    print(f"input = {solver.eval(input_sym, 1)[0]:#x}")

Identifying Crypto

When a symbolic state's constraints suddenly include non-linear operations (bitwise XORs, rotations, modular arithmetic), the code has likely entered cryptographic territory. This can be used to automatically locate crypto routines in malware.

From Binary To Decoded Payload

#!/usr/bin/env python3
"""full_deobf.py - Combine angr analysis to deobfuscate malware"""

import angr
import claripy

def deobfuscate_malware(binary_path: str) -> dict:
    """
    Full deobfuscation workflow:
    1. Find decode functions (XOR loops, crypto constants)
    2. Symbolically execute decode functions
    3. Extract decoded data
    """
    results = {
        'binary': binary_path,
        'decode_functions': [],
        'decoded_strings': [],
        'crypto_detected': [],
    }

    proj = angr.Project(binary_path, auto_load_libs=False)
    cfg = proj.analyses.CFGFast()

    # Step 1: Find decode functions by pattern
    # Decode functions typically: small (<100 instructions), single loop,
    # XOR operation, access to .data or .rodata
    for func_addr, func in cfg.functions.items():
        # Heuristic: function between 5-100 basic blocks
        if not (5 <= len(list(func.blocks)) <= 100):
            continue

        # Has the function been auto-named (no symbol)?
        if func.name.startswith('sub_'):
            # Check for XOR pattern in this function
            try:
                func_cfg = proj.analyses.CFGFast(
                    regions=[(func.addr, func.addr + func.size)]
                )
                # If the function loops over memory with XOR... (simplified)
                results['decode_functions'].append({
                    'addr': func.addr,
                    'name': func.name,
                    'size': func.size
                })
            except:
                continue

    # Step 2: For each decode function, emulate symbolically
    for func_info in results['decode_functions']:
        addr = func_info['addr']

        # Create state at function entry
        state = proj.factory.blank_state(addr=addr)

        # Make the buffer argument symbolic
        sym_buf = claripy.BVS('buf', 1024 * 8)  # Up to 1024 bytes
        state.memory.store(state.regs.rdi, sym_buf)

        # Set reasonable length
        state.regs.rsi = 1024

        # Run until return
        simgr = proj.factory.simulation_manager(state)
        simgr.run()

        if simgr.deadended:
            # Check if the buffer changed
            final = simgr.deadended[0]
            decoded = final.memory.load(final.regs.rdi, 1024)
            try:
                concrete = final.solver.eval(decoded, cast_to=bytes)
                # Filter out all-null results
                if concrete.rstrip(b'\x00'):
                    results['decoded_strings'].append({
                        'decoder_addr': addr,
                        'decoded': concrete.rstrip(b'\x00').decode(
                            'ascii', errors='replace')
                    })
            except:
                pass

    return results

When NOT to Use Symbolic Execution

Symbolic execution is not a universal solution. Use it when:

Use Case Suitable? Alternative if Not
"Find the password" for simple crackme Yes N/A
Inverting a hash function (SHA256, MD5) No Brute force / rainbow tables
Path exploration for >1000 branches Limited Concolic execution, fuzzing
Analyzing 100MB binary No Static analysis first, then targeted SE
Real-time malware interaction (C2) No Dynamic sandbox analysis
Code that uses hardware (GPU, IO ports) No Hardware emulation

Challenge

Write a Go program that plays the role of a small constraint solver. Reproduce the checksum loop from the target program over a four-byte key, then enumerate the printable keyspace and print every key whose checksum equals 0xDEADBEEF . Add a branch constraint such as key[0] == 'A' and count how many candidates remain. 

package main

import "fmt"

func checksum(key []byte) uint32 {
	var sum uint32
	for _, b := range key {
		sum = (sum << 1) ^ (uint32(b) * 0x41) ^ (sum >> 31)
	}
	return sum
}

func main() {
	const target = uint32(0xdeadbeef)

	var found int

	for a := byte(0x20); a < 0x7f; a++ {
		for b := byte(0x20); b < 0x7f; b++ {
			for c := byte(0x20); c < 0x7f; c++ {
				for d := byte(0x20); d < 0x7f; d++ {
					key := []byte{a, b, c, d}
					if checksum(key) == target {
						fmt.Printf("%q -> 0x%08x\n", key, checksum(key))
						found++
					}
				}
			}
		}
	}

	fmt.Printf("%d keys satisfy the constraint\n", found)
}
