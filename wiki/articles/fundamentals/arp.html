ARP

Address Resolution Protocol from first principles: packet structure, ARP cache mechanics, and ARP spoofing concepts.

Overview

Ethernet networks identify hosts by MAC addresses, but IP routes packets by logical addresses. ARP bridges the two by mapping IP addresses to hardware addresses on the local subnet. This article walks through the ARP packet format, the request/reply exchange, the kernel neighbor cache, gratuitous ARP , proxy ARP , and how the protocol's lack of authentication enables ARP spoofing. After reading it you can inspect and manipulate the neighbor cache, capture ARP traffic, and build your own ARP frames.

  • ICMP - IP error and control messages

The Problem ARP Solves

Ethernet networks use MAC addresses, a 48 bit hardware identifier that is mapped to the network interface. The first 24 bits of the MAC address represent the OUI or vendor, whereas the latter 24 bits represent the unique serial number of your network interface hardware.

Ethernet networks identify hosts by MAC (Media Access Control) address

  • a 48-bit hardware identifier burned into the network interface. But IP

(Internet Protocol) uses 32-bit ( IPv4 ) or 128-bit ( IPv6 ) logical addresses that are independent of the hardware.

When a host wants to send an IP packet to another host on the same subnet, it needs the destination's MAC address to construct the Ethernet frame. The IP address alone is not enough - Ethernet frames require a destination MAC .

ARP bridges this gap. It queries the local network: "Who has IP address X? Tell me your MAC address." Every host on the subnet receives this broadcast. The host with the matching IP responds with its MAC address. The asking host caches the result and uses it for subsequent communication.

ARP Packet Structure

ARP is defined in RFC 826. It operates directly over Ethernet (no IP encapsulation) and uses EtherType 0x0806 :

Field Bits IPv4/Ethernet Value Purpose
Hardware Type 16 1 (Ethernet) Type of link layer (Ethernet = 1, IEEE 802 = 6, etc.)
Protocol Type 16 0x0800 (IPv4) Network layer protocol address type
HAL 8 6 Length of hardware address in bytes (MAC = 6)
PAL 8 4 Length of protocol address in bytes (IPv4 = 4)
Operation 16 1=Request, 2=Reply ARP message type
Sender HA HAL x 8 Variable (48 bits for Ethernet) Sender's MAC address
Sender PA PAL x 8 Variable (32 bits for IPv4) Sender's IP address
Target HA HAL x 8 Variable (48 bits for Ethernet) Target's MAC (zero in requests)
Target PA PAL x 8 Variable (32 bits for IPv4) Target's IP address

The target hardware address is zero in an ARP request because the sender doesn't know it yet. In an ARP reply, both sender and target fields are filled.

ARP Operations

Operation Value Direction Purpose
ARP Request 1 Broadcast (ffffff:ff) "Who has this IP?"
ARP Reply 2 Unicast to requester "This IP is at this MAC"
RARP Request 3 Broadcast "Who has this MAC?" (obsolete)
RARP Reply 4 Unicast "This MAC has this IP" (obsolete)

RARP (Reverse ARP ) allowed diskless workstations to discover their own IP address by broadcasting their MAC address. It was replaced by DHCP and BOOTP and is effectively obsolete.

ARP Resolution - Step by Step

Host A (192.168.1.10, MAC aa:aa:aa:aa:aa:aa) wants to send to
Host B (192.168.1.20, MAC bb:bb:bb:bb:bb:bb)

Step 1: A checks its ARP cache
  $ ip neigh show 192.168.1.20
  (no entry — needs to resolve)

Step 2: A constructs Ethernet frame:
  Ether: dst=ff:ff:ff:ff:ff:ff (broadcast), src=aa:aa:aa:aa:aa:aa, type=0x0806
  ARP:   htype=1, ptype=0x0800, hal=6, pal=4, op=1
         sha=aa:aa:aa:aa:aa:aa, spa=192.168.1.10
         tha=00:00:00:00:00:00, tpa=192.168.1.20

Step 3: A sends frame. Switch floods to all ports.

Step 4: B receives the broadcast, sees tpa=192.168.1.20 (matches its IP)
  B constructs ARP Reply:
  Ether: dst=aa:aa:aa:aa:aa:aa, src=bb:bb:bb:bb:bb:bb, type=0x0806
  ARP:   htype=1, ptype=0x0800, hal=6, pal=4, op=2
         sha=bb:bb:bb:bb:bb:bb, spa=192.168.1.20
         tha=aa:aa:aa:aa:aa:aa, tpa=192.168.1.10

Step 5: B sends reply. A receives it, updates ARP cache.
  $ ip neigh show 192.168.1.20
  192.168.1.20 dev eth0 lladdr bb:bb:bb:bb:bb:bb REACHABLE

Step 6: A can now construct IP packets with dst MAC = bb:bb:bb:bb:bb:bb

Host C (192.168.1.30) also receives the broadcast but sees tpa != 192.168.1.30 , so it discards the ARP request and does not respond.

The ARP Cache

The kernel maintains an ARP cache to avoid ARP resolution for every IP packet. The cache has entries in different states: 

# View ARP cache with state
ip neigh show

# Output:
# 192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
# 192.168.1.50 dev eth0 lladdr 11:22:33:44:55:66 STALE
# 192.168.1.100 dev eth0 lladdr 77:88:99:aa:bb:cc DELAY
# 192.168.1.200 dev eth0 INCOMPLETE
State Meaning Timeout Behavior
INCOMPLETE ARP request sent, no reply yet Retries 3 times, 1 second apart, then fails
REACHABLE Confirmed by recent traffic or ARP reply Transitions to STALE afterbase_reachable_time(default 30s)
STALE Entry old but still usable Transitions to DELAY on first use, sends probe
DELAY Waiting for confirmation (5s default) Transitions to PROBE if no confirm, or REACHABLE if confirmed
PROBE Actively re-ARPing Retries up toucast_solicittimes, then FAILED
FAILED Unreachable Removed from cache after garbage collection
PERMANENT Static entry (never expires) Created byip neigh add ... nud permanent

Cache manipulation

# Add static ARP entry (prevents ARP spoofing for critical hosts)
sudo ip neigh add 192.168.1.1 lladdr aa:bb:cc:dd:ee:ff dev eth0 nud permanent

# Replace an entry
sudo ip neigh replace 192.168.1.1 lladdr 11:22:33:44:55:66 dev eth0 nud permanent

# Delete an entry
sudo ip neigh del 192.168.1.1 dev eth0

# Flush entire cache
sudo ip neigh flush all

# Flush by state
sudo ip neigh flush nud stale
sudo ip neigh flush nud failed

# Check cache statistics
cat /proc/net/arp          # Classic format
ip -s neigh show           # With statistics

Gratuitous ARP

A gratuitous ARP is an ARP Request or Reply where the sender's IP matches the target IP . It is sent to broadcast - the sender announces its own MAC -to- IP mapping to the entire subnet, unsolicited.

Uses

  1. Duplicate address detection: Before assigning an IP , a host sends a gratuitous ARP Request for that IP . If it receives a reply, the IP is already in use. This is how DHCP servers verify an address is free before offering it.
  1. Failover/VRRP: When a standby router takes over (for example in VRRP or HSRP ), it sends a gratuitous ARP so switches update their CAM tables and hosts update their ARP caches. Traffic immediately flows to the new active router.
  1. IP change notification: When a host's IP changes, a gratuitous ARP tells the network about the new mapping.
#!/usr/bin/env python3
"""
Construct and send a gratuitous ARP packet using raw sockets.
"""
import socket
import struct

def send_gratuitous_arp(interface: str, src_mac: str, src_ip: str) -> None:
    sock = socket.socket(socket.AF_PACKET, socket.SOCK_RAW,
                         socket.htons(0x0806))
    sock.bind((interface, 0))

    # MAC string to bytes
    src_mac_bytes = bytes.fromhex(src_mac.replace(":", ""))
    broadcast = b'\xff' * 6

    # Ethernet header
    eth = struct.pack("!6s6sH", broadcast, src_mac_bytes, 0x0806)

    # ARP packet
    arp = struct.pack(
        "!HHBBH6s4s6s4s",
        0x0001,      # Hardware type: Ethernet
        0x0800,      # Protocol type: IPv4
        6,           # Hardware address length
        4,           # Protocol address length
        2,           # Operation: Reply (gratuitous ARP is op=2, not 1)
        src_mac_bytes,
        socket.inet_aton(src_ip),
        src_mac_bytes,      # Target MAC = Sender MAC (gratuitous)
        socket.inet_aton(src_ip)  # Target IP = Sender IP (gratuitous)
    )

    sock.send(eth + arp)
    sock.close()
    print(f"[+] Sent gratuitous ARP: {src_ip} is at {src_mac}")

# Usage:
# send_gratuitous_arp("eth0", "aa:bb:cc:dd:ee:ff", "192.168.1.100")
						
# Detect gratuitous ARP with tcpdump
sudo tcpdump -i eth0 -nn -v 'arp and ether[21] == 2 and \
    (arp[24:4] == arp[14:4])'

# This filter matches: ARP Reply (op=2) AND sender IP == target IP

ARP Probe - Duplicate Address Detection

An ARP Probe is a specific type of ARP Request used to check for IP address conflicts before assigning an address. It differs from a normal ARP Request: 

Normal ARP Request:
  Sender IP: sender's actual IP
  Target IP: the IP being resolved
  Operation: 1 (Request)

ARP Probe:
  Sender IP: 0.0.0.0  (unknown — deliberately empty)
  Target IP: the IP being probed
  Operation: 1 (Request)

Purpose: "Is anyone using this IP? Tell me (but I don't have an IP yet)."

The kernel sends ARP probes automatically when an address is assigned to an interface, independent of the settings below. The related sysctls are: 

# Check ARP announce behavior
cat /proc/sys/net/ipv4/conf/eth0/arp_announce
# 0 = always use local address
# 1 = avoid secondary addresses
# 2 = always use best local address

cat /proc/sys/net/ipv4/conf/eth0/arp_accept
# 0 = only accept if ARP table already has the entry
# 1 = create new entries from gratuitous ARP

Proxy ARP

Proxy ARP allows a router to answer ARP requests on behalf of hosts on a different subnet. The router receives the ARP request, sees that it can reach the target IP via another interface, and responds with its own MAC address. The requesting host then sends packets to the router, which forwards them. 

Without Proxy ARP:
  Host A (192.168.1.10/24) wants to send to 10.0.0.5/8
  A calculates: 10.0.0.5 is NOT on my subnet
  A sends packet to default gateway

With Proxy ARP:
  Host A (192.168.1.10/22) wants to send to 192.168.2.5
  A's netmask is /22, 192.168.2.5 IS on the same subnet
  A ARPs for 192.168.2.5
  Router sees ARP request, knows 192.168.2.5 is on another interface
  Router responds with its own MAC
  A sends to router's MAC; router forwards to 192.168.2.5
						
# Enable Proxy ARP on Linux
echo 1 | sudo tee /proc/sys/net/ipv4/conf/eth0/proxy_arp

# Disable (recommended — Proxy ARP breaks subnet isolation)
echo 0 | sudo tee /proc/sys/net/ipv4/conf/all/proxy_arp

Proxy ARP is considered harmful in modern networks because: - It masks the real network topology - It breaks the assumption that same-subnet hosts can communicate directly - It enables ARP -based man-in-the-middle when combined with spoofing - It causes unnecessary broadcast traffic

ARP Spoofing / Poisoning - How It Works

ARP has no authentication. Any host can claim any IP -to- MAC mapping at any time. There is no sequence number, no timestamp, no signature. Receiving hosts trust whatever ARP reply they receive, even if they never sent an ARP request.

The attack: send forged ARP replies to two hosts, telling each that you are the other: 

Attacker (MAC: cc:cc:cc:cc:cc:cc, IP: 192.168.1.99)
Victim A (192.168.1.10, MAC: aa:aa:aa:aa:aa:aa) — wants to reach the internet
Gateway  (192.168.1.1,  MAC: gg:gg:gg:gg:gg:gg) — the router

Step 1: Attacker sends ARP Reply to Victim A:
  "192.168.1.1 is at cc:cc:cc:cc:cc:cc"
  → A's ARP cache: 192.168.1.1 → cc:cc:cc:cc:cc:cc (attacker's MAC)

Step 2: Attacker sends ARP Reply to Gateway:
  "192.168.1.10 is at cc:cc:cc:cc:cc:cc"
  → Gateway's ARP cache: 192.168.1.10 → cc:cc:cc:cc:cc:cc (attacker's MAC)

Result:
  A's traffic to internet → goes to Attacker (who forwards it to Gateway)
  Gateway's traffic to A  → goes to Attacker (who forwards it to A)
  
  Attacker sits in the middle, seeing all traffic between A and the internet.

This requires continuous re-sending of forged ARP replies because ARP cache entries expire. Most ARP spoofing tools send replies every 2-5 seconds to maintain the poisoned state. 

# Detect ARP spoofing — look for multiple MACs claiming the same IP
sudo tcpdump -i eth0 -nn -v 'arp' | grep "is-at"
# Look for the SAME IP mapping to DIFFERENT MACs over time

# arpwatch — monitors ARP traffic, alerts on changes
sudo pacman -S arpwatch
sudo arpwatch -i eth0

# Static ARP for gateway (prevents spoofing of gateway IP)
# Add to /etc/systemd/network/ or use iproute2:
sudo ip neigh add 192.168.1.1 lladdr gg:gg:gg:gg:gg:gg dev eth0 nud permanent

Constructing ARP Packets with Scapy

#!/usr/bin/env python3
"""
ARP packet construction and manipulation with scapy.
"""
from scapy.all import Ether, ARP, srp, sendp, send

# ── ARP Request ──
def arp_request(target_ip: str, interface: str = None):
    pkt = Ether(dst="ff:ff:ff:ff:ff:ff") / ARP(
        op=1,         # Request
        pdst=target_ip
    )
    answered, unanswered = srp(pkt, timeout=2, iface=interface, verbose=False)
    for sent, received in answered:
        print(f"{received.psrc} → {received.hwsrc}")
    return answered

# ── ARP Reply (forged) ──
def arp_reply(target_ip: str, target_mac: str, spoofed_ip: str, spoofed_mac: str):
    """Send a forged ARP reply claiming spoofed_ip is at spoofed_mac."""
    pkt = Ether(dst=target_mac) / ARP(
        op=2,         # Reply
        psrc=spoofed_ip,   # Source (spoofed) IP
        hwsrc=spoofed_mac, # Source (spoofed) MAC
        pdst=target_ip,    # Target IP
        hwdst=target_mac   # Target MAC
    )
    sendp(pkt, verbose=False)

# ── Gratuitous ARP ──
def gratuitous_arp(ip: str, mac: str):
    """Announce an IP-MAC mapping to the entire subnet."""
    pkt = Ether(dst="ff:ff:ff:ff:ff:ff") / ARP(
        op=2,
        psrc=ip,
        hwsrc=mac,
        pdst=ip,      # Target IP = Sender IP (gratuitous)
        hwdst="ff:ff:ff:ff:ff:ff"
    )
    sendp(pkt, verbose=False)

# ── ARP Probe ──
def arp_probe(target_ip: str):
    """Check if an IP address is in use (duplicate address detection)."""
    pkt = Ether(dst="ff:ff:ff:ff:ff:ff") / ARP(
        op=1,
        psrc="0.0.0.0",  # Sender IP unknown
        pdst=target_ip
    )
    answered, _ = srp(pkt, timeout=2, verbose=False)
    if answered:
        print(f"[!] {target_ip} is IN USE by {answered[0][1].hwsrc}")
    else:
        print(f"[+] {target_ip} appears to be free")
    return len(answered) > 0

arping - ARP-Level Ping

arping bypasses IP -level routing entirely. It sends ARP requests directly to the target IP and reports which MAC address responds. Because ARP operates at layer 2, arping works even when the target has iptables dropping all IP traffic - the ARP protocol is independent of IP filtering: 

# Install arping
sudo pacman -S arping

# Single ARP ping
sudo arping -c 3 -I eth0 192.168.1.1

# Output:
# ARPING 192.168.1.1 from 192.168.1.10 eth0
# Unicast reply from 192.168.1.1 [aa:bb:cc:dd:ee:ff] 0.512ms
# Unicast reply from 192.168.1.1 [aa:bb:cc:dd:ee:ff] 0.423ms
# Unicast reply from 192.168.1.1 [aa:bb:cc:dd:ee:ff] 0.401ms
# Sent 3 probes (1 broadcast(s))
# Received 3 response(s)

# Detect duplicate IPs (multiple MACs responding for the same IP)
sudo arping -c 5 -I eth0 -D 192.168.1.100
# Returns exit code 1 if address is already in use

# Unsolicited ARP (gratuitous)
sudo arping -c 3 -U -I eth0 -s 192.168.1.100 192.168.1.100

Switch MAC Address Table (CAM Table)

Switches build a MAC address table (often called CAM , Content Addressable Memory) by observing the source MAC address of incoming frames. This table maps MAC addresses to switch ports: 

CAM Table Example:
  MAC                Port    VLAN    Age
  aa:bb:cc:dd:ee:ff  Gi1/0/1  10     45s
  11:22:33:44:55:66  Gi1/0/5  10     12s
  77:88:99:aa:bb:cc  Gi1/0/8  10     3s

When a frame arrives with a destination MAC in the CAM table, the switch forwards it only to the recorded port (unicast). When the destination MAC is unknown, the switch floods the frame to all ports in the VLAN (except the ingress port). This is why ARP requests (broadcast) reach all hosts. 

# On a managed switch (Cisco):
# show mac address-table

# On Linux bridge (virtual switch):
bridge fdb show
# Output:
# aa:bb:cc:dd:ee:ff dev eth0 master br0
# 11:22:33:44:55:66 dev eth1 master br0 permanent

# On Open vSwitch:
ovs-appctl fdb/show br0

CAM table overflow attack concept: Fill the switch's CAM table with thousands of fake MAC addresses until legitimate frames can no longer be stored. The switch then floods all frames to all ports - turning a switch into a hub and allowing passive traffic interception.

ARP vs NDP - IPv6's Replacement

IPv6 eliminates ARP entirely and replaces it with ICMP v6 Neighbor Discovery Protocol ( NDP ), which operates with ICMP v6 Types 135 (Neighbor Solicitation) and 136 (Neighbor Advertisement). 

ARP (IPv4):                              NDP (IPv6):
  Broadcast ARP Request                   Multicast Neighbor Solicitation
  → Everyone hears it                     → Only solicited-node group hears it
  
  Unicast ARP Reply                       Unicast Neighbor Advertisement
  → No authentication                      → No authentication (but can use SEND/CGA)
  
  EtherType 0x0806                         IP Proto 58 (ICMPv6), Type 135/136
  Directly on Ethernet                     Carried inside IPv6 packet

Key differences:

Feature ARP (IPv4) NDP (IPv6)
Protocol Standalone (EtherType 0x0806) ICMPv6 inside IPv6
Transport Raw Ethernet frame IPv6 multicast
Address resolution Broadcast Solicited-node multicast
Duplicate detection Gratuitous ARP (op=1, spa=0.0.0.0) NS with unspecified source address
Router discovery Separate (ICMP Router Discovery or static) Built into NDP (RS/RA)
Redirect ICMP Redirect (separate) Built into NDP
Security None SEND (RFC 3971) - cryptographic, rarely deployed 
# IPv6 neighbor cache (equivalent to ARP cache)
ip -6 neigh show

# Output:
# fe80::1 dev eth0 lladdr aa:bb:cc:dd:ee:ff router REACHABLE
# 2001:db8::42 dev eth0 lladdr 11:22:33:44:55:66 STALE

# IPv6 duplicate address detection (DAD)
# Before assigning an IPv6 address, the kernel sends NS probes
# Check DAD results:
ip -6 addr show dev eth0 | grep "tentative\|dadfailed"

# NDP parameters
cat /proc/sys/net/ipv6/neigh/eth0/base_reachable_time_ms

NDP is vulnerable to the same spoofing attacks as ARP because NDP also lacks authentication by default. SEND (Secure Neighbor Discovery, RFC 3971) adds cryptographic signatures using CGA (Cryptographically Generated Addresses), but deployment is rare.

ARP in Kernel Bypass Networking

When using kernel-bypass frameworks (DPDK, XDP, netmap), the kernel's ARP stack is not available. The application must implement ARP resolution in userspace: 

#!/usr/bin/env python3
"""
Userspace ARP resolver for kernel-bypass networking.
Demonstrates how DPDK/XDP applications handle ARP.
"""
import socket
import struct
import time
import threading

class UserspaceARP:
    def __init__(self, interface: str):
        self.interface = interface
        self.cache = {}  # ip → (mac, timestamp)
        self.sock = socket.socket(socket.AF_PACKET, socket.SOCK_RAW,
                                  socket.htons(0x0806))
        self.sock.bind((interface, 0))
        self._start_listener()

    def _start_listener(self):
        """Background thread that processes incoming ARP replies."""
        def listen():
            while True:
                data, _ = self.sock.recvfrom(65535)
                if len(data) < 42:
                    continue
                # Parse ARP reply
                arp_op = struct.unpack("!H", data[20:22])[0]
                if arp_op == 2:  # Reply
                    spa = socket.inet_ntoa(data[28:32])
                    sha = ":".join(f"{b:02x}" for b in data[22:28])
                    self.cache[spa] = (sha, time.time())

        t = threading.Thread(target=listen, daemon=True)
        t.start()

    def resolve(self, ip: str, timeout: float = 2.0) -> str | None:
        """Resolve IPv4 address to MAC."""
        # Check cache
        if ip in self.cache:
            mac, ts = self.cache[ip]
            if time.time() - ts < 30:  # 30s cache lifetime
                return mac

        # Send ARP request
        eth = struct.pack("!6s6sH",
                          b'\xff' * 6,                    # Broadcast
                          self._my_mac(),                  # Source MAC
                          0x0806)                          # EtherType ARP

        arp = struct.pack("!HHBBH6s4s6s4s",
                          0x0001, 0x0800, 6, 4, 1,        # op=Request
                          self._my_mac(),
                          self._my_ip(),
                          b'\x00' * 6,                     # Target MAC unknown
                          socket.inet_aton(ip))

        self.sock.send(eth + arp)

        # Wait for reply
        deadline = time.time() + timeout
        while time.time() < deadline:
            if ip in self.cache and self.cache[ip][1] > time.time() - timeout:
                return self.cache[ip][0]
            time.sleep(0.01)

        return None  # Resolution failed

    def _my_mac(self) -> bytes:
        import fcntl
        ifreq = struct.pack("16s", self.interface[:15].encode())
        info = fcntl.ioctl(self.sock.fileno(), 0x8927, ifreq)
        return info[18:24]

    def _my_ip(self) -> bytes:
        import fcntl
        ifreq = struct.pack("16s", self.interface[:15].encode())
        info = fcntl.ioctl(self.sock.fileno(), 0x8915, ifreq)
        return info[20:24]

Common ARP-Related Kernel Parameters

# ── Security ──

# Ignore gratuitous ARP
cat /proc/sys/net/ipv4/conf/all/arp_ignore
# 0 = respond to any local IP on any interface (default)
# 1 = respond only if target IP is on the receiving interface
# 2 = respond only if target IP is on receiving interface AND sender IP is in same subnet

# ARP filtering (respond based on routing table)
cat /proc/sys/net/ipv4/conf/all/arp_filter
# 0 = kernel can respond from any interface (default)
# 1 = kernel responds only from the interface that would route to the sender

# ARP announcement behavior
cat /proc/sys/net/ipv4/conf/all/arp_announce
# 0 = always use any local address
# 1 = avoid secondary addresses on the same subnet
# 2 = always use the best local address for the target

# ARP notifications (send gratuitous ARP on changes)
cat /proc/sys/net/ipv4/conf/all/arp_notify
# 0 = do not notify (default)

Summary

ARP bridges the gap between logical IP addressing and physical MAC addressing on Ethernet networks. It is simple - a request/response protocol with no built-in security - but that simplicity has kept it working for 40 years. Its lack of authentication is both its greatest weakness (enabling spoofing attacks) and its strength (zero configuration, instant resolution). IPv6 addresses the security gap with NDP and SEND, but deployment of cryptographically secured neighbor discovery remains uncommon.

Challenge

Write a Go tool that builds an ARP request for a target IP on a chosen interface, sends it over a raw AF_PACKET socket, and prints the hardware address from the first reply. The snippet below builds and sends the frame; complete it by reading the reply and verify the result with tcpdump . The program needs CAP_NET_RAW , so run it as root. 

package main

import (
	"encoding/binary"
	"fmt"
	"net"
	"os"
	"syscall"
)

func htons(v uint16) uint16 { return v<<8 | v>>8 }

func main() {
	if len(os.Args) != 3 {
		fmt.Fprintf(os.Stderr, "usage: %s <iface> <target-ip>\n", os.Args[0])
		os.Exit(1)
	}
	iface, targetIP := os.Args[1], net.ParseIP(os.Args[2]).To4()
	if targetIP == nil {
		fmt.Fprintln(os.Stderr, "invalid target IP")
		os.Exit(1)
	}

	ifi, err := net.InterfaceByName(iface)
	if err != nil {
		panic(err)
	}
	addrs, err := ifi.Addrs()
	if err != nil || len(addrs) == 0 {
		panic("interface has no address")
	}
	srcIP := addrs[0].(*net.IPNet).IP.To4()

	fd, err := syscall.Socket(syscall.AF_PACKET, syscall.SOCK_RAW, int(htons(0x0806)))
	if err != nil {
		panic(err)
	}
	defer syscall.Close(fd)

	// Ethernet header + ARP request for targetIP (42 bytes, no padding).
	frame := make([]byte, 42)
	for i := 0; i < 6; i++ {
		frame[i] = 0xff // broadcast destination
	}
	copy(frame[6:12], ifi.HardwareAddr)
	binary.BigEndian.PutUint16(frame[12:14], 0x0806) // EtherType: ARP
	binary.BigEndian.PutUint16(frame[14:16], 1)      // HTYPE: Ethernet
	binary.BigEndian.PutUint16(frame[16:18], 0x0800) // PTYPE: IPv4
	frame[18], frame[19] = 6, 4                      // HLEN, PLEN
	binary.BigEndian.PutUint16(frame[20:22], 1)      // OPER: request
	copy(frame[22:28], ifi.HardwareAddr)             // SHA
	copy(frame[28:32], srcIP)                        // SPA
	copy(frame[38:42], targetIP)                     // TPA

	addr := &syscall.SockaddrLinklayer{Protocol: htons(0x0806), Ifindex: ifi.Index}
	if err := syscall.Sendto(fd, frame, 0, addr); err != nil {
		panic(err)
	}
	fmt.Printf("sent ARP request for %s\n", targetIP)
}

go run . eth0 192.168.1.1;
# In another terminal:
sudo tcpdump -i eth0 -nn arp;
