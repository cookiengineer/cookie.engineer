Ransomware

Prevention, detection and response to ransomware attacks through layered controls and kill chain disruption.

Overview

Ransomware is the final step of an intrusion, not the whole of it. This article covers the kill chain that precedes encryption, the signals each phase leaves behind, prevention controls, incident response, and a challenge that builds an entropy-based encryption detector in Go.

Required Reading

  • Processes - process creation, privilege escalation, system calls
  • Cryptography - symmetric encryption, ransomware's use of hybrid encryption

Concept

Ransomware is the monetization of access. Attackers gain a foothold, escalate privileges, move laterally, exfiltrate data for double extortion, then deploy encryption. The ransomware itself is the last 1% of the operation. By the time files are encrypted, the attacker has been inside the network for days or weeks.

Prevention and detection must target the preceding 99% of the kill chain - initial access, persistence, privilege escalation, lateral movement, and data exfiltration. If you wait for the encryption event, you've already lost.

Ransomware Kill Chain

Phase 1: Initial Access
  → Phishing (macro docs, HTML smuggling, QR codes)
  → RDP brute force (exposed port 3389)
  → VPN appliance exploit (CVE-202x on Pulse/Ivanti/Fortinet)
  → Supply chain compromise (trojanized update)

Phase 2: Execution & Persistence
  → PowerShell, WMI, CMD, scheduled tasks, registry Run keys
  → Cobalt Strike beacon, AnyDesk, Atera (legit remote tools)
  → Disable Windows Defender via GPO / registry

Phase 3: Discovery
  → net view, nltest /dclist, AdFind, BloodHound (SharpHound)
  → Identify domain controllers, file shares, backup servers
  → Enumerate AD for high-value targets

Phase 4: Lateral Movement
  → Pass-the-Hash, Pass-the-Ticket, Overpass-the-Hash
  → RDP, WinRM, PsExec, WMI, SMB
  → Goal: reach Domain Controller and backup servers

Phase 5: Exfiltration (Double Extortion)
  → rclone, MegaSync, WinSCP → data uploaded to attacker cloud
  → Exfiltrate before encryption → "pay or we publish"

Phase 6: Impact (Encryption)
  → Delete Volume Shadow Copies: vssadmin delete shadows /all
  → Disable recovery: bcdedit /set {default} recoveryenabled no
  → Stop services: Exchange, SQL, backup agent
  → Encrypt files: AES + RSA hybrid, skip system files to keep OS running
  → Drop ransom note: README.txt in every directory

Common Entry Vectors

Phishing (still #1)

Subject: "Invoice Overdue — Payment Required"
Attachment: invoice_2026-06.docm (macro-enabled)
  → User enables macros
  → VBA downloads next-stage from pastebin.com/raw/abc123
  → Payload executes: IcedID / Emotet / QakBot loader

Subject: "Shared Document: Q3 Financials"
Attachment: Q3_Financials.zip → Q3_Financials.iso
  → Mounts ISO → contains .lnk shortcut
  → .lnk executes hidden .dll via rundll32.exe
  → Bypasses Mark-of-the-Web

RDP brute force

# Detect ongoing RDP brute force (Windows Event Log):
# Event ID 4625 (Failed Logon) — LogonType 10 (RemoteInteractive)
# Count failures per source IP per hour, alert > 20 failures

# Linux equivalent: SSH brute force detection
journalctl -u sshd --since "1 hour ago" \
  | grep "Failed password" \
  | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn \
  | awk '$1 > 20 {print "ALERT:", $2, "—", $1, "failed attempts"}'

VPN appliance exploits

# Detect exploitation of VPN appliances:
# - Mass scanning for specific CVEs
# - Unusual authentication patterns (login from new geo, new device)
# - Web shell uploaded to VPN portal directory
# Monitor: /var/log/vpn/access.log for POST to uncommon paths (webshells)
grep -E "POST.*(cmd|exec|upload|xmlrpc)" /var/log/vpn/access.log

Detection Signals

Ransomware operations generate detectable signals at each phase. Focus on the pre-encryption indicators: 

# Linux: Monitor for ransomware preparation behaviors

# 1. Volume shadow copy interaction (Windows-equivalent fs freeze)
auditctl -w /usr/bin/fsfreeze -p x -k ransomware_fsfreeze

# 2. Bulk file rename events (encryption changes extensions)
auditctl -a always,exit -F arch=b64 -S rename -S renameat -k bulk_rename

# 3. High file write entropy (encrypted data looks like random bytes)
# Use auditd + file integrity monitoring (Wazuh, osquery)

# 4. Disabling security tools
auditctl -w /usr/bin/systemctl -p x -k systemctl_usage
# Monitor for: systemctl stop firewalld, systemctl stop auditd

# 5. Data exfiltration precursors
auditctl -w /usr/bin/rclone -p x -k exfil_tool
auditctl -w /usr/bin/megasync -p x -k exfil_tool

Windows-specific detection signals

Sysmon Event ID 1 (Process Creation):
  vssadmin.exe delete shadows /all /quiet     ← Delete volume shadows
  bcdedit.exe /set {default} recoveryenabled no  ← Disable recovery
  wbadmin.exe delete catalog -quiet           ← Delete Windows backups
  wevtutil.exe cl System                      ← Clear event log
  fsutil.exe behavior set disablelastaccess 1 ← Disable last access timestamps
  
  Any occurrence of these commands = high-confidence ransomware signal

Sysmon Event ID 11 (File Create):
  *.encrypted, *.locked, *.crypt, *.wncry, *.zepto → known ransomware extensions
  HELP_DECRYPT.txt, HOW_TO_RECOVER.txt → ransom notes

Sysmon Event ID 8 (CreateRemoteThread):
  cross-process injection → common in ransomware encrypted payloads

Registry changes:
  HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Shell
  → Modification = persistence indicator

Linux Crypto Monitoring

#!/bin/bash
# Detective control: monitor for high-CPU processes doing unusual file I/O
# Run from cron every 5 minutes

THRESHOLD_CPU=80  # CPU % threshold
THRESHOLD_FILES=100  # open files threshold

# Find suspicious processes
ps aux --sort=-%cpu | awk -v cpu="$THRESHOLD_CPU" 'NR>1 && $3 > cpu {print $2, $11}' | while read pid cmd; do
  # Check how many files this process has open
  open_files=$(ls /proc/$pid/fd 2>/dev/null | wc -l)
  if [ "$open_files" -gt "$THRESHOLD_FILES" ]; then
    echo "ALERT: PID $pid ($cmd) — CPU ${cpu}%, $open_files open files"
    # Log to SIEM
    logger -t ransomware-detect "Suspicious: $pid $cmd"
  fi
done

File entropy monitoring

#!/usr/bin/env python3
# entropy-watch.py — detect ransomware by monitoring file entropy
# Encrypted files have near-maximum Shannon entropy (≈8 bits/byte)

import os
import math
from collections import Counter

def shannon_entropy(data):
    if not data:
        return 0
    total = len(data)
    counts = Counter(data)
    entropy = 0
    for count in counts.values():
        p = count / total
        entropy -= p * math.log2(p)
    return entropy

# Scan directory for high-entropy files
THRESHOLD = 7.5  # bits per byte — encrypted data typically > 7.8

for root, dirs, files in os.walk('/important/data'):
    for name in files:
        filepath = os.path.join(root, name)
        if os.path.getsize(filepath) > 1024 * 1024:  # skip files < 1MB
            continue
        try:
            with open(filepath, 'rb') as f:
                sample = f.read(4096)  # first 4KB is enough
            entropy = shannon_entropy(sample)
            if entropy > THRESHOLD:
                print(f"HIGH ENTROPY: {filepath} ({entropy:.2f} bits/byte)")
        except PermissionError:
            pass

Prevention Controls

Application Whitelisting

Rule: Only signed binaries from %WINDIR% and %PROGRAMFILES% may execute
Result: Phishing macro drops payload to %TEMP% → execution blocked
						
# Linux equivalent: fapolicyd (Red Hat) or custom systemd restrictions
# Restrict execution paths
sudo pacman -S fapolicyd  # if available
# Or enforce with mount options:
# /tmp: noexec
# /home/*: noexec
# Users can only execute from /usr/bin and /usr/local/bin

LSA Protection (Windows)

HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RunAsPPL = 1
→ LSA process protected from credential dumping (mimikatz)

Protected Users group (Active Directory)

Add privileged accounts to "Protected Users" group:
→ No NTLM authentication (Kerberos only, AES encryption)
→ No delegation (constrained or unconstrained)
→ No cached credentials
→ CredSSP and WDigest are disabled

Credential theft hardening (Linux)

# Protect against credential dumping
# /etc/sysctl.d/99-credential-hardening.conf
kernel.kptr_restrict = 2       # hide kernel pointers
kernel.yama.ptrace_scope = 2   # restrict ptrace to CAP_SYS_PTRACE
kernel.perf_event_paranoid = 3 # restrict perf events

# Restrict /proc/mem access
# Mount proc with hidepid=2

Incident Response Specifics

To pay or not to pay

The official position (FBI, NCSC, CISA ): Do not pay. Paying funds future attacks and there is no guarantee of data return or non-publication.

Operational reality: Some organizations pay because their backup strategy failed and the alternative is business extinction. If the decision is made to pay:

  1. Negotiation is through a professional incident response firm (not direct)
  2. Payment is in cryptocurrency (BTC/XMR)
  3. Decryptors provided by attackers are often slow, buggy, and incomplete
  4. Even after payment, assume data was exfiltrated
  5. OFAC compliance: paying sanctioned entities is illegal (Wizard Spider/TrickBot and Evil Corp are sanctioned)

IR steps for ransomware

0. ISOLATE: Disconnect affected systems from network IMMEDIATELY
   - Do NOT shutdown — encrypted files + memory are evidence
   - Pull network cable, disable switch port, isolate VLAN

1. IDENTIFY: Determine ransomware variant
   - Ransom note, file extension, encryption pattern
   - Submit to ID-Ransomware

2. CONTAIN: Block C2 and lateral movement
   - Block attacker IPs at firewall
   - Disable compromised accounts
   - Reset all privileged credentials (assume they're stolen)

3. ASSESS: What did they encrypt? What did they exfiltrate?
   - Check backup integrity BEFORE wiping anything
   - Check firewall/proxy logs for data exfil logs
   - Check if they reached domain controller

4. RECOVER: Restore from clean, verified backups
   - Restore to clean environment (not the infected one)
   - Scan restored data BEFORE putting into production

5. HARDEN: Close the entry vector
   - How did they get in? Fix that.
   - Review and improve detection rules
   - Update backup strategy if needed

6. REPORT: Legal, regulatory, law enforcement
   - Data breach notification laws (GDPR: 72 hours)
   - Report to CISA / FBI / local CERT
   - Cyber insurance notification

Notable Case Studies

Conti (2020-2022)

  • Ransomware-as-a-Service (RaaS): affiliates deploy, core team provides infrastructure
  • TTP s: Cobalt Strike, manual recon, RDP lateral movement, SMB file transfer
  • Double extortion: exfiltrate with rclone to MEGA before encryption
  • Leak site: "Conti News"
  • Skipped .exe , .dll , and .sys files to keep the OS running
  • Disbanded in May 2022 after the Costa Rica attack and leaks of its internal chats and source code

REvil / Sodinokibi (2019-2021)

  • Targeted MSPs and software vendors for supply chain access (Kaseya VSA, July 2021)
  • TTP s: spearphishing, legitimate login, Cobalt Strike, domain admin, deploy
  • The Kaseya attack encrypted 1,500+ businesses through a single MSP
  • Bitdefender and law enforcement released a universal decryptor for pre-July-2021 variants

LockBit (2019-2024)

  • Most prolific RaaS: 25%+ of ransomware incidents in 2022-2023
  • TTP s: RDP brute force, VPN exploits, legitimate pen-testing tools
  • StealBit: custom exfiltration tool, faster than rclone
  • Operation Cronos (Feb 2024): law enforcement disruption and decryptor release
  • The builder leaked, so copycat variants emerged within weeks

The key lesson across all three is the same TTP chain: initial access broker -> Cobalt Strike -> AD enumeration -> domain admin -> deploy. Same kill chain, different branding. Defend the kill chain, not the brand.

Challenge

Write a Go tool that walks a directory tree, samples each regular file, and reports files whose Shannon entropy is close to the maximum of eight bits per byte. Encryption produces near-random output, so a cluster of high-entropy files in a document tree is a strong encryption signal. Add ransom-note filename and known-extension checks to cut the false positives. 

package main

import (
	"flag"
	"fmt"
	"math"
	"os"
	"path/filepath"
	"strings"
)

var suspicious = []string{".encrypted", ".locked", ".crypt", ".wncry", ".zepto", ".conti"}
var notes = []string{"readme.txt", "help_decrypt.txt", "how_to_recover.txt", "restore_files.txt"}

func entropy(data []byte) float64 {
	if len(data) == 0 {
		return 0
	}
	counts := make(map[byte]int)
	for _, b := range data {
		counts[b]++
	}
	total := float64(len(data))
	result := 0.0
	for _, count := range counts {
		p := float64(count) / total
		result -= p * math.Log2(p)
	}
	return result
}

func main() {
	root := flag.String("root", ".", "directory to scan")
	threshold := flag.Float64("threshold", 7.5, "entropy threshold in bits per byte")
	sample := flag.Int("sample", 4096, "bytes to sample per file")
	flag.Parse()

	err := filepath.Walk(*root, func(path string, info os.FileInfo, err error) error {
		if err != nil || info == nil || !info.Mode().IsRegular() || info.Size() == 0 {
			return nil
		}

		file, err := os.Open(path)
		if err != nil {
			return nil
		}

		buffer := make([]byte, *sample)
		n, _ := file.Read(buffer)
		file.Close()
		score := entropy(buffer[:n])

		base := strings.ToLower(filepath.Base(path))
		ext := strings.ToLower(filepath.Ext(path))

		isNote := false
		for _, name := range notes {
			if base == name {
				isNote = true
			}
		}

		isSuspicious := false
		for _, suffix := range suspicious {
			if ext == suffix {
				isSuspicious = true
			}
		}

		if score >= *threshold || isNote || isSuspicious {
			fmt.Printf("entropy=%.3f note=%v ext=%-10s path=%s\n", score, isNote, ext, path)
		}
		return nil
	})
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}

Build the tool, then point it at a directory of compressed archives (high entropy, no note) and a directory of text files (low entropy) to see the difference: 

go build -o ransomwatch ransomwatch.go
./ransomwatch -root /home/user/Documents -threshold 7.5
./ransomwatch -root /home/user/Pictures -threshold 7.9

Reduce false positives by adding a filename allowlist and by ignoring already-compressed formats such as .gz , .zip , .jpg , and .mp4 , then wrap the scan in a systemd timer or an inotify loop to run it continuously.
