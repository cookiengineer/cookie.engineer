Network Monitoring

Detecting suspicious network behaviour with Zeek, ntopng, flow-based monitoring, and beaconing detection.

Overview

Host-based monitoring tells you what a compromised machine is doing internally. Network monitoring tells you what data it is sending to the outside world. C2 callbacks, data exfiltration, lateral movement - they all traverse the wire. A well-placed network sensor sees what endpoint tools miss.

Required Reading

  • TCP Handshake - TCP flags, state machine, connection lifecycle
  • HTTP - HTTP methods, headers, status codes, sessions
  • DNS - DNS resolution, record types, tunneling
  • TLS - TLS handshake, certificates, cipher suites

Zeek (formerly Bro)

Zeek is a passive network security monitor that reconstructs sessions at the application layer, extracts metadata, and fires events that user-defined scripts consume. It is not an inline prevention device and does not block traffic. It is a metadata extraction engine that generates structured logs.

Architecture

Network Interface → Packet Capture (AF_PACKET / PF_RING)
    → Event Engine (TCP reassembly, protocol parsers)
        → Script Layer (policy scripts, notice framework)
            → Logs (conn.log, http.log, dns.log, notice.log, ...)

Zeek generates per-protocol log files continuously. Every connection gets a uid (unique identifier) that links entries across logs.

Installation (Arch)

pacman -S zeek
# Node configuration
sed -i 's/interface=eth0/interface=lo/' /opt/zeek/etc/node.cfg
zeekctl install
zeekctl start

Key Log Files

Log File Contents
conn.log TCP/UDP/ICMP connections, bytes, duration, state
http.log HTTP requests, host header, URI, user-agent, response code
dns.log DNS queries and responses, query type, answer
ssl.log TLS handshake data, SNI, certificate issuer, JA3 hash
ssh.log SSH client/server versions, auth attempts
notice.log Alerts generated by notice framework
files.log Files transferred over protocols Zeek can extract
x509.log X.509 certificate details
weird.log Protocol anomalies (malformed packets, unexpected states)

Querying Zeek Logs

# All connections to port 445 (SMB)
zeek-cut id.orig_h id.resp_h id.resp_p service < conn.log | grep "445"

# Top 10 client IPs by connection count
zeek-cut id.orig_h < conn.log | sort | uniq -c | sort -rn | head -10

# DNS queries for suspicious TLDs
zeek-cut query < dns.log | grep -E '\.(tk|ml|ga|cf|gq|xyz|top)$'

# HTTP POST requests (potential data exfiltration)
zeek-cut method host uri < http.log | grep "^POST"

# TLS connections with suspicious SNI
zeek-cut server_name < ssl.log | sort | uniq -c | sort -rn | head -20

# Long-duration connections (potential C2 beacons)
zeek-cut id.orig_h id.resp_h id.resp_p duration < conn.log | \
    awk '$4 > 3600 {print}'

# Find connections with RST flag (scanning/recon)
zeek-cut id.orig_h id.resp_h id.resp_p conn_state < conn.log | \
    grep -E "RSTO|RSTR"

Zeek Script Writing

Zeek scripts use an event-driven DSL. You register handlers for events the engine generates.

Basic Script Structure

# /opt/zeek/share/zeek/site/scripts/custom/detect-beacon.zeek

module DetectBeacon;

export {
    redef enum Notice::Type += {
        Periodic_Connection
    };

    # Threshold: 5 connections, max 30s variance
    const beacon_threshold = 5 &redef;
    const beacon_variance = 30.0 &redef;
}

# Track connection times per (source, destination) pair
global conn_times: table[addr, addr, port] of vector of time &read_expire=1hr;

event connection_state_remove(c: connection) {
    local key = (c$id$orig_h, c$id$resp_h, c$id$resp_p);

    if (key !in conn_times)
        conn_times[key] = vector();

    conn_times[key] += c$start_time;

    # Check for periodic pattern after threshold
    if (|conn_times[key]| >= beacon_threshold) {
        local intervals: vector of interval;
        for (i in conn_times[key]) {
            if (i > 0)
                intervals += conn_times[key][i] - conn_times[key][i - 1];
        }

        local avg = 0.0;
        for (i in intervals)
            avg += interval_to_double(intervals[i]);
        avg /= |intervals|;

        local variance = 0.0;
        for (i in intervals)
            variance += (interval_to_double(intervals[i]) - avg) ** 2;
        variance /= |intervals|;

        if (variance < beacon_variance) {
            NOTICE([$note=Periodic_Connection,
                    $conn=c,
                    $msg=fmt("Periodic connection: %s -> %s:%d every %.1fs",
                        c$id$orig_h, c$id$resp_h, c$id$resp_p, avg)]);
        }
    }
}

HTTP Request Monitoring

# /opt/zeek/share/zeek/site/scripts/custom/detect-suspicious-http.zeek

event http_request(c: connection, method: string, original_uri: string,
                  unescaped_uri: string, version: string) {
    # Detect unusually long URIs (potential injection)
    if (|unescaped_uri| > 2048) {
        NOTICE([$note=Weird::Activity,
                $conn=c,
                $msg=fmt("Long URI (%d bytes): %s", |unescaped_uri|, unescaped_uri)]);
    }

    # Detect user-agent absence (common in malicious tools)
    if (!c$http?$user_agent || c$http$user_agent == "") {
        NOTICE([$note=Weird::Activity,
                $conn=c,
                $msg=fmt("HTTP request with no User-Agent from %s", c$id$orig_h)]);
    }

    # Detect requests to raw IP addresses (C2 often uses IP, not domain)
    if (c$http?$host && /^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$/ in c$http$host) {
        NOTICE([$note=Weird::Activity,
                $conn=c,
                $msg=fmt("HTTP request to raw IP: %s", c$http$host)]);
    }
}

ntopng

ntopng provides real-time traffic analysis with a web dashboard. It uses nDPI for deep packet inspection (application protocol identification).

pacman -S ntopng nprobe

# Start ntopng with Redis backend
systemctl enable --now redis
ntopng -i eth0 --http-port 3000

# Access dashboard at https://cookie.engineer

ntopng strengths: protocol breakdown per host, top talkers, flow aggregation, alerts on threshold breaches. Weaknesses: resource-intensive, GUI -oriented (harder to integrate with automated pipelines).

Flow-Based Monitoring

Flow records aggregate packets into unidirectional metadata summaries. A flow is defined by the 5-tuple: (src_ip, dst_ip, src_port, dst_port, protocol) . Flows capture bytes, packets, timestamps, and TCP flags.

# NetFlow export with softflowd
pacman -S softflowd
softflowd -i eth0 -n 192.168.1.100:2055

# Collect and analyze with nfdump
pacman -S nfdump
nfcapd -l /var/netflow -p 2055
nfdump -r /var/netflow/nfcapd.202606260000 | head -20

# Top talkers
nfdump -r /var/netflow/nfcapd.202606260000 -s srcip/bytes -n 10

# Flow-based beaconing detection: flows with consistent intervals
nfdump -r /var/netflow/nfcapd.202606260000 \
    -o "fmt:%ts %sa %da %sp %dp %pr %pkt %byt" | \
    awk '{print $2, $3, $5}' | sort | uniq -c | sort -rn | head -20

DNS Query Monitoring for C2

DNS is the most abused protocol for C2 communication because most environments allow outbound DNS unconditionally.

Sinkhole / PassiveDNS

# dnsmasq-based sinkhole — redirect malicious domains to internal sinkhole
# /etc/dnsmasq.d/sinkhole.conf
address=/evil-domain.com/10.0.0.1
address=/.malware-c2.xyz/10.0.0.1

# PassiveDNS with dnsmonster
dnsmonster --interface=eth0 --stdoutType=json | jq '.'

Zeek DNS Analysis

# Detect DNS queries with excessive entropy (DGA domains)
event dns_request(c: connection, msg: dns_msg, query: string, qtype: count,
                  qclass: count) {
    # Domain length check (DGA domains often long)
    if (|query| > 50) {
        NOTICE([$note=Weird::Activity,
                $conn=c,
                $msg=fmt("Long DNS query: %s", query)]);
    }

    # Check entropy of subdomain labels
    local entropy = 0;
    for (i in query) {
        if (query[i] == ".")
            next;
        # Simplified: count unique characters
    }
}

Beaconing Detection

C2 beacons produce predictable connection patterns. Detection approach:

# beacon-detect.py — detect periodic connections from Zeek conn.log
import json
import sys
from collections import defaultdict
from statistics import mean, stdev

connections = defaultdict(list)

for line in sys.stdin:
    parts = line.strip().split('\t')
    if len(parts) < 7:
        continue
    ts, uid, orig_h, resp_h, resp_p, proto, duration = \
        parts[0], parts[1], parts[2], parts[3], parts[4], parts[5], parts[6]
    key = f"{orig_h}->{resp_h}:{resp_p}"
    connections[key].append(float(ts))

for key, times in connections.items():
    if len(times) < 10:
        continue
    # Calculate intervals between successive connections
    intervals = [times[i] - times[i-1] for i in range(1, len(times))]
    avg = mean(intervals)
    sd = stdev(intervals) if len(intervals) > 1 else 0
    # Low standard deviation = regular pattern = potential beacon
    if sd < avg * 0.1 and 10 < avg < 86400:
        print(f"BEACON: {key} interval={avg:.1f}s stddev={sd:.1f}s count={len(times)}")

Usage:

zeek-cut ts uid id.orig_h id.resp_h id.resp_p proto duration < conn.log | \
    python3 beacon-detect.py

TLS Certificate Transparency Monitoring

Monitor Certificate Transparency logs for certificates issued to your domains - catches attackers who obtain fraudulent certs.

# certspotter — monitor CT logs
git clone https://github.com/SSLMate/certspotter.git
./certspotter -domains example.com -start 2026-06-01

# certstream — real-time CT log stream
pip install certstream
python3 -c "
from certstream.core import CertStreamClient
def callback(message, context):
    if message['message_type'] == 'certificate_update':
        domains = message['data']['leaf_cert']['all_domains']
        if any('example.com' in d for d in domains):
            print(f'[!] New cert for our domain: {domains}')
CertStreamClient(on_message=callback).run_forever()
"

Data Exfiltration Detection Patterns

# Large outbound transfers (> 100MB to single destination)
zeek-cut id.orig_h id.resp_h id.resp_p orig_bytes < conn.log | \
    awk '$4 > 104857600 {print $1" -> "$2":"$3, $4/1048576"MB"}'

# Unusual protocol usage (no common service on port 443 is not HTTPS)
zeek-cut id.resp_p service < conn.log | \
    grep -vE "^[0-9]+\t(http|ssl|dns|ssh|smtp)" | \
    sort | uniq -c | sort -rn

# Many small uploads to same destination (data chunking)
zeek-cut id.orig_h id.resp_h id.resp_p orig_bytes < conn.log | \
    awk '{if ($4 > 0) {k=$1"->"$2":"$3; c[k]++; b[k]+=$4}} \
    END {for (k in c) if (c[k]>100) print k, c[k], b[k]/c[k]/1024"KB avg"}'

# Persistent TCP connections with no data (heartbeat beacons)
zeek-cut id.orig_h id.resp_h id.resp_p duration orig_bytes resp_bytes < conn.log | \
    awk '$4+$5<100 && $3>60 {print $1" -> "$2":"$3, $4"sec"}'
