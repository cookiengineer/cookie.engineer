Anti-Debugging Techniques

Linux anti-debugging techniques and the systematic bypass strategies used to defeat them.

Overview

Malware is not a passive artifact. It fights back by detecting the analyst's debugger and changing behavior: exiting cleanly, corrupting output, triggering a logic bomb, or counter-attacking. This article catalogs the Linux anti-debugging checks - ptrace, TracerPid, timing, INT3 scanning, signals, self-modifying code, and environment inspection - and gives a concrete bypass for each. After reading it you can neutralize common checks with GDB scripts, LD_PRELOAD hooks, or small binary patches.

Required Reading

  • GDB Fundamentals - GDB basics, breakpoint internals, hardware and software breakpoints
  • System Calls - ptrace syscall details, /proc filesystem, prctl, signal delivery

1. The Detection Surface

Every anti-debug check observes some side effect of debugging:

Category Detection Target Mechanism Evasion Difficulty
ptrace Tracer presence ptrace(PTRACE_TRACEME) Easy (patch/LD_PRELOAD)
/proc Kernel metadata /proc/self/status TracerPid Medium (hook filesystem)
Timing Execution delay rdtsc / clock_gettime delta Medium (skip/hardware)
INT3 scan Software breakpoints Scan .text for 0xCC Easy (hardware breakpoints)
Signal handlers Signal interception SIGTRAP custom handler Medium (handle pass)
Self-modifying Corrupted patches XOR .text + check integrity Hard (hardware BP or SMC-aware)
Parent process Debugger parent readlink /proc/PPID/exe Easy (LD_PRELOAD)
Environment GDB-specific vars getenv("LD_PRELOAD") Easy (unset vars)
Seccomp System call policy prctl(PR_GET_SECCOMP) Hard (kernel-level)

The approach: identify each check, understand what it detects, choose the minimal bypass.

2. ptrace(PTRACE_TRACEME)

The canonical anti-debug check. The logic:

#include <sys/ptrace.h>
#include <unistd.h>
#include <stdio.h>

int is_debugged_ptrace(void) {
    // If a tracer (GDB) is already attached, this FAILS with -1.
    // If NO tracer, this succeeds (0), making THIS process the tracer.
    if (ptrace(PTRACE_TRACEME, 0, 0, 0) == -1) {
        return 1;  // Debugger present
    }
    return 0;
}

int main() {
    if (is_debugged_ptrace()) {
        printf("Debugger detected — exiting\n");
        _exit(1);
    }
    printf("No debugger — running normally\n");
    return 0;
}

The underlying syscall:

ptrace(PTRACE_TRACEME, 0, 0, 0) → syscall 101
  - On success: returns 0, parent becomes tracer
  - On failure (already traced): returns -1, errno = EPERM
  - Up to Linux 4.8: could retry (PTRACE_TRACEME after failed attempt
    would succeed if first tracer detached... possible race)

Detection via strace

# Compile the test:
gcc -o ptrace-test ptrace-test.c

# Verify: without debugger, succeeds
./ptrace-test
# No debugger — running normally

# With gdb attached, fails:
gdb -batch -ex 'break is_debugged_ptrace' -ex 'run' -ex 'continue' ./ptrace-test
# Debugger detected — exiting

# With strace — strace is a tracer too!
strace ./ptrace-test
# ptrace(PTRACE_TRACEME) = -1 EPERM (Operation not permitted)
# strace IS a ptrace-based tracer — the check sees it.

Bypass strategies

# Bypass 1: LD_PRELOAD hook
cat > ptrace-hook.c << 'EOF'

#include <dlfcn.h>
#include <sys/ptrace.h>
#include <stdarg.h>

long ptrace(enum __ptrace_request request, ...) {
    if (request == PTRACE_TRACEME) {
        return 0;  // Always succeed — "no debugger"
    }
    // For other ptrace requests, call the real one
    static long (*real_ptrace)(enum __ptrace_request, ...) = NULL;
    if (!real_ptrace) {
        real_ptrace = dlsym(RTLD_NEXT, "ptrace");
    }
    va_list args;
    va_start(args, request);
    long ret;
    if (request == PTRACE_PEEKDATA || request == PTRACE_PEEKTEXT) {
        pid_t pid = va_arg(args, pid_t);
        void *addr = va_arg(args, void *);
        void *data = va_arg(args, void *);
        ret = real_ptrace(request, pid, addr, data);
    } else {
        ret = 0;
    }
    va_end(args);
    return ret;
}
EOF

3. /proc/self/status - TracerPid

The kernel exposes tracing state in /proc . Any process can read its own status: 

# Normal process:
head -20 /proc/self/status | grep Tracer
# TracerPid:      0

# Under GDB:
gdb -batch -ex 'shell cat /proc/$_pid/status | grep Tracer' /bin/true
# TracerPid:      <gdb_pid>

# Under strace:
strace -o /dev/null cat /proc/self/status | grep Tracer
# TracerPid:      <strace_pid>

# Under both strace AND gdb:
# TracerPid shows the most recent tracer (the one that attached last).

Malware implementation:

#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int is_debugged_proc(void) {
    FILE *f = fopen("/proc/self/status", "r");
    if (!f) return 1;
    char line[256];
    while (fgets(line, sizeof(line), f)) {
        if (strncmp(line, "TracerPid:", 10) == 0) {
            int pid = atoi(line + 10);
            fclose(f);
            return pid != 0;  // Non-zero = debugger
        }
    }
    fclose(f);
    return -1;  // Error reading
}

Additional /proc checks beyond TracerPid: 

# Check parent process name:
readlink /proc/$PPID/exe
# /usr/bin/gdb → debugger
# /usr/bin/strace → tracer
# /usr/bin/bash → normal shell

# Check /proc/self/cmdline for gdb/strace/stap:
cat /proc/self/cmdline | tr '\0' ' '
# gdb ./malware

# Check /proc/self/wchan (waiting channel):
cat /proc/self/wchan
# Under gdb: "ptrace_stop"
# Normal: "0" or some kernel function

# Check /proc/self/stat — field 3 is state:
awk '{print $3}' /proc/self/stat
# t (T) = stopped/traced
# R = running
# S = sleeping

4. Timing-Based Detection

Debuggers slow execution by orders of magnitude (100x-10000x). Timing checks measure execution between two points. 

#include <stdio.h>
#include <stdint.h>
#include <time.h>

// Method 1: rdtsc (CPU timestamp counter — high precision)
static inline uint64_t rdtsc(void) {
    uint32_t lo, hi;
    __asm__ volatile("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}

int is_debugged_rdtsc(void) {
    uint64_t t1 = rdtsc();
    // Minimal work: a few NOPs or a simple addition
    __asm__ volatile("nop; nop; nop; nop; nop;");
    uint64_t t2 = rdtsc();
    return (t2 - t1) > 1000;  // Threshold: > 1000 cycles = debugger
}

// Method 2: clock_gettime (nanosecond precision)
int is_debugged_clock(void) {
    struct timespec t1, t2;
    clock_gettime(CLOCK_MONOTONIC, &t1);
    // Minimal work
    __asm__ volatile("nop; nop; nop;");
    clock_gettime(CLOCK_MONOTONIC, &t2);
    long ns = (t2.tv_sec - t1.tv_sec) * 1000000000L +
              (t2.tv_nsec - t1.tv_nsec);
    return ns > 10000;  // > 10 microseconds = debugger
}

// Method 3: gettimeofday (microsecond)
#include <sys/time.h>
int is_debugged_timeofday(void) {
    struct timeval t1, t2;
    gettimeofday(&t1, NULL);
    for (volatile int i = 0; i < 100; i++) { }
    gettimeofday(&t2, NULL);
    long us = (t2.tv_sec - t1.tv_sec) * 1000000L +
              (t2.tv_usec - t1.tv_usec);
    return us > 500;  // > 500 microseconds = debugger
}

// Method 4: prctl PR_SET_TIMING (process timing mode)
// Can detect if process was stopped/single-stepped.

Timing threshold reference:

Condition rdtsc delta for~5 NOPs clock_gettime delta
Native execution 20-50 cycles 50-200 ns
Under GDB (continue) 50-100 cycles 200-500 ns
Under GDB (stepped) 10,000-1,000,000+ cycles 50,000-500,000+ ns
Under strace 5,000-50,000 cycles 10,000-100,000 ns
In VM 200-1000 cycles (VM exit overhead) 500-2000 ns

5. INT3 Breakpoint Scanning

GDB software breakpoints write 0xCC (INT3) at the target address. Malware scans its own .text section for 0xCC bytes. 

#include <stdio.h>
#include <stdint.h>

// Check if any function has a leading 0xCC (breakpoint)
int is_debugged_int3(void *func) {
    return *(unsigned char*)func == 0xCC;
}

// Scan an entire function for 0xCC bytes
int scan_for_int3(void *start, size_t len) {
    unsigned char *p = (unsigned char*)start;
    for (size_t i = 0; i < len; i++) {
        if (p[i] == 0xCC) {
            return i;  // Found INT3 at offset i
        }
    }
    return -1;
}

// Self-check your own function for breakpoints
int self_check(void) {
    extern char __executable_start;
    // Calculate checksum of .text
    uint32_t sum = 0;
    unsigned char *p = (unsigned char*)&__executable_start;
    for (int i = 0; i < 4096; i++) {
        sum += p[i];
    }
    return sum;  // Known good value; if different, debugger modified code
}

Advanced variant: check specific critical function bytes:

// The malware knows what bytes should be at critical locations
int check_critical_function(void) {
    extern unsigned char critical_func_start[];
    // Expected bytes (known at compile time)
    static const unsigned char expected[] = {
        0x55, 0x48, 0x89, 0xe5,  // push rbp; mov rbp, rsp
        0x48, 0x83, 0xec, 0x10   // sub rsp, 0x10
    };
    return memcmp(critical_func_start, expected, sizeof(expected)) == 0;
}

# Example: XOR loop at 0x401200-0x401240 decrypts 0x401300-0x401400
# Hardware break at 0x401300 (first decrypted instruction).

# No 0xCC in the XOR region. The XOR decrypts correctly.
# Hardware breakpoint traps on FIRST execution of decrypted code.

6. SIGTRAP Handler Detection

Debuggers intercept signals before the debugged process. If you install a SIGTRAP handler and it runs, no debugger captured the signal first. 

#include <signal.h>
#include <stdio.h>
#include <stdlib.h>

volatile int sigtrap_caught = 0;

void sigtrap_handler(int sig) {
    sigtrap_caught = 1;
}

int is_debugged_sigtrap(void) {
    signal(SIGTRAP, sigtrap_handler);
    sigtrap_caught = 0;

    // Trigger a SIGTRAP
    __asm__ volatile("int3");

    if (sigtrap_caught) {
        // Handler ran — no debugger intercepted the signal
        return 0;  // Not debugged
    }
    return 1;  // Debugger is present (caught SIGTRAP)
}

Variation: raise multiple signal types and check which are intercepted:

// Check if any of these signals reach our handler
int is_debugged_signal_test(void) {
    volatile int caught[4] = {0};

    signal(SIGTRAP, handler_trap);
    signal(SIGILL, handler_ill);
    signal(SIGSEGV, handler_segv);
    signal(SIGBUS, handler_bus);

    __asm__ volatile("int3");                     // SIGTRAP
    __asm__ volatile("ud2");                      // SIGILL (undefined instruction)
    // SIGSEGV triggered by accessing unmapped memory

    return !(caught[0] && caught[1]);  // If handlers ran, no debugger
}

Bypass

# GDB signal handling controls:
handle SIGTRAP nostop noprint pass
handle SIGILL nostop noprint pass
# pass: the signal is delivered to the program (handler runs)
# The malware thinks no debugger is attached.

# The default GDB behavior for SIGTRAP is:
# stop=yes, print=yes, pass=no (GDB keeps the signal)
# Change to: pass=yes to let malware handler execute.

# Alternative: catch signal SIGTRAP, inspect, then pass:
catch signal SIGTRAP
commands

  signal SIGTRAP       # Resend signal to the inferior
  continue
end

7. Self-Modifying Code

SMC + INT3 = corrupted decryption. If malware encrypts its .text and decrypts at runtime:

  1. Malware .text is stored encrypted on disk
  2. At runtime: decrypts .text section (XOR with key)
  3. Executes decrypted code
  4. Re-encrypts when done

If GDB wrote a 0xCC breakpoint in the encrypted region, the decryption XORs it to garbage. The decrypted instruction is corrupted -> SIGILL or wrong behavior. 

// Anti-debug via SMC: code that tries to detect modifications
__attribute__((section(".text"))) 
static const uint8_t encrypted_func[] = {
    0x12, 0x34, 0x56, 0x78, 0x9a, 0xbc, 0xde, 0xf0
};

void decrypt_and_execute(void) {
    uint8_t code[64];
    uint8_t key = 0x55;
    for (int i = 0; i < sizeof(encrypted_func); i++) {
        code[i] = encrypted_func[i] ^ key;
    }
    // code[i] XOR 0x55 = expected instruction bytes
    // If GDB breaks here with 0xCC, the INT3 byte also gets XOR'd
    // and the result is NOT the original instruction.

    // Verify integrity
    if (code[0] != 0x55 || code[1] != 0x48) {  // Expected: push rbp; mov rbp, rsp
        fprintf(stderr, "Code integrity violation (debugger?)\n");
        _exit(1);
    }

    // Execute:
    ((void(*)())code)();
}

Bypass

# Method 1: Hardware breakpoints in SMC regions
hbreak *0x401350              # Decrypt code ends, first instruction of decrypted
# Hardware breakpoints use DR0-DR3, no 0xCC written.

# Method 2: Break after integrity check, before execution
# The check verifies code[0] == 0x55, code[1] == 0x48
# If check passes, set hardware breakpoint at the indirect call:
hbreak *0x4013a0              # Address of ((void(*)())code)();

# Method 3: Record-replay to avoid modifying SMC regions
target record-full btrace      # Intel PT (Processor Trace) recording
continue                       # Execute through SMC without modifying code
# After execution, replay and analyze side effects.

# Method 4: Single-step through SMC region (painful but precise)
# Break BEFORE the SMC function, stepi through decryption,
# dump decrypted code after the loop.

# Method 5: Emulate SMC region with Python
# Read encrypted bytes, XOR with key in Python, place
# result at the expected execution address in GDB.
python
import gdb

def emulate_smc(enc_addr, key_addr, code_addr, length):
    inf = gdb.selected_inferior()
    encrypted = inf.read_memory(enc_addr, length)
    key = inf.read_memory(key_addr, 1)[0]
    decrypted = bytes([b ^ key for b in encrypted])
    inf.write_memory(code_addr, decrypted)
    print(f"[*] Emulated SMC: {length}B decrypted")
end

8. Parent Process Detection

#include <stdio.h>
#include <string.h>
#include <unistd.h>

// Check if parent process name indicates a debugger
int is_debugged_parent(void) {
    char path[256];
    char buf[256];
    pid_t ppid = getppid();

    snprintf(path, sizeof(path), "/proc/%d/exe", ppid);
    ssize_t len = readlink(path, buf, sizeof(buf) - 1);
    if (len == -1) return 0;
    buf[len] = '\0';

    // Check for known debuggers/tracers
    const char *debuggers[] = {
        "gdb", "strace", "ltrace", "stap", "lldb",
        "valgrind", "pin", "qemu", "frida", "rr",
        NULL
    };
    for (int i = 0; debuggers[i]; i++) {
        if (strstr(buf, debuggers[i])) {
            return 1;
        }
    }
    return 0;
}

// Check /proc/self/cmdline for GDB arguments
int is_debugged_cmdline(void) {
    FILE *f = fopen("/proc/self/cmdline", "r");
    if (!f) return 0;
    char buf[512] = {0};
    fread(buf, 1, sizeof(buf)-1, f);
    fclose(f);

    return (strstr(buf, "gdb") != NULL ||
            strstr(buf, "--args") != NULL);
}

10. VDSO and Syscall Checks

// Check if the syscall instruction is intercepted
// by comparing the actual vsyscall page with expected values

#define _GNU_SOURCE
#include <unistd.h>
#include <sys/auxv.h>
#include <string.h>
#include <stdio.h>

int is_debugged_vdso(void) {
    // The vDSO (linux-vdso.so.1) is mapped into every process.
    // Debuggers may intercept syscalls by modifying the vDSO or
    // setting breakpoints on its functions.

    unsigned long vdso_addr = getauxval(AT_SYSINFO_EHDR);
    if (!vdso_addr) return 0;

    // Check for 0xCC breakpoints in common vDSO functions
    // (clock_gettime, gettimeofday, time)
    unsigned char *ptr = (unsigned char*)vdso_addr;
    for (int i = 0; i < 4096; i++) {
        if (ptr[i] == 0xCC) {
            return 1;  // Breakpoint in vDSO
        }
    }
    return 0;
}

    # call rel32: E8 XX XX XX XX where target = rip + 5 + rel32

14. Systematic Defeat Approach

1. IDENTIFY: Run under strace first.
   strace -f -e trace=ptrace,open,openat,read,clock_gettime \
     -o /tmp/antidebug.log ./malware
   Look for:
     - ptrace(PTRACE_TRACEME) = -1 EPERM
     - open("/proc/self/status", O_RDONLY)
     - clock_gettime(CLOCK_MONOTONIC, ...) repeated closely

2. UNDERSTAND: Read the assembly around each check.
   objdump -d ./malware | grep -B 10 -A 10 <address>
   What does the check DO with the result?
     - test eax,eax; jne exit → flags determine behavior
     - call anti_debug; test eax,eax; jz normal → function return check

3. BYPASS: Choose the minimal intervention.
   - Can I patch one instruction? → binary patch
   - Can I hook one library function? → LD_PRELOAD
   - Can I modify one register at one breakpoint? → GDB script
   - Do I need to avoid writing 0xCC? → hardware breakpoints

4. VERIFY: Run the bypassed binary.
   gdb -x bypass.gdb ./malware
   Does it reach the interesting behavior?
   If not, repeat from step 1 with strace output from bypassed run.

Challenge

Write a Go tool that runs two anti-debug checks: read TracerPid from /proc/self/status , and measure how long a fixed loop takes. Run it normally, then under gdb with a breakpoint inside the loop. Explain which check fires, and why a longer timing threshold or a hardware breakpoint lets the other check pass. 

package main

import (
	"fmt"
	"os"
	"strings"
	"time"
)

func tracerPid() string {
	b, err := os.ReadFile("/proc/self/status")
	if err != nil {
		return "?"
	}
	for _, line := range strings.Split(string(b), "\n") {
		if strings.HasPrefix(line, "TracerPid:") {
			return strings.TrimSpace(strings.TrimPrefix(line, "TracerPid:"))
		}
	}
	return "0"
}

func timingCheck() bool {
	start := time.Now()
	sum := 0
	for i := 0; i < 1000000; i++ {
		sum += i
	}
	elapsed := time.Since(start)
	fmt.Printf("[*] loop took %s\n", elapsed)
	return elapsed > 20*time.Millisecond
}

func main() {
	if pid := tracerPid(); pid != "0" {
		fmt.Printf("[!] TracerPid=%s - debugger detected\n", pid)
	} else {
		fmt.Println("[+] TracerPid=0")
	}
	if timingCheck() {
		fmt.Println("[!] timing anomaly - debugger suspected")
	} else {
		fmt.Println("[+] timing looks normal")
	}
}
