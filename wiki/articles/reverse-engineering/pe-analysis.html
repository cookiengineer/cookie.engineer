PE Analysis from Linux

Analyzing Windows PE malware from a Linux workstation: PE structure, import analysis, packer detection, and static triage.

Overview

Windows malware cannot execute natively on Linux. This is not a limitation, it is a safety boundary: the binary is inert, so you can dump every byte, parse every header, and extract every resource without risk. This article covers the PE structures that matter for triage, the Linux toolchain that replaces Dependency Walker and PE Explorer, import and packer analysis, timestamp and Rich header forensics, and ends with a Go tool that scores a PE for suspicious traits.

Required Reading

  • PE Format - PE format structure: DOS header, NT headers, sections, imports, exports, and resources
  • Binary Identification - initial file identification and triage before PE structural analysis

Why Linux for Windows Malware Analysis

Windows malware cannot execute natively on Linux. This is not a limitation - it is a safety boundary. The binary is inert. You can analyze it aggressively: dump every byte, run every static tool, parse every header, extract every resource. Nothing executes. Nothing infects.

The Linux PE toolchain is mature. pev (PE Viewer) provides readpe , pescan , pepack , peres , and pedis - collectively replacing Dependency Walker, PE Explorer, and parts of IDA Pro for triage. pecheck from the pefile Python library exposes every structure programmatically. exiftool surfaces metadata. All of this runs from an ArchLinux terminal.

PE Structure for Reversers

A PE file is a remapping of the COFF object format. The structure from front to back:

Offset 0x00:  DOS Header (64 bytes)
             - e_magic:    "MZ" (0x5A4D)
             - e_lfanew:   offset to PE signature

Offset e_lfanew: PE Signature "PE\0\0" (4 bytes)
                 COFF File Header (20 bytes)
                 - Machine:              0x014C (i386), 0x8664 (AMD64)
                 - NumberOfSections:     section count
                 - TimeDateStamp:        compile timestamp (UNIX epoch)
                 - SizeOfOptionalHeader: varies

Optional Header:
                 - Magic:                0x10B (PE32), 0x20B (PE32+)
                 - EntryPointAddress:    RVA of entry point
                 - ImageBase:            default load address
                 - SectionAlignment:     alignment in memory (0x1000)
                 - FileAlignment:        alignment on disk (0x200)
                 - SizeOfImage:          total virtual size
                 - Subsystem:            GUI, CUI, native, driver
                 - DataDirectory:        array of 16 IMAGE_DATA_DIRECTORY
                   - [0]: Export Directory
                   - [1]: Import Directory
                   - [2]: Resource Directory
                   - [9]: TLS Directory
                   - [14]: .NET Metadata Directory

Section Headers (NumberOfSections * 40 bytes):
                 - Name:                 8-byte section name
                 - VirtualSize:          size in memory
                 - VirtualAddress:       RVA in memory
                 - SizeOfRawData:        size on disk
                 - PointerToRawData:     offset on disk
                 - Characteristics:      flags

Manual PE Parsing

Before relying on tools, understand the raw bytes. Parse the DOS header manually:

$ xxd -l 64 unknown.exe
00000000: 4d5a 9000 0300 0000 0400 0000 ffff 0000  MZ..............
00000010: b800 0000 0000 0000 4000 0000 0000 0000  ........@.......
00000020: 0000 0000 0000 0000 0000 0000 0000 0000  ................
00000030: 0000 0000 0000 0000 0000 0000 e000 0000  ................

Bytes 0x00-0x01 : 4d 5a = MZ (little-endian word 0x5A4D ). Bytes 0x3C-0x3F : e0 00 00 00 = 0x000000E0 (e_lfanew). The PE signature is at offset 0xE0 .

Check the PE signature:

$ xxd -s 0xE0 -l 4 unknown.exe
000000e0: 5045 0000                                PE..

50 45 00 00 = PE\0\0 . Confirmed PE.

Read the COFF header:

$ xxd -s 0xE4 -l 20 unknown.exe
000000e4: 4c01 0400 6c8a da60 0000 0000 0000 0000  L...l..`........
000000f4: e000 2300                                ..#.

Machine at offset 0xE4: 4c 01 = 0x014C (i386/x86). NumberOfSections at offset 0xE6: 04 00 = 4 sections. TimeDateStamp at offset 0xE8: 6c 8a da 60 = Unix timestamp.

$ python3 -c "import datetime; print(datetime.datetime.fromtimestamp(0x60da8a6c, datetime.timezone.utc))"
2021-06-29 02:50:20+00:00

This is the compile timestamp. Malware authors often forge this: NULL (0x00000000), past dates to look legitimate, or dates matching known campaigns.

readpe: Full Dump

$ readpe unknown.exe

Outputs every PE structure. For large binaries, focus on specific sections:

$ readpe -H unknown.exe     # Headers only
$ readpe -S unknown.exe     # Section table
$ readpe -i unknown.exe     # Imports
$ readpe -e unknown.exe     # Exports

Sample section table from readpe -S :

Section Table
=============
Name      VirtAddr  VirtSize  RawSize   RawAddr   Flags
.text     0x1000     0x2A3E    0x2C00    0x400     0x60000020
.rdata    0x4000     0x1580    0x1600    0x3000    0x40000040
.data     0x6000     0x08A0    0x0600    0x4600    0xC0000040
.rsrc     0x7000     0x03C0    0x0400    0x4C00    0x40000040

Section flags decode: - 0x60000020 : Code (CNT_CODE) + Execute + Read - 0x40000040 : Initialized data + Read - 0xC0000040 : Initialized data + Read + Write

Suspicious flag: 0xE0000020 = Code + Execute + Read + Write. This is an RWX section - self-modifying code or packed stub.

What Imports Reveal in Combination

Individual imports are informative. Combinations tell a story:

  • VirtualAlloc + VirtualProtect + CreateRemoteThread + WriteProcessMemory : Process hollowing or DLL injection.
  • RegCreateKey + RegSetValue + CreateService : Persistence via Windows service.
  • socket + connect + recv + CreateProcess + pipe : Reverse shell (connect back, spawn cmd.exe, pipe I/O).
  • CryptEncrypt + FindFirstFile + WriteFile + DeleteFile : Ransomware (find files, encrypt, replace, delete originals).
  • VirtualAlloc + GetProcAddress + LoadLibrary : RunPE - custom PE loader that maps a payload from memory.
  • IsDebuggerPresent + GetTickCount + Sleep : Anti-debug with timing evasion.
  • OpenProcess + VirtualAllocEx + WriteProcessMemory + CreateRemoteThread : Classic DLL injection.

Packer Detection on PE Files

Packers compress the original PE and wrap it in an unpacking stub. Detection from Linux:

$ pepack unknown.exe

Pepack checks signatures for 40+ packers. Output:

Packer: UPX -> www.upx.sourceforge.net

Common packers and their PE indicators:

Packer Section Names Characteristics
UPX UPX0, UPX1, .rsrc Entropy > 7.8 in UPX1, UPX! string
ASPack .aspack, .adata Entry point in .aspack
Themida .themida, .data Obfuscated entry point, VM bytecode
VMProtect .vmp0, .vmp1 Virtualized code, mutated entry
MPRESS .MPRESS1, .MPRESS2 Small stub, high compression
PECompact .pec, .pec1, .pec2 Entry point in .pec section
Enigma .enigma1, .enigma2 Anti-debug VM, multiple layers
Obsidium .obsidium Polymorphic decryptor

Manual packer detection without tools:

$ strings -n 6 unknown.exe | grep -iE 'upx|aspack|themida|vmprotect'
UPX!
$Info: This file is packed with the UPX executable packer
						
$ readpe -S unknown.exe | grep -iE 'upx|aspack|themida|\.pec'
Name      VirtAddr  VirtSize  RawSize   RawAddr   Flags
UPX0      0x00001000 0x0000A000 0x00000000 0x00000400 0xE0000080
UPX1      0x0000B000 0x0000D000 0x0000CC00 0x00000400 0xE0000040

UPX0 has RawSize=0 and VirtSize >> RawSize - the decompression target in memory.

PE Timestamps

The TimeDateStamp in the COFF header is Unix epoch seconds of compilation. This identifies the build era:

$ readpe -H unknown.exe | grep TimeDate
TimeDateStamp:      0x60DA8A6C -> Tue Jun 29 02:50:20 2021

Malware timestamp analysis:

  • Unix epoch 0 (1970-01-01): explicitly zeroed, the author stripped the timestamp.
  • Future dates: timestamp manipulation tool or forged date.
  • Dates matching known campaigns: compare against threat intel timelines.
  • Weekend compile: less common for corporate software, common for hobbyist and malware development.
$ python3 -c "
import datetime
ts = 0x60DA8A6C
dt = datetime.datetime.fromtimestamp(ts, datetime.timezone.utc)
print(f'Compiled: {dt}')
print(f'Day:      {dt.strftime(\"%A\")}')
print(f'Year:     {dt.year}')
"
Compiled: 2021-06-29 02:50:20+00:00
Day:      Tuesday
Year:     2021

Rich Header Analysis

The Rich header is an undocumented section between the DOS stub and PE signature. It contains encoded records of the build toolchain: compiler version, linker version, source language, build count. Each record encodes a product ID and a count (number of object files from that product).

Malware analysts use the Rich header to:

  • Identify the Visual Studio version used (VS2008, VS2019, and so on).
  • Detect discrepancies: if the Rich header says VS2019 but the timestamp says 2010, the timestamp is forged.
  • Cluster malware families by build toolchain (the same Rich header means the same builder environment).
$ pecheck -r unknown.exe
[...]
Rich Header:
  [ 0] Product=0x0104 (VS2019 16.0) Count=45
  [ 1] Product=0x00E3 (VS2019 16.11) Count=12
  [ 2] Product=0x009A (C++ AMP) Count=1

Imphash: PE Import Hash

Imphash hashes the import table for variant detection:

$ python3 -c "
import pefile
pe = pefile.PE('unknown.exe')
print(pe.get_imphash())
"
6f5d6f5d6f5d6f5d6f5d6f5d6f5d6f5d

Identical imphashes mean identical import tables. Variants of the same malware family (same C2 logic, different payload) share the same imphash. Use it to cluster unknown samples against a known malware database.

Imphash limitations: - Does not capture dynamically resolved imports ( GetProcAddress / LoadLibrary ) - the import table is minimal. - Packed binaries have tiny import tables (only the unpacking stub's API s) - the real malware's imports are invisible until unpacked. - Not useful for statically linked binaries (no imports).

YARA Rules for PE Malware

YARA is a pattern-matching engine for malware classification. PE-specific YARA rules check header fields, section names, import tables, and byte patterns.

Install YARA :

$ pacman -S yara

Example YARA rule detecting UPX-packed PEs:

rule UPX_Packed_PE {
    meta:
        description = "Detects UPX-packed PE files"
        author      = "Reverse Engineering Lab"
        date        = "2026-06-26"

    strings:
        $mz  = { 4D 5A }              // DOS magic
        $pe  = { 50 45 00 00 }        // PE signature
        $upx0 = "UPX0"                // UPX section name
        $upx1 = "UPX1"                // UPX section name
        $upxs = "UPX!"                // UPX string signature

    condition:
        $mz at 0 and
        $pe at uint16(uint32(0x3C)) and
        (any of ($upx0, $upx1)) and
        $upxs
}

Rule detecting process injection imports:

rule ProcessInjector {
    meta:
        description = "Detects PE with process injection imports"
        author      = "Reverse Engineering Lab"

    strings:
        $mz = { 4D 5A }
        $pe = { 50 45 00 00 }
        $va  = "VirtualAlloc" ascii wide
        $vp  = "VirtualProtect" ascii wide
        $wpm = "WriteProcessMemory" ascii wide
        $crt = "CreateRemoteThread" ascii wide

    condition:
        $mz at 0 and
        $pe at uint16(uint32(0x3C)) and
        all of ($va, $vp, $wpm, $crt)
}

Save as pe_rules.yar and scan:

$ yara pe_rules.yar samples/
UPX_Packed_PE samples/upx_sample.exe
ProcessInjector samples/injector.exe

More PE YARA Rules

Rule detecting suspicious section permissions:

rule RWX_Section {
    meta:
        description = "PE with RWX (executable+writeable) section"

    strings:
        $mz = { 4D 5A }
        $pe = { 50 45 00 00 }

    condition:
        $mz at 0 and
        $pe at uint16(uint32(0x3C)) and
        pe.sections[0].characteristics & 0xE0000000 == 0xE0000000
}

Rule for anti-debug imports:

rule AntiDebug_Imports {
    meta:
        description = "PE importing anti-debug functions"

    strings:
        $idp = "IsDebuggerPresent" ascii wide
        $crp = "CheckRemoteDebuggerPresent" ascii wide
        $ntq = "NtQueryInformationProcess" ascii wide
        $nts = "NtSetInformationThread" ascii wide

    condition:
        2 of them
}

Extracting PE Resources

Embedded resources often contain additional payloads, configuration, or decoy data:

$ peres unknown.exe

Extract all resources to disk:

$ peres -x unknown.exe

This dumps icons, dialogs, version info, manifests, and embedded binaries. Malware commonly stores: - Encrypted payload in RT_RCDATA or custom resource types. - Decoy documents ( PDF , DOCX) in resources - opened as the malware runs. - Configuration blobs with C2 domains, keys, or campaign IDs.

$ peres -x unknown.exe
$ file .rsrc/*
.rsrc/0_1_1033.bin: data
.rsrc/0_2_1033.bin: PE32 executable (GUI) Intel 80386

An embedded PE inside resources - the second-stage payload.

Static Analysis Script for PE Files

#!/usr/bin/env python3
"""
pe_analyze.py -- static triage of PE files from Linux
Usage: python3 pe_analyze.py <file.exe>
"""

import sys
import hashlib
import datetime
import struct

try:
    import pefile
except ImportError:
    print("pip install pefile")
    sys.exit(1)


CATEGORIES = {
    'network': {
        'socket', 'connect', 'send', 'recv', 'sendto', 'recvfrom',
        'bind', 'listen', 'accept', 'WSAStartup', 'WSACleanup',
        'gethostbyname', 'getaddrinfo', 'inet_addr', 'inet_ntoa',
        'InternetOpenA', 'InternetOpenUrlA', 'InternetConnectA',
        'HttpOpenRequestA', 'HttpSendRequestA', 'WinHttpOpen',
    },
    'file': {
        'CreateFileA', 'CreateFileW', 'WriteFile', 'ReadFile',
        'DeleteFileA', 'DeleteFileW', 'MoveFileA', 'CopyFileA',
        'FindFirstFileA', 'FindNextFileA', 'GetFileAttributesA',
        'SetFileAttributesA',
    },
    'execution': {
        'CreateProcessA', 'CreateProcessW', 'WinExec', 'ShellExecuteA',
        'system', 'popen', '_wsystem', '_wpopen',
    },
    'injection': {
        'VirtualAlloc', 'VirtualAllocEx', 'VirtualProtect', 'VirtualProtectEx',
        'WriteProcessMemory', 'ReadProcessMemory', 'CreateRemoteThread',
        'NtCreateThreadEx', 'RtlCreateUserThread', 'QueueUserAPC',
        'SetThreadContext', 'ResumeThread',
    },
    'persistence': {
        'RegCreateKeyExA', 'RegCreateKeyExW', 'RegSetValueExA', 'RegSetValueExW',
        'RegDeleteKeyA', 'RegDeleteKeyW', 'RegOpenKeyExA', 'RegOpenKeyExW',
        'CreateServiceA', 'CreateServiceW', 'StartServiceA', 'OpenSCManagerA',
        'CopyFileA', 'SHGetSpecialFolderPathA',
    },
    'crypto': {
        'CryptEncrypt', 'CryptDecrypt', 'CryptAcquireContextA', 'CryptAcquireContextW',
        'CryptGenKey', 'CryptExportKey', 'CryptImportKey', 'CryptHashData',
    },
    'anti_analysis': {
        'IsDebuggerPresent', 'CheckRemoteDebuggerPresent',
        'NtQueryInformationProcess', 'NtSetInformationThread',
        'OutputDebugStringA', 'OutputDebugStringW', 'GetTickCount',
        'QueryPerformanceCounter', 'NtQuerySystemInformation',
    },
    'info_gathering': {
        'GetComputerNameA', 'GetUserNameA', 'GetSystemInfo',
        'GlobalMemoryStatusEx', 'GetLogicalDriveStringsA',
    },
}

PACKER_SECTIONS = {
    'UPX0', 'UPX1', '.aspack', '.adata', '.themida',
    '.vmp0', '.vmp1', '.MPRESS1', '.MPRESS2', '.pec',
    '.pec1', '.pec2', '.enigma1', '.enigma2',
}


def analyze_pe(filepath: str):
    try:
        pe = pefile.PE(filepath)
    except pefile.PEFormatError as e:
        print(f"Error: not a valid PE file: {e}")
        return

    print("=" * 64)
    print(f"  TARGET: {filepath}")
    print(f"  MACHINE: {hex(pe.FILE_HEADER.Machine)}")
    print(f"  SUBSYSTEM: {pe.OPTIONAL_HEADER.Subsystem}")

    # Timestamp
    ts = pe.FILE_HEADER.TimeDateStamp
    dt = datetime.datetime.utcfromtimestamp(ts)
    print(f"  COMPILED: {dt} ({ts})")
    if ts == 0:
        print(f"    [!] Timestamp is zero (forged)")
    if dt > datetime.datetime(2028, 1, 1):
        print(f"    [!] Future timestamp (forged)")

    # Entry point
    ep = pe.OPTIONAL_HEADER.AddressOfEntryPoint
    print(f"  ENTRY POINT: {hex(ep)}")
    ep_sec = None
    for sec in pe.sections:
        if sec.VirtualAddress <= ep < sec.VirtualAddress + sec.Misc_VirtualSize:
            ep_sec = sec.Name.decode().rstrip('\x00')
    print(f"  ENTRY SECTION: {ep_sec or 'UNKNOWN'}")

    # Hashes
    with open(filepath, 'rb') as f:
        data = f.read()
    print(f"  SHA-256: {hashlib.sha256(data).hexdigest()}")
    print(f"  IMPHASH: {pe.get_imphash()}")

    # Sections
    print(f"\n  --- SECTIONS ---")
    suspicious_sections = []
    for sec in pe.sections:
        name = sec.Name.decode().rstrip('\x00')
        raw_size = sec.SizeOfRawData
        virt_size = sec.Misc_VirtualSize
        chars = sec.Characteristics
        rwx = (chars & 0xE0000000) == 0xE0000000
        ratio = virt_size / max(raw_size, 1)
        flags_str = []
        if chars & 0x20000000: flags_str.append('X')
        if chars & 0x40000000: flags_str.append('R')
        if chars & 0x80000000: flags_str.append('W')
        flag = ''.join(flags_str) or 'NONE'

        print(f"  {name:<16} Raw={raw_size:#08x}  Virt={virt_size:#08x}  "
              f"Ratio={ratio:.1f}  Flags={flag}")

        if rwx:
            suspicious_sections.append(f"{name}: RWX section")
        if name in PACKER_SECTIONS:
            suspicious_sections.append(f"{name}: packer section")
        if name == '.text' and raw_size == 0:
            suspicious_sections.append(".text: zero raw size")
        if ratio > 5:
            suspicious_sections.append(f"{name}: virt/raw ratio {ratio:.1f}")

    # Imports
    print(f"\n  --- IMPORTS ---")
    findings = {cat: set() for cat in CATEGORIES}
    packer_imports = {'LoadLibraryA', 'LoadLibraryW', 'GetProcAddress', 'VirtualAlloc', 'VirtualFree'}

    if hasattr(pe, 'DIRECTORY_ENTRY_IMPORT'):
        total_imports = 0
        for entry in pe.DIRECTORY_ENTRY_IMPORT:
            dll = entry.dll.decode()
            for imp in entry.imports:
                if imp.name:
                    name = imp.name.decode() if imp.name else ''
                    total_imports += 1
                    for cat, keywords in CATEGORIES.items():
                        if name in keywords:
                            findings[cat].add(name)

        print(f"  Total imports: {total_imports}")
        if total_imports < 5:
            suspicious_sections.append(f"Few imports ({total_imports}) — likely packed")

        # Deduplicate packer_imports from findings
        for cat, syms in sorted(findings.items()):
            if syms:
                print(f"  [{cat}]: {', '.join(sorted(syms))}")
    else:
        print(f"  No import table — static binary or corrupted")

    # Packer indicators
    print(f"\n  --- PACKER ANALYSIS ---")
    if suspicious_sections:
        for f in suspicious_sections:
            print(f"  [!] {f}")
    else:
        print(f"  No packer indicators detected")

    # Rich header
    if hasattr(pe, 'RICH_HEADER') and pe.RICH_HEADER:
        print(f"\n  --- RICH HEADER ---")
        try:
            for record in pe.RICH_HEADER.rich_entries[:10]:
                print(f"  Product=0x{record.ProductId:04X} Count={record.Count}")
        except Exception:
            pass

    print("=" * 64)


if __name__ == '__main__':
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <pe_file>")
        sys.exit(1)
    analyze_pe(sys.argv[1])

Challenge

Write a Go tool that parses a PE file with debug/pe , prints the machine type, the compile timestamp as UTC, every section with its permission flags, and a risk score. Award points for an RWX section, a section name from a known packer, a virtual-size to raw-size ratio above 5 , and fewer than five imports. Print the score with the matching reasons.

package main

import (
	"debug/pe"
	"fmt"
	"os"
	"strings"
	"time"
)

var packerSections = []string{
	"UPX0", "UPX1", ".aspack", ".adata", ".themida",
	".vmp0", ".vmp1", ".MPRESS1", ".MPRESS2", ".pec",
	".enigma1", ".enigma2",
}

func contains(list []string, name string) bool {
	for _, item := range list {
		if strings.EqualFold(item, name) {
			return true
		}
	}
	return false
}

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintln(os.Stderr, "usage: pescore <file.exe>")
		os.Exit(1)
	}

	f, err := pe.Open(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	defer f.Close()

	fmt.Printf("Machine:   0x%04x\n", f.FileHeader.Machine)
	ts := time.Unix(int64(f.FileHeader.TimeDateStamp), 0).UTC()
	fmt.Printf("Compiled:  %s\n", ts)

	score := 0
	reasons := make([]string, 0)

	imports := 0
	if syms, err := f.ImportedSymbols(); err == nil {
		imports = len(syms)
	}
	if imports < 5 {
		score += 2
		reasons = append(reasons, "few imports (likely packed)")
	}

	for _, s := range f.Sections {
		name := s.Name
		if contains(packerSections, name) {
			score += 3
			reasons = append(reasons, "packer section: "+name)
		}
		const (
			IMAGE_SCN_MEM_EXECUTE = 0x20000000
			IMAGE_SCN_MEM_READ    = 0x40000000
			IMAGE_SCN_MEM_WRITE   = 0x80000000
		)
		rwx := s.Characteristics&(IMAGE_SCN_MEM_EXECUTE|IMAGE_SCN_MEM_READ|IMAGE_SCN_MEM_WRITE) ==
			(IMAGE_SCN_MEM_EXECUTE | IMAGE_SCN_MEM_READ | IMAGE_SCN_MEM_WRITE)
		if rwx {
			score += 3
			reasons = append(reasons, "RWX section: "+name)
		}
		if s.VirtualSize > s.Size*5 && s.Size > 0 {
			score += 1
			reasons = append(reasons, "large virtual/raw ratio: "+name)
		}
		fmt.Printf("Section %-10s virt=0x%x raw=0x%x\n", name, s.VirtualSize, s.Size)
	}

	fmt.Printf("Score: %d\n", score)
	for _, r := range reasons {
		fmt.Printf("  - %s\n", r)
	}
}
