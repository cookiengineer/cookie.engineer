Binary Patching

Modifying executable machine code to disable checks, redirect execution, inject code, and verify reverse engineering findings.

Overview

Binary patching modifies a compiled executable's machine code to change its runtime behavior. It is the definitive way to verify a reverse engineering hypothesis: if the patched binary behaves exactly as predicted, the analysis was correct. After reading, you can translate a virtual address to a file offset, build replacement opcodes, patch ELF binaries with Ghidra, radare2, or raw bytes, inject code into caves, and confirm every change with objdump.

The Offset Problem

Disassemblers display virtual addresses (VAs) - addresses the code occupies when loaded into memory. An ELF binary stores code at file offsets that differ from VAs. The mapping is defined per PT_LOAD program header by its p_offset and p_vaddr : 

file_offset = p_offset + (virtual_address - p_vaddr)

A segment's p_offset (file offset) and p_vaddr (virtual address) define the mapping. The .text section typically has p_vaddr aligned to a page boundary while p_offset aligns to a smaller sector boundary. For a typical binary: 

$ readelf -l /bin/ls | grep -A1 LOAD
  LOAD           0x0000000000000000 0x0000000000000000 0x0000000000000000
                 0x0000000000003d40 0x0000000000003d40  R E    0x1000
  LOAD           0x0000000000004000 0x0000000000004000 0x0000000000004000
                 0x0000000000004b38 0x0000000000004b38  RW     0x1000

The first LOAD segment (RE: read+execute) maps file offset 0x00 to virtual address 0x00. The second LOAD segment maps file offset 0x4000 to virtual address 0x4000. Here p_offset equals p_vaddr for both segments, so the two addresses coincide. This binary is a non-PIE executable: 

$ readelf -h /bin/ls | grep Type
  Type:                              EXEC (Executable file)

For PIE (Position Independent Executable) binaries the base virtual address is still typically 0x0, and the actual load address is chosen at runtime by ASLR. When patching, you always work with the static mapping derived from the program headers, never the runtime address.

Compute the file offset for a given virtual address:

#!/bin/bash
# offset_calc.sh - compute file offset from virtual address
BINARY="$1"
VA="$2"

# Get .text section details
readelf -S "$BINARY" | awk -v va="$VA" '
/\.text/ {
    file_off = strtonum("0x" $5);
    vaddr    = strtonum("0x" $4);
    offset   = file_off + (strtonum(va) - vaddr);
    printf "File offset: 0x%x\n", offset;
    exit;
}'

Ghidra automates this: Window -> Memory Map shows every section's file offset and VM A mapping. Radare2 with iS lists sections; ?v 0xaddress in conjunction with S gives you offset calculations.

Opcode Construction

Once you know the target offset, you need replacement bytes. Several paths:

Assembly -> machine code with nasm

echo 'nop; nop; nop; nop; ret' \
  | nasm -f bin -o /dev/stdout - \
  | xxd -p
# Output: 90909090c3

This produces raw opcodes without ELF headers ( -f bin ). The -f bin flag tells nasm to emit flat binary output - exactly the bytes you will inject.

Quick single-instruction encoding

nasm -f bin -o /dev/stdout - <<< 'jmp short 0x04'
# Output: eb02

Tool-Assisted Patching

Tool-assisted patching avoids manual encoding:

Tool Patching Interface Output Format
Ghidra Right-click -> Patch Instruction Export Program -> ELF
radare2 r2 -w,wacommand In-place modification
objcopy --change-section-address+xxd External modification
hexedit/bless Direct byte editing In-place modification

Ghidra Patching

  1. Open binary in Ghidra and perform auto-analysis
  2. Navigate to the instruction you want to modify in the Listing window
  3. Right-click the instruction -> Patch Instruction
  4. Type the new assembly (e.g., NOP; NOP; RET or JMP 0x401234 )
  5. Ghidra encodes the instruction in real-time and shows the new bytes
  6. Apply multiple patches as needed across the binary
  7. File -> Export Program -> Original File (select "ELF" as format)
  8. Patched binary is written to the specified output path

Ghidra handles offset calculations and opcode encoding internally. It rejects invalid assembly immediately. For conditional branch inversions, Ghidra supports the full GNU assembler syntax: 

; Original: jne <target>   (0x75 0xXX)
; Patch:    je  <target>   (0x74 0xXX)

Since both instructions are two bytes, no size mismatch occurs. Ghidra preserves all section headers, symbol tables, and relocation entries - the binary remains structurally valid.

Radare2 Patching

Radare2 operates directly on the file in write mode:

# Open in write mode with analysis
r2 -Aw ./target_binary

# Inside r2:
> aaa                          # Analyze all
> s sym.check_license          # Seek to target function
> pdf                          # Print disassembly of function
> s 0x00401234                 # Seek to specific address
> wa nop;nop;nop;nop;nop      # Write assembly (5 NOPs)
> wx 9090909090                # Write raw hex bytes (alternative)
> wa jmp 0x00401250            # Write a jump
> q                            # Quit - file is patched in place

Key radare2 commands:

Command Purpose
wa <assembly> Write assembly instruction(s)
wx <hex> Write raw hex bytes
woo <value> Write octal value
wv <value> Write value at offset
wz <string> Write zero-terminated string
ws <string> Write string at current offset
wxf <file> @ <off> Write file contents at offset

Radare2's wa command uses r2's internal assembler (rasm2). Test your assembly independently: 

rasm2 -d 9090909090          # Disassemble: nop; nop; nop; nop; nop
rasm2 'push rbp'             # Assemble: 55
rasm2 -a x86 -b 64 'nop; nop; ret'
# Output: 9090c3

Manual Byte Patching

For full control, patch at the byte level using dd or python. Compute the file offset, then overwrite: 

# xxd-based workflow - edit hex dump as text
xxd target_binary > hexdump.txt
vim hexdump.txt               # Edit hex bytes manually
xxd -r hexdump.txt > patched_binary
chmod +x patched_binary

The xxd workflow is error-prone because you must keep the hex dump aligned. A python script is safer: 

#!/usr/bin/env python3
"""
binary_patcher.py - apply hex patches to ELF binary by virtual address.

Usage: python3 binary_patcher.py <binary> <va> <hex_bytes> [output]
Example: python3 binary_patcher.py ./target 0x401234 909090 out
"""

import sys
import struct

def section_for_va(data, va):
    """Locate the segment header containing a given virtual address."""
    # ELF header: e_phoff at offset 0x20 (64-bit) or 0x1c (32-bit)
    ei_class = data[4]  # 1=32-bit, 2=64-bit
    if ei_class == 2:
        (e_phoff, e_phentsize, e_phnum) = struct.unpack_from('<QQH', data, 0x20)
        phdr_size = 56
        is_64 = True
    else:
        (e_phoff, e_phentsize, e_phnum) = struct.unpack_from('<IIH', data, 0x1c)
        phdr_size = 32
        is_64 = False

    for i in range(e_phnum):
        off = e_phoff + i * e_phentsize
        p_type = struct.unpack_from('<I', data, off)[0]
        if is_64:
            (p_type, p_flags, p_offset, p_vaddr,
             p_paddr, p_filesz, p_memsz, p_align) = struct.unpack_from('<IIQQQQQQ', data, off)
        else:
            (p_type, p_offset, p_vaddr, p_paddr,
             p_filesz, p_memsz, p_flags, p_align) = struct.unpack_from('<IIIIIIII', data, off)

        if p_type == 1:  # PT_LOAD
            if p_vaddr <= va < p_vaddr + p_memsz:
                return p_offset, p_vaddr, p_filesz, p_memsz

    return None

def patch_binary(filepath, va, hex_bytes, output_path):
    with open(filepath, 'rb') as f:
        data = bytearray(f.read())

    payload = bytes.fromhex(hex_bytes)
    result = section_for_va(data, va)

    if result is None:
        print(f"[-] Virtual address 0x{va:x} not found in any PT_LOAD segment")
        sys.exit(1)

    p_offset, p_vaddr, p_filesz, p_memsz = result
    file_offset = p_offset + (va - p_vaddr)

    if file_offset + len(payload) > len(data):
        print(f"[-] Patch extends beyond file end (offset 0x{file_offset:x}, len {len(payload)})")
        sys.exit(1)

    print(f"[+] Patching VA 0x{va:x} -> file offset 0x{file_offset:x}")
    print(f"[+] Original bytes: {data[file_offset:file_offset+len(payload)].hex()}")
    print(f"[+] New bytes:      {payload.hex()}")

    data[file_offset:file_offset + len(payload)] = payload

    with open(output_path, 'wb') as f:
        f.write(data)

    print(f"[+] Patched binary written to {output_path}")

if __name__ == '__main__':
    if len(sys.argv) < 4:
        print(f"Usage: {sys.argv[0]} <binary> <va> <hex> [output]")
        sys.exit(1)
    va = int(sys.argv[2], 16)
    out = sys.argv[4] if len(sys.argv) > 4 else sys.argv[1] + '.patched'
    patch_binary(sys.argv[1], va, sys.argv[3], out)

Common Patch Patterns

NOP Sled

Replace one or more instructions with NOP (0x90). Use when you want to eliminate a check without altering control flow. For multi-byte instructions, use multi-byte NOPs: 

; Single-byte NOP
nop              ; 90

; Multi-byte NOPs (x86_64):
xchg eax, eax    ; 87 c0     (2 bytes, register swap NOP)
lea rax, [rax+0] ; 48 8d 04 25 00 00 00 00  (8 bytes)
; Intel multi-byte NOP sequence:
; 66 90           (2 bytes)
; 0f 1f 00        (3 bytes)
; 0f 1f 40 00     (4 bytes)
; 0f 1f 44 00 00  (5 bytes)
; 66 0f 1f 44 00 00 (6 bytes)
; 0f 1f 80 00 00 00 00 (7 bytes)

Example: neutralizing a license check:

; Before patching:
0x401200:  call   check_license   ; e8 ab fe ff ff (5 bytes)
0x401205:  test   eax, eax        ; 85 c0
0x401207:  je     0x401300        ; 0f 84 f3 00 00 00 (license invalid jump)

; After NOP sled + force success:
; Patch call to mov eax,1; nop (3 bytes NOP for remaining):
0x401200:  mov    eax, 0x1        ; b8 01 00 00 00 (5 bytes)
0x401205:  test   eax, eax        ; 85 c0 (unchanged)
0x401207:  jne    0x401300        ; 0f 85 f3 00 00 00 (flip je->jne)

Corresponding python patch commands

python3 binary_patcher.py ./target 0x401200 b801000000 out1
python3 binary_patcher.py out1 0x401207 0f85f3000000 out2

Conditional Jump Inversion

Flip the branch condition - the most surgically precise patch. Since conditional jumps have the same instruction length as their inverses, this never causes offset misalignment. 

JE  (0x74) <-> JNE (0x75)
JG  (0x7F) <-> JLE (0x7E)
JL  (0x7C) <-> JGE (0x7D)
JA  (0x77) <-> JBE (0x76)
JB  (0x72) <-> JAE (0x73)
JS  (0x78) <-> JNS (0x79)
JO  (0x70) <-> JNO (0x71)
JP  (0x7A) <-> JNP (0x7B)

Near variants (multi-byte, 0x0F prefix):

JNE near  (0x0F 0x85) <-> JE near  (0x0F 0x84)
JLE near  (0x0F 0x8E) <-> JG near  (0x0F 0x8F)
JGE near  (0x0F 0x8D) <-> JL near  (0x0F 0x8C)
JBE near  (0x0F 0x86) <-> JA near  (0x0F 0x87)
JAE near  (0x0F 0x83) <-> JB near  (0x0F 0x82)

Example - anti-debugging check:

; Before (PTRACE_TRACEME check aborts if debugger present):
0x401250:  call   ptrace        ; syscall wrapper returns 0 on success
0x401255:  test   eax, eax
0x401257:  jns    0x401280      ; if PTRACE failed, jump to abort
                                 ; (ptrace returns 0 if NOT debugged, -1 if debugged)
; Patch: flip jns -> js
0x401257:  js     0x401280      ; now only aborts if NOT debugged

The patch is a single byte: 0x79 -> 0x78 at file offset. This makes the anti-debug check a no-op since the normal path now leads to abort when no debugger is attached.

Return Immediate

Force a function to return a specific value by replacing its first instruction:

; Function returning success (1):
mov  eax, 0x1      ; b8 01 00 00 00
ret                ; c3

; 6 bytes total. If the original function prologue was:
push rbp           ; 55
mov  rbp, rsp      ; 48 89 e5
; ...
; Replace first 6 bytes with b8 01 00 00 00 c3

; Function returning failure (0):
xor  eax, eax      ; 31 c0 (or b8 00 00 00 00)
ret                ; c3

This is the most common patch for license/auth checks - make check_serial() always return

  1. The remaining function bytes (after the prologue replacement) become dead code that never

executes.

Jump Over

Insert an unconditional JMP to skip a block of harmful instructions:

; Before - calls dangerous function, then executes normally:
0x401300:  call   delete_files       ; e8 XX XX XX XX (5 bytes)
0x401305:  call   exfiltrate_data    ; e8 YY YY YY YY (5 bytes)
0x40130A:  call   normal_operation   ; e8 ZZ ZZ ZZ ZZ (5 bytes)

; After - JMP straight to normal_operation:
0x401300:  jmp    0x40130A           ; eb 08 (2 bytes)
0x401302:  nop                        ; 90
0x401303:  nop                        ; 90
0x401304:  nop                        ; 90
0x401305:  call   exfiltrate_data    ; dead code - never reached
0x40130A:  call   normal_operation   ; executes directly after jmp

The JMP short (0xEB) displacement = target - (JMP_address + 2). Here: 0x40130A - (0x401300 + 2) = 0x08.

String Substitution

Replace an inlined string constant to alter behavior:

; Ghidra decompilation reveals:
execve("/bin/sh", argv, envp);

; The string "/bin/sh" sits in .rodata at VA 0x402000.
; Patch to run a different command (must be same or shorter length):
; Replace "/bin/sh" -> "/bin/ls" (same 8 bytes with null terminator)

python3 binary_patcher.py ./target 0x402000 2f62696e2f6c7300 ./patched

If the replacement is shorter, pad with nulls. If longer, you need a code cave (see below).

Jump Table Modification

Switch statements compile to jump tables. Modifying an entry redirects one case:

; Jump table at 0x403000:
0x403000:  .quad 0x401100  ; case 0
0x403008:  .quad 0x401200  ; case 1 - the handler you want to skip
0x403010:  .quad 0x401300  ; case 2

; Redirect case 1 to case 2's handler:
python3 binary_patcher.py ./target 0x403008 0030010000000000 ./patched

Adding Code with Caves

Sometimes you need more space than the original instruction footprint. A code cave is unused space (or newly allocated space) where you place your injected code, then redirect execution to it.

Sources of usable space

  1. Segment padding : ELF segments are page-aligned (0x1000). The gap between section end and page boundary is usable:
   readelf -S ./target | grep -E '\.text|\.rodata' | awk '{print "0x"$5,"0x"$6}'
   # If .text ends at 0x1234 and page boundary is 0x2000, the range 0x1234-0x1FFF is padding
  1. Between sections : ELF headers, section header table, and .init often have gaps
  1. Segment expansion : Add a new PT _LOAD segment (requires offset recalculation - advanced)
  1. Section header padding : The .note.gnu.build-id or .comment section can be overwritten (they're informational only)

Code cave injection workflow

# 1. Find a cave - any region of zero or unused bytes in a PT_LOAD segment:
r2 -A ./target
> iS                          # list sections
> /x 0000000000000000        # find zero-filled regions

# 2. Write your payload at the cave location:
> s 0x00400180               # seek to cave
> wa call sym.check_license  # write your injected code
> wa test eax, eax
> wa jne 0x00401200

# 3. Redirect original code to jump to cave:
> s sym.main+0x15            # original call site
> wa jmp 0x00400180           # redirect to cave

Cave locating in python

#!/usr/bin/env python3
"""find_caves.py - locate code caves in an ELF binary."""

import sys
import struct

def find_caves(filepath, min_size=32):
    with open(filepath, 'rb') as f:
        data = f.read()

    # Parse program headers to find PT_LOAD segments
    ei_class = data[4]
    if ei_class == 2:  # 64-bit
        e_phoff = struct.unpack_from('<Q', data, 0x20)[0]
        e_phentsize = struct.unpack_from('<H', data, 0x36)[0]
        e_phnum = struct.unpack_from('<H', data, 0x38)[0]
        phdr_size = 56
        is_64 = True
    else:
        e_phoff = struct.unpack_from('<I', data, 0x1c)[0]
        e_phentsize = struct.unpack_from('<H', data, 0x2a)[0]
        e_phnum = struct.unpack_from('<H', data, 0x2c)[0]
        phdr_size = 32
        is_64 = False

    for i in range(e_phnum):
        off = e_phoff + i * e_phentsize
        p_type = struct.unpack_from('<I', data, off)[0]
        if p_type != 1:  # PT_LOAD only
            continue

        if is_64:
            p_offset, p_vaddr, p_filesz = struct.unpack_from('<QQQ', data, off + 8)
            p_flags = struct.unpack_from('<I', data, off + 4)[0]
        else:
            p_offset, p_vaddr, p_filesz = struct.unpack_from('<III', data, off + 4)
            p_flags = struct.unpack_from('<I', data, off + 28)[0]

        # Only executable segments (PF_X = 1)
        if not (p_flags & 1):
            continue

        segment_data = data[p_offset:p_offset + p_filesz]
        # Find zero sequences longer than min_size
        run = 0
        for j, byte in enumerate(segment_data):
            if byte == 0:
                run += 1
            else:
                if run >= min_size:
                    cave_start = p_offset + j - run
                    cave_va = p_vaddr + (cave_start - p_offset)
                    print(f"[+] Cave at VA 0x{cave_va:x}, "
                          f"file offset 0x{cave_start:x}, "
                          f"size {run} bytes")
                run = 0
        if run >= min_size:
            cave_start = p_offset + len(segment_data) - run
            cave_va = p_vaddr + (cave_start - p_offset)
            print(f"[+] Cave at VA 0x{cave_va:x}, "
                  f"file offset 0x{cave_start:x}, "
                  f"size {run} bytes")

if __name__ == '__main__':
    find_caves(sys.argv[1] if len(sys.argv) > 1 else 'a.out')

Modifying PLT and GOT

The Procedure Linkage Table (PLT) and Global Offset Table (GOT) are the dynamic linking trampolines. Patching GOT entries redirects all future calls to a dynamically linked function: 

# Find the GOT entry for puts():
objdump -R ./target | grep puts
# 0000000000404018 R_X86_64_JUMP_SLOT  puts@GLIBC_2.2.5

# The GOT entry at 0x404018 initially points to the PLT stub resolver.
# After first call, it holds the actual libc puts address.
# Patch it to point to a different function (e.g., system):

# Patch: overwrite GOT entry with address of system@plt
r2 -w ./target
> s 0x404018
> wv 0x401040               # write 8-byte little-endian address of system@PLT
> q

# Now every puts() call in the binary invokes system() instead.
# puts("/bin/sh") -> system("/bin/sh")

Patching Segment Permissions

Some binaries have self-modifying code that reads its own .text via mprotect. You can pre-patch segment flags to RWX to simplify analysis: 

# readelf -l target | grep -A1 LOAD
# LOAD  ... RE  (Read + Execute)
# Patch the p_flags field: R=4, W=2, X=1. RE=5, RWX=7.

python3 -c "
import sys
data = bytearray(open(sys.argv[1], 'rb').read())
# Find PT_LOAD with PF_X in phdr flags
# For 64-bit ELF at offset 0x20: e_phoff
import struct
phoff = struct.unpack_from('<Q', data, 0x20)[0]
phnum = struct.unpack_from('<H', data, 0x38)[0]
for i in range(phnum):
    off = phoff + i * 56
    p_type = struct.unpack_from('<I', data, off)[0]
    p_flags = struct.unpack_from('<I', data, off + 4)[0]
    if p_type == 1 and (p_flags & 1):  # PT_LOAD + executable
        data[off+4] = 7  # RWX
        print(f'Patched phdr {i} flags: {p_flags} -> 7 (RWX)')
open(sys.argv[2], 'wb').write(data)
" ./target ./target.rwx
chmod +x ./target.rwx

Verification

After patching, verify the change took effect and loading integrity remains:

# 1. Dump the patched instruction bytes:
objdump -d --start-address=0x401200 --stop-address=0x401210 ./patched

# 2. Verify strings are replaced:
strings ./patched | grep '/bin/'

# 3. Check ELF structural integrity:
readelf -h ./patched    # ELF header valid?
readelf -l ./patched    # Program headers OK?
readelf -S ./patched    # Section headers OK?

# 4. Check the file still loads:
file ./patched          # Should say "ELF 64-bit executable"

# 5. Run it:
./patched               # Observe changed behavior

Common Pitfalls

Problem Cause Fix
Immediate crash (SIGILL) Invalid opcode at patched location Verify hex encoding; runobjdump -don patched binary
SIGSEGV Jump targets incorrect, or NOP sled too large Check jump displacement calculation
Patch has no effect Wrong offset; patched dead code or wrong VMA Verify VA-to-offset mapping with readelf sections
Binary fails to load Corrupted ELF headers or oversized patch Check that patch doesn't extend beyond segment bounds
Instruction overwritten Patch longer than original instruction Use code cave or multi-byte NOP padding
Relative jump lands wrong Displacement not recalculated after code shift Recalculate:disp = target - (jmp_addr + jmp_size)

Displacement Calculation

For relative jumps and calls, the displacement = target_address - (instruction_address + instruction_length):

def calc_displacement(target_va, instruction_va, instruction_len):
    """Calculate jmp/call displacement for x86/x86_64."""
    return target_va - (instruction_va + instruction_len)

def encode_jmp32(target_va, instruction_va):
    """Encode a 32-bit relative JMP (5 bytes: E9 + 4-byte displacement)."""
    disp = calc_displacement(target_va, instruction_va, 5)
    if disp < -2147483648 or disp > 2147483647:
        raise ValueError("Displacement out of 32-bit range")
    return b'\xe9' + struct.pack('<i', disp)

def encode_jmp8(target_va, instruction_va):
    """Encode an 8-bit relative JMP (2 bytes: EB + 1-byte displacement)."""
    disp = calc_displacement(target_va, instruction_va, 2)
    if disp < -128 or disp > 127:
        raise ValueError("Displacement out of 8-bit range")
    return b'\xeb' + struct.pack('<b', disp)

Patching in Podman

When reversing malware in a podman container, your patched binary is safely contained:

# Create a writable container from a snapshot image
podman run --rm -it --name malbox alpine:latest /bin/sh

# Inside container: copy binary, patch, test
cp /tmp/sample /tmp/sample.patched
xxd /tmp/sample.patched | sed 's/74 05/75 05/' | xxd -r > /tmp/patched
chmod +x /tmp/patched

# Run and observe in strace
strace -f -o /tmp/trace.log /tmp/patched

The container isolates filesystem operations and network - if your patch fails and the binary goes haywire, it cannot escape the container namespace.

Patching Static Binaries

Stripped binaries lack symbol tables. Ghidra still provides meaningful function labels (FUN_00401200). Radare2 requires address-based navigation: 

r2 -Aw ./stripped_binary
> aaa
> s 0x00401200     # navigate by address
> pdf              # disassemble the function
> wa ret           # patch it

Patching Go Binaries

Go binaries are statically linked with a large runtime. Their function prologues differ (no frame pointer by default). Go uses its own calling convention (stack-based arguments on x86, register-based on ARM64). Patching Go binaries: 

# Go binary has a unique section layout
readelf -S ./go-binary | grep -E '\.text|\.rodata|\.gopclntab'

# Ghidra handles Go ABI natively; patch as usual but test thoroughly
# Go's gopclntab is critical for stack unwinding - leave it intact

Patching goroutine-governed functions is safe since goroutines share a flat address space - there are no thread-local complications.

Patching With objcopy

objcopy can extract, modify, and re-insert sections: 

# Extract .text section
objcopy -O binary --only-section=.text ./target text.bin

# Edit text.bin with a hex editor, then reinsert:
objcopy --update-section .text=text.bin ./target ./patched

# Caveat: objcopy rewrites section table offsets; if your patch
# changes section size, everything downstream shifts.

Writing a Patch File (PWNF)

For distribution, represent patches as a sequence of offset+bytes:

# pwnf format - comment
@0x401200: b801000000  # mov eax, 1
@0x401207: 75           # jne (flip from je)
@0x402000: 2f62696e2f6c7300  # "/bin/ls\0"

A python loader applies these:

import re, sys

def apply_pwnf(binary_path, pwnf_path, output_path):
    with open(binary_path, 'rb') as f:
        data = bytearray(f.read())

    with open(pwnf_path) as f:
        for line in f:
            line = line.split('#')[0].strip()
            if not line or not line.startswith('@'):
                continue
            m = re.match(r'@(0x[0-9a-fA-F]+):\s*([0-9a-fA-F]+)', line)
            if not m:
                continue
            offset = int(m.group(1), 16)
            payload = bytes.fromhex(m.group(2))
            data[offset:offset + len(payload)] = payload
            print(f"[+] Patched 0x{offset:x}: {payload.hex()}")

    with open(output_path, 'wb') as f:
        f.write(data)

if __name__ == '__main__':
    apply_pwnf(sys.argv[1], sys.argv[2], sys.argv[3])

Challenge

Write a Go tool that applies a patch by virtual address. Parse the ELF header and the PT_LOAD program headers, translate the target VA into a file offset, and overwrite the first six bytes of the function with mov eax, 1; ret ( b8 01 00 00 00 c3 ) so it always returns success. Print the original and patched bytes, then verify with objdump -d and run the binary. 

package main

import (
	"encoding/binary"
	"fmt"
	"os"
)

type segment struct {
	offset uint64
	vaddr  uint64
	filesz uint64
}

func loadSegments(data []byte) ([]segment, error) {
	if len(data) < 64 || string(data[:4]) != "\x7fELF" {
		return nil, fmt.Errorf("not an ELF file")
	}
	little := data[5] == 1
	var order binary.ByteOrder = binary.LittleEndian
	if !little {
		order = binary.BigEndian
	}
	class := data[4]
	var phoff uint64
	var phentsize, phnum uint16
	if class == 2 {
		phoff = order.Uint64(data[0x20:0x28])
		phentsize = order.Uint16(data[0x36:0x38])
		phnum = order.Uint16(data[0x38:0x3a])
	} else {
		phoff = uint64(order.Uint32(data[0x1c:0x20]))
		phentsize = order.Uint16(data[0x2a:0x2c])
		phnum = order.Uint16(data[0x2c:0x2e])
	}
	segments := make([]segment, 0)
	for i := 0; i < int(phnum); i++ {
		base := int(phoff) + i*int(phentsize)
		if class == 2 {
			pType := order.Uint32(data[base : base+4])
			if pType != 1 {
				continue
			}
			segments = append(segments, segment{
				offset: order.Uint64(data[base+8 : base+16]),
				vaddr:  order.Uint64(data[base+16 : base+24]),
				filesz: order.Uint64(data[base+32 : base+40]),
			})
		} else {
			pType := order.Uint32(data[base : base+4])
			if pType != 1 {
				continue
			}
			segments = append(segments, segment{
				offset: uint64(order.Uint32(data[base+4 : base+8])),
				vaddr:  uint64(order.Uint32(data[base+8 : base+12])),
				filesz: uint64(order.Uint32(data[base+16 : base+20])),
			})
		}
	}
	return segments, nil
}

func vaToOffset(segments []segment, va uint64) (uint64, error) {
	for _, seg := range segments {
		if va >= seg.vaddr && va < seg.vaddr+seg.filesz {
			return seg.offset + (va - seg.vaddr), nil
		}
	}
	return 0, fmt.Errorf("VA 0x%x not in a PT_LOAD segment", va)
}

func main() {
	if len(os.Args) != 3 {
		fmt.Fprintf(os.Stderr, "usage: %s <binary> <va>\n", os.Args[0])
		os.Exit(1)
	}
	data, err := os.ReadFile(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	var va uint64
	if _, err := fmt.Sscanf(os.Args[2], "%v", &va); err != nil {
		fmt.Fprintln(os.Stderr, "invalid address")
		os.Exit(1)
	}
	segments, err := loadSegments(data)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	offset, err := vaToOffset(segments, va)
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	patch := []byte{0xb8, 0x01, 0x00, 0x00, 0x00, 0xc3}
	fmt.Printf("VA 0x%x -> file offset 0x%x\n", va, offset)
	fmt.Printf("original: % x\n", data[offset:offset+uint64(len(patch))])
	copy(data[offset:], patch)
	fmt.Printf("patched:  % x\n", patch)
	if err := os.WriteFile("patched.bin", data, 0o755); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	fmt.Println("wrote patched.bin")
}
