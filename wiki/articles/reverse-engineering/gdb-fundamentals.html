GDB Fundamentals

Using GDB to inspect running binaries through breakpoints, stepping, memory examination, disassembly, TUI, and scripting.

Overview

GDB is a window into execution. Breakpoints freeze time. Stepping advances it one instruction at a time. Memory inspection peels back abstractions. From a reverse engineer's perspective, GDB is not a bug-finding tool - it is a truth-extraction tool. The binary does something at runtime that you cannot see in a disassembler, and GDB shows you what that something is. After reading, you can set conditional and hardware breakpoints, walk the stack, patch registers and memory in a live process, and automate a session with command and Python scripts.

Required Reading

  • Stack - stack frame structure, rbp/rsp mechanics, prologue/epilogue
  • Calling Conventions - System V AMD64 ABI, register arguments, return values
  • ELF Reversing - ELF structure, sections, segments, dynamic linking, entry point

Launching and Attaching

# Launch binary directly:
gdb ./binary
gdb --args ./binary arg1 arg2 arg3

# Attach to running process:
gdb -p $(pgrep binary_name)
gdb -p 28741

# Launch with environment:
gdb -ex 'set environment LD_PRELOAD=/path/to/lib.so' ./binary

# Launch with arguments and scripts:
gdb -q -x script.gdb --args ./binary arg1

# Core dump analysis:
gdb ./binary core.28741

# Remote debugging (gdbserver):
# On target:
gdbserver :1234 ./binary
# On analyst:
gdb -ex 'target remote 192.168.1.10:1234' ./binary

-q suppresses the license banner. -x sources a GDB command file. -ex executes a single command before the prompt.

Breakpoints

Setting Breakpoints

# Function name (with or without argument types):
break main
break my_function
break __libc_start_main
break *0x401000          # Address breakpoint (prefixed with *)

# Source file + line number:
break src/main.c:42

# Conditional breakpoint:
break process_data if ptr == 0
break write_buffer if length > 1024
break decrypt if $rdi == 0xDEADBEEF

# Temporary breakpoint (fires once, auto-deletes):
tbreak check_key          # Same as: break check_key; enable delete $bpnum

# Hardware breakpoint (uses debug registers, works in read-only memory):
hbreak *0x401050
# Hardware breakpoints are limited: x86-64 has 4 debug address registers.
# Use for: code in .text that you don't want to modify (no INT3 written).

# Break on library function via PLT:
break *0x401030           # PLT stub for puts@plt
# Alternative: break puts (GDB resolves through PLT)

# Break on system call:
catch syscall open        # Break when open() is called
catch syscall execve      # Break when execve() is called
catch syscall ptrace      # Break when ptrace() is called
catch syscall connect     # Break on connect()
catch syscall write       # Break on write() — filters by fd with condition

# General catchpoints:
catch fork                # Break on fork()
catch exec                # Break on execve()
catch throw               # Break on C++ exception throw
catch signal SIGSEGV      # Break on segmentation fault signal
catch syscall             # Break on ALL system calls (verbose, but comprehensive)

Managing Breakpoints

info breakpoints          # List all breakpoints (aliases: i b, info b)
                          # Output columns: Num, Type, Disp, Enb, Address, What

enable 3                  # Enable breakpoint #3
enable once 3             # Enable #3, disable after next hit
enable delete 3           # Enable #3, delete after next hit
enable count 2 3          # Enable #3, disable after 2 hits

disable 3                 # Disable breakpoint #3
disable                   # Disable ALL breakpoints

delete 3                  # Delete breakpoint #3
delete                    # Delete ALL breakpoints

ignore 3 50               # Ignore the next 50 hits of breakpoint #3
                          # Useful: skip loop iterations to reach a condition

# Commands on breakpoint hit (auto-execute):
commands 3
  silent                  # Don't print "Breakpoint 3, ..."
  printf "RAX = 0x%lx\n", $rax
  continue
end

# Conditional break with auto-print and continue:
break *0x401234
commands
  silent
  printf "[*] decrypt called: arg=%p, len=%d\n", $rdi, $rsi
  continue
end

Breakpoint Internals

Software breakpoints write 0xCC (INT3) at the target address. When the CPU executes that byte, it raises SIGTR AP , which GDB catches. GDB then: 1. Replaces 0xCC with the original byte 1. Decrements RIP by 1 (to point to the restored instruction) 1. Gives control to the user

This is why malware can detect software breakpoints: by scanning its own .text for 0xCC bytes.

Hardware breakpoints avoid this by storing the target address in debug registers (DR0-DR3 on x86-64). No byte is modified. The CPU traps when RIP matches a debug register. Downside: only 4 addresses can be watched simultaneously. 

# Show debug registers:
info registers dr0 dr1 dr2 dr3 dr6 dr7
# DR0-DR3: breakpoint addresses
# DR6: status register (which breakpoint fired)
# DR7: control register (enabled, condition, length)

Stepping and Execution Control

# Instruction-level stepping:
stepi                     # Step one MACHINE INSTRUCTION, step into calls
nexti                     # Step one MACHINE INSTRUCTION, step OVER calls
si 5                      # Step 5 instructions
ni 3                      # Next over 3 instructions

# Source-level stepping:
step                      # Step one SOURCE LINE, step into function calls
next                      # Step one SOURCE LINE, step over function calls
s                         # Short form of step
n                         # Short form of next

# Function-level:
finish                    # Run until current function returns (fin/fini)
                          # Prints return value in $rax
until                     # Run until next source line (past current line)
until 42                  # Run until line 42 in current file
advance my_func           # Run until function my_func

# Continue execution:
continue                  # Resume execution until next breakpoint / signal
c                         # Short form
continue 5                # Ignore next 5 breakpoint hits

# Kill and restart:
kill                      # Kill the inferior (debugged process)
run                       # Restart from beginning
run arg1 arg2             # Restart with new arguments

# Signal handling:
signal SIGINT             # Send SIGINT to the inferior
signal 0                  # Resume without sending a signal (0 = no signal)

Examining State

Registers

# All registers:
info registers            # General-purpose, segment, flags, FPU
info all-registers        # Including SSE/AVX, MMX, model-specific

# Specific registers:
p/x $rax                  # Print rax in hex
p/t $rax                  # Print rax in binary
p/d $rax                  # Print rax as signed decimal
p/u $rax                  # Print rax as unsigned decimal
p/c $rax                  # Print rax as character
p/s $rax                  # Print string at address in rax
p/a $rax                  # Print as address (hex with symbol lookup)

# Register shortcuts:
p/x $pc                   # Program counter (rip on x86-64)
p/x $sp                   # Stack pointer (rsp)
p/x $fp                   # Frame pointer (rbp)

# Flag register:
p/x $eflags               # 32-bit EFLAGS (lower 32 bits of RFLAGS)
# Common flag bits:
# CF (bit 0): Carry flag
# PF (bit 2): Parity flag
# ZF (bit 6): Zero flag
# SF (bit 7): Sign flag
# OF (bit 11): Overflow flag

# Decode EFLAGS:
p ($eflags & 0x40) != 0   # Is ZF set? (1 = yes)

Memory Examination

The x command is the most versatile memory inspector. Format: x/NFU ADDRESS

Letter Meaning Options
N Count Any positive integer
F Format x(hex), d(decimal), u(unsigned), o(octal), t(binary), a(address), c(char), s(string), i(instruction), f(float)
U Unit size b(byte), h(halfword/2B), w(word/4B), g(giant/8B) 
# Stack examination:
x/10gx $rsp               # 10 giant words (8 bytes) in hex at rsp
x/20wx $rsp               # 20 words (4 bytes) in hex at rsp
x/40bx $rsp               # 40 bytes in hex at rsp
x/10i $rip                # 10 instructions at rip

# Mixed:
x/8gx $rbp-0x40           # 8 giant words at rbp-0x40
x/s $rdi                  # Null-terminated string at address in rdi
x/32cb $rdi               # 32 characters in byte at rdi

# Disassemble memory:
x/20i main                # 20 instructions starting at main
x/5i $rip                 # 5 instructions starting at current rip
x/10i *0x401000           # 10 instructions at address 0x401000

# Print with GDB variables:
set $ptr = $rdi + 0x10
x/4gx $ptr                # Examine at computed address

Disassembly

# Disassemble a function:
disassemble main           # Disassemble main (alias: disas main)
disassemble /m main        # Mixed source + assembly
disassemble /r main        # Raw opcodes + assembly
disassemble /s main        # Source lines interleaved

# Disassemble address range:
disassemble 0x401000, 0x401050
disassemble 0x401000, +100 # From address, +100 bytes

# Disassemble current function:
disassemble $rip, $rip+200

# Set disassembly flavor:
set disassembly-flavor intel       # Intel syntax: mov eax, [rbp-4]
set disassembly-flavor att          # AT&T syntax: mov -4(%rbp), %eax
# Intel is more readable for reverse engineering.

# Show current flavor:
show disassembly-flavor

# Disassembly output format (AT&T vs Intel):
# AT&T:
#   mov    -0x4(%rbp),%eax
#   add    $0x1,%eax
#   cmp    $0xa,%eax
# Intel:
#   mov    eax, DWORD PTR [rbp-0x4]
#   add    eax, 0x1
#   cmp    eax, 0xa

# Display next N instructions (like visual disassembly):
display/10i $rip           # Show 10 instructions after each step
undisplay 1                # Remove display #1

Modifying Execution

# Modify registers:
set $rax = 42              # Change rax to 42
set $rip = main            # Reset to main
set $rsp = $rsp - 8        # Adjust stack
set $eflags = $eflags | 0x40  # Set ZF

# Modify memory:
set {int}0x601040 = 99     # Write 4-byte int to address
set {char[8]}0x601050 = "PATCHED"  # Write string
set {long}($rsp) = 0x41414141     # Write to stack
set {unsigned char}0x401000 = 0x90  # Write single byte (0x90 = NOP)

# Modify variables:
set var counter = 0        # Set local variable
set var g_config.key[0] = 0x00  # Set array element

# Jump execution:
jump *0x401100             # Resume execution at address (no return)
jump main                  # Jump to function
# WARNING: jump does not adjust stack. Use with caution.

# Force return:
return                     # Return from current function immediately
return 42                  # Return with value 42 in $rax

# Modify control flow with breakpoint commands:
break check_license
commands
  set $rax = 1             # Force license check to return true
  continue
end

# Patch a conditional jump:
# Original: je 0x401080     (opcode: 74 XX)
# Patched:  jmp 0x401080    (opcode: EB XX)
set {char}0x401060 = 0xEB  # Change JE to JMP (unconditional)

Variables and Expressions

# GDB convenience variables ($ prefix = user-defined, $name = GDB-managed):
set $myvar = 0x41414141

# Built-in convenience variables:
p $pc                      # Program counter (rip)
p $sp                      # Stack pointer (rsp)

p $_exitcode               # Last exit code
p $_thread                 # Current thread number

p $_sdata                  # Data address for signal

# Expression evaluation:
p/x $rdi + 0x10            # Register arithmetic

Watchpoints

Watchpoints break when a memory expression changes. They use hardware debug registers and are limited but powerful. 

# Watch a variable:
watch counter              # Break when counter is written
watch *0x601050            # Watch memory at fixed address
watch my_struct.field      # Watch struct member
watch -l *0x601050         # Watch location (entire object at address)

# Read watchpoint (breaks on read):
rwatch *0x601050            # Break when read (hardware-assisted)

# Access watchpoint (breaks on read OR write):
awatch *0x601050            # Break on any access

# Conditional watchpoint:
watch len if len > 1000    # Only break when value exceeds 1000

# Info and management:
info watchpoints            # List watchpoints
info breakpoints            # Watchpoints appear in breakpoint list
delete 5                    # Delete watchpoint #5

# Watchpoint mechanics:
# GDB single-steps the program, checking the watched value after each
# instruction. This is SLOW for software watchpoints.
# Hardware watchpoints (via DR0-DR3) are fast — CPU traps on access.
# Only 4 hardware watchpoints can be active simultaneously.
# GDB falls back to software watchpoints when hardware registers are exhausted.

Dynamic Analysis

GDB can extract runtime information that static analysis cannot:

# 1. Find dynamically resolved functions:
break _dl_runtime_resolve
# Breaks whenever the dynamic linker resolves a lazy binding.
# At this break, you can see which function is being resolved.
# After stepping through _dl_runtime_resolve, $rax = resolved function address.

# 2. Hook PLT entries:
break *0x401030              # Address of puts@plt
# When hit, $rdi = string pointer, you can x/s $rdi

# 3. Break on indirect calls:
# call rax — at this instruction, you can print rax to see which function
break *0x401234
# Then: p/x $rax  (shows the resolved function address)
#      info symbol $rax  (shows symbol name if available)

# 4. Monitor heap allocations:
catch syscall brk
catch syscall mmap
# Check $rax for return (allocated address or MAP_FAILED)

# 5. Track file operations:
catch syscall open
catch syscall openat
# $rdi = filename pointer -> x/s $rdi

# 6. Dump decrypted data at runtime:
break *0x401200              # Break AFTER decryption loop
set logging file /tmp/decrypted.hex
set logging on
x/100bx $rdi                 # Dump decrypted buffer
set logging off

GDB Python API

GDB embeds a Python interpreter. The API provides programmatic control over breakpoints, frames, symbols, and memory. 

# ~/.gdbinit or sourced from file:
python
import gdb
import struct

class DumpRegsBreakpoint(gdb.Breakpoint):
    """Breakpoint that dumps registers and continues."""
    def __init__(self, spec):
        super().__init__(spec, gdb.BP_BREAKPOINT)
        self.silent = True

    def stop(self):
        rip = int(gdb.parse_and_eval("$rip"))
        rax = int(gdb.parse_and_eval("$rax"))
        rdi = int(gdb.parse_and_eval("$rdi"))
        rsi = int(gdb.parse_and_eval("$rsi"))
        rdx = int(gdb.parse_and_eval("$rdx"))
        print(f"[*] 0x{rip:x}: rax=0x{rax:x} rdi=0x{rdi:x} "
              f"rsi=0x{rsi:x} rdx=0x{rdx:x}")
        return False  # Don't stop — continue automatically

class LogArgsBreakpoint(gdb.Breakpoint):
    """Log function arguments to file."""
    def __init__(self, spec, logfile="/tmp/gdb-args.log"):
        super().__init__(spec, gdb.BP_BREAKPOINT, internal=True)
        self.silent = True
        self.log = open(logfile, "a")
        self.count = 0

    def stop(self):
        self.count += 1
        frame = gdb.selected_frame()
        rip = int(frame.pc())
        func = gdb.execute(f"info symbol {rip}", to_string=True).strip()

        # Read up to 6 integer arguments
        rdi = int(frame.read_register("rdi"))
        rsi = int(frame.read_register("rsi"))
        rdx = int(frame.read_register("rdx"))
        rcx = int(frame.read_register("rcx"))
        r8  = int(frame.read_register("r8"))
        r9  = int(frame.read_register("r9"))

        self.log.write(f"[{self.count}] {func}: "
                       f"rdi=0x{rdi:x} rsi=0x{rsi:x} rdx=0x{rdx:x} "
                       f"rcx=0x{rcx:x} r8=0x{r8:x} r9=0x{r9:x}\n")
        self.log.flush()
        return False  # Continue

    def delete(self):
        self.log.close()
        super().delete()

# Usage:
# DumpRegsBreakpoint("*0x401200")
# LogArgsBreakpoint("decrypt_string")
end

Common Debugging Patterns

# Pattern: Identify which function an indirect call targets
break *0x401234            # break on "call rax"
run
p/x $rax                   # print target address
info symbol $rax           # get symbol name
# Output: puts in section .text of /lib/libc.so.6

# Pattern: Decode XOR-encrypted string at runtime
break *0x401300            # after XOR loop
run
set $start = $rdi           # buffer pointer
set $len = $rsi             # buffer length
dump binary memory /tmp/decoded.bin $start ($start + $len)
shell xxd /tmp/decoded.bin

# Pattern: Trace all writes to a specific memory region
# Set watchpoint on memory (4-byte granularity, hardware):
watch *((int*)0x601000)
continue
# Each time the watchpoint fires, backtrace shows who wrote it.

# Pattern: Find where a value comes from (taint-like)
# Reverse execution with record/replay:
record full                # Start recording
continue                   # Run to point of interest
reverse-stepi              # Step backwards
reverse-continue           # Run backwards

# Pattern: Dump entire memory mapping at known address
info proc mappings         # Get base address of mapping
dump binary memory /tmp/dump.bin 0x7f0000000000 0x7f0000010000

# Pattern: Monitor all exec'd programs
catch exec
run
# Each exec() triggers a break.
# Useful: malware that runs secondary payloads.

Challenge

Write a Go tool that performs the three core GDB operations - break, step, and examine - without GDB. Use the ptrace system call to launch a target, stop it at the first instruction, read the registers, single-step 16 instructions, and print the opcode bytes at RIP before each step. Compare the trace with gdb -ex starti -ex 'x/16i $rip' ./target . 

package main

import (
	"fmt"
	"os"
	"os/exec"
	"syscall"
)

func regs(pid int) syscall.PtraceRegs {
	var r syscall.PtraceRegs
	if err := syscall.PtraceGetRegs(pid, &r); err != nil {
		fmt.Fprintln(os.Stderr, "getregs:", err)
		os.Exit(1)
	}
	return r
}

func main() {
	target := "./target"
	if len(os.Args) > 1 {
		target = os.Args[1]
	}

	cmd := exec.Command(target)
	cmd.Stdin = os.Stdin
	cmd.Stdout = os.Stdout
	cmd.Stderr = os.Stderr
	cmd.SysProcAttr = &syscall.SysProcAttr{Ptrace: true}

	if err := cmd.Start(); err != nil {
		fmt.Fprintln(os.Stderr, "start:", err)
		os.Exit(1)
	}

	pid := cmd.Process.Pid
	var status syscall.WaitStatus
	if _, err := syscall.Wait4(pid, &status, 0, nil); err != nil {
		fmt.Fprintln(os.Stderr, "wait:", err)
		os.Exit(1)
	}

	r := regs(pid)
	fmt.Printf("stopped at entry: rip=0x%016x rsp=0x%016x\n", r.Rip, r.Rsp)

	for i := 0; i < 16; i++ {
		code := make([]byte, 8)
		if _, err := syscall.PtracePeekData(pid, uintptr(r.Rip), code); err != nil {
			fmt.Fprintln(os.Stderr, "peek:", err)
			break
		}
		fmt.Printf("%2d  rip=0x%016x  % x\n", i, r.Rip, code)

		if err := syscall.PtraceSingleStep(pid); err != nil {
			fmt.Fprintln(os.Stderr, "step:", err)
			break
		}
		if _, err := syscall.Wait4(pid, &status, 0, nil); err != nil {
			fmt.Fprintln(os.Stderr, "wait:", err)
			break
		}
		r = regs(pid)
	}

	syscall.PtraceCont(pid, 0)
	cmd.Wait()
}

Build it against a tiny target. The tracer is the parent, so PTRACE_TRACEME needs no elevated privileges: 

cat > target.c <<'EOF'
int main(void) { return 0; }
EOF
gcc -o target target.c
go build -o minitrace minitrace.go
./minitrace ./target
