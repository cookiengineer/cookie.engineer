System Calls

The gateway between user space and kernel space - syscall mechanism, Linux syscall table, strace deep dive, raw syscall invocation, vDSO.

Overview

User programs cannot touch hardware, page tables, or kernel memory directly. To open a file, map memory, or send a packet they must cross the user/kernel boundary with a system call. This article explains the x86-64 syscall instruction, the kernel dispatch through the syscall table, the register argument convention, and the tools used to observe all of it. It also covers the vDSO, which serves some calls entirely in user space. By the end you can invoke a syscall directly and read a raw strace trace.

  • Processes - process fundamentals, /proc, fork/exec

The User/Kernel Boundary

Modern CPU s enforce a strict separation between user space and kernel space through protection rings. x86-64 uses ring 0 (kernel) and ring 3 (user). User programs cannot directly access hardware, modify page tables, or read kernel memory. To request kernel services - opening a file, allocating memory, sending a network packet - a program must cross the boundary via a system call.

What Happens During a System Call

Each CPU architecture has one instruction that triggers the privilege transition:

Architecture Instruction Syscall Number Reg Return Reg
x86-64 syscall rax rax
x86-32 int 0x80(legacy) /sysenter eax eax
ARM64 svc #0 x8 x0
ARM32 svc #0/swi #0 r7 r0
RISC-V ecall a7 a0

Step-by-step on x86-64

  1. User program calls libc wrapper (e.g., write() ).
  2. libc wrapper places the syscall number in rax , arguments in rdi, rsi, rdx, r10, r8, r9 , and executes syscall .
  3. 'syscall' instruction : CPU switches to ring 0, sets rcx = return address (saved rip ), r11 = saved rflags , loads rip from MSR_LSTAR (the kernel's syscall entry point address), loads cs / ss from MSR_STAR .
  4. Kernel entry ( entry_SYSCALL_64 ) saves registers, switches to kernel stack, calls the actual syscall handler via the sys_call_table .
  5. Syscall handler does the work: validates arguments, copies data between user/kernel memory ( copy_from_user / copy_to_user ), performs the operation.
  6. Return path restores registers, executes sysretq (or iretq in some cases) to return to ring 3.

Argument Passing Convention (x86-64)

Reg Purpose
rax Syscall number
rdi Argument 1
rsi Argument 2
rdx Argument 3
r10 Argument 4 (rcx is clobbered by syscall)
r8 Argument 5
r9 Argument 6
rax Return value (or -errno on error)
rcx Clobbered (saved RIP)
r11 Clobbered (saved RFLAGS)

Note: rcx and r11 are destroyed by the syscall instruction. Unlike the usual calling convention, r10 replaces rcx for the 4th argument. A maximum of 6 arguments can be passed in registers

Writing Raw Syscalls in C

The syscall() function from glibc allows calling any syscall by number without a dedicated wrapper: 

#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>
#include <string.h>

int main() {
    const char* msg = "Hello from raw syscall!\n";

    // Invoke write(1, msg, strlen(msg)) directly
    // syscall number 1 = SYS_write
    long ret = syscall(SYS_write, 1, msg, strlen(msg));

    if (ret < 0) {
        perror("syscall write");
        return 1;
    }

    printf("Bytes written: %ld\n", ret);

    // gettid() - no libc wrapper until glibc 2.30
    pid_t tid = syscall(SYS_gettid);
    printf("Thread ID: %d\n", tid);

    return 0;
}
						
gcc -o raw-syscall raw-syscall.c && ./raw-syscall

Why libc wrappers exist

  1. errno handling : The kernel returns a negative error code (e.g., -ENOENT). libc stores the positive value in errno and returns -1.
  2. Cancellation points : Functions like read() and write() are P OSI X cancellation points. libc adds pthread_testcancel() around them.
  3. Architecture abstraction : libc hides architecture differences - SYS_fork might not exist on all architectures (only clone ).
  4. Thread safety : libc manages per-thread errno correctly.

strace Deep Dive

strace is the single most important tool for understanding what a process actually does. It intercepts every syscall and prints the arguments and return value. 

# Basic usage
strace ls /tmp

# Follow child processes (fork + exec)
strace -f gcc -o hello hello.c

# Filter by syscall category
strace -e trace=file cat /etc/hostname
# Shows: open, openat, stat, read, write, close, etc.

strace -e trace=network curl https://example.com
# Shows: socket, connect, sendto, recvfrom, bind, listen, accept

strace -e trace=process bash -c 'ls | grep test'
# Shows: fork, execve, clone, wait4, exit

strace -e trace=memory ls
# Shows: brk, mmap, munmap, mprotect

strace -e trace=signal kill -HUP $$
# Shows: kill, rt_sigaction, rt_sigprocmask

# Summary: count and time each syscall
strace -c find /usr/share -name '*.so' 2>/dev/null
# Output:
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- ----------------
#  34.21    0.008123           3      2342           getdents64
#  28.91    0.006865           2      2342      2342 newfstatat
#  15.33    0.003640           1      2342           close
#   ...

# Attach to a running process
strace -p $(pidof nginx | cut -d' ' -f1)

# Timestamps
strace -t ls              # Wall clock time
strace -tt ls             # Microsecond precision
strace -T ls              # Syscall duration after return

# Write output to file
strace -o /tmp/trace.log -f python3 server.py

# Filter by syscall name (comma-separated)
strace -e open,openat,read,write,close vim /tmp/test.txt

# Show string arguments fully
strace -v -s 4096 cat /etc/hostname
# -s 4096: show up to 4096 bytes of string args (default: 32)

Common strace Patterns

# What files does this command open?
strace -e trace=file -e signal=none ls 2>&1 | grep -E '^open(at)?\('

# What network connections does this process make?
strace -e trace=network curl example.com 2>&1

# Child process tree - -ff: one file per child, -o prefix
strace -ff -o /tmp/strace/ bash -c 'ls; sleep 1'
ls /tmp/strace/  # One file per PID

# Show only failed syscalls (useful for debugging)
strace -e trace=file -Z ls /nope 2>&1
# -Z: suppress successful returns; only show errors

# Inject a fault (seccomp-filter style)
strace -e inject=openat:error=ENOENT cat /etc/hostname
# Makes every openat() return ENOENT - useful for testing error paths

# Trace only the first process, not children
strace -b execve ls  # Detach on exec

# Count signals received
strace -e trace=signal sleep 5 &
strace -p $! -e trace=signal
kill -HUP $!

System Call Tables in the Kernel

The kernel maintains the sys_call_table array, indexed by syscall number. You can examine it: 

# Find sys_call_table address
sudo cat /proc/kallsyms | grep sys_call_table
# ffffffff82000280 R sys_call_table

# List all available syscalls on this kernel
ausyscall --dump 2>/dev/null || cat /proc/kallsyms | grep -i 'sys_' | head -30
						
// Kernel-side: syscall table entry (from arch/x86/entry/syscalls/)
// Table entry 0 (SYS_read):
asmlinkage long sys_read(unsigned int fd, char __user *buf, size_t count);

// Kernel-side handler (simplified from fs/read_write.c):
SYSCALL_DEFINE3(read, unsigned int, fd, char __user *, buf, size_t, count)
{
    struct fd f = fdget_pos(fd);
    if (!f.file)
        return -EBADF;
    ssize_t ret = vfs_read(f.file, buf, count, &f.file->f_pos);
    fdput_pos(f);
    return ret;
}

vDSO - Virtual Dynamic Shared Object

Some syscalls (like gettimeofday , clock_gettime , time ) are so frequent that the overhead of syscall -> ring 0 -> ring 3 is unacceptable. The kernel solves this with the vDSO: a small shared library mapped into every process's address space that implements these functions entirely in user space, reading from a shared memory page updated by the kernel. 

# See the vDSO mapping
cat /proc/self/maps | grep vdso
# 7ffff7fcb000-7ffff7fcd000 r-xp ... [vdso]
# 7ffff7fcb000-7ffff7fcd000 r--p ... [vdso]  <- readable page with kernel-updated clock data

# Inspect the vDSO ELF
dd if=/proc/self/mem bs=1 skip=$((0x7ffff7fcb000)) count=$((0x2000)) 2>/dev/null | \
    xxd | head -20

# Get vDSO base address
python3 -c "
import ctypes, os
# Parse /proc/self/maps for [vdso] entry
with open('/proc/self/maps') as f:
    for line in f:
        if 'vdso' in line:
            print(line.strip())
"

How vDSO clock_gettime works

Normal path:          vDSO path:
────────────          ──────────
Application           Application
  │                     │
  ▼                     ▼
libc wrapper           libc wrapper
  │                     │
  ▼                     ▼
syscall instruction    vDSO function (user space!)
  │                     │
  ▼                     ▼  Reads kernel-updated
Ring 0 kernel        struct vdso_data from
  │                   shared read-only page
  ▼                     │
clock_gettime()         ▼
  │                   Return result
  ▼
Return result

No ring transition!  ~20-50x faster.
						
# Verify vDSO is being used
strace -e clock_gettime date 2>&1
# On modern glibc + kernel: no clock_gettime syscall appears
# (it's handled by vDSO)

# The vDSO is mapped automatically, so force the kernel path with syscall(2).
# 228 is SYS_clock_gettime on x86-64.
strace -e clock_gettime python3 -c "import ctypes; libc=ctypes.CDLL('libc.so.6'); ts=ctypes.c_long(); libc.syscall(228, 0, ctypes.byref(ts))"

Signal Handling and Syscalls

When a signal arrives while a process is blocked in a slow syscall (like read() on a socket with no data), the kernel can interrupt the syscall. The behavior depends on whether SA_RESTART is set in the signal handler: 

#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

void handler(int sig) {
    printf("Signal received\n");
}

int main() {
    // Without SA_RESTART: read() returns EINTR
    signal(SIGALRM, handler);
    alarm(2);  // Send SIGALRM in 2 seconds

    char buf[1024];
    ssize_t n = read(STDIN_FILENO, buf, sizeof(buf));
    printf("read returned: %zd, errno: %s\n", n,
           n == -1 ? strerror(errno) : "none");
    return 0;
}
						
gcc -o sig-syscall sig-syscall.c && ./sig-syscall
# Wait 2 seconds - read() returns -1 with EINTR

syscall vs int 0x80 - Historical Note

On x86-32, the original syscall mechanism was int $0x80 (software interrupt 128). This is slow because the CPU must go through the full interrupt dispatch path. AMD introduced sysenter / sysexit (Intel later adopted) which are much faster. On x86-64, syscall / sysretq replaced both. 

x86-32 (legacy):   int $0x80        <- slow: interrupt dispatch
x86-32 (fast):     sysenter/sysexit <- fast: direct entry
x86-64:            syscall/sysretq  <- fast: direct entry, official method

The kernel still supports int $0x80 on x86-64 for backward compatibility with 32-bit binaries, but it should never be used in new 64-bit code.

Verification Checklist

# 1. Find your architecture's syscall table
ls /usr/include/asm/unistd*.h

# 2. Trace the syscalls of a simple command
strace -c ls / 2>&1 | tail -20

# 3. Count syscall invocations per type for a program
strace -c find /usr/share -maxdepth 2 -type d 2>/dev/null

# 4. Observe the syscall instruction in a disassembled binary
objdump -d /usr/bin/ls | grep -A5 'syscall' | head -20

# 5. Count syscalls system-wide for one second (requires bpftrace)
sudo bpftrace -e 'tracepoint:raw_syscalls:sys_enter { @[comm] = count(); } interval:s:1 { exit(); }'

# 6. Verify vDSO presence
cat /proc/self/maps | grep vdso

# 7. List syscall numbers available via syscall()
echo '#include <sys/syscall.h>' | gcc -E -dM - | grep 'SYS_' | head -20

# 8. Find which syscalls a binary uses (static analysis)
objdump -d /usr/bin/ls | grep -E 'call.*<.*@plt>' | grep -v 'DYNAMIC' | head -20
# Dynamic-linked: look at PLT entries
# Static: look for 'syscall' instructions directly

# 9. Count the syscalls a simple command makes
strace -e trace=all echo "test" 2>&1 | wc -l

Challenge

Call the kernel without a libc wrapper. Write a Go program that invokes write and getpid through syscall.Syscall , then trace it with strace -e write,getpid and confirm the calls reach the kernel directly. Compare the trace with the same program calling fmt.Println , which also ends in write but only after the runtime sets up its buffers. 

package main

import (
	"fmt"
	"syscall"
	"unsafe"
)

func main() {
	msg := []byte("hello from a raw syscall\n")

	ret, _, errno := syscall.Syscall(
		syscall.SYS_WRITE,
		uintptr(1),
		uintptr(unsafe.Pointer(&msg[0])),
		uintptr(len(msg)),
	)
	if errno != 0 {
		fmt.Println("write failed:", errno)
		return
	}
	fmt.Printf("write returned %d\n", ret)

	pid, _, _ := syscall.Syscall(syscall.SYS_GETPID, 0, 0, 0)
	fmt.Printf("getpid returned %d\n", pid)
}
						
go build -o rawsyscall rawsyscall.go
strace -e write,getpid ./rawsyscall

Extend the program with SYS_CLOCK_GETTIME and confirm that the trace now contains a clock_gettime call that the vDSO normally hides.
