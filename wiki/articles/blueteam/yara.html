YARA

Creating detection rules for malware classification and file-based IOC matching.

Overview

YARA is a pattern-matching engine for identifying and classifying files based on textual or binary patterns. It is one of the most widely used tools for malware classification, and almost every incident response toolkit ships YARA rules.

A YARA rule describes what a file looks like: strings it contains, binary patterns at specific offsets, characteristics of its executable headers, and logical relationships between these elements. When a rule matches, you know the file belongs to a specific malware family or shares an indicator with known malicious software.

Required Reading

  • ELF - executable header structure, sections, segments, dynamic linking
  • PE - PE32/PE32+ headers, imports, exports, resources, relocation

Rule Anatomy

rule CobaltStrike_Beacon_Shellcode
{
    meta:
        description = "Detects Cobalt Strike beacon shellcode in memory or PE"
        author = "You"
        date = "2026-06-26"
        reference = "https://attack.mitre.org/software/S0154/"
        hash = "d41d8cd98f00b204e9800998ecf8427e"
        severity = "HIGH"

    strings:
        $cmd_a = "sleep" ascii wide nocase
        $cmd_b = "spawn" ascii wide nocase
        $cmd_c = "inject" ascii wide nocase

        $enc_a = { 6A 00 68 [4] FF 15 [4] 85 C0 }
        $enc_b = { 55 8B EC 51 8B 45 [1-2] 83 C0 }

        $url_re = /https?:\/\/([a-z0-9-]+\.)+[a-z]{2,}\/[a-zA-Z0-9\/]{4,12}/ nocase

    condition:
        3 of ($cmd_*) and any of ($enc_*) and $url_re and filesize < 5MB
}

Meta Section

Arbitrary key-value metadata. It is not used in matching logic but is critical for documentation, sharing, and IOC management. Common fields: description , author , date , reference , hash , severity , malware_family , TLP .

Strings Section

Defines named patterns to search for. Each string identifier starts with $ . Text strings match substrings, hex strings match byte sequences, and regex strings match regular expressions.

Condition Section

A boolean expression determining when the rule matches. It can reference strings, filesize , entrypoint , PE or ELF headers, imported and exported functions, and results from loaded modules.

String Types

Text Strings

$text_ascii = "malware.exe"
$text_wide  = "malware.exe" wide        // UTF-16LE (Windows wide strings)
$text_both  = "malware.exe" wide ascii  // match both encodings
$text_case  = "MALWARE" nocase          // case insensitive
$text_full  = "MALWARE" fullword        // bounded by non-alphanumeric chars
$text_xor   = "malware" xor(0x01-0xff)  // XOR-encoded with any single-byte key

Hex Strings

$hex_basic = { 6A 00 68 ?? ?? ?? ?? FF 15 }       // ?? = wildcard byte
$hex_nib   = { 55 8B EC 5? 8B 45 }                 // 5? = wildcard nibble (0x50-0x5F)
$hex_range = { 55 8B EC 51 8B 45 [1-4] 83 C0 }    // [1-4] = jump of 1 to 4 bytes
$hex_jump  = { 6A 00 68 [4-] FF 15 }               // [4-] = jump of 4 or more bytes
$hex_alt   = { 6A ( 00 | 01 ) 68 }                  // alternatives: 00 or 01
$hex_opt   = { 55 8B EC [0-1] 51 8B 45 }            // [0-1] = optional byte
$hex_cnt   = { 55 [3] 51 }                          // exactly 3 bytes wildcard
$hex_alt2  = { 55 8B EC ( 51 | 52 | 53 ) }          // alternative byte values

Regex Strings

$re_domain = /[a-z0-9-]{4,63}\.(xyz|top|tk|ml|ga|cf)/ nocase
$re_ip     = /\b[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\b/
$re_b64    = /[A-Za-z0-9+\/=]{40,}/
$re_c2_url = /https?:\/\/([a-z0-9-]+\.)+[a-z]{2,}\/[a-zA-Z0-9\/]{8,64}/

Condition Operators

condition:
    // String presence
    $str1 and $str2
    $str1 or $str2
    not $str1

    // Count matches
    #str1 > 5                  // string appears more than 5 times
    @str1 < 0x1000             // first occurrence at offset < 0x1000
    !str1 at 0x400             // string at exact offset 0x400
    $str1 in (0x400..0x800)    // string within offset range

    // Match N of M strings
    3 of ($a, $b, $c, $d)      // at least 3 of these 4
    2 of ($cmd_*)               // at least 2 of strings starting with "$cmd_"
    all of them                 // all strings in the rule
    any of them                 // any string in the rule

    // File properties
    filesize > 100KB and filesize < 5MB
    uint16(0) == 0x5A4D        // MZ header (PE/DOS)
    uint32(0) == 0x464C457F    // ELF magic (0x7F 'E' 'L' 'F')
    uint16be(0) == 0x4D5A      // MZ header (big-endian check)

    // Iteration (loop over occurrences of a string)
    for all i in (1..#a) : (@a[i] >= 0x1000)
    for any of ($a, $b) : ($ at 0x400..0x800)

    // Combination
    ($str1 and $str2) or ($str3 and filesize < 1MB)

PE Module

The pe module exposes parsed PE header fields without needing raw offset seeks. 

import "pe"
import "math"

rule Suspicious_PE_Characteristics
{
    condition:
        // No digital signature - common in malware
        pe.number_of_signatures == 0

        // Unusual section names - packed or custom loader
        and for any i in (0..pe.number_of_sections - 1) : (
            pe.sections[i].name == ".upx0" or
            pe.sections[i].name == ".vmp0" or
            pe.sections[i].name == ".petite"
        )

        // High entropy in first section (packed code)
        and math.entropy(pe.sections[0].raw_data_offset, pe.sections[0].raw_data_size) > 7.0

        // Suspicious imports
        and pe.imports("kernel32.dll", "VirtualAlloc")
        and pe.imports("kernel32.dll", "WriteProcessMemory")
        and pe.imports("kernel32.dll", "CreateRemoteThread")
}

Common PE module fields:

pe.is_32bit()           // true if PE32
pe.is_64bit()           // true if PE64
pe.is_dll()             // true if DLL
pe.number_of_sections   // section count
pe.entry_point          // raw (file) entry point offset
pe.machine              // IMAGE_FILE_MACHINE_*
pe.subsystem            // IMAGE_SUBSYSTEM_*
pe.timestamp            // PE compilation timestamp (epoch)

pe.sections[i].name
pe.sections[i].raw_data_offset
pe.sections[i].raw_data_size
pe.sections[i].virtual_size
pe.sections[i].characteristics  // section flags

math.entropy(offset, size)      // Shannon entropy, bits per byte

pe.imports(dll, function)       // count of imports from dll->function
pe.exports(function)            // count of exports by function name

pe.imphash()                    // import hash (ignoring ordinal order)
pe.rich_signature               // raw rich signature data

pe.data_directories             // array of IMAGE_DATA_DIRECTORY

ELF Module

import "elf"

rule Suspicious_ELF_Binary
{
    condition:
        // Statically linked - common in malware to avoid dependency issues
        elf.type == elf.ET_EXEC

        // No dynamic symbol table - stripped binary
        and not elf.dynamic_section_entries

        // Write+Execute segment - shellcode, JIT, or unpacking stub
        and for any i in (0..elf.number_of_segments - 1) : (
            elf.segments[i].flags & elf.PF_W and
            elf.segments[i].flags & elf.PF_X
        )

        // Suspicious segment offset (packed binary)
        and elf.entry_point > elf.segments[elf.number_of_segments - 1].offset
}

Scanning with YARA

# Install on ArchLinux
sudo pacman -S yara

# Scan a single file
yara my_rule.yar suspicious.exe

# Scan a directory recursively
yara -r my_rule.yar /mnt/forensic_image/

# Scan with multiple rule files
yara rules/malware/*.yar /path/to/scan/

# Compile rules for faster scanning (large scans)
yarac my_rule.yar my_rule.compiled
yara -C my_rule.compiled /path/to/scan/

# Print matching strings and their offsets
yara -s my_rule.yar sample.exe

# Output in JSON for automation
yara -j my_rule.yar sample.exe

# Timeout after N seconds per file (avoid hanging on large files)
yara -a 30 my_rule.yar /path/to/scan/

# Scan process memory (Linux)
yara my_rule.yar /proc/1234/mem

# Recursive scan, skip files larger than 100MB
yara -r --max-filesize=100MB my_rule.yar /path/

yarGen Rule Generation

yarGen generates YARA rules from malware samples by extracting unique strings and selecting those with low false positive probability against a "goodware" database. 

# Install
git clone https://github.com/Neo23x0/yarGen.git
cd yarGen
pip install -r requirements.txt

# Download a goodware string database
python yarGen.py --update

# Generate a rule from a malware sample
python yarGen.py -m /path/to/malware_sample.exe -o output.yar

# Generate rules from a directory of samples (one rule per family)
python yarGen.py -m /path/to/malware_samples/ -o output_rules/

# Exclude known strings to reduce false positives
python yarGen.py -m sample.exe --excludegood -o output.yar

Treat yarGen-generated rules as a starting point. Always review and refine them by hand, because the tool may select strings shared with benign software.

Rules for Malware Families

Web Shell - PHP

rule Webshell_PHP_Generic
{
    meta:
        description = "Detects common PHP webshell patterns"
        severity = "HIGH"

    strings:
        $func_eval    = "eval(" ascii nocase
        $func_assert  = "assert(" ascii nocase
        $func_system  = "system(" ascii nocase
        $func_exec    = "exec(" ascii nocase
        $func_passthru = "passthru(" ascii nocase
        $func_shell   = "shell_exec(" ascii nocase
        $func_popen   = "popen(" ascii nocase

        $var_request  = "$_REQUEST" ascii nocase
        $var_post     = "$_POST" ascii nocase
        $var_get      = "$_GET" ascii nocase

        $b64_decode   = "base64_decode" ascii nocase
        $gz_inflate   = "gz" ascii nocase

    condition:
        (any of ($func_*) and any of ($var_*))
        or ($b64_decode and $gz_inflate)
        or (filesize < 5KB and #func_eval > 0 and #var_request > 0)
}

Ransomware Common Patterns

rule Ransomware_Generic_File_Operations
{
    meta:
        description = "Detects generic ransomware file operation patterns"

    strings:
        $crypto_api_a = "CryptAcquireContext" ascii wide
        $crypto_api_b = "CryptEncrypt" ascii wide
        $crypto_api_c = "CryptGenRandom" ascii wide

        $file_enum_a  = "FindFirstFile" ascii wide
        $file_enum_b  = "FindNextFile" ascii wide

        $shadow_a     = "vssadmin" ascii wide nocase

        $ext_rgx = /\.(encrypted|locked|crypto|enc|locky|wncry|crypt|zzz)\x00/i

    condition:
        (2 of ($crypto_api_*) and 2 of ($file_enum_*))
        or (any of ($crypto_api_*) and $shadow_a)
        or (any of ($crypto_api_*) and $ext_rgx)
}

C2 Beacon Detection

rule C2_Beacon_HTTP_Pattern
{
    meta:
        description = "Detects HTTP-based C2 beacon patterns in binaries"

    strings:
        $useragent_a = "Mozilla/5.0" ascii wide

        $sleep_pattern = { B8 [4] 50 E8 [4] 83 C4 04 }  // mov eax, ms; push; call sleep

        $b64_re = /[A-Za-z0-9+\/=]{100,}/  // long base64 strings

        $uri_template = "/api/v1/%s/%s/%s" ascii wide

    condition:
        $useragent_a
        and (2 of ($sleep_pattern, $b64_re, $uri_template))
        and filesize < 2MB
}

Performance Optimization

  1. Anchor strings : Prefer strings at fixed, known offsets (like PE entry point code) over generic strings that may match anywhere.
  1. Avoid broad regex : /.*/ and unanchored regex are pathologically slow. Always include specific characters or length bounds.
  1. Use 'filesize' as first condition : YARA evaluates conditions left-to-right with short-circuit. filesize < 5MB and <expensive check> avoids running expensive checks on large files.
  1. Order strings by rarity : Place the least common string first in the condition. YARA stops scanning a file as soon as a condition resolves.
  1. Limit hex jumps : [4-] with no upper bound forces the scanner to search the entire remainder of the file. Prefer bounded jumps: [4-256] .
  1. Combine conditions with all of/any of : YARA can optimize these better than explicit and / or chains.
  1. Pre-compile rules : yarac pre-processes strings into an optimized Aho-Corasick automaton. Always compile rules for production scanning.
# Compile ruleset for production
yarac rules/production/*.yar production_rules.compiled

# Fast production scan
yara -C production_rules.compiled -r --fail-on-warnings /scan/target/

YARA Integration

osquery

Endpoint visibility with YARA support: 

-- Scan every running process memory with a YARA rule
SELECT pid, name, path
FROM processes
WHERE pid IN (
    SELECT pid FROM yara
    WHERE path = '/etc/osquery/yara/cobalt_strike.yar'
      AND count > 0
);

-- Scan specific directory for malware
SELECT path, matches
FROM yara
WHERE path LIKE '/var/www/html/%%'
  AND sigfile = '/etc/osquery/yara/webshells.yar'
  AND count > 0;

ClamAV

ClamAV can load YARA rules natively when it is built with YARA support. Place the .yar files in the ClamAV database directory and restart the daemon: 

# Copy YARA rules into the ClamAV database directory
sudo cp rule.yar /var/lib/clamav/

# Restart so ClamAV compiles the new signatures
sudo systemctl restart clamav-daemon

Testing YARA Rules

# Create positive test (malicious sample)
echo '<?php eval($_POST["cmd"]); ?>' > /tmp/test_webshell.php

# Create negative test (benign file)
echo '<?php echo "Hello World"; ?>' > /tmp/test_benign.php

# Test: positive should match, negative should not
yara rules/webshell/php_generic.yar /tmp/test_webshell.php
# Expected output: Webshell_PHP_Generic /tmp/test_webshell.php

yara rules/webshell/php_generic.yar /tmp/test_benign.php
# Expected output: (nothing - no match)

# Automated test script
#!/bin/bash
echo "=== Running YARA rule tests ==="
PASS=0; FAIL=0
for rule in rules/**/*.yar; do
    baserule=$(basename "$rule")
    testdir="tests/${baserule%.yar}"

    if [ -d "$testdir/positive" ]; then
        for sample in "$testdir/positive/"*; do
            if yara "$rule" "$sample" > /dev/null; then
                ((PASS++)); echo "PASS: $baserule matches $sample"
            else
                ((FAIL++)); echo "FAIL: $baserule does NOT match $sample (positive test)"
            fi
        done
    fi

    if [ -d "$testdir/negative" ]; then
        for sample in "$testdir/negative/"*; do
            if yara "$rule" "$sample" > /dev/null; then
                ((FAIL++)); echo "FAIL: $baserule MATCHES $sample (false positive)"
            else
                ((PASS++)); echo "PASS: $baserule correctly ignores $sample"
            fi
        done
    fi
done
echo "Results: $PASS passed, $FAIL failed"

Challenge

Build the container and work through the bundled exercises. It ships with template rules, a malicious PHP webshell, a benign contact form, and a generated ransomware sample so you can write a rule, scan it, and validate that it does not fire on clean files.

yara.Containerfile

podman build -t yara-lab -f yara.Containerfile .
podman run -it --rm yara-lab

Inside the container:

  • /opt/exercise/samples/ - malicious and benign test files
  • /opt/exercise/rules/ - template and pre-built rules
  • /opt/exercise/run_exercises.sh - automated validation script
