Device Drivers

Linux device model internals - character/block/network drivers, DMA, IOMMU, mmap, ioctl, power management, driver vulnerabilities, and writing a character driver from scratch.

Overview

Drivers are the kernel's contract with hardware: they register with the device model, expose a file_operations table, and move data across the user/kernel boundary with DMA and copy_*_user . This article builds that picture from the bus/device/driver tree down to a working character driver, then audits the classic bug classes (bounds checks, races, pointer leaks, unchecked ioctl sizes). After reading it you can read an unfamiliar driver and spot its attack surface.

Required Reading

  • Kernel Architecture - kernel layout, init sequence, kbuild, sources
  • Interrupts - IRQ handling, top/bottom halves, softirqs, workqueues
  • Kernel Modules - module loading, signing, parameters

The Linux Device Model

The Linux device model is neither a simple list of devices nor a flat namespace. It is a tree

  • a directed acyclic graph rooted at the platform bus - where every device, driver, bus,
class, and firmware node is represented by a kobject embedded in a larger struct. Understanding this model is mandatory before writing or auditing any driver. 

sysfs                  Core Data Structures           Physical World
─────                  ────────────────────           ──────────────
/sys/
├── bus/
│   ├── pci/
│   │   ├── devices/   struct pci_dev                PCIe endpoint
│   │   └── drivers/   struct pci_driver             Driver loaded
│   ├── usb/
│   │   ├── devices/   struct usb_device             USB peripheral
│   │   └── drivers/   struct usb_driver             USB driver
│   └── platform/
│       ├── devices/   struct platform_device        SoC peripheral
│       └── drivers/   struct platform_driver        Platform driver
├── class/
│   ├── net/           struct net_device             Network interface
│   ├── tty/           struct tty_driver              Terminal driver
│   ├── block/         struct gendisk                 Block device
│   └── input/         struct input_dev              HID device
├── devices/
│   └── pci0000:00/    struct device (root)
│       └── 0000:00:01.0/  struct pci_dev           PCI function
└── kernel/
    └── debug/         debugfs entries               Dynamic debugging

Three foundational structures form the device model:

// include/linux/device.h

struct device {
    struct kobject      kobj;           // sysfs object
    struct device      *parent;         // parent in device hierarchy
    struct device_node  *of_node;       // Device Tree node (ARM, RISC-V)
    struct fwnode_handle *fwnode;       // Firmware node (ACPI + DT unified)
    void               *driver_data;    // Private driver data
    struct bus_type     *bus;           // Bus this device lives on
    struct device_driver *driver;       // Bound driver
    const char         *init_name;      // Initial name
    struct dev_pm_info   power;         // Power management state
    struct dev_links_info links;        // Device links (supplier/consumer)
    void               *platform_data;  // Platform-specific data
    u64                *dma_mask;       // DMA addressable range
    u64                 coherent_dma_mask;
    dev_t               devt;           // Device number (major:minor)
    struct class        *class;         // Device class
    // ... many more fields
};

struct device_driver {
    const char   *name;
    struct bus_type *bus;
    struct module *owner;
    int (*probe)(struct device *dev);
    void (*remove)(struct device *dev);
    void (*shutdown)(struct device *dev);
    int (*suspend)(struct device *dev, pm_message_t state);
    int (*resume)(struct device *dev);
    const struct dev_pm_ops *pm;
    // ...
};

struct bus_type {
    const char *name;
    int (*match)(struct device *dev, struct device_driver *drv);
    int (*probe)(struct device *dev);
    struct subsys_private *p;   // Internal: linked lists of devices/drivers
    const struct dev_pm_ops *pm;
    // ...
};

Device-driver binding follows a match-then-probe sequence. When a device is registered to a bus, the bus iterates its driver list calling match() . When a driver is registered, it iterates the device list. A successful match calls driver->probe() : 

Device Registration         Driver Registration
───────────────────         ───────────────────
device_register()           driver_register()
    │                             │
    ▼                             ▼
bus_add_device()             bus_add_driver()
    │                             │
    ▼                             ▼
bus_probe_device()           driver_attach()
    │                             │
    ▼                             ▼
device_initial_probe()       __driver_attach()
    │                             │
    └────► bus_for_each_drv()     └────► driver_match_device()
               │                            │
               ▼                            ▼
           drv->match(dev, drv)        bus->match(dev, drv)
               │                            │
               ▼ (match)                    ▼ (match)
           really_probe(dev, drv)      really_probe(dev, drv)
               │                            │
               ▼                            ▼
           drv->probe(dev)             drv->probe(dev)
               │                            │
               ▼                            ▼
           driver_bound(dev)           driver_bound(dev)
               │                            │
               ▼                            ▼
           sysfs: create symlink       sysfs: create symlink
           devices/.../driver →        devices/.../driver →
           drivers/...                  drivers/...

Device Tree and Firmware Enumeration

On x86, the firmware (ACPI) describes the platform. On ARM, RISC-V, and embedded systems, the Device Tree Blob (DTB) serves the same role. The kernel unifies both behind struct fwnode_handle .

─────────                          ────────────────

     │                                   │
     ▼                                   ▼

     │                                   │
     ▼                                   ▼
acpi_bus_scan()                     of_platform_populate()
     │                                   │
     ▼                                   ▼
struct acpi_device                  struct platform_device
     │                                   │
     └──────────+────────────────────────┘
                ▼
     struct device (with fwnode pointer)

Character Devices

Character devices provide byte-stream access: serial ports, /dev/null , /dev/urandom , terminal drivers, i2c devices. They are identified by a dev_t (major:minor) and implement struct file_operations .

};

Character Driver Example

// echo_driver.c — a /dev/echo that echoes back everything written to it
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>
#include <linux/slab.h>

#define DEVICE_NAME "echo"
#define CLASS_NAME  "echo"
#define BUF_SIZE    4096

static dev_t        echo_dev;       // Device number
static struct class *echo_class;
static struct cdev  echo_cdev;
static char        *echo_buf;

static int echo_open(struct inode *inodep, struct file *filp)
{
    pr_info("echo: device opened\n");
    return 0;
}

static int echo_release(struct inode *inodep, struct file *filp)
{
    pr_info("echo: device closed\n");
    return 0;
}

static ssize_t echo_read(struct file *filp, char __user *buf,
                         size_t len, loff_t *off)
{
    size_t remaining = BUF_SIZE - *off;
    size_t to_copy = min(len, remaining);

    if (to_copy == 0)
        return 0;  // EOF

    if (copy_to_user(buf, echo_buf + *off, to_copy))
        return -EFAULT;

    *off += to_copy;
    return to_copy;
}

static ssize_t echo_write(struct file *filp, const char __user *buf,
                          size_t len, loff_t *off)
{
    size_t to_copy = min(len, (size_t)BUF_SIZE);

    if (copy_from_user(echo_buf, buf, to_copy))
        return -EFAULT;

    pr_info("echo: received %zu bytes: '%s'\n", to_copy, echo_buf);
    *off = to_copy;
    return to_copy;
}

static struct file_operations echo_fops = {
    .owner   = THIS_MODULE,
    .open    = echo_open,
    .release = echo_release,
    .read    = echo_read,
    .write   = echo_write,
};

static int __init echo_init(void)
{
    int ret;

    // Allocate kernel buffer
    echo_buf = kzalloc(BUF_SIZE, GFP_KERNEL);
    if (!echo_buf)
        return -ENOMEM;

    // Register character device region
    ret = alloc_chrdev_region(&echo_dev, 0, 1, DEVICE_NAME);
    if (ret < 0) {
        pr_err("echo: failed to allocate chrdev region: %d\n", ret);
        kfree(echo_buf);
        return ret;
    }

    // Create device class (for udev to create /dev node)
    echo_class = class_create(CLASS_NAME);
    if (IS_ERR(echo_class)) {
        unregister_chrdev_region(echo_dev, 1);
        kfree(echo_buf);
        return PTR_ERR(echo_class);
    }

    // Initialize and add cdev
    cdev_init(&echo_cdev, &echo_fops);
    echo_cdev.owner = THIS_MODULE;
    ret = cdev_add(&echo_cdev, echo_dev, 1);
    if (ret) {
        class_destroy(echo_class);
        unregister_chrdev_region(echo_dev, 1);
        kfree(echo_buf);
        return ret;
    }

    // Create device node
    device_create(echo_class, NULL, echo_dev, NULL, DEVICE_NAME);

    pr_info("echo: device registered (major %d, minor %d)\n",
            MAJOR(echo_dev), MINOR(echo_dev));
    return 0;
}

static void __exit echo_exit(void)
{
    device_destroy(echo_class, echo_dev);
    cdev_del(&echo_cdev);
    class_destroy(echo_class);
    unregister_chrdev_region(echo_dev, 1);
    kfree(echo_buf);
    pr_info("echo: device unregistered\n");
}

module_init(echo_init);
module_exit(echo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Security Researcher");
MODULE_DESCRIPTION("Character device that echoes back written data");
						
# Makefile for echo_driver.ko
obj-m += echo_driver.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Block Devices

Block devices provide random-access, fixed-size block I/O. Disks, SSDs, NVMe drives, and ramdisks are block devices. They operate on struct request queues, not byte streams.

Network Devices

Network devices are fundamentally different from block and character devices - they have no file node in /dev . Access occurs through sockets, not read() / write() . The struct net_device is the kernel's representation. 

// include/linux/netdevice.h (simplified)
struct net_device {
    char               name[IFNAMSIZ];      // eth0, wlan0, ...
    struct net_device_ops *netdev_ops;
    const struct ethtool_ops *ethtool_ops;
    struct device       dev;              // embedded struct device
    unsigned int        mtu;
    unsigned int        flags;            // IFF_UP, IFF_BROADCAST, ...
    struct list_head    dev_list;         // global linked list
    struct net_device  *upper_level_priv; // bridge/bond master
    int                 ifindex;          // unique ifindex
    struct napi_struct  napi;             // NAPI polling
    int                 needs_free_netdev;
    // ...
};

struct net_device_ops {
    int  (*ndo_open)(struct net_device *dev);
    int  (*ndo_stop)(struct net_device *dev);
    netdev_tx_t (*ndo_start_xmit)(struct sk_buff *skb,
                                   struct net_device *dev);
    void (*ndo_set_rx_mode)(struct net_device *dev);
    int  (*ndo_set_mac_address)(struct net_device *dev, void *addr);
    int  (*ndo_change_mtu)(struct net_device *dev, int new_mtu);
    void (*ndo_tx_timeout)(struct net_device *dev, unsigned int txqueue);
    int  (*ndo_get_stats64)(struct net_device *dev,
                             struct rtnl_link_stats64 *storage);
    // ... 40+ callbacks
};

NAPI (New API) amortizes interrupt cost by switching between interrupt-driven and poll-driven modes. Under high load, the driver disables RX interrupts and polls in softirq context, draining the ring buffer cheaply without per-packet interrupt overhead. 

Light Load (Interrupt Mode)          Heavy Load (Polling Mode)
────────────────────────────         ─────────────────────────
Packet arrives                       Packet arrives
    │                                   │
    ▼                                   ▼
Hardware IRQ                         NAPI: IRQ disabled
    │                                   │
    ▼                                   ▼
napi_schedule()                      Softirq polls net_rx_action()
    │                                   │
    ▼                                   ▼
Softirq runs napi->poll()           driver->poll() drains ring
    │                                   │
    ▼                                   ▼
Re-enable IRQ                       napi_complete_done()
                                    → if queue empty, re-enable IRQ
                                    → else keep polling (budget-based)

Direct Memory Access (DMA)

DMA lets devices access system memory directly, bypassing CPU . Two fundamental mapping types exist: 

Coherent DMA (Consistent)              Streaming DMA (Synchronous)
─────────────────────────              ───────────────────────────
- Allocated once, reused many times    - Mapped/unmapped per transfer
- CPU and device see same data         - May require explicit sync/flush
- No cache flushing on modern HW       - Cache coherency not guaranteed
- Lower overhead, higher memory cost   - Flexible, works with vmalloc, stack
- Use for: ring buffers, descriptors   - Use for: packet data, user buffers
- API: dma_alloc_coherent()            - API: dma_map_single()
        dma_free_coherent()                    dma_unmap_single()

DMA API overview

// Coherent DMA — for descriptors, ring buffers
void *dma_alloc_coherent(struct device *dev, size_t size,
                         dma_addr_t *dma_handle, gfp_t flag);
void dma_free_coherent(struct device *dev, size_t size,
                       void *cpu_addr, dma_addr_t dma_handle);

// Streaming DMA — for payload data
dma_addr_t dma_map_single(struct device *dev, void *cpu_addr,
                          size_t size, enum dma_data_direction dir);
void dma_unmap_single(struct device *dev, dma_addr_t dma_addr,
                      size_t size, enum dma_data_direction dir);

// Sync after CPU modifies buffer, before device reads it
void dma_sync_single_for_device(struct device *dev, dma_addr_t addr,
                                size_t size, enum dma_data_direction dir);
// Sync after device wrote, before CPU reads it
void dma_sync_single_for_cpu(struct device *dev, dma_addr_t addr,
                              size_t size, enum dma_data_direction dir);

// Scatter-gather DMA
int dma_map_sg(struct device *dev, struct scatterlist *sg,
               int nents, enum dma_data_direction dir);
void dma_unmap_sg(struct device *dev, struct scatterlist *sg,
                  int nents, enum dma_data_direction dir);

The IOMMU (Intel VT-d, AMD-Vi, ARM SMMU) translates device-visible DMA addresses to physical addresses, providing: - Isolation: device A cannot DMA into device B's buffers - Remapping: 32-bit devices can access >4GB physical RAM - Interrupt remapping for security

The ioctl() Interface

ioctl() is the escape hatch for device-specific operations that do not fit the read() / write() model. Its 32-bit command word encodes direction, argument size, type (magic), and command number:

Bits Field Meaning
2 dir 00=none, 01=write, 10=read, 11=read/write
14 size sizeof(argument struct)
8 type magic number (unique per driver, 0x00-0xFF in /usr/include/linux/ioctl.h reserved)
8 nr sequential command number 
// include/uapi/asm-generic/ioctl.h — command constructors
#define _IO(type, nr)          _IOC(_IOC_NONE, (type), (nr), 0)
#define _IOR(type, nr, size)   _IOC(_IOC_READ, (type), (nr), sizeof(size))
#define _IOW(type, nr, size)   _IOC(_IOC_WRITE,(type), (nr), sizeof(size))
#define _IOWR(type,nr, size)   _IOC(_IOC_READ|_IOC_WRITE,(type),(nr),sizeof(size))

// Decoding helpers
#define _IOC_DIR(nr)   (((nr) >> _IOC_DIRSHIFT) & _IOC_DIRMASK)
#define _IOC_TYPE(nr)  (((nr) >> _IOC_TYPESHIFT) & _IOC_TYPEMASK)
#define _IOC_NR(nr)    (((nr) >> _IOC_NRSHIFT) & _IOC_NRMASK)
#define _IOC_SIZE(nr)  (((nr) >> _IOC_SIZESHIFT) & _IOC_SIZEMASK)

ioctl implementation in a driver

// Define commands with a unique magic number
#define ECHO_IOC_MAGIC  'e'
#define ECHO_IOC_RESET      _IO(ECHO_IOC_MAGIC, 0)
#define ECHO_IOC_GETSIZE    _IOR(ECHO_IOC_MAGIC, 1, uint32_t *)
#define ECHO_IOC_SETSIZE    _IOW(ECHO_IOC_MAGIC, 2, uint32_t *)
#define ECHO_IOC_FILL       _IOWR(ECHO_IOC_MAGIC, 3, struct echo_fill_args)
#define ECHO_IOC_MAXNR      3

struct echo_fill_args {
    uint32_t offset;
    uint32_t length;
    uint8_t  byte_val;
};

// Driver-side ioctl handler
static long echo_ioctl(struct file *filp, unsigned int cmd,
                       unsigned long arg)
{
    uint32_t size_val;
    struct echo_fill_args fill;

    // ALWAYS validate magic and command range
    if (_IOC_TYPE(cmd) != ECHO_IOC_MAGIC)
        return -ENOTTY;
    if (_IOC_NR(cmd) > ECHO_IOC_MAXNR)
        return -ENOTTY;

    switch (cmd) {
    case ECHO_IOC_RESET:
        memset(echo_buf, 0, BUF_SIZE);
        break;

    case ECHO_IOC_GETSIZE:
        size_val = BUF_SIZE;
        if (copy_to_user((uint32_t __user *)arg, &size_val, sizeof(uint32_t)))
            return -EFAULT;
        break;

    case ECHO_IOC_SETSIZE:
        if (copy_from_user(&size_val, (uint32_t __user *)arg, sizeof(uint32_t)))
            return -EFAULT;
        if (size_val > 65536)  // Always bound-check ioctl args
            return -EINVAL;
        pr_info("echo: requested new size: %u (ignored in demo)\n", size_val);
        break;

    case ECHO_IOC_FILL:
        if (copy_from_user(&fill, (void __user *)arg, sizeof(fill)))
            return -EFAULT;
        if (fill.offset + fill.length > BUF_SIZE)
            return -EINVAL;
        memset(echo_buf + fill.offset, fill.byte_val, fill.length);
        break;

    default:
        return -ENOTTY;
    }
    return 0;
}

mmap() for Device Memory

Drivers can map device memory ( PCI BARs, framebuffers, GPU memory) directly into user space via the mmap() file_operation callback. The key function is remap_pfn_range() : 

// mm/io-mapping.c — remap I/O memory and device memory into user space
int remap_pfn_range(struct vm_area_struct *vma,
                    unsigned long addr,
                    unsigned long pfn,        // Physical frame number
                    unsigned long size,
                    pgprot_t prot);

// Higher-level wrapper for PCI BARs

                             unsigned long addr,

Driver mmap example

static int echo_mmap(struct file *filp, struct vm_area_struct *vma)
{
    unsigned long size = vma->vm_end - vma->vm_start;
    unsigned long pfn;

    // Kernel address to physical page frame
    pfn = virt_to_phys(echo_buf) >> PAGE_SHIFT;

    // NEVER allow PROT_WRITE + MAP_SHARED without careful consideration
    // For read-only mapping, enforce:
    if (vma->vm_flags & VM_WRITE) {
        pr_warn("echo: writing via mmap not supported\n");
        return -EACCES;
    }

    // Map physical pages to user virtual addresses
    if (remap_pfn_range(vma, vma->vm_start, pfn, size, vma->vm_page_prot))
        return -EAGAIN;

    return 0;
}

Power Management

Modern devices support multiple power states. The kernel's runtime PM framework automatically suspends idle devices and resumes them on access.

Device Power States ( PCI example):

State Description
D0 Fully ON - highest power consumption
D1 Light sleep - context preserved, fast resume
D2 (rarely used)
D3hot Deep sleep - context may be lost, PCI config space accessible, slow resume
D3cold Power removed - all context lost, reset on resume, PCI config space not accessible

System Sleep States:

State Description
Suspend-to-Idle Freeze user space, freeze devices, enter s2idle (lightest)
Suspend-to-RAM Freeze, suspend non-boot CPUs, suspend devices, sleep
Suspend-to-Disk Freeze, snapshot RAM, power off; resume restores from snapshot 
// include/linux/pm.h
struct dev_pm_ops {
    int (*prepare)(struct device *dev);
    void (*complete)(struct device *dev);
    int (*suspend)(struct device *dev);
    int (*resume)(struct device *dev);
    int (*freeze)(struct device *dev);
    int (*thaw)(struct device *dev);
    int (*poweroff)(struct device *dev);
    int (*restore)(struct device *dev);
    int (*suspend_late)(struct device *dev);
    int (*resume_early)(struct device *dev);
    int (*runtime_suspend)(struct device *dev);
    int (*runtime_resume)(struct device *dev);
    int (*runtime_idle)(struct device *dev);
};

User-Kernel Communication Fundamentals

Data crossing the user/kernel boundary must be explicitly copied. Direct dereference of userspace pointers is catastrophic - it bypasses SMAP / SMEP (if present) and may fault. The safe primitives: 

// include/linux/uaccess.h

// Check entire range is valid user memory (cheap: only checks range bounds)
int access_ok(const void __user *addr, unsigned long size);

// Returns 0 on success, number of uncopied bytes on failure
unsigned long copy_from_user(void *to, const void __user *from, unsigned long n);
unsigned long copy_to_user(void __user *to, const void *from, unsigned long n);

// Simple types — optimized for 1/2/4/8 byte transfers
int get_user(x, ptr);
int put_user(x, ptr);

// String operations
long strncpy_from_user(char *dst, const char __user *src, long count);
long strnlen_user(const char __user *str, long n);
long strnlen_user_nofault(const char __user *str, long n);  // won't fault

Always validate user pointers

static ssize_t secure_read(struct file *f, char __user *buf, size_t len, loff_t *off)
{
    // BUG: no access_ok check — relies on copy_to_user catching it
    // Better: explicitly validate
    if (!access_ok(buf, len))
        return -EFAULT;

    char *kbuf = kmalloc(len, GFP_KERNEL);
    if (!kbuf)
        return -ENOMEM;

    // ... fill kbuf from device ...

    if (copy_to_user(buf, kbuf, len)) {
        kfree(kbuf);
        return -EFAULT;
    }

    kfree(kbuf);
    return len;
}

Common Driver Vulnerabilities

Missing Bounds Checks

// VULNERABLE: attacker controls size field
#define BAD_IOCTL _IOW('X', 1, char[0])  // size encoded in ioctl cmd
static long bad_ioctl(struct file *f, unsigned int cmd, unsigned long arg)
{
    int size = _IOC_SIZE(cmd);
    char kbuf[256];

    // If size > 256 → kernel stack buffer overflow!
    if (copy_from_user(kbuf, (void __user *)arg, size))
        return -EFAULT;

    return 0;
}

// CORRECT:
static long good_ioctl(struct file *f, unsigned int cmd, unsigned long arg)
{
    int size = _IOC_SIZE(cmd);
    if (size > 256)          // Bound check
        return -EINVAL;
    if (!access_ok((void __user *)arg, size))  // User address valid?
        return -EFAULT;

    // Even better: kmalloc with size from trusted source
    char *kbuf = kmalloc(size, GFP_KERNEL);
    if (!kbuf)
        return -ENOMEM;
    if (copy_from_user(kbuf, (void __user *)arg, size)) {
        kfree(kbuf);
        return -EFAULT;
    }
    // ... process ...
    kfree(kbuf);
    return 0;
}

    return -EFAULT;

    return -EINVAL;                  // ...but state already partially used

    mutex_unlock(&dev->lock);
    return -EFAULT;
