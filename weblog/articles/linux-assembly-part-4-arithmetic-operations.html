Linux Assembly Part 4: Arithmetic

Learn Linux assembly to do arithmetic operations.

Overview

This is the fourth article of the Linux Assembly series, the previous article described the Linux Assembly Part 3: Control Flow . This time, we will focus on how to do arithmetic operations in nasm so that we can actually calculate values in our programs. We already saw a couple of arithmetic instructions in the previous articles, but now we are going to take a closer look at how they work behind the scenes.

Arithmetic Operations

Arithmetic operations are the instructions that let us calculate values directly on the CPU . Unlike most high-level programming languages, there is no single "math" library in assembly. Instead, every operation maps to a single CPU instruction that operates on the general purpose registers we learned about in Linux Assembly Part 2 about Declaring Data .

The most important arithmetic instructions are:

Instruction Description
ADD dest, src dest = dest + src
SUB dest, src dest = dest - src
INC dest dest = dest + 1
DEC dest dest = dest - 1
NEG dest dest = -dest (two's complement negation)
ADC dest, src dest = dest + src + carry flag (add with carry)
SBB dest, src dest = dest - src - carry flag (subtract with borrow)
MUL src unsigned multiplication of the accumulator with src
IMUL src signed multiplication of the accumulator with src
DIV src unsigned division of the accumulator by src
IDIV src signed division of the accumulator by src

The ADD and SUB instructions are pretty straight forward, but multiplication and division are a little special because they use implicit operands that are not written out explicitly. We are going to learn about that in a moment.

Addition and Subtraction

The ADD and SUB instructions take two operands. The first operand is the destination and is always modified in place, the second operand is the source that is read but never changed.

mov rax, 13    ; rax = 13
add rax, 37    ; rax = 13 + 37 = 50
sub rax, 10    ; rax = 50 - 10 = 40

The source operand can be a register, an immediate value, or a memory location. The destination operand can be a register or a memory location, but both operands can never be memory locations at the same time, because the x86 instruction set only supports a single memory address per instruction.

mov rax, 13
add rax, rbx        ; register + register
add rax, 37         ; register + immediate
add rax, [buffer]   ; register + memory

Remember that [buffer] refers to the value stored at the memory address of the buffer label, and not to the address itself. We already worked with this notation when we learned about the stack in the previous article.

Increment, Decrement and Negation

For the very common case of adding or subtracting exactly 1 , the x86 instruction set has two dedicated instructions that are shorter and faster than their ADD / SUB equivalents.

mov rax, 13
inc rax    ; rax = 14
dec rax    ; rax = 13

The NEG instruction replaces the value with its two's complement negation, which is the same as subtracting the value from zero.

mov rax, 13
neg rax    ; rax = -13

Negation is useful when you want to turn an addition into a subtraction or the other way around, and it is often what compilers emit for -x expressions.

Multiplication

Multiplication is where the x86 instruction set gets a little quirky, because the MUL and IMUL instructions only take a single explicit operand. The other operand is always implicit and depends on the size of the source operand:

Source size Other operand Result size Result location
byte al word ax
word ax doubleword dx:ax
doubleword eax quadword edx:eax
quadword rax octaword rdx:rax

The reason for this is that multiplying two n bit numbers can produce a result that is up to 2n bits wide. The low part of the result is stored in the accumulator ( al / ax / eax / rax ), and the high part is stored in the data register ( ah / dx / edx / rdx ).

mov rax, 13
mov rbx, 37
mul rbx        ; rdx:rax = rax * rbx = 481 (rdx = 0, rax = 481)

The IMUL instruction works the same way for signed numbers, but it also has two and three operand forms that allow us to pick the destination register and store only the low part of the result. This is the form that compilers use most of the time, because the high part is rarely needed:

imul rax, rbx       ; rax = rax * rbx
imul rax, rbx, 37   ; rax = rbx * 37

Keep in mind that the MUL instruction always clobbers the data register ( rdx ) with the high part of the result, even if that high part is 0 . If we need the value in rdx afterwards, we have to save it on the stack or in another register first.

Division

Division is even more asymmetric than multiplication, because it produces two results at once: the quotient and the remainder. The DIV and IDIV instructions also use implicit operands and follow the inverse layout of the multiplication instructions:

Divisor size Dividend location Quotient Remainder
byte ax al ah
word dx:ax ax dx
doubleword edx:eax eax edx
quadword rdx:rax rax rdx

The most common mistake when using DIV is to forget that the dividend is the pair rdx:rax and not just rax . If rdx contains leftover data from a previous operation, the result will be garbage (or worse, a division overflow). That is why we almost always see a xor rdx, rdx right before a DIV instruction:

mov rax, 37
mov rbx, 13
xor rdx, rdx   ; clear the high part of the dividend
div rbx        ; rax = 2 (quotient), rdx = 11 (remainder)

The IDIV instruction behaves the same way for signed numbers. For signed division we have to sign-extend rax into rdx first, which is what the cqo instruction does:

mov rax, -37
mov rbx, 13
cqo            ; sign-extend rax into rdx:rax
idiv rbx       ; rax = -2 (quotient), rdx = -11 (remainder)

One more thing to keep in mind: dividing by zero is not allowed. The CPU cannot produce a result and raises a division error, which the kernel reports to our program as the SIGFPE signal. Make sure the divisor is never zero before we divide.

Status Flags

All arithmetic instructions update the status flags inside the special rflags register. The comparison instructions that we learned about in Linux Assembly Part 3 about Control Flow actually do nothing but a hidden subtraction and then throw away the result, only keeping the flags.

The flags that matter the most for arithmetic are:

  • The zero flag ( ZF ) is set when the result is 0 .
  • The sign flag ( SF ) is set when the result is negative (the highest bit is 1 ).
  • The carry flag ( CF ) is set when an unsigned addition overflows or a subtraction underflows.
  • The overflow flag ( OF ) is set when a signed result overflows.

This is why we can use the conditional jump instructions like je or jg directly after an ADD or SUB instruction, without an explicit cmp in between:

mov rax, 13
add rax, 37
jz  .is_zero      ; taken if rax became 0

The ADC (add with carry) and SBB (subtract with borrow) instructions from the table above work exactly like ADD and SUB , but they also add the current carry flag to the result. This allows us to chain multiple additions together to implement arbitrary precision arithmetic that is wider than a single register:

; add rdx:rax + rcx:rbx (128 bit)
add rax, rbx
adc rdx, rcx

If the low addition overflows, the carry flag is set, and ADC picks it up and adds it to the high part. That is the same trick the CPU uses internally to do 64 bit arithmetic on 32 bit machines.

Arithmetic Calculator Program

Now that we know all the arithmetic instructions, we can write a small calculator program that computes the sum, difference, product, quotient and remainder of two numbers and prints the results to the terminal.

The program uses a helper routine that converts a number in rax to its decimal string representation. It does this by repeatedly dividing by 10 and storing the digits from right to left in a buffer, which is the same technique we already used in Linux Assembly Part 3 about Control Flow .

section .data
    num1: equ 13
    num2: equ 37

    label_sum:  db "Sum:      "
    label_diff: db "Diff:     "
    label_prod: db "Product:  "
    label_quot: db "Quotient: "
    label_rem:  db "Remainder:"
    newline:    db 0x0a

section .bss
    buffer resb 20

section .text
    global _start

_start:
    ; sum = num1 + num2 = 50
    mov rax, num1
    add rax, num2
    mov rsi, label_sum
    mov rdx, 10
    call .write
    call .print_number
    call .print_newline

    ; difference = num2 - num1 = 24
    mov rax, num2
    sub rax, num1
    mov rsi, label_diff
    mov rdx, 10
    call .write
    call .print_number
    call .print_newline

    ; product = num1 * num2 = 481
    mov rax, num1
    mov rbx, num2
    mul rbx
    mov rsi, label_prod
    mov rdx, 10
    call .write
    call .print_number
    call .print_newline

    ; quotient = num2 / num1 = 2
    mov rax, num2
    xor rdx, rdx
    mov rbx, num1
    div rbx
    push rdx           ; save the remainder (rdx is clobbered by print_number)
    mov rsi, label_quot
    mov rdx, 10
    call .write
    call .print_number
    call .print_newline

    ; remainder = num2 % num1 = 11
    pop rax             ; restore the remainder
    mov rsi, label_rem
    mov rdx, 10
    call .write
    call .print_number
    call .print_newline

    call .exit

.write:
    push rax       ; preserve the caller's rax (syscall clobbers it)
    mov rax, 1
    mov rdi, 1
    syscall
    pop rax
    ret

.print_newline:
    mov rsi, newline
    mov rdx, 1
    call .write
    ret

.print_number:
    ; rax contains the unsigned number to print
    mov rcx, 0
    mov rsi, buffer + 19 ; point to the end of the buffer
    mov rbx, 10

    test rax, rax
    jnz .convert_loop

    ; handle the zero case
    dec rsi
    mov byte [rsi], '0'
    mov rcx, 1
    jmp .print_number_done

.convert_loop:
    xor rdx, rdx
    div rbx

    add dl, '0'
    dec rsi
    mov [rsi], dl

    inc rcx
    test rax, rax
    jnz .convert_loop

.print_number_done:
    mov rdx, rcx
    call .write
    ret

.exit:
    mov rax, 60
    mov rdi, 0
    syscall

The arithmetic calculator program can also be downloaded from here . If we compile and run our program, we can see the results of all five operations:

nasm -f elf64 -o arithmetic.o arithmetic.asm;
ld -o arithmetic.bin arithmetic.o;
chmod +x arithmetic.bin;

./arithmetic.bin;

The output of the program should look like this:

Sum:      50
Diff:     24
Product:  481
Quotient: 2
Remainder:11

Note how the MUL instruction only needed rax and rbx , while the DIV instruction also required us to clear rdx with xor rdx, rdx beforehand. The quotient ended up in rax and the remainder in rdx , which is why we pushed the remainder onto the stack before the next call so that it would not be overwritten by the helper routine.
