Sysmon

Windows endpoint telemetry for detection with Sysinternals Sysmon event IDs, XML configuration, and SIEM integration.

Overview

Sysmon is a Windows kernel driver and service from Sysinternals that records process creation, network connections, image loads, registry writes, and other endpoint events into the Windows event log with far more detail than the built-in auditing. This article covers the event IDs, the XML configuration that decides what is collected, the community configurations that balance signal against noise, and the forwarding path into a SIEM .

Required Reading

  • Processes - process creation, parent-child relationships, process injection
  • PE - PE file structure, sections, imports, digital signatures

Why Sysmon

Windows Event Log provides limited process telemetry. Event ID 4688 (Process Creation) tells you a process was created, but not the full command line, the parent process, file hashes, or DLL loads. Sysmon (System Monitor) fills this gap by installing as a kernel driver and Windows service, capturing granular endpoint telemetry that the built-in event log omits.

Sysmon runs only on Windows, so this article ships no container. The challenge is a Go tool that parses an exported Sysmon event log on Linux, which keeps the exercise reproducible without a Windows host.

Architecture

SysmonDrv.sys  — kernel driver, hooks process/thread creation, registry, file system
Sysmon.exe     — userspace service, manages driver, receives events, writes to event log
Sysmon64.exe   — 64-bit variant
config.xml     — XML configuration controlling which events to collect

Sysmon writes events to Microsoft-Windows-Sysmon/Operational in the Windows Event Log. These events can be forwarded via Windows Event Forwarding (WEF) or collected by Winlogbeat.

Installation

On Windows (elevated PowerShell):

# Download and install
Invoke-WebRequest -Uri "https://download.sysinternals.com/files/Sysmon.zip" -OutFile Sysmon.zip
Expand-Archive Sysmon.zip
cd Sysmon

# Install with configuration
.\Sysmon64.exe -accepteula -i sysmonconfig.xml

Event IDs Reference

Sysmon generates events numbered 1 through 28 (version-dependent). The most critical for detection:

ID Name Fields Detection Use
1 ProcessCreate Image, CommandLine, ParentProcessId, Hashes, User Process lineage, suspicious commands
2 FileCreateTime UtcTime, PreviousTime, Image Timestomping (antiforensics)
3 NetworkConnect Image, User, Protocol, SourceIp, DestinationIp, DestinationPort C2 connections, lateral movement
5 ProcessTerminate Image, ProcessId Process kill events
6 DriverLoaded ImageLoaded, Hashes, Signature Rootkit detection
7 ImageLoad ImageLoaded, Hashes, Signed, Signature DLL injection, reflective loading
8 CreateRemoteThread SourceImage, TargetImage, StartAddress Process injection
9 RawAccessRead Device, Image Direct disk access (credential theft)
10 ProcessAccess SourceImage, TargetImage, GrantedAccess LSASS access, process hollowing
11 FileCreate Image, TargetFilename Malware dropped files
12 RegistryEvent (Create/Delete) Image, TargetObject Persistence registry keys
13 RegistryEvent (Set) Image, TargetObject, Details Registry value modification
14 RegistryEvent (Rename) Image, TargetObject, NewName Registry key rename
15 FileCreateStreamHash Image, TargetFilename, Hash Alternate Data Streams (ADS)
16 ServiceConfigurationChange Image, Configuration Service persistence
17 PipeEvent (Create) Image, PipeName Named pipe creation (lateral movement)
18 PipeEvent (Connect) Image, PipeName Named pipe connection
19 WmiEvent Image, Operation, Name, Query WMI persistence/monitoring
21 WmiEvent (Consumer) Destination, Consumer, Filter WMI subscription for persistence
22 DNSEvent Image, QueryName, QueryStatus DNS query monitoring
23 FileDelete Image, TargetFilename File deletion (log wiping)
25 ProcessTampering Image, Type Process hollowing/herpaderping
27 FileBlockExecutable Image, TargetFilename Driver block event
28 FileBlockShredding Image, TargetFilename SDelete/wipe detection

XML Configuration

The config XML uses <Sysmon> as root, containing <EventFiltering> with <RuleGroup> elements.

<!-- sysmonconfig.xml — Production-ready partial configuration -->
<Sysmon schemaversion="4.80">
  <EventFiltering>

    <!-- Event ID 1: Process Creation -->
    <!-- Include: Capture everything, let SIEM filter -->
    <RuleGroup name="Process Creation" groupRelation="or">
      <ProcessCreate onmatch="exclude">
        <!-- Exclude noisy system processes -->
        <Image condition="end with">\svchost.exe</Image>
        <Image condition="end with">\RuntimeBroker.exe</Image>
        <Image condition="end with">\SearchIndexer.exe</Image>
        <Image condition="end with">\msiexec.exe</Image>
        <Image condition="end with">\taskhostw.exe</Image>
        <Image condition="end with">\wlms\wlms.exe</Image>
      </ProcessCreate>
    </RuleGroup>

    <!-- Event ID 3: Network Connections -->
    <RuleGroup name="Network" groupRelation="or">
      <NetworkConnect onmatch="include">
        <!-- Include all network connections -->
      </NetworkConnect>
    </RuleGroup>

    <!-- Event ID 7: DLL Loaded -->
    <!-- Exclude Microsoft-signed DLLs to reduce noise -->
    <RuleGroup name="Image Load" groupRelation="or">
      <ImageLoad onmatch="exclude">
        <Signature condition="contains">Microsoft Corporation</Signature>
        <Signature condition="contains">Microsoft Windows</Signature>
        <ImageLoaded condition="end with">\mscoree.dll</ImageLoaded>
        <ImageLoaded condition="end with">\clr.dll</ImageLoaded>
        <ImageLoaded condition="end with">\kernel32.dll</ImageLoaded>
        <ImageLoaded condition="end with">\ntdll.dll</ImageLoaded>
      </ImageLoad>
    </RuleGroup>

    <!-- Event ID 8: CreateRemoteThread — always include -->
    <RuleGroup name="Remote Thread" groupRelation="or">
      <CreateRemoteThread onmatch="exclude">
        <!-- Exclude only if needed -->
      </CreateRemoteThread>
    </RuleGroup>

    <!-- Event ID 10: Process Access — critical for detection -->
    <RuleGroup name="Process Access" groupRelation="or">
      <ProcessAccess onmatch="include">
        <!-- LSASS access grants that indicate credential dumping -->
        <GrantedAccess condition="is">0x1010</GrantedAccess>   <!-- PROCESS_VM_READ | PROCESS_QUERY_INFORMATION -->
        <GrantedAccess condition="is">0x1410</GrantedAccess>   <!-- + PROCESS_DUP_HANDLE -->
        <GrantedAccess condition="is">0x1438</GrantedAccess>   <!-- + PROCESS_VM_OPERATION -->
        <GrantedAccess condition="is">0x143A</GrantedAccess>   <!-- + PROCESS_VM_WRITE -->
        <GrantedAccess condition="is">0x1F0FFF</GrantedAccess> <!-- PROCESS_ALL_ACCESS -->
        <GrantedAccess condition="is">0x1F1FFF</GrantedAccess> <!-- PROCESS_ALL_ACCESS + PROCESS_QUERY_LIMITED_INFORMATION -->
        <GrantedAccess condition="is">0x1F2FFF</GrantedAccess>
        <GrantedAccess condition="is">0x1F3FFF</GrantedAccess>
      </ProcessAccess>
    </RuleGroup>

    <!-- Event ID 11: File Creation -->
    <RuleGroup name="File Create" groupRelation="or">
      <FileCreate onmatch="include">
        <!-- Monitor startup folders (persistence) -->
        <TargetFilename condition="contains">\Start Menu\Programs\Startup</TargetFilename>
        <TargetFilename condition="contains">\Startup\</TargetFilename>
        <!-- Temp directories -->
        <TargetFilename condition="begin with">C:\Windows\Temp\</TargetFilename>
        <TargetFilename condition="begin with">C:\Users\</TargetFilename>
        <!-- Executable file extensions -->
        <TargetFilename condition="end with">.exe</TargetFilename>
        <TargetFilename condition="end with">.dll</TargetFilename>
        <TargetFilename condition="end with">.ps1</TargetFilename>
        <TargetFilename condition="end with">.vbs</TargetFilename>
        <TargetFilename condition="end with">.js</TargetFilename>
        <TargetFilename condition="end with">.vbe</TargetFilename>
        <TargetFilename condition="end with">.bat</TargetFilename>
        <TargetFilename condition="end with">.scr</TargetFilename>
      </FileCreate>
    </RuleGroup>

    <!-- Event ID 12-14: Registry Events -->
    <RuleGroup name="Registry" groupRelation="or">
      <RegistryEvent onmatch="include">
        <!-- Persistence locations -->
        <TargetObject condition="contains">\CurrentVersion\Run</TargetObject>
        <TargetObject condition="contains">\CurrentVersion\RunOnce</TargetObject>
        <TargetObject condition="contains">\CurrentVersion\Windows\Run</TargetObject>
        <TargetObject condition="contains">\CurrentVersion\Policies\Explorer\Run</TargetObject>
        <TargetObject condition="contains">\CurrentVersion\RunServices</TargetObject>
        <TargetObject condition="contains">\Software\Microsoft\Windows\CurrentVersion\Run</TargetObject>
        <TargetObject condition="contains">\Winlogon\Shell</TargetObject>
        <TargetObject condition="contains">\Winlogon\Userinit</TargetObject>
        <TargetObject condition="contains">\Image File Execution Options</TargetObject>
        <!-- Service registry hives -->
        <TargetObject condition="contains">\Services\</TargetObject>
        <!-- WMI persistence -->
        <TargetObject condition="contains">\WBEM\</TargetObject>
        <TargetObject condition="contains">\WOW6432Node\Microsoft\Windows\CurrentVersion\Run</TargetObject>
      </RegistryEvent>
    </RuleGroup>

    <!-- Event ID 22: DNS Queries -->
    <RuleGroup name="DNS" groupRelation="or">
      <DnsQuery onmatch="include">
      </DnsQuery>
    </RuleGroup>

  </EventFiltering>
</Sysmon>

Configuration Strategies

onmatch Rules

Two approaches:

  • exclude with onmatch=exclude : List noise to exclude; everything else matches. Higher volume, no gaps.
  • include with onmatch=include : Only include what you specify. Lower volume, risk of blind spots.

Best practice: use onmatch=exclude for broad event types (ProcessCreate, NetworkConnect) - you rarely miss what you didn't know to include. Use onmatch=include for targeted rules (ProcessAccess with specific GrantMask values).

Community Configurations

SwiftOnSecurity sysmon-config is the most widely deployed community baseline. It balances coverage with noise reduction. Covers 25+ event types with tuned exclusions.

# Install with SwiftOnSecurity config
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/SwiftOnSecurity/sysmon-config/master/sysmonconfig-export.xml" -OutFile sysmonconfig.xml
Sysmon64.exe -accepteula -i sysmonconfig.xml

Olaf Hartong's Sysmon-Modular takes a building-block approach: separate config files per event type, merged at install time.

# Clone and merge modular rules
git clone https://github.com/olafhartong/sysmon-modular.git
cd sysmon-modular
. .\Merge-SysmonXml.ps1
Merge-AllSysmonXml -Path (Get-ChildItem '[0-9]*\*.xml') -AsString | Out-File sysmonconfig-merged.xml
Sysmon64.exe -accepteula -i sysmonconfig-merged.xml

SIEM Integration

Winlogbeat

Winlogbeat ships Windows Event Logs (including Sysmon channel) to Elasticsearch or Logstash.

# winlogbeat.yml
winlogbeat.event_logs:
  - name: Microsoft-Windows-Sysmon/Operational
    fields:
      log_type: sysmon
      environment: production
    ignore_older: 72h
    processors:
      - add_host_metadata: ~
      - add_cloud_metadata: ~

output.elasticsearch:
  hosts: ["elasticsearch.example.com:9200"]
  index: "winlogbeat-%{+yyyy.MM.dd}"

Detection Examples

Malicious Process Tree Detection

Attackers often chain process execution in detectable patterns:

Word.exe → cmd.exe → powershell.exe → encoded command
Service → rundll32.exe → suspicious DLL
wmic.exe → cmd.exe → net.exe user /add

In a SIEM query (Elastic/Kibana):

event_id:1 AND (parent_process.name:winword.exe AND process.name:cmd.exe)
 OR (parent_process.name:cmd.exe AND process.name:powershell.exe)
 OR (parent_process.name:excel.exe AND process.name:cscript.exe)

LSASS Access Detection

event_id:10 AND target_process.name:lsass.exe
 AND NOT (source_process.name:svchost.exe OR
          source_process.name:vmcompute.exe OR
          source_process.name:MsMpEng.exe)

Legitimate processes accessing LSASS : svchost.exe (SCM), vmcompute.exe (Hyper-V), MsMpEng.exe (Defender), csrss.exe (subsystem). Anything else is suspect, especially rundll32.exe , taskmgr.exe , procdump.exe , or any process not signed by Microsoft.

Lateral Movement Detection

# PsExec: Service creation with random name + network connection from SMB
event_id:16 AND service_name matches "^[A-Z0-9]{8}\$" AND service_cmd_line contains "PSEXESVC"

# WMI lateral movement
event_id:19 AND operation:"Created" AND query contains "SELECT * FROM Win32_Process"

# WinRM lateral movement (wsmprovhost)
event_id:1 AND process.name:"wsmprovhost.exe" AND parent_process.name:"svchost.exe"

C2 Beaconing Detection

# Sysmon Event ID 3 + 22 correlation
# A process making periodic DNS queries to the same domain, and
# periodic outbound connections on non-standard ports

event_id:22 AND query_name:*.baddomain.xyz
event_id:3 AND destination_port NOT IN (80,443) AND destination_ip NOT IN (private_ranges)

Configuring Sysmon Updates

# Check current config version
sysmon64.exe -c

sysmon64.exe -c sysmonconfig-v2.xml

# Verbose installation
sysmon64.exe -accepteula -i config.xml -l -n

Challenge

Write a Go tool that reads an exported Sysmon event log in XML form and reports process creation events (Event ID 1) where an Office or web server process spawns a command interpreter. On a Windows host, wevtutil qe Microsoft-Windows-Sysmon/Operational /f:xml produces the input; the sample below is enough to test the tool.

package main

import (
	"encoding/xml"
	"fmt"
	"os"
	"strings"
)

type event struct {
	XMLName xml.Name `xml:"Event"`
	System  struct {
		EventID int `xml:"EventID"`
	} `xml:"System"`
	EventData struct {
		Data []struct {
			Name  string `xml:"Name,attr"`
			Value string `xml:",chardata"`
		} `xml:"Data"`
	} `xml:"EventData"`
}

var suspicious = map[string][]string{
	"winword.exe": {"cmd.exe", "powershell.exe", "wscript.exe", "cscript.exe", "mshta.exe"},
	"excel.exe":   {"cmd.exe", "powershell.exe", "wscript.exe", "cscript.exe", "mshta.exe"},
	"outlook.exe": {"cmd.exe", "powershell.exe", "wscript.exe", "cscript.exe", "mshta.exe"},
	"w3wp.exe":    {"cmd.exe", "powershell.exe", "whoami.exe", "net.exe"},
	"httpd":       {"bash", "sh", "python", "perl"},
	"apache2":     {"bash", "sh", "python", "perl"},
}

func base(path string) string {
	path = strings.ReplaceAll(path, "\\", "/")
	parts := strings.Split(path, "/")
	return strings.ToLower(parts[len(parts)-1])
}

func main() {

	decoder := xml.NewDecoder(os.Stdin)

	for {

		var e event

		if err := decoder.Decode(&e); err != nil {
			break
		}

		if e.System.EventID != 1 {
			continue
		}

		fields := make(map[string]string)

		for _, d := range e.EventData.Data {
			fields[d.Name] = strings.TrimSpace(d.Value)
		}

		children, ok := suspicious[base(fields["ParentImage"])]

		if ok == false {
			continue
		}

		for _, child := range children {
			if base(fields["Image"]) == child {
				fmt.Printf("[SUSPICIOUS LINEAGE] %s -> %s\n", fields["ParentImage"], fields["Image"])
				fmt.Printf("    %s\n", fields["CommandLine"])
				break
			}
		}

	}

}

Feed it the sample stream:

wevtutil qe Microsoft-Windows-Sysmon/Operational /f:xml > sysmon-events.xml
						
<Event>
  <System><EventID>1</EventID></System>
  <EventData>
    <Data Name="Image">C:\Windows\System32\cmd.exe</Data>
    <Data Name="ParentImage">C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE</Data>
    <Data Name="CommandLine">cmd.exe /c whoami</Data>
  </EventData>
</Event>
<Event>
  <System><EventID>1</EventID></System>
  <EventData>
    <Data Name="Image">C:\Windows\System32\notepad.exe</Data>
    <Data Name="ParentImage">C:\Windows\explorer.exe</Data>
    <Data Name="CommandLine">notepad.exe</Data>
  </EventData>
</Event>
						
go build -o lineage lineage.go
./lineage < sysmon-events.xml
# [SUSPICIOUS LINEAGE] C:\Program Files\...\WINWORD.EXE -> C:\Windows\System32\cmd.exe
#     cmd.exe /c whoami
