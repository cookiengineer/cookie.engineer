Control Flow Reconstruction

Reconstructing high-level program logic from disassembly with control flow graphs, dominance, loop detection, and switch recovery.

Overview

Control flow reconstruction converts flat disassembly into a control flow graph of basic blocks and edges. The graph shape reveals loops, conditionals, switches, and tail calls long before you read every instruction, which is the foundation of decompilation. After reading, you can identify leaders, partition blocks, compute dominance, detect natural loops, recover switch tables, and build a CFG analyzer.

Required Reading

  • /wiki/articles/reverse-engineering/reading-assembly.html - x86-64 instruction semantics, prologue/epilogue patterns, condition codes

What Reconstruction Solves

Raw disassembly is a linear sequence of instructions. Programs are not linear. They branch, loop, call, and return. Control flow reconstruction converts the flat instruction list into a structured representation - a control flow graph (CFG) - where nodes are basic blocks (straight-line code sequences) and edges are possible execution paths.

Without a CFG, reversing a 10,000-instruction function is impossible. With one, you reduce it to a graph of maybe 50 blocks connected by if-else diamonds and loop back-edges. The structure tells you what the code does before you've read a single instruction.

Basic Blocks and Discovery

A basic block is a maximal sequence of instructions with a single entry point and a single exit point. Inside a basic block, execution is strictly sequential - no branches in, no branches out (except the final instruction). Every instruction in the block executes exactly once per block invocation.

To partition disassembly into basic blocks, identify leaders - instructions that start a new block:

  1. The first instruction of a function (entry point)
  2. Any instruction that is the target of a branch ( jmp , jcc , call )
  3. Any instruction immediately following a branch or ret

A block runs from a leader up to (but not including) the next leader, or until a control transfer instruction ( jmp , jcc , call , ret ).

Example - disassembly of a simple function:

0x401140:  push   rbp                    ; Block A (leader: entry)
0x401141:  mov    rbp, rsp
0x401144:  mov    DWORD PTR [rbp-0x4], edi
0x401147:  cmp    DWORD PTR [rbp-0x4], 0xa
0x40114b:  jle    0x401155               ; -> leader at 0x401155

0x40114d:  mov    eax, DWORD PTR [rbp-0x4]  ; Block B (leader: after jle)
0x401150:  add    eax, 0x1
0x401153:  jmp    0x40115b               ; -> leader at 0x40115b

0x401155:  mov    eax, DWORD PTR [rbp-0x4]  ; Block C (leader: target of jle)
0x401158:  sub    eax, 0x1

0x40115b:  pop    rbp                    ; Block D (leader: target of jmp + after C)
0x40115c:  ret

Block partition:

Block A: 0x401140 - 0x40114b (ends with conditional jump jle)
Block B: 0x40114d - 0x401153 (ends with unconditional jump jmp)
Block C: 0x401155 - 0x401158 (falls through to D)
Block D: 0x40115b - 0x40115c (ends with ret)

Edges: - A -> B (fall-through, when jle not taken) - A -> C (branch taken, when jle is true)

  • B -> D (unconditional jump)
  • C -> D (fall-through)

Decompilation:

if (x > 10)
    return x + 1;
else
    return x - 1;

Building a CFG Algorithm

The algorithm takes a function's disassembly and produces a dictionary of {address -> Block} where each Block contains its instruction list and outgoing edges.

ALGORITHM: build_cfg(function_start, function_end, disassembly)

1. Identify all instructions in the function range.
   Parse each line: address, bytes?, mnemonic, operands.

2. Find leaders:
   - The function entry address is a leader.
   - Every jump target is a leader (resolve relative offsets to absolute addresses).
   - Every instruction after a jmp/jcc/ret is a leader.

3. Sort leaders by address. For each consecutive pair (L[i], L[i+1]),
   create Block L[i] containing all instructions from L[i] to L[i+1]-1.
   The last block runs from its leader to the function end.

4. For each block, examine its final instruction:
   - jmp ADDR   -> add edge block -> ADDR
   - jCC ADDR   -> add edges: block -> ADDR (taken), block -> next_block (fall-through)
   - ret        -> no outgoing edges (or edge to virtual exit node)
   - call ADDR  -> edge to next block (call returns, but also consider the callee)
   - Other      -> fall-through to next block

5. Optionally add edges for indirect jumps if resolvable (jump tables, tail calls).

The result is a directed graph. Blocks with multiple predecessors are merge points (end of if-else, loop header). Blocks with multiple successors are branch points . Back-edges (an edge from a block to a block that appears earlier in the address space) identify loops.

High-Level Structures from CFG

The shape of the CFG directly encodes the control structure. This is the core insight behind decompilation.

if-then (no else)

    Block A  (condition check)
     /   \
    v     v
Block B   Block A.fallthrough
(if body) |
     \   /
      v v
    Block D  (merge)

The conditional jump creates two paths: one into B (the then-block) and one skipping B. B jumps or falls through to the merge point D.

; if (x > 10)
;     x = 0;
; ...
    cmp    [rbp-4], 0xa
    jle    .L_skip
    mov    [rbp-4], 0
.L_skip:
    ; after if

if-then-else (diamond)

      Block A
      /     \
     v       v
 Block B   Block C
      \     /
       v   v
      Block D

Block A is the condition. Two outgoing edges lead to B (then) and C (else). Both converge at D. D has in-degree 2 from within the diamond structure.

    cmp    [rbp-4], 0xa
    jle    .L_else
    mov    eax, 1
    jmp    .L_end
.L_else:
    mov    eax, 0
.L_end:
    ret

while loop (pre-test)

      Block A (loop header)
      /   \
     v     v
Block B    Block C (exit)
     \     /
      v   v

The critical feature is the back-edge : Block B points back to Block A (the loop header). Block A dominates all blocks inside the loop - meaning all paths into any loop block must pass through A. The conditional branch at A either enters the loop body (B) or exits (C).

.L_loop:
    cmp    [rbp-4], 0xa
    jge    .L_exit
    ; loop body
    add    [rbp-4], 1
    jmp    .L_loop
.L_exit:

do-while loop (post-test)

    Block A (loop body start)
     |  \
     v   v
Block B  Block A (back-edge)

The condition test is at the bottom. The back-edge originates from a block containing the condition, pointing to the loop body start. There is no initial branch to skip the body - it always executes at least once.

.L_do_top:
    add    [rbp-4], 1
    cmp    [rbp-4], 0xa
    jl     .L_do_top

for loop

Structurally identical to a while loop in the CFG:

    Block A (init: i=0)
      |
      v
    Block B (condition: i<N?)
     /   \
    v     v
Block C  Block E (exit)
    |
    v
Block D (increment: i++)
    |
    v
  Block B (back-edge)

Block A initializes the loop counter. Block B tests the condition. Block C is the body. Block D increments. The back-edge goes from D to B.

if (condition) { /* setup */ }
while (condition) {
    /* body */
    /* increment */
}

Loop Detection with Dominance

Not every back-edge forms a meaningful loop (compiler-generated jumps can go anywhere). The standard approach uses dominator trees .

Block A dominates block B if every path from the function entry to B must pass through A. The immediate dominator of B is the unique node that dominates B and does not dominate any other dominator of B (the "closest" dominator).

A back-edge is an edge A -> B where B dominates A. That is, the target of the edge is a block that must have been executed before the source can be reached - this is a cycle.

A natural loop is defined by a back-edge A -> B: - B is the loop header (it dominates A) - The loop body consists of all nodes that can reach A without passing through B - The header dominates all nodes in the loop body

┌─────────────────────────────────────────────────────────────┐
│                   Loop Detection Algorithm                  │
├─────────────────────────────────────────────────────────────┤
│ For each edge A -> B in the CFG:                             │
│   If B dominates A (B is an ancestor of A in the dominator  │
│   tree), then A -> B is a back-edge.                         │
│                                                             │
│   The natural loop of back-edge A -> B:                      │
│     Loop = { B }                                            │
│     Worklist = { A }                                       │
│     While Worklist not empty:                               │
│       Pop node X from Worklist                              │
│       If X not in Loop:                                         │
│         Loop = Loop union { X }                                │
│         For each predecessor P of X:                        │
│           Add P to Worklist                                 │
│     Result: Loop contains header B + all nodes that reach A │
│             without going through B                         │
└─────────────────────────────────────────────────────────────┘

Nested loops are detected by finding back-edges where the header is already inside an outer loop body.

Switch Statement Recovery

Switch statements compile to one of two patterns:

Jump table (dense cases)

    cmp    eax, MAX_CASE        ; range check
    ja     .L_default           ; if out of range -> default
    cdqe                        ; sign-extend eax -> rax
    lea    rcx, [rip+TABLE]     ; rcx = &jump_table
    movsxd rax, [rcx + rax*4]   ; rax = table[eax] (32-bit signed offset)
    add    rax, rcx              ; rax = &table + offset = target
    jmp    rax                   ; indirect jump

The jump table is an array of 32-bit signed offsets from the table base (or absolute addresses in non-PIE binaries). The pattern to recognize:

  1. A cmp against a constant (the maximum case value)
  2. A ja conditional branch to the default case
  3. A memory load with index scaling ( [base + rax*4] or [base + rax*8] )
  4. An indirect jmp through the loaded value

To recover the case count: the maximum value in the cmp minus the minimum (usually 0, but check for subtraction of a base value). To recover individual case targets: read the jump table from the binary data section.

Decision tree (sparse cases)

For sparse switch values, the compiler emits a binary decision tree: a sequence of cmp / jcc pairs that narrows the range.

    cmp    eax, 0x100
    je     .L_case_256
    cmp    eax, 0x200
    je     .L_case_512
    cmp    eax, 0x7fff
    je     .L_case_32767
    jmp    .L_default

This pattern linearizes to a chain of if-else comparisons. Less efficient but preserves code size.

Tail Call Identification

A tail call is a function call positioned as the last action in a function, where the callee's return value becomes the caller's return value. In disassembly:

; Normal call (not a tail call)
    call   target
    ; more instructions...
    ret

; Tail call
    jmp    target              ; OR: pop reg; jmp target

When the compiler sees return func(args) , it can replace call func; ret with jmp func . The jmp transfers control to func without pushing a new return address. When func executes ret , it returns directly to the original caller, skipping the intermediate frame.

Tail calls break function boundary detection because there's no ret at the apparent end of the function. In the CFG, a tail call is an edge from the calling block to the entry block of the target function (an interprocedural edge).

Tail calls through pointers:

; tail call via function pointer
    mov    rax, [rbp-0x8]     ; function pointer
    pop    rbp
    jmp    rax                 ; first restore frame, then jump

Or with argument preparation:

; function returns target(args) - compiled as tail call
    mov    rdi, rbx            ; set up first arg
    mov    rsi, r12            ; set up second arg
    pop    rbp
    pop    rbx
    pop    r12
    jmp    target              ; tail call

Function Boundary Discovery

When symbols are stripped, you have a sea of bytes without function labels. Several heuristics recover function boundaries:

Prologue signature scanning

Scan the binary for the byte sequence 55 48 89 E5 ( push rbp; mov rbp, rsp ). Each occurrence is a candidate function start. But: - -fomit-frame-pointer eliminates this signature. - False positives exist (the bytes could be data or part of another instruction). - Functions compiled with -O2 rarely use rbp as a frame pointer.

Call target collection

Find all call ADDR instructions. Each ADDR is a function entry. Also find all lea rdi, [rip+OFFSET] near call instructions - those register loads often set up a function pointer argument to __libc_start_main (which reveals main ).

Return instruction clustering

Every ret ends a function. The instruction after a ret (up to alignment padding) is a function start - or unreachable dead code.

Gap scanning

Between functions, compilers insert alignment padding (typically nop sequences or 0xcc ). Scan for the pattern: ret -> padding bytes -> prologue-like instruction -> start of next function.

Cross-reference analysis

Build a complete cross-reference table: for every instruction, record which other instructions reference it (as a jump/call target, or as data). Addresses with many incoming call references are functions. Addresses with only jmp references might be jump table targets or case labels.

Ghidra/IDA approach

Modern tools combine all heuristics: they scan for prologues, collect call targets, run recursive disassembly (following all control flow from known entry points), and apply machine learning classifiers trained on known function signatures. The -M intel objdump output alone won't do this - you need the raw binary bytes.

Call Graphs

Beyond intraprocedural CFGs, build a call graph - nodes are functions, edges are call relationships.

main
├── authenticate (0x401196)
│   ├── strcmp@plt (0x401036)
│   └── check_password (0x401162)
│       └── strcmp@plt (0x401036)
└── printf@plt (0x401040)

Call graphs reveal: - Leaf functions : functions with no outgoing calls (terminate at syscalls or computation-only). - Wrapper functions : short functions that do nothing but call another function with rearranged arguments. - Recursion : a cycle in the call graph. - Library dependency profile : all external symbols resolve to specific behaviors (networking, crypto, file I/O).

To build one from disassembly: for each function, collect all call instruction targets. Group by resolved symbol name if available, by address if not. Create an edge from the calling function to the target.

Data Flow as Context for Control Flow

Control flow alone doesn't tell you what a function computes. But data flow provides hints about control flow:

  • If a function's return value is compared to 0 immediately after a call, the return value is a boolean success/failure indicator.
  • If a register is loaded with a constant before a call, the constant is an argument - and knowing common constant values reveals intent (e.g., 0x1f4 = 500, likely a timeout in milliseconds; AF_INET = 2 , SOCK_STREAM = 1 , IPPROTO_TCP = 6 are socket triplet).
  • If a function reads from a buffer in a loop and calls no other functions, it's likely a checksum, hash, or encoding function.

Handling Obfuscated Control Flow

Control flow flattening is the most common obfuscation. The compiler (or obfuscator) replaces structured control flow with a state machine:

// Original
while (i < 10) {
    if (cond) i++;
    else i += 2;
}

// Flattened
int state = 0;
while (1) {
    switch (state) {
        case 0: if (i >= 10) state = 3; else state = 1; break;
        case 1: if (cond) state = 2; else state = 4; break;
        case 2: i++; state = 0; break;
        case 3: return; break;
        case 4: i += 2; state = 0; break;
    }
}

In the CFG, this produces a single dispatcher block (containing the indirect jump through the jump table) and multiple "case handler" blocks that all jump back to the dispatcher. The dominator tree is flat - every handler block is immediately dominated by the dispatcher. There are no back-edges from inside the loop because the loop no longer exists structurally.

To recover the original logic from flattened control flow: 1. Identify the dispatcher block (indirect jump through table with loop variable in a register). 1. Track the state variable through case handlers. 1. Determine which state transitions are the original loop back-edges.

  1. Reconstruct by grouping state transitions into their original control structures.

This is an active research area. Tools like debins and GSoC-deobfuscation Ghidra plugin attempt automated recovery, but manual analysis is the fallback for heavily obfuscated code.

Go CFG Builder

This script reads objdump disassembly output, partitions it into basic blocks, identifies function boundaries, and builds a CFG with basic loop detection via back-edge analysis.

#!/usr/bin/env python3
"""cfg.py - Build CFG from objdump disassembly output."""

import re
import sys
from collections import defaultdict, namedtuple
from typing import Dict, List, Set, Tuple, Optional

Instruction = namedtuple('Instruction', ['address', 'mnemonic', 'operands', 'line'])
Block = namedtuple('Block', ['start', 'end', 'instructions', 'successors'])

def parse_objdump(objdump_output: str) -> Dict[int, Instruction]:
    """Parse objdump -d -M intel output into address->instruction map."""
    insns = {}
    pattern = re.compile(
        r'^\s*([0-9a-f]+):\s+((?:[0-9a-f]{2}\s+)+)?\s*(\w+)\s*(.*?)\s*$',
        re.IGNORECASE
    )
    for line in objdump_output.split('\n'):
        match = pattern.match(line.strip())
        if not match:
            continue
        addr = int(match.group(1), 16)
        mnemonic = match.group(3).lower()
        operands = match.group(4).strip() if match.group(4) else ''
        insns[addr] = Instruction(addr, mnemonic, operands, line.strip())
    return insns

def is_branch(mnemonic: str) -> bool:
    """Check if mnemonic is a conditional jump."""
    return mnemonic in {'je', 'jz', 'jne', 'jnz', 'jg', 'jnle',
                        'jge', 'jnl', 'jl', 'jnge', 'jle', 'jng',
                        'ja', 'jnbe', 'jae', 'jnb', 'jb', 'jnae',
                        'jbe', 'jna', 'js', 'jns', 'jo', 'jno',
                        'jp', 'jpe', 'jnp', 'jpo', 'jcxz', 'jecxz'}

def is_unconditional_jump(mnemonic: str) -> bool:
    return mnemonic == 'jmp' or mnemonic == 'jmpq'

def is_return(mnemonic: str) -> bool:
    return mnemonic in {'ret', 'retn', 'retf', 'iret', 'iretq', 'sysret'}

def resolve_operand_target(operands: str, current_addr: int) -> Optional[int]:
    """Resolve a hex operand (relative or absolute) to an absolute address."""
    match = re.search(r'(0x[0-9a-f]+)', operands, re.IGNORECASE)
    if not match:
        return None
    return int(match.group(1), 16)

def find_leaders(insns: Dict[int, Instruction]) -> Set[int]:
    """Identify basic block leaders."""
    sorted_addrs = sorted(insns.keys())
    leaders = set()
    leaders.add(sorted_addrs[0])

    for addr in sorted_addrs:
        insn = insns[addr]
        # Target of any jump is a leader
        target = resolve_operand_target(insn.operands, addr)
        if target and target in insns:
            leaders.add(target)

        # Instruction after a branch/jump/ret is a leader (fall-through)
        if is_branch(insn.mnemonic) or is_unconditional_jump(insn.mnemonic) \
                or is_return(insn.mnemonic) or insn.mnemonic == 'call':
            next_idx = sorted_addrs.index(addr) + 1
            if next_idx < len(sorted_addrs):
                leaders.add(sorted_addrs[next_idx])

    return leaders

def partition_blocks(insns: Dict[int, Instruction],
                     leaders: Set[int]) -> List[Block]:
    """Group instructions into basic blocks."""
    sorted_addrs = sorted(insns.keys())
    sorted_leaders = sorted(leaders)
    blocks = []

    for i, start in enumerate(sorted_leaders):
        if start not in insns:
            continue
        end_idx = sorted_leaders[i + 1] if i + 1 < len(sorted_leaders) else None
        block_addrs = []
        cursor = sorted_addrs.index(start)
        while cursor < len(sorted_addrs):
            addr = sorted_addrs[cursor]
            if end_idx and addr >= end_idx:
                break
            block_addrs.append(addr)
            insn = insns[addr]
            if is_branch(insn.mnemonic) or is_unconditional_jump(insn.mnemonic) \
                    or is_return(insn.mnemonic):
                break
            cursor += 1

        block_insns = [insns[a] for a in block_addrs if a in insns]
        if not block_insns:
            continue

        # Determine successors
        last = block_insns[-1]
        successors = set()

        target = resolve_operand_target(last.operands, last.address)
        if target and target in insns:
            successors.add(target)

        if is_branch(last.mnemonic):
            # Fall-through to next block
            block_end = block_addrs[-1]
            fallthrough = next((a for a in sorted_addrs if a > block_end), None)
            if fallthrough and fallthrough in insns:
                successors.add(fallthrough)
        elif not is_unconditional_jump(last.mnemonic) \
                and not is_return(last.mnemonic):
            # Natural fall-through to next instruction
            block_end = block_addrs[-1]
            fallthrough = next((a for a in sorted_addrs if a > block_end), None)
            if fallthrough and fallthrough in insns:
                successors.add(fallthrough)

        blocks.append(Block(start, block_addrs[-1], block_insns, successors))

    return blocks

def compute_dominators(blocks: List[Block], entry_idx: int) -> Dict[int, Set[int]]:
    """Compute dominator sets for each block."""
    n = len(blocks)
    all_indices = set(range(n))
    dom = {i: all_indices.copy() if i == entry_idx else set() for i in range(n)}
    dom[entry_idx] = {entry_idx}

    changed = True
    while changed:
        changed = False
        for i, block in enumerate(blocks):
            if i == entry_idx:
                continue
            # Predecessors: blocks that have this block as a successor
            preds = [j for j, b in enumerate(blocks)
                     if block.start in b.successors]
            # Also handle fall-through from previous block
            if i > 0 and blocks[i - 1].end + 1 >= block.start:
                preds.append(i - 1)

            if not preds:
                continue

            new_dom = dom[preds[0]].copy()
            for p in preds[1:]:
                new_dom &= dom[p]
            new_dom.add(i)

            if new_dom != dom[i]:
                dom[i] = new_dom
                changed = True
    return dom

def find_loops(blocks: List[Block],
               dom: Dict[int, Set[int]]) -> List[Tuple[int, List[int]]]:
    """Find natural loops via back-edge detection."""
    loops = []
    for i, block in enumerate(blocks):
        header = block.start
        for succ in block.successors:
            # Find index of successor block
            j = next((idx for idx, b in enumerate(blocks)
                      if b.start == succ), None)
            if j is None:
                continue
            # Back-edge: j dominates i (source)
            if i in dom.get(j, set()):
                # Natural loop body: all nodes that can reach i
                # without going through j
                loop_body = {j}
                stack = [i]
                while stack:
                    x = stack.pop()
                    if x not in loop_body:
                        loop_body.add(x)
                        preds = [idx for idx, b in enumerate(blocks)
                                 if blocks[x].start in b.successors]
                        for p in preds:
                            stack.append(p)
                loops.append((j, sorted(loop_body)))
    return loops

def print_cfg(blocks: List[Block], loops: List[Tuple[int, List[int]]]):
    """Pretty-print the CFG with annotated blocks."""
    loop_headers = {h for h, _ in loops}
    loop_body = set()
    for _, body in loops:
        loop_body |= set(body)

    for i, block in enumerate(blocks):
        flags = []
        if i in loop_headers:
            flags.append("LOOP_HEADER")
        if i in loop_body:
            flags.append("LOOP")

        flag_str = f" [{', '.join(flags)}]" if flags else ""
        print(f"\nBlock {i} @ 0x{block.start:x} - 0x{block.end:x} "
              f"({len(block.instructions)} insns){flag_str}")

        for insn in block.instructions:
            print(f"  0x{insn.address:x}: {insn.mnemonic:8s} {insn.operands}")

        succ_str = ", ".join(f"Block {next((idx for idx, b in enumerate(blocks) if b.start == s), '?')}" for s in block.successors)
        print(f"  -> {succ_str or '(exit)'}")

def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <function_name> [objdump_file]")
        print("  Reads objdump -d -M intel output from stdin or file")
        sys.exit(1)

    func_name = sys.argv[1]
    if len(sys.argv) > 2:
        with open(sys.argv[2]) as f:
            text = f.read()
    else:
        text = sys.stdin.read()

    # Extract function's disassembly from objdump output
    # Pattern: "0000000000401140 <func_name>:"
    func_pattern = re.compile(
        rf'^([0-9a-f]+)\s+<{re.escape(func_name)}>:',
        re.MULTILINE
    )
    match = func_pattern.search(text)
    if not match:
        print(f"Function '{func_name}' not found in objdump output")
        sys.exit(1)

    func_start = int(match.group(1), 16)

    # Find end of function (next symbol or empty line gap)
    lines = text[match.start():].split('\n')
    func_lines = []
    for line in lines:
        if line.strip() == '':
            break
        if re.search(r'^[0-9a-f]+\s+<', line) and func_lines:
            break
        func_lines.append(line)

    insns = parse_objdump('\n'.join(func_lines))
    if not insns:
        print("No instructions parsed")
        sys.exit(1)

    leaders = find_leaders(insns)
    blocks = partition_blocks(insns, leaders)

    entry_idx = next(i for i, b in enumerate(blocks) if b.start == func_start)
    dom = compute_dominators(blocks, entry_idx)
    loops = find_loops(blocks, dom)

    print(f"\n=== CFG for {func_name} ===\n")
    print(f"Basic blocks: {len(blocks)}")
    print(f"Loops detected: {len(loops)}")

    for header_idx, body in loops:
        print(f"  Loop header: Block {header_idx} (0x{blocks[header_idx].start:x})")
        print(f"  Body blocks:  {body}")

    print_cfg(blocks, loops)

if __name__ == '__main__':
    main()

Loop Detection Walkthrough

The authenticate function has two conditional branches. The CFG:

Block 0: prologue + strcmp(user, "root") + je -> Block 1 or Block 2
Block 1: return 0 (jmp -> Block 4)
Block 2: strcmp(pass, "1337haxor") + je -> Block 3 or Block 5
Block 3: return 1 (jmp -> Block 4)
Block 4: epilogue + ret (merge)
Block 5: return 0 (jmp -> Block 4)

No loops - the dominator tree shows Block 0 as root, all blocks dominated by it. No back-edges exist. The structure is strictly diamond-shaped (if-then-else).

Crypto Functions by CFG Shape

Crypto functions have distinctive CFG signatures:

Algorithm CFG Signature
AES-128 10 nearly identical blocks (rounds), each containing 16 sbox lookups (movzx; mov [base+idx]; xor)
CRC32 Single small block with lookup table access (movzx; xor; shr; mov [table+reg*4]) in a tight loop
MD5/SHA1 4 groups of 16 rounds, each group with different round constant; 4 state variables shifted
RC4 Tight loop: i = (i+1)&0xFF; j = (j+sbox[i])&0xFF; swap(sbox[i],sbox[j]); keystream = sbox[(sbox[i]+sbox[j])&0xFF]
Base64 3-byte-to-4-char conversion loop with repeated division by 64 (shr edx, 6 pattern) and lookup table

Crypto constants are easier to search for (see Ghidra Scripting article), but control flow confirms the algorithm after detection.

Challenge

Write a Go tool that reads objdump -d -M intel output and partitions each function into basic blocks. Identify leaders (function entry, jump targets, instructions after a jump or return), count the blocks per function, and report back-edges, which mark natural loop headers. Run it against a binary with a known loop and confirm the header you found.

package main

import (
	"bufio"
	"fmt"
	"os"
	"regexp"
	"sort"
	"strings"
)

var insnRe = regexp.MustCompile(`^\s*([0-9a-f]+):\s+(?:[0-9a-f]{2}\s+)+\s*([a-z][a-z0-9]*)\s*(.*)$`)
var targetRe = regexp.MustCompile(`([0-9a-f]+)\s`)

func isCondJump(m string) bool {
	return len(m) > 1 && m[0] == 'j' && m != "jmp" && m != "jmpq"
}

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	addresses := []uint64{}
	mnemonics := map[uint64]string{}
	targets := map[uint64]uint64{}
	for scanner.Scan() {
		m := insnRe.FindStringSubmatch(scanner.Text())
		if m == nil {
			continue
		}
		var addr uint64
		fmt.Sscanf(m[1], "%x", &addr)
		addresses = append(addresses, addr)
		mnemonics[addr] = m[2]
		if t := targetRe.FindStringSubmatch(m[3]); t != nil {
			var target uint64
			fmt.Sscanf(t[1], "%x", &target)
			targets[addr] = target
		}
	}
	if len(addresses) == 0 {
		fmt.Println("no instructions parsed")
		return
	}
	sort.Slice(addresses, func(i, j int) bool { return addresses[i] < addresses[j] })
	leaders := map[uint64]bool{addresses[0]: true}
	for i, addr := range addresses {
		m := mnemonics[addr]
		if target, ok := targets[addr]; ok {
			leaders[target] = true
		}
		if m == "jmp" || m == "ret" || isCondJump(m) {
			if i+1 < len(addresses) {
				leaders[addresses[i+1]] = true
			}
		}
	}
	leadersList := make([]uint64, 0, len(leaders))
	for addr := range leaders {
		leadersList = append(leadersList, addr)
	}
	sort.Slice(leadersList, func(i, j int) bool { return leadersList[i] < leadersList[j] })

	fmt.Printf("instructions: %d\n", len(addresses))
	fmt.Printf("basic blocks: %d\n", len(leadersList))
	var sb strings.Builder
	for i, header := range leadersList {
		sb.Reset()
		sb.WriteString(fmt.Sprintf("Block %d @ 0x%x:", i, header))
		next := uint64(0)
		if i+1 < len(leadersList) {
			next = leadersList[i+1]
		}
		count := 0
		for _, addr := range addresses {
			if addr >= header && (next == 0 || addr < next) {
				count++
			}
		}
		sb.WriteString(fmt.Sprintf(" %d insns", count))
		if target, ok := targets[header]; ok && target < header {
			sb.WriteString(" <- loop header (back-edge)")
		}
		fmt.Println(sb.String())
	}
}
