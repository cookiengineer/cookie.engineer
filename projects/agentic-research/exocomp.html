Exocomp

Overview

GitHub Repository | GitLab Mirror

Exocomp is an Agentic Environment that is tailored to Malware Reverse Engineering, Purpleteaming, and Golang. It is an IDE written in Golang, for Golang, and with Golang.

The Exocomp environment has been used to combat various malware and supply-chain worm campaigns in 2026, as its primary focus is reverse engineering malware samples and creating counter payloads to defeat malware on a network scale. Think of it as an IDE giving you the necessary tools to rapidly develop counter payloads to ongoing APT malware campaigns.

An example of such a generated counter payload is the Antimiasma mitigation tool, which has also been successfully deployed as a self-vaccinating counter-worm.

Features

  • Self-hosted OpenAI API compatibility
  • Made for abliterated qwen3-coder and qwen3.6 A3B models
  • Planner/Orchestrator architecture
  • Sandboxed and Unit-Tested Agent Tools
  • Multi-Agent Lifecycle environment
  • Specialized short-lived agents to save context window size
  • Dedicated Agent Hiring workflows

Requirements

Its architecture allows to use everything self-hosted, it is compatible with ollama and llama.cpp servers and uses the OpenAI API for maximum compatibility. As the nature of cyber security related tasks requires abliterated models that have been retrained with heretic , these are the recommended system requirements for the best experience:

  • qwen3.6:35b A3B heretic model
  • 96GB dedicated CPU RAM
  • 48GB dedicated GPU VRAM
  • q8 Keys cache
  • f16 Values cache
  • 262144 Context Window length

Installation

The LLM inference server needs to fulfill the above requirements. The development host machine doesn't need to fulfill those requirements and can run on fairly low system specifications without issues. In any case, the faster the memory and storage drives, the better.

  1. Install llama.cpp .
  2. Create the folders /opt/llamacpp/configs and /opt/llamacpp/models .
  3. Install the Q8 quantized GGUF file of the Qwen3.6:35b heretic model from huggingface.
  4. If no abliterated or hereticed model quantizations were available, run heretic manually on your server. This might take a few hours.

Model Configuration

The Exocomp workflow currently requires either of two different models to run on the inference server. The newer and recommended model is qwen3.6:35b , and the older supported model is qwen3-coder:30b . In both cases the model needs to be abliterated and use the hereticed model weights.

The recommended Qwen3.6 llama.cpp configuration:

; llama.cpp config for Qwen3.6-35B-A3B (Q8_0)
; save as /opt/llamacpp/configs/qwen3.6.ini

version = 1

[qwen3.6-35b]
model = /opt/llamacpp/models/Qwen3.6-35B-A3B-heretic-Q8_0.gguf
c = 262144
b = 2048
ub = 2048
t = 8
ngl = 999
flash-attn = on
no-mmap = true
cache-type-k = q8_0
cache-type-v = f16
embeddings = true
pooling = last
jinja = true
load-on-startup = true

Usage

On your LLM inference server, start the llama-server . 

/opt/llamacpp/bin/llama-server --models-preset /opt/llamacpp/qwen3.6.ini;

On your IDE host machine, start exocomp with the correct URL parameter. 

exocomp webview --role="planner" --model="qwen3.6-35b" --url="http://inference-server-ip:11434/v1";
