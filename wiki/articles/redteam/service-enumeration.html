Service Enumeration

Service version detection, NSE scripts, protocol-specific enumeration for SSH , FTP , SMTP , DNS , HTTP , My SQL , Redis, SMB , and SNMP .

Overview

Service enumeration identifies what is listening behind each open port and how it is configured, which decides whether a port is a dead end or an entry point. After reading this article you can run version detection, choose the right NSE scripts, and probe SSH , FTP , SMTP , DNS , HTTP , My SQL , Postgre SQL , Redis, SMB , and SNMP by hand.

The Service Discovery Problem

Port scanning tells you which doors are open. Service enumeration tells you what is behind each door and whether it is vulnerable. An open TCP port 80 could be Apache httpd 2.4.6 from 2013, nginx 1.26.1 from last week, or a custom Python web server written by an intern. The version determines your next move.

Service enumeration has two approaches:

Approach Method Speed Accuracy Detection Risk
Banner-based Read the service's greeting string Fast Low (spoofable) Low (normal connection)
Behavior-based Probe with specific payloads, measure responses Slow High Medium (malformed payloads)

Banners are aspirational: they say what the service claims to be. Behavior-based detection measures what the service actually does. A misconfigured nginx can claim to be Apache. A patched Apache with backported fixes looks vulnerable to a banner-based scanner but is not.

nmap Service Version Detection (-sV)

nmap's -sV uses a probe database ( nmap-service-probes ) containing~6800 probes. It sends protocol-specific queries to open ports and pattern-matches the responses against known service signatures. 

# Basic version detection
nmap -sV 10.10.0.5

# Aggressive version detection — more probes, higher probability of correct match
nmap -sV --version-intensity 9 10.10.0.5
# Intensity scale: 0 (light, only most common probes) to 9 (all probes)
# Default: 7

# All probes (intensity 9 equivalent)
nmap -sV --version-all 10.10.0.5

# Combine with port scan for a complete picture
nmap -sS -sV -p- --min-rate 1000 10.10.0.5 -oA full-scan

# Limit version detection to specific ports (saves time)
nmap -sS -p- 10.10.0.5 -oA sweep && \
  grep 'portid.*open' sweep.xml | grep -oP 'portid="\K[^"]+' | sort -nu | \
  tr '\n' ',' | xargs -I{} nmap -sV -p {} 10.10.0.5 -oA service-scan

How nmap-service-probes Works

The probe file ( /usr/share/nmap/nmap-service-probes ) defines structured queries. Each probe has a protocol type ( TCP / UDP ), a probe string (hex or ASCII), and a set of match patterns (regex against response). 

# Example probe from nmap-service-probes (simplified)
Probe TCP GetRequest q|GET / HTTP/1.0\r\n\r\n|
match http m|^HTTP/1\.[01] \d\d\d .*\r\nServer: ([^\r\n]+)|s p/Apache httpd/ v/$1/
match http m|^HTTP/1\.[01] \d\d\d .*\r\nServer: nginx/([\d.]+)|s p/nginx/ v/$1/
match http m|^HTTP/1\.[01] \d\d\d .*\r\nX-Powered-By: PHP/([\d.]+)|s p/PHP/ v/$1/

Probe TCP NULL q||
# Empty probe — waits for server to send banner first (SMTP, SSH, FTP)
						
# View the probe database
wc -l /usr/share/nmap/nmap-service-probes
# ~16,000 lines, ~6,800 probes, ~20,000 match patterns

# grep for probes related to a service
grep -A 10 'Probe TCP.*mysql\|Probe TCP.*ssh\|Probe TCP.*smtp' /usr/share/nmap/nmap-service-probes

NSE Scripts for Service Enumeration

Nmap Scripting Engine (NSE) provides Lua scripts for protocol-specific enumeration beyond version detection. Scripts are categories: default , safe , discovery , version , vuln , exploit . 

# Default safe scripts — basic information gathering
nmap -sV --script=default 10.10.0.5

# Discovery scripts — deeper enumeration, higher noise
nmap -sV --script=discovery 10.10.0.5

# All scripts matching a category or name pattern
nmap -sV --script='http-*' 10.10.0.5        # all HTTP-related scripts
nmap -sV --script='ssl-*' 10.10.0.5         # all SSL/TLS scripts
nmap -sV --script='smb-*' 10.10.0.5         # all SMB scripts
nmap -sV --script='ftp-*' -p 21 10.10.0.5   # all FTP scripts

# List available scripts in a category
ls /usr/share/nmap/scripts/ | grep ^http- | head -20

Protocol-by-Protocol Enumeration

Automated tools are fast. Manual enumeration is precise. Below is protocol-by-protocol manual enumeration: every command produces output you would see in a real engagement.

SSH (TCP 22)

The SSH protocol exchanges version strings before any crypto negotiation. This is the server's only unencrypted output. 

# Read the SSH banner directly
nc 10.10.0.5 22 <<< ''
# SSH-2.0-OpenSSH_7.4
# → OpenSSH version 7.4. This version shipped with RHEL/CentOS 7.

# nmap SSH scripts
nmap -sV -p 22 --script='ssh-auth-methods,ssh-hostkey,ssh2-enum-algos' 10.10.0.5

# OpenSSH version ↔ OS mapping (rough):
# 6.6p1   — RHEL/CentOS 7.0
# 7.4p1   — RHEL/CentOS 7.x, Debian 9 (Stretch)
# 7.9p1   — Debian 10 (Buster)
# 8.4p1   — Debian 11 (Bullseye)
# 8.9p1   — Ubuntu 22.04 LTS
# 9.3p1   — Ubuntu 23.10
# 9.6p1   — Ubuntu 24.04 LTS

# Enumerate supported authentication methods
nmap -p 22 --script ssh-auth-methods 10.10.0.5
# If "publickey" is shown, try the host key fingerprint:
nmap -p 22 --script ssh-hostkey --script-args ssh_hostkey=full 10.10.0.5

# Enumerate SSH algorithms — reveals server age and crypto posture
nmap -p 22 --script ssh2-enum-algos 10.10.0.5
# Old algorithms (ssh-dss, diffie-hellman-group1-sha1) = old server or misconfiguration
						
# Manual SSH banner via Python (handles timeouts gracefully)
python3 -c "
import socket
s = socket.socket()
s.settimeout(3)
s.connect(('10.10.0.5', 22))
print(s.recv(256).decode().strip())
s.close()
"

# Manual SSH algorithm enumeration with nmap nse output parsing
nmap -p 22 --script ssh2-enum-algos 10.10.0.5 -oX - | \
  xmlstarlet sel -t -v '//script[@id="ssh2-enum-algos"]/@output'

FTP (TCP 21)

FTP is one of the most verbose protocols. The 220 banner, FEAT response, and anonymous login attempt all reveal configuration details. 

# Banner grab — FTP sends the 220 greeting immediately on connect
nc 10.10.0.5 21 <<< ''
# 220 (vsFTPd 3.0.3) ← vsFTPd, version 3.0.3
# 220 ProFTPD 1.3.5 Server ← ProFTPD
# 220 Microsoft FTP Service ← IIS FTP

# FEAT command — lists supported FTP extensions
printf 'FEAT\r\n' | nc -w 3 10.10.0.5 21
# 211-Features:
#  EPSV
#  MDTM
#  UTF8
#  AUTH TLS
# → AUTH TLS supported = FTPS capable

# Anonymous login attempt
printf 'USER anonymous\r\nPASS anonymous\r\n' | nc -w 3 10.10.0.5 21
# 230 Login successful ← anonymous FTP enabled, immediate finding
# 530 Login incorrect ← anonymous disabled

# nmap FTP scripts
nmap -p 21 --script='ftp-anon,ftp-bounce,ftp-syst,ftp-vsftpd-backdoor' 10.10.0.5

# ftp-syst — system information
printf 'SYST\r\n' | nc -w 3 10.10.0.5 21
# 215 UNIX Type: L8 ← Unix/Linux server

SMTP (TCP 25, 465, 587)

SMTP supports user enumeration via VRFY and EXPN. These commands are disabled on modern servers but frequently found on internal mail relays. 

# SMTP banner
nc 10.10.0.5 25 <<< ''
# 220 mail.target.com ESMTP Postfix (Ubuntu)

# EHLO — Extended Hello, smtp server capabilities
printf 'EHLO test\r\n' | nc -w 3 10.10.0.5 25
# 250-STARTTLS
# 250-AUTH LOGIN PLAIN
# 250 PIPELINING
# → STARTTLS supported, AUTH mechanisms exposed

# VRFY — verify user exists
printf 'VRFY root\r\n' | nc -w 3 10.10.0.5 25
# 252 2.0.0 root ← user exists
# 550 5.1.1 User unknown ← does not exist
# 252 2.0.0 Cannot VRFY ← VRFY disabled

# EXPN — expand mailing list
printf 'EXPN mail-list\r\n' | nc -w 3 10.10.0.5 25

# RCPT TO — recipient verification (connects, sends MAIL FROM, RCPT TO)
printf 'MAIL FROM: <test@test.com>\r\nRCPT TO: <user@target.com>\r\nQUIT\r\n' | nc -w 3 10.10.0.5 25
# 250 2.1.5 OK ← recipient exists
# 550 5.1.1 User unknown ← doesn't exist

# nmap SMTP scripts
nmap -p 25,465,587 --script='smtp-commands,smtp-enum-users,smtp-open-relay' 10.10.0.5

# smtp-user-enum — dedicated user enumeration tool
smtp-user-enum -M VRFY -u root -t 10.10.0.5
smtp-user-enum -M RCPT -u root -t 10.10.0.5
smtp-user-enum -M EXPN -u root -t 10.10.0.5

DNS (TCP/UDP 53)

DNS servers expose version information via the version.bind CHAOS query. Recursion settings tell you if the server can be used for DNS amplification attacks or if it can resolve internal hostnames. 

# Version query — CHAOS class, TXT record for version.bind
dig @10.10.0.5 version.bind CHAOS TXT +short
# "9.11.4-P2-RedHat-9.11.4-26.P2.el7_9.10" ← BIND 9.11.4 on RHEL 7.9
# "dnsmasq-2.85"
# "" ← version.bind disabled, good security practice

# Recursion test — can this DNS server resolve external domains?
dig @10.10.0.5 google.com A +short
# If you get an answer: recursion enabled
# If you get a referral (NS records): recursion disabled, it's an authoritative server only

# Recursion enabled is a finding: potential for DNS amplification attacks
# or for resolving internal hostnames when pivoting.

# Zone transfer attempt
dig @10.10.0.5 target.com AXFR
# If you get a zone dump: critical finding, misconfigured nameserver
# "Transfer failed" or "REFUSED": zone transfers restricted (correctly configured)

# nmap DNS scripts
nmap -p 53 --script='dns-nsid,dns-recursion,dns-service-discovery,dns-zone-transfer' 10.10.0.5

# dnsrecon — comprehensive DNS enumeration
dnsrecon -d target.com -t axfr -n 10.10.0.5        # zone transfer
dnsrecon -d target.com -t rvl -n 10.10.0.5         # reverse lookup
dnsrecon -d target.com -t brt -n 10.10.0.5         # brute force subdomains

HTTP/HTTPS (TCP 80, 443, 8080, 8443)

HTTP is the richest information source. Every request, every header, every error page leaks data. 

# Full HTTP response headers — the Server, X-Powered-By, and Set-Cookie headers
curl -sI https://10.10.0.5 | tee http-headers.txt
# Server: Apache/2.4.6 (CentOS) ← specific version + OS
# X-Powered-By: PHP/5.4.16 ← PHP version (EOL since 2015)
# Set-Cookie: PHPSESSID=... ← PHP session

# Analyze all headers systematically
curl -sIL https://10.10.0.5 | grep -iE 'server|x-powered|set-cookie|x-frame|x-content|content-security|strict-transport'

# OPTIONS method — what HTTP methods does the server support?
curl -sI -X OPTIONS https://10.10.0.5
# Allow: GET, HEAD, POST, OPTIONS, PUT, DELETE, TRACE
# TRACE + Allow header = potential Cross-Site Tracing (XST)
# PUT + DELETE = potential WebDAV misconfiguration

# TRACE method — echo back request (debugging)
curl -sI -X TRACE https://10.10.0.5

# Directory listing — is autoindex enabled?
curl -sI https://10.10.0.5/icons/ 2>/dev/null
# 200 OK + Apache autoindex content = directory listing enabled

# Common paths that leak server info
curl -sI https://10.10.0.5/phpinfo.php       # PHP configuration dump
curl -sI https://10.10.0.5/server-status     # Apache mod_status
curl -sI https://10.10.0.5/server-info       # Apache mod_info
curl -sI https://10.10.0.5/.env              # Laravel env file
curl -sI https://10.10.0.5/actuator/health   # Spring Boot Actuator
curl -sI https://10.10.0.5/.git/HEAD         # exposed .git directory

# nmap HTTP scripts
nmap -p 80,443 --script='http-enum,http-headers,http-methods,http-php-version,http-title,http-server-header' 10.10.0.5

# nikto — comprehensive web server scanner
nikto -h https://10.10.0.5 -output nikto-scan.txt
						
# TLS enumeration — what ciphers and protocols does the server support?
nmap -p 443 --script='ssl-enum-ciphers,ssl-cert,ssl2-enum-ciphers' 10.10.0.5

# Manual TLS version testing
for proto in ssl3 tls1 tls1_1 tls1_2 tls1_3; do
  result=$(openssl s_client -connect 10.10.0.5:443 -"$proto" -servername 10.10.0.5 \
    </dev/null 2>/dev/null)
  if echo "$result" | grep -q 'BEGIN CERTIFICATE'; then
    cipher=$(echo "$result" | grep -E '^\s+Cipher\s+:' | sed 's/.*://' | tr -d ' ')
    echo "[+] $proto — SUPPORTED ($cipher)"
  else
    echo "[-] $proto — NOT SUPPORTED"
  fi
done

# Check for specific weak ciphers
for cipher in 'RC4-MD5' 'RC4-SHA' 'DES-CBC3-SHA' 'EXP-RC4-MD5'; do
  result=$(openssl s_client -connect 10.10.0.5:443 -cipher "$cipher" </dev/null 2>/dev/null)
  if echo "$result" | grep -q 'BEGIN CERTIFICATE'; then
    echo "[!] WEAK CIPHER ACCEPTED: $cipher"
  fi
done

MySQL (TCP 3306)

My SQL sends a protocol handshake packet before authentication. This contains the server version, capabilities flags, and authentication plugin information. 

# MySQL version — the handshake packet contains the server version
mysql -h 10.10.0.5 -u root --password=badpassword 2>&1 | head -1
# ERROR 1045 (28000): Access denied for user 'root'@'10.0.0.100' (using password: YES)
# → Server is MySQL, root account exists, password auth required

# nmap MySQL script
nmap -p 3306 --script='mysql-info' 10.10.0.5
# Output includes: Version, Protocol, Capabilities, Status, Salt

# MySQL version probe via Python (reads the handshake packet)
python3 -c "
import socket, struct
s = socket.socket()
s.settimeout(3)
s.connect(('10.10.0.5', 3306))
data = s.recv(1024)
# MySQL handshake packet header: 4 bytes length + 1 byte sequence ID
proto_version = data[4]
# Server version is null-terminated, starting at offset 5
end = data.index(b'\x00', 5)
version = data[5:end].decode()
print(f'Protocol: {proto_version}')
print(f'Version: {version}')
s.close()
"

# nmap MySQL scripts for auth testing
nmap -p 3306 --script='mysql-empty-password,mysql-databases,mysql-users' \
  --script-args='mysqluser=root,mysqlpass=' 10.10.0.5

PostgreSQL (TCP 5432)

Postgre SQL uses a binary protocol. The startup packet triggers either an authentication request or an error. 

# nmap PostgreSQL scripts
nmap -p 5432 --script='pgsql-brute' 10.10.0.5

# Manual PostgreSQL version check via psql
psql -h 10.10.0.5 -U postgres -c 'SELECT version();' 2>&1
# If password prompt appears: server is reachable, user exists
# If "FATAL: no pg_hba.conf entry": server reachable, but you're not in allowed IP range

# PostgreSQL version via Python
python3 -c "
import socket, struct
s = socket.socket()
s.settimeout(3)
s.connect(('10.10.0.5', 5432))
# PostgreSQL StartupMessage: int32 length + int32 protocol + params
# The length field counts itself (4) plus the protocol (4) plus the params.
params = b'user\x00postgres\x00database\x00postgres\x00\x00'
startup = struct.pack('>II', 8 + len(params), 3 << 16) + params
s.send(startup)
data = s.recv(1024)
msg_type = data[0:1]
if msg_type == b'R':
    print('Authentication required — server is PostgreSQL (live)')
elif msg_type == b'E':
    print(f'Error: {data[1:].decode(errors=\"replace\")}')
else:
    print(f'Response type: {msg_type}')
s.close()
"

Redis (TCP 6379)

Redis is plain-text and extremely informative. The PING, INFO, and CONFIG commands reveal the server state. 

# Redis PING — basic liveness check
printf 'PING\r\n' | nc -w 3 10.10.0.5 6379
# +PONG ← server is Redis, accepting commands, no authentication required

# Redis INFO — everything about this Redis instance
printf 'INFO\r\n' | nc -w 3 10.10.0.5 6379 | head -40
# redis_version:6.0.16
# os:Linux 5.4.0-150-generic x86_64
# redis_mode:standalone
# connected_clients:3
# used_memory_human:2.15M

# Redis CONFIG — read server configuration
printf 'CONFIG GET *\r\n' | nc -w 3 10.10.0.5 6379 | head -40
# If this works without a password: critical finding
# Includes: bind address, port, dir, dbfilename (can be abused for RCE)

# Redis KEYS — enumerate all keys
printf 'KEYS *\r\n' | nc -w 3 10.10.0.5 6379

# Redis AUTH — test common passwords
printf 'AUTH password\r\n' | nc -w 3 10.10.0.5 6379
# +OK ← authenticated

# nmap Redis scripts
nmap -p 6379 --script='redis-info' 10.10.0.5

SMB (TCP 139, 445)

SMB is a binary protocol with multiple dialects. Enumeration reveals the OS version, domain name, and available shares. 

# nmap SMB scripts
nmap -p 139,445 --script='smb-os-discovery,smb-protocols,smb-security-mode,smb-enum-shares,smb-enum-users' 10.10.0.5

# smb-os-discovery — operating system detection via SMB
# smb-protocols — negotiated SMB dialect (SMBv1 through v3)
# smb-security-mode — signing required? message signing yes/no
# smb-enum-shares — list available shares including hidden ones ($)
# smb-enum-users — domain users (requires credentials)

# enum4linux — comprehensive SMB enumeration (Perl, older but thorough)
pacman -S enum4linux
enum4linux 10.10.0.5
enum4linux -U 10.10.0.5    # user list
enum4linux -S 10.10.0.5    # share list
enum4linux -O 10.10.0.5    # OS detection
enum4linux -P 10.10.0.5    # password policy

# smbclient — list shares without credentials
smbclient -L //10.10.0.5 -N
# Anonymous login successful ← null session allowed, significant finding
# Sharename       Type      Comment
# ---------       ----      -------
# ADMIN$          Disk      Remote Admin
# C$              Disk      Default share
# IPC$            IPC       Remote IPC
# Users           Disk      ← accessible share without authentication

# Connect to a share
smbclient //10.10.0.5/Users -N
# smb: \> ls
# smb: \> get confidential.xlsx
						
# SMB protocol version — important for exploit selection
nmap -p 445 --script smb-protocols 10.10.0.5
# SMBv1 enabled → EternalBlue (MS17-010) candidate
# SMBv1 disabled → modern server, look for SMB signing issues

# Check SMB signing
nmap -p 445 --script smb-security-mode 10.10.0.5
# message_signing: disabled ← relay attack possible
# message_signing: enabled and required ← relay not possible

SNMP (UDP 161)

SNMP is the "keys to the kingdom" protocol. A readable community string exposes system configuration, network interfaces, running processes, and installed software. 

# SNMP walk with community string "public"
snmpwalk -v1 -c public 10.10.0.5 1.3.6.1.2.1.1.5.0
# iso.3.6.1.2.1.1.5.0 = STRING: "server01.internal"
# → hostname exposed

# System information
snmpwalk -v1 -c public 10.10.0.5 system
# sysDescr: Linux server01 5.4.0-150-generic #167-Ubuntu SMP
# → OS, kernel version, distribution

# Network interfaces — all IPs, MACs, traffic counters
snmpwalk -v1 -c public 10.10.0.5 1.3.6.1.2.1.2.2.1.2
# iso.3.6.1.2.1.2.2.1.2.1 = STRING: "lo"
# iso.3.6.1.2.1.2.2.1.2.2 = STRING: "eth0"

# Running processes
snmpwalk -v1 -c public 10.10.0.5 1.3.6.1.2.1.25.4.2.1.2
# Lists every running process name by PID

# Installed software
snmpwalk -v1 -c public 10.10.0.5 1.3.6.1.2.1.25.6.3.1.2
# Lists every installed package

# Community string brute force
onesixtyone -c /usr/share/seclists/Discovery/SNMP/common-snmp-community-strings.txt 10.10.0.5
# onesixtyone — fast SNMP community scanner (~1 million strings/sec)

# nmap SNMP scripts
nmap -sU -p 161 --script='snmp-interfaces,snmp-processes,snmp-sysdescr,snmp-info' 10.10.0.5

Service Enumeration Workflow

A complete service enumeration follows a repeatable, parallelizable process:

#!/bin/bash
# service-enum.sh — standard service enumeration workflow
TARGET="$1"
OUTDIR="enum-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$OUTDIR"

echo "[*] Phase 1: Port scan (SYN, top 10000 ports)"
nmap -sS -T4 --top-ports 10000 "$TARGET" -oA "$OUTDIR/1-port-scan" -n

echo "[*] Phase 2: Service version detection on open ports"
OPEN_PORTS=$(grep 'portid=.*state=.open' "$OUTDIR/1-port-scan.xml" | \
  grep -oP 'portid="\K[^"]+' | sort -nu | tr '\n' ',' | sed 's/,$//')
if [ -n "$OPEN_PORTS" ]; then
  nmap -sV -p "$OPEN_PORTS" "$TARGET" -oA "$OUTDIR/2-service-versions"
fi

echo "[*] Phase 3: NSE default scripts on discovered services"
if [ -n "$OPEN_PORTS" ]; then
  nmap -sV -p "$OPEN_PORTS" --script=default "$TARGET" -oA "$OUTDIR/3-nse-default"
fi

echo "[*] Phase 4: Protocol-specific enumeration"
# SSH
grep -q '22/open' "$OUTDIR/2-service-versions.nmap" && {
  nmap -sV -p 22 --script='ssh-auth-methods,ssh2-enum-algos,ssh-hostkey' \
    "$TARGET" -oA "$OUTDIR/4-ssh-enum"
  nc "$TARGET" 22 <<< '' > "$OUTDIR/4-ssh-banner.txt" 2>&1
}

# HTTP/HTTPS
for port in $(grep -oP '(80|443|8080|8443)/open' "$OUTDIR/2-service-versions.nmap" | \
  cut -d'/' -f1); do
  scheme="http"
  [ "$port" = "443" ] || [ "$port" = "8443" ] && scheme="https"
  curl -sI "$scheme://$TARGET:$port" > "$OUTDIR/4-http-$port-headers.txt" 2>&1
  curl -sI -X OPTIONS "$scheme://$TARGET:$port" >> "$OUTDIR/4-http-$port-options.txt" 2>&1
done

# FTP
grep -q '21/open' "$OUTDIR/2-service-versions.nmap" && {
  printf 'FEAT\r\n' | nc -w 3 "$TARGET" 21 > "$OUTDIR/4-ftp-feat.txt" 2>&1
  printf 'USER anonymous\r\nPASS anonymous\r\n' | nc -w 3 "$TARGET" 21 > "$OUTDIR/4-ftp-anon.txt" 2>&1
}

# SMB
grep -q '445/open' "$OUTDIR/2-service-versions.nmap" && {
  enum4linux "$TARGET" > "$OUTDIR/4-smb-enum4linux.txt" 2>&1
  smbclient -L "//$TARGET" -N > "$OUTDIR/4-smb-shares.txt" 2>&1
}

# Redis
grep -q '6379/open' "$OUTDIR/2-service-versions.nmap" && {
  printf 'PING\r\nINFO\r\n' | nc -w 3 "$TARGET" 6379 > "$OUTDIR/4-redis-info.txt" 2>&1
}

# SNMP
grep -q '161/open' "$OUTDIR/2-service-versions.nmap" && {
  snmpwalk -v1 -c public "$TARGET" system > "$OUTDIR/4-snmp-system.txt" 2>&1
}

echo "[*] Enumeration complete. Results in $OUTDIR/"

Verification

# Verify: nmap correctly identifies the HTTP server version
grep -E 'http-server-header|http-generator' service-scan.xml

# Verify: SSH version matches the OS expectation
# If OpenSSH says 7.4 → probably CentOS/RHEL 7.4
# Cross-reference with OS detection: nmap -O 10.10.0.5

# Verify: banner vs behavior — is the service lying?
# Compare nmap -sV output against manual banner grab
# If nginx reports itself nginx but manual grab says Apache → modified banner

# Verify: multiple services on same host indicate VM/container
# Windows: 135, 139, 445, 3389 all open = likely Windows host
# Linux: 22 (SSH) + 25 (SMTP) + 80/443 (HTTP) = likely web/mail server
# Database-only: 3306, 5432 open but no web ports = database server (high value target)

Troubleshooting

  1. nmap shows port as open|filtered: Firewall is dropping packets silently. Try -sT (connect scan) instead of -sS ( SYN scan). Connect scan uses the OS TCP stack, which may retransmit differently.
  2. Service detection returns no match: Service is on a non-standard port or uses a custom protocol. Try --version-all to send all probes.
  3. nmap cannot determine SSH version: SSH version string sent before crypto negotiation. If nothing received, port is open but protocol is not SSH . Try netcat to read raw response.
  4. SMB scripts require credentials: Many SMB enumeration scripts need authentication. Try null session ( smbclient -N ) first. If blocked, note "null session disabled" in report.
  5. Redis INFO works without AUTH: This is a finding. Redis without authentication allows reading and writing all data. Immediate reportable vulnerability.
