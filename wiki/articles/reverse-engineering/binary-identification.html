Binary Identification

Identify unknown binaries through magic bytes, hashing, entropy analysis, and packer detection.

Overview

Before you can reverse engineer a binary, you have to know what it is. This article shows how to identify an unknown file statically, without executing it, using magic bytes, cryptographic and fuzzy hashes, entropy measurement, and packer detection. After reading it you can triage a sample and decide which analysis path to take next.

Required Reading

  • ELF - ELF format structure, sections, segments, and dynamic linking
  • Filesystems - how file metadata, types, and attributes work at the OS level

The Unknown Binary

You have downloaded a file. It has no extension, no documentation, and no clear origin. Maybe it arrived in a tarball from an untrusted source. Maybe you recovered it from a compromised system during incident response. Maybe it was dropped by a process you caught behaving strangely. Your first step is always the same: identify what kind of file this is without executing it.

Under no circumstances do you run an unknown binary. Everything in this article operates on dead bytes - static analysis only. The moment you execute, you surrender control.

File: The First 10 Seconds

$ file unknown.bin
unknown.bin: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 2.6.32, stripped

file is not looking at the extension. It reads magic bytes - fixed byte sequences at specific offsets that identify formats. The magic database lives at /usr/share/file/magic/ . Each format specification declares an offset, a byte pattern, and a MIME type.

$ file -v unknown.bin

-v prints exactly which magic entries matched. This reveals the detection chain:

>>> 0xb
[    0] == 0x7F
[    1] == 0x45
[    2] == 0x4C
[    3] == 0x46
>>> ELF, offset 0x10
[    0] == 0x02
>>> ELF 64-bit

The magic database parses recursively. For ELF, after matching \x7fELF , it reads byte 4 ( EI_CLASS ) for 32/64-bit, byte 5 ( EI_DATA ) for endianness, byte 16 ( e_type ) for executable/shared/relocatable. For PE, it matches MZ at offset 0, then seeks to offset 0x3C to find the PE signature PE\0\0 .

Manual Magic Byte Check

When file is unavailable (embedded systems, constrained containers), check manually with xxd or od :

$ xxd -l 32 unknown.bin
00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000  .ELF............
00000010: 0200 3e00 0100 0000 0005 4000 0000 0000  ..>.......@.....

The first 4 bytes ( 7f 45 4c 46 ) are .ELF . Byte 4 ( 02 ) = 64-bit. Byte 5 ( 01 ) = little-endian. \x02\x00 at offset 0x10 = ET_EXEC (executable). Without file , cross-reference the table above.

$ python3 -c "
import sys
data = open(sys.argv[1], 'rb').read(4)
print(data.hex(), '->', repr(data))
" unknown.bin

Hashing Fingerprints

A cryptographic hash uniquely identifies a byte sequence. In malware analysis, hashes serve three purposes:

  1. IoC creation : Distribute the hash to blocklists, firewall rules, and AV signatures.
  2. Detection : Check unknown files against VirusTotal or internal malware databases.
  3. Family clustering : Variants of the same family produce different hashes - but fuzzy hashes group them.

SHA-256 (Primary)

$ sha256sum unknown.bin
a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2  unknown.bin

SHA-256 is the current standard for malware IoCs. It is collision-resistant enough that identical hashes mean identical files. VirusTotal accepts SHA-256 lookups. The hash represents the exact bytes

  • if the malware author changes one byte (recompile, different config, different C2

), the SHA-256 changes completely.

MD5 and SHA-1 (Legacy)

$ md5sum unknown.bin
d41d8cd98f00b204e9800998ecf8427e  unknown.bin

$ sha1sum unknown.bin
da39a3ee5e6b4b0d3255bfef95601890afd80709  unknown.bin

MD5 and SHA-1 are broken for cryptographic purposes (collisions can be generated) but remain useful for fuzzy matching across older malware databases. Many legacy threat intel feeds still index by MD5. Generate them for compatibility, but rely on SHA-256 for identification.

SSDeep: Fuzzy Hashing

Two variants of the same malware - different C2 domain, different compilation flags - produce different SHA-256 hashes. SSDeep detects that they share a common ancestor.

$ pacman -S ssdeep
$ ssdeep unknown_v1.bin unknown_v2.bin
ssdeep,1.1--blocksize:hash:hash,filename
384:S6fG8HjK9LmN2pQr3sTu4vWx5yZ6aB7c:S6fG8HjK9LmN2pQr3sTu4v,"unknown_v1.bin"
384:S6fG8HjK9LmN2pQr3sTu4vWx5yZ6aB7c:S6fG8HjK9LmN2pQr3sTu4v,"unknown_v2.bin"

SSDeep divides the file into blocks, hashes each block with a rolling hash (FV hash), and concatenates the results. Blocksize adjusts based on file size. Two similar files produce similar ssdeep hashes.

$ ssdeep -c unknown_v1.bin unknown_v2.bin
unknown_v2.bin matches unknown_v1.bin (99)

A score of 99 means 99% similarity - almost certainly variants. A score of 20 or below means unrelated. The threshold for "same family" is typically 30-40.

Generating multiple ssdeep comparisons:

$ ssdeep -r -d malware_directory/ > signatures.ssdeep
$ ssdeep -m signatures.ssdeep new_sample.bin
new_sample.bin matches malware_directory/trojan_abc.bin (88)

TLSH: Locality Sensitive Hash

TLSH (Trend Micro Locality Sensitive Hash) is designed for file similarity. It is more robust than ssdeep against certain byte-level mutations.

$ pacman -S tlsh-tools
$ tlsh -f unknown.bin
T1ABCD1234EFGH5678IJKL9012MNOP3456QRST7890UVWX1234YZAB5678CDEF9012

TLSH produces a fixed-length hex string. The distance between two TLSH hashes indicates similarity:

$ tlsh -c unknown_v1.bin unknown_v2.bin
distance: 42

Distances below 30 are very similar; distances above 100 are dissimilar. TLSH handles insertion and deletion better than ssdeep.

Imphash: PE Import Hash

Imphash is specific to Windows PE files. It hashes the import table ( DLL

  • function name, case-insensitive and sorted). The idea: different variants of the same malware

use the same API imports. Even if the payload is repacked or the binary is recompiled, the imports stay the same.

$ python3 -c "
import pefile
pe = pefile.PE('unknown.exe')
print(pe.get_imphash())
"
6f5d6f5d6f5d6f5d6f5d6f5d6f5d6f5d

Two PEs with identical imphash import the same set of functions - strong indicator they share source code or builder. Imphash is useless for packed binaries (UPX strips imports, the stub resolves them dynamically) but excellent for unpacked samples.

Programmatic Hashing

Every triage script must compute all hashes. Python's hashlib handles this directly, without subprocess calls:

#!/usr/bin/env python3
import hashlib
import sys

def all_hashes(filepath: str) -> dict:
    with open(filepath, 'rb') as f:
        data = f.read()

    return {
        'md5':    hashlib.md5(data).hexdigest(),
        'sha1':   hashlib.sha1(data).hexdigest(),
        'sha256': hashlib.sha256(data).hexdigest(),
        'sha512': hashlib.sha512(data).hexdigest(),
    }

if __name__ == '__main__':
    for k, v in all_hashes(sys.argv[1]).items():
        print(f"{k}: {v}")

For large files (disk images, memory dumps), read in chunks:

def sha256_stream(filepath: str, chunk_size: int = 8192) -> str:
    h = hashlib.sha256()
    with open(filepath, 'rb') as f:
        while chunk := f.read(chunk_size):
            h.update(chunk)
    return h.hexdigest()

Entropy: Measuring Randomness

Entropy measures how uniformly bytes are distributed. A file containing only ASCII text has low entropy ( 4.5-5.5 bits per byte). Encrypted or compressed data approaches maximum entropy ( 8.0 bits per byte). High entropy in a binary section indicates packing, encryption, or compression.

Shannon Entropy Formula

For a byte stream with byte value probabilities p(b), the Shannon entropy H is:

H = -sum(p(b) * log2(p(b)))  for b in 0..255

If all 256 bytes appear with equal frequency (1/256 each), entropy = 8.0. If the file contains only one byte value, entropy = 0.

Computing Entropy in Python

#!/usr/bin/env python3
import math
import sys
from collections import Counter

def shannon_entropy(data: bytes) -> float:
    if not data:
        return 0.0
    total = len(data)
    counts = Counter(data)
    return -sum(
        (count / total) * math.log2(count / total)
        for count in counts.values()
    )

def file_entropy(filepath: str) -> float:
    with open(filepath, 'rb') as f:
        return shannon_entropy(f.read())

if __name__ == '__main__':
    score = file_entropy(sys.argv[1])
    print(f"entropy: {score:.3f} bits/byte")
    if score > 7.5:
        print("[!] HIGH ENTROPY -- likely packed or encrypted")
    elif score > 7.0:
        print("[*] Medium-high entropy -- possibly compressed")
    elif score > 5.5:
        print("[*] Moderate entropy -- normal binary")
    else:
        print("[*] Low entropy -- text, log, or repetitive data")

Visualizing Entropy with binwalk

Binwalk is primarily a firmware analysis tool, but its entropy plot is invaluable for binary triage:

$ pacman -S binwalk
$ binwalk -E unknown.bin

This generates an entropy graph. Interpretation:

  • Flat line near 8.0 across the entire file : The whole binary is packed or encrypted (UPX, Themida, XOR-encoded). The entire data section is opaque.
  • Spiky graph with peaks at 5-7 and drops near 0 : Normal compiled binary. Low-entropy regions are strings/data tables. High-entropy regions are compressed code.
  • Sharp spike at a specific offset to 8.0, rest of file at 5-6 : Embedded encrypted payload (config blob, second stage, resource).
  • Entire file at 8.0 except header at 4-5 : Packed executable. The header is the unpacking stub.

for f in samples/*; do
    score=$(python3 -c "

    print(0)
    sys.exit(0)
counts = Counter(data)
H = -sum((c/total)*math.log2(c/total) for c in counts.values())
print(f'{H:.3f}')
")
    size=$(stat -c%s "$f")

Entropy by Section

For ELF files, compute per-section entropy. The .text section should be~5.5-6.5. The .rodata section varies. .data / .bss have no file bytes. A .text section at 7.8+ means packed code.

#!/usr/bin/env python3
# elfsection_entropy.py -- per-section entropy for ELF
import math
import sys
from collections import Counter

try:
    from elftools.elf.elffile import ELFFile
except ImportError:
    print("pip install pyelftools")
    sys.exit(1)

def entropy(data):
    if not data:
        return 0.0
    total = len(data)
    counts = Counter(data)
    return -sum((c/total)*math.log2(c/total) for c in counts.values())

with open(sys.argv[1], 'rb') as f:
    elf = ELFFile(f)

    for section in elf.iter_sections():
        data = section.data()
        if len(data) == 0:
            continue
        e = entropy(data)
        flag = ''
        if e > 7.5:
            flag = ' [!] HIGH ENTROPY'
        elif e > 7.0:
            flag = ' [*] Medium-high'
        print(f"  {section.name:<24} size={len(data):>8}  entropy={e:.3f}{flag}")

Packer Detection

Packers compress the original binary and wrap it in an unpacking stub. When executed, the stub decompresses the original code into memory and jumps to it. Statically, the binary is opaque

  • high entropy, few strings, small import table.

UPX Detection

UPX (Ultimate Packer for Executables) is the most common packer. It's legitimate (reduces binary size) but also used by malware to evade signature detection.

Signs of UPX:

  • Section names: UPX0 , UPX1 . UPX0 is empty (zero file size, large virtual size - the decompressed code lands here). UPX1 contains the compressed payload.
  • A UPX! string near the end of the file, often followed by version info.
  • High entropy in the UPX1 section.
  • file reports ELF executable, packed with UPX .
$ strings unknown_upx.bin | grep -i upx
$Info: This file is packed with the UPX executable packer http://upx.sf.net $
UPX!

UPX-packed ELFs have a distinctive header. The p_filesz of the first LOAD segment is zero, and the section UPX0 has sh_size = 0 in the file but a large sh_addr range:

$ readelf -l unknown_upx.bin

Program Headers:
  Type           Offset             VirtAddr           PhysAddr
                 FileSiz            MemSiz              Flags  Align
  LOAD           0x0000000000000000 0x0000000000400000 0x0000000000400000
                 0x0000000000010910 0x0000000000010910  R E    0x1000
  LOAD           0x0000000000010910 0x0000000000411910 0x0000000000411910
                 0x0000000000000000 0x0000000000010000  RW     0x1000

Notice the second LOAD: FileSiz=0 , MemSiz=0x10000 . This is the decompression target. The stub writes the decompressed code there at runtime.

Detecting Packed Binaries

Key heuristics:

  1. High overall entropy (>7.5).
  2. Few or no human-readable strings.
  3. Small import table (dynamic API resolution to evade static import analysis).
  4. Non-standard section names.
  5. Large discrepancy between raw and virtual section sizes.
def is_likely_packed(entropy_score, num_strings, num_imports, section_names):
    suspicious = []
    if entropy_score > 7.5:
        suspicious.append(f"entropy={entropy_score:.3f}")
    if num_strings < 20:
        suspicious.append(f"few_strings={num_strings}")
    if num_imports < 5:
        suspicious.append(f"few_imports={num_imports}")
    unusual_sections = [s for s in section_names
                        if s not in {'.text','.rodata','.data','.bss','.init','.fini',
                                     '.plt','.got','.dynamic','.interp','.comment',
                                     '.note','.eh_frame','.shstrtab','.symtab','.strtab'}]
    if unusual_sections:
        suspicious.append(f"unusual_sections={','.join(unusual_sections)}")
    return suspicious

The Triage Script

Combine everything into a single triage script. This is the first tool you run against an unknown binary. It answers: what is this, how unique is it, is it packed, and does it look suspicious.

#!/usr/bin/env python3
"""
binary_triage.py -- first-pass analysis of unknown binaries
Usage: python3 binary_triage.py <file>
"""
import hashlib
import math
import os
import re
import sys
import subprocess
from collections import Counter


def file_size(path: str) -> int:
    return os.path.getsize(path)


def all_hashes(filepath: str) -> dict:
    with open(filepath, 'rb') as f:
        data = f.read()
    return {
        'md5':    hashlib.md5(data).hexdigest(),
        'sha1':   hashlib.sha1(data).hexdigest(),
        'sha256': hashlib.sha256(data).hexdigest(),
    }


def shannon_entropy(data: bytes) -> float:
    if not data:
        return 0.0
    total = len(data)
    counts = Counter(data)
    return -sum((c / total) * math.log2(c / total) for c in counts.values())


def file_entropy(filepath: str) -> float:
    with open(filepath, 'rb') as f:
        return shannon_entropy(f.read())


def file_type(filepath: str) -> str:
    try:
        result = subprocess.run(
            ['file', '-b', filepath],
            capture_output=True, text=True, timeout=5
        )
        return result.stdout.strip()
    except Exception:
        return "unknown"


def strings_count(filepath: str, min_len: int = 6) -> int:
    try:
        result = subprocess.run(
            ['strings', f'-n{min_len}', filepath],
            capture_output=True, text=True, timeout=10
        )
        return len(result.stdout.splitlines())
    except Exception:
        return 0


def ssdeep_hash(filepath: str):
    try:
        result = subprocess.run(
            ['ssdeep', '-b', filepath],
            capture_output=True, text=True, timeout=10
        )
        line = result.stdout.strip()
        if line:
            return line.split(',')[0]
    except Exception:
        pass
    return None


def detect_packer(filepath: str, entropy: float, num_strings: int) -> list:
    indicators = []

    if entropy > 7.5:
        indicators.append(f"high_entropy({entropy:.3f})")

    if num_strings < 30:
        indicators.append(f"few_strings({num_strings})")

    try:
        with open(filepath, 'rb') as f:
            data = f.read()
        upx_magic = data.find(b'UPX!')
        if upx_magic > 0:
            indicators.append(f"upx_signature_found_at_{hex(upx_magic)}")

        if data[:2] == b'MZ':
            pe_offset = int.from_bytes(data[0x3C:0x3C+4], 'little')
            pe_sig = data[pe_offset:pe_offset+4]
            if pe_sig == b'PE\x00\x00':
                section_start = pe_offset + 4 + 20 + data[pe_offset+4+16]
                section_names = []
                for i in range(data[pe_offset+4+2] & 0xFFFF):
                    offset = section_start + i * 40
                    name = data[offset:offset+8].rstrip(b'\x00').decode(errors='ignore')
                    section_names.append(name)
                packed_sections = [n for n in section_names
                                   if n in {'UPX0', 'UPX1', '.aspack', '.adata', '.themida'}]
                if packed_sections:
                    indicators.append(f"packed_sections({','.join(packed_sections)})")
    except Exception:
        pass

    return indicators


def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <binary>")
        sys.exit(1)

    path = sys.argv[1]
    if not os.path.isfile(path):
        print(f"Error: {path} not found")
        sys.exit(1)

    # File identification
    ftype = file_type(path)
    size = file_size(path)
    hashes = all_hashes(path)
    entropy = file_entropy(path)
    nstrings = strings_count(path)
    ssdeep = ssdeep_hash(path)

    # Packer detection
    packer_flags = detect_packer(path, entropy, nstrings)

    # Output
    print("=" * 64)
    print(f"  TARGET: {path}")
    print(f"  TYPE:   {ftype}")
    print(f"  SIZE:   {size:,} bytes ({size/1024:.1f} KB)")
    print("-" * 64)
    print(f"  MD5:    {hashes['md5']}")
    print(f"  SHA-1:  {hashes['sha1']}")
    print(f"  SHA-256:{hashes['sha256']}")
    if ssdeep:
        print(f"  SSDEEP:  {ssdeep}")
    print("-" * 64)
    print(f"  ENTROPY:  {entropy:.3f} bits/byte")
    print(f"  STRINGS:  {nstrings} (min length 6)")
    print("-" * 64)
    if packer_flags:
        print(f"  PACKER INDICATORS:")
        for flag in packer_flags:
            print(f"    [!] {flag}")
    else:
        print(f"  PACKER:    No obvious packer indicators")
    print("=" * 64)


if __name__ == '__main__':
    main()

Next Steps

After identification, the analysis path branches:

  • If packed: Unpack before further analysis. Try UPX decompression first: upx -d packed.bin . If a custom packer is used, dynamic analysis (execution and memory dump) is required.
  • If ELF: Proceed to ELF Reversing for deep structural analysis.
  • If PE: Proceed to PE Analysis for Windows binary analysis from Linux.
  • If script: Read the source. Check for obfuscation, eval chains, and encoded payloads.
  • In all cases: Run Strings Analysis next.

Challenge

Write a Go triage tool that reads a file, prints its SHA-256, computes its Shannon entropy, identifies the format from its magic bytes, and flags likely packing. Run it against a normal binary and a UPX-packed one and compare the entropy values.

package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"math"
	"os"
)

func magic(data []byte) string {
	switch {
	case len(data) >= 4 && string(data[:4]) == "\x7fELF":
		return "ELF"
	case len(data) >= 2 && string(data[:2]) == "MZ":
		return "PE"
	case len(data) >= 4 && string(data[:4]) == "PK\x03\x04":
		return "ZIP/JAR/APK"
	case len(data) >= 5 && string(data[:5]) == "%PDF-":
		return "PDF"
	case len(data) >= 8 && string(data[:8]) == "\x89PNG\r\n\x1a\n":
		return "PNG"
	case len(data) >= 3 && string(data[:3]) == "\xff\xd8\xff":
		return "JPEG"
	default:
		return "unknown"
	}
}

func entropy(data []byte) float64 {
	if len(data) == 0 {
		return 0
	}
	var counts [256]int
	for _, b := range data {
		counts[b]++
	}
	var h float64
	n := float64(len(data))
	for _, c := range counts {
		if c == 0 {
			continue
		}
		p := float64(c) / n
		h -= p * math.Log2(p)
	}
	return h
}

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintln(os.Stderr, "usage: triage <file>")
		os.Exit(1)
	}
	data, err := os.ReadFile(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	sum := sha256.Sum256(data)
	h := entropy(data)
	fmt.Printf("type:    %s\n", magic(data))
	fmt.Printf("size:    %d bytes\n", len(data))
	fmt.Printf("sha256:  %s\n", hex.EncodeToString(sum[:]))
	fmt.Printf("entropy: %.3f bits/byte\n", h)
	if h > 7.5 {
		fmt.Println("verdict: HIGH ENTROPY - likely packed or encrypted")
	} else {
		fmt.Println("verdict: normal entropy")
	}
}
