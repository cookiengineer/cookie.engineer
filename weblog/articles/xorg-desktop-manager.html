So your Xorg Desktop Manager broke again...

You're probably here because your Xorg Desktop Manager of choice broke down again. In my case that was ly , lightdm and pretty much all other gtk based Desktop Managers. Tough luck trying to get everything working again, huh.

This is a little tutorial that shows how to integrate the most failsafe of them all, XDM and xconsole .

Overview

Xorg Desktop Manager doesn't use the /usr/share/xsessions/* service file definitions, so it is a little quirky to setup. But that's a feature, because it can't break easily and everything it uses are essentially just shell scripts relying on sh , xorg and nothing else.

  • /etc/X11/xdm/Xsetup_0 prepares the Xorg session before login
  • /etc/X11/xdm/Xresources contains window-id based configuration properties for Xorg
  • ~/.xsession prepares the Xorg session after login
  • ~/.xinitrc is used by startx (compatibility in case XDM breaks)

How to Install XDM

Install the xorg-xdm package and feh to display a background image, this will also provide an xdm.service file for later. 

sudo pacman -S xorg-xdm feh;

How to Configure XDM

First, you have to setup the Xsetup_0 file and make sure it's executable. Inside it, we can place modifications that are executed before the Xorg session is started (which displays the login greeter).

The contents of the /usr/X11/xdm/Xsetup_0 file: 

#!/bin/sh

/usr/bin/feh --no-feh-bg --bg-fill /usr/share/backgrounds/xdm-wallpaper.png &

xconsole -geometry 400x130-0-0 -daemon -notify -verbose -fn fixed -exitOnFail &

exit 0;

Now make sure that the file is executable:

chmod +x /usr/X11/xdm/Xsetup_0;

As you can see, it's important to chain all commands with the & symbol at the end of each line. Only the very last command of the shell script is allowed to return or exit. That's a common pattern in shell scripts of Xorg related config files.

Next, you have to create an ~/.xsession file which runs all programs of your Xorg session. It is executed after you logged in successfully.

In my case, i3 is actually executing all programs that I need, too, but for the case of demonstrating its usage, this file is going to set the background again. You can never be too sure about that.

The contents of the ~/.xsession file: 

#!/bin/sh

/usr/bin/feh --no-feh-bg --bg-fill /usr/share/backgrounds/xdm-wallpaper.png &

setxkbmap us &

xset r rate 250 50 &

exec i3;

Now make sure that the file is executable:

chmod +x ~/.xsession;

If you want to use startx (in case XDM breaks for whatever reason) you can just copy or symlink the ~/.xsession file to ~/.xinitrc : 

cp ~/.xsession ~/.xinitrc;
chmod +x ~/.xinitrc;

How to style XDM

The wallpaper file has to be located at /usr/share/backgrounds/xdm-wallpaper.png because that's the path that the earlier feh command expects to exist. I picked my nice neon-space.png picture that I've used probably for over 10 years now, but you can use whatever you want. 

sudo mv ~/Wallpaper.png /usr/share/backgrounds/xdm-wallpaper.png;

Next we're going to create a logo file that's displayed on the right side of the xlogin window: 

sudo magick /usr/share/pixmaps/archlinux-logo.png -colors 256 /usr/share/xdm/pixmaps/archlinux-logo.xpm;

We can also style the xlogin window quite a bit by modifying the /etc/X11/xdm/Xresources file and changing a few lines so it looks like this: 

Xcursor.theme: whiteglass

xlogin*login.translations: #override \
	Ctrl<Key>R: abort-display()\n\
	<Key>F1: set-session-argument(failsafe) finish-field()\n\
	<Key>Delete: delete-character()\n\
	<Key>Left: move-backward-character()\n\
	<Key>Right: move-forward-character()\n\
	<Key>Home: move-to-begining()\n\
	<Key>End: move-to-end()\n\
	Ctrl<Key>KP_Enter: set-session-argument(failsafe) finish-field()\n\
	<Key>KP_Enter: set-session-argument() finish-field()\n\
	Ctrl<Key>Return: set-session-argument(failsafe) finish-field()\n\
	<Key>Return: set-session-argument() finish-field()

xlogin*greeting: Welcome to CLIENTHOST
xlogin*namePrompt: \040\040\040\040\040\040\040Login:

Enable and Reboot

Now we need to enable our SystemD service for XDM and reboot the machine to test it. 

sudo systemctl enable xdm.service;
sudo reboot;
