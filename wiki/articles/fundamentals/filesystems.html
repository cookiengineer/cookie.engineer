Filesystems

Linux VFS layer, inodes, ext4 internals, hard/symbolic links, journaling, file timestamps, stat(), mount namespaces, and the FHS.

Overview

A filesystem is the kernel's mapping from names to stored bytes. Linux hides every concrete format behind the Virtual File System, so the same open() , read() , and stat() calls work on ext4, btrfs, tmpfs, and network filesystems alike. Understanding inodes, directory entries, links, and journaling matters for forensics, privilege escalation, and container escapes: the difference between a hard link and a symlink, or a timestamp that did not change, is often the pivot point of an investigation. After reading this article you can inspect inodes and superblocks, tell the link types apart, and mount a filesystem image through a loop device.

  • Unix Permissions - file permissions, setuid, and ACL s

The VFS - Linux Virtual File System

The Linux kernel does not operate on one filesystem type. It provides a unified interface - the Virtual File System (VFS) - that abstracts ext4, btrfs, NFS, procfs, tmpfs, and dozens of other filesystem types behind a common set of objects. 

                    ┌─────────────────┐
                    │   User Process   │
                    └─────────────────┘
                             │ read(), write(), open(), stat(), ...
                             ▼
              ┌──────────────────────────┐
              │       VFS Layer          │
              │  (fs/namei.c,            │
              │   fs/read_write.c,       │
              │   fs/open.c)             │
              └──────────────────────────┘
                             │
           ┌───────────────────────────────────┐
           ▼                 ▼                  ▼
     ┌──────────┐     ┌──────────┐       ┌──────────┐
     │   ext4   │     │  btrfs   │       │   NFS    │
     │  driver  │     │  driver  │       │  driver  │
     └──────────┘     └──────────┘       └──────────┘
          ▼                ▼                  ▼
     ┌──────────────────────────────────────────┐
     │         Block I/O Layer                  │
     │         Block Device Drivers             │
     └──────────────────────────────────────────┘

The VFS defines four key object types:

Object Kernel Struct What It Represents
superblock struct super_block A mounted filesystem (one per mount)
inode struct inode A file, directory, symlink, device, pipe (one per object)
dentry struct dentry A directory entry - maps name -> inode (cached)
file struct file An open file from a process's perspective (fd, offset)

Inodes - The Core Filesystem Object

An inode (index node) is a filesystem object that represents exactly one file, directory, symlink, FIFO, socket, block device, or character device. Every inode has a unique inode number within its filesystem. 

Inode Contents:
┌─────────────────────────────────────┐
│  Inode number (unique in this fs)   │
│  File type (regular, dir, symlink)  │
│  Permissions (rwx + setuid/setgid)  │
│  Owner (UID)                        │
│  Group (GID)                        │
│  Size (in bytes)                    │
│  Number of hard links               │
│  Timestamps:                        │
│    - atime (last access)            │
│    - mtime (last modification)      │
│    - ctime (last metadata change)   │
│  Block pointers:                    │
│    - Direct blocks (12)             │
│    - Single indirect                │
│    - Double indirect                │
│    - Triple indirect                │
│  Extended attributes (file ACLs)    │
│  Flags (immutable, append-only...)  │
└─────────────────────────────────────┘
						
# View inode details with stat
stat /etc/hostname

# View inode number
ls -i /etc/hostname
# Output: 12345678 /etc/hostname

# Find files by inode number
find /home -inum 12345678

# Check filesystem inode usage
df -i
# Filesystem      Inodes  IUsed   IFree IUse%
# /dev/sda1       6553600 234567 6319033    4%

# Detailed inode info via debugfs (read-only)
sudo debugfs -R "stat <12345678>" /dev/sda1

Directories Are Special Files

A directory is a file whose data consists of an array of {inode_number, name} pairs. The kernel (and ls ) reads directory entries via getdents() :

Directory Data Layout

Inode # Rec Len Name Len Type Name
(4/8 B) (2 B) (2 B) (1 B) (variable) 
# Read raw directory entries
# getdents64 syscall = number 217 on x86-64
python3 << 'EOF'
import os, struct

fd = os.open('/etc', os.O_RDONLY | os.O_DIRECTORY)
while True:
    data = os.getdents(fd, 4096)
    if not data:
        break
    offset = 0
    while offset < len(data):
        d_ino, d_off, d_reclen, d_type, name = \
            struct.unpack_from('=QqHQb', data, offset)
        name = data[offset+19:offset+19+struct.unpack_from('B', data, offset+18)[0]]
        type_char = {4:'d', 8:'f', 10:'l', 12:'s'}.get(d_type, '?')
        print(f'{d_ino:10d} {type_char} {name.decode()}')
        offset += d_reclen
os.close(fd)
EOF

Superblock

The superblock contains metadata about the entire filesystem:

# View ext4 superblock
sudo dumpe2fs -h /dev/sda1 | head -40

# Key superblock fields:
# Filesystem UUID
# Block count
# Block size (4096 typical)
# Inode count
# Inodes per group
# Blocks per group
# Mount count / max mount count
# Last mount time / last write time
# Filesystem state (clean/dirty)
# Journal UUID / inode

# View superblock via tune2fs
sudo tune2fs -l /dev/sda1

ext4 - Block Groups and Journal

ext4 divides the filesystem into block groups to improve locality. Each block group contains: 

Block Group Layout:
┌──────────────────────────────────────────┐
│  Superblock (copy)        │ 1 block       │
│  Group Descriptors        │ N blocks      │
│  Block Bitmap             │ 1 block       │
│  Inode Bitmap             │ 1 block       │
│  Inode Table              │ N blocks      │
│  Data Blocks              │ remaining     │
└──────────────────────────────────────────┘

Block allocation attempts to keep a file's data blocks in the same block group as its inode, minimizing seek time. New directories are placed in least-loaded block groups (Orlov allocator).

Extents replace the traditional indirect block scheme in ext4. An extent is a contiguous range of blocks described by {logical_block, start_physical_block, length} . A single extent can describe 128 MiB of contiguous data. 

Indirect blocks (ext2/ext3):     Extents (ext4):
inode                            inode
  ├── direct [0] -> block          ├── extent [0]: start=1000, len=500
  ├── direct [1] -> block          ├── extent [1]: start=2000, len=300
  ├── single indirect             ├── extent [2]: start=3000, len=128
  │    └── block[]                └── extent [3]: start=4000, len=50
  ├── double indirect
  └── triple indirect
						
# Check if a file uses extents
sudo filefrag -v /path/to/large/file
# Output includes extent flags and contiguous ranges

Journaling

The journal (or write-ahead log) ensures filesystem consistency after a crash. Before modifying metadata, ext4 writes a record to the journal. If the system crashes mid-operation, the journal replay recovers.

ext4 Journal Modes

Mode Behavior
data=journal Everything (metadata + data) goes to journal. Slowest, safest.
data=ordered (Default) Metadata journaled. Data written to disk before metadata committed. If metadata says the file is there, the data blocks are there too. Never exposes stale data blocks.
data=writeback Metadata journaled. Data may be written before or after metadata. Crash can expose old data in newly created files. Fastest. 
# Check journal mode
sudo dumpe2fs -h /dev/sda1 | grep -i 'journal features\|default mount'
# Or look at mount options:
mount | grep ' / '
# Look for data=ordered, data=journal, data=writeback

# Journal size and location
sudo dumpe2fs -h /dev/sda1 | grep -i journal

Journaling vs. Copy-on-Write (btrfs, ZFS): Journaling writes changes twice (journal then final location). Copy-on-write never overwrites in place - it writes new data elsewhere and atomically updates the metadata pointer. CoW avoids the journal entirely.

Hard Links

A hard link is a directory entry that points to an existing inode. All hard links to the same inode are equal - there's no "original." 

touch original
ln original hardlink

ls -li original hardlink
# 12345678 -rw-r--r-- 2 user user 0 ... hardlink
# 12345678 -rw-r--r-- 2 user user 0 ... original
# Same inode! Link count = 2.

# The link count must reach 0 (and no process holding the file open)
# before the inode and data blocks are freed.

Hard link constraints: - Cannot span filesystems (different fs = different inode namespace)

  • Cannot link to directories (prevents infinite loops; . and .. are kernel-managed exceptions)
  • All links share the same permissions, owner, timestamps (they're the same inode)

Symbolic Links (Symlinks)

A symlink is a separate inode (type = symbolic link) whose data is a path string. The kernel follows symlinks during path resolution. 

ln -s /etc/hostname mylink
ls -li mylink
# 12345679 lrwxrwxrwx 1 user user 14 ... mylink -> /etc/hostname

# Symlink inode has:
#  - Own inode number (different from target)
#  - Own permissions (lrwxrwxrwx, typically 0777 - but not used in access checks)
#  - Own timestamps
#  - Data: the path string "/etc/hostname"

Symlink internals

Accessing /a/b/c where c -> /x/y:
┌───────────────────────┐
│ Kernel path resolver  │
│                       │
│ 1. Read "/" inode     │
│ 2. Find "a" in "/"    │-> inode A
│ 3. Find "b" in d_ent  │-> inode B
│ 4. Find "c" in d_ent  │-> SYMLINK detected!
│ 5. Read symlink data  │-> "/x/y"
│ 6. Restart from step 1│
│    (or append to      │
│     current path if   │
│     relative)         │
│ 7. Return final inode │-> resolved
└───────────────────────┘
						
# Follow symlinks step by step
namei -l /usr/bin/java  # Resolves every path component

# Read symlink target without resolving
readlink /etc/localtime

# Follow all symlinks to get the real path
realpath /etc/localtime
readlink -f /etc/localtime  # Same

File Timestamps

Timestamp Meaning Updated When
atime Last access time Read, execve (but may be lazy - see relatime)
mtime Last modification time File data is modified (write, truncate)
ctime Last metadata change time Permissions, owner, link count, xattrs change; also updated when mtime changes
btime(birth) Creation time File created; ext4 records it (statx or debugfs) 
# Full timestamp display
stat /etc/hostname

# atime optimization: relatime (default on ArchLinux)
# atime is only updated if previous atime < mtime or previous atime < ctime
# or if previous atime is older than 24 hours.
# This drastically reduces write I/O.
cat /proc/mounts | grep ' / ' | grep -o 'relatime\|noatime\|strictatime'

# Check btime (birth time) - ext4 only, needs debugfs
sudo debugfs -R "stat /etc/hostname" /dev/sda1 2>/dev/null | grep crtime
# crtime: 0x676e1b2e:12345678 - creation time in epoch

# Alternative: statx syscall
python3 << 'EOF'
import os, struct, ctypes
libc = ctypes.CDLL('libc.so.6')

class StatxTimestamp(ctypes.Structure):
    _fields_ = [("tv_sec", ctypes.c_int64),
                ("tv_nsec", ctypes.c_uint32),
                ("__reserved", ctypes.c_int32)]

class Statx(ctypes.Structure):
    _fields_ = [("stx_mask", ctypes.c_uint32),
                ("stx_blksize", ctypes.c_uint32),
                ("stx_attributes", ctypes.c_uint64),
                ("stx_nlink", ctypes.c_uint32),
                ("stx_uid", ctypes.c_uint32),
                ("stx_gid", ctypes.c_uint32),
                ("stx_mode", ctypes.c_uint16),
                ("__spare0", ctypes.c_uint16),
                ("stx_ino", ctypes.c_uint64),
                ("stx_size", ctypes.c_uint64),
                ("stx_blocks", ctypes.c_uint64),
                ("stx_attributes_mask", ctypes.c_uint64),
                ("stx_atime", StatxTimestamp),
                ("stx_btime", StatxTimestamp),
                ("stx_ctime", StatxTimestamp),
                ("stx_mtime", StatxTimestamp),
                ("stx_rdev_major", ctypes.c_uint32),
                ("stx_rdev_minor", ctypes.c_uint32),
                ("stx_dev_major", ctypes.c_uint32),
                ("stx_dev_minor", ctypes.c_uint32),
                ("stx_mnt_id", ctypes.c_uint64)]

buf = Statx()
STX_BTIME = 0x800
ret = libc.statx(0, b"/etc/hostname", 0, STX_BTIME, ctypes.byref(buf))
import time
if ret == 0 and (buf.stx_mask & STX_BTIME):
    print("Creation time:", time.ctime(buf.stx_btime.tv_sec))
EOF

stat() System Call

#include <stdio.h>
#include <sys/stat.h>
#include <time.h>

int main() {
    struct stat sb;
    if (stat("/etc/hostname", &sb) == -1) {
        perror("stat");
        return 1;
    }

    printf("Inode:         %lu\n", sb.st_ino);
    printf("Mode:          %#o\n", sb.st_mode);
    printf("Links:         %lu\n", sb.st_nlink);
    printf("UID:           %u\n", sb.st_uid);
    printf("GID:           %u\n", sb.st_gid);
    printf("Size:          %ld bytes\n", sb.st_size);
    printf("Blocks:        %ld\n", sb.st_blocks);
    printf("Block size:    %ld\n", sb.st_blksize);
    printf("Device:        %d,%d\n", major(sb.st_dev), minor(sb.st_dev));
    printf("File type:     ");
    if (S_ISREG(sb.st_mode))  printf("regular\n");
    if (S_ISDIR(sb.st_mode))  printf("directory\n");
    if (S_ISLNK(sb.st_mode))  printf("symlink\n");
    if (S_ISCHR(sb.st_mode))  printf("character device\n");
    if (S_ISBLK(sb.st_mode))  printf("block device\n");
    if (S_ISFIFO(sb.st_mode)) printf("FIFO\n");
    if (S_ISSOCK(sb.st_mode)) printf("socket\n");

    printf("Access time:   %s", ctime(&sb.st_atime));
    printf("Modify time:   %s", ctime(&sb.st_mtime));
    printf("Change time:   %s", ctime(&sb.st_ctime));
    return 0;
}

Extended File Attributes

ext4 supports special flags that modify filesystem behavior:

# List extended attributes
lsattr somefile

# Common flags:
# a - append only (only write in append mode, root only)
# i - immutable (cannot modify, delete, rename, or link to; root only)
# A - no atime updates
# c - compressed (on filesystems that support it)
# d - no dump (exclude from dump backup)
# e - extent format (auto-set by ext4)
# j - data journaling (write all data to journal first)
# s - secure deletion (zero blocks on delete)
# S - synchronous updates (immediate write to disk)
# u - undeletable (save contents for undeletion)

# Set immutable flag
sudo chattr +i important.file
# Now even root cannot modify it without removing the flag:
# sudo chattr -i important.file

/proc/filesystems and Mounts

# List all filesystem types the kernel supports
cat /proc/filesystems
# nodev = no block device needed (virtual: proc, sysfs, tmpfs)
# Otherwise = requires a block device (ext4, btrfs, xfs)

# List all mounted filesystems
mount
findmnt  # Nicer tree view

# Mount namespace - unshare a mount namespace
sudo unshare -m /bin/bash
mount -t tmpfs none /mnt
ls /mnt           # Only visible in this namespace
exit              # Returns to parent namespace; /mnt not visible

# Inspect mount info for a process
cat /proc/$$/mountinfo
cat /proc/$$/mounts

Loop Devices

A loop device maps a regular file to a block device, allowing you to mount filesystem images:

# Create a 100 MB filesystem image
dd if=/dev/zero of=/tmp/disk.img bs=1M count=100
mkfs.ext4 /tmp/disk.img

# Mount via loop device
sudo mount -o loop /tmp/disk.img /mnt

# Or explicitly:
sudo losetup -f /tmp/disk.img         # Find free loop device
losetup -a                            # List all loop devices
sudo mount /dev/loop0 /mnt

# Clean up
sudo umount /mnt
sudo losetup -d /dev/loop0

Filesystem Hierarchy Standard (FHS)

The FHS defines the purpose of each directory on a Linux system:

/                   Root - everything lives under here
├── /bin/           Essential user command binaries (may be symlink to /usr/bin)
├── /boot/          Boot loader files (kernel, initramfs)
├── /dev/           Device files (created by udev)
├── /etc/           Host-specific system configuration
│   ├── /etc/systemd/      systemd unit files
│   ├── /etc/passwd        User account database
│   └── /etc/ssh/          SSH server configuration
├── /home/          User home directories
├── /lib/           Essential shared libraries (may be symlink to /usr/lib)
├── /media/         Mount point for removable media
├── /mnt/           Temporary mount point
├── /opt/           Add-on application software packages
├── /proc/          Virtual filesystem for process/kernel info
├── /root/          Root user's home directory
├── /run/           Runtime variable data (tmpfs since boot)
├── /sbin/          System binaries (may be symlink to /usr/bin)
├── /srv/           Data for services provided by this system
├── /sys/           Kernel and device tree info (sysfs)
├── /tmp/           Temporary files (may be cleaned on reboot / via tmpfiles.d)
├── /usr/           Shareable, read-only data
│   ├── /usr/bin/   Most user commands
│   ├── /usr/lib/   Libraries for /usr/bin and /usr/sbin
│   ├── /usr/local/ Local sysadmin-installed software (mirrors /usr structure)
│   ├── /usr/share/ Architecture-independent data
│   └── /usr/src/   Source code (e.g., kernel headers)
└── /var/           Variable data
    ├── /var/log/   Log files
    ├── /var/cache/ Application cache data
    ├── /var/lib/   State information (databases, package manager data)
    └── /var/tmp/   Temporary files preserved between reboots

Verification Checklist

# 1. Inspect inode details of a file
stat /etc/hostname
ls -li /etc/hostname

# 2. Check filesystem type and features
df -Th /
sudo dumpe2fs -h $(findmnt -n -o SOURCE /) 2>/dev/null | head -30

# 3. List all open files on a filesystem
lsof / 2>/dev/null | head -20

# 4. Verify journal mode
mount | grep ' / '

# 5. Find all symlinks in a directory
find /etc -maxdepth 1 -type l -ls

# 6. Check filesystem mount flags
cat /proc/mounts | grep '/ '

# 7. List filesystem types available in kernel
cat /proc/filesystems

# 8. Inspect a directory's raw entries
ls -laU /etc | head -10  # -U = unsorted, raw directory order

# 9. Check for hardlinked files (link count > 1)
find /etc -type f -links +1

# 10. Trace file operations on a program
strace -e trace=file cat /etc/hostname 2>&1

Challenge

Read an ext4 superblock from userspace without mounting it. Create a small image, then write a Go program that opens the file, seeks to byte 1024, checks the 0xEF53 magic, and prints the block size, inode count, and block count. 

dd if=/dev/zero of=disk.img bs=1M count=8
mkfs.ext4 disk.img
						
package main

import (
	"encoding/binary"
	"fmt"
	"os"
)

func main() {
	data := make([]byte, 2048)
	f, err := os.Open(os.Args[1])
	if err != nil {
		panic(err)
	}
	defer f.Close()
	f.ReadAt(data, 0)

	sb := data[1024:2048]
	if magic := binary.LittleEndian.Uint16(sb[0x38:0x3a]); magic != 0xEF53 {
		panic("not an ext4 superblock")
	}
	logBlockSize := binary.LittleEndian.Uint32(sb[0x18:0x1c])
	blockSize := uint32(1024) << logBlockSize
	fmt.Printf("block_size=%d inodes=%d blocks=%d\n", blockSize,
		binary.LittleEndian.Uint32(sb[0x00:0x04]),
		binary.LittleEndian.Uint32(sb[0x04:0x08]))
}

Compare the numbers with dumpe2fs -h disk.img , then extend the parser to decode the inode table position and walk the root directory.
