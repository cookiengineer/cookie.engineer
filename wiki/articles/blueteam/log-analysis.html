Log Analysis

Correlating events across systems to reconstruct attacker timelines and detect anomalous patterns.

Overview

Log analysis is the practice of aggregating, normalizing, and correlating event records from disparate systems to answer two questions: what happened and in what order . An attacker's activity rarely fits within a single log source. The phishing email hits the mail gateway, the payload executes on the workstation, the beacon reaches out through the proxy, and lateral movement traverses domain controllers - each step leaves traces in a different log.

The skill is stitching these traces together.

Time Synchronization

Correlation is meaningless without accurate timestamps. If server A is 47 seconds behind server B, event ordering becomes ambiguous and timeline reconstruction fails.

NTP (Network Time Protocol)

Millisecond accuracy over LAN , tens of milliseconds over WAN : 

# ArchLinux: enable and configure NTP
sudo pacman -S ntp
sudo systemctl enable --now ntpd

# Verify synchronization status
ntpq -p
# Look for '*' in first column — indicates active sync peer
# Offset should be < 10ms for reasonable correlation
						
# /etc/ntp.conf — minimal client config
server 0.pool.ntp.org iburst
server 1.pool.ntp.org iburst
server 2.pool.ntp.org iburst
server 3.pool.ntp.org iburst

driftfile /var/lib/ntp/ntp.drift
restrict default noquery nomodify nopeer notrap
restrict 127.0.0.1

PTP (Precision Time Protocol)

Sub-microsecond accuracy for DC -local networks: 

# linuxptp for environments needing sub-ms correlation
sudo pacman -S linuxptp
sudo ptp4l -i eth0 -m

For SIEM deployments, all log sources must synchronize to the same trusted time source. Enforce this via Group Policy (Windows) or configuration management (Linux). A single host with a skewed clock can ruin an investigation. 

# Quick check: compare local time against NTP
sudo timedatectl set-ntp true
timedatectl status

Distributed Tracing Concepts

Modern applications use distributed tracing to follow requests across services. The same concepts apply to security log correlation - you need an identifier that survives across system boundaries.

Concept Security Analog
Trace ID Session token, SSH connection ID, Kerberos ticket
Span ID Individual event within a session
Parent Span The event that triggered this event

Trace IDs in practice

# SSH: connection ID ties authentication to session events
journalctl -u sshd -o json | jq 'select(.SSH_CONNECTION != null) | {time: .__REALTIME_TIMESTAMP, conn: .SSH_CONNECTION, user: .USER}'

Writing Correlation Queries

The art of log analysis is joining disjoint log sources on a common key. Here are practical patterns for common investigative scenarios.

Phishing to C2 Corridor

Step 1 - Start from the known (phishing email timestamp / sender / subject):

-- Loki LogQL: find mail gateway events matching a suspicious sender
{job="mailgw"} |= "evil.domain" | json

Step 2 - Extract attachment hash, trace execution on endpoints:

# Search EDR / sysmon logs for process creation from the downloaded file
# Sysmon Event ID 1: Process Creation
# Look for Image path matching the download location and parent = browser/email client
						
-- Correlate: process created shortly after email received
-- Pseudo-SQL joining mail logs with endpoint logs on hostname + time window
SELECT e.hostname, e.timestamp AS email_time, p.timestamp AS exec_time,
       p.process_name, p.command_line, p.hashes
FROM email_logs e
JOIN process_logs p ON e.hostname = p.hostname
WHERE e.sender LIKE '%evil.domain%'
  AND p.timestamp BETWEEN e.timestamp AND (e.timestamp + INTERVAL '5 minutes')
  AND p.parent_process IN ('outlook.exe', 'chrome.exe', 'firefox.exe')
ORDER BY e.timestamp DESC;

Step 3 - After execution, find the C2 callback: 

-- Join process events with DNS/proxy logs on timestamp proximity
-- The malware (process_logs.command_line) connects out (proxy_logs.url)
-- within N seconds of execution
SELECT p.hostname, p.process_name, p.command_line, p.timestamp AS exec_time,
       d.query AS dns_query, d.timestamp AS dns_time,
       pr.url AS proxy_request
FROM process_logs p
LEFT JOIN dns_logs d ON p.hostname = d.hostname
  AND d.timestamp BETWEEN p.timestamp AND (p.timestamp + INTERVAL '10 seconds')
LEFT JOIN proxy_logs pr ON p.hostname = pr.hostname
  AND pr.timestamp BETWEEN p.timestamp AND (p.timestamp + INTERVAL '10 seconds')
WHERE p.process_name IN ('powershell.exe', 'cmd.exe', 'wscript.exe', 'rundll32.exe')
  AND p.command_line NOT LIKE '%Windows\\System32%'
ORDER BY p.timestamp DESC;

Tracking lateral movement via SSH/RDP

# Linux SSH — trace a user hopping between hosts
# On each host, journald records SSH authentication and session start
# Connection ID (e.g., "connection closed by authenticating user root 10.0.0.5 port 51234")
# persists across authentication, session, and disconnect events

# Extract all SSH sessions for a compromised user
journalctl -u sshd --since "2026-06-26 00:00:00" | awk '
  /Accepted publickey for compromised_user/ {
    match($0, /from ([0-9.]+) port/, a); from=a[1]
    match($0, /([0-9]{2}:[0-9]{2}:[0-9]{2})/, t); time=t[1]
    print time, "LOGIN from", from
  }
  /Disconnected from authenticating user compromised_user/ {
    match($0, /([0-9]{2}:[0-9]{2}:[0-9]{2})/, t); time=t[1]
    print time, "LOGOUT"
  }'
						
# Reconstruct the SSH hop chain across servers
for host in web-01 db-01 app-02; do
  echo "=== $host ==="
  ssh "$host" "journalctl -u sshd --since '2026-06-26' --until '2026-06-27' | grep -E '(Accepted|Disconnected|session opened)'"
done

Event ID 4778 (Session Reconnected)
Event ID 4779 (Session Disconnected)
Event ID 4648 (Explicit Credential Logon Attempt)

Timeline Reconstruction

Timeline analysis arranges every timestamped artifact into a unified chronological view. This reveals the attacker's sequence of actions across filesystem, registry, logs, and network.

Super Timeline with Plaso

# Install on ArchLinux
sudo pacman -S plaso

# Create a super timeline from a forensic image
log2timeline.py --storage-file case-001.plaso /mnt/evidence/image.dd

# Extract all events to CSV for analysis
psort.py -o l2tcsv -w timeline.csv case-001.plaso

# Filter for specific time range and artifacts of interest
psort.py -o dynamic \
  --slice "2026-06-26 08:00:00" "2026-06-26 12:00:00" \
  case-001.plaso

# Common Plaso filters:
#   date > '2026-06-26 08:00:00'
#   parser in ('syslog', 'bash_history', 'sqlite/chrome_history')
#   filename contains 'evil'

Manual Timeline from Live Logs

# Collect timestamps from all available sources
{
  echo "=== AUTHENTICATION ==="
  journalctl --since "2026-06-26" --until "2026-06-27" | grep -E 'sshd|sudo|su|login'
  echo "=== PACKAGE CHANGES ==="
  journalctl --since "2026-06-26" -u pacman 2>/dev/null || cat /var/log/pacman.log
  echo "=== PROCESS EXECUTION ==="
  ausearch -ts 06/26/2026 00:00:00 -te 06/26/2026 23:59:59 -m execve 2>/dev/null
  echo "=== NETWORK CONNECTIONS ==="
  ausearch -ts 06/26/2026 00:00:00 -te 06/26/2026 23:59:59 -m connect 2>/dev/null
} | sort -t' ' -k1,3 > attack-timeline.txt

auditd Forensics Rules

# /etc/audit/rules.d/99-forensics.rules
# Delete previous rules
-D

# Buffer size — prevent audit backlog under heavy load
-b 8192

# Monitor process execution
-a always,exit -F arch=b64 -S execve -k process_execution

# Monitor network connections
-a always,exit -F arch=b64 -S connect -S accept -k network_connections

# Monitor file access in sensitive paths
-w /etc/shadow -p rwxa -k credential_access
-w /etc/passwd -p rwxa -k account_changes
-w /root/.ssh/authorized_keys -p rwxa -k ssh_keys

# Monitor persistence mechanisms
-w /etc/systemd/system/ -p wa -k systemd_persistence
-w /etc/cron.d/ -p wa -k cron_persistence
-w /home/*/.config/autostart/ -p wa -k user_autostart

# Monitor tools commonly abused by attackers
-w /usr/bin/wget -p x -k suspicious_downloads
-w /usr/bin/curl -p x -k suspicious_downloads
-w /usr/bin/nc -p x -k netcat_usage

# Make rules immutable (requires reboot to change)
-e 2
						
# Load and verify rules
sudo auditctl -R /etc/audit/rules.d/99-forensics.rules
sudo auditctl -l

Statistical Baseline & Outlier Detection

Detecting anomalous behavior requires knowing what normal looks like. Statistical baselines identify volumetric and frequency anomalies. 

# outlier_detect.py — simple statistical outlier detection
# Run daily against summarized log counts

import json
import sys
from collections import defaultdict
from statistics import mean, stdev

def load_counts(filepath):
    """Load per-hour event counts from JSON log summary."""
    with open(filepath) as f:
        return json.load(f)

# Example input structure:
# {"ssh_logins": {"00": 3, "01": 1, ..., "23": 5},
#  "dns_queries": {"00": 1200, "01": 987, ...}}

historical = load_counts("baseline-week-avg.json")
current = load_counts("today-summary.json")

THRESHOLD = 2.5  # standard deviations

for metric, hourly in current.items():
    baseline_values = list(historical.get(metric, {}).values())
    if len(baseline_values) < 24:
        continue
    mu = mean(baseline_values)
    sigma = stdev(baseline_values)

    for hour, count in sorted(hourly.items()):
        if sigma == 0:
            continue
        z_score = (count - mu) / sigma
        if abs(z_score) > THRESHOLD:
            print(f"ANOMALY: {metric} at hour {hour}: {count} "
                  f"(μ={mu:.0f}, σ={sigma:.0f}, z={z_score:.2f})")

# Example output:
# ANOMALY: ssh_logins at hour 03: 47 (μ=2, σ=1.5, z=30.00)
# ANOMALY: dns_queries at hour 02: 8452 (μ=1200, σ=250, z=29.01)

Practical baseline collection with Loki

# Generate a 7-day baseline of hourly login counts
for day in {0..6}; do
  date=$(date -d "$day days ago" +%Y-%m-%d)
  for hour in $(seq -w 0 23); do
    count=$(curl -G -s 'http://localhost:3100/loki/api/v1/query' \
      --data-urlencode "query=count_over_time({job=\"auth\"} |= \"Accepted publickey\" [1h] offset ${day}d${hour}h)" \
      --data-urlencode "time=$(date -d "$date $hour:00:00" +%s)000000000" \
      | jq '.data.result[0].value[1] // "0"')
    echo "$date $hour:00 — $count"
  done
done

Detection Queries

-- Known-bad IP correlation
{job="proxy"} | json | dest_ip="203.0.113.99"

-- PowerShell spawned from Office/browser (not explorer.exe)
-- Sysmon Event ID 1 with suspicious parent
{job="sysmon"} | json
  | event_id=1
  | parent_image!~"explorer.exe|services.exe"
  | image="*powershell.exe"
  | command_line!~"*Windows\\System32*"

-- Beacon detection: periodicity check
-- Regular interval connections to a single IP with low jitter
-- 60s ± 2s repeated 10+ times → flag

Cross-Source Correlation

#!/bin/bash
# correlate.sh — pivot across log sources on IP, hostname, or user
# Usage: ./correlate.sh 203.0.113.99
#        ./correlate.sh --user victor
#        ./correlate.sh --host workstation-42

PIVOT="$1"
LOKI_URL="http://localhost:3100"
TIME_START=$(date -d '24 hours ago' +%s)000000000

echo "=== Matching IP: $PIVOT ===" >&2

# Query all log streams in parallel
curl -s "${LOKI_URL}/loki/api/v1/query_range" \
  --data-urlencode "query={job=~\"proxy|firewall|dns\"} |~ \"(?i)${PIVOT}\"" \
  --data-urlencode "start=${TIME_START}" \
  --data-urlencode "limit=500" | jq -r '
    .data.result[].values[][] |
    select(length > 0) |
    .[1]' | sort

Challenge

Write a Go tool that parses an authentication log and flags credential stuffing: any source address that produces five or more failed passwords and then a successful login. Run it over a sample log, confirm the compromise, then extend it to build a per-host timeline of every event from one address. 

package main

// authscan - flag credential stuffing from an OpenSSH auth log.
// Usage: go run authscan.go < auth.log

import (
	"bufio"
	"fmt"
	"os"
	"regexp"
	"strings"
)

var (
	reIP   = regexp.MustCompile(`from ([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+)`)
	reUser = regexp.MustCompile(`for ([A-Za-z0-9._-]+)`)
)

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	failures := map[string]int{}

	for scanner.Scan() {
		line := scanner.Text()
		m := reIP.FindStringSubmatch(line)
		if m == nil {
			continue
		}
		ip := m[1]

		if strings.Contains(line, "Failed password") {
			failures[ip]++
			continue
		}

		if strings.Contains(line, "Accepted") && failures[ip] >= 5 {
			user := "?"
			if u := reUser.FindStringSubmatch(line); u != nil {
				user = u[1]
			}
			fmt.Printf("COMPROMISE %s after %d failures as %s\n", ip, failures[ip], user)
		}
	}

	fmt.Println("--- source addresses ranked by failures ---")
	for ip, n := range failures {
		fmt.Printf("%-16s %d\n", ip, n)
	}
}
