TOCTOU

Time-of-Check to Time-of-Use filesystem races - symlink swaps, access/open gaps, O_NOFOLLOW, openat, mkstemp, hardlink attacks, /proc/self/fd tricks, and atomic file operations.

Overview

TOCTOU (Time-of-Check to Time-of-Use) is a subclass of race condition specific to filesystem operations. A program checks a condition about a filesystem object (file exists, permission, ownership, type), then later acts on that object (open, write, chmod). Between the check and the act, an attacker changes what the pathname resolves to, so the check and the action apply to different objects.

The root cause is that pathname-to-inode resolution is not a single atomic operation. Every syscall that takes a pathname re-resolves it from the directory tree, and between two syscalls the tree can change. After reading you can recognize the vulnerable access/open, stat/open, and pathname-chown patterns, and replace them with file-descriptor based operations.

The Classic Example: access() + open()

/* toctou_setuid.c — setuid-root program with TOCTOU bug
   Compile: gcc -o toctou_setuid toctou_setuid.c
   Install: sudo chown root:root toctou_setuid && sudo chmod u+s toctou_setuid
*/
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>

int main(int argc, char **argv) {
    if (argc < 3) {
        fprintf(stderr, "Usage: %s <file> <data>\n", argv[0]);
        return 1;
    }

    /* TIME OF CHECK: is the file writable by the real user? */
    if (access(argv[1], W_OK) != 0) {
        fprintf(stderr, "access denied: %s is not writable\n", argv[1]);
        return 1;
    }

    /* RACE WINDOW: attacker replaces argv[1] with symlink to /etc/passwd */

    /* TIME OF USE: open() resolves pathname again */
    int fd = open(argv[1], O_WRONLY | O_APPEND);
    if (fd < 0) {
        perror("open");
        return 1;
    }

    write(fd, argv[2], strlen(argv[2]));
    close(fd);

    printf("wrote to %s\n", argv[1]);
    return 0;
}

As root (via setuid), the program checks if the real user can write to the file - then opens it as root. The attacker: 

# Terminal 1 — the attacker
mkdir /tmp/attacker
echo "innocent" > /tmp/attacker/userfile
ls -l /tmp/attacker/userfile

# Set up the race loop
while true; do
    ln -sf /etc/passwd /tmp/attacker/userfile  # symlink to target
    ln -sf /tmp/attacker/real_file /tmp/attacker/userfile  # switch back
done

# Terminal 2 — the victim (setuid program is invoked repeatedly)
while true; do
    ./toctou_setuid /tmp/attacker/userfile "eviluser::0:0::/root:/bin/sh"
done

# If the symlink is in place when open() resolves the path,
# data is appended to /etc/passwd as root

The race window is the gap between access() returning and open() beginning. On a modern system this gap is microseconds, but with enough attempts (thousands per second) and kernel scheduling jitter, the race is consistently winnable.

Limits of O_NOFOLLOW

O_NOFOLLOW tells open() to fail if the final component of the path is a symlink: 

int fd = open(path, O_WRONLY | O_NOFOLLOW);
if (fd < 0 && errno == ELOOP)
    /* symlink detected, refuse */;

This prevents symlink-based TOCTOU for the last path component. But it does not protect against:

  • Directory symlinks: if /tmp/userdir is a symlink to /etc , opening /tmp/userdir/file with O_NOFOLLOW follows the directory symlink but refuses a symlink named file . The directory traversal itself is a TOCTOU vector.
  • Hardlink attacks: no symlink involved, O_NOFOLLOW passes. A hardlink to /etc/passwd is a regular directory entry - O_NOFOLLOW does not reject it.
  • Rename attacks: rename("/tmp/evil", "/tmp/userfile") replaces the file atomically between check and open, without symlinks.

Correct Pattern: open and fstat

Instead of checking permissions before opening, open the file first, then verify that the file descriptor refers to the expected object: 

/* toctou_safe.c — race-free permission check */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/stat.h>

int safe_open_for_write(const char *path, uid_t expected_owner) {
    /* Open first — atomic path resolution */
    int fd = open(path, O_WRONLY | O_NOFOLLOW);
    if (fd < 0) {
        perror("open");
        return -1;
    }

    /* Now check the fd refers to what we expect */
    struct stat st;
    if (fstat(fd, &st) < 0) {
        perror("fstat");
        close(fd);
        return -1;
    }

    /* Verify: is it a regular file? */
    if (!S_ISREG(st.st_mode)) {
        fprintf(stderr, "not a regular file\n");
        close(fd);
        return -1;
    }

    /* Verify: is it owned by the expected user? */
    if (st.st_uid != expected_owner) {
        fprintf(stderr, "owner mismatch: uid %d, expected %d\n",
                st.st_uid, expected_owner);
        close(fd);
        return -1;
    }

    /* Check device + inode against a previous stat to ensure
       the file hasn't been replaced between a prior lstat and this open.
       If you have an earlier lstat st_dev/st_ino, compare here. */

    printf("safe_open_for_write: fd=%d, inode=%lu\n", fd, st.st_ino);
    return fd;
}

int main(int argc, char **argv) {
    if (argc < 2) return 1;

    /* Suppose we want to ensure the file is owned by uid 1000 */
    int fd = safe_open_for_write(argv[1], 1000);
    if (fd >= 0) {
        write(fd, "safe data\n", 10);
        close(fd);
    }
    return 0;
}

The fd is bound to the inode at open() time. fstat() operates on the fd, not the pathname

  • it cannot be tricked by a pathname swap. The attacker can replace the pathname between open()

and fstat() , but it doesn't matter: the fd already points to the file that open() resolved to. The check is on the actual file, not the name.

openat() and Relative Path Operations

openat(dirfd, pathname, flags) resolves pathname relative to the directory referenced by dirfd . If pathname is absolute, dirfd is ignored. If dirfd is AT_FDCWD , it's relative to the current working directory. 

int dirfd = open("/tmp/safedir", O_RDONLY | O_DIRECTORY);
if (dirfd < 0) { perror("open dir"); return 1; }

/* Now open files relative to the directory fd — if someone replaces
   /tmp/safedir with a symlink, our dirfd still points to the original
   directory (assuming no rename of the directory itself). */
int fd = openat(dirfd, "userfile", O_WRONLY | O_NOFOLLOW);

But: openat(dirfd, path) where path contains ../ components resolves those relative to the directory's position in the tree , not the fd. The fd gives a starting point; path resolution still walks the tree and remains vulnerable to parent directory replacement.

The full race-free pattern uses openat() with an fd obtained from open() on the parent directory, plus O_NOFOLLOW , plus device+inode verification via fstat() on the fd that openat() returns.

/proc/self/fd Tricks

Linux's /proc/self/fd/N provides a pathname that re-opens file descriptor N. This is intended for debugging but enables TOCTOU bypass: 

# Program opens /tmp/allowed/file → fd 3
# Program verifies fd 3 is safe
# Attacker replaces /tmp/allowed with symlink to /etc
# Program does open("/proc/self/fd/3", O_WRONLY)
#         → re-opens fd 3's file, but if fd 3 was closed
#           and replaced with a new fd pointing to something else...

The /proc/self/fd entry follows the symlink of the original open. If the original was opened without O_NOFOLLOW , this re-open may follow a symlink that was swapped in after the original open. But since the fd points to the inode, not the path, the re-open should get the same inode

  • the race here is on the fd number, not the path.

A more subtle vector: if you pass a fd number to a setuid program and it opens /proc/self/fd/N to access "your" file, the file is opened with the program's privileges, bypassing permission checks.

Temp Files: mkstemp and tmpfile

Creating temporary files safely requires atomic operations:

# WRONG: race between existence check and creation
if (access("/tmp/myapp.lock", F_OK) != 0) {
    fd = open("/tmp/myapp.lock", O_CREAT | O_WRONLY, 0600);
    /* Another process may have created it between access() and open() */
}

mkstemp() atomically creates and opens a unique temporary file: 

/* mkstemp_demo.c */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <errno.h>

int main() {
    char template[] = "/tmp/myapp_XXXXXX";

    /* mkstemp replaces XXXXXX with random characters and creates the file.
       The check for existence and creation are atomic — no race window. */
    int fd = mkstemp(template);
    if (fd < 0) {
        perror("mkstemp");
        return 1;
    }

    printf("Created temporary file: %s (fd=%d)\n", template, fd);

    /* template now contains the actual filename with random suffix */
    write(fd, "sensitive data\n", 15);

    /* The file persists after close. Unlink if you want auto-cleanup: */
    // unlink(template);  // file removed when last fd is closed

    close(fd);
    return 0;
}

mkstemp() uses O_CREAT | O_EXCL | O_RDWR internally - if the file already exists (unlikely with random 6-character suffix), it fails and picks a new name.

tmpfile() creates an anonymous temporary file - it has no directory entry at all (it's immediately unlinked after creation). No path means no TOCTOU: 

FILE *fp = tmpfile();
if (!fp) { perror("tmpfile"); return 1; }
fprintf(fp, "data\n");
rewind(fp);
/* read back */
fclose(fp);  // file contents freed automatically

The downside: the file has no name, so no other process can access it (by design), and you cannot preserve it across exec() .

O_CREAT | O_EXCL for Exclusive Creation

The combination O_CREAT | O_EXCL makes open() atomically check for file existence and create the file. If the file exists, open() fails with EEXIST . This is the building block of lock files: 

int lock_fd = open("/var/run/myapp.pid", O_CREAT | O_EXCL | O_WRONLY, 0644);
if (lock_fd < 0) {
    if (errno == EEXIST) {
        fprintf(stderr, "another instance is already running\n");
    } else {
        perror("open O_EXCL");
    }
    return 1;
}
/* We hold the exclusive creation — write PID */
dprintf(lock_fd, "%d\n", getpid());
/* Do not close if you want the lock to persist */

The atomicity guarantee: POSIX requires that O_CREAT | O_EXCL on a regular file, on a system supporting the POSIX file semantics, never returns success if the file already exists. The check and creation happen atomically in the kernel's VFS layer.

Hardlink chown TOCTOU

A TOCTOU variant uses hard links instead of symlinks:

# Victim (setuid) does:
#   1. open("/home/user/myfile", O_RDONLY)   → fd for myfile
#   2. fstat(fd, &st)                        → owner = user
#   3. close(fd)
#   4. chown("/home/user/myfile", user, root) → TOCTOU!

# Attacker, between steps 3 and 4:
#   1. rm /home/user/myfile
#   2. ln /etc/passwd /home/user/myfile      → hardlink to /etc/passwd

# Now chown changes /etc/passwd's owner

This works because chown() takes a pathname, not a fd. The POSIX functions fchown() , fchmod() , futimes() , fstat() operate on file descriptors and are immune to this class of attack: 

/* Race-free version */
int fd = open(path, O_RDONLY | O_NOFOLLOW);
if (fd < 0) { perror("open"); return 1; }
struct stat st;
if (fstat(fd, &st) < 0) { perror("fstat"); close(fd); return 1; }
if (st.st_uid != expected_owner) {
    fprintf(stderr, "owner mismatch\n");
    close(fd);
    return 1;
}
/* Use fchown/fchmod on fd, not the pathname-based variants */
fchown(fd, new_owner, new_group);
close(fd);

Directory Traversal and TOCTOU

If an attacker controls a directory component of the path, they can replace that directory with a symlink: 

# Program opens: /tmp/userdir/config.txt
# Step 1: lstat("/tmp/userdir") → it's a real directory, owned by user
# Step 2: Attacker: mv /tmp/userdir /tmp/userdir.old
# Step 3: Attacker: ln -s /etc /tmp/userdir
# Step 4: Program opens /tmp/userdir/config.txt → actually opens /etc/config.txt

# Even with O_NOFOLLOW on the final component, the directory traversal
# follows the symlink because O_NOFOLLOW only affects the last path component

The defense: open() the directory with O_NOFOLLOW , get a dirfd, and use openat() for subsequent operations. The dirfd pins the directory inode even if the name is moved or replaced. 

int dirfd = open("/tmp/userdir", O_RDONLY | O_DIRECTORY | O_NOFOLLOW);
if (dirfd < 0) { perror("open dir"); return 1; }

/* Verify the directory fd points to what we expect */
struct stat dir_st;
fstat(dirfd, &dir_st);

/* Now use openat relative to dirfd */
int fd = openat(dirfd, "config.txt", O_RDONLY | O_NOFOLLOW);
if (fd < 0) { perror("openat"); close(dirfd); return 1; }

/* Even if someone replaces /tmp/userdir, our dirfd still points
   to the original directory (the inode is kept alive by the fd) */

But note: if config.txt is itself a symlink within the original directory, O_NOFOLLOW catches it. If not, it opens the original file within the original directory - TOCTOU safe.

rename() and link() Atomicity

rename() is atomic - the new name either replaces the old or exists, never both. This makes it a building block for safe file updates: 

/* Atomic file update pattern */
int fd = open("/tmp/myfile.tmp", O_CREAT | O_WRONLY | O_TRUNC, 0644);
write(fd, new_data, len);
fsync(fd);
close(fd);

/* Atomically swap new file into place */
if (rename("/tmp/myfile.tmp", "/tmp/myfile") < 0) {
    perror("rename");
    unlink("/tmp/myfile.tmp");
    return 1;
}
/* Any process opening "/tmp/myfile" sees either the old or new inode —
   never a half-written file, never corruption. */

link() is also atomic - two hard links to the same inode either both exist or neither does (except on filesystems that don't support hard links, e.g., FAT).

However: rename() only guarantees atomicity within a single filesystem. Cross-device rename() returns EXDEV and requires a copy+delete fallback, which is not atomic.

inotify-Based Detection

Linux inotify lets a process monitor filesystem events. It cannot prevent TOCTOU but can help detect attacks: 

#include <sys/inotify.h>
#include <limits.h>
#include <stdio.h>
#include <unistd.h>

int main() {
    int fd = inotify_init1(IN_NONBLOCK);
    int wd = inotify_add_watch(fd, "/tmp",
        IN_CREATE | IN_DELETE | IN_MOVED_FROM | IN_MOVED_TO | IN_DELETE_SELF);

    /* In your processing loop: check for events before each open */
    char buf[sizeof(struct inotify_event) + NAME_MAX + 1] __attribute__((aligned(8)));
    ssize_t n = read(fd, buf, sizeof(buf));

    if (n > 0) {
        struct inotify_event *ev = (struct inotify_event *)buf;
        if (ev->mask & IN_MOVED_FROM && strcmp(ev->name, "myfile") == 0) {
            fprintf(stderr, "TOCTOU detected: myfile was renamed/moved\n");
            /* abort operation or retry with fresh stat */
        }
    }

    inotify_rm_watch(fd, wd);
    close(fd);
    return 0;
}

Detection is inherently racy - an attacker can perform the swap after the inotify read but before the application's open() . Defense in depth: combine inotify monitoring with fd-based operations.

The race succeeds when stat() reads the decoy symlink (it follows symlinks - use lstat() to avoid this) and returns decoy's metadata, then open() resolves the path while it points to /etc/shadow . Since the program runs as root (setuid), it reads the shadow file.

Filesystem-Specific Considerations

NFS. Network File System introduces server-side latency and caching. O_EXCL is not guaranteed atomic across NFS clients on older NFS versions (NFSv3 and earlier). NFSv4 provides a more robust OPEN with OPEN4_CREATE semantics.

tmpfs. Memory-backed filesystems like /tmp (often tmpfs) are local and fast. Races are easier to win because there's no disk I/O jitter. The same O_CREAT | O_EXCL guarantees apply.

ext4 / btrfs. Full POSIX semantics. rename() is atomic within the filesystem. Hard links are supported.

FAT / exFAT. No hard links or symlinks - limited TOCTOU surface. But rename() may not be atomic; on FAT, rename() can be a copy+delete.

Summary

TOCTOU exploits the gap between a pathname-based check and a pathname-based action. The file path is a name - it resolves to an inode at the moment of each syscall. Between syscalls, the name-to-inode mapping can change via symlink swaps, hardlink creation, directory replacement, or rename. The defense: open first, check second ( open() -> fstat() -> verify on the fd). Use O_NOFOLLOW , O_CREAT | O_EXCL , mkstemp() , tmpfile() , and openat() with directory fds. Replace chown() , chmod() , and utimes() calls on pathnames with their fd-based counterparts ( fchown() , fchmod() , futimes() ). The kernel cannot protect you from pathname races

  • only fd-based operations provide the necessary atomic binding between the file object and

the permission check.

Challenge

Write the race-free open pattern in Go. Open the target with O_NOFOLLOW , verify the file descriptor with Fstat , then write through that same descriptor. Add an ownership check so that the program refuses a file owned by another user. 

package main

import (
	"fmt"
	"os"
	"syscall"
)

const target = "safe.txt"

// writeSafe opens the target with O_NOFOLLOW and verifies with Fstat that the
// descriptor refers to a regular file owned by the current user.
func writeSafe(path string) error {
	fd, err := syscall.Open(path, syscall.O_WRONLY|syscall.O_CREAT|syscall.O_NOFOLLOW, 0o600)
	if err != nil {
		return err
	}
	defer syscall.Close(fd)

	var st syscall.Stat_t
	if err := syscall.Fstat(fd, &st); err != nil {
		return err
	}
	if st.Mode&syscall.S_IFMT != syscall.S_IFREG {
		return fmt.Errorf("refusing non-regular file")
	}
	if st.Uid != uint32(os.Getuid()) {
		return fmt.Errorf("refusing file owned by uid %d", st.Uid)
	}

	_, err = syscall.Write(fd, []byte("safe data\n"))

	return err
}

func main() {
	if err := writeSafe(target); err != nil {
		fmt.Fprintln(os.Stderr, "refused:", err)
		os.Exit(1)
	}
	fmt.Println("wrote", target)
}

Run it once to create safe.txt . Then replace the path with a symlink to /etc/passwd using ln -sf and confirm the program refuses with ELOOP instead of following it. Finally, remove O_NOFOLLOW and confirm the Fstat ownership check still catches the swap.
