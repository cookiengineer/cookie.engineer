lychee.js Engine

Overview

GitHub Archive | GitLab Archive
Download

The lychee.js Engine is an Isomorphic Application Engine for writing Apps in JavaScript and which targets a large variety of platforms like Embedded, Mobile, Server and Desktop environments.

Its core idea is to reuse components and isomorphic code across all platforms. These platforms can be incremental in its feature support, which means that also low-end platforms like Arduino variants are supported.

The lychee.js Engine delivers Apps to different platforms using so-called Fertilizer Adapters which allow feature detection and automated isomorphic builds from and to every single platform it supports using the lychee.js Fertilizer workflow and runtimes.

Underneath the lychee.js Engine has a strong serialization and deserialization concept that allows simulations and re-simulations across all platforms, for example when bugs in the code cause an error the whole event graph is serialized to generate test cases for later simulations that aim to fix those bugs. Errors can be reproduced everywhere, even network traffic and user interactions are put into event graphs and are identified, classified, and learned by neural networks in order to figure out which module or definition had corrupted states or data.

Fertilizer Adapters

The Fertilizer Adapters are feature-detection based definitions that can be tagged for specific build tags . In the build workflow, all platforms are tagged according to their live featureset of the runtime that the lychee.js Project will be running in.

In order to support new platforms, these are the typical components that are required for a minimal featureset:

  • Buffer to load and process Byte buffers
  • Config to load and process JS ON buffers
  • Texture to load and process Image buffers
  • Font to load and process Font spritemaps
  • Sound and Music to load and process Audio buffers
  • setTimeout and setInterval polyfills

The high-level App Engine needs these components to be able to resimulate a serialized lychee.js Project's data or event graph:

  • lychee.Input for mouse, keyboard or other user input
  • lychee.Storage to offer temporary storage within the simulation
  • (optional) lychee.Renderer to offer drawing mechanisms
  • (optional) lychee.Stash to offer persistent storage on the filesystem
  • (optional) lychee.Viewport to offer display and screen integrations

The drawing mechanisms of a fully supported visual platform need to implement the Renderer's drawArc , drawBox , drawBuffer , drawCircle , drawLine , drawTriangle , drawPolygon , drawSprite and drawText methods.

If there is no lychee.Stash available, the Project's data and event graph will be serialized and transferred over the network, where the lychee.js Harvester will store the data after the simulation's epoche is iterated to the next one.

lychee.Definition System

An implementation in lychee.js needs to be defined via its feature detection embracing API , which is similar to Common JS syntax but has the advantage that it can precompile implementations and "test them out live on the target platform" before running those instances.

If a new platform is partially supported by let's say html and node , it can automatically choose the components which are compatible with that platform, live, while the simulation is temporarily paused. This also gives the advantage that the whole simulation can be paused temporarily, serialized, the adapters replaced, and then resumed after the feature detection process has detected the replacement components. 

lychee.define('lychee.Example').tags({
	platform: 'html'
}).supports((lychee, global) => {

	/*
	 * XXX: typeof CanvasRenderingContext2D is:
	 * > function in Chrome, Firefox, IE10
	 * > object in Safari, Safari Mobile
	 */


	if (
		typeof global.document !== 'undefined'
		&& typeof global.document.createElement === 'function'
		&& typeof global.CanvasRenderingContext2D !== 'undefined'
	) {
		return true;
	}


	return false;

}).exports((lychee, global, attachments) => {

	const Composite = function(data) {

		states = null;

	};

	Composite.prototype = {

		destroy: function() {

			let canvas = this.__canvas;
			if (canvas.parentNode !== null) {
				canvas.parentNode.removeChild(canvas);
			}

			return true;

		},

});
