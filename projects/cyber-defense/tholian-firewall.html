Tholian Firewall

Overview

GitHub Repository | GitLab Mirror

Most firewalls are asked politely to drop a packet after the kernel has already carried it up the networking stack, matched it against a rule set, and handed it to a userspace process to decide.

The Tholian Firewall refuses that negotiation. It compiles a small eBPF program and attaches it to the XDP hook, so that the matching network traffic is dropped by the driver before the stack ever allocates a socket for it.

It is built for people who defend networks for a living. A Go backend can embed the firewall and call actions.Forbid , actions.Permit , and actions.Check on addresses, subnets, ports, ASN networks, and domains from inside their own processes.

Operators who prefer a shell get the same engine as a standalone CLI . When eBPF is not available, it degrades to iptables / ip6tables and a managed /etc/hosts block instead of failing outright.

The result is a programmable eBPF firewall you can carry inside the services that need it, without a central daemon, or a CGo dependency deciding the fate of every packet.

Features

  • Drops ingress traffic in-kernel via XDP before the networking stack runs.
  • Embeds as a Go library with no CGo dependency
  • All actions are ordinary function calls, like forbid , permit , and check .
  • Blocks addresses, CIDR subnets and ASN networks.
  • Blocks TCP and UDP ports.
  • Blocks domains, resolution, and DNS exfil attempts.
  • Drops DNS responses for banned domains in the kernel.
  • Falls back to iptables / ip6tables and a delimited /etc/hosts block when eBPF is unavailable.
  • Cross-compiles for linux/amd64 , linux/arm64 , and OpenWrt, plus BSD fallback builds.
  • Reports honestly whether a ban was actually applied instead of pretending it worked.

Architecture

CLI args -> main.go -> actions.* -> matchers / types / structs
                            |
             +--------------+--------------+
             |                             |
  adapters/mitigations/ebpf      iptables and /etc/hosts
             |
  ebpf/module (embedded bytecode)
             |
  XDP program in the kernel

A single XDP program, xdp_prog_main , parses Ethernet plus up to 4 VLAN tags, IPv4 or IPv6 (including extension headers), TCP / UDP / ICMP , and UDP DNS when ENABLE_DNSFILTER is defined. It returns XDP_DROP on a match and XDP_PASS otherwise. Anything it cannot parse is passed, so the filter fails open rather than breaking the interface.

Map Type Key Purpose
domain_bans HASH 8-byte FNV-1a hash BannedDNSnames
ipv4_bans LPM_TRIE prefix +4address bytes BannedIPv4addresses and subnets
ipv4_warnings LRU_HASH prefix +4address bytes Warning entries forIPv4
ipv6_bans LPM_TRIE prefix +16address bytes BannedIPv6addresses and subnets
ipv6_warnings LRU_HASH prefix +16address bytes Warning entries forIPv6
port_bans HASH network-order port BannedTCP/UDPports

Building

Building needs go , clang , llc / LLVM , libbpf headers, and a Linux kernel with XDP support. Loading the program requires root or CAP_BPF plus CAP_NET_ADMIN . 

cd /path/to/tholian-network/firewall;

# compile the eBPF module, emit LLVM IR, and generate both endiannesses
bash make.sh ebpf;

# cross-compile the CLI variants (also rebuilds the eBPF module)
bash make.sh source;

ls ./build/linux/*;
# tholian-firewall-guard-amd64
# tholian-firewall-guard-arm64
# tholian-firewall-guard_openwrt-amd64
# tholian-firewall-guard_openwrt-arm64

Build tags select which backend ships in the binary:

Tag Includes
guard(orguard_<distro>) eBPF adapter plusinsightsASN data
guard_openwrt eBPF adapter only
guard_freebsd/_netbsd/_openbsd iptables/hostsfallback
intel/oversight eBPF stubs

The generated module.ll , module.bpfel , and module.bpfeb artifacts are committed, so rebuild and commit them whenever module.c or module.h changes.

Testing

cd /path/to/tholian-network/firewall;
bash test.sh;

The one-shot runner writes everything to logs/test.log and ends with RESULT: PASS or RESULT: FAIL . It runs the unit tests, rebuilds the eBPF module and CLI , compiles the integration tests into a single binary with go test -c , and executes that binary under sudo . Running the privileged checks in one process is not a style choice: unpinned maps and XDP links are process-scoped, so separate CLI invocations cannot observe each other's state.

Test What it checks
TestModuleLoad Program and maps load; the verifier accepts the program
TestAddressRoundTrip Forbid, lookup, and permit forIPv4
TestIPv6AddressRoundTrip Forbid, lookup, and permit forIPv6
TestSubnetRoundTrip LPMmatching for a/24covering a/32
TestPortRoundTrip Forbid, lookup, and permit for ports
TestDomainRoundTrip FNV-1a domain key with case-insensitive matching
TestAttachAll AttachesXDPto every non-loopback interface (opt-in)

Tests skip themselves when they are not run as root. TestAttachAll is gated behind THOLIAN_TEST_ATTACH=1 because attaching to host interfaces is intrusive; test.sh enables it by default and the selftest CLI action offers the same round-trip check without the suite.

Usage: CLI

# block an address, a subnet, and a connection
sudo tholian-firewall forbid "1.3.3.7";
sudo tholian-firewall forbid "1.3.3.0/24";
sudo tholian-firewall forbid "1.3.3.7:1338";

# block an IPv6 target (RFC 2732 syntax)
sudo tholian-firewall forbid "[fe80::1337]/64";
sudo tholian-firewall forbid "[fe80::1337]:1338";

# block a domain: drop its DNS responses and ban the resolved addresses
sudo tholian-firewall forbid "evil.example";

# check (exit 0 = allowed, 1 = forbidden, 3 = no backend)
sudo tholian-firewall check "1.3.3.7";

# look up the network and ASN details for an address
sudo tholian-firewall search "1.1.1.1";

# attach to all interfaces and inspect current bans
sudo tholian-firewall init;
sudo tholian-firewall status;

Usage: Rule Files

Bulk rules use the same target syntax, one instruction per line:

# rules.txt
forbid 1.3.3.7;
forbid 1.3.3.0/24;
forbid evil.example;
permit 8.8.8.8;
						
sudo tholian-firewall load rules.txt;

Usage: Embedding

Tholian is a library first. Create a structs.Console for output, load the backends, and call actions.Init once at startup to attach to the interfaces. The console is passed to every call so its message log stays complete and can be serialized later. 

import "tholian-firewall/actions"
import "tholian-firewall/adapters/mitigations/ebpf"
import "tholian-firewall/insights"
import "tholian-firewall/structs"
import "os"

func main() {

    console := structs.NewConsole(os.Stdout, os.Stderr, 0)

    ebpf.Init(console)
    insights.Init(console)

    if actions.Init(console) == false {
        // no eBPF backend available; fall back or exit
    }

    actions.Forbid(console, "1.3.3.7")
    actions.Forbid(console, "evil.example")

    if actions.Check(console, "1.3.3.7") {
        // traffic to 1.3.3.7 is currently dropped
    }

    actions.Permit(console, "1.3.3.7")
}

Because unpinned BPF maps and XDP links live in the process that created them, the embedding process must stay alive for filtering to continue. A daemon mode with pinned maps is planned.
