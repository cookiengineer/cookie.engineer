Capabilities

Linux capabilities - fragmenting the root model, capability sets, file capabilities, capability-aware programming, user namespaces, and practical examples.

Overview

For decades Unix treated privilege as binary: UID 0 could do anything and everyone else could do nothing. Capabilities split root's power into roughly 40 independent privileges, so a program can be granted exactly the operation it needs - such as binding a low port or opening a raw socket - without full root. This article covers the five capability sets, the execve() transition rules, file capabilities, the capsh tooling, capability-aware programming, and user namespaces. After reading it you can inspect, grant, and drop capabilities on processes and binaries.

Why Capabilities Exist

For decades, Unix security divided the world into two classes: the omnipotent root (UID 0) and everyone else. A process running as root can do anything - read any file, kill any process, load kernel modules, bind to privileged ports, change the system clock. A single vulnerability in a setuid-root binary like /usr/bin/passwd gives the attacker total control.

Linux capabilities break the all-or-nothing root model into approximately 40 distinct privileges. A process can hold CAP_NET_RAW to open raw sockets without the ability to read /etc/shadow . A web server can bind to port 80 with CAP_NET_BIND_SERVICE without any other root powers. This implements the principle of least privilege .

Capability Transition Across execve()

The rules for how capabilities change when a process calls execve() are complex but follow a clear logic: 

Before exec:
  pP = process Permitted
  pE = process Effective
  pI = process Inheritable
  pA = process Ambient
  pB = process Bounding (inherited from parent)

File capabilities (xattr security.capability on the binary):
  fP = file Permitted
  fI = file Inheritable
  fE = file Effective (boolean flag)

Privileged file = setuid/setgid root OR has file capabilities.
For an unprivileged file, F(inheritable/permitted/effective) = 0.

After exec (from capabilities(7)):
  P'(ambient)     = (file is privileged) ? 0 : P(ambient)
  P'(permitted)   = (P(inheritable) & F(inheritable)) |
                    (F(permitted) & P(bounding)) | P'(ambient)
  P'(effective)   = F(effective) ? P'(permitted) : P'(ambient)
  P'(inheritable) = P(inheritable)

For a setuid-root binary the kernel bypasses the above and grants the
full permitted and effective sets with an empty ambient set.

The Ambient Capability Set (Linux 4.3+)

Before ambient capabilities, if a program wanted to execute another non-setuid program while keeping capabilities, it was impossible - capabilities were always dropped. Ambient caps fix this: 

# Example: capsh with ambient capability
# capsh knows how to set ambient capabilities
capsh --caps="cap_net_raw+p cap_net_bind_service+p" \
      --user=user \
      --addamb=cap_net_raw \
      -- -c 'getpcaps $$'

capsh - View and Manipulate Capabilities

# Full capability report of current shell
capsh --print

# Decode hexadecimal capability sets from /proc/PID/status
capsh --decode=0000000000000000

# List all available capabilities on this kernel
capsh --supports

# Run a command with specific capabilities
sudo capsh --caps="cap_net_raw,cap_net_admin+eip cap_setpcap+ep" -- \
    -c 'tcpdump -i any'

# Securebits: control how capabilities propagate
# Securebits prevent UID 0 from automatically getting all capabilities
# and prevent capability sets from changing when UID changes.

# --keep=1  → keep capabilities on setuid transition
# --keep=0  → default: clear capabilities when UID changes
capsh --keep=1 --caps="cap_net_raw+eip" --user=nobody -- \
    -c 'getpcaps $$'

# Check what caps a process has: getpcaps
getpcaps 1      # Check PID 1 (init/systemd)
getpcaps $$     # Current shell
getpcaps $(pidof nginx | cut -d' ' -f1)  # nginx

Inspecting Capabilities via /proc

# Process capability sets (hexadecimal bitmask)
cat /proc/$$/status | grep -i cap
# CapInh: 0000000000000000   ← Inheritable
# CapPrm: 0000000000000000   ← Permitted
# CapEff: 0000000000000000   ← Effective
# CapBnd: 0000000000000000   ← Bounding
# CapAmb: 0000000000000000   ← Ambient

# Decode the hex values
capsh --decode=0000000000000000

# Example: a process with CAP_NET_RAW only
# CapPrm: 0000000000002000 ← bit 13 = CAP_NET_RAW
# capsh --decode=0000000000002000
# → 0x0000000000002000=cap_net_raw
						
// Program that reads its own capabilities
#define _GNU_SOURCE
#include <stdio.h>
#include <linux/capability.h>
#include <sys/capability.h>

int main() {
    cap_t caps = cap_get_proc();
    char* text = cap_to_text(caps, NULL);
    printf("Current capabilities: %s\n", text ? text : "(none)");

    cap_free(text);
    cap_free(caps);

    // Also dump from /proc/self/status
    FILE* f = fopen("/proc/self/status", "r");
    char line[128];
    while (fgets(line, sizeof(line), f))
        if (strstr(line, "Cap"))
            fputs(line, stdout);
    fclose(f);

    return 0;
}

File Capabilities - getcap / setcap

Instead of making a binary setuid-root (granting ALL capabilities), file capabilities grant only specific capabilities to the executed program. 

# Check file capabilities
getcap /usr/bin/ping
# /usr/bin/ping cap_net_raw=ep
# ep = effective + permitted (both sets)

# Set file capabilities
sudo setcap cap_net_raw=ep /path/to/program

# Set multiple capabilities
sudo setcap "cap_net_bind_service,cap_net_raw=ep" /path/to/server

# Remove file capabilities
sudo setcap -r /path/to/program

# Verify
getcap /path/to/program

File capability notation

Notation Meaning
cap_name=ep cap_name added to both permitted and effective
cap_name=eip cap_name added to effective, inheritable, permitted
cap_name=p cap_name added to permitted only (must be activated via cap_set_proc())
all=ep ALL capabilities in effective and permitted (dangerous!)
=(empty) Reset file capabilities to none

File capabilities vs setuid

# Traditional: setuid-root ping (grants ALL root powers)
ls -l /usr/bin/ping
# Before capabilities: -rwsr-xr-x 1 root root ... /usr/bin/ping

# Modern: file capabilities on ping
ls -l /usr/bin/ping
# -rwxr-xr-x 1 root root ... /usr/bin/ping
# No 's' bit! But:
getcap /usr/bin/ping
# /usr/bin/ping cap_net_raw=ep

CAP_NET_RAW Without Root

# File capabilities work on BINARIES (ELF), not scripts directly.
# For scripts, use a wrapper binary or capsh.

# Method 1: Use capsh
sudo capsh --caps="cap_net_raw+eip" --user=$(whoami) -- \
    -c 'python3 -c "
import socket
s = socket.socket(socket.AF_PACKET, socket.SOCK_RAW, socket.ntohs(3))
# Now we have a raw socket without running as root
print(\"Got raw socket!\")
s.close()
"'

# Method 2: Make a Python launcher with file capabilities
# (Python binary itself, not the script, gets the capability)
sudo setcap cap_net_raw=ep /usr/bin/python3.11  # Specific version
# Now any Python 3.11 script can use raw sockets!
# This is a security risk — use a dedicated copy.

# Method 3: Use a minimal C wrapper
cat > /tmp/scap-wrapper.c << 'EOF'
#include <unistd.h>
#include <sys/capability.h>

int main(int argc, char* argv[]) {
    if (argc < 2) return 1;
    // cap_net_raw is bit 13 → 1 << 13 = 0x2000
    cap_t caps = cap_get_proc();
    cap_value_t cap_list[1] = { CAP_NET_RAW };
    cap_set_flag(caps, CAP_EFFECTIVE, 1, cap_list, CAP_SET);
    cap_set_flag(caps, CAP_PERMITTED, 1, cap_list, CAP_SET);
    cap_set_proc(caps);
    cap_free(caps);
    execvp(argv[1], &argv[1]);
    return 1;
}
EOF

gcc -o /tmp/scap-wrapper /tmp/scap-wrapper.c -lcap
sudo setcap cap_net_raw=ep /tmp/scap-wrapper
/tmp/scap-wrapper python3 -c "
import socket; print(socket.socket(socket.AF_PACKET, socket.SOCK_RAW, 3))
"

Capability-Aware Programming

A well-designed program should:

  1. On startup, check which capabilities it actually needs.
  2. Drop all unnecessary capabilities from the Permitted set.
  3. Set the Effective set to only the needed caps when performing privileged operations.
  4. Drop the capability from Effective immediately after use.
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/capability.h>
#include <sys/prctl.h>

void drop_all_caps_except(cap_value_t* keep, int nkeep) {
    cap_t caps = cap_init();  // Start with empty set
    cap_set_flag(caps, CAP_PERMITTED, nkeep, keep, CAP_SET);
    cap_set_flag(caps, CAP_EFFECTIVE, nkeep, keep, CAP_SET);
    if (cap_set_proc(caps) == -1) {
        perror("cap_set_proc");
        exit(1);
    }
    cap_free(caps);

    // Lock the bounding set: no child can exceed what we keep
    for (int i = 0; i <= CAP_LAST_CAP; i++) {
        int needed = 0;
        for (int j = 0; j < nkeep; j++)
            if (keep[j] == i) needed = 1;
        if (!needed)
            prctl(PR_CAPBSET_DROP, i, 0, 0, 0);
    }
}

void use_privilege(cap_value_t cap) {
    cap_t caps = cap_get_proc();
    cap_set_flag(caps, CAP_EFFECTIVE, 1, &cap, CAP_SET);
    cap_set_proc(caps);
    cap_free(caps);
}

void drop_privilege(cap_value_t cap) {
    cap_t caps = cap_get_proc();
    cap_set_flag(caps, CAP_EFFECTIVE, 1, &cap, CAP_CLEAR);
    cap_set_proc(caps);
    cap_free(caps);
}

int main() {
    cap_value_t needed[] = { CAP_NET_RAW };
    drop_all_caps_except(needed, 1);

    printf("Capabilities dropped to CAP_NET_RAW only\n");
    // ... rest of program ...
    return 0;
}

sudo setcap cap_net_raw=ep ./cap-aware

Capability Bounding Set

The bounding set acts as an upper limit for all descendants. If a capability is removed from the bounding set, no child process - not even one running as root - can recover it. 

# Drop capabilities from the bounding set
capsh --drop=cap_sys_admin,cap_sys_module,cap_net_admin -- \
    -c 'capsh --print'

# In a systemd service file:
# CapabilityBoundingSet=CAP_NET_BIND_SERVICE CAP_NET_RAW
# This prevents the service (and all its children) from ever having
# any capability not in this list, even if they become root somehow.
						
# Check securable bits
cat /proc/sys/kernel/cap_last_cap
# 40 — the highest capability number on this kernel

User Namespaces and Capabilities

User namespaces allow an unprivileged user to create a namespace where they appear as UID 0 and have a full set of capabilities - but ONLY within that namespace. These capabilities do not extend to the parent namespace. 

# Create a user namespace (unprivileged)
unshare --user --map-root-user /bin/bash

# Inside the namespace:
id          # uid=0(root) gid=0(root)
capsh --print
# Full capability set inside THIS namespace!
# But if you try to modify anything not owned by you in the parent
# namespace, you'll get EPERM — capabilities are namespace-scoped.

# Mount a tmpfs (uses CAP_SYS_ADMIN within the namespace)
mount -t tmpfs none /tmp
ls /tmp   # Works inside the namespace
exit      # Returns to parent namespace
						
# Run a container with a minimal capability set
podman run --cap-drop=ALL --cap-add=NET_BIND_SERVICE myapp

cap_get_proc / capset Syscall Interface

The libcap functions are wrappers around the raw capget() / capset() syscalls: 

#define _GNU_SOURCE
#include <stdio.h>
#include <linux/capability.h>
#include <sys/syscall.h>
#include <unistd.h>

int main() {
    struct __user_cap_header_struct hdr;
    struct __user_cap_data_struct data[2];

    hdr.version = _LINUX_CAPABILITY_VERSION_3;
    hdr.pid = 0;  // 0 = current process

    // Read current capabilities
    if (syscall(SYS_capget, &hdr, data) == -1) {
        perror("capget");
        return 1;
    }

    printf("Effective:     %08x%08x\n", data[1].effective, data[0].effective);
    printf("Permitted:     %08x%08x\n", data[1].permitted, data[0].permitted);
    printf("Inheritable:   %08x%08x\n", data[1].inheritable, data[0].inheritable);

    return 0;
}

Capability Rules Summary

Root (UID 0):
  - By default, all capabilities in all sets.
  - Securebits can restrict this (capsh --keep=0).
  - Dropping from bounding set is permanent — no going back.

Non-root:
  - Starts with empty capability sets.
  - Gains capabilities from:
    a) File capabilities on the executed binary.
    b) Inheritance through ambient + inheritable sets.
    c) User namespace creation (namespace-local caps).
  - Once a capability is dropped, it requires CAP_SETPCAP to re-add.

setuid transition:
  - setuid(0) from a privileged process: capabilities may change
    depending on securebits.
  - setuid(nonzero): all capabilities dropped unless securebits keep=1.

execve() transition:
  - File capabilities on the new binary interact with the process's
    inheritable/ambient/bounding sets (see transition rules above).

Challenge

Write a Go tool that inspects the effective capability set of a process by parsing /proc/<pid>/status . Decode the CapEff hexadecimal mask and report whether CAP_NET_RAW , CAP_NET_BIND_SERVICE , and CAP_SYS_ADMIN are present. Compare the output with getpcaps <pid> and capsh --print . The snippet reads the current process; extend it to take a PID as an argument. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func parseMask(value string) uint64 {
	fields := strings.Fields(value)
	if len(fields) != 2 {
		return 0
	}
	mask, err := strconv.ParseUint(fields[1], 16, 64)
	if err != nil {
		return 0
	}
	return mask
}

func main() {
	f, err := os.Open("/proc/self/status")
	if err != nil {
		panic(err)
	}
	defer f.Close()

	var eff uint64
	scanner := bufio.NewScanner(f)
	for scanner.Scan() {
		if strings.HasPrefix(scanner.Text(), "CapEff:") {
			eff = parseMask(scanner.Text())
		}
	}

	interesting := map[int]string{
		10: "CAP_NET_BIND_SERVICE",
		13: "CAP_NET_RAW",
		21: "CAP_SYS_ADMIN",
	}
	fmt.Printf("CapEff = 0x%016x\n", eff)
	for bit, name := range interesting {
		state := "absent"
		if eff&(1<<uint(bit)) != 0 {
			state = "present"
		}
		fmt.Printf("  %-24s %s\n", name, state)
	}
}
