Packet Analysis

Investigating attacks using packet captures with tcpdump, tshark, protocol dissection, and real-world pcap analysis.

Overview

Logs record that a connection happened; packets record exactly what moved across the wire. This article covers capture and display filters, protocol dissection, and the analysis of real-world captures with tcpdump, tshark, and tcpreplay.

Required Reading

  • TCP - TCP flags, connection state machine, sequence numbers
  • Network Scanning - scan types ( SYN , ACK, NULL, XMAS) and scan detection
  • HTTP - HTTP request/response structure, headers, methods

Why Packet Analysis

Logs tell you that a connection happened. Packets tell you exactly what data moved across the wire. When investigating an intrusion, the pcap is the ground truth - it captures what actually transpired, not what an application chose to log. Packet analysis is the skill that separates SOC analysts from IR investigators.

tcpdump

tcpdump is the universal packet capture tool. It uses Berkeley Packet Filter (BPF) syntax for filtering, which compiles to BPF bytecode and executes in kernel context before data reaches userspace.

Capture Filters (BPF)

BPF filters discard packets in kernel space, before tcpdump processes them. This is essential for high-throughput links. 

# Capture only TCP traffic to/from 192.168.1.100
tcpdump -i eth0 host 192.168.1.100 and tcp

# Capture only SYN packets (connection initiation / scanning)
tcpdump -i eth0 'tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0'

# Capture only the first 5 packets of each TCP connection (handshake)
tcpdump -i eth0 'tcp[tcpflags] & (tcp-syn|tcp-ack|tcp-fin) != 0'

# Exclude SSH (port 22) and our management IP
tcpdump -i eth0 not port 22 and not host 10.0.0.1

# Capture DNS queries (port 53) — both TCP and UDP
tcpdump -i eth0 port 53

# Capture traffic from a subnet excluding broadcast
tcpdump -i eth0 'src net 192.168.1.0/24 and not broadcast and not multicast'

# Capture ICMP (excluding echo-reply noise)
tcpdump -i eth0 'icmp[icmptype] != icmp-echoreply'

# Capture HTTP GET/POST requests
tcpdump -i eth0 -A 'tcp port 80 and (tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x47455420 or tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x504f5354)'

# Capture only packets with payload (ignore SYN/ACK/FIN-only)
tcpdump -i eth0 'tcp port 443 and (tcp[((tcp[12:1] & 0xf0) >> 2):] > 0)'

# VLAN-tagged traffic
tcpdump -i eth0 'vlan 100'

Output Options

# Standard verbose output
tcpdump -i eth0 -nn -v

# -n  : no name resolution (faster, no DNS leaks)
# -nn : no port name resolution either
# -v  : verbose (TTL, ID, offset, flags, options)
# -vv : more verbose (checksum)
# -vvv: even more (full decode)
# -X  : hex + ASCII dump of packet payload
# -A  : ASCII only (useful for HTTP, SMTP)
# -x  : hex only
# -XX : hex + ASCII for entire frame (including link layer)
# -e  : show link-layer headers (MAC addresses)

# Capture with readable timestamps to file
tcpdump -i eth0 -nn -tttt -w capture.pcap host 192.168.1.100

# Read pcap and display
tcpdump -r capture.pcap -nn -v

# Rotating capture files (50MB each, keep 10)
tcpdump -i eth0 -nn -w capture.pcap -C 50 -W 10

# Capture limited number of packets
tcpdump -i eth0 -c 1000 -w capture.pcap

# Apply time unit
tcpdump -i eth0 -nn -ttt  # delta from previous packet
tcpdump -i eth0 -nn -tttt # human-readable timestamp
tcpdump -i eth0 -nn -ttttt # epoch with microseconds

Statistical Summaries

# Print stats on signal (SIGINT / SIGTERM)
tcpdump -i eth0 -nn -c 1000

# Count packets matching filter
tcpdump -r capture.pcap 'tcp port 443' | wc -l

# Summarize unique source IPs
tcpdump -r capture.pcap -nn 'ip' | awk '{print $3}' | cut -d. -f1-4 | \
    sort | uniq -c | sort -rn | head -20

tshark / Wireshark

tshark is the command-line version of Wireshark. It can read pcaps, apply display filters, and output structured data. The key distinction: capture filters (BPF, applied at capture time) vs display filters (Wireshark syntax, applied post-capture).

Display Filters

Display filters use a packet-field-oriented syntax. They run after capture and can decode protocol layers that BPF cannot express. 

# Read pcap with display filter
tshark -r capture.pcap -Y 'http.request.method == "GET"'

# Common display filters
tshark -r capture.pcap -Y 'tcp.flags.syn == 1 and tcp.flags.ack == 0'     # SYN only
tshark -r capture.pcap -Y 'tcp.flags.reset == 1'                           # RST packets
tshark -r capture.pcap -Y 'http.request or http.response'                  # All HTTP
tshark -r capture.pcap -Y 'http.user_agent contains "curl"'                # curl clients
tshark -r capture.pcap -Y 'dns.qry.name contains "malware"'                # DNS queries
tshark -r capture.pcap -Y 'ssl.handshake.type == 1'                        # TLS ClientHello
tshark -r capture.pcap -Y 'tcp.analysis.retransmission'                    # Retransmissions
tshark -r capture.pcap -Y 'ip.dst == 10.0.0.1 and not tcp.port == 22'     # Combined
tshark -r capture.pcap -Y 'tcp.window_size < 1000'                         # Small windows
tshark -r capture.pcap -Y 'tcp.flags == 0x29'                              # SYN+FIN (nmap XMAS)
tshark -r capture.pcap -Y 'tcp.flags == 0x00'                              # NULL scan
tshark -r capture.pcap -Y 'frame contains "password"'                      # Packet grep
tshark -r capture.pcap -Y 'http.file_data contains "base64"'               # File data search

Field Extraction

# Extract specific fields with headers
tshark -r capture.pcap -T fields \
    -e frame.time \
    -e ip.src \
    -e ip.dst \
    -e tcp.srcport \
    -e tcp.dstport \
    -e tcp.flags.syn \
    -e tcp.flags.ack \
    -E header=y -E separator=,

# Extract HTTP host and URI
tshark -r capture.pcap -T fields -e http.host -e http.request.uri -Y 'http.request'

# Extract DNS queries and responses
tshark -r capture.pcap -T fields -e dns.qry.name -e dns.a -Y 'dns.flags.response == 1'

# Extract TLS server names (SNI)
tshark -r capture.pcap -T fields -e tls.handshake.extensions_server_name -Y 'ssl.handshake.extensions_server_name'

Follow TCP Stream

# Extract and follow a TCP stream by number
tshark -r capture.pcap -z follow,tcp,ascii,0

# Export HTTP objects (files transferred over HTTP)
tshark -r capture.pcap --export-objects "http,/tmp/http-objects"

# Extract all TCP payloads for a specific connection
tshark -r capture.pcap -Y 'ip.addr == 192.168.1.100 and tcp.port == 80' -T fields -e tcp.payload

Statistics

# Protocol hierarchy statistics
tshark -r capture.pcap -z io,phs

# Endpoint statistics (traffic per host)
tshark -r capture.pcap -z endpoints,tcp

# Conversation statistics (traffic per host pair)
tshark -r capture.pcap -z conv,tcp

# HTTP request statistics
tshark -r capture.pcap -z http,req,tree

# TCP stream graph (RTT vs time)
tshark -r capture.pcap -z io,stat,0,"AVG(tcp.analysis.ack_rtt)tcp.analysis.ack_rtt"

Protocol Dissection

TCP Flags: Scan Detection

Different scan types set different flag combinations. Identifying them in a pcap reveals attacker activity. 

# SYN scan: many SYN packets to different ports, few completions
tcpdump -r scan.pcap -nn 'tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0' | wc -l

# tshark: Identify scan type by flag pattern
tshark -r scan.pcap -T fields -e tcp.flags -e ip.src -e tcp.dstport | \
    awk '{flags[$1]++} END {for (f in flags) print f, flags[f]}'

# Output explanation:
# 0x02 = SYN alone (SYN scan)
# 0x12 = SYN+ACK (from open port)
# 0x14 = RST+ACK (from closed port after SYN)
# 0x04 = RST alone (response to unexpected packet)
# 0x29 = SYN+FIN+URG (XMAS scan)
# 0x00 = no flags (NULL scan)

HTTP Request Extraction

# Extract all HTTP GET request paths
tshark -r capture.pcap -Y 'http.request.method == "GET"' \
    -T fields -e http.request.uri | sort | uniq -c | sort -rn

# Extract full HTTP requests with host headers
tshark -r capture.pcap -Y 'http.request' -T fields \
    -e frame.time -e ip.src -e http.host -e http.request.method \
    -e http.request.uri -e http.user_agent

# Identify directory enumeration (many 404 responses)
tshark -r capture.pcap -Y 'http.response.code == 404' \
    -T fields -e ip.src -e http.request.uri | awk '{a[$1]++} END {for (i in a) print i, a[i]}'

# Detect SQL injection patterns in URI
tshark -r capture.pcap -Y 'http.request.uri contains "UNION" or http.request.uri contains "SELECT"' \
    -T fields -e ip.src -e http.request.uri

DNS Tunneling Detection

DNS tunneling encodes data in DNS queries/responses. Indicators: - Unusually long query names - High entropy in subdomain labels - High volume of queries to a single domain - Unusual record types (TXT, NULL) 

# Find long DNS query names
tshark -r capture.pcap -Y 'dns.qry.name.len > 50' \
    -T fields -e ip.src -e dns.qry.name -e dns.qry.type

# Count queries per client per domain
tshark -r capture.pcap -Y 'dns.flags.response == 0' -T fields \
    -e ip.src -e dns.qry.name | sort | uniq -c | sort -rn | head -20

# Extract all TXT record responses (common tunneling vector)
tshark -r capture.pcap -Y 'dns.txt' -T fields -e dns.txt

# Identify entropy of subdomains
tshark -r capture.pcap -Y 'dns.qry.name matches "^[a-z0-9]{20,}\\."' \
    -T fields -e dns.qry.name

PCAP File Format

A pcap file consists of: 1. Global header (magic number 0xa1b2c3d4 or 0xd4c3b2a1, version, timezone, snaplen, link type) 1. Packet records: (timestamp, captured length, original length, link-layer data)

pcapng (next-generation) adds: multiple interfaces, packet comments, name resolution records, dropped packet counters. 

# Inspect pcap file metadata
capinfos capture.pcap

# Merge multiple pcaps
mergecap capture1.pcap capture2.pcap -w merged.pcap

# Split by time
editcap -A "2026-06-26 08:00:00" -B "2026-06-26 12:00:00" capture.pcap window.pcap

# Split by packet count
editcap -c 10000 capture.pcap split.pcap

# Strip VLAN tags
editcap -L capture.pcap stripped.pcap

Analyzing Real-World Captures

Identifying C2 Traffic

# 1. Find long-lived, low-data connections (beacons)
tshark -r capture.pcap -T fields \
    -e tcp.stream -e frame.time_epoch -e ip.src -e ip.dst -e tcp.dstport | \
    python3 -c "
import sys
from collections import defaultdict
streams = defaultdict(list)
for line in sys.stdin:
    parts = line.strip().split('\t')
    if len(parts) >= 3:
        streams[(parts[2], parts[3])].append(float(parts[1]))
for (src, dst), times in streams.items():
    if len(times) >= 3:
        intervals = [times[i]-times[i-1] for i in range(1, len(times))]
        if len(set(round(i)) for i in intervals) <= 2:
            print(f'Beacon: {src} -> {dst}: {len(times)} conns, ~{intervals[0]:.0f}s interval')
"

# 2. Find unusual outbound ports
tshark -r capture.pcap -T fields -e ip.src -e tcp.dstport | \
    grep -vE '\t(80|443|53|22|25|587|993|995|8080|8443)$' | \
    sort | uniq -c | sort -rn | head -20

# 3. Find user-agent strings (malware often uses none or custom)
tshark -r capture.pcap -Y 'http.user_agent' -T fields -e ip.src -e http.user_agent | \
    sort | uniq -c | sort -rn

Data Exfiltration

# Asymmetric traffic ratio (much more outbound than inbound)
tshark -r capture.pcap -T fields -e ip.src -e ip.dst -e frame.len | \
    python3 -c "
import sys
from collections import defaultdict
out, inb = defaultdict(int), defaultdict(int)
for line in sys.stdin:
    parts = line.strip().split('\t')
    if len(parts) == 3:
        out[parts[0]] += int(parts[2])  # source sent
        inb[parts[1]] += int(parts[2])  # dest received
for ip in set(list(out.keys()) + list(inb.keys())):
    ratio = out.get(ip,0) / max(inb.get(ip,0), 1)
    if ratio > 10 and out[ip] > 1000000:
        print(f'Exfiltration candidate: {ip} sent {out[ip]} bytes, ratio {ratio:.1f}')
"

# POST requests with large body
tshark -r capture.pcap -T fields -e ip.src -e http.request.method -e ip.dst -e frame.len \
    -Y 'http.request.method == "POST"' | \
    awk '$4 > 100000 {print $1" POST "$3, $4" bytes"}'

tcpreplay

Replay captured traffic onto a live network for testing detection rules, IDS tuning, and training. 

pacman -S tcpreplay

# Replay pcap at captured speed
tcpreplay -i eth0 capture.pcap

# Replay at 10x speed
tcpreplay -i eth0 --multiplier=10 capture.pcap

# Replay at constant Mbps
tcpreplay -i eth0 --mbps=100 capture.pcap

# Loop replay indefinitely
tcpreplay -i eth0 --loop=0 capture.pcap

# Preload into RAM for consistent timing
tcpreplay -i eth0 --preload-pcap capture.pcap

Challenge

The container ships tcpdump, tshark, and tcpreplay, and builds /root/attack-traffic.pcap from a simulated attack run. Identify the scan, the injection attempt, the beaconing, and the exfiltration using only the capture.

packet-analysis.Containerfile

podman build -f blueteam/packet-analysis.Containerfile -t packet-analysis-ctf .
podman run -it --rm packet-analysis-ctf

Start with the port scan and the beacon interval:

tshark -r attack-traffic.pcap -Y 'tcp.flags.syn == 1 and tcp.flags.ack == 0' \
    -T fields -e ip.src -e tcp.dstport | sort -n | uniq -c
tshark -r attack-traffic.pcap -Y 'ip.dst == 203.0.113.99' -T fields -e frame.time_epoch
