Memory Manager

Page table walk, TLB shootdown, page fault handling, copy-on-write, swap, huge pages, NUMA, page reclaim, reverse mapping, and kernel memory accounting.

Overview

The memory manager owns every virtual-to-physical translation in the system. This article follows a page from a fault on a user address through the four- and five-level page tables, the TLB, the page allocator, and the reclaim path, and shows how to inspect the result with /proc , /sys , and perf .

Required Reading

  • Virtual Memory - page tables, TLB, mmap() internals, demand paging, ASLR, OOM killer

The Memory Manager's Job

The memory manager is the kernel subsystem responsible for translating virtual addresses to physical addresses, handling page faults, managing the page cache, reclaiming memory under pressure, and enforcing process isolation. It is not a single function or file - it spans /usr/src/linux/mm/ , consuming roughly 150,000 lines of C across 80+ source files. Every memory access in the system passes through code that originates here. 

User process requests a page (via mmap, brk, or implicit demand paging):
    │
    ▼
  ┌──────────────────┐
  │  Page Fault       │ ← CPU raises #PF exception
  │  Handler          │    (arch/x86/mm/fault.c: do_page_fault)
  └────────+─────────┘
           │
           ▼
  ┌──────────────────┐
  │  Address in       │──── No ──► SIGSEGV sent to process
  │  VMA range?       │            (do_user_addr_fault)
  └────────+─────────┘

  ┌──────────────────┐
  │  Permission       │──── No ──► SIGSEGV (write to read-only mapping)
  │  check            │

Page Table Walk - Deep Dive

Virtual-to-physical translation is a multi-level lookup. Each level narrows the search by indexing into a 512-entry table. The final PT E (Page Table Entry) contains the physical frame number and permission bits.

x86-64 4-Level Paging

Virtual Address (48 bits):
┌──────+──────+──────+──────+────────────┐
│ PML4 │ PDPT │  PD  │  PT  │   Offset   │
│ 9bit │ 9bit │ 9bit │ 9bit │   12 bit   │
│47:39 │38:30 │29:21 │20:12 │   11:0     │
└──────+──────+──────+──────+────────────┘

Page Table Entry bits (x86-64 PTE, 8 bytes):
  Bits 0-11:        Flags
    Bit 0  (P):      Present (1 = page in memory)
    Bit 1  (R/W):    Read/Write (0 = read-only, 1 = writeable)
    Bit 2  (U/S):    User/Supervisor (0 = kernel only, 1 = user accessible)
    Bit 3  (PWT):    Page Write-Through
    Bit 4  (PCD):    Page Cache Disable
    Bit 5  (A):      Accessed (set by CPU on read/write)
    Bit 6  (D):      Dirty (set by CPU on write)
    Bit 7  (PAT):    Page Attribute Table (or PS at PDPT/PD level)
    Bit 8  (G):      Global (not flushed on CR3 reload)
    Bit 9-11:        Available to OS (ignored by hardware)
  Bits 12-51:       Physical Frame Number (PFN)
    Bits 52-58:      Available to OS
  Bits 59-62:        Protection Keys (PKU)
  Bit 63  (XD/NX):   Execute Disable (1 = cannot execute)

ARM64 PTE entries (4-level, 48-bit VA)

ARM64 uses a different bit layout:
  Bits 0-1:    Type (0b11 = valid descriptor)
  Bit 2:       Table vs Block/Page (1 = table, 0 = block/page)
  Bits 5-4:    Memory attributes index (MAIR)
  Bit 6:       Access flag (AF) — no hardware update on some CPUs
  Bit 7:       Dirty bit modifier (DBM) — hardware dirty bit
  Bit 10:      Access Permission (AP[1], AP[2] in upper attribute)
  Bits 11-12:  Shareability
  Bit 53:      Privileged execute-never (PXN)
  Bit 54:      Unprivileged execute-never (UXN)
  Bits 47-12:  Output physical address [47:12]
						
# Examine page table entries in a running process
# Dump PTEs for a specific memory range (needs /proc/PID/pagemap)
PID=$$
VADDR=0x555555554000  # Typical text segment start
PAGESIZE=$(getconf PAGE_SIZE)

sudo python3 -c "
import os, struct

pid = $PID
vaddr = $VADDR
pagesize = $PAGESIZE

pagemap_path = f'/proc/{pid}/pagemap'
with open(pagemap_path, 'rb') as f:
    offset = (vaddr // pagesize) * 8
    f.seek(offset)
    entry = struct.unpack('Q', f.read(8))[0]

present = bool(entry & (1 << 63))
swapped = bool(entry & (1 << 62))
pfn = entry & ((1 << 55) - 1)
r_soft = bool(entry & (1 << 61))
flags = entry >> 63  # Just present/swap bits for quick check

if present:
    print(f'VA: 0x{vaddr:x}  PTE: 0x{entry:016x}')
    print(f'  Present: yes, PFN: 0x{pfn:x}')
    print(f'  Physical: 0x{(pfn * pagesize) + (vaddr % pagesize):x}')
    print(f'  Flags: W={bool(entry & (1<<1))} U={bool(entry & (1<<2))} '
          f'D={bool(entry & (1<<6))} NX={bool(entry & (1<<63))}')
elif swapped:
    print(f'VA: 0x{vaddr:x}  Swapped (swap offset in bits 54-0)')
else:
    print(f'VA: 0x{vaddr:x}  Not mapped')
"

5-Level Paging

With 5-level paging, the virtual address expands to 57 bits (128 PiB address space). An additional P5GD/PGD level sits above PML4: 

57-bit VA:  [PGD:9][P4D:9][PDPT:9][PD:9][PT:9][Offset:12]
Levels:     CR3 → PGD → P4D → PDPT → PD → PT → Page
						
# Check if running with 5-level paging
grep "5-level" /proc/cpuinfo && echo "5-level paging supported" || echo "4-level paging only"
grep "CONFIG_X86_5LEVEL=" /boot/config-$(uname -r)

TLB - Translation Lookaside Buffer

The TLB is a small, CPU -internal cache that maps virtual pages to physical frames. It is multi-level (L1 ITLB/DTLB, L2 STLB), virtually-tagged on some designs, and per- CPU -core. 

Intel Ice Lake TLB hierarchy (example):

L1 ITLB:  128 entries (4 KiB) + 8 entries (2 MiB/4 MiB)   ← instructions
L1 DTLB:  96 entries (4 KiB) + 32 entries (2 MiB/4 MiB)    ← data
L2 STLB:  2048 entries (4 KiB/2 MiB)                        ← shared, unified
						
TLB Lookup Flow:
  Virtual address
       │
       ▼
  ┌─────────┐
  │ L1 TLB  │ → Hit: physical address (fast, 1-2 cycles)
  │ Lookup  │ → Miss:
  └────+────┘     │
       │          ▼
       │    ┌─────────┐
       │    │ L2 STLB │ → Hit: physical address (slower, ~10 cycles)
       │    │ Lookup  │ → Miss:
       │    └────+────┘     │
       │         │          ▼
       │         │     Page table walk (4-5 memory accesses, ~100 cycles)
       │         │          │
       │         │          ▼
       │         │     Physical address inserted into TLB (evicts LRU entry)
       │         │          │
       ▼         ▼          ▼
    Physical address delivered to cache subsystem

TLB Shootdown

When a page table entry is modified (unmapped, permissions changed), every CPU core that might have that translation cached in its TLB must be notified. This is called a TLB shootdown, implemented via Inter-Processor Interrupts ( IP Is). 

TLB shootdown sequence:
  1. CPU A modifies PTE (e.g., unmaps a page)
  2. CPU A sends IPI to all CPUs that might have cached the PTE
  3. Each target CPU:
     a. Receives IPI
     b. Executes TLB flush handler
     c. Executes invlpg for the specific address (or reloads CR3)
     d. Acknowledges completion
  4. CPU A waits for all acknowledgments
  5. Operation completes (CPU A can now free the physical page)

Cost: TLB shootdown is expensive.
  - IPI latency: ~1000 cycles
  - Context switch: TLB flush via CR3 reload → hundreds of TLB misses on resume
  - PCID reduces the cost by tagging TLB entries with address-space IDs
						
# Count TLB-related performance events
sudo perf stat -e dtlb_load_misses.miss_causes_a_walk,dtlb_store_misses.miss_causes_a_walk \
    -e itlb_misses.miss_causes_a_walk \
    -e page-faults \
    sleep 2 2>&1 | grep -E "miss|fault"

# Check PCID support
grep -q pcid /proc/cpuinfo && echo "PCID supported" || echo "No PCID"

# ASID on ARM64 (equivalent to PCID)
grep -q asid /proc/cpuinfo 2>/dev/null && echo "ASID in flags" || true

Page Fault Handling

Page faults are divided into major and minor:

  • Minor fault : Page is in memory (page cache, swap cache, zero page), just needs PT E update. Cheap.
  • Major fault : Page must be read from disk. Requires I/O, the process blocks, and latency spikes.
// /usr/src/linux/arch/x86/mm/fault.c — do_user_addr_fault()
// Simplified flow for a page fault at address addr:

void do_user_addr_fault(struct pt_regs *regs, unsigned long error_code,
                         unsigned long address)
{
    struct vm_area_struct *vma;
    struct mm_struct *mm = current->mm;

    // 1. Find the VMA that covers this address
    vma = find_vma(mm, address);
    if (!vma || vma->vm_start > address) {
        // No VMA → SIGSEGV
        goto bad_area;
    }

    // 2. Permission check
    if (error_code & X86_PF_WRITE) {
        if (!(vma->vm_flags & VM_WRITE))
            goto bad_area;  // Write to read-only mapping
        // For write to a shared cow page:
        if (vma->vm_flags & VM_SHARED) {
            if (!(vma->vm_flags & VM_MAYWRITE))
                goto bad_area;
        }
    }
    if (error_code & X86_PF_INSTR) {
        if (!(vma->vm_flags & VM_EXEC))
            goto bad_area;  // Execute on NX mapping
    }

    // 3. Handle the fault (mm/memory.c: handle_mm_fault())
    fault = handle_mm_fault(vma, address, flags, regs);
    if (fault & VM_FAULT_ERROR) {
        if (fault & VM_FAULT_OOM)
            goto out_of_memory;
        if (fault & VM_FAULT_SIGBUS)
            goto do_sigbus;
    }
    return;

bad_area:
    force_sig_fault(SIGSEGV, SEGV_MAPERR, (void __user *)address);
    return;
}

Page fault error code bits (x86-64)

bit 0: P   — 0 = non-present page, 1 = protection violation
bit 1: W/R — 0 = read access, 1 = write access
bit 2: U/S — 0 = kernel-mode access, 1 = user-mode access
bit 3: RSVD— 0 = not reserved, 1 = reserved bit violation
bit 4: I/D — 0 = data access, 1 = instruction fetch
bit 5: PK  — protection key violation
bit 6: SS  — shadow stack access
bit 15: SGX — SGX-related
bit 31: RMP — SEV-SNP RMP violation
						
# Count page faults for a process
cat /proc/$$/stat | awk '{print "Minor faults:", $10, "  Major faults:", $12}'

# Total faults in your shell's lifetime
echo "Min: $(awk '{print $10}' /proc/$$/stat)  Maj: $(awk '{print $12}' /proc/$$/stat)"

# Trace page faults in real time (perf)
sudo perf stat -e page-faults find /usr -name "*.h" 2>&1 | grep page-faults

# Detailed fault statistics
cat /proc/vmstat | grep -E "^(pgfault|pgmajfault|pgpgin|pgpgout|pswpin|pswpout)"

Copy-on-Write (CoW)

Copy-on-write is the optimization that makes fork() fast. Instead of copying every page of the parent's address space, the child shares the parent's pages as read-only. When either tries to write, a page fault occurs, a new physical page is allocated, the data is copied, and the page table is updated. 

fork() CoW Sequence:
  Parent process                    Child process
  ──────────────                    ─────────────
  
  fork() called:
    ├─ task_struct copied
    ├─ mm_struct shared (reference count increased)
    ├─ All PTEs marked read-only
    │  (even if they were writable before)
    └─ CR3 not changed
  
  Both parent and child now share all writable pages as read-only.
  
  Parent writes to page X:
    ├─ #PF (write to read-only page)
    ├─ do_wp_page() detects CoW
    ├─ alloc_pages() → new physical page
    ├─ Copy 4 KiB from original to new page
    ├─ Update parent's PTE → writable, new PFN
    ├─ Decrement original page's _refcount
    ├─ If _refcount == 1 (only child uses it):
    │   Mark child's PTE writable again
    └─ Return → write succeeds
						
// /usr/src/linux/mm/memory.c — do_wp_page() (simplified)
static vm_fault_t do_wp_page(struct vm_fault *vmf)
{
    struct vm_area_struct *vma = vmf->vma;

    // If this is the only reference, just mark it writable
    if (page_mapcount(vmf->page) == 1 &&
        page_count(vmf->page) == 1) {
        // Reuse the page, mark PTE writable
        return wp_page_reuse(vmf);
    }

    // Multiple references → must copy
    return wp_page_copy(vmf);
}
						
# Observe CoW behavior:
# Write a program that forks, then monitor /proc/PID/smaps_rollup

python3 << 'EOF'
import os, time, sys

print(f"Parent PID: {os.getpid()}")

# Allocate some memory and write to it
data = bytearray(10 * 1024 * 1024)  # 10 MiB
for i in range(0, len(data), 4096):
    data[i] = 0x41

pid = os.fork()
if pid == 0:
    # Child: write to the data
    time.sleep(0.5)
    for i in range(0, len(data), 4096):
        data[i] = 0x42
    print(f"Child {os.getpid()} wrote to CoW pages")
    os._exit(0)
else:
    time.sleep(1)
    os.waitpid(pid, 0)
    print("Fork CoW test completed")
EOF

Working Set and Page Replacement

The kernel must decide which pages to evict when memory is scarce. Linux uses a two-list LRU strategy (active + inactive lists) for each reclaimable page type. 

Two-List LRU Strategy:

New Page Allocated
       │
       ▼
┌──────────────┐
│  Inactive     │ ← Pages not recently accessed
│  LRU list    │    When memory pressure rises, eviction
│              │    starts from the tail of this list.
└──────+───────┘
       │ Page accessed (PG_referenced set)
       │
       ▼
┌──────────────┐
│  Active       │ ← Pages recently accessed
│  LRU list    │    Pages that survive here are "working set"
│              │    When inactive list is low, demote from
└──────+───────┘    active to inactive.
       │ Non-accessed for a while
       │
       ▼
Back to Inactive LRU (or evicted)

For anonymous pages:  anon_active → anon_inactive → swap
For file pages:       file_active → file_inactive → free (or writeback)
For unevictable:      mlocked, ramfs → never evicted
						
# Inspect LRU lists
cat /proc/meminfo | grep -E "Active|Inactive|Unevictable|Mlocked"
# Active:      1234567 kB  ← pages on active list
# Inactive:     765432 kB  ← pages on inactive list
# Active(anon):  500000 kB
# Inactive(anon):200000 kB
# Active(file):  734567 kB
# Inactive(file):565432 kB

# Watch reclaim activity
cat /proc/vmstat | grep -E "pgscan|pgsteal|kswapd"
# pgscan_kswapd    — pages scanned by kswapd
# pgsteal_kswapd   — pages reclaimed by kswapd
# pgscan_direct    — pages scanned by direct reclaim
# pgsteal_direct   — pages reclaimed by direct reclaim

Swap Subsystem

When anonymous memory must be evicted, it is written to swap space. Linux supports multiple swap areas (partitions, files) with priorities. The swap subsystem uses a swap cache to avoid duplicate writes and to handle race conditions between page-out and subsequent page-in. 

Swap Lifecycle:
  Page on anonymous LRU
       │
       ▼ (memory pressure, page at tail of inactive list)
  ┌───────────────────┐
  │ add_to_swap()     │ ← Allocates a swap entry (slot on disk)
  │                   │    Maps page → swap entry
  └────────+──────────┘
           ▼
  ┌───────────────────┐
  │ Pageout I/O       │ ← Submits write to swap device
  │ (swap_writepage)  │
  └────────+──────────┘
           ▼
  ┌───────────────────┐
  │ Page freed         │ ← Physical frame returned to allocator
  │ PTE updated        │    PTE → swap entry (not zero)
  └───────────────────┘
       
  ... Later, process accesses the swapped-out page ...
       
  ┌───────────────────┐
  │ Page fault         │ ← #PF, PTE points to swap entry
  │ do_swap_page()     │
  └────────+──────────┘
           ▼
  ┌───────────────────┐
  │ Swap cache lookup  │── Hit ──► Page already being read, wait
  │                    │── Miss ─► Alloc new page, submit read I/O
  └────────+──────────┘
           ▼
  ┌───────────────────┐
  │ Page returned to    │
  │ process (minor      │ ← Not a major fault (swap is faster than disk fs)
  │  fault)             │
  └───────────────────┘

zswap: Compresses pages before writing them to swap, storing them in a compressed RAM pool. This avoids slow disk I/O for compressible pages.

frontswap: A hook that allows a backend (like Xen tmem or VM ware balloon driver) to intercept swap-out before it reaches disk.

Huge Pages

Standard 4 KiB pages create enormous page tables (4 GiB of RAM = 1 million pages = 8 MiB of page tables). Huge pages reduce TLB pressure and page table overhead at the cost of internal fragmentation and allocation latency.

x86-64 huge page sizes

2 MiB huge pages (PMD-level):
  - One PMD entry covers 2 MiB (512 × 4 KiB pages)
  - PTE level is skipped → 1 less memory access per TLB miss
  - Page table walk: CR3 → PML4 → PDPT → PD → 2 MiB page
  - Used by: THP (Transparent Huge Pages), hugetlbfs

1 GiB huge pages (PUD-level):
  - One PUD entry covers 1 GiB (512 × 2 MiB pages)
  - PT and PD levels are skipped → 2 less memory accesses
  - Page table walk: CR3 → PML4 → PDPT → 1 GiB page
  - Used by: hugetlbfs, static huge page pools (not THP)
  - Requires `hugetlb.1G=yes` on kernel cmdline
						
4 KiB page walk:          2 MiB huge page walk:
  CR3                       CR3
   │                         │
   ▼                         ▼
  PML4                      PML4
   │                         │
   ▼                         ▼
  PDPT                      PDPT
   │                         │
   ▼                         ▼
  PD                        PD  → 2 MiB page (PS=1 in PDE)
   │                         (No PT level!)
   ▼
  PT
   │
   ▼
  4 KiB page

Transparent Huge Pages (THP)

THP automatically promotes contiguous 4 KiB pages to 2 MiB huge pages when possible. The kernel daemon khugepaged scans memory for merge opportunities. When a THP must be split (e.g., mprotect with smaller granularity), it's demoted back to 4 KiB pages.

NUMA - Non-Uniform Memory Access

On multi-socket systems, each CPU has local memory (fast) and remote memory (2-3x slower). The kernel's page allocator and scheduler are NUMA-aware, preferring to allocate memory from the local node and schedule threads on the CPU closest to their memory. 

NUMA Topology (2-socket system):

┌───────────────────────┐   ┌───────────────────────┐
│     NUMA Node 0       │   │     NUMA Node 1       │
│  ┌──────┐ ┌────────┐ │   │  ┌──────┐ ┌────────┐ │
│  │CPU 0 │ │CPU 1   │ │   │  │CPU 2 │ │CPU 3   │ │
│  └──+───┘ └───+────┘ │   │  └──+───┘ └───+────┘ │
│     │         │       │   │     │         │       │
│  ┌──+─────────+──┐   │   │  ┌──+─────────+──┐   │
│  │ Memory Ctrl  │   │   │  │ Memory Ctrl  │   │
│  │ (local DIMMs)│   │   │  │ (local DIMMs)│   │
│  └──────────────┘   │   │  └──────────────┘   │
│                      │   │                      │
│  16 GiB DDR5         │   │  16 GiB DDR5         │
└───────────────────────┘   └───────────────────────┘
         │                            │
         └──────── QPI/UPI ───────────┘
                (interconnect)

Access costs:
  Local:  ~80-100 ns
  Remote: ~140-180 ns (1.5-2x)

Page allocation with NUMA:
  GFP_KERNEL  → try local node, fallback to remote nodes
  GFP_THISNODE → only local node, return NULL if OOM
  mbind()/set_mempolicy() → explicit per-process node preferences

#          21 10 (node 1→0 = 21, node 1→1 = 10)
# 10 = local (100% bandwidth), 21 = remote (70% bandwidth)

Memory Reclaim and kswapd

When memory runs low, pages must be reclaimed. Reclamation happens on two paths:

  1. Background (kswapd): Woken when free memory drops below the "low" watermark. Runs asynchronously, reclaiming pages until free memory exceeds the "high" watermark.
  1. Direct reclaim: When an allocation fails despite kswapd's efforts (or before kswapd has responded), the allocation path itself performs synchronous reclaim. This is expensive - the allocating process blocks until pages are freed.
Memory Watermarks:
  High ───────────────────── kswapd stops reclaiming
         ▲
  Low  ───────────────────── kswapd wakes up (async reclaim starts)
         ▲
  Min  ───────────────────── Direct reclaim (synchronous, process blocks)
         ▼
  0    ───────────────────── OOM killer activates
						
# Check memory watermarks
cat /proc/zoneinfo | grep -E "(Node|pages free|min|low|high)" | head -20

# Reclaim activity
cat /proc/vmstat | grep -E "(kswapd|direct|pgscan|pgsteal)"

# Pressure stall information
cat /proc/pressure/memory

# Manual reclaim trigger
echo 3 | sudo tee /proc/sys/vm/drop_caches  # Drop pagecache, dentries, inodes

# Check which pages are reclaimable
cat /proc/meminfo | grep -E "SReclaimable|SUnreclaim|Cached|Buffers"

Reverse Mapping (rmap)

Reverse mapping solves the problem: "Given a physical page, which PT Es point to it?" When the kernel needs to evict a page, it must find and invalidate every PT E that references it. The rmap subsystem tracks this information through anon_vma and address_space structures. 

Page → PTE mappings:

Anonymous page (swappable):
  struct page → mapping → struct anon_vma
    → anon_vma_chain (avc) → vma → mm → page table → PTE

File-backed page:
  struct page → mapping → struct address_space
    → i_mmap (interval tree of VMAs)
    → For each VMA: mm → page table → PTE
						
# Rmap-related kernel statistics
cat /proc/vmstat | grep -E "rmap|pte|pmd|pud"

# Trace rmap operations
# (requires debugfs mounted and root)
echo 1 | sudo tee /sys/kernel/debug/tracing/events/rmap/try_to_unmap/enable 2>/dev/null
sleep 0.1
sudo cat /sys/kernel/debug/tracing/trace | head -10
echo 0 | sudo tee /sys/kernel/debug/tracing/events/rmap/try_to_unmap/enable 2>/dev/null

Page Cache Interaction

The page cache stores file data in memory. It sits between the VFS and the block layer, absorbing reads and delaying writes. The memory manager treats file-backed pages differently from anonymous pages:

  • File-backed pages can be evicted without swap (just write back dirty data)
  • Anonymous pages require swap to evict
  • Shared file-backed pages (libraries, executables) are reclaimed by dropping them from the page cache
# Page cache statistics
cat /proc/meminfo | grep -E "^Cached|^Buffers|^Dirty|^Writeback"

# Active vs inactive file pages
cat /proc/meminfo | grep "file"

# Page cache hit rate (approximate via pgpgin/pgpgout)
awk '{ printf "Page cache reads: %d pages (%.1f MiB)\n", $1, $1*4096/1048576 }' /proc/vmstat 2>/dev/null | head -1
cat /proc/vmstat | grep pgpgin

Memory Control Groups (memcg)

Memory cgroups limit, account, and isolate memory usage for groups of processes. Each memcg has its own LRU lists, page counters, and OOM settings - enabling container memory limits, per-service charging, and accurate accounting. 

Memory cgroup accounting:
  mem_cgroup → memory.stat (counters)
    ├─ anon      — anonymous memory
    ├─ file      — file-backed memory (page cache)
    ├─ kernel    — kernel structures (not reclaimable)
    ├─ kernel_stack — per-thread kernel stacks
    ├─ slab      — slab allocator charges
    ├─ sock      — socket buffers
    ├─ shmem     — shared memory
    ├─ file_mapped — file-backed pages mapped into processes
    ├─ file_dirty  — dirty file pages
    ├─ file_writeback — file pages under writeback
    ├─ swap      — swapped-out anonymous memory
    └─ pgpgin/pgpgout — I/O counters
						
# Inspect the memory cgroup for the current process
cat /proc/$$/cgroup

# If using cgroups v2, check memory controller
cat /sys/fs/cgroup/$(cat /proc/$$/cgroup | cut -d: -f3)/memory.current 2>/dev/null
cat /sys/fs/cgroup/$(cat /proc/$$/cgroup | cut -d: -f3)/memory.stat 2>/dev/null | head -20

# System-wide memory info
cat /proc/meminfo
# Key fields:
#   MemTotal        — total usable RAM
#   MemFree          — completely unused RAM
#   MemAvailable     — RAM available for new allocations (includes reclaimable)
#   Cached           — page cache (can be reclaimed)
#   Buffers          — block device buffer cache
#   Active/Inactive  — LRU lists
#   AnonPages        — anonymous (heap, stack) pages
#   Mapped           — file-backed pages mapped into processes
#   Shmem            — tmpfs, shared memory
#   KReclaimable     — kernel reclaimable (SReclaimable)
#   KernelStack      — kernel stack memory
#   PageTables       — page table memory
#   CommitLimit      — max allocatable with overcommit
#   Committed_AS     — currently committed

/proc/meminfo for Exploit Development

# Critical fields for assessing the memory state before exploitation:

# How much physical memory is free (completely untouched)?

Kernel Same-page Merging (KSM)

KSM scans anonymous pages for identical content and merges them into a single copy-on-write page. Originally designed for virtual machine memory deduplication, it can be used by any application via madvise(MADV_MERGEABLE) . 

# KSM status
cat /sys/kernel/mm/ksm/run             # 1 = enabled
cat /sys/kernel/mm/ksm/pages_shared    # Pages being shared
cat /sys/kernel/mm/ksm/pages_sharing   # Pages saved (additional refs)
cat /sys/kernel/mm/ksm/pages_unshared  # Pages checked but not merged
cat /sys/kernel/mm/ksm/pages_volatile  # Pages changing too fast

# KSM is a side channel: if two processes share a page via KSM,
# one can detect the other's writes by measuring CoW fault timing.
# This has been used in VM escape exploits.

Challenge

Write a Go tool that translates a virtual address to a physical frame by reading /proc/self/pagemap . Allocate a 1 MiB slice, touch one byte per page, then print the present, swapped, and shared bits plus the physical frame number for the first page. 

package main

import (
	"encoding/binary"
	"fmt"
	"os"
	"unsafe"
)

func pageEntry(addr uintptr) uint64 {
	file, err := os.Open("/proc/self/pagemap")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	defer file.Close()

	entry := make([]byte, 8)
	if _, err := file.ReadAt(entry, int64(addr/4096*8)); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	return binary.LittleEndian.Uint64(entry)
}

func main() {
	buf := make([]byte, 1<<20)
	for i := 0; i < len(buf); i += 4096 {
		buf[i] = 0x41
	}

	addr := uintptr(unsafe.Pointer(&buf[0]))
	entry := pageEntry(addr)

	present := entry&(1<<63) != 0
	swapped := entry&(1<<62) != 0
	shared := entry&(1<<61) != 0
	pfn := entry & ((1 << 55) - 1)

	fmt.Printf("addr    = %#x\n", addr)
	fmt.Printf("present = %v\n", present)
	fmt.Printf("swapped = %v\n", swapped)
	fmt.Printf("shared  = %v\n", shared)
	if present && pfn != 0 {
		fmt.Printf("frame   = %#x\n", pfn<<12)
	} else {
		fmt.Println("frame   = unavailable (PFNs need CAP_SYS_ADMIN)")
	}
}

Build it with go build -o pagemap pagemap.go . Run it as an unprivileged user, then with sudo : since Linux 4.0 the kernel zeroes the PFN field for callers without CAP_SYS_ADMIN . Finally, have the process fork a child that writes to the same buffer and re-read the shared and present bits to observe copy-on-write in action.
