GoNEAT

Overview

GitHub Repository | GitLab Mirror

GoNEAT is a Go decision engine: a library for building live simulation, training and execution environments around NEAT and HyperNEAT .

It controls arbitrary software through adapters that translate program state into a normalized NEAT world and translate neural outputs back into control signals. Because the engine only ever sees float64 values in [-1, 1] , the same training code can drive a Pong paddle, a robot or a classifier - anything that can be expressed as sensors and controls.

Most neuroevolution code is glued to a single game or benchmark. GoNEAT keeps the brain separate from the environment, so an evolved controller can be moved between worlds, gradient-trained in place, snapshotted, and resumed later. That makes it a practical substrate for agentic research and for reproducible evolutionary experiments in Go.

Features

  • A genetic core with genomes, innovation tracking, phenotype networks, mutation, crossover, speciation, population epochs and phased searching.
  • JSON snapshots that include the random number generator state, so interrupted runs resume exactly.
  • A differentiable graph over a neat.Genome with MSE and cross-entropy losses, plus SGD with momentum and RMSProp optimizers.
  • HyperNEAT with CPPN indirect encoding, grid and evolvable substrate layouts, threshold and link-expression link rules, and ES-HyperNEAT hidden-node discovery.
  • Gradient training on both the substrate weights and the CPPN that generated them.
  • A brain-agnostic Agent whose Reward and Punish callbacks can trigger immediate gradient learning.
  • A lock-step ChannelRunner with one goroutine per agent and a deterministic InlineRunner that produces identical results for the same seed.
  • Adapters for Go's native types: bool , int , uint , float32 , float64 , byte , rune , complex , time.Duration , slices, maps, strings, enums and 2D/3D positions.
  • SIMD and scalar math kernels, plus a serializable PCG32 random number generator.
  • Standard library only, with no third-party dependencies.

Architecture

The packages form a shallow, acyclic dependency graph. engine/neat never imports engine/backprop : gradient training is injected through the neat.PhaseTrainer interface, so the genetic core stays independent of the differentiable layer.

Package Responsibility
engine/vector Allocation-free scalar and SIMD[]float64kernels
engine/random Deterministic PCG32 generator with a serializable state
engine/neat Genomes, speciation, population, phases and snapshots
engine/backprop Differentiable graph, losses, optimizers and trainer
engine/hyperneat CPPN, substrate layouts, link expression and discovery
adapter Sensor/control vectorizers and the frame manifest
agent Brains, agents and training
simulation World, callbacks, runners and snapshots

Brain Adapters

Everything a brain sees or does is normalized to [-1, 1] : 

arbitrary program --adapters--> normalized frames [-1,1] --channels--> brain
       ^                                                                  |
       +---------------- controls (denormalized) <------------------------+

Each tick is a lock-step barrier. The world sends one frame per agent, every agent activates its brain and returns a control frame, the world applies all controls and steps, then the reward and punish callbacks run. Because the barrier waits for every agent, all agents observe the same world generation. InlineRunner runs the same sequence sequentially, and a test asserts both runners produce byte-identical fitness and genomes for a given seed.

Search Strategies

Phase selects the mutation strategy for a generation:

  • PhaseDefault - complexify: weight mutation plus add link or node.
  • PhasePrune - simplify: weight mutation plus remove link or node.
  • PhaseBackprop - exploit: weight mutation only, offspring are gradient-trained.
  • PhaseHybrid - complexify and gradient-train offspring.

PhaseOptions either fixes a mode or cycles a schedule (the default is {Default, Prune} ), advancing after a generation budget or early when the best fitness has stalled.

Prune-only and Backprop-only searches cannot solve the combinatorial or curved tasks because they cannot add the hidden units those tasks require. Hybrid usually converges fastest on tasks that need structure, because gradient training refines the weights of newly grown topology.

Usage: Agent Rewards

The callback runs once per agent per tick and returns a fitness delta plus an optional supervised sample. The raw World is available for conditions that are not vectorized, and the normalized frames come from step.Sensors : 

func myReward(step *simulation.StepContext, a *agent.Agent) (float64, *agent.Training) {
    index := step.AgentIndex(a.ID)
    if index < 0 {
        return 0, nil
    }

    world := step.World.(*MyWorld)

    // Measure any condition you like on the raw world.
    delta := 0.0
    if world.Scored(index) {
        delta = 1
    }

    // Translate a target into the normalized world to trigger learning.
    training := &agent.Training{
        Inputs:     step.Sensors[index],
        Targets:    []float64{world.DesiredControl(index)},
        Rate:       0.05,
        Iterations: 1,
    }

    return delta, training
}

Returning a zero delta with a nil training sample is a no-op, so sparse events such as scores or collisions need no special case.

Usage: NEAT

A minimal training loop wires a World , a neat.Population and a runner together. The reward callback is where the domain logic lives: 

options := neat.DefaultOptions(4, 2) // 4 sensors -> 2 controls
options.PopulationSize = 200

population, _ := neat.NewPopulation(options)

sim, _ := simulation.NewSimulation(world, population, simulation.Options{
    Ticks:  600,
    DT:     1.0 / 60.0,
    Runner: simulation.ChannelRunner{},
    Reward: myReward,
})
sim.SetAutoSave("run_snapshot.json", 5)
sim.RunGenerations(context.Background(), 30)

Usage: HyperNEAT

A CPPN is a NEAT genome evaluated on coordinates. It indirectly encodes a substrate, and the substrate can be gradient-trained in place or differentiated back into the CPPN itself: 

cppn, _ := hyperneat.NewCPPN(cppnGenome) // 6 inputs, one or more outputs

layout := hyperneat.NewGridSubstrateLayout(1, 4, 2, 2)

solver, _ := hyperneat.NewSolver(layout, cppn, hyperneat.DefaultOptions())

outputs := make([]float64, solver.OutputCount())
solver.Activate(inputs, outputs)

For evolvable substrates, hyperneat.DiscoverHiddenPoints runs a variance-driven quadtree and returns stable-region centres that feed an MappedEvolvableSubstrateLayout .
