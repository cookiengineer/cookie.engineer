Firewalls

Stateful packet filtering with iptables and nftables, rule evaluation, connection tracking, and default-deny policy deployment.

Overview

A firewall decides which packets may pass by evaluating stateful rules against every connection. This article covers the netfilter hook points, iptables and nftables rule structure, connection tracking, and the default-deny policy that should back every host. After reading, you can write a stateful ruleset, test it with nmap, and detect attempts to disable it.

Required Reading

  • TCP Handshake - TCP flags, SYN /ACK/FIN/RST, state transitions
  • Network Scanning - port scanning techniques, responses

Concept

A firewall is a policy enforcement point that decides whether a packet is allowed, denied, or modified based on a set of rules. Linux firewalls are built on the netfilter framework in the kernel, managed through userspace tools: iptables (legacy), nftables (modern), or firewalld (abstraction layer).

The fundamental principle of firewall engineering: default deny . Everything not explicitly permitted is dropped. This is the opposite of the "allow everything, block known bad" approach which is impossible to maintain.

Netfilter Architecture

Netfilter hooks into five points in the kernel network stack:

                   ┌──────────────────────────────┐
                   │         Local Process         │
                   │              │                │
                   │       [INPUT │ OUTPUT]        │
                   │              │                │
    ┌──────────────+──────────────+────────────────┤
    │              ▼                             ▲ │
    │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  │ │
    │  │ PRER │─▶│ ROUT │─▶│ FORW │─▶│ POST │  │ │
    │  │ OUT  │  │ ING  │  │ ARD  │  │ ROUT │  │ │
    │  └──────┘  └──────┘  └──────┘  └──────┘  │ │
    │          ▲          │           │         │ │
    └──────────+──────────+───────────+─────────┘
               │          │           │
          NIC ingress  (routing)  NIC egress
  • PREROUTING : First hook. Packet just arrived. Used for destination NAT (D NAT ).
  • INPUT : Packet destined for local process.
  • FORWARD : Packet is being routed through this machine.
  • OUTPUT : Packet from local process about to exit.
  • POSTROUTING : Last hook. Used for source NAT (S NAT ) and masquerading.

iptables Tables and Chains

iptables organizes rules into tables (functional groups) and chains (hook points):

Table Purpose Chains
filter Packet filtering (default) INPUT, OUTPUT, FORWARD
nat Network Address Translation PREROUTING, INPUT, OUTPUT, POSTROUTING
mangle Packet modification (TOS, TTL, MARK) All 5 chains
raw Connection tracking bypass PREROUTING, OUTPUT 
# List rules in filter table with packet counters
sudo iptables -L -v -n --line-numbers

# List rules in nat table
sudo iptables -t nat -L -v -n

# Show rules in parsable format (for backups)
sudo iptables-save > /etc/iptables/rules.v4
sudo ip6tables-save > /etc/iptables/rules.v6

Default-Deny Firewall Example

#!/bin/bash
# firewall.sh — Default-deny iptables firewall
# Restore: iptables-restore < /etc/iptables/rules.v4

# Flush all existing rules and chains
iptables -F        # Flush chains
iptables -X        # Delete user-defined chains
iptables -t nat -F
iptables -t nat -X
iptables -t mangle -F
iptables -t mangle -X

# Default policies: DROP everything
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT DROP

# --- Loopback (internal communication) ---
iptables -A INPUT  -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT

# --- Connection tracking ---
# Allow responses to established outbound connections
iptables -A INPUT  -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Drop invalid packets (spoofed, mangled flags, no state)
iptables -A INPUT  -m conntrack --ctstate INVALID -j DROP
iptables -A FORWARD -m conntrack --ctstate INVALID -j DROP

# --- Allowed outbound (for the server to function) ---
iptables -A OUTPUT -p tcp --dport 53 -j ACCEPT  # DNS TCP
iptables -A OUTPUT -p udp --dport 53 -j ACCEPT  # DNS UDP
iptables -A OUTPUT -p tcp --dport 80  -j ACCEPT  # HTTP (apt updates)
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT  # HTTPS
iptables -A OUTPUT -p tcp --dport 22  -j ACCEPT  # Outbound SSH (admin)
iptables -A OUTPUT -p udp --dport 123 -j ACCEPT  # NTP

# --- Allowed inbound (services this machine provides) ---
iptables -A INPUT -p tcp --dport 22  -m conntrack --ctstate NEW -j ACCEPT  # SSH
iptables -A INPUT -p tcp --dport 80  -m conntrack --ctstate NEW -j ACCEPT  # HTTP
iptables -A INPUT -p tcp --dport 443 -m conntrack --ctstate NEW -j ACCEPT  # HTTPS

# --- Rate limiting for SSH (brute force prevention) ---
iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m recent --set --name SSH
iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m recent --update --seconds 60 --hitcount 4 --name SSH -j DROP

# --- ICMP (controlled) ---
iptables -A INPUT -p icmp --icmp-type echo-request \
  -m limit --limit 1/second --limit-burst 2 -j ACCEPT
iptables -A INPUT -p icmp --icmp-type echo-reply   -j ACCEPT
iptables -A INPUT -p icmp --icmp-type destination-unreachable -j ACCEPT
iptables -A INPUT -p icmp --icmp-type time-exceeded -j ACCEPT  # traceroute

# --- Logging dropped packets (limit rate to avoid DoS) ---
iptables -A INPUT   -m limit --limit 5/min --limit-burst 10 \
  -j LOG --log-prefix "IPTABLES_INPUT_DROP: " --log-level 4
iptables -A OUTPUT  -m limit --limit 5/min --limit-burst 10 \
  -j LOG --log-prefix "IPTABLES_OUTPUT_DROP: " --log-level 4
iptables -A FORWARD -m limit --limit 5/min --limit-burst 10 \
  -j LOG --log-prefix "IPTABLES_FORWARD_DROP: " --log-level 4

# Verify
iptables -L -v -n

nftables - Modern Replacement

nftables replaces iptables/ip6tables/arptables/ebtables with a single unified framework. It is the recommended tool on ArchLinux. 

# /etc/nftables.conf — Default deny with stateful filtering

#!/usr/sbin/nft -f

flush ruleset

table inet filter {

    chain input {
        type filter hook input priority 0; policy drop;

        # Loopback
        iif lo accept

        # Established connections
        ct state established,related accept

        # Drop invalid packets early
        ct state invalid drop

        # SSH
        tcp dport 22 ct state new accept

        # HTTP/HTTPS
        tcp dport { 80, 443 } ct state new accept

        # ICMPv4
        ip protocol icmp icmp type { echo-reply, destination-unreachable, time-exceeded } accept
        ip protocol icmp icmp type echo-request limit rate 5/second accept
        # ICMPv6 (required for IPv6 to function)
        ip6 nexthdr icmpv6 icmpv6 type { nd-router-advert, nd-router-solicit, nd-neighbor-advert, nd-neighbor-solicit } accept
        ip6 nexthdr icmpv6 icmpv6 type { echo-request, echo-reply, destination-unreachable, time-exceeded } limit rate 5/second accept

        # Log and drop the rest
        log prefix "NF_INPUT_DROP: " limit rate 5/minute
        counter drop
    }

    chain output {
        type filter hook output priority 0; policy drop;

        # Loopback
        oif lo accept

        # Established connections (responses)
        ct state established,related accept

        # DNS
        udp dport 53 accept
        tcp dport 53 accept

        # HTTP/HTTPS (updates, API calls)
        tcp dport { 80, 443 } accept

        # SSH (admin outbound)
        tcp dport 22 accept

        # NTP
        udp dport 123 accept

        # ICMP
        ip protocol icmp accept
        ip6 nexthdr icmpv6 accept

        log prefix "NF_OUTPUT_DROP: " limit rate 5/minute
        counter drop
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
        # This host is not a router
        log prefix "NF_FORWARD_DROP: " limit rate 5/minute
        counter drop
    }
}
						
# Load rules
sudo nft -f /etc/nftables.conf

# Enable the nftables service
sudo systemctl enable --now nftables

# List current rules with counters
sudo nft list ruleset -a

# Monitor new connections in real-time
sudo nft monitor new

Connection Tracking (conntrack)

conntrack maintains a table of all active connections. This is how stateful firewalls distinguish between NEW, ESTABLISHED, RELATED, and INVALID packets. 

# View connection tracking table
sudo conntrack -L

# Count active connections
sudo conntrack -C

# Watch new connections in real-time
sudo conntrack -E

# List connections by source IP (investigation)
sudo conntrack -L -s 10.0.0.5

# Connection tracking limits
# /etc/sysctl.d/99-conntrack.conf
net.netfilter.nf_conntrack_max = 262144
net.netfilter.nf_conntrack_tcp_timeout_established = 86400
net.netfilter.nf_conntrack_tcp_timeout_syn_sent = 60
net.netfilter.nf_conntrack_tcp_timeout_syn_recv = 60
net.netfilter.nf_conntrack_tcp_timeout_fin_wait = 120
net.netfilter.nf_conntrack_tcp_timeout_close_wait = 60

firewalld

firewalld is a frontend to nftables (or iptables on older systems) that uses zones and services . It is the default on RHEL/Fedora but available on ArchLinux. 

sudo pacman -S firewalld
sudo systemctl enable --now firewalld

# Default zone (public: reject everything not allowed)
sudo firewall-cmd --get-default-zone

# Add services to the public zone
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https

# Open a custom port
sudo firewall-cmd --permanent --add-port=8443/tcp

# Custom zone for internal services
sudo firewall-cmd --permanent --new-zone=internal
sudo firewall-cmd --permanent --zone=internal --add-source=10.0.0.0/8
sudo firewall-cmd --permanent --zone=internal --add-service=postgresql

# Check active configuration
sudo firewall-cmd --list-all
sudo firewall-cmd --list-all-zones

# Reload to apply permanent changes
sudo firewall-cmd --reload

Common Rule Patterns

Accept established, drop invalid

ct state established,related accept
ct state invalid drop

Rate limiting for brute force

tcp dport 22 ct state new limit rate 4/minute accept
tcp dport 22 ct state new drop

Geo-blocking with geoip

# nftables with nft-geoip
ip saddr @geoip_blocked drop

Port knocking (conceal SSH)

# Require connection attempts to ports 7000, 8000, 9000 in sequence
# to temporarily open port 22 for the knocker's IP

Blackhole (drop without response)

# DROP sends no RST — connection times out (slows scanners)
ip saddr 10.0.50.42 counter drop

Reject with ICMP

# REJECT sends ICMP unreachable — allows fast failure
ip saddr 10.0.0.0/8 tcp dport 22 ct state new counter reject

Rule Order and Performance

Rules are evaluated top-to-bottom, first-match-wins. Place frequently matched rules early:

chain input {
    # 1. Most common case: established traffic (80%+ of packets)
    ct state established,related accept

    # 2. Fast reject: invalid packets
    ct state invalid drop

    # 3. Frequent services
    tcp dport { 80, 443 } ct state new accept

    # 4. Less frequent services
    tcp dport 22 ct state new accept

    # 5. Rarely matched
    ip saddr 192.168.0.0/24 tcp dport 8080 ct state new accept

    # 6. Catch-all
    log prefix "DROP: " counter drop
}

Use named sets for IP lists rather than individual rules: 

# Define a set once, reference anywhere
table inet filter {
    set allowed-admin-ips {
        type ipv4_addr
        flags interval
        elements = { 10.0.0.0/24, 192.168.1.0/24 }
    }

    chain input {
        ip saddr @allowed-admin-ips tcp dport 22 accept
    }
}

Testing Firewall Rules

# TCP connectivity to specific port
nc -zv -w 2 192.168.1.100 22
# Connection succeeded / Connection refused / Timeout

# nmap scan to see what's visible
nmap -sS -p- 192.168.1.100

# Compare nmap results with firewall rules
# If nmap shows "filtered", nftables DROP is working
# If nmap shows "closed", nftables REJECT is working
# If nmap shows "open", something allowed it

# Test UDP rules
nmap -sU -p 53,123,161 192.168.1.100

# Check if logging is working
sudo journalctl -k -f | grep NF_INPUT_DROP

# Generate test traffic
curl http://192.168.1.100/
# Expected: timeout (dropped) or connection refused (rejected)

Detection Rules

# auditd rule for nftables/iptables changes
-w /etc/nftables.conf -p wa -k firewall_config_change
-w /etc/iptables/ -p wa -k firewall_config_change

# Monitor for firewall flush (attacker disabling firewall)
-a exit,always -F arch=b64 -S setsockopt -k firewall_flush
						
# Sigma rule — Firewall rules flushed on Linux
title: Linux Firewall Rules Flushed
status: experimental
logsource:
  product: linux
  category: process_creation
detection:
  selection_iptables:
    Image|endswith: '/iptables'

  condition: selection_iptables or selection_iptables2 or selection_nft
falsepositives:
  - Legitimate firewall maintenance windows
level: high

Challenge

A container running a vulnerable web service behind a misconfigured firewall. Your task is to turn the default "allow all" policy into a default-deny posture without breaking the service.

firewalls.Containerfile

podman build -t firewalls -f firewalls.Containerfile .
podman run -it --rm -p 8080:8080 firewalls

The container starts with nftables in "allow all" mode and a command-injection service listening on port 8080. Inside the container:

  1. Switch the input policy to default deny.
  2. Allow only the ports the service needs.
  3. Protect the service with rate limiting.
  4. Verify with nmap and nc that external access is blocked but localhost access works.
