GoAccess

Overview

GitHub Repository | GitLab Mirror

The GoAccess project is an experimental IoT exploitation framework written entirely in Go with CGO_ENABLED=0 and zero runtime dependencies.

It combines device fingerprinting, vulnerability scanning, credential testing, exploit modules, protocol clients, and multi-architecture payload generation into a single command-line tool and reusable Go library.

The project is intended for authorized security research against IoT devices, embedded systems, network appliances, web applications, and other systems where identifying exposed services and reproducing known vulnerabilities is part of a legitimate security assessment.

Rather than implementing a single exploitation technique, GoAccess provides a common framework for collecting device information, selecting applicable modules, testing vulnerabilities, and, where explicitly authorized, validating whether a discovered weakness can be used to obtain access.

The framework currently contains exploit modules covering dozens of vendors and device families, together with credential modules, protocol implementations, configuration parsers, hardcoded SSH key databases, and architecture-specific payloads.

Architecture

The framework is organized around a small set of reusable interfaces and registries. The exploit package provides the global module registry, while the scanner package coordinates identification, vulnerability checks, and access operations using a concurrent worker pool.

Protocol-specific functionality is separated into reusable pure-Go clients for HTTP / HTTPS , TCP , UDP , SSH , Telnet, FTP , and SNMP . This keeps exploit modules focused on their target-specific logic rather than requiring every module to implement its own network protocol handling.

The project is deliberately built without CGo dependencies. This allows the framework and its supporting binaries to be compiled as portable static executables and makes cross-compilation for embedded architectures considerably simpler.

The current repository contains exploit coverage for routers, cameras, drones, servers, and miscellaneous devices and applications. The documented module inventory includes 174 exploit modules across 55 vendors and 184 credential modules.

Features

The framework is designed to cover the workflow from initial device identification through vulnerability validation and authorized access testing:

Name Type Mechanism
Identification Device Fingerprinting Port scan, OUI, banners, UPnP, SNMP
Exploitation Vulnerability Testing Registered exploit modules
Credentials Authentication Testing Vendor-specific credential modules
Passwords Credential Generation MAC/serial-derived generators
HTTP/HTTPS Web Protocol Pure Go HTTP client
TCP/UDP Network Protocol Pure Go socket clients
SSH Remote Access Pure Go SSH client
Telnet Remote Access Native Telnet client
FTP File Transfer Pure Go FTP client
SNMP Device Management Pure Go SNMP client
OUI Hardware Identification MAC vendor database
SSH Keys Credential Research Known embedded keys
Parsers Credential Extraction Device configuration parsers
Payloads Architecture Support Static multi-arch binaries
Reporting Results Terminal, JSON output

The framework supports seven primary payload architectures: ARM , ARM64 , MIPS , MIPSLE , MIPS64 , x86 , and x86_64 . Payloads can be cross-compiled as static binaries, which is particularly useful when researching embedded devices with different CPU architectures.

All commands can produce JSON output, making the scanner suitable not only for interactive terminal use but also for automated security testing, result collection, and integration into larger research workflows.

Analysis Profiles

GoAccess organizes vulnerability research around reusable exploit, credential, and protocol modules rather than a single monolithic scanner.

Each exploit module exposes metadata describing its vendor, device type, protocol, options, fingerprints, vulnerability checks, and execution logic. Modules register themselves with the global exploit registry and can then be selected by vendor, model, or other scanner criteria.

This architecture makes it possible to extend the framework without modifying the central scanning engine. A new research module can implement the shared exploit interface, register itself, and immediately become available to the CLI and library interfaces.

The same modular approach is used for credential testing and password generation. Vendor-specific dictionaries, generated credentials, configuration parsers, and known embedded keys can therefore be maintained independently from the network protocol implementations.

Because the scanner exposes a Go API , the framework can also be embedded into other security-research tooling. Identification and scanning results can be consumed programmatically, while JSON output provides a convenient boundary for external automation.

Building

GoAccess requires Go 1.22 or newer. The repository can be cloned and built without external runtime dependencies: 

# Clone repository
git clone https://github.com/cookiengineer/goaccess.git;

# Build goaccess and its implant payloads
cd /path/to/goaccess;
make build;

Usage

The resulting binary is written to ./bin/goaccess . The project exposes three operational modes: identify , scan , and access .

For an authorized laboratory target, device identification can be performed before running vulnerability checks: 

# Identify and fingerprint target machine
cd /path/to/goaccess;
./bin/goaccess identify 192.168.1.1;

The identification phase combines port scanning, MAC OUI lookup, HTTP banner collection, UPnP SSDP probing, and SNMP system-description queries to build an initial fingerprint of the target device.

Vulnerability scanning can then be performed with optional concurrency and target-specific filtering: 

# Scan for vulnerabilities
cd /path/to/goaccess;
./bin/goaccess scan 192.168.1.1 --threads 32;

Results can also be exported as JSON for later analysis: 

# Scan for vulnerabilities and export to results.json
./bin/goaccess scan 192.168.1.1 --json --output results.json;

The framework also exposes commands for inspecting the registered research modules: 

# List available modules
./bin/goaccess list exploits;
./bin/goaccess list credentials;
./bin/goaccess list payloads;
./bin/goaccess list keys;
./bin/goaccess list vendors;

Testing

For development and integration testing, the repository provides Go tests, Podman-based integration tests, static analysis, and combined build/test/lint targets: 

CGO_ENABLED=0 go test ./...;
CGO_ENABLED=0 go test -v -run Integration ./scanner/;
go vet ./...;

make payloads;
make build;
make test;
make lint;

Agentic Usage

GoAccess is also designed to be consumed as a Go library. The scanner exposes identification and vulnerability-scanning functionality through reusable Go API s, allowing the framework to become part of larger security-research, inventory, or automated validation systems.

The project is actively developed and should be used only against systems for which the operator has explicit authorization. The repository contains the current implementation, module inventory, build instructions, and development documentation.
