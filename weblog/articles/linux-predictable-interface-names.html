Linux Predictable Interface Names

This is my guide on how to deal with unpredictable network interface names that were being generated based on which USB hub during the bootup process reacted the quickest.

Unpredictability of Predictable Interface Names

The problem I have with the format of names like wlp196s0f3u2u2 is that they are in fact, unpredictable. If you reboot your system a bunch of times, it really depends on which device reacted the quickest. If you connect another USB device to the same USB hub which draws more power, like say, a spinning hard drive, then good luck having to fix all your shell scripts and config files all over again.

I have no idea who came up with the idea of these device names, because they're definitely not user friendly. A quick search tells me they've been introduced with systemd v197 but I have no idea how reliable that wiki entry is.

Anyways, if you're pissed off by these types of device names and if your network setup relies on non- GUI ways to connect and route traffic to the internet or WAN , here's a quick writeup on how to fix it.

How to Rename Network Interfaces by USB ID

Most systems rely on udev to match rights, names and other attributes of connected devices. In this case we first need to find our device's name and address to be able to write a udev rule for it.

If it's connected via USB , it can be shown via lsusb , that's the easiest way. For example, it may look like this: 

lsusb;

(...)
Bus 002 Device 005: ID 0bda:1337 Realtek Semiconductor Corp. RTLxxxxbu [ACxxxx Whatever]
(...)

With the Bus identifier and the Device identifier, we can now show more details of the connected device using the lsusb -v -D /path/to/device command. 

# Bus 002 Device 005
sudo lsusb -v -D /dev/bus/usb/002/005;

Device: ID 0bda:1337 Realtek Semiconductor Corp. RTLxxxxbu [ACxxxx Whatever]
Negotiated speed: SuperSpeed (5Gbps)
Device Descriptor:
(...)

Now that we've verified that the USB identifier is correct, we can write a udev rule to match that device and save it at /etc/udev/rules.d/70-wlan0-external.rules . 

# /etc/udev/rules.d/70-wlan0-external.rules
SUBSYSTEM=="net", ACTION=="add", ATTRS{idVendor}=="0bda", ATTRS{idProduct}=="1337", NAME="wlan0"

Now we need to reload the udev configuration and trigger the add action.

The device should be renamed afterwards and be available as wlan0 and shown in ip link . If that's not the case, that means that systemd is renaming the device after it's been connected. Then you need to continue with the systemd dedicated section in this article. 

sudo udevadm control --reload;
sudo udevadm trigger -c add /sys/class/net/wlp196s0f3u2u2;

How to Rename Network Interfaces by MAC Address

If your device already is connected and working, you can also rename the device using its MAC address. That's a little useless for pentesting purposes so I pretty much try to avoid writing rules based on MAC addresses, but I'm gonna include it here for the sake of completion.

If the device is connected, it should be visible via ip link . 

ip link;

(...)
4: wlp196s0f3u2u2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP mode DORMANT group default qlen 1000
    link/ether 74:19:f8:13:33:37 brd ff:ff:ff:ff:ff:ff
    altname wlx7419f8133337

Now that we've found the MAC address, we can write a udev rule to match that device and save it at /etc/udev/rules.d/70-wlan0-external.rules . 

# /etc/udev/rules.d/70-wlan0-external.rules 
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="74:19:f8:13:33:37", NAME="wlan0"

Now we need to reload the udev configuration and trigger the add action.

The device should be renamed afterwards and be available as wlan0 and shown in ip link . If that's not the case, that means that systemd is renaming the device after it's been connected. Then you need to continue with the systemd dedicated section in this article. 

sudo udevadm control --reload;
sudo udevadm trigger -c add /sys/class/net/wlp196s0f3u2u2;

How to Change SystemD's Network Interface Names

Okay, so you've been systemd'ed and don't know why systemd network interface names keep being used instead of the udev configuration files that have been applied before to your network interfaces. Worry no more, I got you covered.

How to Rename SystemD Network Interfaces by USB Identifier

SystemD's configuration files for network interfaces are stored in the /usr/lib/systemd/network/ folder. We need to create a new configuration file at /usr/lib/systemd/network/10-wlan0.link so that it's parsed early in the bootup process. 

# /usr/lib/systemd/network/10-wlan0.link
[Match]
USBVendor=0x0bda
USBProduct=0x1337

[Link]
Name=wlan0

If we now reload the udev configuration and the systemd-udevd service, the device should be renamed, by both udev and SystemD, into the correct network interface name. 

sudo udevadm control --reload;
sudo systemctl restart systemd-udevd;

How to Rename SystemD Network Interfaces by MAC Address

SystemD's configuration files for network interfaces are stored in the /usr/lib/systemd/network/ folder. We need to create a new configuration file at /usr/lib/systemd/network/10-wlan0.link so that it's parsed early in the bootup process. 

# /usr/lib/systemd/network/10-wlan0.link
[Match]
MACAddress=74:19:f8:13:33:37

[Link]
Name=wlan0

If we now reload the udev configuration and the systemd-udevd service, the device should be renamed, by both udev and SystemD, into the correct network interface name. 

sudo udevadm control --reload;
sudo systemctl restart systemd-udevd;
