Words with Learners

A Self-Hosted Word Game for Language Learners

Overview

Game Repository | Game Mirror | Android App | Android Mirror

Words with Learners is a self-hosted, turn-based word game for language learners. It uses a Words With Friends style 15x15 board, a server-authoritative tile bag, and configurable rack sizes. The interface is in English, while hints and gameplay are centred on a selected foreign language and CEFR level.

The game runs as one Go binary with an embedded frontend and dictionaries. There is no database, no external asset pipeline, and no account service to sign up for. Profiles and games are JSON files in a directory you choose, which makes the whole thing easy to back up, move, or run on a small home server.

For phone-sized games there is an Android wrapper. It runs the same Go server inside the app, displays it in a WebView, and shares the invite so other players can join from their own mobile devices from within the same Wi-Fi network.

Features

  • Seven languages: Dutch, English, German, Spanish, French, Italian, and Russian.
  • CEFR levels A1, A2, B1, B2, C1, and C2.
  • One to four players per game. Single-player games work as local training.
  • Configurable maximum word length and rack size from 5 to 15.
  • Server-side move validation, scoring, hints, bag and rack management, and replay checks.
  • Automatic rack reshuffling when the current player has no playable word and the bag has tiles.
  • Pass, blanks, bingo bonuses, and end-game scoring.
  • Searchable player directory reused by the invite dialog.
  • Pannable, zoomable, grid-aligned board up to 2x.
  • Gameboard country flags and flag-inspired bonus-square themes.
  • JSON profiles and games stored in a configurable data directory.

Architecture

Each language has an alphabet.json with tile values and counts, one word file per CEFR level, and two curated supplement files:

dictionaries/nl/alphabet.json
dictionaries/nl/a1.json
dictionaries/nl/a2.json
...
dictionaries/nl/cities.json
dictionaries/nl/sights.json

Word files use a simple JSON schema:

{
  "schemaVersion": 1,
  "language": "nl",
  "level": "A1",
  "words": [
    { "word": "HUIS", "hint": "house" }
  ]
}

City and sight supplements use the same word format with a kind field. The bundled dictionaries are generated from the Lingvoberry A0 to C2 word lists, with A0 merged into A1. Hints come from the English definitions for each word's language section in English Wiktionary. The importer reads a ZIM file through the external zimdump and zimsearch commands, so the server does not need the ZIM at runtime.

Existing hints can be cleaned without re-running the importer:

cd /path/to/words-with-learners-game;
go run ./cmd/dictclean -dry-run;
go run ./cmd/dictclean;

The cleanup trims cut-off definitions, removes Wiktionary maintenance notes and clarification markers, and reports entries that still need a hand-written hint.

Building

The game needs Go 1.26 or newer and has no frontend build step.

cd /path/to/words-with-learners-game;
make build;      # bin/words-with-learners
make run;        # go run ./cmd/server

The Android app expects the game repository as a sibling directory and builds inside a Podman container with the Android SDK, NDK, Go, and Gradle.

words-with-learners-game/       # The game repository
words-with-learners-android/    # The Android repository
						
cd /path/to/words-with-learners-android;
make image;      # build the Podman builder image
make apk;        # app/build/outputs/apk/debug/app-debug.apk
make install;    # install the APK over ADB

Set GAME_DIR=/path/to/words-with-learners-game when the repositories do not sit next to each other in the same folder structure.

Testing

The game test suite covers board layout, scoring, move validation, replay determinism, idempotent moves, and a full WebSocket game flow with hidden racks and stale-move rejection.

cd /path/to/words-with-learners-game;
make test;       # go test ./...
make vet;        # go vet ./...
make check;      # fmt, vet, and test

The Android build runs its own unit tests and the game tests inside the container.

cd /path/to/words-with-learners-android;
make test;       # gradle testDebugUnitTest and go test ./...
make lint;       # gradle lintDebug
make check;      # test and lint

Usage: Run the Game

Start the server and open http://localhost:8080:

cd /path/to/words-with-learners-game;
go run ./cmd/server;

Useful flags:

-addr :8080                            HTTP listen address
-data ~/.config/words-with-learners    profile and game data directory
-dev                                   serve frontend and dictionaries from disk
-public public                         frontend directory used with -dev
-dictionaries dictionaries             dictionary directory used with -dev
-verify-games                          replay every stored game on startup

For frontend development, run with -dev so the server reads public/ and dictionaries/ from disk instead of the embedded copies.

Usage: Play a Gameboard

Enter a username and password. A new username creates an account automatically; an existing username needs the matching password. Then create a game, choose the language, CEFR level, rack size, and maximum word length, and invite another player or start a solo training game.

Drag tiles from the rack onto the board. The first word must cover the centre square, and every formed word must exist in the selected language at any CEFR level.

  • The ? button shows an English hint for a playable word.
  • The Recall button returns tentative tiles to the rack.
  • The Submit button sends the move to the server.
  • The Pass button skips the turn.

There is no manual tile exchange. If a rack has no legal word when the turn starts, the server reshuffles it with bag tiles and notifies the player. The game ends when a rack is emptied with an empty bag, or after three scoreless turns.

Usage: Android Gameplay

Install the APK and start the embedded server from the app.

The foreground notification shows the LAN URL, and the WebView wrapper opens the local game. Use the game's Invite button to show the LAN URL again and a scannable QR code that other players on the same Wi-Fi or LAN can open.

The notification also offers a stop action that shuts the server down and removes the foreground web service.
