Firmware Reversing

Extracting and analyzing embedded device firmware from image extraction to cross-architecture binary analysis and vulnerability discovery.

Overview

Firmware reversing extracts and analyzes the software inside embedded devices such as IoT gear, routers, and cameras. A firmware image bundles a bootloader, kernel, and root filesystem, and its extracted binaries expose the device's attack surface. After reading, you can identify and extract a firmware image, explore its root filesystem, find hardcoded credentials and backdoors, and audit cross-architecture binaries in Ghidra.

What Firmware Is

Firmware is a monolithic blob containing everything an embedded device needs to boot and operate. Unlike a desktop OS where the bootloader, kernel, and root filesystem reside on separate partitions, firmware often combines all these into a single image. The typical layout:

┌──────────────────────────────────────────┐
│                  FIRMWARE IMAGE           │
├──────────+──────────+────────────────────┤
│Bootloader│  Kernel  │   Root Filesystem   │
│ (U-Boot) │ (Linux)  │  (SquashFS/JFFS2)  │
├──────────+──────────+────────────────────┤
│ Configuration partition, persistent data │
└──────────────────────────────────────────┘

The bootloader initializes hardware, loads the kernel. The kernel mounts the root filesystem (often read-only compressed - SquashFS) and executes /sbin/init . The entire device stack runs from this filesystem: BusyBox, web server, UPnP daemon, configuration scripts.

Acquiring Firmware

Before analysis begins, you need the firmware image:

$ curl -L "https://example.com/support/device-v2.3.4.bin" -o firmware.bin

# Or extract from OTA update capture
$ tcpdump -i eth0 -w ota_capture.pcap
# Later: filter HTTP/FTP/HTTP2 traffic, extract firmware binary
$ tshark -r ota_capture.pcap -Y "http.response" -T fields \

Firmware Identification

Before extraction, identify what you have:

$ file firmware.bin
firmware.bin: u-boot legacy uImage, Linux-3.18.84, Linux/ARM, OS Kernel Image

$ binwalk firmware.bin

DECIMAL     HEXADECIMAL     DESCRIPTION
───────────────────────────────────────────────────────────────
0           0x0             uImage header, header size: 64 bytes
64          0x40            LZMA compressed data
1048576     0x100000        Squashfs filesystem, little endian,
                            version 4.0, compression: xz,
                            size: 8572313 bytes, 1847 inodes
1048580     0x100004        Squashfs filesystem signature found

The file command identifies the top-level format. binwalk recursively scans for embedded file signatures - magic bytes at known offsets - revealing the firmware's internal structure.

binwalk Deep Dive

binwalk is the standard firmware analysis tool. It matches known magic byte sequences at any offset in the binary:

# Analyze (no extraction)
$ binwalk firmware.bin

# Extract all recognizable components (-e: extract, -M: recursively)
$ binwalk -Me firmware.bin

# Results go to _firmware.bin.extracted/
$ ls _firmware.bin.extracted/
100000.squashfs    squashfs-root/

When binwalk Misses

Sometimes binwalk fails because the firmware uses custom headers or non-standard alignment. Manual carving:

# Search for SquashFS magic bytes manually
$ xxd firmware.bin | grep "6873 7173"   # "hsqs"
# Found at offset 0x100000

# Extract manually
$ dd if=firmware.bin of=rootfs.squashfs bs=1 skip=1048576
$ unsquashfs rootfs.squashfs

Filesystem Extraction Reference

Each filesystem has a specific extraction tool:

# SquashFS (most common in embedded Linux)
$ unsquashfs rootfs.squashfs          # Creates squashfs-root/
$ unsquashfs -l rootfs.squashfs       # List contents without extracting

# JFFS2 (journaling flash filesystem - older routers)
$ pip install jefferson
$ jefferson jffs2_dump.bin -d jffs2-root/

# YAFFS (common in Android devices, cameras)
$ pip install yaffshiv
$ yaffshiv -f yaffs_dump.bin -d yaffs-root/

# CPIO archive
$ cpio -idmv < cpio_archive.bin
$ # Or if gzip-compressed: zcat archive.cpio.gz | cpio -idmv

# CramFS (older Linux, some routers)
$ sudo mount -t cramfs -o loop rootfs.cramfs /mnt/cramfs/
$ cp -a /mnt/cramfs/ cramfs-root/
$ sudo umount /mnt/cramfs/

# UBIFS (UBI volumes - newer routers, NAND flash)
$ # First extract UBI volume
$ modprobe nandsim first_id_byte=0xec second_id_byte=0xa1
$ ubiformat /dev/mtd0 -f ubi_image.bin
$ ubiattach -p /dev/mtd0
$ mount -t ubifs /dev/ubi0_0 /mnt/ubifs/
$ cp -a /mnt/ubifs/ ubifs-root/

Post-Extraction Analysis

Once the root filesystem is extracted, the real analysis begins. The directory structure follows the FHS (Filesystem Hierarchy Standard):

$ ls -la squashfs-root/
bin/       # -> BusyBox symlinks (usually)
sbin/      # System binaries (init, networking daemons)
lib/       # Shared libraries (libc, libssl, libpthread)
usr/       # User-space programs, web server files
etc/       # Configuration files, init scripts, passwords
www/       # Web server root (router admin panels)
tmp/       # Temporary files
var/       # Runtime data, logs

Step 2: Analyze BusyBox

BusyBox is a single binary that implements dozens of Unix utilities ( ls , cp , sh , wget , httpd ). In firmware, /bin/ls is often a symlink to /bin/busybox . The set of compiled-in applets reveals device capabilities:

$ strings squashfs-root/bin/busybox | grep "Currently defined"
[, [[, ash, awk, base64, cat, chmod, cp, crond, dd, df, dhcprelay,
dmesg, dnsdomainname, echo, egrep, fgrep, getty, grep, gunzip,
gzip, hostname, httpd, ifconfig, init, insmod, iptables, kill,
killall, ln, login, ls, lsmod, md5sum, mdev, mkdir, mknod, mktemp,
mount, nc, netstat, nslookup, passwd, ping, ping6, ps, pwd, rm,
rmmod, route, sed, sh, sha256sum, sleep, syslogd, telnet, telnetd,
tftp, top, traceroute, udhcpc, umount, uptime, vi, wget, zcat

Note httpd , telnetd , tftp - these indicate network services. iptables , route - firewall/routing capabilities.

Step 3: Find Startup Scripts

Embedded Linux uses one of these init systems:

# BusyBox init (most common): /etc/inittab -> /etc/init.d/rcS
$ cat squashfs-root/etc/inittab
::sysinit:/etc/init.d/rcS
::respawn:/sbin/getty -L ttyS0 115200 vt100

# rcS runs all scripts in /etc/init.d/
$ ls squashfs-root/etc/init.d/
rcS    network    firewall    httpd    telnetd    upnp

# Systemd (newer devices):
$ ls squashfs-root/etc/systemd/system/multi-user.target.wants/

# OpenRC:
$ ls squashfs-root/etc/runlevels/default/

Read rcS to understand the boot sequence:

$ cat squashfs-root/etc/init.d/rcS
#!/bin/sh
mount -t proc proc /proc
mount -t sysfs sysfs /sys
mount -t tmpfs tmpfs /tmp
mkdir -p /var/log /var/run

# Start services from /etc/init.d/
for script in /etc/init.d/S*; do
    [ -x "$script" ] && "$script" start
done

Step 4: Identify Running Services

Services expose the attack surface. Find them:

# Check inetd-style services
$ cat squashfs-root/etc/inetd.conf 2>/dev/null
telnet  stream  tcp  nowait  root  /usr/sbin/telnetd  telnetd
http    stream  tcp  nowait  root  /usr/sbin/httpd     httpd -i

# Check listening binaries (search for bind/listen socket creation)
$ for bin in squashfs-root/bin/* squashfs-root/sbin/* squashfs-root/usr/sbin/*; do
    [ -f "$bin" ] && strings "$bin" 2>/dev/null | grep -q "0.0.0.0" && echo "$bin"
  done

# Check for CGI scripts (web server integration)
$ ls squashfs-root/www/cgi-bin/ 2>/dev/null

Finding Hardcoded Credentials

This is the most common firmware vulnerability. Grep for password-related patterns:

# Search for password strings in entire filesystem
$ grep -rI "password\|passwd\|pass\b" squashfs-root/etc/ 2>/dev/null | \
    grep -v "^#" | grep -v "^//"

# Check /etc/passwd and /etc/shadow
$ cat squashfs-root/etc/passwd
root:$1$salt$hash:0:0:root:/root:/bin/sh
admin:$1$salt$hash:0:0:admin:/admin:/bin/sh
# No service accounts? Good sign.

$ cat squashfs-root/etc/shadow
root:$1$rounds=5000$salt$encrypted_pw:18000:0:99999:7:::

# Search in configuration files
$ grep -rI "admin\|root\|user" squashfs-root/etc/ --include="*.conf" \
    --include="*.cfg" --include="*.ini" 2>/dev/null | head -20

# Check web server configuration
$ cat squashfs-root/etc/httpd.conf 2>/dev/null
A:172.16.0.0/255.255.0.0     # Allowed client IP range
/admin:admin:password123      # <- Hardcoded web admin credentials

Common patterns in vendor firmware:

Pattern Example Where Found
printf("password=%s", p) Debug logging leaks credentials /usr/sbin/httpd
strcmp(pass, "admin") Hardcoded comparison Init scripts, binaries
/etc/default_passwd File with plaintext password $ cat squashfs-root/etc/default_passwd
Telnet backdoor Hidden debug service /etc/init.d/S99debug
Default password in binary strings shows "admin:admin" Web server binary

Automated Credential Scan

#!/bin/bash
# scan_creds.sh - Find hardcoded credentials in extracted firmware
DIR="$1"

echo "=== Hardcoded credentials scan ==="

# Passwords in config files
echo "--- Config files ---"
grep -rI -E "(password|passwd|secret|key)\s*[:=]\s*\S+" \
    "$DIR/etc" "$DIR/www" 2>/dev/null | \
    grep -v "^#" | grep -v "^//" | grep -v "^$"

# Passwords in shadow
echo "--- Shadow file ---"
cat "$DIR/etc/shadow" 2>/dev/null

# Default credentials in binaries
echo "--- Binaries (strings search) ---"
for bin in "$DIR/bin/"* "$DIR/sbin/"* "$DIR/usr/sbin/"*; do
    if [ -f "$bin" ] && [ -x "$bin" ]; then
        matches=$(strings "$bin" 2>/dev/null | \
            grep -iE "admin|root|password|backdoor|debug" | \
            grep -v "^$\|^\.\|\%s\|copyright")
        if [ -n "$matches" ]; then
            echo "  $(basename "$bin"):"
            echo "$matches" | while read line; do
                echo "    $line"
            done
        fi
    fi
done

Cross-Architecture Binary Analysis

Firmware binaries are rarely x86 - they're ARM, M IPS , or PowerPC. Ghidra handles all of these natively:

Import into Ghidra

  1. File -> Import File -> select the binary ( squashfs-root/usr/sbin/httpd )
  2. Language: auto-detected (ARM32:v7, M IPS 32:default, etc.)
  3. Options: enable "Load External Libraries" if the firmware's /lib is accessible

Find the Authentication Function

/* Ghidra Java script: find authentication-related functions */
// Run in Ghidra Script Manager (Java)

import ghidra.app.script.GhidraScript;
import ghidra.program.model.listing.*;
import ghidra.program.model.symbol.*;

public class FindAuthFunctions extends GhidraScript {
    @Override
    public void run() throws Exception {
        Listing listing = currentProgram.getListing();
        FunctionIterator funcs = listing.getFunctions(true);

        String[] auth_keywords = {
            "login", "auth", "password", "verify", "check",
            "authenticate", "validate", "admin", "credential"
        };

        for (Function func : funcs) {
            String name = func.getName().toLowerCase();

            for (String keyword : auth_keywords) {
                if (name.contains(keyword)) {
                    printf("Potential auth function: %s @ 0x%x\n",
                           func.getName(), func.getEntryPoint().getOffset());

                    // Look for string comparisons in this function
                    InstructionIterator iter =
                        listing.getInstructions(func.getBody(), true);
                    while (iter.hasNext()) {
                        Instruction inst = iter.next();
                        // Check for calls to strcmp, strncmp, memcmp
                        if (inst.getMnemonicString().equals("BL") ||
                            inst.getMnemonicString().equals("CALL")) {
                            Reference[] refs = inst.getReferencesFrom();
                            for (Reference ref : refs) {
                                String target = ref.getToAddress().toString();
                                if (target.contains("strcmp") ||
                                    target.contains("strncmp")) {
                                    printf("  -> String comparison at 0x%x\n",
                                           inst.getAddress().getOffset());
                                }
                            }
                        }
                    }
                    break;
                }
            }
        }
    }
}

Tracing Password Validation

  1. Find the login page handler (search for string "login" in strings)
  2. Cross-reference to the function that uses it
  3. Follow the function's control flow to the strcmp or hash comparison
  4. Back-trace to find how the expected password is computed or stored

Example: a common ARM router pattern:

; ARM disassembly (Ghidra) - typical password check
ldr    r0, [input_buffer]    ; User-supplied password
ldr    r1, =0x00012345       ; Pointer to hardcoded password
bl     strcmp
cmp    r0, #0x0
beq    auth_success

; At 0x12345: "admin123"     <- Hardcoded password string

Emulating Firmware Binaries

Use QEMU user-mode to test individual binaries from the firmware:

# Prerequisite: the binary must match host architecture, or use qemu-arch
$ qemu-arm -L squashfs-root/ squashfs-root/usr/sbin/httpd
# -L points to the firmware root so the dynamic linker and libs are found

# For statically linked binaries (no -L needed):
$ qemu-arm squashfs-root/bin/busybox ls

# Test a web server in isolation:
$ sudo cp squashfs-root/usr/sbin/httpd /tmp/test_httpd
$ cp -r squashfs-root/www /tmp/
$ qemu-arm -L squashfs-root/ -E LD_LIBRARY_PATH=/lib:/usr/lib \
    /tmp/test_httpd -p 8080 -h /tmp/www

Full System Emulation with QEMU

For complete firmware behavior (network services, init scripts), emulate the entire device:

# Step 1: Identify the kernel
$ binwalk firmware.bin | grep "uImage"
0    0x0    uImage header, ... Linux-3.18.84, Linux/ARM

# Step 2: Extract the kernel payload (strip the 64-byte uImage header)
$ dd if=firmware.bin of=kernel.bin bs=64 skip=1
$ file kernel.bin
kernel.bin: Linux kernel ARM boot executable zImage (little-endian)

# Step 3: Determine the machine type from the bootloader environment or
# the device tree; a generic "-M virt" will not run a vendor kernel.
$ strings kernel.bin | grep -i "machine\|compatible"

# Step 4: Boot the raw kernel with QEMU system emulation. The machine type
# and load address must match the vendor kernel.
$ qemu-system-arm \
    -M virt \
    -cpu cortex-a15 \
    -m 256M \
    -kernel kernel.bin \
    -drive file=rootfs.squashfs,if=none,format=raw,id=drive0 \
    -device virtio-blk-device,drive=drive0 \
    -netdev user,id=net0 \
    -device virtio-net-device,netdev=net0 \
    -append "console=ttyAMA0 root=/dev/vda rw" \
    -nographic

This is complex - the machine type, device tree, and load address must all match the kernel's expectations, which is why a vendor kernel rarely boots on -M virt . A simpler approach uses firmadyne or FirmAE for automated firmware emulation.

Firmware Extraction Pipeline

#!/bin/bash
# firmware_pipeline.sh - Automated firmware extraction and analysis
FIRMWARE="$1"
OUTDIR="analysis_$(basename "$FIRMWARE" | sed 's/\.[^.]*$//')"

mkdir -p "$OUTDIR"
echo "[+] Analyzing $FIRMWARE -> $OUTDIR/"

# Phase 1: Extract with binwalk
echo "[1/5] binwalk extraction..."
binwalk -Me "$FIRMWARE" --directory "$OUTDIR" 2>&1 | tee "$OUTDIR/binwalk.log"

# Phase 2: Find the root filesystem
ROOTFS=$(find "$OUTDIR" -name "squashfs-root" -type d 2>/dev/null | head -1)
if [ -z "$ROOTFS" ]; then
    ROOTFS=$(find "$OUTDIR" -maxdepth 3 -type d -name "bin" 2>/dev/null | \
        head -1 | xargs dirname)
fi

if [ -z "$ROOTFS" ] || [ ! -d "$ROOTFS/bin" ]; then
    echo "[-] Could not find root filesystem in extracted data"
    # Try manual carving
    echo "[*] Attempting manual SquashFS carving..."
    for offset in $(grep -boa "hsqs" "$FIRMWARE" | cut -d: -f1); do
        echo "  Found SquashFS at offset $offset"
        dd if="$FIRMWARE" of="$OUTDIR/rootfs_$offset.squashfs" \
            bs=1 skip=$offset 2>/dev/null
        unsquashfs -d "$OUTDIR/squashfs-root_$offset" \
            "$OUTDIR/rootfs_$offset.squashfs" 2>/dev/null && \
            ROOTFS="$OUTDIR/squashfs-root_$offset" && break
    done
fi

echo "[2/5] Root filesystem: $ROOTFS"

# Phase 3: Architecture detection
echo "[3/5] Architecture analysis..."
BUSYBOX=$(find "$ROOTFS" -name "busybox" -type f 2>/dev/null | head -1)
if [ -f "$BUSYBOX" ]; then
    file "$BUSYBOX" | tee "$OUTDIR/architecture.txt"
    readelf -h "$BUSYBOX" 2>/dev/null | grep -E "Class:|Machine:" | \
        tee -a "$OUTDIR/architecture.txt"
    echo "Architecture recorded: $OUTDIR/architecture.txt"
fi

# Phase 4: Vulnerability scan
echo "[4/5] Vulnerability scanning..."

# Hardcoded credentials
grep -rI -E "(password|passwd|secret)\s*=" \
    "$ROOTFS/etc" "$ROOTFS/www" 2>/dev/null | \
    grep -v "^#" | grep -v "^//" > "$OUTDIR/hardcoded_creds.txt"
echo "  Credentials: $(wc -l < "$OUTDIR/hardcoded_creds.txt") potential findings"

# Services
find "$ROOTFS" -path "*/init.d/*" -type f 2>/dev/null > "$OUTDIR/services.txt"
echo "  Services: $(wc -l < "$OUTDIR/services.txt") init scripts"

# Interesting binaries
find "$ROOTFS" \( -path "*/sbin/*" -o -path "*/bin/*" \) -type f -executable \
    2>/dev/null > "$OUTDIR/binaries.txt"

# Phase 5: Report
echo "[5/5] Generating report..."
{
    echo "# Firmware Analysis Report"
    echo "## Target: $FIRMWARE"
    echo "## Date: $(date)"
    echo ""
    echo "## Architecture"
    cat "$OUTDIR/architecture.txt" 2>/dev/null
    echo ""
    echo "## Services"
    cat "$OUTDIR/services.txt" 2>/dev/null
    echo ""
    echo "## Hardcoded Credentials"
    cat "$OUTDIR/hardcoded_creds.txt" 2>/dev/null
} > "$OUTDIR/report.md"

echo ""
echo "[+] Analysis complete: $OUTDIR/report.md"

Challenge

Write a Go tool that parses a U-Boot legacy uImage header, reports the kernel load address and entry point, and carves the embedded filesystem. Scan the image for the SquashFS magic hsqs , print each offset, and write each region to a separate file for unsquashfs .

package main

import (
	"bytes"
	"encoding/binary"
	"fmt"
	"os"
)

func main() {
	if len(os.Args) != 2 {
		fmt.Fprintf(os.Stderr, "usage: %s <firmware.img>\n", os.Args[0])
		os.Exit(1)
	}
	data, err := os.ReadFile(os.Args[1])
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if len(data) >= 64 && binary.BigEndian.Uint32(data[0:4]) == 0x27051956 {
		name := string(bytes.TrimRight(data[32:64], "\x00"))
		load := binary.BigEndian.Uint32(data[16:20])
		entry := binary.BigEndian.Uint32(data[20:24])
		size := binary.BigEndian.Uint32(data[12:16])
		fmt.Printf("uImage: name=%q type=%d load=0x%x entry=0x%x size=%d\n",
			name, data[30], load, entry, size)
		if int(size)+64 <= len(data) {
			os.WriteFile("kernel.bin", data[64:64+size], 0o644)
			fmt.Println("wrote kernel.bin")
		}
	} else {
		fmt.Println("no uImage header; treating as raw image")
	}
	magic := []byte("hsqs")
	from := 0
	found := 0
	for {
		idx := bytes.Index(data[from:], magic)
		if idx < 0 {
			break
		}
		offset := from + idx
		fmt.Printf("SquashFS magic at offset 0x%x (%d)\n", offset, offset)
		out := fmt.Sprintf("rootfs_%d.squashfs", offset)
		if err := os.WriteFile(out, data[offset:], 0o644); err == nil {
			fmt.Printf("wrote %s\n", out)
		}
		found++
		from = offset + len(magic)
	}
	if found == 0 {
		fmt.Println("no SquashFS magic found")
	}
}
