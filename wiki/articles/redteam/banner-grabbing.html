Banner Grabbing

Manual and automated banner grabbing across TCP , TLS , and application-layer protocols including HTTP , SSH , FTP , SMTP , MySQL , Redis, Elasticsearch, and Kafka.

Overview

Services announce themselves before authentication. Many protocols send a greeting, a version string, or a capability list as soon as a connection opens. This article shows how to capture those banners over TCP , TLS , and common application protocols, how to verify a banner against real service behavior, and how to recognize a server that deliberately lies.

Required Reading

  • TCP - connection establishment and the three-way handshake
  • HTTP - request/response structure, headers, cookies
  • TLS - ClientHello, ServerHello, and certificate exchange

The Banner Principle

A banner is any data a service sends before authentication. It exists because protocols use human-readable greeting strings, version identifiers, or capability advertisements. The banner is the first piece of intelligence you collect after discovering an open port.

Banners are not reliable. Any service can be configured to report any version string. They are a starting point - a hypothesis to be verified through behavior-based techniques. But they are fast, cheap, and often accurate enough to guide your next step.

Banner Grabbing vs Service Detection

Method Mechanism Relies on Bypassable
Banner Grabbing Read whatever the server sends on connect Server's greeting string Yes (ServerTokens, ServerSignature)
Service Detection Send protocol-specific probes, analyze behavior Protocol fingerprint, timing, quirks Harder (must emulate another server's exact TCP behavior)

nmap -sV does both. It grabs the banner AND sends probes. Manual banner grabbing teaches you what the tool does under the hood.

Raw TCP Banner Grabbing

Every TCP service that speaks a text protocol sends something on connect. The simplest banner grab is a TCP connect + read. 

# netcat — the universal banner grabber
nc 10.10.0.5 22
# SSH-2.0-OpenSSH_7.4
# ^C

nc 10.10.0.5 25
# 220 mail.target.com ESMTP Postfix (Ubuntu)
# ^C

nc 10.10.0.5 21
# 220 (vsFTPd 3.0.3)
# ^C

# Bash /dev/tcp — no external tools required
exec 3<>/dev/tcp/10.10.0.5/22
cat <&3
# SSH-2.0-OpenSSH_7.4
exec 3>&-

# Timeout wrapper — nc with explicit timeout prevents hanging
nc -w 3 10.10.0.5 22
# -w: timeout in seconds. nc exits after 3 seconds of inactivity.

# Read all data available, then close
echo '' | nc -w 3 10.10.0.5 22
# Sends empty line (harmless), receives banner, exits after timeout.
						
# telnet — works for text-based protocols
telnet 10.10.0.5 80
Trying 10.10.0.5...
Connected to 10.10.0.5.
Escape character is '^]'.
GET / HTTP/1.0
Host: 10.10.0.5
                           # ← blank line signals end of request headers
HTTP/1.1 200 OK
Server: nginx/1.22.1

Banner Grabbing With Python Sockets

A reusable banner grabbing script handles timeouts, retries, and both plain TCP and TLS : 

#!/usr/bin/env python3
# banner-grabber.py — grab banners from plain TCP and TLS services

import socket
import ssl
import sys
import argparse

DEFAULT_TIMEOUT = 3

def grab_tcp(host, port, timeout=DEFAULT_TIMEOUT):
    """Grab banner from a plain TCP service."""
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(timeout)
    try:
        sock.connect((host, port))
        # Send a protocol-appropriate empty/newline probe
        if port in (80, 443, 8080, 8443):
            # HTTP: send a basic request to trigger response
            sock.send(b'GET / HTTP/1.0\r\nHost: %b\r\n\r\n' % host.encode())
        else:
            # Non-HTTP: services typically send banner on connect
            pass
        data = b''
        while True:
            try:
                chunk = sock.recv(4096)
                if not chunk:
                    break
                data += chunk
                # Stop after a reasonable amount of data
                if len(data) > 16384:
                    break
            except socket.timeout:
                break
        return data.decode(errors='replace')
    except (socket.error, socket.timeout) as e:
        return f"ERROR: {e}"
    finally:
        sock.close()

def grab_tls(host, port, timeout=DEFAULT_TIMEOUT):
    """Grab banner from a TLS-wrapped service."""
    context = ssl.create_default_context()
    context.check_hostname = False
    context.verify_mode = ssl.CERT_NONE
    # Allow older TLS versions for enumeration purposes
    context.minimum_version = ssl.TLSVersion.TLSv1

    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(timeout)
    try:
        sock.connect((host, port))
        tls_sock = context.wrap_socket(sock, server_hostname=host)
        tls_sock.settimeout(timeout)
        # After TLS handshake, send HTTP request
        tls_sock.send(b'GET / HTTP/1.0\r\nHost: %b\r\n\r\n' % host.encode())
        data = b''
        while True:
            try:
                chunk = tls_sock.recv(4096)
                if not chunk:
                    break
                data += chunk
                if len(data) > 16384:
                    break
            except socket.timeout:
                break
        return data.decode(errors='replace')
    except (socket.error, ssl.SSLError, socket.timeout) as e:
        return f"ERROR: {e}"
    finally:
        try:
            sock.close()
        except:
            pass

if __name__ == '__main__':
    parser = argparse.ArgumentParser(description='TCP/TLS Banner Grabber')
    parser.add_argument('host', help='Target host')
    parser.add_argument('port', type=int, help='Target port')
    parser.add_argument('--tls', action='store_true', help='Use TLS')
    parser.add_argument('--timeout', type=float, default=DEFAULT_TIMEOUT)
    args = parser.parse_args()

    if args.tls:
        print(grab_tls(args.host, args.port, args.timeout))
    else:
        print(grab_tcp(args.host, args.port, args.timeout))

Usage:

python3 banner-grabber.py 10.10.0.5 22
python3 banner-grabber.py 10.10.0.5 443 --tls
python3 banner-grabber.py 10.10.0.5 80 --timeout 5

Protocol-by-Protocol Banner Grabbing

HTTP - Headers and Responses

HTTP banners live in response headers: Server , X-Powered-By , X-Generator , X-AspNet-Version , Set-Cookie , and custom headers. 

# Minimal HEAD request — get headers without body
curl -sI http://10.10.0.5 | grep -iE 'server|x-powered|x-generator|x-aspnet|set-cookie'

# GET request with full response analysis
curl -sIL http://10.10.0.5 2>/dev/null | tee http-full-response.txt

# Force HTTP/1.0 (avoids chunked encoding, simplifies parsing)
curl -sI --http1.0 http://10.10.0.5

# Manual HTTP/1.0 request via netcat (most portable)
printf 'GET / HTTP/1.0\r\nHost: 10.10.0.5\r\n\r\n' | nc -w 3 10.10.0.5 80

# Manual HTTP/1.1 request — requires Host header
printf 'GET / HTTP/1.1\r\nHost: 10.10.0.5\r\nConnection: close\r\n\r\n' | nc -w 3 10.10.0.5 80

# HEAD request via netcat
printf 'HEAD / HTTP/1.0\r\nHost: 10.10.0.5\r\n\r\n' | nc -w 3 10.10.0.5 80

# OPTIONS request — methods supported, often includes Server header
printf 'OPTIONS / HTTP/1.1\r\nHost: 10.10.0.5\r\nConnection: close\r\n\r\n' | nc -w 3 10.10.0.5 80
						
# Non-standard HTTP responses that leak information
curl -sI http://10.10.0.5/nonexistent-page-12345
# Look at:
#   - Custom 404 page content (may include paths, stack traces)
#   - X-Debug-Token headers (Symfony debug mode)
#   - X-Runtime headers (Rails performance data)
#   - X-Request-ID / X-Trace-ID (often base64-encoded internal data)

# Error page fingerprinting — trigger errors to see server default pages
curl -s http://10.10.0.5/%00         # null byte → 400 error
curl -s http://10.10.0.5/..%255c..   # double encoding
curl -s -X INVALID http://10.10.0.5/ # invalid method
# The error page format reveals the web server and sometimes the framework

HTTPS - TLS Handshake Enumeration

TLS services require a handshake before any application data flows. The handshake itself leaks server information: supported versions, cipher suites, certificate chain, and Server Name Indication (SNI) response. 

# openssl s_client — the standard TLS banner tool
openssl s_client -connect 10.10.0.5:443 -servername 10.10.0.5 </dev/null 2>/dev/null | \
  head -40
# CONNECTED(00000003)
# ---
# Certificate chain
#  0 s:CN = *.target.com
#     i:C = US, O = Let's Encrypt, CN = R3
# ---
# Server certificate
# -----BEGIN CERTIFICATE-----
# ...
# -----END CERTIFICATE-----
# SSL-Session:
#     Protocol  : TLSv1.3
#     Cipher    : TLS_AES_256_GCM_SHA384
#     Server Temp Key: X25519 253 bits

# Extract the HTTP banner from HTTPS
openssl s_client -connect 10.10.0.5:443 -servername 10.10.0.5 -quiet <<< $'GET / HTTP/1.0\r\nHost: 10.10.0.5\r\n\r\n' 2>/dev/null

# SNI testing — what certificate does the server return for this hostname?
openssl s_client -connect 10.10.0.5:443 -servername admin.target.com </dev/null 2>/dev/null | \
  openssl x509 -noout -subject

# ALPN negotiation — what protocols does the server support?
openssl s_client -connect 10.10.0.5:443 -alpn h2,http/1.1 </dev/null 2>/dev/null | \
  grep 'ALPN protocol'
# ALPN protocol: h2  → HTTP/2 supported
# ALPN protocol: http/1.1  → HTTP/1.1 only
						
# nmap TLS enumeration — cipher suite analysis
nmap -p 443 --script ssl-enum-ciphers 10.10.0.5

# sslscan — dedicated TLS scanner
sslscan --show-certificate 10.10.0.5:443

# testssl.sh — comprehensive TLS testing
git clone https://github.com/drwetter/testssl.sh.git /opt/testssl
/opt/testssl/testssl.sh --server-defaults 10.10.0.5:443
/opt/testssl/testssl.sh --headers 10.10.0.5:443

SSH - Version String

SSH servers send a single line with the protocol version and software identifier before any key exchange. This is mandatory per RFC 4253. 

# SSH banner
nc 10.10.0.5 22 <<< ''
# SSH-2.0-OpenSSH_7.4

# Common SSH banners and their meaning:
# SSH-2.0-OpenSSH_7.4          → Linux server, likely CentOS/RHEL 7
# SSH-2.0-OpenSSH_8.9p1        → Ubuntu 22.04
# SSH-2.0-dropbear_2022.83     → Dropbear (embedded/IoT devices)
# SSH-2.0-ROSSSH               → RouterOS (MikroTik)
# SSH-2.0-Cisco-1.25           → Cisco IOS
# SSH-2.0-OpenSSH_for_Windows_8.1  → Windows with OpenSSH server

# nmap SSH enumeration combines banner + algorithm analysis
nmap -p 22 --script ssh2-enum-algos,ssh-hostkey 10.10.0.5

FTP - The 220 Greeting

FTP servers send a 220 greeting immediately after the TCP handshake completes. The format is loosely standardized, making banner parsing reliable. 

# FTP banner
nc 10.10.0.5 21 <<< ''
# 220 (vsFTPd 3.0.3)

# Common FTP banners:
# 220 (vsFTPd X.Y.Z)              → vsFTPd (Linux)
# 220 ProFTPD X.Y.Z Server        → ProFTPD (Linux/Unix)
# 220 Microsoft FTP Service        → IIS FTP (Windows)
# 220 Serv-U FTP Server vX.Y       → Serv-U (Windows, commercial)
# 220 Pure-FTPd                    → Pure-FTPd
# 220 FileZilla Server             → FileZilla Server (Windows/Linux)

# FTP FEAT command — capability enumeration
printf 'FEAT\r\n' | nc -w 3 10.10.0.5 21

# FTP SYST command — system type
printf 'SYST\r\n' | nc -w 3 10.10.0.5 21
# 215 UNIX Type: L8

# FTP HELP command — available commands
printf 'HELP\r\n' | nc -w 3 10.10.0.5 21

SMTP - 220 Greeting and EHLO Response

SMTP servers send a 220 greeting and respond to EHLO with a list of supported extensions. 

# SMTP banner
nc 10.10.0.5 25 <<< ''
# 220 mail.target.com ESMTP Postfix (Ubuntu)

# EHLO — extended capabilities
printf 'EHLO test.local\r\n' | nc -w 3 10.10.0.5 25

# Common SMTP service identifiers:
# Postfix, Exim, Sendmail, Microsoft ESMTP, Exchange
# The OS/distribution is often present: "Postfix (Ubuntu)", "Exim 4.94 (Debian)"

# POP3 banner (TCP 110)
nc 10.10.0.5 110 <<< ''
# +OK Dovecot ready.

# IMAP banner (TCP 143)
nc 10.10.0.5 143 <<< ''
# * OK [CAPABILITY IMAP4rev1 SASL-IR LOGIN-REFERRALS ID ENABLE IDLE ...] Dovecot ready.

MySQL - Protocol Handshake Packet

MySQL does not send a text banner. The handshake is a binary packet that contains the server version, protocol version, capabilities flags, and authentication seed. 

MySQL HandshakeV10 packet structure:
 1 byte   protocol_version (0x0a = MySQL 5.x+, 0x09 = MySQL 4.1)
 N bytes  server_version (null-terminated string)
 4 bytes  connection_id (thread ID)
 8 bytes  auth-plugin-data-part-1 (scramble/salt)
 1 byte   filler (0x00)
 2 bytes  capability_flags (lower 2 bytes)
 1 byte   character_set
 2 bytes  status_flags
 2 bytes  capability_flags (upper 2 bytes)
 1 byte   auth_plugin_data_len
 10 bytes reserved (zeros)
 N bytes  auth-plugin-data-part-2 (rest of salt, length from auth_plugin_data_len)
 N bytes  auth_plugin_name (null-terminated, if capabilities indicate it)
						
# MySQL banner via Python hex dump
python3 << 'EOF'
import socket
s = socket.socket()
s.settimeout(5)
s.connect(('10.10.0.5', 3306))
data = s.recv(1024)
protocol = data[4]
end = data.index(b'\x00', 5)
version = data[5:end].decode()
conn_id = int.from_bytes(data[end+1:end+5], 'little')
caps_low = int.from_bytes(data[end+10:end+12], 'little')
caps_high = int.from_bytes(data[end+19:end+21], 'little')
capabilities = (caps_high << 16) | caps_low
print(f'Protocol Version: {protocol}')
print(f'Server Version: {version}')
print(f'Connection ID: {conn_id}')
print(f'Capabilities: 0x{capabilities:08x}')
# Key capability flags:
# CLIENT_LONG_PASSWORD (0x00000001)
# CLIENT_PROTOCOL_41 (0x00000200) — always set for modern MySQL
# CLIENT_SECURE_CONNECTION (0x00008000)
# CLIENT_PLUGIN_AUTH (0x00080000) — if set, auth_plugin_name present
EOF

# nmap MySQL info
nmap -p 3306 --script mysql-info 10.10.0.5

Redis - PING and INFO

Redis is plain-text and extremely verbose. Commands return structured data with type prefixes ( + for simple string, $ for bulk string, * for array). 

# Redis PING
printf 'PING\r\n' | nc -w 2 10.10.0.5 6379
# +PONG

# Redis INFO — comprehensive server status
printf 'INFO\r\n' | nc -w 2 10.10.0.5 6379
# redis_version:6.0.16
# redis_git_sha1:00000000
# os:Linux 5.15.0-91-generic x86_64
# arch_bits:64
# gcc_version:11.4.0
# process_id:12345
# tcp_port:6379
# uptime_in_seconds:1234567
# connected_clients:5
# maxmemory_human:0B (no limit)
# redis_mode:standalone

# Redis CLIENT LIST — connected clients
printf 'CLIENT LIST\r\n' | nc -w 2 10.10.0.5 6379
# id=3 addr=10.0.0.100:54321 fd=9 name= age=300 idle=0 ...

# Redis CONFIG — dangerous if accessible
printf 'CONFIG GET dir\r\n' | nc -w 2 10.10.0.5 6379
# *2
# $3
# dir
# $16
# /var/lib/redis

# nmap Redis
nmap -p 6379 --script redis-info 10.10.0.5

Docker API (TCP 2375/2376)

Docker's API is HTTP -based. An unauthenticated Docker API is equivalent to root access on the host. 

# Docker API version endpoint
curl -s http://10.10.0.5:2375/version 2>/dev/null | jq .
{
  "Platform": {"Name": "Docker Engine - Community"},
  "Version": "24.0.7",
  "ApiVersion": "1.43",
  "Os": "linux",
  "Arch": "amd64",

# Docker API — list containers

# Docker API — list images
curl -s http://10.10.0.5:2375/images/json 2>/dev/null | jq '.[].RepoTags'

# nmap Docker API
nmap -p 2375,2376 --script docker-version 10.10.0.5

Elasticsearch (TCP 9200)

Elasticsearch returns JSON on all endpoints. The root endpoint is the richest banner source. 

# Elasticsearch root endpoint
curl -s http://10.10.0.5:9200/ | jq .
{
  "name": "node-1",

# Elasticsearch node stats — leaks filesystem paths, memory, JVM version

# Elasticsearch indices — what data is stored?
curl -s http://10.10.0.5:9200/_cat/indices?v

Apache Kafka (TCP 9092)

Kafka uses a binary protocol. The ApiVersions request ( API key 18) returns the broker's supported API versions, which directly maps to the broker version. 

# Kafka ApiVersions request via Python
python3 << 'EOF'
import socket, struct

def send_kafka_request(host, port, api_key, api_version, correlation_id=0):
    """Send a Kafka protocol request and return the response."""
    client_id = 'banner-grabber'
    request_body = b''
    # Request header v2: api_key(2) + api_version(2) + correlation_id(4) + client_id(str) + tagged_fields(1)
    client_id_bytes = client_id.encode()
    header = struct.pack('>hhih', api_key, api_version, correlation_id, len(client_id_bytes))
    header += client_id_bytes + b'\x00'  # tagged fields
    message = struct.pack('>i', len(header) + len(request_body)) + header + request_body
    sock = socket.socket()
    sock.settimeout(5)
    sock.connect((host, port))
    sock.send(message)
    response_size = struct.unpack('>i', sock.recv(4))[0]
    response = sock.recv(response_size)
    sock.close()
    return response

# ApiVersions request v3
# Minimal body: client_software_name (string) + client_software_version (string) + tagged_fields (1 byte)
body = b'\x00\x00\x00\x00'  # empty client_software_name, empty client_software_version, no tagged fields
sock = socket.socket()
sock.settimeout(5)
sock.connect(('10.10.0.5', 9092))
# Send with header v2 (ApiVersions API key=18)
client_id = 'banner-grabber'.encode()
header = struct.pack('>hhih', 18, 3, 0, len(client_id)) + client_id + b'\x00'
message = struct.pack('>i', len(header) + len(body)) + header + body
sock.send(message)
size = struct.unpack('>i', sock.recv(4))[0]
response = sock.recv(size)
sock.close()

correlation_id = struct.unpack('>i', response[:4])[0]
error_code = struct.unpack('>h', response[4:6])[0]
print(f'Auto offset: {response[6:6+response[5]]}')
if error_code == 0:
    print('Kafka broker responded successfully')
else:
    print(f'Kafka error code: {error_code}')
EOF

TLS Banner Grabbing in Depth

Many services wrap plain-text banners in TLS . The encrypted channel does not prevent banner grabbing - it prevents passive sniffing, but active TLS connections still receive the banner. 

# HTTPS banner via openssl — one-liner
echo -e 'GET / HTTP/1.0\r\nHost: 10.10.0.5\r\n\r\n' | \
  openssl s_client -connect 10.10.0.5:443 -quiet 2>/dev/null

# SMTPS (465) — SMTP over TLS
openssl s_client -connect 10.10.0.5:465 -quiet 2>/dev/null <<< ''
# 220 mail.target.com ESMTP Postfix

# IMAPS (993) — IMAP over TLS
openssl s_client -connect 10.10.0.5:993 -quiet 2>/dev/null <<< ''
# * OK [CAPABILITY ...] Dovecot ready.

# POP3S (995) — POP3 over TLS
openssl s_client -connect 10.10.0.5:995 -quiet 2>/dev/null <<< ''
# +OK Dovecot ready.

# FTPS (990) — FTP over TLS (implicit)
openssl s_client -connect 10.10.0.5:990 -quiet 2>/dev/null <<< ''
# 220 (vsFTPd 3.0.3)

# LDAPS (636) — LDAP over TLS
openssl s_client -connect 10.10.0.5:636 -quiet 2>/dev/null <<< '' | head -1
						
# STARTTLS — negotiation within plain-text protocol
# SMTP STARTTLS
printf 'EHLO test\r\nSTARTTLS\r\n' | nc -w 3 10.10.0.5 25
# 220 2.0.0 Ready to start TLS

# After STARTTLS, you need an openssl client that supports STARTTLS:
openssl s_client -connect 10.10.0.5:25 -starttls smtp -quiet </dev/null 2>/dev/null

# FTP AUTH TLS
printf 'AUTH TLS\r\n' | nc -w 3 10.10.0.5 21
# 234 Proceed with negotiation.
openssl s_client -connect 10.10.0.5:21 -starttls ftp -quiet </dev/null 2>/dev/null

Banner Deception and Spoofing

Services can be configured to hide or falsify their banners. Understanding these techniques prevents false conclusions. 

# Apache — control banner verbosity
# ServerTokens Prod        → Server: Apache
# ServerTokens Major       → Server: Apache/2
# ServerTokens Minor       → Server: Apache/2.4
# ServerTokens Min         → Server: Apache/2.4.41
# ServerTokens OS          → Server: Apache/2.4.41 (Ubuntu)
# ServerTokens Full        → Server: Apache/2.4.41 (Ubuntu) OpenSSL/1.1.1f
# ServerSignature Off      → removes version from error pages, directory listings

# nginx — control banner
# server_tokens off;        → Server: nginx
# server_tokens on;         → Server: nginx/1.22.1
# server_tokens build;      → Server: nginx/1.22.1 (Ubuntu)

# Custom Server header via nginx:
# more_set_headers 'Server: Microsoft-IIS/10.0';  (with headers-more module)
# add_header Server "Apache/2.4.6 (CentOS)";      (standard: only appends, not replaces)

# SSH — change banner via /etc/ssh/sshd_config
# Banner /etc/ssh/banner.txt
# But the version string (SSH-2.0-OpenSSH_X.Y) is hardcoded in the binary.
# To change it: recompile OpenSSH with modified version.h
# Or: use a proxy that rewrites the version string
						
# Detecting false banners — the consistency check
# If Apache is reporting but the error page format is nginx → banner is fake
# If Server: nginx but Set-Cookie: JSESSIONID → backend is Java (Tomcat/JBoss), nginx is reverse proxy

# Cross-reference methods:
# 1. Banner says Apache → try /server-status, /icons/apache_pb.gif (Apache-specific)
# 2. Banner says IIS → try /iisstart.htm, /_aspmvc/ (IIS-specific)
# 3. Check HTML comments: <!-- This is Apache --> vs <!-- nginx -->
# 4. Check the default 404 page — each web server has a distinctive format
# 5. Check TLS fingerprint: Apache uses OpenSSL, IIS uses SChannel, nginx uses OpenSSL/BoringSSL

# nmap can sometimes detect the real server behind a false banner
nmap -sV -p 80,443 --script http-server-header 10.10.0.5

Batch Banner Grabbing

When you have a list of open ports from a port scan, run banner grabbing across all of them.

#!/bin/bash
# batch-banner-grab.sh — grab banners from all open TCP ports on a host
HOST="$1"
TLS_PORTS="443,8443,993,995,465,636,989,990"
TIMEOUT=3

# Phase 1: find open TCP ports
OPEN_PORTS=$(nmap -sT -T4 -p- --open "$HOST" -oG - 2>/dev/null | \
  grep '/open/' | awk -F'[/ ]' '{print $2}' | sort -nu)
echo "[*] Open ports: $(echo $OPEN_PORTS | wc -w)"

# Phase 2: grab banner from each port
for PORT in $OPEN_PORTS; do
  echo "=== Port $PORT ==="
  if echo "$TLS_PORTS" | grep -q "$PORT"; then
    # TLS port
    echo -e '\n' | openssl s_client -connect "$HOST:$PORT" -quiet 2>/dev/null | \
      head -5
  else
    # Plain TCP — send appropriate probe
    if [ "$PORT" -eq 80 ] || [ "$PORT" -eq 8080 ]; then
      printf "GET / HTTP/1.0\r\nHost: %s\r\n\r\n" "$HOST" | nc -w "$TIMEOUT" "$HOST" "$PORT" 2>/dev/null | head -20
    else
      nc -w "$TIMEOUT" "$HOST" "$PORT" < /dev/null 2>/dev/null | head -5
    fi
  fi
  echo
done

# Verify: banner matches nmap -sV output

# Verify: check for WAF/CDN stripping headers
# If your curl shows no Server header but nmap shows one, a WAF/CDN removed it
# WAFs like Cloudflare strip Server headers by default
curl -sI https://target.com | grep -i server
# If empty → CDN/WAF in front, banner-grab the origin IP instead

# Verify: TLS version affects the response
# Some servers return different HTTP headers depending on TLS version negotiated
openssl s_client -connect 10.10.0.5:443 -tls1_2 -quiet \
  <<< $'GET / HTTP/1.0\r\n\r\n' 2>/dev/null | grep -i '^Server:'

# 3. Does the service require a protocol-specific init? Some services wait for the client.
